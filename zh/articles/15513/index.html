时间与空间复杂度 · FDE 编程题

原标题：Time and space complexity · FDE coding question

FDE Interview Prep · 2026 · 约 2 分钟读完

摘要

本文讲解 FDE 面试中的时间与空间复杂度题，素材来自 Palantir 官方指南及 OpenAI 候选人面经。核心观点：不要只答“O(n)”，要先命名变量（如 n 笔付款、m 张发票）、逐阶段计价、单独说明峰值内存、指出最坏输入，并结合真实数据规模判断是否值得优化。文章以银行付款匹配发票为例给出两分钟口头答案模板，并列出面试官追问方向与常见失误，如忽略空间、把字典查找当作无条件常数时间、未问数据规模就优化。

要点

  • 复杂度答案必须命名多个变量，而非笼统的 O(n)。
  • 需逐阶段计价，包括排序、索引构建等隐性成本。
  • 空间复杂度要单独说明，含输入副本的峰值占用。
  • 先找数据倾斜，如同一金额或超大账户构成最坏情况。
  • 结合真实行数与运行频率，规模不大就明说不必优化。

如何回答

Palantir 的全公司指南《分析代码的效率》告诉候选人要懂得如何计算算法的效率，并且不要忘记空间复杂度。Source 1分析代码的效率发布方Palantir来源类型公司招聘页面 这个问题的后半部分才是关键：客户的数据有其形态，而数据的形态决定了你的大 O 复杂度是否重要。

  • 先说出各个变量。 不是笼统的“O(n)”，而是“n 笔付款、m 张发票、k 张金额相同的发票”。大多数实际方案都有不止一个规模。
  • 为每个阶段计算成本，而不仅仅是主循环。 包括构建索引、每次排序以及每项数据的处理工作。把隐藏的成本说出来：list.pop(i)、x in some_list、循环内的排序、字符串拼接。
  • 单独说明空间开销。 峰值时占用了什么，包括输入的排序副本。
  • 说出最坏情况以及导致它的输入。 在客户数据中首先寻找偏斜：所有订阅都是同一个价格、一个巨型账户、关键列中的一个默认值。
  • 结合真实规模来谈。 询问有多少行数据、运行频率如何、用户是否需要等待它、工作节点有多少内存。把算术过程大声说出来，或者实际测量。
  • 说明你会做什么改动，以及在什么规模下。 如果数据规模表明它无关紧要，就直说，然后停止。

陷阱是那种一个词的回答——“线性”，既没有指明变量，也没有说明最坏情况。另一个相反的陷阱是在不了解数据之前就为了速度而重写代码。

追问

当你的第一个回答摆在桌面上之后，面试官接下来可能会问的问题。

  • 构造一个能让你的方案最慢的输入。
  • 这从夜间批处理任务变成了用户需要等待的 API 调用。你的回答会有什么变化？
  • 数据不再能装进单个工作节点的内存。你会怎么做？
  • 你说查找是常数时间。在什么上是常数，背后又隐藏着什么？

回答容易出错的地方

  • 只说“它是 O(n)”，没有指明变量、没有最坏情况、也没有数据规模，因此这个答案无法对照任何东西进行验证。
  • 把字典查找称为常数时间，而每个键背后的列表却随着数据增长。
  • 忽略了空间开销，或者只计算了新结构而没算你排序时输入的副本。
  • 在还没问清数据规模有多大、代码运行频率有多高之前就开始优化。
