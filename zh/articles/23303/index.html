你的定价模式决定了 FDE 团队的用途

原标题：Your Pricing Model Decides What Your FDE Team Is For

FDE Hub · 2026-07-28 · 约 9 分钟读完

摘要

文章以 AWS 六月底公布的前沿部署工程组织为切入点，指出其真正值得关注的不是十亿美元投入，而是五到六人小组、四十五天周期、按固定结果定价的模式。作者梳理了四种部署收费模式：计量消费型（如 Anthropic、AWS，部署实为获客成本，安装“计量表”）；显式收费型（如 Sierra 按成功解决计费约 1.5 美元/案例，另收 5 万至 20 万美元实施费）；产品化零部署型（如 Fin 每结果 0.99 美元、无任何集成费）；以及隐性收费型——把实施成本打包进年度订阅，第一年亏损、利润靠续约。作者引用 Tanay Padhi 的观点：企业系统总拥有成本历来约六至七成是服务，目标为每名 FDE 创收 100 万至 150 万美元。核心论点是：定价模式决定了 FDE 团队的真正使命，且所有定价都在信息最少时确定；公司阶段决定了你能有多大操作空间，Palantir 用多年时间把服务收入占比从约四分之一降到约五分之一即是刻意调整的范例。

要点

  • AWS 前沿部署工程采用五到六人小组、四十五天周期、按固定结果定价。
  • 计量消费型公司把部署当获客成本，固定结果定价近乎促销。
  • Sierra 按解决案例收费约 1.5 美元，另收 5 万至 20 万美元实施费。
  • 隐性订阅模式第一年亏损，利润全靠续约与真实采用。
  • 定价在信息最少时确定，公司阶段决定可操作空间。

当 AWS 于六月底宣布其前沿部署工程组织时，大多数报道的焦点都放在了十亿美元上。真正值得细读的细节在更下面：五到六名工程师组成的小组，四十五天的周期，按固定成果定价，而非按计费小时收费。

固定成果，在工作开始之前就做出承诺，而且时间表几乎没有给范围估计出错留下余地。这是一个大胆的承诺，而有趣的问题在于，为什么一家公司会愿意这样做。答案完全取决于其背后是哪种类型的业务。

部署工作的收费方式有四种。经验丰富的 FDE 负责人应该见过其中几种，而且很可能对每一种都争论过。我在这里想做的，是把它们并排摆出来，因为每一种方式都赋予 FDE 团队不同的任务，而只有当你观察资金实际流向时，这些差异才会显现出来。

1. 计量器买单

第一种模式属于各大实验室和超大规模云厂商，也是目前讨论得最热烈的一种。

如果你的核心业务是按用量计费的消费，那么部署根本不是一条收入线，而是获客成本。Anthropic 已将企业合同从固定的按席位定价，改为更低的名义席位价格，再加上按 API 费率计费的 token 消耗。一旦业务呈现这种形态，部署该收多少钱这个问题就不再有趣了。部署的存在就是为了安装计量器。

你可以从 AWS 的架构本身看到这一点：它在客户自己的 AWS 账户内放置一个语义层，并构建一个供 Agent 进行推理的带版本管理的知识图谱。这不是交付物，而是一个水龙头。微软的版本——一个旨在让客户的专有数据和工作流随时间不断复利的双平台结构——是同一理念的不同表述。

这就是为什么提供固定成果定价对他们来说几乎毫无成本。如果成果达成，皆大欢喜。如果没有达成，语义层仍然留在客户的账户里，集成仍然接通，消耗仍然在运行。成果费用相对于之后流过的资金来说只是四舍五入的零头。它看起来像风险转移，实际上更接近一次促销优惠。

这种模式还有一个更小的版本，出现在远低于超大规模云厂商的量级上。一家出售用量额度的供应商免费构建解决方案，作为回报，要求客户预先承诺一个消费水平。比如说，五万美元的额度，在构建开始之前购买或以合同形式承诺。部署在纸面上仍然是免费的，但客户已经为其提供了担保。只要定价诚实，这对双方都是合理的结构；但如果承诺的消费量是为了给构建买单而设定的，而不是根据客户实际会用到的量来定的，那就是一个隐蔽的陷阱。

这些都不是批评。当你按仪表计费销售时，这是一种理性的行为方式。但如果你在一个不按仪表计费的公司里管理 FDE 团队，却发现自己面临匹配那些商业条款的压力，那么值得知道的是：你正在被拿来与一个不承担你所要承担风险的商业模式作比较。

2. 客户付费，而且看得见

第二种模式是显性的，但它并不像你想象的那么常见。

Sierra 按成功解决计费，大约每单 1.5 美元。除此之外还有设置费，根据集成复杂程度在 5 万到 20 万美元之间，部署周期为三到七个月。按解决计费承担了叙事功能，而设置费才是真正收回部署成本的地方。

这种结构有很多优点。它把构建工作作为一件有真实成本的真实事物呈现在买家面前，这意味着关于范围的讨论发生在双方还握着笔的时候，而不是交付六周之后。它还划出了一个清晰的内部边界。负责构建的团队由某份合同上的一个具体条目资助，你可以判断这笔资金是否覆盖了工作。当评估出错时，错误是显而易见的，纠正方式是一场商业谈判，而不是一笔无声的核销。

问题在于，这要求买家足够成熟，不会对六位数的设置费望而却步，同时要求你的市场地位足够强，才敢开口要这个价。很多公司想对实施收费却做不到，因为隔壁的竞争对手不收费。

3. 没人付费，因为几乎没有构建

第三种模式是每个产品团队都说自己正在迈向的方向。

Fin 按结果收费 99 美分，没有集成费、没有设置费，运行在现有客服系统上时也不收平台费。它能做到这一点，是因为它的部署以天计而非以月计。没有需要收回的部署成本。

这是产品化的诚实终态，是真正的成就而非花招。但请注意它意味着什么。定价模式取决于产品需要多少部署。当有人告诉你他们的定价比你的更简单时，他们通常是在告诉你他们产品形态的某些特点，而不是他们商业上的成熟度。而且这种模式适用的品类往往任务范围狭窄、边界清晰。在企业运营这片混乱的中间地带，这种情况尚未发生，我也不认为它已经临近。

4. 客户付费，但永远看不见

然后是第四种模式，这实际上是中端市场大量部署工作真正发生的地方。

这个模式大家都很熟悉。FDE 评估解决方案的复杂程度，评估结果对应一个层级，交易按该层级的年度订阅报价。两万、四万、八万、十万，从签约后的次月起按月开票。没有单独的实施费用条目。供应商负责构建、跑通，并在合同期内逐步收回构建成本。锁定一年，到期自动续约，除非有人取消。

从客户的角度看，这很干净。他们看到的是软件定价，于是默认这个数字反映的是产品本身。

从供应商的角度看，第一年是亏的。你把公司里最昂贵的人力投入到一项不收费的构建中，而订阅收入需要大半个合同期才能持平。利润不在第一年，而在续约。

这个结构背后隐藏的赌注是：只有当你相信自己的解决方案确实足够好，能够以低于雇佣成本的方式替代一个人甚至几个人时，这个模式才成立。如果属实，客户就没有理由关掉它。取消意味着把工作重新雇回来。续约不是你每年都要争取的东西，而是默认状态，漫长的成本回收也不再是风险，而是耐心。整个模式本质上是对产品的一种信心宣言，只是包装成了定价决策。

它也改变了 FDE 团队的存在意义。如果利润在续约里，那么采用率就不再是让所有人对项目感觉良好的软性成果，而是全部的商业逻辑。一个技术上能跑通却无人使用的部署，损失的不只是口碑，而是你已经投入的整整一年。让持怀疑态度的操作员把真实工作接入系统的漫长过程，不再是项目中不起眼的收尾工作，而成为决定这个客户当初是否值得签约的关键。

Tanay Padhi 在我们交谈时很好地概括了底层经济逻辑：企业系统的总拥有成本历来大约是百分之六十到七十的服务费加百分之三十的许可费，而如今按软件倍数融资的公司，目标是每个 FDE 创造一百万到一百五十万美元的收入。分层订阅模式并没有让服务成本消失，只是把它从账单挪进了利润率——一个更难看清、也更难争论的地方。

定价发生在信息最少的那一刻

无论你处于这四种情况中的哪一种，它们都依赖同一个脆弱的东西。

等级、实施费、成果定义、消费承诺——所有这些都在签约时敲定，依据的是在任何人都还没接触过实际流程之前做出的复杂度评估。而成果必须尽可能严格地写进合同，因为没有明确的成果，就没人能判断工作何时算完成。所以你会用当时所知的一切，把成果写得尽可能严密。

而当时你所知道的，只是那位支持者所描述的情况。真正的一线操作人员——那些日常工作实际上决定了构建复杂程度的人——通常还没出现在会议室里。于是，价格和定义都是在整个合作过程中信息最少的时刻确定的，之后的一切要么是在消化这个差距，要么就得回头找客户重新谈。

回头重新谈并非致命。当评估被证明有误时，你可以进行沟通，重新定价或找到追加销售的机会，有时结果还不错，因为那时你已经有能拿得出手的东西了。但这恰恰在你最需要赢得信任的时刻消耗了信誉，而对同一个客户，你能这样做的次数是有限的。

阶段决定了你被允许做什么

有一件事我想告诉每一个在早期组建 FDE 团队的人：你拥有的回旋余地比以后任何时候都大，你应该有意识地利用它，而不是无意中挥霍掉。

在小公司，你更关心收入本身，而不是收入的构成。你可以把一个几乎完全定制的构建项目记作产品许可收入，因为没有人会质疑你，而且你也确实打算以后把它产品化。这种灵活性是真实存在的，而且很有用。它让你能用客户的钱而不是投资人的钱来资助探索，这笔交易比听起来划算得多。

问题在于这种灵活性会过期。到了某个时点，收入结构开始被认真审视，那些被你记作许可收入的定制工作必须按其本来面目被确认。Palantir 花了多年时间把专业服务收入占比从大约四分之一降到接近五分之一，并建立了整套 bootcamp 模式来减少每个新客户所需的部署工作量。这才叫有意识的做法。

当你无法再模糊这条界线的那一刻，本身就是一个阶段标志，值得在别人告诉你之前，先弄清楚自己处在界线的哪一边。

还有一个变量我刻意没有涉及，那就是客户方的预算由谁掌握。工程部门主导、市场推广部门主导和客户成功部门主导的交易，在定价、范围界定和续约上都各不相同，而我还没有一个清晰的框架来解释原因。我能确定的是：贵公司采用的商业模式是某个人在当时合理的约束条件下选定的，而大多数 FDE 团队只是继承了它，却从未被告知它给自己带来了什么承诺。早点弄清楚，总比到续约时才发现要便宜。
