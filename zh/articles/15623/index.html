安全问卷：使用 SOC 2 和 ISO 27001

原标题：Security questionnaire: using SOC 2 and ISO 27001

FDE Times · 2026-10-09 · 约 7 分钟读完

摘要

这篇文章面向前沿部署工程师，讲解如何在写代码之前应对客户发来的安全问卷。文章区分了 SOC 2 报告与 ISO 27001 证书各自证明的内容，建议先发送 SOC 2 报告再填写问卷：据合规咨询机构 Agency 估计，一份有效的 SOC 2 Type II 报告可直接回答 CAIQ 约 260 题中的 60% 至 70%，即只需自行撰写约 78 至 104 题。作者给出固定答题模板，强调 Scope（范围）与 Owner（负责人）两个字段最关键，用注明范围的“Partial”比含糊的“Yes”更可信。答案库应按主题而非框架组织，且每条需有负责人和复审日期，因为过时的答案可能构成违约风险。文末列出常见错误，如误发 Type 1 报告、忽略证书范围覆盖、工程师独自作答等，并建议求职者在简历中体现安全审查经验。

要点

  • SOC 2 是 CPA 出具的报告，ISO 27001 是注明 ISMS 范围的证书，两者证明内容不同。
  • 先发 SOC 2 Type II 报告，估计可覆盖 CAIQ 约 260 题中的 60% 至 70%。
  • 答题须注明范围与负责人，注明范围的“Partial”比含糊的“Yes”更可信。
  • 答案库按主题组织，每条设负责人和复审日期，过时答案比没有更危险。
  • 常见错误：误发 Type 1、忽略证书范围、无证据答“Yes”、工程师独自作答。

一家咨询公司估计，先发送 SOC 2 报告，可以把 260 道题的 CAIQ 缩减到大约 78 至 104 道需要你自己作答的问题。

简要说明

  • SOC 2 是一份包含注册会计师（CPA）意见的报告，说明一个组织是否言行一致；ISO 27001 是一份证书，标明 ISMS 的覆盖范围。它们证明的是不同的事情。
  • 在开始填写表格之前先发送报告：一家合规咨询公司估计，SOC 2 Type II 可以直接回答大约 60%–70% 的 CAIQ 问题。
  • 按主题组织答案库，并指定负责人和审查日期。一个过时的答案库比没有答案库风险更大。

在驻场的第一个星期，你还没运行过一行代码，就收到一封邮件：一个包含数百道安全问题的表格，并附有说明——填完之后才能获得访问权限。如果客户是金融机构，问卷可能是 SIG Core，超过 800 道题。

提供 FDE 人员的公司 Appsierra 观察到，访问权限配置、安全审查和等待客户批准所花的时间，往往比最初找到工程师还要长——不过这是一家销售该服务的公司的观点。

好消息是，这是一项可以学会的技能。FDE 的工作不是重写公司的安全政策。你的工作是在合适的时机，把范围合适的正确证据摆在客户面前，让他们的安全团队有足够的依据说“可以”。

SOC 2 和 ISO 27001 证明的是不同的事情

要用好证据，首先需要知道每种证据证明什么。根据审计公司 Schellman 的说法，SOC 2 的产出是一份报告，其中注册会计师（CPA）就组织是否真正做到其所声称的事情给出意见。

AICPA 表示，SOC 报告为用户提供信息，以评估和应对外包服务的风险。其 SOC 2 材料围绕五个类别构建：安全性、可用性、处理完整性、保密性和隐私。

SOC 2 报告分为两种类型。根据 Schellman 的说法，Type 1 评估的是单一时间点，而 Type 2 覆盖一个时间段，通常为 12 个月。因此 Type 2 说明的内容更多：控制措施是在整个期间内接受审查的，而不是某一天。

ISO 27001 则不同。Schellman 表示，其产出是一份证书，标明 ISMS 的范围，包括所覆盖的部门和地点，认证周期为三年，并附有年度审查。

每个客户都有自己的要求，所以要尽早询问其安全团队需要哪种类型的证据。

SOC 2ISO 27001
你发给客户的东西一份包含注册会计师意见的报告一份证书
它回答的问题该组织是否做到了它承诺的事情？信息安全管理体系是否经过认证？

先发送报告，之后再填写表格

不要打开文件就从第 1 行开始。安全合规咨询机构 Agency 建议先提交 SOC 2 报告，因为买方有时会接受它来替代整份问卷。该来源有商业利益考量，所以把这当作一种可能性，而非承诺。

同一来源指出，云安全联盟（Cloud Security Alliance）的 CAIQ 在 17 个领域中共有约 260 个问题。该来源还估计，一份最新的 SOC 2 Type II 报告能直接回答约 60-70% 的 CAIQ 问题。

算一算这个估计：260 的 60% 是 156 个问题，70% 是 182 个。也就是说，你只需自己撰写大约 78 到 104 个问题，而不是 260 个。

你自己的数字可能不同。但这个思路是成立的：一份冗长的问卷实际上由两部分组成——一部分已有证据支撑，另一部分仍是空白。首要任务就是把这两部分区分开来。

一个完整的实战示例

假设你是一名 FDE，正在为一家银行部署一个读取信贷文件的 AI Agent。客户发来了 CAIQ。

在回答任何问题之前，你先向自己的安全团队提出三个问题：最新的 SOC 2 报告是 Type 1 还是 Type 2，ISO 27001 证书上的 ISMS 范围写了什么，以及公司是否已有一份填写完成的 CAIQ？

第二个问题是 FDE 最需要密切关注的。如果你的 AI Agent 运行在银行的云环境中，或者依赖证书上未列出的某个部门或地点，那么证书的范围就不涵盖你即将开展的工作。在不说明这一点的情况下发送证书，之后可能被视为虚假陈述。

接下来，你给表格中的每一行标注以下三种标签之一：“由报告回答”（引用报告的具体章节）、“已在知识库中”，以及“需要新答案”。对于最后一组，每个答案都遵循固定模板：

Question: [the client's question, verbatim]
Answer: Yes / No / Partial
Explanation: [1-2 sentences, no marketing]
Evidence: [SOC 2 report section, policy name, configuration screenshot]
Scope: [which system/environment this applies to]
Owner: [who confirms this answer]
Last updated: [date]

“范围”和“负责人”字段正是 FDE 发挥作用的地方。你了解实际的部署架构；安全团队了解政策。一个范围明确清晰的“部分符合”，远比一个含糊的“是”更有说服力。

以下是上述银行项目的一个已完成答案的示例，假设信贷文件存放在银行的云中：

Question: Is customer data encrypted at rest?
Answer: Partial
Explanation: Data in the company's environment is encrypted at rest. Credit files sit in the bank's cloud and follow the bank's encryption configuration.
Evidence: Encryption section of the latest SOC 2 Type 2 report; screenshot of the project's storage configuration
Scope: The company's environment; excludes the bank's cloud
Owner: Confirmed by the security lead, drafted by the project FDE
Last updated: [date of most recent review]

客户的安全团队读到这份答案，立刻就知道哪部分由你的公司负责，哪部分由他们负责，以及应打开报告的哪一页进行核实。他们不需要再发邮件来询问。

按主题组织的答案库，以及旧答案库的代价

填过几份问卷后，你会发现同一个要点会以不同方式被问及：CAIQ 用一种方式表述，SIG 用另一种方式，而银行自己的模板又是第三种。

因此，请按主题组织答案库，例如访问管理、加密、日志或事件响应，而不是按框架组织。这样，一条关于访问管理的答案就能适用于所有三类问卷。

但答案库也有缺点。同一资料来源警告说，过时的答案库比没有答案库风险更大。

想象一下，粘贴一条在公司更换基础设施提供商之前写下的答案，客户依赖它并签署了合同。从那一刻起，错误的答案就成了留在客户记录中的承诺，一旦真相大白，你的公司可能会被视为违背了对客户的承诺。

因此，答案库中的每一条目都需要有负责人和审查日期。

在客户提出要求之前先做好准备

Drata 指出，问卷对本已人手不足的安全团队来说是一种负担。因此，一些公司会提前向重要潜在客户发送已完成的标准化问卷，以回答常见问题。

据 Drata 称，主动分享这些文档既节省时间，又通过展示透明度来建立信任。

如果你的公司还没有任何材料，CSA STAR Level 1 是一个低成本的起点：它是一项使用 CAIQ v4 的自我评估，免费且发布在云安全联盟（Cloud Security Alliance）注册表中。

将报告、证书、已完成的 CAIQ 以及该项目的数据流图打包成一个资料包，在项目启动会上发送。

导致提交材料被退回的错误

第一个错误是在客户需要看到长期持续维护的控制措施时，提交了 Type 1 报告。第二个错误是在未将 ISO 27001 证书的范围与实际系统核对的情况下就提交证书。第三个错误是在没有任何证据的情况下回答“是”，迫使客户再次询问，并多花一轮邮件往来。

另一个要避免的错误是 FDE 为了省时而独自作答。你了解系统，但安全承诺是整个公司的承诺。在不确定的地方，写上“部分满足”并注明范围，然后交给有权限的人确认。

如果你想转型为 FDE，这项技能应该写进你的简历，因为安全审查所花的时间可能比找到合适的人还要长。阅读职位描述时，请留意“安全审查”、“供应商评估”或“SOC 2”等字眼。

在简历上，要描述具体的成果，例如你如何对问卷进行分类处理、将审查时间缩短了多少，而不是只写“熟悉安全”。

下次当一份冗长的电子表格出现在你的收件箱时，不要从第一行开始做。先弄清楚哪些证据已经存在、其覆盖范围有多大，然后再处理剩下的空白部分。
