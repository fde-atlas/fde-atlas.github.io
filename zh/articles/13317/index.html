什么是前沿部署工程师？

前沿部署工程师在客户的环境中工作：找到真实的工作流程，基于实时数据交付一个可运行的系统，对其进行加固并交付。首先是工程师，其次是面向客户。这份工作涉及什么 · FDE 与解决方案工程师的对比

三个构建项目，及其局限性。

每个项目都明确标注了它的实际性质。没有任何一个被包装成客户部署项目，并且每个项目都说明了它尚未证明的内容。

  • Open source · public repo + live demo

    CiteRAG

    Python · FastAPI · LlamaIndex · evalsCitation-grounded RAG with the evaluation built in: hybrid retrieval, per-citation verification, and a golden set that runs against the hosted API.
    • 我负责的部分
    • 检索流水线、引用验证、评测框架、API、部署。
    • 值得追问的权衡
    • 每条引用都会经过一次独立的 LLM 验证。这会增加延迟（已列入已知局限清单），以换取捕获不支持答案的引用。
    • 已知局限
    • 每个进程只有一个内存索引；除非使用自动种子或外部存储，否则重启会丢失索引。引用验证以顺序 LLM 调用方式运行，因此会增加延迟。黄金集仅覆盖一个小型演示语料库，而非客户的文档。
    • 生产边界
    • 需要持久化向量存储、并行验证，以及基于真实客户问题构建的黄金集。
  • In development · live demo

    SupportPilot

    Next.js · Supabase · RAG · approvalsAn AI support workspace: cited answers from help-centre content, a human approval queue for risky drafts, golden-question evals and an audit log on every AI decision.
    • 我负责的部分
    • 产品、RAG 流水线、审批工作流、评测运行器、小组件。
    • 值得追问的权衡
    • 生产模式采用“失败即关闭”策略。如果身份验证、速率限制或机器人验证未配置，它会拒绝提供服务，而不是退回到演示行为。
    • 已知局限
    • 尚未有真实的客户流量，因此没有可报告的分流率或满意度数据。多用户 RLS 已在本地测试；真实的多租户验证仍需要一个干净的项目。
    • 生产边界
    • 在做出任何效果声明之前，需要与一个支持团队进行受控试点，并在固定时间窗口内进行测量。
  • Hackathon build · AMD Developer Hackathon

    Autopsy

    Multi-agent orchestration · AMD MI300XSix specialised agents per mode across four modes research in parallel, challenge each other, then a synthesiser writes one verdict in about 22 seconds.
    • 我负责的部分
    • Agent 角色、编排、辩论与综合流程、UI。
    • 值得追问的权衡
    • 整个辩论在一块 MI300X 上约 22 秒内完成。结论质量尚无基准测试，案例研究中也明确说明了这一点。
    • 已知局限
    • 尚无针对专家分析的结论质量基准测试；它展示的是编排能力，而非研究准确性。
    • 生产边界
    • 需要一个针对已知企业失败案例的评分评估集，其结论才能被信赖。

常见问题。

  • 前沿部署工程师日常做什么？前沿部署工程师界定真实的客户问题，在客户环境中编写生产代码，调试集成（数据、认证、API），交付运维人员可运行的系统，并编写交接文档，确保项目在合作结束后仍能持续运行。
  • Anil Pervaiz 作为 FDE 专注于什么领域？包括 AI Agent、基于引用的 RAG 以及现代 Web 技术栈上的自动化，并把那些不起眼但重要的部分做扎实：评测、人工审批流程、审计日志，以及为每个项目编写明确的生产边界。
