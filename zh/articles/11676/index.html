面向 FDE 的 Agent 系统扩展（2025）详解

原标题：Scaling Agent Systems (2025) Explained for FDEs

FDE Interviews · 2026-10-18 · 约 4 分钟读完

摘要

这篇论文通过只改变协调结构、固定提示词、工具和总 token 预算，比较单 Agent 与四种多 Agent 架构在六个交互式基准上的表现。结果显示效果高度依赖任务：Finance-Agent 上中心化协调提升 80.8%，而 PlanCraft 上所有多 Agent 架构下降 39%–70%，整体平均变化仅 -0.3%。唯一在所有稳健性检验中成立的是能力饱和效应：单 Agent 得分超过约 45% 时，增加 Agent 往往有害。作者据此给出选型规则，并提醒回归解释力有限（R² 约 0.4），部分结论不显著。

要点

  • 实验固定提示词、工具与约 4,800 token 预算，只改变协调结构。
  • 覆盖 9 个模型、6 个基准、260 种配置。
  • Finance-Agent 中心化提升 80.8%，PlanCraft 多 Agent 全部下降。
  • 单 Agent 得分超约 45% 时加 Agent 通常有害。
  • 并行时应有中心检查者，避免无审核拼接输出。

一分钟读完这篇论文

多智能体系统很流行，声称它们没用的论文也很流行。这篇论文试图通过只改变协调结构来弄清它们何时有用。

作者比较了五种架构。单个 agent 运行一个循环。独立智能体并行工作，输出直接拼接，不做检查。去中心化智能体进行点对点辩论。中心化子智能体向一个负责分解任务并检查结果的编排者汇报。混合架构在编排者基础上增加点对点消息。每种配置使用相同的提示词、相同的工具和匹配的总 token 预算（平均每次试验约 4,800 个 token），因此一组智能体分摊的是单个智能体独自花费的预算。

他们运行了 260 种配置：来自 OpenAI、Google 和 Anthropic 的九个模型（Claude Sonnet 3.7 因弃用退出了两个 基准测试），在六个因需要真实交互而入选的基准上进行：BrowseComp-Plus（网络研究）、Finance-Agent、PlanCraft（Minecraft 合成计划）、Workbench（商业工具）、SWE-bench Verified 和 Terminal-Bench。

结果高度依赖于任务。在 Finance-Agent 上，分析天然可分为新闻、财报和运营，中心化协调使结果提升了 80.8%。在 PlanCraft 上，每一步都依赖上一步，所有多智能体架构都表现更差，降幅在 39% 到 70% 之间。在其他任务上，影响很小。综合所有情况，平均变化为 -0.3%。

他们随后拟合了一个回归模型来解释这些影响并得出规则：当单个智能体的得分已超过约 45% 时，保持单智能体；预期工具密集型任务会受协调开销拖累；优先选择带有中央检查器的架构以限制错误传播。

研究笔记：问题、方法与结果

多智能体相对单个智能体的最佳与最差结果：Finance-Agent 上的中心化架构，PlanCraft 上的独立架构

在全部六个基准和四种架构上，增加智能体带来的平均相对变化

在匹配 token 预算下，混合架构相对单个智能体的每任务平均轮次

团队添加智能体（编排者、辩论者、并行工作者）是因为这似乎有帮助，但已发表的比较在改变架构的同时也改变了提示词、工具和算力，而且大多在集成很容易的静态基准上测试。没人能说清在真实的智能体任务上协调何时划算。

固定除协调之外的一切。用相同的提示词和工具以及匹配的 token 预算，运行单个智能体和四种多智能体拓扑（独立、去中心化、中心化、混合），覆盖三个家族的九个模型和六个智能体基准，然后对模型能力、任务属性和协调指标拟合回归。

效果范围从 +80.8%（集中式，Finance-Agent）到 -70.0%（独立式，PlanCraft）；总体均值为 -0.3%。当单 Agent 得分已超过约 45% 时，多 Agent 配置往往表现更差。回归模型在 87% 的留出配置上选出了最佳架构，但其 R² 仅为 0.37 到 0.41，而且论文自身的稳健性检验表明，能力饱和是唯一站得住脚的结论。

这对 FDE 意味着什么

客户常常要求“一个 Agent 团队”，因为这听起来很强大。这篇论文为你提供了反驳的依据，以及在合适时说“是”的底气。

从单个 Agent 开始并加以测量。 如果一个配备良好工具的单 Agent 已经能处理大多数情况，论文发现增加 Agent 往往会带来负面影响。能力饱和效应是唯一经受住作者所有稳健性检验的发现。

当任务可拆分为独立流时再增加 Agent。 大幅提升出现在子任务可以分开运行再合并的场景：跨新闻、财报和运营的金融分析。而在顺序任务中——每一步都会改变下一步所依赖的状态——每种 多 Agent 设计都表现更差。

为协调预留预算。 在固定 token 预算下，混合架构平均需要 44.3 轮，而单 Agent 只需 7.2 轮，每千 token 的成功次数从 67.7 降至 13.6。如果预算不固定，协调消耗的是金钱而非准确性。

在中间设置一个检查者。 输出未经审核直接拼接的独立 Agent 整体表现最差。如果要并行化，就要有东西来验证和合并。

阅读论文中那些看似精确的数字时要谨慎。这些阈值来自一个仅能解释约 40% 方差的回归，其几个核心效应在论文自身的检验下并不显著，而且两个 基准 中每个配置只用了 20 个任务。
