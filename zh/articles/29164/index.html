Private-Deployment-Gateway

FDE中国社区 · 2026-07-12 · 约 4 分钟读完

摘要

本文介绍 FDE中国社区发布的 Private-Deployment-Gateway 技能包（v1.1，成熟度 usable），面向国内政企私有化、国产化（信创）、数据不出域及 PoC 转生产等场景，给出一条可复用的交付路径。方法论分三层：先用 Dify/MaxKB 等开箱工具快速验证，再小范围定制，最后用 FastAPI 加网关和监控做工程化落地。AI Gateway 负责统一鉴权、模型路由、审计、限流与内容安全。技能包定义了 PoC 准备到复盘资产化的阶段门控（如生产门禁要求 evaluation.md 指标不低于 80%）、FDE 与 AIBP 等角色的协作接口，并提示三个常见误区：PoC 工具直接上生产、缺少网关审计、忽略国产化兼容。交付物包括架构图、部署清单、Gateway 配置、上线检查表和运维 Runbook，可导入 Claude、Cursor 等支持 Agent Skills 的工具。

要点

  • 面向政企私有化、信创、数据不出域与 PoC 转生产四类场景。
  • 三层路径：开箱工具验证、小范围定制、FastAPI 加网关的工程化落地。
  • AI Gateway 统一鉴权、模型路由、审计、限流与内容安全。
  • 阶段门控要求生产上线前 evaluation.md 指标不低于 80%。
  • 常见误区：PoC 工具直接上生产、无网关审计、忽略国产化兼容。

常见问题 FAQ

Q1：执行【Private-Deployment-Gateway】时如何避免「PoC 工具直接上生产」？

A：按 README 方法论逐步执行，在周度 Demo 展示阶段性交付物；若 PoC 材料不齐，先输出「待验证清单」再推进。

Q2：私有化/信创/等保环境下有哪些额外约束？

A：在 prompt 约束段明确部署形态；涉及数据不出域、国产化组件、审计日志时同步引用 Private-Deployment-Gateway 与 RBAC-Audit。

Q3：与 AIBP 分工边界不清怎么办？

A：回到 AIBP-Collaboration-Playbook 更新 RACI；AIBP 负责 Ground Truth 与业务验收，FDE 负责可交付技术资产。

Q4：PoC 通过后如何衔接到 Beta/生产？

A：输出物中标注下一阶段 Skill（如 RAG-Evaluation→Private-Deployment-Gateway→FDE-Adoption-Growth），并在 checklist 触发上线门禁。
