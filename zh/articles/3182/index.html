AIEWF 每日快报：循环、软件工厂与前沿部署工程师

原标题：AIEWF Daily Dispatch: Loops, Software Factories & Forward Deployed Engineers

Latent Space · 2026-07-01 · 约 5 分钟读完

循环、循环、还是循环。“循环”这个词主导了 AI Engineer World’s Fair 第二天——也是首个完整的主题演讲和分论坛日——的讨论。也许是因为提前预知了大家会聊什么，AIEWF 联合创始人 swyx 将他的开场演讲命名为“Loopcraft：叠加循环的艺术”。

swyx 开场先谈了 AI 工程自 2022 年以来的演进：从聊天，到工具，再到目标。“如今，我们都在做自动化，”他补充道，“我们都在做定时任务和循环。”

Keycard 的技术成员 Allie Howe 随后介绍了当天主舞台的主题：软件工厂。她引用了 Geoffrey Huntley 那篇颇具影响力的文章“everything is a ralph loop”，该理论讲的是通过针对同一份规格说明反复重启，把一个 AI 编程 Agent 变成持续工作的工人。

微软的 Pablo Castro 接着介绍了 Foundry，该公司的“AI 应用与 Agent 工厂”。他声称，当人和 Agent 协同工作时，就会出现一个“学习循环”。

接下来是 OpenAI 的 Alexander Embiricos 和 Romain Huet，他们重点介绍了该公司的编程 Agent Codex。他们提出的一个观点是，通过循环使用多个 Agent 可以提升生产力。

“今天会有很多关于循环的讨论，”Embiricos 说。“如果你不仅能让 Agent 连接到你要做的工作，还能连接到为什么要做这些工作，那就能让 Agent 开始承担多得多的工作。然后，如果你能把它连接到后续要做的事——审查和部署——那就能帮它落地多得多的工作。”

由此过渡到 Peter Steinberger 的演讲，他是 OpenClaw 的“ClawFather”，现在就职于 OpenAI。他同样对循环全情投入，指出他通过设计循环来管理 Agent。他补充说，决定该关注什么是他如今面临的主要挑战——而未来在于“更好的循环”来帮助解决这一问题。

软件工厂

所有这些关于循环的讨论自然引出了“软件工厂”的概念，这是来自一家名为 Factory 的公司的 Tereza Tížková 演讲的主题。她将软件工厂定义为“以自主方式开发软件的整个循环、整个生命周期”。她补充说，这不仅仅意味着写代码，还包括“收集所有信号，对用户反馈和日志做出响应，确定优先级，然后统筹一切”。

Warp 的 Zach Lloyd 也谈到了软件工厂；实际上，他的论点是“软件工程将变成工厂工程”。在 Lloyd 的框架中，循环是为了改进系统。

在 Tížková 和 Lloyd 的演讲中，重点都是让 Agent 替你完成构建。用 Lloyd 的话说：“你要构建的是那个构建产品的东西。”

之后，我来到 AIEWF 展厅的 Warp 展位，与 Lloyd 聊了聊软件工厂。我特别想知道，Warp 最初是一款面向开发者的 CLI 工具，为什么如今转型成了一个“软件工厂”平台——在这个平台上，开发者 supposedly 不再需要亲自写代码了。

“你可以这样理解工厂：选择你的代码仓库，选择你想要自动化的生命周期环节，选择你希望人类以何种方式介入其中，”Lloyd 告诉我。“不同的组织和代码库会有不同的偏好，比如，是完全自动化代码审查，还是让人类来做复杂的编码工作，诸如此类。”

我指出，“工厂”这个词可能会让许多开发者感到反感，因为它暗示着机械化的重复劳动——与我们刚刚经历的那个充满创造力的编码时代大不相同。Lloyd 承认这是一个挑战，但他认为软件工厂将成为一种新的工程学科——而且它仍然需要解决问题的能力。

“无论好坏，这些系统的能力如此强大，加速效果如此显著，以至于纯手工编写代码……我认为它不会在太长时间内还有意义，”他说。

（想了解更多 Zach Lloyd 关于软件工厂的观点，请关注即将发布的 Latent Space 访谈。）

前沿部署工程师

与循环和软件工厂相关的是，今天 AIEWF 的另一个主题是时下热门的新角色——前沿部署工程师。在 对 Sierra Agent 工程负责人 Natalie Meurer 的访谈 中，我确认了 FDE 有时也被称为“Agent 工程师”。其核心在于从开发的角度帮助组织适应 AI Agent。

Meurer 指出，如今将 AI 集成到企业中的大量工作都在于编排 Agent。

“在实践中，大多数针对客户的工作发生在编排层，而不是模型本身，”她告诉我。

Cursor 的前沿部署工程副总裁 Pauline Brunet 今天也在 AIEWF 主持了一场演讲，她将 FDE 定位为向软件工厂转型的一部分。“我们与您的组织合作，共同设计和共同构建您的 AI 软件工厂，”她说。“我们改变您在整个生命周期中设计、开发和维护软件的方式。”

（更多来自 Brunet 的洞见将出现在即将推出的问答中。）

开源 AI

今天 AIEWF 的另一个关键主题是开源 AI 的崛起。颇具看点的新兴中国公司 Z.ai 的负责人 Zixuan Li 原定将在大会上亮相。由于旅行问题，他无法亲临现场。不过他还是进行了线上演讲，重点介绍了该公司突破性的开源 LLM GLM-5.2——其“面向长周期任务的旗舰模型”。

他还介绍了 ZCode，一个“支持所有前沿模型”的 harness。他特别将其与 OpenAI 的 Codex 进行了比较。

随后，HuggingFace 的 Thomas Wolf 采访了中国公司 MiniMax 的 Olive Song，该公司最近发布了其最新的开放权重模型 M3。

开源 AI 是本地 AI 日益流行的一个重要原因。Ahmad Osman 是 Osmantic 的创始人，该公司致力于构建用于部署和运营本地 AI 系统的开源软件。他今天接受我们的采访时指出，开放模型近来有了显著改进。

“架构正变得越来越高效，许多微小的改进不断累积，”他说。“一旦前沿实验室证明了某种能力是可行的，开源生态系统就可以从中倒推，找到更高效地复现它的方法。”
