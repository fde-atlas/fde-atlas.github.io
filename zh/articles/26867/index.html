前沿部署团队的面孔：Fran Marmousez

原标题：The Faces of the Forward Deployed Team: Fran Marmousez

Cresta · 2026-10-15 · 约 6 分钟读完

摘要

Cresta 访谈其澳大利亚办公室的前沿部署工程师 Fran Marmousez。她曾在 Google Cloud 工作五年多，担任日本及亚太区 AI Agents 负责人。访谈涵盖对话式 AI 自 2020 年以来的变化：LLM 取代了意图列表和固定流程，Agent 依据目标自主决策。她结合电信公司全球客服中心的评测经验指出，CSAT 下降未必说明 Agent 有问题，指标需结合场景，如今可用 LLM 作为评判者分析对话记录。她还谈到企业常误以为 LLM 足够聪明而无需详细需求，实际上应分析现有客服对话，了解用户真实提问和升级人工的原因。她选择 Cresta 是因为前沿部署团队可自行修复产品缺陷，并介绍了改进 Compass 助手的首个项目。

要点

  • Fran Marmousez 曾在 Google Cloud 任职五年多，负责日本及亚太区 AI Agents。
  • LLM 让意图列表和固定对话流程成为历史，Agent 按目标自主行动。
  • CSAT 下降不一定归咎于 Agent，评测指标需结合具体场景判断。
  • 企业仍需详细需求，并应分析历史客服对话中的提问与升级原因。
  • Cresta 的前沿部署团队可直接修复发现的产品问题，而非仅提交报告。

欢迎阅读《前沿部署团队风采》第一期，本栏目聚焦那些将 AI Agent 从有前景的想法变为客户生产现实的团队成员。

本期我们聚焦 Fran Marmousez，她是一名前沿部署工程师（FDE），常驻 Cresta 澳大利亚办公室。

在加入 Cresta 之前，Fran 在 Google Cloud 工作了五年多，最近担任的职位是日本及亚太区 AI Agent 负责人。

在此期间，她为重要客户领导过生成式 AI 和对话式 AI 项目的技术交付。其中包括为一家电信公司的联络中心实施的多年期项目，该联络中心拥有数千名坐席，服务数百万客户。

我们聊了自她 2020 年进入这个领域以来对话式 AI 发生的变化、AI 质量评估中隐藏的陷阱，以及客户在部署 Agent 时常犯的错误。我们还聊到了她为什么从 Google 跳槽到 Cresta。

请继续阅读，看看她分享了什么。

你从 2020 年起就从事对话式 AI 和生成式 AI 工作，这让你对这个领域有独特的视角。这些年来最大的变化是什么？

就在几年前，构建一个基础的聊天机器人还是一项非常繁重的工作。

你必须定义我们所说的意图（intent），也就是用户可能询问的每一种操作。然后针对每个意图，你得想出尽可能多的表达同一件事的说法，再用所有这些变体来训练分类模型。

现在由 LLM 来接管这项工作。你告诉 LLM 用户可以做什么，比如付款，LLM 就能理解客户提出该请求的多种方式，无需意图列表，也无需训练变体。

Agentic AI 也给了我们更大的灵活性。

过去我们构建的是僵化的流程：一旦客户说了某句话，就会进入一个按固定顺序提问的流程，期待得到“是”、“否”或其他非常具体的回答。每条路径都必须提前规划好。

现在我们给 Agent 下达关于要完成什么目标的指令，由 Agent 自己决定如何达成。

如果某个步骤不需要，比如客户已经提供了相关信息，Agent 就会跳过而不是再次询问。这种方式给客户带来更好的体验，对我们来说也比规划每一种可能的流程组合要容易得多。

我们构建 Agent 的方式也发生了变化。例如在 Cresta，我们有 Conductor，你只需提供需求以及希望 Agent 做什么，AI 就会帮助开发者构建 Agent，并与他们一起迭代。

你曾在一家电信公司的全球联络中心花了几年时间衡量和改进 AI 质量。这段经历让你对评估 AI 质量有了哪些认识？

如今构建一个 AI Agent 已经非常容易，真正的问题在于它是否足够好、能否用于生产环境。而回答这个问题的唯一方法就是评测。

在电信公司工作时，我了解到评测一个 AI Agent 有很多方法，也有很多陷阱。例如在客服领域，我们有很多想要提升的指标，比如客户满意度。

你可能希望当客户满意度（CSAT）下降时，说明 AI Agent 出了问题，但 CSAT 下降并不总是意味着 AI Agent 有错。有些用例的 CSAT 本来就会一直偏低。

如果你的网络断了，AI Agent 把所有事情都做对了，告诉你服务明天就会恢复，你在调查问卷里也不会说自己满意。

有时情况甚至更极端，比如一场雷暴同时导致所有人的网络中断。在这些时刻，AI Agent 反而最有用，因为同时联系你的人太多，即使指标看起来很难看，你的联络中心本来也无法承受这样的话务量。

说到底，正确的指标取决于具体情境。

如今我们可以用 LLM 作为评判者来审阅对话记录，理解其中发生了什么。我们在 Cresta AI Agent 中采用这种方法，这让评测比过去容易得多。

你看到的公司对 AI Agent 的期望与它实际能力之间，最常见的差距是什么？

有些公司认为，既然 AI Agent 运行在 LLM 之上，而 LLM 很聪明，就不再需要提供详细的需求了。

这种假设并不成立。你仍然需要了解你的公司是如何运作的、你的语气风格是什么，以及在特定情况下你希望如何回复客户。

而且，需求也不是全部。我们有时会跳过分析已有对话这一步。很可能已经有关于同一主题的人工客服对话，而这些对话之所以重要有两个原因。

第一，它们展示了客户实际会问什么。

你可以针对理想路径进行构建，但有趣的部分在于客户过程中提到的各种旁支问题和其他问题。仅凭需求构建的 AI Agent 会漏掉这些。

第二，它们展示了如今客户为什么会升级转人工。如果我们不解决这些升级原因，新的 AI Agent 不会比已经在生产环境中的那一个更有帮助。

在 Cresta，我们有 Insights 来进行这类分析，Insights 会呈现最常见的问题以及用户升级转人工的原因。

是什么吸引你从 Google 跳槽到 Cresta？

在 Google，我也会看到产品缺陷和 bug，但我只能提交功能请求或 bug 报告。请求由另一个团队处理，后续如何发展我完全无法掌控。

而在 Cresta，前沿部署团队被鼓励去修复他们发现的问题。

当我们在与客户合作时发现缺口或 Bug，我们会评估能否亲自把修复加入产品，团队也会积极推动我们去尝试。

这让我们能够快速地为整个用户群改进产品。

我们可以做出修改、展示给客户，并在不断学习中持续打磨，而不必等待其他团队的排期。其他每一位客户也都能从中受益。

在 Cresta 有没有让你特别自豪的项目？

我参与的第一个项目是改进Compass，这是内置于 Cresta 用户体验中的一款 AI 助手。

它帮助客户获取答案、查找相关文档，并在工作流的各个步骤之间切换，而无需自己摸索产品。

Compass 利用上下文来准确回答问题，用户无需重复说明。例如，我们会查看用户当前在平台中的页面。如果 Compass 无法给出好的答案，它会主动提出创建支持工单。

我在 Compass 上的工作包括：把从真实客户对话中学到的经验用于优化助手的回答方式，同时审查 Compass 处理真实客户对话的表现，并修复它给出糟糕或不完整答案的情况。

这些优化帮助更多客户快速获得准确的答案，也减轻了支持团队的工单负担，让他们有时间认真处理每一个剩余问题，而不是匆忙应付队列。

总的来说，Compass 是一个绝佳的起步项目。客户会提出关于我们产品的各种问题，因此我很快对 Cresta 有了深入了解。

对于考虑加入 Cresta 前沿部署团队的人，你有什么建议？

目前 AI 公司的空缺职位并不少，但这并不意味着这些职位就一定有回报或影响力。许多职位实际上只涉及浅层工作，比如接入别人的模型或调整提示词，几乎没有真正的自主权。

Cresta 的 FDE 职位的独特之处在于，它结合了产品工程和面向客户的工作。这意味着你既能贴近客户、发现真正的问题所在，又有能力去构建修复方案、发布上线，并观察实际效果。

随着时间推移，我们与客户的亲身协作正是赢得他们对产品信任的关键。这让人非常有成就感。

最后我想说的是，我们的团队正在快速扩张。这意味着你加入的时机，恰好能真正参与塑造我们的标准、工具、技术方向以及与客户合作的方式，而不是仅仅继承别人已经建好的流程。

我们的前沿部署团队正在招聘，我们期待与你见面。欢迎查看我们的空缺职位，看看是否有适合你的机会。
