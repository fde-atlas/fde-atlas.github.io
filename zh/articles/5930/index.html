摘要

本文梳理 Figma 创始前沿部署工程师岗位的面试准备要点。该岗位隶属产品与工程团队，面向企业客户，围绕设计转代码工作流，涉及 Make、Code Connect 与 Agent 工具，要求将客户设计系统接入生产代码库。文章指出公开面试流程数据有限，未公布具体轮次，也无可验证的薪资区间，建议以官方招聘信息为准。备考重点包括 TypeScript 或 Python 调试、企业设计系统集成、客户需求挖掘与安全访问，以及调试生成界面与客户实际组件、权限和开发实践之间的边界。

要点

  • Figma 开设创始 FDE 岗位，属产品与工程团队，面向企业客户。
  • 工作核心是设计转代码流程，涉及 Make、Code Connect 与 Agent 工具。
  • 面试轮次未公开，备考方向为 TypeScript/Python、系统集成与客户沟通。
  • 文章未提供可验证的薪资区间，需以官方招聘页为准。
  • 关键能力是调试生成界面与客户组件、权限及开发实践的边界。

编码与工程技艺

基础解析混乱的真实世界数据客户的文件往往很脏：引号不一致、表头缺失、垃圾行、编码“说谎”。这项工作的要点是防御性地解析，跳过并记录坏行而不是中止整个批次，并保持解析逻辑纯净、与业务逻辑分离，从而保持可测试和确定性。这正是早期 FDE 数据接入工作的大部分内容。

基础真正重要的 Big-O在部署现场，Big-O 不是白板上的谜题；它是唯一能告诉你客户的数据是否适合你所选方案的计算。这项技能在于找出在客户规模下占主导地位的项，知道暴力法何时失效、何时需要索引或 ANN，并识别常数因子和内存何时比指数更能决定结果。

生产环境中的 AI 系统设计

基础从概念验证到生产环境在演示中正确回答了一个问题的 notebook 并不是交付物。生产环境是那些不起眼的工作，它把一次性的成功变成客户可以在你不在场的情况下运行、信任和运维的系统。弥合这一差距正是 FDE 工作的大部分内容。

基础重试、指数退避与抖动当调用因瞬时错误而失败时，立即重试是最糟糕的做法：它会给本已不堪重负的服务增加负载，并让所有客户端同步形成踩踏。指数退避可以拉开重试的间隔，而抖动则让客户端去同步，避免它们步调一致地同时到达。

检索与智能体

基础检索增强生成（RAG）RAG 通过在查询时检索相关段落并将其放入提示词中，使语言模型基于你自己的数据，从而让模型依据真实来源而非记忆来回答。它几乎是所有企业级 FDE 部署的默认模式，这也是为什么几乎每个循环都会测试它。

基础向量数据库向量数据库将嵌入与元数据一起存储，并使用近似索引快速回答最近邻查询。真正的面试问题不是它们如何工作，而是你何时真正需要一个向量数据库，而不是一个库或带 pgvector 的普通 Postgres。

面向客户的技艺

基础需求挖掘需求挖掘是找出隐藏在客户明确诉求背后的真实问题的工作。客户交给你的请求（“给我们做一个聊天机器人”）几乎从来不是真正的需求；能够挖掘出谁在使用它、成功是什么样子、实际存在哪些数据、以及为什么截止日期是截止日期的 FDE，才是能交付出人们真正会使用的东西的人。

基础篇界定模糊问题界定一个开放式提示（“某城市想缩短911响应时间”）是一种结构化操作，而非灵光一现：澄清输入和约束条件，大声说出你的假设，划分出最小有用的 MVP，明确你所选择的准确性/成本/延迟权衡，并规划失败时的应对方案。直接跳入某个模型或架构是候选人在模拟轮次中最常见的被淘汰原因。

基础篇向非工程师解释权衡高管并不关心你选择了 RAG 还是微调；他们关心成本、上线时间以及可能出错的地方。翻译技术权衡意味着将准确性、成本和延迟转化为企业实际正在做出的决策，用他们的语言将每个选项框定为一个带有后果的选择，并回答他们最终都会问的问题：为什么 AI 每次给出的答案都不同，以及为什么这不是一个 bug。
