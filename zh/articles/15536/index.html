FDE 候选人 AI 辅助编程面试技巧

原标题：AI-assisted coding interview tips for FDE candidates

FDE Interview Prep · 2026-09-25 · 约 15 分钟读完

摘要

这篇文章面向允许使用 AI 助手的 FDE 编程面试，核心观点是：代码本身不再稀缺，面试官考察的是候选人的判断力。作者给出可操作的方法：先口头梳理问题范围再提问，分小步提示词，每条建议先读、跑、测再决定取舍；模型出错时先在小样例上复现、精确指出错误，再选择自己修或重新提示。文中用合并时间区间的例子演示了如何发现模型未排序、边界条件错误两个 bug。文章还引用 Ramp、Sierra、Meta 等公司的面试形式，并列举了静默提示词、盲信模型自测、使用未授权工具等常见失误。

要点

  • 面试考察的是判断力而非代码产出。
  • 提示词前先口头明确问题范围和边界条件。
  • 每条 AI 建议须先读、跑、自选样例测试再接受。
  • 模型出错时精确指出错误，两次重试无果就自己写。
  • 各公司 AI 使用规则不同，需提前向招聘方确认。

面试官刚刚告诉你可以使用 AI 助手，而你的第一反应是显而易见的：如果模型能写代码，那他们到底在考察什么？答案是你：你提出什么要求、你检查什么、你拒绝接受什么。这篇文章会告诉你每一步该说什么、先验证再接受的习惯，以及模型出错时的应对计划。它涵盖一轮面试；FDE 面试指南则覆盖整个流程。

简短回答

在 AI 辅助编程面试中，代码是廉价的，所以你的判断力才是真正展现出来的东西。在输入提示词之前，先大声界定问题范围。用小而可检查的步骤进行提示。在采纳每一条建议之前先阅读并测试它，并说明你为什么保留或丢弃它。当模型出错时，在一个小案例上发现它，指出错误所在，然后修复它。

Ramp 的 Leo Mehr（YouTube 自动生成的英文字幕）发布者dearCC（Clara Shih），YouTube来源类型录制的演讲或访谈 Sierra 表示，其 AI 原生的现场面试让他们更容易评估候选人的主动性（卡住时是否会调整方向？）和判断力（如何在限定时间内界定要构建的内容？）。来源 2AI 原生面试（Vijay Iyengar、Arya Asemanfar、Angie Wang）发布者Sierra来源类型公司博客

当允许使用助手时，他们能看到什么

面试官无法看到你的内心。在现场面试中，他们看到四样东西；在带回家构建任务中，他们事后通过你展示和解释的内容看到同样的四样东西：

  • 你在第一次输入提示词之前做了什么。 你是提出了问题并陈述了计划，还是直接把题目粘贴进去？
  • 你提出了什么要求。 一个小而具体的请求表明你知道自己想要什么。“解决这个问题”则表明你不知道。
  • 你如何处理输出。 你是阅读了它、运行了它并测试了它，还是直接接受然后继续？
  • 你说了什么。 你的讲述是他们了解你推理过程的唯一途径。

一个名为 Axium Industries 的组织的公开 GitHub 仓库描述了一场现场面试，其中面试官扮演客户，候选人使用任意编程 Agent 构建一个小项目。来源 3第二轮面试——前沿部署工程师（AI）发布者Axium Industries（GitHub 组织）来源类型公司招聘页面 它列出了评分标准：客户直觉、Agent 架构、判断力与验证，以及沟通能力。来源 3第二轮面试——前沿部署工程师（AI）发布者Axium Industries（GitHub 组织）来源类型公司招聘页面 这只是一个组织的仓库，并非标准，但请注意，这些维度中没有一个是“写了代码”。

本文的其余部分是我们的方法，用于让这四件事变得可见。这是我们如何辅导候选人的方式，而不是雇主的评分标准。

在你输入提示词之前：口头界定问题范围

你最有力的信号出现在模型做任何事情之前。像没有助手时那样开始：复述问题，询问输入和边界情况，并说明“完成”是什么样子。

像这样说：

  • “在我输入任何提示词之前，让我先复述一下：给定一组预订时间窗口，将重叠的窗口合并后返回。”
  • “两个问题。输入是有序的吗？还有，如果一个预订恰好在下一个预订开始时结束，这算重叠还是两个首尾相接的预订？”
  • “这是我的计划。我会让助手起草合并逻辑，我自己写三个测试用例，并在信任它之前检查边界情况。”

假设面试官回答：“无序。首尾相接的预订保持独立。”现在你知道了两件模型不知道的事情。在输入提示词之前先写三个测试：一组乱序的时间对、两个相接的窗口、一个空列表。

最后那句话最重要。它告诉面试官，助手是为你工作的，而且你已经知道将如何评判它的输出。Sierra 表示，这会在现场面试之前告诉候选人：构建时缩小范围是可以的，跳过 CRUD 和鉴权这类样板代码、专注于独特部分也是可以的。Source 2The AI-native interview (Vijay Iyengar, Arya Asemanfar, Angie Wang)PublisherSierraSource typecompany blog 口头界定范围就是展示你知道哪一部分是独特的方式。

在面试官面前输入提示词

Meta 表示，特定职位的候选人在技术面试中可以在 CoderPad 内使用经授权的 AI 助手。Source 4Meta Jobs Hiring ProcessPublisherMetaSource typecompany hiring page 在这样的共享编辑器中，要假设面试官能看到你的提示词，写提示词时要当作他们正在你身后阅读。

能体现判断力的提示词

  • 一次只要求一个部分：一个函数、一个测试、一个解析器。而不是整个解决方案。
  • 把你的决策写进提示词：“输入可能是无序的。结束时间是开区间。”
  • 说明约束条件：语言版本、不引入新依赖、符合现有代码风格。
  • 单独要求测试或边界情况，以便与你自己的进行对比。
  • 提示词要短到可以大声读出来。

用一句话为每个提示词做解说：“我只要求合并函数，并且我告诉了它输入可能是无序的，因为这是我预计它会遗漏的情况。”

如果面试官离开

并非每种面试形式都有人在旁观看。Sierra 表示，在其 Build 阶段，面试官会离开，让候选人使用自己选择的工具进行构建。Source 2The AI-native interview (Vijay Iyengar, Arya Asemanfar, Angie Wang)PublisherSierraSource typecompany blog 对着空房间解说毫无意义；此时重要的是你之后如何解释自己的决策。

我们的方法：在构建过程中，在 README 中持续维护一份决策日志。每砍掉什么、为什么砍，模型给出的建议中拒绝了什么、为什么拒绝，以及你抓到的 bug 和如何抓到的，各记一行。面试官回来时，带着评审走一遍这份日志，而不是靠回忆。

接受之前先验证

这是让你区别于工具的习惯。每一条建议在被保留之前，都要经过阅读、运行和测试。以下是我们教授的流程：

  • 简要地把它读出来。“它循环一次，当区间重叠时扩展最后一个窗口，否则开启一个新窗口。”
  • 说出它的假设。“它假设输入已按开始时间排序。”
  • 在你自选的小用例上测试。选你预期会出错的用例，而不是提示词里给的那个。
  • 做出决定，并说明理由。“保留，但改一处”或“拒绝，因为……”。

一个完整的示例。你请求合并，助手返回了这段代码：

def merge(windows):
    out = []
    for s, e in windows:
        if out and s <= out[-1][1]:
            last = out[-1]
            last[1] = max(last[1], e)
        else:
            out.append([s, e])
    return out

它读起来不错，提示词中的已排序示例也通过了。现在运行你预期它会漏掉的用例：

merge([(5, 8), (1, 6)])
# returns [[5, 8]]; expected [[1, 8]]

它从不排序，所以后到的较早预订会被吞掉。它还把仅仅相接的区间当作重叠，因为

<=

。面试官告诉过你，前后相接的预订要保持独立，所以这也是错的：

merge([(1, 3), (3, 5)])

返回

[[1, 5]]

.

修复只需两处小改动：遍历

sorted(windows)

，并用

<

.

def merge(windows):
    out = []
    for s, e in sorted(windows):
        if out and s < out[-1][1]:
            last = out[-1]
            last[1] = max(last[1], e)
        else:
            out.append([s, e])
    return out

你在读它的代码之前写的三个测试现在全部通过：

assert merge([(5, 8), (1, 6)]) == [[1, 8]]
touch = [(1, 3), (3, 5)]
assert merge(touch) == [[1, 3], [3, 5]]
assert merge([]) == []

把收尾说出来：“输入已排序，区间端点互斥。两个边界用例都通过，所以我保留它。”面试官刚刚亲眼看到你找出了模型自信写下的两个 bug。这就是信号。

不要相信助手自己写的测试

如果你在模型写完代码后让它写测试，它的测试往往会沿用它的假设：代码里忘记处理未排序输入，测试里大概率也会忘记。在阅读它的代码之前，至少自己写好边界用例的测试。

当模型出错时

它一定会出错，而这是好消息。错误的建议是你展示判断力的最佳机会。关键在于你如何应对。

说出你在做什么。“这看起来不对。在改动任何东西之前，我先在一个小输入上追踪一下。”

精确指出错误。不要说“它有 bug”，而要说“当输入乱序到达时，它会丢失一条预订。”

选择修复还是重新提示，并说明理由。如果修复只需一两行，就自己动手：“修复比解释更快。”如果模型误解了任务，就用失败的用例重新提示：“这是一个你的版本返回错误答案的输入。请重写它以处理未排序的输入。”

知道何时停止提示。 如果重新提示两次仍未解决，就自己动手写。“模型总是漏掉同一种情况，所以这部分我自己来写。”在时间流逝的同时反复纠结于提示，恰恰是缺乏判断力的表现。Sierra 表示，他们会考察候选人在遇到瓶颈时是否会及时调整方向。来源 2The AI-native interview (Vijay Iyengar, Arya Asemanfar, Angie Wang)PublisherSierraSource typecompany blog

模型在面试中出问题的其他方式：

  • 已不存在或从未存在过的 API。 df.append(row) 看起来没问题，但当前的 pandas 已经没有 DataFrame.append() 了；正确的做法是 pd.concat。在基于它构建之前先运行验证，并说“让我确认一下这个调用在我们使用的版本中是否存在。”
  • 悄悄改变的行为。 你让它整理一个函数，而这次“清理”却把返回字典中的 user_id 改名为 userId，导致所有调用方都出问题。把它与你原来的代码做对比：“它改了输出的键名，我要把这部分还原。”
  • 自信的复杂度声明。 它说“这是 O(n log n)”，但它在循环内部调用了 sorted()。自己验证一下：“排序在循环里面，所以每个元素都会执行一次。我要把排序提到前面，只做一次。”

在现有代码库中借助助手工作

一些 AI 辅助的面试环节被描述为从现有代码开始。Blind 上询问 Cohere FDE 现场面试的帖子写道，招聘人员介绍的是一个现有的 Python 代码库和 AI。来源 5Cohere FDE onsite, AI enabled coding round?PublisherBlindSource typecandidate report on Blind Sierra 表示，他们正在试点一种调试面试，候选人需要在一个中等规模的代码库中使用编码 Agent 来改进同事的草稿 PR，并且该环节允许的 AI 使用程度尚未确定。来源 2The AI-native interview (Vijay Iyengar, Arya Asemanfar, Angie Wang)PublisherSierraSource typecompany blog

阅读不是你写的代码是这一环节的核心技能；重构一个长函数以便测试这道免费题目专门训练这一点。这种面试形式的陷阱是还没读代码就开始提示。模型不了解代码库的既有约定，所以会凭空发明新的约定。你应该这样做：

  • 先阅读。 运行测试，找到你的修改应该放在哪里，并指出要模仿的模式：“这里的错误会抛出 FilterError，然后处理器把它映射为 HTTP 400。”
  • 自己编写验收测试。 把你预计模型会漏掉的情况也包含进去。
  • 带着模式去提示。 “给这个处理器添加一个日期过滤器，像 parse_limit 那样对非法输入抛出 FilterError。”
  • 对 diff 负责。 准备好解释它写的任何一行代码，并还原任何你没有要求的内容。

让助手看起来像候选人本人的错误做法

  • 无声提示。 在现场环节中，你输入提示，它给出答案，你直接接受，全程无人开口。纠正方法：每次提示和每个决策都口头说一句话。如果没人看着，决策日志也能起到这个作用。
  • 接受第一稿。 纠正方法：在你选定的案例上运行通过之前，什么都不保留。
  • 把提问外包出去。 在问面试官之前先问模型边界情况有哪些。纠正方法：面试官才是客户；先问他们。
  • 使用不被允许的工具。 Meta 表示未授权任何外部 AI 工具，只允许使用其面试环境中的工具。来源 4Meta Jobs 招聘流程发布方Meta来源类型公司招聘页面纠正方法：询问招聘人员，只使用他们点名的工具。
  • 大声朗读 AI 答案。 GitLab 要求候选人在面试中不要照读 AI 生成的答案。来源 7在面试流程中使用 AI发布方GitLab来源类型公司招聘页面纠正方法：让助手负责代码，说话由你自己来。
  • 拒绝使用它。 如果雇主期望你使用助手，正如 Meta 对部分岗位所说的那样，回避使用反而隐藏了他们想看到的东西。来源 4Meta Jobs 招聘流程发布方Meta来源类型公司招聘页面纠正方法：使用它，并在使用方式中展现你的判断力。

关于 AI 的谈话可能不止于代码。练习 Pro 问题你在日常工作中如何使用 AI 编程工具，又在哪些方面不信任它们？，并用你刚刚展示的习惯来回答：你在哪里信任工具，在哪里进行核查，以及它出错的一次经历。如果助手问题出现在带回家的作业中，请阅读带回家作业可以使用 ChatGPT 或 Claude 吗？

在面试当天之前练习这些内容

这种边做边说的叙述方式第一次做会感觉别扭，所以要在面试之前练习，而不是在面试中。

你的练习环节

  • 选一道编程题并设置计时器。
  • 在输入任何提示词之前，大声说出你的复述、两个问题和你的计划。
  • 在阅读任何生成的代码之前，自己先写出两个边界情况测试。
  • 对每条建议，说出它的假设是什么，以及你是否保留它。
  • 找出模型写出的一个 bug，并说明你是如何发现的。
  • 给自己录音，回听是否有长时间的沉默。

常见问题

在 AI 辅助编程面试中，面试官看重什么？

两家描述过这类面试轮次的雇主都关注你如何与工具协作。Ramp 的工程总监表示，他想看到候选人如何向 Claude 提示以及如何界定问题范围；Sierra 则表示，其 AI 原生现场面试能更容易地评估候选人的主动性和判断力。来源 1什么是前沿部署工程师？（FDE 详解，特邀 Ramp 的 Leo Mehr）（YouTube 自动生成的英文字幕）发布者dearCC (Clara Shih)，YouTube来源类型录制的演讲或访谈来源 2AI 原生面试（Vijay Iyengar、Arya Asemanfar、Angie Wang）发布者Sierra来源类型公司博客

如果面试提供 AI 助手，我应该使用它吗？

应该，当雇主期望你使用时。Meta 的招聘页面表示，特定职位的候选人应在 CoderPad 中使用授权的 AI 助手，且不允许使用任何外部 AI 工具。来源 4Meta Jobs 招聘流程发布者Meta来源类型公司招聘页面

当 AI 助手给我错误的代码时，我该怎么办？

说明你正在检查它，在一个小案例上运行或跟踪它，指出错误所在，然后自己修复，或带着失败的案例重新提示。大声指出错误能展示面试官 otherwise 无法看到的验证习惯。

我可以在面试中使用自己的 AI 工具吗？

只有在雇主允许的情况下才可以。Meta 表示只能使用其面试环境中的工具；OpenAI 的面试指南表示，AI 工具的使用规则因面试而异，不确定的候选人应询问招聘人员。请在面试当天之前询问可以使用哪些工具。来源 4Meta Jobs 招聘流程发布者Meta来源类型公司招聘页面来源 8面试指南发布者OpenAI来源类型公司招聘页面来源 9OpenAI 面试指南（Wayback Machine 存档）发布者OpenAI（由 Internet Archive 存档）来源类型存档的公司页面
