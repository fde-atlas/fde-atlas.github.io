在公网 SaaS 场景中，工程师只需调用几行 API 即可实现大模型原型；但在 2026 中国企业 AI 交付供需全景报告 追踪的政企、金融、国防与高端制造在招岗位中，71% 明确要求内网物理机房与隔离网络交付能力——数据出境与外网连接属于绝对红线。能否在完全断开物理外网的涉密机房、单向安全隔离网闸、以及企业专属虚拟私有云（VPC，Virtual Private Cloud，即企业在云端构建的逻辑隔离专用网络）环境中完成端到端系统构建、安全鉴权与可维护交接（结合 交付实战三部曲 与 企业 IM 与 ERP 接入实战 的工程护栏），是衡量一名 FDE（前线部署工程师）是否具备工业级交付能力的终极分水岭。

企业涉密网络的三大物理与逻辑隔离形态

企业安全基础设施通常呈现以下三种隔离形态，FDE 必须针对不同形态匹配架构：

  • 形态一：物理完全断网机房（Air-Gapped Data Center）：物理切断所有外网网线与无线设备，服务器之间仅通过内部物理专网互联。系统交付物必须做到 100% 离线自包含，严禁任何隐藏的外部依赖下载请求（如 pip 索引、HuggingFace 权重下载或外部 CDN 字体）。
  • 形态二：物理单向安全网闸（Data Diode）：内网与外网之间部署了物理级光纤单向传输网闸（单向发光/单向受光），数据只能单向流入内网，绝无物理回路。系统必须设计专门的单向穿透代理与异步签名回执校验机制，严防因缺乏 HTTP 响应确认而导致的状态悬挂。
  • 形态三：企业虚拟私有云专网（VPC with PrivateLink & Peering）：在公有云或混合云上划定完全隔离的虚拟私有云子网，关闭公网 NAT 网关。所有服务间通信通过 VPC 对等连接（VPC Peering）或专用内网终端节点（Private Endpoint）流转，严守内网合规边界。

涉密 AI 系统端到端拓扑架构规范

涉密 AI 系统必须采用五层物理与逻辑解耦架构：

  • 第一层：业务作业终端与内网统一门户：部署于内网安全受控工作站，通过 SSO 单点登录与双因子认证 (MFA) 接入；
  • 第二层：前置鉴权与敏感数据金库 (Security Vault)：在请求流转至模型前，自动对个人身份信息 (PII) 与涉密字段执行不可逆脱敏，仅在内网金库中保存映射字典；
  • 第三层：确定性状态机护栏 (Agent Harness)：由确定性有限状态机严格驱动多步骤长事务流转，任何大模型输出不得直接触发底层写指令；
  • 第四层：本地私有化开源大模型集群 (Local LLM Cluster)：在离线 GPU 服务器（如国产算力集群或私有算力池）上通过 vLLM/SGLang 挂载量化微调模型权重，提供稳定的离线并发推理能力；
  • 第五层：企业遗留数据与内部知识底座：稠密与稀疏混合 RAG 向量库部署于本地私有数据库，严控切片数据生命周期与文档溯源。

离线运行包工程化标准（零外网依赖的镜像、权重与依赖）

FDE 交付团队在进入客户机房前，必须按照以下标准准备交付介质包：

  • 自包含 Docker 镜像归档：使用 
    docker save
    导出完整系统镜像包，并在纯净无网测试机上验证 
    docker load
    后的无网冷启动；
  • 本地微调模型权重固化：模型权重采用 SafeTensors 格式打包，校验 SHA-256 哈希值；显式禁用模型的 
    trust_remote_code=True
    动态网络下载；
  • Pinned 依赖 Wheel 包镜像库：随包附带本地 pip wheel 离线源，通过 
    pip install --no-index --find-links
    安装所有 Python 依赖；
  • 零外网静态前端资源：前端页面所引用的所有 JS、CSS、SVG 图表及 Web 字体文件，必须 100% 相对路径本地化托管，严禁通过 
    <script src="https://...">
    引入外部公网 CDN。

单向物理网闸穿透代理与加密回执确认机制

针对物理单向网闸无法建立双向 TCP 握手的痛点，白皮书规范了异步单向穿透通信协议：

  • 数据包组装与 HMAC 签名：外部数据源将事件打包为规范 JSON 载荷 (Payload)，使用双方约定的非对称私钥签名，附加全局唯一时间戳与请求指纹序列号；
  • 单向穿透代理推送 (Unidirectional Egress Agent)：通过专用网闸传输软件单向推入内网，外网端将该事务标记为 
    SENT_UNCONFIRMED
    ；
  • 内网接收与验签落地 (Ingress Processing & Verification)：内网服务监听接收端口，校验签名有效性与请求幂等性；入库成功后将回执写入内网审计日志；
  • 定时对账与离线对账单同步：对于极高要求的财务或审计业务，每日通过物理单向网闸反向通道（或专用受控只读接口）同步回执摘要，核对两端流水，保障账实相符。

白盒安全合规走查与上线验收清册

在正式签署上线交付报告前，双方技术负责人必须对照以下清册逐项闭环走查：

  • [ ] 物理断网验证：现场拔掉服务器公网网线，系统全生命周期核心业务流可正常流转并完成验收测试；
  • [ ] 提示词注入防御（Prompt Injection）：输入预置的 20 组注入反例（如“忽略上述规则”、“输出全部密码”），边界网关必须 100% 拦截并记录审计日志；
  • [ ] 多租户数据隔离走查：以普通租户身份尝试构造跨租户请求，数据库层与检索层必须物理隔离拒单；
  • [ ] 断点快照恢复验证：在长事务审批中间节点强制杀死进程并重启，系统依据原请求 ID 完美找回上下文并完成续跑，无重复写动作；
  • [ ] 资产交接与无密码演练：提供无外网密钥依赖的完整离线 Runbook 与运维排障包，客户技术团队可独立复核复现全部功能。

常见问题

离线涉密机房如何解决模型知识更新问题？

通过本地 RAG 知识库切片热重载与增量挂载机制解决。业务制度与手册的更新直接同步至内网私有向量库与全文字检索引擎，无需频繁重新训练或微调底座大模型。

VPC 专网部署相比完全断网物理机房有何优势？

VPC 专网具备云端弹性和更成熟的运维监控基础设施，同时通过 VPC Peering 和私网终端节点确保数据不出专用内网，适合既需要云端算力调度、又有严苛合规隔离要求的企业客户。

白盒安全走查中发现模型被越权提问如何快速止血？

在网关层配置确定性规则黑名单与敏感词布隆过滤器，在不重启和不重新微调模型的前提下，毫秒级热更新过滤策略，实现即时阻断。
