评测 AGENTS.md（2026）：FDE 详解

原标题：Evaluating AGENTS.md (2026) Explained for FDEs

FDE Interviews · 2026-10-17 · 约 4 分钟读完

摘要

ETH Zurich 与 LogicStar.ai 的研究者构建了 CTXBench，检验仓库根目录的 AGENTS.md 等上下文文件是否真能帮助编码 Agent 完成任务。四款 Agent 在 CTXBench（138 个任务）和 SWE-bench Lite（300 个任务）上分别以无文件、LLM 生成文件、开发者手写文件三种设置运行。结果显示成功率无显著变化，但步骤数和成本上升，Agent 会严格执行文件中的具体指令。

要点

  • CTXBench 含 138 个任务，来自 12 个已有上下文文件的仓库
  • 开发者手写文件提升 2.4 个百分点，不显著（p=0.21）
  • LLM 生成文件使成功率略降，成本增加约五分之一
  • Agent 会遵循具体指令（如使用 uv），但仓库概览无助于定位文件
  • 对 FDE 的启示：默认不要自动生成文件，只写 Agent 无法自行发现的内容

一分钟读懂这篇论文

上下文文件是一份为编码 agent 编写的 README。它通常命名为 AGENTS.md、CLAUDE.md 或类似名称，位于仓库根目录，并在每次会话开始时加载到 agent 的上下文中。这类文件通常描述仓库的结构、如何安装和测试，以及需要遵循的约定。Agent 开发商推荐使用它们，一些工具只需一条

/init

命令就能生成一个，而且 AGENTS.md 项目统计到超过 60,000 个公开仓库包含此类文件。

Thibaud Gloaguen、Martin Vechev 以及苏黎世联邦理工学院（ETH Zurich）和 LogicStar.ai 的同事们想知道这些文件是否真的能帮助 agent 完成任务。现有的 基准测试 无法回答这个问题，因为它们所用的仓库早于上下文文件的出现。于是作者构建了 CTXBench：包含 138 个 Python 任务、缺陷修复和功能开发，取自 12 个开发者自己提交过上下文文件的较小仓库。他们还使用了包含 300 个任务的 SWE-bench Lite 数据集，并用每个 agent 自己推荐的命令在其中生成上下文文件。

共测试了四个 agent：搭配 Sonnet 4.5 的 Claude Code、分别搭配 GPT-5.2 和 GPT-5.1 mini 的 Codex，以及搭配 Qwen3-30B-Coder 的 Qwen Code。每个 agent 在三种条件下运行所有任务：无文件、LLM 生成的文件，以及在 CTXBench 上使用开发者自己写的文件。上下文文件并未显著改变成功率。但它们确实增加了步骤数和成本，因为 agent 会忠实地遵循文件中的额外指令：运行更多测试、搜索更多文件，并使用文件中提到的工具。

研究笔记：问题、方法与结果

在 CTXBench 上使用开发者编写的文件带来的平均成功率变化，不显著（p = 0.21）

在 SWE-bench Lite 上使用 LLM 生成的上下文文件时每个任务的平均成本，显著

文件中提到 uv 时与未提到时每个任务对 uv 的使用次数：指令确实被遵循了

Agent 厂商建议在每个仓库中都放置一个 AGENTS.md 或 CLAUDE.md 文件，超过 60,000 个公开仓库已经这样做了。但此前从未有人测量过这些文件是否真的能帮助 agent 完成实际任务。

让四个编码 agent 在 300 个 SWE-bench Lite 任务以及一个新基准（包含来自 12 个已配有开发者编写上下文文件的仓库的 138 个任务）上运行，分别使用无文件、LLM 生成的文件或开发者自己的文件。

LLM 生成的文件略微降低了平均成功率；开发者编写的文件将其提高了 2.4 个百分点，两者都不显著。两者都增加了步骤数和成本。Agent 会遵循诸如“使用 uv”之类的指令；仓库概览并不能帮助它们找到正确的文件。

为什么这对 FDE 很重要

在客户处部署编码 agent 时，通常第一步就是有人运行

/init

并提交生成的结果。这篇论文指出，这个文件很可能只是在白白花钱，却无法改善结果，而且它还告诉你哪些内容值得保留。

默认情况下不要发布自动生成的上下文文件。 LLM 生成的文件平均略微降低了成功率，并将成本提高了约五分之一。作者建议目前先不使用它们。

写指令，而不是导览。 Agent 会严格遵守具体的指令：当文件中要求使用某个工具时，Agent 就会使用它。仓库概览是最常见的内容，但并不能帮助 Agent 更快地找到正确的文件。文件中只保留 Agent 无法自行发现的内容：非标准命令、必须遵守的约定、绝对不能做的事情。

每一行都有成本。 该文件会随每次模型调用一起发送，其中包含的每条指令都可能触发额外的工作。把它当作有预算限制的配置，而不是文档。

在标准化之前先进行测量。 如果团队想要一个跨仓库通用的上下文文件模板，请在这些仓库的真实任务上测试它，分别在使用和不使用该文件的情况下进行对比，并比较成功率和成本。
