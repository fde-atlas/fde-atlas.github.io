数据与 SQL 工程

基础SQL 窗口函数窗口函数在与当前行相关的一组行上计算数值，而不会将它们折叠，因此你可以在保留每一行的同时进行排名、与相邻行比较或计算累计总和。这是分析师在纯 SQL 中回答“与什么相比？”这类问题的方式，大多数面试官用它来区分“会 SQL 的人”和“只会 GROUP BY 的人”。

检索与 Agent

基础检索增强生成（RAG）RAG 通过在查询时检索相关段落并将其放入提示词中，将语言模型建立在你自己的数据之上，使模型基于真实来源而非记忆来回答。它是几乎所有企业 FDE 部署的默认模式，这也是为什么几乎每一轮面试都会考察它。

基础向量数据库向量数据库将嵌入向量与元数据一起存储，并使用近似索引快速回答最近邻查询。真正的面试问题不是它们如何工作，而是你什么时候真正需要一个向量数据库，而不是一个库或带 pgvector 的普通 Postgres。

生产环境 AI 系统设计

基础从概念验证到生产环境在演示中正确回答了一个问题的 Notebook 并不是交付物。生产环境是那些不起眼的工作，它把一次性的成功转变为客户可以在没有你在场的情况下运行、信任和运维的系统。弥合这一差距是 FDE 工作的大部分内容。

基础重试、指数退避与抖动当调用因瞬时错误而失败时，立即重试是最糟糕的做法：它会给本已不堪重负的服务叠加负载，并让所有客户端同步形成踩踏。指数退避将重试在时间上拉开间隔，而抖动则让客户端去同步，使它们不再齐步到达。

面向客户的技艺

基础需求挖掘需求挖掘是找出隐藏在客户明确提出的需求背后的真实问题的工作。客户交给你的请求（“给我们做一个聊天机器人”）几乎从来不是真正的需求；能够弄清楚谁在使用它、成功是什么样子、实际存在哪些数据、以及为什么截止日期就是截止日期的 FDE，才是能交付出人们真正会使用的产品的 FDE。

基础篇界定模糊问题界定一个开放式提示（“某城市想缩短 911 响应时间”）是一种结构化的操作，而不是灵光一现：澄清输入和约束，大声说出你的假设，划分出最小可用的 MVP，明确你正在选择的准确性/成本/延迟权衡，并规划失败时该怎么办。直接跳到某个模型或架构是候选人在模拟环节中最常见的被淘汰原因。

基础篇向非工程师解释权衡高管并不关心你选择了 RAG 还是微调；他们关心的是成本、上线时间以及可能出错的地方。翻译技术权衡意味着把准确性、成本和延迟转化为业务真正在做的决策，用他们的语言把每个选项框定为带有后果的选择，并回答他们最终都会问的问题：为什么 AI 每次给出的答案都不一样，而这为什么不是 bug。
