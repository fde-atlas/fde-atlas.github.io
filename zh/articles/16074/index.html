Palantir 内幕交易面试题：FDE 解题演示

原标题：Palantir insider trading interview question: FDE walkthrough

FDE Interview Prep · 2026-09-25 · 约 14 分钟读完

摘要

文章拆解 Palantir 一道有据可查的 FDE 面试题：面试官先解释内幕交易，再让候选人现场设计检测方案。作者给出五步答法：复述领域定义、明确用户及其决策、按数据获取难度排序信号、说明每个数据源的所有者与缺陷、交付一个供人工复核的排序队列而非自动判定系统。文章强调这是前招聘负责人的举例，并非官方题库，应准备题型而非原题。

要点

  • Shilpa Balaji 向 First Round Review 证实此题存在，但无评分标准。
  • 五步法：复述定义、定用户、排信号、列数据源、出第一版。
  • 核心信号是访问权加时机加方向，只需合规部门已有数据。
  • 第一版是每日排序复核队列，规则优先，不用模型。
  • 系统只排序不判定，需说明局限与不自动化的部分。

面试官会用几句通俗易懂的话解释内幕交易，然后问你会如何检测它。你从未在金融行业工作过，不确定这里的“重大”是什么意思，而时间正在流逝。这篇文章将完整地走完这个场景，而分解面试指南则涵盖了整个面试环节。

这个场景是有据可查的：Palantir 前招聘负责人 Shilpa Balaji 告诉 First Round Review，面试官会向候选人解释内幕交易，并要求他们设计一个解决方案，包括需要什么数据、会向客户问什么问题，以及会关注什么。来源 1So You Want to Hire a Forward Deployed Engineer发布方First Round Review来源类型新闻报道

你不需要懂证券法也能答好这道题。答案分五步：

  • 当着面试官的面，边问边学，掌握这个领域。
  • 明确用户是谁，以及他们要做什么决策。
  • 按数据获取的难易程度对信号进行排序。
  • 指出每个数据源的所有者及其缺陷。
  • 交付一个带人工审核的排序队列，而不是一台自动下结论的机器。

当着面试官的面，边问边学，掌握这个领域。

面试官会给你一个可用的定义。听起来可能是这样（这是为练习而做的简化，不构成法律建议）：

内幕交易是指在你掌握公众尚不知道的公司重要信息时买卖该公司股票，或将这些信息透露给据此交易的人。

你的第一步是用自己的话复述一遍，并检查边界情况：

“让我确认一下我理解得对不对。有人在消息公布前得知了会影响股价的信息，比如一起收购。他们在公告发布前进行交易，或者告诉一个朋友去交易。这些信息必须重要到足以影响投资者，并且在交易发生时必须是非公开的。是这样吗？”

然后提出那些能把定义变成系统的问题。每一个问题都会改变你要构建的东西：

  • 谁会在公众之前知道？ 交易团队、高管、律师，以及任何了解该交易内情的人。
  • 信息何时变成公开？ 公告有时间戳。这个时间戳是整个设计的核心。
  • 一笔可疑交易作为记录看起来是什么样的？ 谁交易了、交易了什么、方向如何、数量多少，以及何时交易。
  • 他们如何得知这个信息重要吗？ 参与交易的银行家和在火车上偶然听到消息的陌生人是不同的情况，因为在美国法律中，案件很大程度上取决于是否有保密义务（SEC Rule 10b5-2 列出了该义务存在的情况）。

Palantir 的招聘博客在 2022 年 8 月告诉实习生和应届毕业生候选人，要边思考边说出想法，分享问题和观察，以便面试官能看到他们如何解决问题。来源 2From Pipeline to Prospect: Insights and Advice from Palantir Recruitment (Palantir Blog; archived copy)发布方Palantir Technologies（Medium 上的 Palantir 博客）来源类型存档的公司页面 学习领域知识正是这种做法最能带来回报的地方。面试官听不到的推理对你没有帮助。

不要假装懂行话

如果你知道像“重大非公开信息”这样的术语，就使用它们，并确认你们指的是同一件事。如果不知道，就提问。假装懂行比问一个清楚的问题代价更大。

现场学习一个概念本身就是一项技能，我们关于 Palantir 的学习面试的文章对此进行了深入讲解：复述、要一个例子、构建最小版本。

用户是谁，以及他们做出什么决策

“检测内幕交易”还不是一个问题。它没有用户。要问：

“在我设计任何东西之前：客户是谁，谁会每天早上使用这个系统？”

答案会改变你能看到哪些数据以及输出的用途。第一行是一个真实的职责：FINRA

Rule 3110(d)

要求成员公司在其监督程序中纳入一个流程，用于审查公司自有账户和员工账户的交易，旨在识别可能违反内幕交易规则的交易。

客户有什么不同
银行的合规团队看到自己员工的交易和自己的交易清单。决定调查哪些交易。
交易所的监察团队能看到其市场上的每一笔订单，但看不到谁知道什么。决定哪些案件上报。
监管机构接收上报案件，并可调取记录。决定立案调查哪些案件。

如果面试官说“你来选”，就选一个并说明理由：

“我假设客户是一家为并购提供咨询的投资银行的合规团队。他们的银行家在交易公开前就会得知交易信息，所以风险在机构内部，而合规部门既能看到交易清单，也能看到员工的交易账户。用户是合规分析师。要做的决定是：今天的交易中，我该优先查看哪些，又该上报哪些？”

我们关于分解面试中的澄清问题的文章介绍了如何挑选那些会改变你第一版方案的问题，其余则先做假设。

值得关注的信号

接下来回答“他们会关注什么？”先列出信号，再按成本排序。

成本低，来自合规部门已有的记录：

  • 访问权限。 该员工在交易团队中、曾听取交易简报，或该公司在银行的监控名单上。
  • 时机。 交易发生在影响价格的公告发布前不久，而不是之后。
  • 方向。 利好消息发布前买入，或利空消息发布前卖出。
  • 流程违规。 交易未经事先审批，或交易时该股票在限制名单上。

成本更高，来自历史数据：

  • 对该员工而言异常。 这是其在该股票上的首次交易、交易规模远超其历史水平，或交易期权而非股票。

成本高昂，且时间靠后：

  • 关联。 亲属账户、其他公司的朋友，或多个互不相关的账户在同一消息发布前买入同一股票。

像这样把它说出来：

“访问权限加时机加方向是核心信号，而且只需要合规部门已有的记录。对员工个人异常需要交易历史。人与人之间的关联是最强的信号，但数据最难获取，所以我会把它排除在第一版之外。”

你需要的数据，以及数据的归属方

每个数据源都有归属方、延迟和缺陷。把这三点都说出来。

数据归属方，以及问题所在
交易清单及听取简报的人员合规部门。靠人工录入，因此可能滞后于实际交易。
监控名单和限制名单合规部门。你需要知道每个名字是何时被加入的，而不仅仅是今天的名单。
员工的个人交易券商数据源或发送给合规部门的对账单。到达时间较晚，且可能缺少某些账户。
员工档案及家庭账户人力资源部和合规部门。家庭账户靠自行申报。
公告和价格市场数据供应商。你需要精确的时间戳，而不仅仅是日期。
邮件和聊天记录IT 和法务部。最敏感的数据，需要法务批准。不纳入第一版。

然后指出数据关联的难点。在我们的方法中，这正是展现你技术推理能力的地方。

  • 人员。HR 系统中的员工 ID 可能与券商对账单上的账户持有人不一致。你需要一张映射表，而且必须有人负责维护它。
  • 证券。股票代码会变化，尤其是在并购前后。请用稳定不变的证券标识符来关联，而不是股票代码。
  • 时间。公告发布前几分钟的交易和公告发布后几分钟的交易讲述的是截然相反的故事，仅凭日期无法区分它们。在加载时将所有时间戳转换为 UTC 并统一存储为一种格式，这样纽约收盘前的一笔交易和当晚在伦敦发布的一份公告才能正确比较。
“对于每个数据源，我想知道谁负责它、数据有多新、它有什么问题，以及谁能批准访问。交易清单是我第一个要的，因为没有它我就无法判断谁有访问权限。”

分析师可以使用的第一版方案

Palantir 的招聘页面上关于开放式问题的说明是：要清晰地阐述备选方案和权衡取舍，务实到能得出一个具体的方法，先交付一个可运行的构想，再逐步扩展。来源 3Palantir Careers | Navigating Open-Ended Questions发布方Palantir Technologies来源类型公司招聘页面 在这里，可运行的构想并不是一个机器学习模型，而是一个按优先级排序的审查队列。

“第一版是给分析师的每日清单。对于每一条影响股价的公告，它会在公告发布前的短时间窗口内查找该公司股票的交易。有记录在案的访问权限者的交易排在最前面。每一行都说明它为什么出现在这里：谁、做了什么、什么时候、距公告多久，以及他们拥有什么访问权限。由分析师来判断，系统只负责排序。”

如果面试官要求你把它具体化，就画出核心查询。在一个小型虚构 schema 上，用 SQLite 语法，它非常简短：

-- timestamps: UTC text, 'YYYY-MM-DD HH:MM:SS'
SELECT t.employee_id, t.security_id, t.side,
       t.traded_at, a.announced_at,
       EXISTS (
         SELECT 1 FROM access AS x
         WHERE x.employee_id = t.employee_id
           AND x.security_id = t.security_id
           AND x.from_at <= t.traded_at
       ) AS had_access
FROM trade AS t
JOIN announcement AS a
  ON a.security_id = t.security_id
 AND t.traded_at < a.announced_at
 AND t.traded_at >=
     datetime(a.announced_at, '-10 days')
ORDER BY had_access DESC, t.traded_at DESC;

四个值得说出口的选择：

  • 用 security_id，而不是 ticker。股票代码在并购前后会变化，而这恰恰是这条查询最关键的时候。
  • 访问权限用 EXISTS，而不是 join。否则，同一笔交易被两次通报的人会出现两次，队列会把他们重复计数。一笔交易仍可能匹配同一窗口内的两条公告；我会只显示一次，放在时间更近的那条公告旁边。
  • 只取公告发布前的交易。严格的 < 会排除消息传出后下达的交易。
  • -10 天的窗口只是猜测。把它做成分析师可以调整的设置，并说明你会和他们一起调优。

为什么用规则而不是模型？你还没有标签：没有人标注过哪些历史警报是真实的。规则对分析师、法务和审计人员来说都是可解释的。模型可以以后再上，用分析师的判断结果来训练。

第一版方案中哪些是简化处理的：访问权限表可能只是每周导出的电子表格，而且在这个草图中访问权限永不过期；真实的表需要在交易成交或终止时设置一个结束日期。要主动说明这一点，并说明你接下来会自动化什么。

误报、审核与不该自动化的部分

队列会标记出无辜的交易，一个有力的回答应当为此做好规划。可以点名的无辜原因包括：

  • 该交易已由合规部门预先批准。
  • 它属于事先设定的交易计划的一部分。
  • 它是在全权委托管理账户中进行的，由经理操作交易，员工本人并不选择交易。
  • 它是自动分红再投资。

不要删除这些记录。应附带一个审计人员可见的明确理由将其屏蔽。

然后设计审核环节：

  • 分析师为每条警报关闭时注明原因，向员工询问解释，或上报给法务部门。
  • 每个决定都记录在案，包括由谁做出以及何时做出。
  • 这些决定将成为后续模型所需的标注数据。

你如何知道它有效

“你会如何衡量效果？”是对第一版方案最可预见的追问。准备好一句话：

“我会追踪分析师上报而非直接关闭的警报占比、每条警报的关闭时长，以及是否有任何案件通过其他渠道到达我们——比如监管机构的问询或举报——而队列未能发现。如果大多数警报在几秒内就被当作明显的噪音关闭，下一步就是完善屏蔽规则。”

并说明你不会自动化的部分：

“系统绝不会指控任何人、冻结账户或向监管机构报告。这些是具有法律后果的人类决定。而且第一版我不会读取员工的消息。那需要法务批准和明确的理由，仅凭交易数据就足以给分析师提供有用的队列。”

预期会有追问来试探边界：“如果银行家把消息透露给朋友，而朋友在另一家券商交易怎么办？”一个好的回答会承认这一局限：

“这个系统看不到那个账户。那是交易所或监管机构的视野，不是银行的。银行能做的是让自己的记录在被要求时易于移交：谁听取了交易的简报，以及何时。我会明确指出这超出第一版的范围，而不是假装能够覆盖。”

在任何你不熟悉的领域运用同样的方法

剥去金融的外衣，这本质上是一个检测与响应问题：在嘈杂的数据中出了问题，却发现得太晚。在 Pro 课程中，关于问题形态的课展示了如何在医院、工厂或支付公司中识别这种形态，以及它需要哪些首要问题。Pro 课程实战案例：医疗与金融为你提供了一个填了一半棋盘的商户欺诈案例：同样的形态，只是涉及真金白银。

在同一篇 First Round Review 文章中，一位 FDE 招聘负责人表示，FDE 不是那种带着现成操作手册来的人，FDE 是以结果为导向的独立思考者。来源 1So You Want to Hire a Forward Deployed Engineer发布方First Round Review来源类型新闻报道 你无法死记硬背一个领域，但你可以演练这些方法。

适用于任何陌生领域的方法

  • 用自己的话复述该领域，并检验边界情况。
  • 询问客户是谁、用户是谁，以及他们做出什么决策。
  • 列出信号，并按数据获取的难易程度排序。
  • 对每个数据源，说明负责人、延迟和缺陷。
  • 提出一个真实用户可以执行的初版方案，先定规则，再谈模型。
  • 为误报和人工审核做好规划，并说明哪些环节你不会自动化。
  • 说明初版方案看不到什么。

需要避免的错误，以及对应的纠正方法：

  • 背诵法律条文。 纠正方法：用一句话复述，然后转向用户。
  • 一上来就谈模型。 在没有标注数据的情况下说“我要训练一个分类器”。纠正方法：先定规则，标注来自人工审核。
  • 没有负责人。 把数据列出来，仿佛它们已经集中在一处。纠正方法：明确每个数据源由谁拍板。
  • 自动化最终判定。 纠正方法：系统负责排序，人来决策。

关于 Palantir 的内幕交易面试题，First Round Review 报道了什么？

Palantir 的前 FDE 招聘负责人告诉 First Round Review，面试官会向候选人解释内幕交易，并要求他们设计一个解决方案：需要什么数据、会向客户问什么问题、会寻找什么。这是她举的示例场景，并非公开的题目清单。来源 1So You Want to Hire a Forward Deployed Engineer发布方First Round Review来源类型新闻报道

对于 First Round Review 描述的内幕交易场景，我需要懂金融吗？

不需要。在 Palantir 前 FDE 招聘负责人给 First Round Review 举的例子中，面试官会先解释内幕交易，而且她说这类面试旨在考察商业推理和技术推理能力。要针对领域提出犀利的问题，而不是背诵证券法。来源 1So You Want to Hire a Forward Deployed Engineer发布方First Round Review来源类型新闻报道

检测内幕交易的一个好的初版方案是什么？

为合规分析师准备的排序队列：与公司相关人员在价格敏感公告发布前不久进行的交易，每条都显示被标记的原因及其背后的记录。由分析师来做决定；系统只负责排列优先查看的顺序。
