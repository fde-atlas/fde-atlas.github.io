Harness²（2026）FDE 解读

原标题：Harness² (2026) Explained for FDEs

FDE Interviews · 2026-10-21 · 约 4 分钟读完

摘要

Google Cloud AI Research 的 Ruiyao Xu 等人提出 Harness²：在无标准答案的情况下，通过双循环让 AI Agent 的 harness（提示、技能、脚本等）随任务逐个自我改进。核心做法是运行当前 harness 后，由两个编辑器分别从行为与领域知识角度提出候选，再由合成器基于运行差异写出后继版本；任务结束后沉淀经验教训到库中。在三个专业基准、两种执行模型上，单步改进均优于基线（提升 1.2 至 11.8 分），但相对最强基线的优势多在噪声范围内。

要点

  • Harness² 用双循环在无评测集时改进 Agent harness
  • 编辑依据是同任务两次运行的行为差异，而非评分
  • 冷改 harness 不运行验证反而使 WB-code 从 73.4 降至 63.2
  • 移除经验库使 WorkBuddy-Bench 损失 3.1 分
  • 十二种设置均超基线，但对最强基线优势多在噪声内

一分钟读完这篇论文

Agent 是模型加上 harness：即围绕一个冻结模型的系统提示词、常设规则、记忆文件、技能、辅助脚本、子 Agent 和钩子。Google Cloud AI Research 的实习生 Ruiyao Xu 及其同事提出了一个问题：能否在 Agent 工作的同时，逐任务地改进这个 harness，而且不需要任何答案钥匙？改进者本身能否随着任务的推进越来越擅长这项工作？

该方法名为 Harness²（Harness squared），包含两个循环。在每个任务内部，当前 harness 运行一次以产生一个参考结果。两位编辑阅读该轨迹，各自撰写一个候选 harness：一个改变 Agent 的工作方式（规划、工具使用、检查自身输出），另一个补充该领域的从业者会知道的知识。两个候选都在同一任务上运行。一个合成器并排阅读这三次运行，根据它能指出的差异撰写后继 harness，或者保留旧 harness。后继 harness 随后运行，其输出被交付。在任何阶段都没有分数、评分标准或评分器；该流水线拒绝向编辑交付一个包含这些内容的目录。

第二个循环在每个任务之后运行。一个反思器记录哪些编辑改变了行为，并且只有在有执行对比支持时，才写出至多一条经验教训。该经验教训和被采纳的 harness 进入一个库，供后续编辑阅读。下一个任务仍然从公共基础 harness 出发。

评估覆盖三个专业基准（WorkBuddy-Bench 用于代码、网页和办公交付物，JobBench 用于完整工作任务，以及 Harvey 的 Legal Agent Benchmark），使用两个冻结的执行器 Gemini 3.5 Flash 和 GLM-5，各自在两个现成 harness（OpenCode 和 Codex）下运行。编辑器是 Claude Opus 4.8。代码链接见论文中的

Harness（提示词、技能、脚本、子 Agent、钩子）通常靠手工调优，或针对固定训练集离线搜索。而部署后的 Agent 面对的是没有答案钥匙的新任务，因此没有任何东西可以用来为 harness 的编辑打分。

对每个任务：运行当前 harness，让两位编辑从不同角度提出修改，运行两者，并根据行为差异合成一个后继版本。任务结束后，将被采纳的 harness 以及任何有执行对比支持的经验教训保存在一个库中，用于指导后续编辑。

一步改进使全部十二种执行器、harness 和基准设置都优于基础 harness，提升幅度为 1.2 到 11.8 分。每个范围五个候选又额外增加了 2.6 到 6.7 分。相对最强基线的优势大多在运行间噪声范围之内。

为什么这对 FDE 很重要

大多数客户的 AI Agent 从来没有足够大的带标签评测集可供调优。任务一个接一个地到来，每个都略有不同，而能够评判输出的人又很忙。这篇论文正是针对这种场景对 harness 进行的一次细致改进尝试，即使你从不运行整个流水线，它的设计选择也很有参考价值。

在信任编辑之前先运行它。 最实用的结果是一个负面结果。一个在没有运行任何东西、也没有库的情况下重写 harness 的编辑器反而让效果变差了：WB-code 从 73.4 降到 63.2，WB-web 从 69.9 降到 65.0。凭空写出的编辑读起来不错，却造成了损害。有效方法中的每一处编辑都能追溯到轨迹中的某个具体时刻。

比较行为，而不是结论。 在没有评分器的情况下，证据就是同一任务的两次运行之间的差异：一次调和了文件，另一次没有；一次重新检查了输出，另一次直接信任了写入。这种对比是客户团队的评审人员通过阅读就能核实的。

保留经验教训，而不只是 harness。 库中的每一条都是一个可用的 harness，外加一条关于它何时起作用、为何起作用的说明。作者移除库后，在 WorkBuddy-Bench 上损失了 3.1 分，在 JobBench 上损失了 1.8 分。

把增益和噪声放在一起读。 每种设置都比基础 harness 有所提升，但相对于最强竞争方法的大多数优势都小于三次运行的波动幅度。这才是衡量你自己 harness 改动的正确标准。
