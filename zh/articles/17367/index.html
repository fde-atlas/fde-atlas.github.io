前沿部署工程师的技能：那些没人写进招聘启事的能力

原标题：Forward Deployed Engineer skills: the ones nobody puts in the job ad

herdes.nl · 2026-09-03 · 约 7 分钟读完

摘要

作者认为招聘广告上的 FDE 技能清单排序失当：全栈基础、SQL 和 API 集成只是入门门槛，模型 API 和向量数据库最容易学也最不易出错，检索管道的难点在于理解混乱的业务文档而非技术本身。真正的决定性技能是判断力——敢于提出某事不该做，因为做错东西会长期损耗信任。沟通上应简化决策而非简化技术，把权衡转化为对方能承担的后果。作者还认为大公司背景并非必要，端到端流程经验和承担过失败责任才是关键，而这些判断力无法通过课程或证书获得。

要点

  • 招聘广告的技能清单按易写程度而非重要性排序。
  • SQL 和 API 集成是真正的门槛，模型 API 两周即可学会。
  • 多数需求本质是数据问题，用查询而非提示词解决。
  • 最难技能是敢于说某事不该做，做错会长期失去信任。
  • 大公司背景非必要，端到端流程经验与担责更关键。

作者：Marc Herdes · 荷兰阿尔梅勒 ·

先认真对待那份标准清单。它通常写着：全栈基础，即 Python 或 TypeScript、SQL、数据库和 API 集成；然后是 AI 和云的熟练度，即模型 API、检索管道和向量数据库；再然后是高度主动性和沟通能力，即利益相关者管理和用业务语言解释权衡取舍。

正在亲自处理这类问题？用两句话向我描述一下。我会亲自阅读。

这些都没有错。只是它按“容易写下来的程度”排序，而不是按“决定工作能否落地的程度”排序。所以下面是同一份清单，按“缺失时会让你付出什么代价”重新排序。

前沿部署工程师到底需要哪些技能？

公开的技能清单是真实的，但权重严重失衡。全栈基础和 SQL 只是入场门槛，模型 API 是其中最容易的部分，而真正起决定作用的技能是判断力：知道哪个问题值得解决，并且敢于公开说出某些东西根本不应该被构建。

标准清单上哪些技能被高估了？

模型 API 和向量数据库。它们是清单上最新、写出来最令人兴奋的项目，所以总是出现在每份招聘启事的最顶端。但实际上，它们是学得最快的部分，也是最不可能出问题的部分。一个有能力的开发者两周就能掌握这两项，之后再也不用去想它们。

检索管道的情况略有不同。技术本身很简单；难的部分在于，要求你搜索的文档往往互相矛盾、已经过时，或者是由四个意见不合的人写成的。这不是 AI 技能。这是要知道四个人中谁是对的——这是只有业务内部的人才能回答的问题。

对于这类工作中的大部分场景，云架构也属于同一类。如果你是在一家公司的流程内部构建，你并不是在为一个你永远达不到的规模做设计。能够可靠地运行某个东西就足够了。能够为数百万用户运行它是另一份工作，有另一个头衔。

什么才是真正的入场门槛？

SQL、API 集成，以及能自如地在别人的代码库中工作。这些都不起眼，但三者都不可妥协。如果你无法把数据取出来、正确地做关联，并把结果放回业务方已经在看的地方，清单上的其他任何技能都没有机会发挥作用。

广告里漏掉的一点是：阅读一个不是你设计的数据库，没有文档，列名还是一种你可能不懂的语言。这种情况经常发生。第一周有一半的工作是搞清楚三张表里哪一张才是大家真正在用的。

为什么 SQL 在这里比任何模型 API 都更有用？

因为几乎每个需求最终都是一个戴着不同帽子的数据问题。“AI 能帮我们写报价吗”几乎总是归结为“我们的价格存在两个地方，而且互相矛盾”。你是通过查询发现这一点的，而不是通过提示词。大多数项目中最有价值的一小时，都花在统计那些从来没人统计过的东西上。

统计还能平息争论。当有人坚称某种情况很常见，而数据显示去年只发生过两次时，项目范围在一句话之内就改变了。这就是为什么我会先去找数字，再去找设计方案。

最难的技能是什么？

说某件事不应该做。这很难，因为它会让面前的人失望，通常会终结那笔付你钱的对话，而且你必须用推理而不是热情来为它辩护。几乎所有人都觉得，把东西做出来然后抱有希望要容易得多。

这也是失败代价最清晰的技能。做错了东西，你损失的不只是一笔费用。你失去的是所有必须使用它的人的信任，而你下一次提出的诚恳建议会被当成推销。这种代价会持续多年，这就是为什么我现在会在写任何代码之前先把理由写下来：不做什么的论证。

如何向一个不关心技术的人解释技术上的权衡？

把它翻译成出错时的代价。不要说“这需要一个队列”，而是说“如果连接在繁忙时段断开，要么丢失订单，要么让客户等待，二选一”。当选择以他们自己要承担的后果来表达时，没有技术背景的人也能做出极好的决策。

常见的错误是把技术简化。不要这样做。要简化的是决策。任何经营企业的人都习惯于在两个都不完美、都涉及真金白银的选项之间做选择；这占了他们一周的大部分时间。他们做不到的，是猜出究竟存在哪两个选项。

这还有另一半，就是以一种经得起矛盾考验的方式去倾听。每天做这项工作的人和签发票据的人，对同一个流程的描述会不一样，而两人对自己所看到的描述都是真实的。你的工作不是挑选更资深的那一版。

这些需要大公司背景吗？

不需要，而且这种假设反而碍事。小公司让你看到整条链路：报价、订单、安装、投诉、发票、回头客。在大型组织里，你只被交给其中的一小段，而且很少能弄清你的工作在下游发生了什么。

你真正需要的是不止一次地完整观察过一个流程的始末，最好是在它失败时由你负责。人们说这些职位需要资深，指的就是这个。不是年限，而是曾经真正承担过责任。

从一个小案例可以看出这种特质的样子：一个每天爬十五次梯子的人不需要一个平台。他需要的只是把一块屏幕放在正确的位置，而它之所以有效，与里面的技术毫无关系。

谁往往擅长这件事？

习惯于想办法绕过障碍的人。如果你无法分辨某些颜色怎么办？你会记住顺序，数清位置，发明某种办法让它照样能用。这样坚持多年，你就会变得擅长找到那扇真正能打开的门。

这是一种观察，而非解释。为什么这两者如此频繁地重合，我不知道，我也不会编造一项研究来支持它。我能看到的是，留下来的正是这种习惯，而这种习惯恰恰是这份工作所需要的。

有两点需要在这句话中明确说明。你不需要任何此类特质也能做好这件事：大多数擅长此事的人并没有什么特别之处。反过来也不成立。它不会自动让你成为一个能看清事物之间联系的人。

所以客户购买的不是一种特质，而是一种习惯。一个从来无法走最省事路线的人，早已习惯于寻找第二条路。正如 Marc 所说：如果这件事容易，谁都能做。

有什么是课程学不到的？

那种识别的瞬间。在交谈进行十分钟后就知道，对方描述的问题并不是真正存在的问题。这来自于你以前曾在真实付出代价的情况下判断失误。没有任何练习能重现自己的钱牵涉其中的那种感觉。

这也是对人们不断搜索的一个问题的诚实回答：没有任何证书涵盖这些内容。这不是对学历的势利。而是因为被考验的东西是真实利害关系下的判断力，而教学大纲无法提供这种利害关系。

如果你想了解这些技能在一周内具体是如何运用的，那就是一天实际上由什么组成。

Marc Herdes，Almere，2026 年 9 月 4 日。五家公司，每一家都在这份清单上教会了我不同的东西。

这听起来像你的公司吗？

两句话就够了。你会得到一个诚实的回答：我会构建什么，我会放着不动什么，以及这件事应该归我还是归别人。第一次交谈不花任何成本。

是在为此招聘，还是想成为这样的人？

无论哪种，都告诉我你想完成什么。这比一份技术清单是更有用的起点。
