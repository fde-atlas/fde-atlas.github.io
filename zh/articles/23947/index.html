Palantir Gotham 与 Foundry 的区别｜用途、客户与 FDE 实务

原标题：Palantir GothamとFoundryの違い｜用途・顧客・FDE実務

FDE総研 · 2026-10-21 · 约 10 分钟读完

摘要

这篇文章比较了 Palantir 的两大产品：面向政府与防务、情报机构的 Gotham，以及面向民间企业的 Foundry。两者共享同一设计理念，即把原始数据转化为可授权查看的对象并记录决策，但客户、用途与运行环境要求不同。文章还梳理了 AIP 与 Apollo 在产品体系中的分层关系，并对比了 FDE 在两类项目中的工作方式与职业发展差异。

要点

  • Gotham 服务防务、情报与执法机构，核心是实体关系分析与作战支持。
  • Foundry 通过 Ontology 整合企业数据，用于供应链、生产等业务优化。
  • AIP 在 Ontology 之上接入 LLM，Apollo 负责向隔离环境持续交付更新。
  • Gotham 项目受安全审查与隔离环境约束，Foundry 项目更看重业务建模能力。
  • 对日本工程师而言，Foundry 与 AIP 的民间项目是更现实的 FDE 入口。

Palantir Gotham 与 Foundry 有什么区别？

Gotham 是面向政府、国防与情报领域的分析平台，Foundry 则是整合民间企业业务数据并进行运营的平台。

Palantir Technologies 创立于 2003 年，最初的主力产品是面向政府机构的 Gotham。此后又面向民间企业推出了 Foundry。两者的共同点在于都是整合数据并用于决策，区别则在于“由谁、用于什么样的判断”。Palantir 自身也在官网和年报（Form 10-K）中说明，其主力平台为 Gotham、Foundry、Apollo、AIP 四个。

目标客户与目的有何不同？

Gotham 是为了“发现威胁与目标并做出判断”，Foundry 则是为了“优化业务并执行”的平台。

视角Palantir GothamPalantir Foundry
主要客户国防、情报、执法等政府机构制造、能源、金融、医疗等民间企业及部分公共机构
主要目的人物、组织、事件的关系分析、态势掌握、作战支持供应链、生产、维护、供需计划等业务优化
核心概念实体（人、地点、物、事件）及其关系Ontology（业务对象与动作的模型）
典型界面地图、时间线、关系图谱仪表盘、业务应用、工作流
要求的条件密级管理、严格的访问控制、在割裂环境中的运营与现有核心系统（ERP、MES 等）的对接、现场易用性

技术基础是否共通？

技术基础的很大部分已经实现共通化。即便如此，数据模型的思路与运营环境的条件仍因产品而异。

与其说 Gotham 和 Foundry 是完全不同的产品，不如说它们是将同一设计思想分别面向政府和民间展开的产品，这更接近实际情况。两者都遵循“将原始数据转换为有意义的对象，按权限展示，并记录判断”的流程。Foundry 将这一流程明确产品化为 Ontology，后发的 AIP 也以 Ontology 为基础。

从现场角度来看，无论哪类项目，所需的能力都是“决定数据含义的能力”。比起构建数据管道的技术本身，能否正确建模客户的业务往往决定了成果。

Palantir Gotham 被哪些组织用于什么用途？

Gotham 主要被美国及盟国的国防、情报、执法机构使用，支撑情报分析与作战判断。

Gotham 的“Gotham”普遍被认为取自蝙蝠侠故事中的虚构城市。由于创业初期的一部分资金来自美国 CIA 系风险投资机构 In-Q-Tel，这也很好地体现了 Palantir 从政府业务起步的事实。

主要应用领域有哪些？

主要应用领域有四个：情报分析、国防作战计划、执法机构侦查支持、灾害应对。

  • 情报分析：将通信记录、报告、公开信息等串联起来，可视化人物与组织的关系
  • 国防与作战支持：整合部队、装备、地理信息，支持指挥官掌握态势与决策
  • 执法与侦查：跨事件记录和侦查资料进行检索，发现关联性
  • 灾害应对与公共卫生：掌握物资和据点状况，判断分配方案

具体的合同名称和金额，能在各国政府采购信息和 Palantir 财报资料中确认的范围有限。多数项目不对外公开。对于文章和社交媒体上流传的“Gotham 被用于某某作战”之类的信息，需要甄别其是否有一手信息可查证。

Gotham 特有的要求是什么？

在 Gotham 中，按密级进行访问控制、在与网络隔离的环境中运营、可审计性被置于最优先地位。

与民间系统的重大区别在于，必须能够事后验证“谁在何时查看了哪些信息、做出了怎样的判断”。此外，也有部署在无法连接互联网的环境（气隙环境）或通信带宽受限的前线环境的情况。参与 Gotham 开发和部署的工程师，比起添加功能，更需要以安全和运营约束为前提来思考设计。

Palantir Foundry 在企业中是如何被使用的？

Foundry 用于将企业内分散的数据通过 Ontology 连接为业务对象，并一直做到构建现场决策应用。

Foundry 的特点是数据平台与应用开发环境融为一体。与分别引入数据仓库和 BI 工具不同，从数据接入、转换、建模、业务应用化到写回，都可以在同一套权限管理下处理。

公开的代表性部署案例有哪些？

作为公开案例，知名的有 Airbus 的航空数据平台“Skywise”、英国 NHS 的联邦数据平台，以及与日本 SOMPO 的合资业务。

组织领域概要（基于公开信息）
Airbus飞机制造与运营与 Palantir 共同构建与航空公司共享的数据平台“Skywise”
英国 NHS England公共医疗在 Federated Data Platform（联邦数据平台）的采购中，以 Palantir 为主导的联合体于 2023 年入选
SOMPO控股保险·护理2019年合资设立Palantir Technologies Japan，作为在日本国内拓展的基础

NHS的案例属于公共机构，但使用的是Foundry系的基础平台。记住这个例子很有用，说明不能简单地以“Gotham＝政府、Foundry＝民间”来划分。

企业中常用的业务领域有哪些？

常用的是供应链、生产与质量管理、设备维护、供需计划等跨越多个系统的业务。

这些业务的共同点在于，数据分散在ERP、MES、电子表格文件、现场的纸质记录等之中，而一个决策需要用到多个数据。Foundry的价值并不在于制作仪表盘本身，而在于能够在同一个Ontology上处理“这个零件的交期延误会影响哪些订单、应该由谁来决定什么”。

从实务者的感觉来看，Foundry导入是否成功，与其说取决于技术，不如说更容易取决于“最初选择的用例”。比起从经营层想看的全公司KPI入手，选择一项现场人员每天使用的决策业务并深入打磨，往往更容易落地生根。

AIP、Apollo与Gotham和Foundry是什么关系？

AIP是在Gotham和Foundry之上运行生成式AI的层，Apollo则是持续向各环境交付和更新这两款产品的基础平台。

四款产品并非并列关系，而是作为层相互叠加的关系。

层产品作用
AI应用层AIP（Artificial Intelligence Platform）将LLM连接到Ontology和业务动作，嵌入Agent和业务应用
应用·数据层Gotham / Foundry数据集成、建模、分析、业务应用
交付·运维层Apollo向云端、本地部署、气隙隔离环境等持续交付和更新软件

AIP与Gotham、Foundry有什么不同？

AIP不是独立的分析工具，而是在现有的Ontology和权限管理之上，将LLM安全地融入业务的产品。

AIP于2023年4月发布。此后，让客户在几天内试作用例的“AIP Bootcamp”导入方式，成为Palantir销售与导入的核心手法。关键在于，LLM并不直接操作数据库，而是通过Ontology中定义的对象和动作来运作。因此，Gotham、Foundry的“谁可以做什么”的权限模型也原样适用于AI。

Apollo为什么重要？

正因为有Apollo，Palantir才能将同一套软件从政府的隔离环境到民间云端一致地持续更新。

Gotham的客户中，存在与网络隔离的环境，以及机密等级不同的多个环境。Apollo是一种吸收这些环境差异、将软件交付自动化的机制。Palantir从2021年前后开始也将Apollo作为面向外部的产品推出。对FDE而言，它是避免“为每个客户分叉的代码需要手工维护”状态的基础。

FDE的工作方式在Gotham项目和Foundry项目中有什么不同？

Gotham项目由安全约束和机密性决定工作方式，Foundry项目则由业务理解和成果的速度决定工作方式。

在Palantir，相当于FDE（Forward Deployed Engineer）的职位在公司内部被称为“Forward Deployed Software Engineer”，深入客户现场，负责从发现问题到实现落地。无论哪种项目，“在客户身边构建”这一本质是相同的，但日常的约束条件大不相同。

工作环境和所需条件有什么不同？

Gotham项目中安全审查和工作地点的约束较大，Foundry项目则要求能够灵活深入客户企业的现场。

视角Gotham项目Foundry项目
工作地点多以客户设施内的限制区域或专用环境为主多为客户办公室、工厂与远程办公相结合
参与条件有时要求国籍或安全审查多数情况下在一般保密协议范围内即可参与
开发环境对可携带的工具和外部服务的使用有严格限制在云端环境中可使用相对自由的开发工具
沟通对象分析员、指挥官、调查负责人现场负责人、业务部门、经营企划、信息系统部门
成果衡量方式对任务执行的贡献、分析时间的缩短成本削减、交期缩短等业务KPI
对外发布大多无法公开业绩在客户许可的情况下，有时可作为案例公开

对在日本以FDE为目标的工程师来说，现实中接触机会较多的是Foundry、AIP系的民间项目。Gotham系的防卫项目由于国籍和审查的要求，能够参与的人有限。

从职业发展来看，哪个更有利？

哪个更有利取决于你的目标方向。更容易打磨出适用于各行业的通用FDE技能的，是Foundry项目。

在Foundry项目中，可以反复积累将不同行业的业务落到Ontology上的经验。这种“业务建模能力”是容易迁移到Palantir以外的FDE职位、数据平台导入支持、企业内部DX推进等角色的技能。另一方面，在Gotham项目中，可以获得高安全环境下的设计、运维、审计应对等稀缺经验。对于想在防卫、公共领域长期发展职业的人来说，这将成为优势。

从现场实务者的视角补充一点：无论哪种项目，受到认可的都是“能用客户的语言重新表述问题”。熟悉Palantir产品的操作只是入门。能否作为FDE创造价值，取决于能否与客户一起明确“这些数据是为了做出什么判断”。理解Gotham与Foundry的区别，正是读懂这一判断背景的第一步。
