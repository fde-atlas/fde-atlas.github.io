FDE 作品集项目：构建一个客户会实际使用的东西

原标题：FDE portfolio project: build something a customer would use

FDE Interview Prep · 2026-09-25 · 约 14 分钟读完

摘要

这篇来自 FDE Interview Prep 的文章主张：求职作品集项目应模拟前沿部署工程师的真实工作，即面向真实用户、处理混乱数据并据反馈迭代。文章引用 Palantir、Ramp、LangChain、ElevenLabs 等公司的招聘信号，指出没有证据表明作品集是硬性要求，但真实项目能给招聘官打电话的理由。作者提出四项检验标准，并给出三个项目模板：基于真实文档集的问答助手（含评测集）、整合两个混乱公开数据源的集成项目（含客户邮件）、为真实用户做的内部工具，还附上 README 写法、五分钟内演示脚本和面试话术。

要点

  • 作品集非硬性要求，但真实项目能促使招聘官联系你。
  • 四项检验：具名用户、混乱数据、有人用过、据反馈改动。
  • 三个模板：文档问答助手、双数据源集成、内部小工具。
  • README 应以用户开头，写明决策与已知局限。
  • 演示视频建议五分钟内，Palantir Build to Apply 有此要求。

你的 GitHub 上有一个待办事项应用、一个天气仪表盘和三个教程复刻项目，而它们除了你自己之外从未被任何人使用过。再增加一个这样的项目也无法让招聘者停止滑动屏幕。真正能做到这一点的作品集项目规模很小，运行在真实且杂乱的数据上，有一位试用过的具名用户，并且配有 README 和简短的演示视频来展示你所做的调用。本文是 FDE 简历指南 的一部分。它为你提供三个项目模板——一个 AI 项目、一个数据集成项目和一个内部工具项目——以及配套的 README、演示脚本和面试话术。

我们没有找到任何来源表明 FDE 招聘普遍要求作品集，也没有任何来源说明项目是如何评分的。这些来源真正支持的观点更简单：当你构建过真实的东西时，它给了招聘者打电话给你的理由，也给了面试官可以具体提问的内容。

由此，我们采用四项检验标准。这是我们的方法，而非任何雇主发布的评分细则：

  • 一个具名的用户。 一个有实际工作的人，而不是“用户们”。“我登山俱乐部的财务主管”可以通过。“任何想记录任务的人”则不合格。
  • 一份混乱的输入。 带有缺失、重复和奇怪格式的真实数据，或者由从未想过会有解析器的人撰写的真实文档。
  • 一个有人用过的第一版。 丑没关系，没人用不行。
  • 一次因用户而做的改动。 你砍掉的功能、你重做的界面、你了解到他们真正需要的东西。

第四项检验是教程式项目永远无法通过的，这正是它值得作为目标去构建的原因。以下是常见项目改进前后的对比：

典型项目FDE 式版本
一个待办事项应用咖啡馆团队使用了一个月的换班表
一个覆盖“任意 PDF”的聊天机器人面向某租户团体、基于一个城市住房法规的助手
一个著名数据集的仪表盘为一位本地记者整合的检查与执照记录
一个热门应用的克隆俱乐部财务主管至今仍在使用的报销追踪工具

如果客户部分比构建部分更让你担心，如何展示你能应对客户是本文的姊妹篇。ElevenLabs 的 FDE 招聘要求有与客户打交道的经验，并说明来自学生社团或副项目的经验也可以。来源 12Forward Deployed Engineer - Software Engineer - North America @ ElevenLabs发布方ElevenLabs（Ashby 招聘板）来源类型公司招聘启事 一个有真实用户的项目就算作这类经验。

模板一：基于真实文档集的助手

用户。 需要从一堆文档中回答同样问题的人：解答住房法规问题的租户协会志愿者、解释章程的社团秘书、回答课程政策问题的助教。

数据。 一个公开、有边界的文档集：某市的市政法规、某学区的会议纪要、某大学的手册。混乱正是重点所在：扫描页面、表格、覆盖旧条款的修正案，以及两份相互矛盾的文档。

第一版。 一个，即每一层都很薄、端到端连接起来：

  • 加载文档，将其切分为段落，并保留每个段落的来源和章节。
  • 为问题检索相关段落，并仅根据这些段落作答。这就是检索增强生成。
  • 在每个答案下方展示引用的章节。
  • 当检索结果不佳时，说“我在这些文档中找不到”，而不是猜测。

如何知道它有效。 与你的用户坐在一起，记下他们收到的问题，以及正确答案和答案来源的章节。这份清单就是你的黄金集。三行可能如下所示：

问题通过的标准
租金上涨需要提前多久通知？引用修正后的章节，而不是被取代的文本
房东可以不通知就进入吗？引用进入相关章节，包括其例外情况
我的楼受租金稳定政策保护吗？拒绝回答：不在这些文档中

一次示例性的首轮运行：

31 of 40

正确，且 9 个失误中有 6 个引用了被取代的章节。这一行告诉你该修什么。

在每次改动前后用它运行助手，并记下它答错的地方。免费问题你怎么知道你的 AI 系统有效？就是这个步骤的面试版本，值得用你自己的项目作为例子来演练。

展示什么。 一个带引用的好答案、一个它正确拒绝回答的问题，以及一个你发现并修复的失败案例，比如它曾以旧形式引用某个修正后的章节。

模板二：连接两个混乱公开数据源的集成

用户。 需要两个数据集相互印证的人：询问哪些获批户外就餐的餐厅检查结果不佳的本地记者、将食品分发点与公交站点匹配的食品银行协调员、核查哪些会员持有有效许可证的小企业协会。

数据。 两个公开数据源，以不同的方式描述同样的事物。NYC Open Data 同时发布了记者问题所需的两部分数据：DOHMH New York City Restaurant Inspection Results 和 Open Restaurant Applications (Historical)。两者没有共同的餐厅 ID：检查记录以一个

CAMIS

编号为键，而申请记录中的名称则是申请人自己输入的样子。共享的

BBL

和

BIN

代码只能把匹配范围缩小到一栋建筑，而不是一家餐厅。名称从来无法干净地匹配：一个文件里的“JOE’S PIZZA, INC.”在另一个文件里是“Joe’s Pizza LLC”。

第一个版本。 拉取两个数据源，规范化连接键，进行连接，并把所有未匹配的记录放进一个待审核列表，而不是直接丢弃。它的核心可以就这么小：

import re
TAIL = {"inc", "llc", "corp", "co", "ltd"}

def name_key(name: str) -> str:
    name = name.lower().replace("’", "'")
    name = name.replace("'", "").replace("&", " and ")
    words = re.sub(r"[^a-z0-9]+", " ", name).split()
    if words[:1] == ["the"]:
        words = words[1:]
    while words and words[-1] in TAIL:
        words.pop()
    return " ".join(words)

name_key("JOE'S PIZZA, INC.")  # joes pizza
name_key("Joe’s Pizza LLC")    # joes pizza

它只去除末尾的法律后缀，所以“Co-op Grocery”会保留为

co op grocery

。然后报告键匹配遗漏了什么。“Joes Pizzeria”不会匹配“Joe’s Pizza”，这没关系，只要它进入待审核列表、旁边附有地址，并且你能说出列表里有多少条记录。隐藏未匹配的行是让数据项目失去可信度的错误做法。

客户邮件。 按照真实项目的方式收尾。Ethyca 公布的前沿部署隐私工程师岗位的 take-home 作业要求候选人复现并诊断客户的 API 错误，然后撰写给该客户的回复邮件。Source 13Ethyca Technical Challenge -- Forward Deployed Privacy Engineer (FDPE)PublisherEthyca (GitHub)Source typecompany website 借用这一步：给你的用户写一封简短的邮件，说明哪些匹配了、哪些没匹配、为什么，以及你需要他们提供什么来弥补差距。把它放进代码仓库。我们关于为客户写作的课程讲解了这类邮件的结构。

要展示什么。 两个原始文件并排展示、连接结果、待审核列表，以及那封邮件。

模板三：为真实用户构建的内部工具

用户。 一个流程靠电子表格、聊天群组和某人的记忆运转的小团体：处理报销的社团财务、管理答疑时间队列的助教、追踪库存的家族企业。

第一个版本。 替代该流程中一个步骤的最小工具。对财务来说，这可能是一个可以上传收据照片和金额的表单、一个供财务审批的列表，以及一个用于银行的导出功能。没有账户系统，没有角色模型，没有设置页面。

让它成为 FDE 工作的部分。 在几天内（而不是几周内）把它交到他们面前，并观察他们如何使用。保持一份简短的日志：

  • 他们要求了什么；
  • 他们实际做了什么，而不是你期望的什么；
  • 你改了什么，又删了什么。

那份日志是仓库中最有价值的文件。它体现了 Jarvis 所描述的习惯：功能重于形式。Source 11前沿部署工程的未来 | OpenAI, Ramp, Nominal, DatalandPublisherSouth Park Commons (YouTube)Source typerecorded talk or interview 如果用户忽略了你引以为傲的仪表盘，只用导出功能，就直说，并表明你砍掉了仪表盘。

我们的行走骨架课程更深入地讲解了第一个版本必须包含什么，以及哪些内容可以造假。

招聘经理会读的 README

假设读者只会浏览你的 README，从不运行代码。为这样的读者而写，标题要指明用户，例如

# Housing-code assistant for the Elm Street tenants' association

，按以下顺序：

  • 面向谁： 协会里回答租户住房法规问题的志愿者。
  • 做什么： 基于城市法规回答问题，并引用具体条款。
  • 发生了什么： 用户用它做了什么，用他们自己的话。
  • 决策： 一个选择、你否决的方案，以及原因。
  • 已知局限： 哪些地方会出问题，以及你接下来会怎么做。
  • 我如何使用 AI： 你生成了什么，以及你手动核查了什么。
  • 运行方式： 一条命令。

几条规则让它行之有效：

  • 以用户开头，而不是技术栈。 技术栈放在最后，如果非要放的话。
  • 在顶部附近放一张截图或简短的 GIF，让手机上的读者无需克隆任何东西就能看到产品。
  • 让决策部分真实可信。 “当没有段落得分超过阈值时它会拒绝回答，因为关于驱逐通知的错误回答比没有回答更糟”体现了判断力。“用 React 构建”则不能。
  • 自己写出局限性。 如果面试官发现一个你已经指出的缺口，他会知道你很细心。如果他发现一个你没提到的缺口，那他得出的就是另一种结论了。

演示脚本

即使没有申请要求，也录一段简短的屏幕演示，并在 README 顶部附上链接。如果申请有长度限制，严格遵守：Palantir 的 Build to Apply 职位，针对部署策略师岗位，要求不超过 5 分钟。Source 6Deployment Strategist, Build to Apply - US GovernmentPublisherPalantir Technologies (Lever)Source typecompany job posting 以下时长是我们对这类项目的建议。

0:00

用户和痛点。

“这是为租户协会里回答住房问题的志愿者做的。目前他们要在一份很长的 PDF 里手动搜索。”

0:30

实际运行。

像用户那样操作。提出一个真实问题，展示答案和引用的条款。

1:30

棘手的部分。

展示你修复的故障，或未匹配记录的审查清单。“第一个版本引用了一条城市已修订的条款。现在它会先检查修订表。”

2:30

一个决策。

“我让它在检索效果不佳时拒绝回答，因为关于驱逐通知的错误回答比没有回答更糟。”

3:00

用户的反馈以及下一步计划。

以你接下来会与这位用户采取的下一步作结，而不是罗列功能清单。

关于记录失误和权衡取舍的措辞，课后作业演示视频文章中有完整讲稿。如果你正通过 Build to Apply 申请 Palantir 的部署策略师职位，我们的 Build to Apply 文章介绍了如何确定范围并录制演示。

把项目写进简历并用于面试

在简历上，用一行描述项目，包含用户和成果，并在旁边附上链接：

  • 弱：“用 Python 和向量数据库构建了一个聊天机器人。”
  • 强：“为租户协会志愿者构建了一个基于城市住房条例的助手；他们现在用它回答租户问题，并附上引用的条款。链接。”

应届毕业生或转行者可以把项目放在工作经历之前，因为那才是证据所在。FDE 简历指南介绍了它在页面上的位置。

在面试中，这个项目让你能回答一个今天就可以准备的问题。免费问题带我过一遍你简历上的一个项目要求你讲出问题、你的设计、哪里出了问题以及你会如何改进。可以这样开场：

“用户是我们租户协会里负责回答住房问题的志愿者。问题在于答案都写在一份没人能搜索的 PDF 里。我会带你过一遍第一版、她使用时哪里出了问题，以及我做了哪些改动。”

然后停下来，让他们引导方向。你已经给了他们三个可以深挖的点：用户、失败和改动。为每一点准备更多细节。

要从对方角度练习这种对话，免费练习案例让你在十分钟时限内面对一位问题模糊的 AI 客户，并根据你说过的话进行引用式评分。

为混合听众准备同一故事的第二个版本。向工程师和高管展示过往项目就是为此设计的练习。

常见错误及对应的解决办法：

  • 五个半成品项目。只链接一个完成的项目。其余的归档或取消置顶。
  • 没有用户。在写更多代码之前先找到一个用户。朋友社团只要真的在用就算数。
  • 技术栈优先的 README。围绕用户重写前三行。
  • 隐藏失败。把它们写进“已知局限”和演示中。它们是你最好的面试素材。
  • 夸大自己的贡献。如果某个库或助手完成了最难的部分，就直说，然后谈谈属于你的那些决策。

常见问题

FDE 的申请需要作品集吗？

有些需要。LangChain 在旧金山的 Deployed Engineer, Professional Services 申请表要求提交作品集，而 Palantir 针对其美国政府部署策略师职位的 Build to Apply 流程要求申请者构建一个 Foundry 和 AIP 项目并提交演示视频。在没有要求的情况下，附上一个项目链接仍能让招聘人员和面试官有具体内容可以提问。来源 4申请表发布方LangChain（Ashby 招聘平台）来源类型公司招聘信息来源 5Deployment Strategist, Build to Apply - US Government (Washington, D.C.) - Palantir on Lever发布方Palantir Technologies（Lever）来源类型公司招聘信息

我应该为前沿部署工程师职位构建什么样的项目？

构建一个具体的人能够使用的项目，基于真实且杂乱的数据，例如一个基于公开文档集的助手、一个连接两个公开数据源的集成，或一个供社团或团队使用的小型内部工具。Palantir 针对开放性问题的官方准备建议是找一个公开数据集，并想出一些有趣的用法。来源 1Palantir Careers | Navigating Open-Ended Questions发布方Palantir Technologies来源类型公司招聘页面

FDE 项目的演示视频应该多长？

如果雇主设定了时长限制，请遵守。Palantir 的 Build to Apply 职位（针对的是其美国政府部署策略师岗位，而非 FDSE 申请）要求提供一段 5 分钟以内的演示视频，以未公开的 YouTube 链接形式提交。在没有限制的情况下，视频应短到可以一口气看完，并以用户的问题而非技术栈作为开头。来源 6部署策略师，Build to Apply - 美国政府发布方Palantir Technologies (Lever)来源类型公司招聘启事
