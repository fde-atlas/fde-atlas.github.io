16道考核题全文与评分标准（全公开）

深圳市真实智元科技有限公司 · 2026-11-03 · 约 7 分钟读完

摘要

真实智元公开其FDE课程考核的16道题全文与评分标准。考核分五个环节（过程作业30%、中期项目20%、技术交付项目30%、终期客户答辩20%），题目按认知判断、发现、原型、生产交付、客户沟通、终期综合六组编排，每题映射五步法环节并附评分要点。允许使用AI但须能解释、验证并修改产物；终期评分中评测集、指标与归因占20%为最大单项，另设数据泄露、无人工确认、无法回滚等五项一票否决门槛。

要点

  • 考核分五环节：过程作业30%、技术交付项目30%权重最高。
  • 16道题分六组，覆盖认知判断到终期答辩全链路。
  • 允许用AI，但须解释、验证、修改，答辩现场抽问。
  • 终期评分七维度，评测·指标·归因占20%最大。
  • 设五项一票否决：数据泄露、无人工确认、无法回滚等。

考核结构（五个环节）

入学诊断不计分（30 分钟自测）→ 过程作业 30% → 中期项目 20% → 技术交付项目 30% → 终期客户答辩 20%。

环节 占比 形式
入学诊断 不计分 30 分钟自测：五问速查 + deployment gap 举例（用于分班与诊断，不设门槛淘汰）
过程作业 30% 各章 practice 产物，按「完成 / 可复核」两级计分
中期项目 20% Discover + Prototype 两阶段提交物
技术交付项目 30% Validate + Go live 两阶段提交物：评测报告 + 上线方案 + 生产工程产物
终期客户答辩 20% 三场汇报 + 临时变量现场调整（即 F16 毕业项目答辩）

AI使用规则：过程作业、技术交付项目与终期答辩均允许使用 AI 编程助手，考核点是「解释、验证、修改」——学员须能解释产物中的每一处关键决策、用测试 / 评测验证结果、并在 AI 建议出错时识别并修改（现场答辩会抽问「这行为什么这样写」）。「不借助 AI」的练习均为选修诊断，用于暴露离开 AI 后的真实理解缺口，不计入主考核分。

16 道考核题全文（六组）

每题标注与五步法六环节的映射。训练方法：限时作答 → 对照对应章的 practice 产物自评 → 弱项回到对应章重做实验。

A 组 · 认知判断（3 题）

考「是否真的理解这个岗位」。（答不出产品反哺通道的具体机制即不过。）

A1 · 前置认知3 分钟讲清 FDE 与售前 / 实施 / 驻场外包的区别——用职责重心表述（FDE 重心通常落在：写生产代码并对结果负责、处理现场问题、有产品反哺通道），并说明这是光谱而非绝对判据（对照 5.2 五维评估逐维看）。考察：是否理解相邻岗位是职责重心光谱而非真 / 假二分。评分要点：按 5.2 五维评估逐维对照：问题定义权、工程责任、生产结果、复用与反哺、商业参与度；能说明这是职责重心差异、不是岗位真假判据；能讲出产品反哺通道的具体机制（playbook / 组件 / 产品反哺工单）。
A2 · 前置认知用五维评估（问题定义权 / 工程责任 / 生产结果 / 复用与反哺 / 商业参与度，计费方式单列记录不当否决项）判断「按工时交付、无产品团队、无评测要求」的 FDE 岗位是否合规，给出逐维判断。考察：是否掌握五维评估的用法与计费口径（计费单列、不作一票否决）。评分要点：逐维给出证据与判断；计费方式单列记录、不当否决项；结论能落到「缺哪些维、向哪个相邻角色漂移」。
A3 · 前置认知解释 deployment gap，并举出模型能力无法直接转化企业价值的例子（数据 / 流程 / 权限 / 组织 / 合规至少三项）。考察：是否理解 FDE 存在的第一因：部署鸿沟。评分要点：能画出 / 讲清部署鸿沟的构成；举例覆盖数据、流程、权限、组织、合规中至少三项，且例子是「模型能力无法直接转化」而非「模型不行」。

B 组 · Discover（2 题）

考「能否把混沌诉求收敛为可做、可测、可授权的场景」。

B4 · ① 发现15 分钟收敛「给所有员工上企业级 AI 助手」：三类访谈对象、两个候选场景、被考核的人、被考核的指标、baseline、最坏情况、第一个数据权限请求。考察：需求收敛：把口号式诉求落成可验证的场景与授权路径。评分要点：三类访谈对象与目的清晰；两个候选场景可评测；指标、baseline、最坏情况齐备；第一个数据权限请求具体到对象与范围。
B5 · ① 发现「工单 / 有效客户 / 大客户」三部门三定义，设计轻量 Ontology：实体、属性、关系、数据来源、权限边界、冲突处理。考察：业务口径冲突的建模能力（Ontology 设计）。评分要点：实体 / 属性 / 关系完整；每个字段标注数据来源；权限边界明确；给出三部门定义冲突的处理规则。

C 组 · 原型技术（4 题）

考「动手能力与权限工程」。（全部可用脱敏数据或本地模型完成。）

C6 · ② 原型48 小时门店巡检报告 MVP：单场景、真实或脱敏数据、3 分钟演示脚本、记录 Prompt / 模型版本 / 输出样例。考察：在时间约束下交付可演示、可复现的最小原型。评分要点：单场景打通；数据真实或脱敏；演示脚本 ≤3 分钟；Prompt、模型版本与输出样例留痕可复现。
C7 · ② 原型（④ 的前置——权限工程）库存助手四个工具（查库存 / 查调拨单 / 创建调拨申请 / 催办通知）的权限分级：自动执行 / 人工确认 / 禁止开放 / 审计日志。考察：工具权限分级与审计设计。评分要点：四个工具逐一给出分级与理由；高风险动作保留人工确认；审计日志覆盖谁、何时、做了什么。
C8 · ③ 验证企业制度文档 RAG 评测方案：30 条黄金集、10 条难例、recall@5、引用正确率、拒答标准、baseline、优化前后对比。考察：RAG 评测集与指标设计。评分要点：黄金集 / 难例构成合理；指标定义（recall@5、引用正确率、拒答）可复算；有 baseline 与优化前后对比设计。
C9 · ② 原型销售日报异常检测选 workflow 还是 agent：自主规划、工具数量、失败处理、步数上限、人工介入点五个维度给依据。考察：workflow 优先、agent 按需的选型判断。评分要点：五维度逐一给出依据；结论与维度一致（而非先定结论再凑理由）；说明人工介入点。

D 组 · 生产交付（3 题）

考「上线之后出了事怎么办」。（重点看拦截层与回滚是否具体。）

D10 · ④ 生产交付四级灰度上线方案：影子运行 / 小流量 / 双轨对照 / 全量，附每级晋级条件、回滚条件、负责人。考察：灰度路径与晋级 / 回滚规则的具体性。评分要点：四级各有量化晋级与回滚条件；每级有负责人；灰度非机械必走时能按场景裁剪并说明理由。
D11 · ④ 生产交付模型上线后引用了已废止制度，用 trace 定位并修复：文档版本、索引更新、检索结果、引用校验、回归测试、旧数据下线。考察：用可观测证据定位并修复检索 / 索引问题。评分要点：trace 定位路径完整；文档版本与索引更新机制落地；引用校验与回归测试可复跑；旧数据下线有流程。
D12 · ④ 生产交付Agent 被诱导调用「创建付款申请」，完成安全复盘：攻击路径、风险等级、过程层拦截、人工确认、审计证据、回归案例。考察：越权与提示注入的安全复盘能力。评分要点：攻击路径还原清晰；风险定级有依据；过程层拦截与人工确认落地；给出审计证据与回归案例。

E 组 · 客户沟通（3 题）

考「技术承诺能否换算成对方考核表上的数字」。

E13 · ⑥ 结项汇报「准确率 85% 还是不够好」——分别向业务负责人、 IT 负责人、 CTO 解释并给出各自的行动项。考察：分层沟通：同一技术结论对三类角色各有一套说法与行动项。评分要点：三版说法各对准对方考核口径；行动项具体、可验收；不虚假承诺、不回避问题。
E14 · ⑥ 结项汇报客户临时加三个功能但只剩一周的范围谈判：当前范围、影响、变更成本、最小版本、书面纪要。考察：范围变更的谈判与书面化。评分要点：影响与变更成本讲清；给出最小可行版本；谈判结果落到书面纪要。
E15 · ⑥ 结项汇报（反馈回流部分衔接 ⑤ 回流沉淀）技术达标但使用率低的归因与下周行动计划：用户流程、权限、组织推动、培训、反馈回流、指标设计。考察：采用（adoption）问题的归因与行动计划。评分要点：从用户流程 / 权限 / 组织 / 培训等维度归因而非归咎用户；行动计划有负责人与时间；反馈回流机制落到指标设计。

F 组 · 终期综合（1 题）

即第 30 章毕业项目全流程：这正是 48 小时挑战考不了、必须由毕业项目承担的部分。

F16 · 六环节全覆盖（发现 → 原型 → 验证 → 生产交付 → 回流沉淀 → 结项汇报）连锁零售「门店运营智能助手」完整交付（第 30 章毕业项目）：13 项提交物 + 两个答辩临时变量（客户要求提前一周上线；安全团队拒绝提供生产数据），现场调整方案，不能只演示准备好的 Demo。考察：五步法六环节的全链路综合运用与临场调整。评分要点：13 项提交物齐全且可复核；对两个临时变量在 10 分钟内给出不牺牲关键安全门槛的可行方案；答辩能解释每一处关键决策。

三套考核的用途区分

  • 公开练习题（这16道题）：课程考核题库的公开练习集，用于限时自测、对照各章 practice 产物自评、定位弱项后回炉重做实验。
  • 课程终期答辩（F16）：即第 30 章毕业项目全流程，覆盖五步法六环节——生产交付与回流沉淀这两环是 48 小时挑战考不了的，由毕业项目单独考核。
  • FCB 48 小时挑战：另一套压缩考核形态（需求澄清 → 工作原型 → 评测报告 → 客户答辩四阶段），场景包另行封存、不与本题库混用；评定规则见 FCB 白皮书。

终期评分七维度

评测集·指标·归因（20%）是最大单项——这是 FDE 区别于 demo 工程师的分水岭。

维度 权重
问题定义 15%
数据·Ontology·权限 10%
原型与工程 15%
评测集·指标·归因 20%
安全合规监控回滚 15%
客户沟通 15%
Playbook·反哺·复盘 10%

评分原则：产物可复核、过程可审计、AI 可使用但须留痕；每维细分项仍需逐项合格。

五项一票否决门槛

以下任何一项出现，无论总分多高，考核不通过：

  • 严重数据泄露
  • 无人工确认执行高风险动作
  • 无法回滚
  • 无法复现提交结果
  • 评测集与成功指标不一致

与 FCB 的关系

课程考核对齐 FCB 能力基准 的 L1/L2/L3 能力分级与 48 小时挑战，不另设新的认证层级（FCB 本身不是认证、不发证书）。两者的关键失败门槛同构：终期出现上表任一项，技术分再高也不通过。完成课程答辩即获得 FCB 口径下的岗位能力评定记录；证据链要求见 FCB 白皮书「证据链：可投递的交付档案」一节。
