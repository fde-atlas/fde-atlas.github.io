自我改进型 Agent Harness：Harness²、MemoHarness 与 Meta-Harness 对比，附我们自己的运行结果

原标题：Self-Improving Agent Harnesses: Harness², MemoHarness and Meta-Harness Compared, With Our Own Runs

FDE Interviews · 2026-10-21 · 约 12 分钟读完

摘要

本文比较了三个自我改进 Agent Harness 研究系统：Meta-Harness 离线用标签搜索、MemoHarness 离线搜索加测试时逐案适配、Harness² 完全无标签在线改进。作者实测了 Harness² 的免凭证 demo，重算了 MemoHarness 的成本表，结论是三者都有效但提升幅度小于宣传，且成本优势取决于缓存命中率。对前沿部署工程师而言，值得借鉴的是一套编辑纪律而非框架：每次修改须对应轨迹中的具体时刻、先运行验证再保留、记录效果判定，并在离线跑完改进循环后冻结部署。

要点

  • 三种系统分别代表离线标签搜索、测试时适配和无标签在线改进。
  • Harness² 在 12 项设置中全部超过基线，但多数优势在噪声范围内。
  • MemoHarness 成本优势依赖 94% 缓存命中，无缓存时反比 Codex 贵。
  • 作者建议复制编辑纪律：修改须对应轨迹时刻并先运行验证。
  • 生产环境应离线跑改进循环后冻结部署，权限与安全检查不开放编辑。

自我改进的 agent harness 让一个模型重写围绕另一个模型的指令、技能、脚本和钩子，保留有效的改动并记住原因。三个 2026 年的研究系统展示了三种做法：Meta-Harness 在离线状态下利用标签进行搜索，MemoHarness 先离线搜索然后在测试时针对具体案例进行适配，而 Harness² 则在完全没有标签的情况下逐任务改进 harness。 我们运行了 Harness² 的免凭证演示，重新计算了 MemoHarness 的成本表，并复核了两篇论文的算术。我们的观点：三者都有效，收益是真实的但比标题宣传的要小，而从中最值得带走的是一种纪律，而不是一个框架。将每一次 harness 修改都关联到轨迹中的某个时刻。在保留之前，先在同一个任务上运行它。记录它是有所帮助、有所损害还是存在混淆因素。在离线运行昂贵的循环，然后交付一个冻结的 harness。

为什么现在这很重要

一年前，“harness” 指的是一个 system prompt 和一些工具。现在它指的是一棵文件树：始终开启的指令、常设规则、记忆文件、工具指南、按需技能、辅助脚本、子 Agent，以及挂钩工具循环的插件。我们在关于 harness engineering 的文章中介绍过团队如何手工构建这些。这些文件中的每一个都是有能力模型可以编辑的东西。这些论文回答的问题是：让模型进行这种编辑是否能让 Agent 变得更好，以及在什么样的证据条件下。

对于前沿部署工程师来说，这个问题非常具体。你到达客户现场，Agent 在他们的文档上以没人预料到的方式失败，而你只有一周时间。针对每个失败手工调整 harness 无法扩展到最初的几个失败之外。自动改进承诺可以做到这一点——前提是它能在没有标准答案的情况下区分好的修改和坏的修改。

最重要的一列是自上而下的第四列：每一种方法如何知道一次编辑是否有帮助。有标注时，你可以度量。没有标注时，Harness² 会比较同一任务的两次运行并解读差异，例如“参考运行从未重新打开其输出文件，而候选运行这么做了，其总额现在能对上了”。没有标注的自我改进就是自我一致性。 它能可靠地改进过程（Agent 是否检查了自己的工作、是否使用了正确的工具、是否完成了交付物）。但它无法告诉你答案是否为真。

数字，保留其中的噪声

Harness²（Google Cloud AI Research 与西北大学，2026 年 10 月）在三个基准上，用两个原生测试框架对两个执行器 Gemini 3.5 Flash 和 GLM-5 进行了测试，并使用 Claude Opus 4.8 作为编辑器。其中一步改进在全部 12 种设置中都优于基础测试框架，领先幅度为 1.2 到 11.8 分；每个范围五个候选方案又额外增加了 2.6 到 6.7 分。在我们对 Harness² 论文的拆解中，我们使用报告的均值和标准差（各三次运行）对每个单步优势相对于最强竞争方法进行了检验：12 个中只有 1 个明显大于噪声。符号模式是更有力的证据：在 12 个设置中的 12 个里领先于基础测试框架，在 12 个中的 11 个里领先于最佳基线。还有一个注意事项：在 JobBench 上，评分器也是 Claude Opus 4.8，即编辑测试框架并挑选最终答案的同一个模型。

MemoHarness（圣母大学、慕尼黑大学和南加州大学，2026 年 7 月）使用 GPT-5.3-Codex 搜索了一个六维测试框架空间，并在测试时针对每个案例进行适配。在一个包含 18 个任务的留出 Terminal-Bench 分割上，它得分为 0.806，而最强基线 Codex 为 0.722：每次运行大约多完成一个半任务。FinanceAgent 从 0.600 上升到 0.767，LiveCodeBench 从 0.900 上升到 0.967。作者异常坦诚：他们的局限性部分指出主分割只有 18 个任务，结果是点估计且没有置信区间，并且经验库和测试时适配并非在每种设置下都进行了单独消融。他们还报告了验证集选出的测试框架，而不是训练中的峰值（第 4 次迭代时的 0.833），这是正确的选择。

成本声明是一个缓存声明。 MemoHarness 在 Terminal-Bench 分割上报告的成本为 6.89 美元，而 Codex 为 10.28 美元，Claude Code 为 9.51 美元，因此它看起来不仅更好，而且更便宜。它还使用了其表格中任何系统最多的输入 token，1418 万个，其中 1332 万个（94%）是缓存命中。我们从表格中反推了每 token 的价格（它们在六美分误差范围内拟合了所有五行：约每百万输入 token 1.77 美元，缓存 0.18 美元，输出 13.36 美元），并在没有缓存命中的情况下重新计算了每笔账单。

在没有缓存命中的情况下，MemoHarness 的成本将为 28.06 美元，而 Codex 为 17.12 美元。作者指出他们的成本结果“取决于观察到的可缓存性”；图表显示了这有多重要。检索到的经验大多是稳定的文本，因此高缓存率是合理的。但是每个内存密集型 Agent 的成本表都是关于缓存命中率的声明，在计划最好的情况之前，你应该先为最坏的情况定价。

哪里出了问题

Harness² 的作者在他们自己的运行中列出了九个回归案例，对于从业者来说，这是两篇论文中最有用的部分。

  • 盲选会选中较弱的输出。 在一项编码任务中，选择器选择了得分为 55 的候选方案，而不是得分为 95 的那个，理由是偏好“最朴素的实现”。
  • 错误的前提会扩散。 一位编辑器写入了一条规则，规定某个键不得被“修复”；结果每个候选方案都继承了这个规则，每个候选方案都因此失分。
  • 检查器会带有其作者同样的盲点。 一位编辑器编写了一个验证脚本，对未通过真实测试的代码三次报告 PASS。用论文的话说：“由编辑器编写的检查器无法发现编辑器自身的假设。”
  • 经验教训会固化为规则。 一个从无标注运行中提炼出的技能，预先判定了一个法律立场，而评分标准奖励的恰恰是相反的立场。
  • 未经运行的编辑会造成伤害。 在没有参考运行、也没有库的情况下编辑测试框架，使 WB-code 从 73.4 降至 63.2。你从未运行过的编辑只是一个语法漂亮的猜测。 这与 SkillsBench 的结果教训相同：冷启动编写的 Agent 技能让 Agent 变得更差；参见 SkillsBench。

这份清单可以直接映射到控制措施上：向选择器展示源材料和明确的检查清单，轮换或多样化编辑器，使单一前提无法触及所有候选方案，让评分者远离编辑器之手，并要求由人来批准任何将成为常驻规则的教训。

我们对客户部署的建议

先复制纪律，再复制框架。 Harness² 提示词中的规则适用于任何测试框架和任何模型，而且零成本：

  • 每次编辑都要指明促使其发生的轨迹时刻。如果你无法指明，那这个编辑就是臆测。
  • 按顺序优先选择：一次分歧（某些运行已经做对了）、一个重复出现的失败，然后是一个可见的风险。永远不要修复运行中已经做对的部分。
  • 选择最廉价的形式：触发性流程用按需技能，重复的确定性工作用脚本，大输入小答案用子 Agent，只有当文字指令明显被忽视时才用钩子。常驻文字指令放在最后，因为它的每一个字在每次运行中都要付出代价。
  • 把关于该客户数据的事实作为事实写入，并明确标注，同时为整个领域编写流程。
  • 将每次编辑记录为有帮助、有害、无观察到效果或存在混杂因素，当只有一次运行支持它时，优先标记为存在混杂因素。
  • 每个任务最多保留一条可迁移的教训，附上其触发条件和证据，且仅当有对比支持时才保留。

离线运行循环，然后冻结。 选取 30 到 50 个有代表性的客户任务，以 k = 2 到 5 运行 Harness² 或你自己的版本，让一位工程师审查每一个被采纳的编辑和教训，并将 resulting 的测试框架作为带版本的制品发布。按计划或在生产质量下降时重新运行。在生产环境中进行按请求的自我改进会使成本增加一个数量级，并使 Agent 的行为在两个完全相同的请求之间发生变化，客户会注意到这一点。

保持边界固定。 权限、数据访问、网络出站和安全检查都留在可编辑表面之外。Harness² 允许编辑者在工具循环内编写 TypeScript 插件；在客户系统上，这是来自模型的可执行代码，需要像其他代码一样进行代码审查。

每个客户一个库。 库中保存着它从所学任务中获得的事实。跨客户共享库会把一个客户的数据带入另一个客户的提示词中。

许可证很重要。 Harness² 采用 Apache-2.0。MemoHarness 在我们 2026 年 10 月 21 日查看时没有许可证文件，这意味着阅读和学习没问题，但把它的代码复制到客户项目中需要作者的许可。

自我改进的 harness 是今年 Agent 领域最实用的研究方向，因为它能与你现有的模型配合工作，并产出人类可读的编辑。它不是停止审查的理由。如果说有什么影响，那就是它让工程师有更多东西需要审查，而且速度更快。如果你想在面试中谈论这个话题，要能解释有标注与无标注改进的区别、为什么跨设置的一致性胜过单一领先幅度，以及你会把哪些内容留在可编辑表面之外。我们的 Harness 工程课程和 agentic 评测与轨迹概念涵盖了这些基础内容。

常见问题

harness 是围绕模型使其成为 Agent 的一切：系统提示词、规则、记忆文件、工具指引、技能、脚本、子 Agent 和钩子。自我改进的 harness 让模型根据 Agent 的表现编辑这些部分，然后保留有效的编辑。模型的权重从不改变；改变的是围绕它的指令和工具。

Meta-Harness 针对带标注的搜索集离线搜索 harness 代码并部署胜出者。MemoHarness 也跨六个 harness 维度离线带标注搜索，把学到的东西存储在经验库中，然后在测试时无需标注即可将 harness 自适应到每个新案例。Harness² 完全不需要标注：对于每个新任务，它尝试两次限定范围的编辑，比较运行的表现，组合出后继版本，并把经验教训记录到库中供后续任务使用。

在已发表的结果中，是的，但优势不大。Harness² 在其报告的全部 12 个设置中都优于其初始 harness，提升幅度为 1.2 到 11.8 分，但它相对于竞争方法的大多数优势都在运行间噪声范围之内。MemoHarness 在一个包含 18 个任务的 Terminal-Bench 留出集上提升了 0.084，大约相当于每次运行多完成一个半任务。跨设置的一致性比任何单一数字都更有说服力。

相当于普通运行的数倍。Harness² 在预算 k 下每个任务运行 agent 4k 次，外加编辑器会话；当 k 等于 5 时，即每个任务 20 次运行和 17 次编辑器会话。MemoHarness 报告的账单低于 Codex 在 Terminal-Bench 上的费用，但其 94% 的输入命中了缓存；在没有缓存命中的情况下，我们根据其自身表格估算为 28.06 美元，而 Codex 为 17.12 美元。

通常不是按请求进行。先在具有代表性的任务样本上离线运行改进循环，审查产生的编辑和经验教训，然后发布一个冻结的 harness，并按计划或在质量下降时重新运行该循环。将权限、数据访问和安全检查保留在可编辑范围之外，并把每一项被采纳的编辑当作需要审查的代码变更来对待。

讨论 (5)

判定词汇表是我从 Harness² 借用到我们自己流程中的东西：有帮助、有害、未观察到效果、存在混淆。一旦我们诚实地面对现实，我们对客户提示词的大多数“改进”其实都存在混淆，因为我们一次改了三样东西，而且只运行了一次。

读者提问：在实际项目中，你会从这三者中的哪一个开始？

不是任何框架，而是方法本身。一份包含五十个真实任务的表格、agent 的轨迹记录，以及一条规则：每一次 harness 编辑都必须指明它所修复的轨迹时刻，并在发布前在同一任务上运行验证。如果这行得通且工作量足以证明其必要性，那么 Harness² 是最容易采用的，因为它不需要标注，而且是 Apache-2.0 许可。

缓存这一点可以推广到 MemoHarness 之外。任何将检索到的经验加入提示词的方法，都是在押注缓存命中。在每张成本表旁边都要求提供缓存命中率，并在你为最好的情况买单之前，先为最坏的情况定价。

对客户工作再多一点提醒：这个库除了名字之外，实际上就是训练数据。如果它从客户 A 的任务中学习，就可能把客户 A 的事实带入客户 B 的 harness 中。每个客户保留一个独立的库，并在数据协议中明确写明这一点。
