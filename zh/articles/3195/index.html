前沿部署工程师与软件工程的未来

原标题：Forward Deployed Engineers and the future of software engineering

Latent Space · 2026-07-01 · 约 7 分钟读完

摘要

Sierra 的 Agent Engineering 负责人 Natalie Meurer 在 Latent Space 访谈中阐述前沿部署工程师与 agent 工程师的角色定位。她认为 FDE 的核心是客户责任而非具体技能，Sierra 刻意采用 agent 工程师这一称谓。团队为客户构建客服 AI Agent，多数定制工作发生在模型之上的编排层，客户最快 40 至 60 天上线。她预测产品工程与前沿部署工程正在融合，通才型工程师将更有价值。

要点

  • FDE 的定义核心在于对客户负责，而非固定技能组合。
  • Sierra 称其为 agent 工程师，专注客服 AI Agent 的集成与开发。
  • 大部分定制工作在编排层完成，客户最快 40-60 天上线。
  • 产品工程与前沿部署工程正在融合，通才将更吃香。
  • 客服场景需一致流程，而非让系统每次自行摸索。

Sierra 的 Natalie Meurer 出席今天的 AI 工程师世界博览会。

Natalie Meurer 是 Sierra 的 Agent 工程负责人，她领导着一个由 120 多名工程师组成的全球团队，为企业客户服务构建对话式 AI Agent。在加入 Sierra 之前，她从事技术政策工作，自学编程，并在 Palantir 工作了五年。

前沿部署工程（FDE）是今天 AI 工程师世界博览会 的议题之一。正如 Meurer 在演讲前向 Latent Space 解释的那样，FDE 最初是一种将高技术员工派驻到客户身边的模式。但如今这一头衔涵盖了 AI 行业中广泛的角色——包括 Sierra 所称的 agent 工程师：一种将系统集成和 Agent 开发与对客户运营、产品和终端用户体验的理解相结合的工程师。

在本次问答中，Meurer 认为 FDE 的定义更多在于对结果负责，而非特定的技能组合，并补充说产品工程和面向客户的工程可能正在开始融合。

定义前沿部署工程

Latent Space： 你对前沿部署工程师的定义是什么？

Natalie Meurer： 这正是我这场演讲的核心：这个角色缺乏一致的定义。

如果纵观它从历史到现在的发展轨迹，它的定义更多体现在对客户负责，而不是角色的形态或你所做的工作本身。

拥有这种责任意识是有力量的。但相关技能组合的范围已经变得如此宽泛，以至于几乎变得毫无意义。

Latent Space： 你是如何进入这类角色的？

Meurer： 我最初从事技术政策工作。我是一个业余自学编程的政策迷，这让我在 Palantir 获得了隐私团队工程师的职位。

我在那里工作了大约五年，涉及执法、国防和基础设施工程。之后我去了商学院，因为我想把商业维度融入进来。随后我加入了 Sierra，并创建了 agent 工程职能。

为什么 Sierra 称他们为 agent 工程师

Latent Space： Palantir 的前沿部署工程模式对 Sierra 的这个角色有影响吗？

Meurer： 有一定影响，不过我们有意将这个角色称为 agent 工程师，而不是前沿部署工程师。

前沿部署工程的含义太宽泛了。我们认为这个头衔应该体现技术工作的形态，而不仅仅是贴近客户这一要素。这就是我们选择 agent 工程师这一称谓的原因。

我认为 agent 工程是前沿部署工程的一个子集，或者与之相邻。它描述了一种更具体的面向客户的工程形式，专注于开发 Agent。

agent 工程师做什么

Latent Space： 你的团队在与客户合作时会做些什么？

Meurer： Sierra 为呼入和呼出客户服务构建对话式 AI Agent。我们的工作包括将客户系统与低延迟的语音和聊天 Agent 集成，以及通过电子邮件运作的 Agent。

这个角色需要数据集成等技术能力，但也需要品味。在设计语音 Agent 时，你需要理解什么样的声音听起来悦耳、什么样的体验会让人感觉有人情味。这一要素是 Agent 工程所特有的。

Latent Space： 合作是从一个已确定的用例开始，还是你们帮助客户决定要构建什么？

Meurer： 我们与客户一起进行需求探索。我们试图找到真正困难的问题——因为我们擅长解决困难问题——与具有重大业务影响的问题之间的交集。

例如在金融服务领域，这可能从争议处理开始。它很复杂，必须正确完成，但同时也是一项需要高情商的互动。如果有人在信用卡账单上看到一笔欺诈性扣款，他们可能会感到恐慌，Agent 需要安抚他们的情绪。

几乎每一位 Sierra 客户都在朝着将 Agent 用作其前台交互式语音应答系统的方向前进：也就是客户来电时第一个应答的实体。

艰巨的工作往往在模型层之上

Latent Space： 这项工作有多少涉及底层 AI 模型？

Meurer： 我们把我们的 Agent 视为一个经过编排的模型星座。在内部，我们不断评估最适合特定任务的模型，并将其中最好的成果带给客户。

在实践中，大多数针对客户的工作发生在编排层，而不是模型本身。我们有时会与客户自己的模型集成，我们也帮助客户使用平台并自行构建 Agent。

很多工作涉及帮助他们应用自己的内部知识和上下文。

定制部署与可复用模式

Latent Space： 这项工作有多少是针对特定客户的，有多少可以复用？

Meurer： 两者兼有。

每位客户构建的 Agent 都是有意针对其组织定制的。它应该代表与该特定品牌尽可能最佳的互动体验。

其他能力则更具可复现性。例如，从知识库中回答问题是一个相当普遍的问题。我们还拥有覆盖金融服务、医疗健康、旅游与酒店业以及零售业的行业专家，他们带来领域知识和最佳实践。

但我们所售产品的根本吸引力在于定制化。我们看到各行业的大型组织最快在 40 到 60 天内就达到了生产环境。

每个 Agent 仍然围绕客户的 API、系统、标准操作流程、品牌和语气进行定制。

作为企业系统的 Agent

Latent Space: Agent 开发是否正在变成一个以编排为主的问题？

Meurer: 多 Agent 架构有很多不同的形态。“Agent”这个词既可以指接听电话的那个实体，也可以指一个子 Agent，甚至可以指一个配备了工具的单一提示词。

我们合作的每一家企业都想知道，如何维护其 Agent 生态系统能够做的一切。它需要管理所有的集成，以及为 Agent 做出贡献的所有团队。

这其中有一部分是变更管理的问题。

在 Sierra，我们倾向于把单个 Agent 视为管理整个客户交互过程，而不论其中涉及什么具体的子任务。我们把这些子任务称为 journeys。

尽管如此，企业仍需要一种方式，让成百上千的人能够为这些系统做出贡献，了解发生了什么变化，并遵循一个明确的发布流程。

产品工程与 FDE 正在融合

Latent Space: 随着企业积累更多内部专业知识，FDE 这一角色将如何演变？

Meurer: 我认为它仍将保持面向客户的属性。但当编写代码变得廉价时，把客户洞察直接转化为产品也变得更容易了。

因此，产品工程与前沿部署工程在某些方面正在融合——至少在这两种角色中最优秀的人身上是如此。

如果你是产品工程师，你应该去和客户交流。如果你是前沿部署工程师，你应该去构建产品。我认为这是新变化。

面向客户仍将非常重要。即使你拥有一个类似 AGI 的推理模型，每次都能自己想出如何执行某个流程，你仍然需要把那个流程恰当地编码进去。

你不会希望系统在那周的第十万次订单退货时还在独立摸索如何处理。你希望它遵循一个一致的流程。

这使得客户服务不同于其他一些 Agent 用例。编程 Agent 通常是在第一次尝试解决一个新问题。而在客户服务中，你解决的本质上是同一个问题，只是表述略有不同，一周可能要处理十万次。

这对平台以及帮助客户编码其规则的合作伙伴都提出了不同的需求。构建 Agent 会变得越来越容易，但能够与客户合作并把所学转化为产品的人，永远都会有一席之地。

为什么通才可能变得更有价值

Latent Space: 开发者会越来越需要产品技能和面向客户的技能吗？

Meurer: 我是这样认为的。我认为最优秀的开发者会培养这些技能。

很多人都在问，一两年后工程师这个角色会是什么样子。一种观点认为，专家会变得更加重要，因为他们掌握着 Agent 不容易获得的知识。

另一种观点，也是我更倾向于的，是通才会变得更有价值。

前沿部署工程历来是典型的通才角色，因为它将工程能力与面向客户的工作性质结合在一起。

因此，前沿部署工程师——或者说 Agent 工程师——身处 AI 和工程领域最具前瞻性的方向之一。

Latent Space: “Agent 工程师”最终会成为默认的称呼吗？

Meurer: 我不确定。我预计工程这个整体会朝着更全面的定义发展，这个定义可能会纳入更多我们目前所称的前沿部署工程的内容。

目前市场上有市场推广工程师、前沿部署工程师、Agent 工程师和 AI 工程师。

我认为这些都会成为工程这门手艺的不同组成部分。我们还会发现工程师可以从事的全新工作。
