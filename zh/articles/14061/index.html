0.1前沿部署工程师做什么

你将能够用雇主自己的语言，用三句话描述 FDE 工作，说出三家公司的成功衡量标准，并判断一个岗位是配置平台还是构建定制系统。

内容涵盖

  • 雇主写下的定义
  • 一位客户，多种能力
  • 一周的工作内容——来自亲历者的讲述
  • 成功如何衡量——逐家公司解析
  • 平台配置还是定制构建
  • 这份工作不是什么

核心要点

  • 这份工作是在客户的问题现场构建并交付软件，多家雇主在职位描述中明确说明了这一点。
  • 这里引用的雇主以客户发生了什么变化来评判工作，措辞各不相同：对客户目标的影响、生产环境的采用、采用而非收入，或第 30 天有什么不同。如果职位描述中说明 FDE 是计费的，那么按规格交付也算数。
  • Palantir、Google 和 Cursor 都通过与咨询工作对比来定义这个角色：Palantir 将其与顾问的一次性分析相对比，Google 与“传统咨询角色”相对比，Cursor 则说“FDE 不做咨询”。
  • 从职位描述中的动词判断该角色是配置平台还是构建定制系统，并优先讲述与之匹配的故事。

练习

  • 建筑许可需要数月
  • 为什么选择前沿部署工程，而不是软件工程师岗位？
  • 讲一次你在客户环境中而非自己环境中工作的经历。最难的是什么？
  • 你什么时候会告诉客户他们根本不需要工程师驻场？ Pro

0.2FDE、软件工程师、解决方案架构师、售前工程师：如何区分

面对任何面向客户的职位描述，你都能将其归类为 FDE、SA、SE 或 SWE 工作，并指出决定分类的具体表述。

内容涵盖

  • 为什么这些头衔界限模糊
  • 生产代码与概念验证
  • 售前、售后，还是两者兼有
  • 配额、OTE 以及薪酬基础透露的信息
  • FDE 在组织架构中的位置
  • 一家公司，两个头衔，四项测试
  • 基于真实职位描述语句的分类练习
  • 答案与决定性的措辞
  • 在面试循环中如何表达

核心要点

  • 找到说明工程师构建什么以及在哪里运行的语句：为单个客户编写的生产代码是 FDE 工作；原型、演示或指导性实施是 SA 或 SE 工作；为所有客户构建的同一功能是 SWE 工作。
  • 售前与售后并不能清晰区分这些角色：OpenAI 和 LangChain 的 FDE 类职位描述两者兼有。不如问这个角色在签约后负责什么。
  • 工程类头衔上出现 OTE 意味着你的部分薪酬是浮动的；在现场面试前，问清比例以及浮动部分以什么指标衡量。
  • 当职位描述无法回答四项测试中的某一项时，那项测试就成为你问招聘者的问题。

练习

  • 为什么选择前沿部署工程，而不是软件工程师岗位？
  • 你如何在为单个客户构建定制方案与推动产品改进之间做决定？ Pro
  • 你有哪些面向客户的工作经验？请具体说明客户是谁。

0.3为什么这个角色恰在此时兴起

说明 FDE 团队为何存在、你的目标公司何时组建了这样的团队以及你为何现在跳槽，不要使用经不起第一个追问的增长数字。

内容涵盖

  • 从模型 API 到可运行部署之间的差距
  • 为什么是现在
  • 这个术语的由来
  • 谁组建了团队，以及何时组建
  • 为什么增长数据各不相同
  • 团队的成立时间能告诉你什么
  • 一次简短交流中的两个追问
  • 这对你的面试陈述意味着什么

核心要点

  • 说出模型 API 与可运行部署之间差距的四个组成部分（连接器、身份、客户评测和回退方案），并说明你会如何应对每一项。
  • Palantir 声称开创了这个职位，而我们找到的资料都没有给出创立年份，所以绝不要提供年份。
  • OpenAI、AWS 和 Microsoft 在几周内相继宣布了有资金支持的部署组织（OpenAI 的是一家由其多数股权持有并控制的新公司，而 Microsoft 的覆盖范围不止 FDE），但几家大型雇主表示，在这些组织成立之前他们就已经有 FDE 了。
  • 来自不同数据集的增长数据无法相互比较，因此引用时要么注明来源和时间窗口，要么干脆不引用。
  • 用两个部分回答“为什么是现在”：一是目标公司自己有明确日期的 FDE 决策，二是为什么你在职业生涯的这个节点选择行动，而不是引用市场统计数据。

练习

  • 为什么选择这家公司，为什么是现在？
  • 请讲讲让你走到今天的职业选择。你为什么做出每一次转变？ Pro
  • 未来两年你最愿意投入解决哪类问题？ Pro

0.4谁在招聘 FDE，以及使用哪些职位名称

你能够列出目标公司实际发布的职位名称，并解释为什么只搜索“forward deployed engineer”会漏掉相关职位。

内容涵盖

  • 四条搜索规则
  • 按雇主逐一列出要搜索的职位名称
  • 一个招聘网站，从头到尾搜一遍
  • 名不副实的职位名称
  • 当职位搜索结果为空或不明确时
  • 咨询公司和绑定平台的职位
  • 职位名称透露的级别信息
  • 建立你的搜索清单

核心要点

  • 一些雇主以其他职位名称招聘 FDE 工作，例如 Deployed Engineer、Agent Deployment Engineer 和 Software Engineer, Agent。
  • 一些带有 FDE 头衔的职位描述的是现场硬件、应用支持或面向销售的工作，所以在信任头衔之前，先问清楚你要构建什么、它将在哪里运行、你向谁汇报。
  • 职位名称后面的后缀——指明产品、地区或安全审查项目——可能正是决定该职位是否适合你的关键词。
  • 除了职位名称，还要按职责搜索，并在信任搜索结果之前先仔细阅读其返回的内容。

练习

  • 你认为自己处于什么级别，为什么？
  • 这个团队为政府客户服务。你是否持有或能否获得安全审查许可，你对这类工作有何看法？ Pro
  • 你用过我们哪些 API 或产品进行开发，你觉得哪些方面有局限？ Pro

0.5 差旅、地点和驻场时间：先读职位描述，再提问

在与招聘人员通话之前，你就可以说明某个具体职位要求的差旅量、你将就此提出的问题，以及你自己的底线。

内容涵盖

  • 先读差旅那一行，再看其他内容
  • 两行差旅描述，从头到尾逐一解读
  • 不同雇主之间的差异，以及同一雇主内部的差异
  • 远程不等于没有差旅
  • 个人经历者如何描述
  • 先确定你的底线，再提问

核心要点

  • 明示的差旅范围从偶尔出差到全年大部分时间不等，而且同一家雇主内部也会因团队而异。
  • 远程职位仍可能要求定期拜访客户。
  • “灵活”可能指你的灵活性，也可能指客户的灵活性，而“最多”可能就是常态：要问清楚是谁的灵活性，并按上限做打算。
  • 以周为单位确定你的差旅底线，尽早告知招聘人员，并询问哪些团队符合你的要求。

练习

  • 这个职位需要出差到客户现场。你能承诺什么？什么情况会让你无法接受？
  • 这个团队为政府客户服务。你是否持有或能否获得安全审查许可，你对这类工作有何看法？ Pro
  • FDE 工作可能意味着出差和频繁的上下文切换。告诉我你是如何应对一段持续高强度工作期的。 Pro

0.6 如何逐行解读 FDE 职位描述

把任何一份 FDE 职位描述转化为一页纸的准备计划：你会构建什么，薪资和差旅的真实含义，以及面试最可能先考察什么。

内容涵盖

  • 职位描述页面
  • 能揭示真实工作内容的职责描述
  • 你能弥补的要求与你无法弥补的要求
  • 一份职位描述实例解析：Okta 的高级 FDE
  • 第二份职位描述实例解析：Databricks 的高级 FDE
  • 两条 AI 实验室职位描述的简要解读
  • 把职位描述转化为准备优先级
  • 每个目标公司保留一页记录，每轮面试前重读

核心要点

  • 对职责条目进行排序而非简单计数；你最具体的两条职责所指向的技术标签，就是你对应聘流程考察重点的猜测，而这个猜测需要通过与招聘人员交流来验证。
  • 始终记录薪资是基本工资、总目标薪酬（OTE）还是未注明，并记下你查看的日期。
  • 在一家公司的多个职位中重复出现的条目描述的是团队整体；而提到具体协议、平台或产出的那条，才是你应该优先研究的主题。
  • 为每家目标公司保留一页职位描述记录，并在每轮面试前重读该轮所需的内容。

练习

  • 你解决过的最难的技术问题是什么？带我了解其中的细节。 Pro

  • 你用过我们哪些 API 或产品进行开发，你觉得哪些方面有局限？ Pro

0.7桥梁故事，以及简短的“为什么选择 FDE”回答

你可以用一个两分钟的故事把过往工作与 FDE 职位联系起来，并基于这个故事给出一个“为什么选择 FDE 而不是软件工程”的回答，这个回答能经受住三轮追问。

内容涵盖

  • 招聘负责人认为哪些特质预示着优秀的 FDE
  • 你已有的证据
  • 教学、创业与第一份职业
  • 桥梁故事的结构
  • 基于故事构建的简短“为什么选择 FDE”回答
  • 经不起追问的理由
  • 针对追问进行演练

核心要点

  • 构建一个能传递两种信号的回答：一是被客户和成果所吸引，二是证明你能把东西做出来。只展示前者，可能会被解读为要离开工程岗位。
  • 桥梁故事要点名一个客户、他们提出的要求与实际需要之间的差距、你构建了什么，以及给他们带来了什么改变。
  • 在高级（senior）级别，同一个故事要体现你端到端地对客户的成果负责。在资深（staff）或首席（principal）级别，它要点出多个客户共同面临的问题、其他工程师在其基础上继续构建的设计，以及在你离开后由谁接手推进。
  • 一个理由要能经受住追问，需要来自你自己的工作经历、点明 FDE 角色能提供而产品角色不能提供的东西，并且承认一种代价。
  • 先给出简短回答，被问到时再讲故事，并在问题页面上针对“为什么不选择产品工程？”对两者进行演练。
