定义 2026 年世界博览会 AI 工程的五大趋势

原标题：5 Trends That Defined AI Engineering at World’s Fair 2026

Latent Space · 2026-07-14 · 约 11 分钟读完

摘要

Latent Space 总结了 2026 年 AI Engineer World's Fair 的五大趋势：AI 工程重心从 Agent 本身转向其外围系统，循环工程成为新的控制层，前沿部署工程师推动 AI 进入企业，编码 Agent 取代 IDE 成为主流开发界面，各大平台围绕技能构建 Agent。文章认为 AI 工程实践正融入主流软件开发。

要点

  • Lilian Weng 新文提出重心从 Agent 转向 harness 工程
  • 循环工程成为人类监督 Agent 的控制层
  • 前沿部署工程师推动企业采用 AI 与软件工厂
  • 编码 Agent 取代 IDE，成为开发者主要界面
  • Anthropic 带火的技能成为各平台构建范式

AI 工程在过去三年里取得了长足进展。当 swyx 于 2023 年 6 月创造“AI 工程师”一词时，他是在为从大语言模型大爆发中涌现的一类新型开发者命名。如今看来这已是陈年旧事，但请还记得，我们曾把 AI 与软件开发的交叉领域称为“提示工程”？那距离 swyx 重新定义这一概念仅过去数月。

最近的AI 工程师世界博览会充分展示了这个领域已经成熟到何种程度。“AI 工程师”是否已在各地成为正式的职位头衔，几乎已无关紧要。过去三年围绕 AI 发展起来的工程实践——构建编码 Agent、设计 harness、管理上下文、评估模型输出，以及编排日益自主的系统——正在成为主流软件开发的一部分。

本文不聚焦 AIEWF 上的各个具体发布，而是提炼出五个更大的趋势，以展示 2026 年 AI 工程的现状。

1：焦点从 Agent 转向其周围的系统

观察 AI 工程如何演进，最清晰的方式之一就是对比前 OpenAI 研究员、现为 Thinking Machines Lab 联合创始人 Lilian Weng 的两篇文章。她 2023 年那篇影响深远的文章《LLM Powered Autonomous Agents》从规划、记忆和工具使用三个角度描述了 LLM Agent 的构造。AutoGPT、BabyAGI 和 GPT-Engineer 都在她的例证之列——这些概念验证系统预示着自主 Agent 或许很快就能变得实用。

她 2026 年的新文章《Harness Engineering for Self-Improvement》则采取了截然不同的视角。Weng 认为，重点不应放在 Agent 本身，而模型周围的系统已变得同样重要：即管理工作流、上下文、权限、评估、持久状态和持续改进的 harness。换言之，AI 工程已超越了对模型进行提示的阶段，转向围绕模型构建可靠系统的工程。

编码 Agent 循环；图片由 Lilian Weng 提供

这一转变在 AIEWF 上备受关注。我认为 AutoGPT——那个2023 年人人热议的备受瞩目的自主 Agent 项目——今年甚至都没有被提及。取而代之，讨论的焦点是 Claude Code、Codex、Gemini CLI、Cursor、Warp，以及让编码 Agent 在生产环境中可靠运行所需的各种基础设施。

我记得在 2023 年的活动上，AutoGPT 的炒作让我很反感，主要是因为所有讨论似乎都聚焦于把人从流程中剔除。但过去几年我们了解到，Agent 的完全自主不仅不可靠，甚至也并非人们所期望的——尤其是在大规模场景下。因此，在 AIEWF 上，Agent 主要被定位为增强 AI 工程师，而非取代他们，这让人松了一口气。

在 AIEWF 第二天的 OpenAI 主题演讲中，Romain Huet 强调了这一点。他认为，借助 OpenAI 的 Codex 等工具，工程师可以更轻松地与 Agent 协作。正如他所说：“软件吞噬了世界，然后 AI 吞噬了软件，而现在我们想说的是，AI 工程师正在吞噬世界。”

尽管 AI 工程师的能力日益强大，但人们也有一种感觉：即使是前沿公司也不完全理解他们的模型是如何演化的——那么工程师究竟能对模型拥有多少真正的控制权呢？在另一场主题演讲中，Anthropic 的 Thariq Shihipar 谈到他们最新的模型 Claude Fable 就像一个有机系统——“模型是培育出来的，而不是设计出来的。” 他说存在一种“能力冗余”，“Claude 的变聪明方式是不均衡、跳跃式的。”

这更加说明我们需要为 Agent 化开发构建系统，以便对输出进行评估和监控。

2：循环工程是新的控制层

到 AIEWF 第一个上午的主题演讲结束时，很明显“循环”是本次活动的当日热词。撇开这个词被过度使用不谈，它确实凸显了 AI 工程领域的一个关键矛盾：Agent 应该拥有多少控制权，而人类又应该在哪里保持在循环之中？

OpenClaw 创作者 Peter Steinberger 倡导构建更好的循环。

现在许多顶尖工程师采取的一种方法，是把自己置于“外循环”中——监督 Agent 在内循环中完成的大体自主的工作。

Roland Gavrilescu 是 Introspection 的联合创始人兼 CEO，这是一家为部署自我改进系统构建基础设施的新公司。在接受 Latent Space 采访时，他解释了“自动研究”的概念如何为 Agent 循环提供必要的反馈结构：

“你可以把这个系统想象成有一个内循环和一个外循环。内循环是与用户交互并执行工作的主系统。自动研究更关注的是外循环：另一个研究和维护主系统的系统。”

外循环可以包含反馈信号、评测和人类输入。所以它可能仍然大体上是自主的，但关键在于它是对主 Agent 循环的一种监督方法。前 Google 工程负责人 Addy Osmani 对此有一句精辟的话：“Agent 可以承担更多内循环的执行工作，但外循环仍然是工程。”

“循环工程”这个词在 AIEWF 期间被多次提及，这表明构建这些循环系统是人类 AI 工程师的职责。就连 OpenClaw 的创造者、“ClawFather”Peter Steinberger 也特别强调要把自己放在外循环中。在 OpenAI 的主题演讲中，他解释道：“Agent 运行内层执行循环；我在外循环中设定方向并做出决策。”

AIEWF 上的循环之争。

在最后一天，一场现场辩论举行，探讨完全自主的 Agent 是否真的有能力管理循环。来自 HumanLayer 的 Dex Horthy 声称“炒作已经跑在了严谨性前面”。他并非反对循环本身，他指出 Kubernetes 就是建立在控制循环之上的——“但那些是确定性循环。”Ralph Loop 的创造者 Geoffrey Huntley 承认循环属于“前沿思维”，但他给观众留下了一个值得深思的绝妙类比：

“我们现在有点像火车司机。这就是我们的工作：让火车保持在轨道上。”

3：AI 工程进入企业

这种与 AI 工具协作的工作方式正开始进入企业，通常是通过一个名为“前沿部署工程师”（FDE）的新角色——工程师直接与组织合作，落地 AI 能力。

在 Sierra 领导 FDE 团队的 Natalie Meurer 告诉 Latent Space，将 AI 落地到组织中通常需要大量的编排工作。“我们合作的每一家企业都想知道，如何维护其 Agent 生态系统能够做的一切，” 她说。“它需要管理所有的集成，以及所有为 Agent 做出贡献的团队。”

Cursor 的 Pauline Brunet 在 AIEWF 的一场分享中谈论 FDE。

在 AIEWF 的分享中，Cursor 的 Pauline Brunet 谈到了他们的 FDE 在每个项目中力求实现的目标：

“当我们在项目结束时离开——就我们而言，我们部署了云端 Agent、长时间运行的 Agent、自动化，并且基于我们的 Cursor SDK 构建了应用程序——当我们离开时，对他们来说这是严格的 ROI。这意味着我们走后他们不会把东西关掉。”

大会上另一个被频繁使用的术语是“软件工厂”。Brunet 说，在 Cursor，“软件工厂意味着长时间运行的 Agent 在整个过程中帮助人们”。这基本上就是她的 FDE 团队负责落地的东西，他们与客户的工程师并肩工作。

人类工程师在软件工厂中的定位是企业关注的关键问题。Warp CEO Zach Lloyd 解释道，组织需要选择生命周期的哪些部分进行自动化，以及应该在哪些环节把人类引入循环。

Warp 的 Zach Lloyd 谈构建那个构建产品的工具。

“你可以选择你的代码仓库、你想要自动化的软件生命周期环节，以及应该让人类介入的节点，”Lloyd 在谈到他公司新推出的软件工厂平台 Oz 时告诉我们。“不同的组织和代码库会有不同的偏好。你要完全自动化代码审查吗？还是让人类来审查某些高风险的变更？”

企业关心的另一个问题是如何在 AI 系统中管理其独特的组织数据。Atlan 的 Prukalpa Sankar 在大会上谈到了“上下文工程”，并在一条推文中解释说，重要的是要考虑“上下文如何从你的业务系统流入共享的公司大脑，然后通过 MCP、API 和检索输出到 Agent、副驾驶和应用中”。

最后， lest 我们以为企业已经全面拥抱 Agent，Cursor 的 Brunet 指出，企业对 AI 的采用“仍然集中在早期采用者之中”。因此，在这个阶段，找到“组织内部合适的拥护者”对 FDE 来说是一个挑战。

4：编码 Agent 取代 IDE 成为开发者界面

自首届 AI 工程师峰会以来，最大的实际变化或许就是开发者日常与 AI 交互的方式。

2023 年，AI 辅助编程主要是指 GitHub Copilot 补全接下来的几行代码。大多数开发者仍然几乎自己编写所有代码，把 AI 当作智能自动补全工具使用。但现在我们有了 Claude Code、Codex、Gemini CLI、Cursor 和 Warp 等工具。这些“编码 Agent”通常能够理解更宏观的目标，探索代码库，修改多个文件，运行测试，调试故障，并在把结果交回开发者之前自主迭代自己的工作。

在 Barr Yaron 的 AI 工程调查中，编码 Agent 是一个关键趋势。

编码 Agent 的这一趋势如今也延伸到了 Web 开发领域——随着 Vercel 最近发布的 eve，该公司称之为“Agent 框架”，可与其广受欢迎的开源 React 框架 Next.js 相媲美。

Vercel 的软件负责人 Andrew Qu 在 AIEWF 上告诉 Latent Space，Agent 实际上是一种新型软件。“它们（Agent）不像 Web 应用那样可预测，”他解释道。“基础设施可能看起来相似，但交互、界面和输出要动态得多。”

Qu 补充说，为 Agent 开发构建框架的工作远未结束。“一年前，我们不知道沙箱会变得如此重要，也不知道对安全代码执行和长时间运行任务的需求会有多大，”他说。“随着我们从生产环境中了解到更多，还有更多东西需要构建。”

A 代表 Agent？Andrew Qu 展示 Vercel 的三角形标志。

这让我们回到软件工厂的趋势，即开发者同时管理多个 Agent。Charlie Holtz，Conductor 的 CEO，在 AIEWF 大会上提醒听众：无论使用什么编码工具，人类工程师都应始终保持掌控。

“我不希望未来围绕工厂来构建，”Holtz 说。“我想感觉自己是一个人，我想处于心流之中，我想站在乐队前挥动指挥棒。”

大会上有一种感觉：AI 工程师们尚未就哪个说法更合适达成一致：是软件工厂，还是乐队？即使是 loopmaxxing 的倡导者 Geoffrey Huntley，也提醒大家在自动化方面不要操之过急：

“我最担心的是，明年的这个时候，在大会上我们会看到一大堆人说，我们的工厂失败了，我们的循环失败了。这些是我们尚未弄清楚的事情。”

5：每个 Agent 平台都在围绕技能构建

大会的讨论热点之一是“技能”，这是 Anthropic 在去年十月向 Claude 引入“Agent 技能”时推广开来的概念。借用 Addy Osmani 的定义，技能“编码了资深工程师在构建软件时所使用的工作流、质量关卡和最佳实践。”

在 AIEWF 上，Vercel 的 Andrew Qu 表示，技能是“有用的可移植、按需知识。” Introspection 联合创始人 Roland Gavrilescu 宣称，AI 工程已经“从 Agent 工具转向了 Agent 技能”。

在主舞台的一场演讲中，Google DeepMind 的 Philipp Schmid 展示了如何通过使用技能（以及其他声明式 Markdown 文件），让开发者实现“无需代码的 Agent”。他的核心观点是，技能减少了对编排代码的需求，而在此之前，编排通常是用 Python 来完成的。他的结论是：

“Agent 只不过是文件。我们编写 Markdown 文件来扩展能力。Agent 可以从中学习，也可以创建自己的文件。”

Paul Bakaus 曾任职于 Google，现在经营一家名为 Renaissance Geek 的公司，他围绕 Agent 技能创建了一整个项目。Impeccable 是一个开源的设计技能系统，为编码 Agent 提供了一套用于改进界面的词汇体系。他甚至倡导将“技能工程”作为一门独立的学科。

Paul Bakaus：“设计无法一蹴而就。”

在接受 Latent Space 采访时，Bakaus 认为大多数技能——实际上大多数模型——都缺乏创造力。“它们朝一个方向收敛，如果每个人都用同一个技能去做前端设计之类的工作，最终所有东西看起来都会一模一样，”他说。

显然还存在一种“技能地狱”，Matt Pocock 表示这可以类比为以往开发者的烦恼——比如框架地狱。在一次线上演讲中，Pocock 提供了一份详细的技能编写清单，你可以在下面的视频中看到。简而言之，他建议编写更少、更小的技能，并在结构上投入更多思考。

在闭幕主题演讲中，Y Combinator 总裁 Garry Tan 呼吁听众在自己的初创公司或雇主公司中使用技能和其他“AI 原生”方法。谈到销售、支持和财务等业务职能时，Tan 表示：“我在 YC 内部看到的那些 AI 原生公司，把所有这些都编码为技能，即由他们的 Agent 执行的书面流程，并且他们聘请工程师来维护这些技能，去做技能目前还无法完成的工作。”

但同样，过度依赖 Agent 自主完成的工作也存在危险。正如 AIEWF 参会者 Tyler Brown 在 X 上指出的：“没有结构的自主性带来的混乱和杠杆一样多。”他从这次大会得到的收获之一是“重新审视并重新实现你的技能”：

“每次有新模型发布，就好像你的孩子从初中升到了高中。你必须为他们调整课程，才能获得新模型带来的好处。”

大规模的 Agent 工程

距离《AI 工程师的崛起》和首届 AI Engineer Summit 已经整整三年了。回顾过去，对话的演变程度着实令人惊叹。三年前，人们关注的焦点是证明 LLM 究竟能否作为自主 Agent 运行（当时的答案通常是否定的）。AutoGPT、提示词工程以及 Langchain 等早期编排框架主导了当时的讨论。

如今 Agent 不仅能够运行，而且已被证明可以规模化， 今年的 AI Engineer World's Fair 得以聚焦更重大的问题：构建可靠的系统、编排 Agent 团队、管理上下文、评估输出以及将 AI 集成到生产软件中。

Agent 现在无处不在……甚至出现在旧金山公交车的车尾上。

“AI 工程师”这个词最初可能只是一个新的职位头衔，但在 AIEWF 2026 上，它更像是软件工程本身发展方向的一种描述。无论开发者自称 AI 工程师、软件工程师还是前沿部署工程师，他们都在越来越多地使用同一套理念：编码 Agent、harness 工程、设计循环和编排。
