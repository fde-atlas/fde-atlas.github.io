基础Token 化与 Token语言模型读取的不是字符或单词，而是 token：由分词器产生的子词片段，每个 token 被映射为模型嵌入的一个整数。Token 是上下文窗口和计费的单位，文本如何切分成 token 也解释了大量看似奇怪的模型行为，这就是为什么几乎每个面试流程都从这里开始。

基础上下文窗口上下文窗口是语言模型一次能够关注的固定 token 数量，输入和输出共享同一预算。理解它，正是能够合理规划提示词大小、控制成本与延迟、并判断何时该使用 RAG 的工程师，与那些只是把所有内容一股脑粘贴进去然后祈祷的工程师之间的分水岭。

基础嵌入与向量表示嵌入将一段文本转换为一组数字，其位置使得含义相近的文本在空间中彼此靠近，从而让你可以按语义而非关键词进行搜索。嵌入是 RAG、语义搜索、聚类和去重背后的引擎，因此 FDE 面试流程期望你能解释余弦相似度，以及那些会悄悄破坏向量索引的陷阱。

基础Transformer 的直观理解Transformer 是所有现代大语言模型背后的架构，其核心是自注意力机制，让每个 token 可以并行地关注其他所有 token。FDE 面试流程不要求数学推导；他们希望你用高管或同事都能听懂的通俗语言，解释为什么注意力机制胜过 RNN、decoder-only 意味着什么，以及为什么长上下文的成本很高。

基础Temperature、Top-p 与采样在每一步，模型都会为每个可能的下一个 token 输出一个概率分布，而 temperature、top-p 和 top-k 等采样设置决定了如何将这个分布转化为实际选择。FDE 环节会考察这一点，因为它控制着确定性与创造性之间的调节旋钮：知道何时在信息提取时调低、在头脑风暴时调高，以及为什么同一个提示词给出不同答案是预期行为而非 bug。

Decagon 的前沿部署工程师环节会考察 llm 与 genai 基础问题，例如："你的语音 Agent 总是抢话并听错账号号码，但词错误率只有 6%。请诊断这两个问题，并说明应该改用什么指标来衡量。"、"为接听入站支持电话的语音 Agent 设计评测。哪些指标可以离线测量，哪些只有生产环境才能告诉你？"、"客户想用 Jev 替换他们的 LLM 工单分类器以降低成本。会有哪些变化，切换前需要验证什么？"。Token、上下文窗口、提示工程 vs RAG vs 微调、幻觉、评测、成本与延迟：这是每个 AI 原生 FDE 环节首先考察的概念核心。完整题集按由易到难排序并附专家答案，如下所示。
