前沿部署工程师面试题（25 题）

原标题：Forward Deployed Engineer Interview Questions (25)

摘要

AIXL Academy 整理了 25 道 FDE 面试题，按五大类分组：需求发现、数据访问与安全、评测、Agent 设计、生产交接。文章强调 FDE 面试考察的是处理混乱业务问题的思路，而非纯编码能力；好答案会先讲清负责人、数据、验证方式和退出计划，再谈框架。文中引用 Bloomberry 对 1,000 条 FDE 招聘信息的分析，约 60% 描述的是嵌入客户、写生产代码并负责结果的 builder 角色。文章不提供标准答案，并建议结合真实工作流口头练习。

核心要点

  • FDE 面试考察的更多是你如何处理一个混乱的业务问题，而不是纯粹的编码能力。
  • 这 25 个问题分为五个领域：需求发现、数据访问与安全、评测、Agent 设计，以及生产交接。
  • 强有力的回答会先明确负责人、数据、测试方案和退出计划，然后再谈框架。
  • Bloomberry 分析了 1,000 条 FDE 职位发布，发现其中约 60% 描述的是构建者角色。

前沿部署工程师（FDE）面试与普通软件面试不同。你仍然需要写代码，但大部分考察信号来自你如何处理一个混乱的业务问题：你先和谁沟通，你拒绝构建什么，你如何证明方案有效，以及你如何收尾离开。

Bloomberry 分析了 1,000 条 FDE 职位发布，发现其中约 60% 描述的是构建者角色：深入客户现场、编写生产代码并对结果负责。其余的大多是售前工程师类型的职位，外加一小部分内部工具类职位。本题库针对的是构建者角色。

我们按照问题考察的内容进行了分组。对于每个问题，我们都列出了优秀回答应涵盖的要点。这里没有可供背诵的标准答案。面试官想听的是你的思考方式，而背诵的答案很容易被识破。

1. 需求发现：你能找到真正的问题吗？

先试一试：开启练习模式隐藏答案，先思考每个问题，然后再查看答案。

业务团队提出需求：“一个用于发票查询的 AI Agent”。你在第一次会议上会问什么？

优秀回答应涵盖的要点

目前谁在处理这些查询以及处理量有多大，正确答案应该是什么样的，哪些系统保存着数据，Agent 被允许修改什么，以及由谁签字确认。优秀的候选人会要求与实际执行工作的人坐在一起观察。

你如何选择第一个要构建的工作流？

优秀回答应涵盖的要点

一个有真实业务量、数据确实可以获取、有明确负责人、并且有成功衡量方式的小范围工作流。糟糕的回答会选择最炫酷的工作流。

你什么时候会对一个用例说不？

优秀回答应涵盖的要点

没有负责人、无法测试正确性、数据无法访问，或者错误成本是业务无法接受的。好的回答还会提出替代方案。

利益相关者对流程的描述与你观察到的用户实际操作不一致。这时你怎么办？

优秀回答应涵盖的要点

相信观察到的实际流程，记录下例外情况，并在将规则编码之前与负责人确认。

你如何判断项目已经完成？

优秀回答应涵盖的要点

在项目开始时就写好的退出标准、一个生产环境的工作流，以及一个能在没有你的情况下独立运营的指定负责人。Andreessen Horowitz 认为前沿部署应被视为脚手架，而不是房子本身；面试官想听到你有退出计划。

2. 数据访问与安全：你能安全地获取真实数据吗？

请描述一下你会如何撰写一份数据访问申请。

优秀回答应涵盖的要点

用一句话说明工作流程、需要哪些字段、不需要哪些字段、是读还是写、服务账号的负责人、模型在哪里运行以及哪些数据保留在本地。

安全团队说不。你怎么办？

优秀回答应涵盖的要点

先询问具体的顾虑是什么，缩小范围（减少字段、只读、数据脱敏），然后带着更小的申请再来。而不是一上来就升级上报。

你如何处理提示词和日志中的个人数据？

优秀回答应涵盖的要点

尽量减少发送的内容，对标识符进行脱敏或删除，确定日志保留策略，并确认模型的托管位置。

一个 AI Agent 需要被允许做什么，哪些事情始终需要人工介入？

优秀回答应涵盖的要点

读取操作自由进行，可逆的写入操作要有日志记录，不可逆或对外的操作则必须经过审批环节。

在你的 Agent 上线一个月后，审计人员会要求提供什么？

优秀回答应涵盖的要点

一份记录每次操作的日志，包含输入、输出和审批人；随时间推移的评测结果；以及提示词和模型的变更历史。

3. 评测：你能证明它有效吗？

对于一个你从未见过的流程，你如何构建评测集？

优秀回答应涵盖的要点

收集真实的过往输入（包括杂乱的输入），与业务负责人一起编写预期输出，并就每个案例的评分方式达成一致。

什么时候用精确匹配、评分细则，或用 LLM 作为评判？

优秀回答应涵盖的要点

结构化输出用精确匹配，自由文本用评分细则，LLM 作为评判只有在通过与人工评分在样本上进行核对后才可使用。

修改提示词后，你的准确率数字上升了。你会发布吗？

优秀回答应涵盖的要点

检查哪些案例发生了变化，查找性能回退，确认评测集仍然能代表真实流量。

什么是基线，为什么它很重要？

优秀回答应涵盖的要点

第一天的得分就是你要捍卫的数字；没有它，“更好”只是一种主观意见。

上线三周后，用户开始抱怨，但你的评测仍然通过。为什么？

优秀回答应涵盖的要点

评测集被冻结而输入发生了变化、上游数据发生了变化，或者某个工具开始静默失败。解决办法是每周把用户抱怨转化为评测案例。

4. Agent 设计：你能构建出经得起考验的东西吗？

这个流程用单 Agent 还是多 Agent？

优秀回答应涵盖的要点

从一个 Agent 和清晰的工具开始；只有当单个 Agent 无法承载上下文，或者不同角色需要不同权限时，才增加更多 Agent。

你如何为 Agent 设计工具？

优秀回答应涵盖的要点

工具要少而精，输入输出有类型定义，错误信息清晰，并在工具内部进行权限检查。

循环如何结束？

优秀回答应涵盖的要点

完成条件、轮次上限、错误策略，以及轮次之间保留哪些状态。

你把人类放在流程中的哪个环节？

优秀回答应涵盖的要点

在难以撤销的操作、低置信度的情况下，以及任何新工具的首次运行时。

你如何估算这个 Agent 的运行成本？

优秀回答应涵盖的要点

按完成任务计算的成本，而不是按 token 计算：每次调用的 token 数、每个任务的调用次数（包括重试），以及需要人工修正的任务占比。

5. 生产与交接：你能离开吗？

交接包里应该放什么？

优秀回答应涵盖的要点

一份运行手册、评测集及其扩展方法、负责人、升级路径，以及已知的故障模式。

系统在运行但给出错误答案。运行手册怎么说？

优秀回答应涵盖的要点

如何识别错误输出、评测集存放在哪里、如何添加失败案例，以及该通知谁。

你如何监控生产环境中的 Agent？

优秀回答应涵盖的要点

任务成功率、人工干预率、延迟、每任务成本，以及输入类型的漂移。

讲一次你用真实数据上线交付的经历。什么阻碍了你？

优秀回答应涵盖的要点

一个具体的故事，包括阻碍是什么、你做了什么，以及你会如何以不同方式处理。这个问题最能体现真实经验。

你如何在五分钟内向业务负责人解释这个系统？

优秀回答应涵盖的要点

它做什么、不做什么、你如何知道它有效，以及出错时他们该怎么做。

如何练习

选五个问题，每个部分选一个。针对你熟悉的一个真实工作流，大声回答这些问题，然后请朋友提出质疑。目标不是给出完美答案，而是展示你在考虑框架之前，会先考虑负责人、数据、测试和退出机制。
