直观理解 Transformer

原标题：The Transformer, Intuitively

FDE Interviews · 2026-06-14 · 约 7 分钟读完

摘要

这篇文章用非技术语言解释 Transformer 架构，面向需要向客户讲解技术的前沿部署工程师。核心内容包括自注意力机制、模型结构、三种架构形态，以及长上下文成本高的根本原因。

要点

  • 自注意力让每个 token 并行查看所有其他 token，取代 RNN 的逐步处理。
  • 每个 token 生成 query、key、value 三个向量来决定关注谁。
  • 主流聊天模型多为 decoder-only，只能看到之前的 token，适合生成文本。
  • 注意力成本随序列长度平方增长，1000 token 约产生一百万个 query-key 对。
  • Transformer 训练比 RNN 快的关键在于整个序列可并行处理。

Transformer 是所有现代大语言模型背后的架构，其核心是自注意力机制，让每个词元可以并行地关注其他所有词元。FDE 循环不需要数学推导；他们希望你用高管或同事能听懂的通俗语言，解释为什么注意力机制胜过了 RNN、decoder-only 意味着什么，以及为什么上下文长度代价高昂。

文字记录

有人请你解释 transformer。不是用写满矩阵的白板，而是用非技术背景的买家能听懂的语言来解释，因为作为一名前沿部署工程师，你要解释的对象正是这类人。你需要讲清楚四个概念，没有一个涉及数学。

在 transformer 出现之前，像 RNN 这样的模型一次只处理一个词元，并把一个不断更新的摘要向前传递。这本质上是串行的，导致训练很慢，而且容易遗忘很久之前看到的内容。Transformer 抛弃了这种循环结构，让每个词元同时直接关注其他所有词元。

对于每个词元，注意力机制会问：我应该关注哪些其他词元，关注多少？以"the trophy didn't fit in the suitcase because it was too big"中的"it"为例。正是注意力机制让"it"从"trophy"而不是"suitcase"中获取含义。而且每个词元都会对其他所有词元做这件事，这就是全配对计算成本的来源。

一个词元是如何决定的？每个词元会生成三个小向量。一个查询（query）：大致表示"我在找什么"。一个键（key）：表示"我包含什么"。还有一个值（value）：如果被选中，它所提供的信息。

一个词元的查询会与其他所有词元的键进行打分。这些分数变成总和为 1 的权重，然后该词元按权重求和拉取各个值。"it"对"trophy"赋予很高的权重，因为它的查询与"trophy"生成的键相匹配。

现在来构建一个块。词元变成向量，再加上位置信号，因为注意力机制本身没有词序的概念。然后是一个块：自注意力从其他词元收集信息，一个小型前馈网络对收集到的信息进行重塑，每一步之后，块会把输入加回去并做归一化，这个残差连接为训练信号提供了一条直接回传的路径，因此你可以把这个块堆叠几十层，模型仍然能够学习。

各种架构的区别在于每个词元被允许看到什么。Encoder-only（BERT 系列）让每个词元看到整个序列，包括过去和未来：非常适合分类和嵌入。Decoder-only（GPT 系列）则屏蔽未来，正是这一约束使它擅长生成下一个词元。你聊过天的大多数模型都是 decoder-only。而 encoder-decoder，即 2017 年最初的 transformer，则适合翻译任务。

由于每个 token 都会关注所有其他 token，成本是平方级的。一千个 token 在每个注意力层会产生一百万个查询-键对。两千个则是四百万。提示词翻倍，注意力计算量大约翻四倍。而且每一层、每个注意力头都要再来一遍。这就是为什么长上下文很昂贵、为什么人们如此关注 KV 缓存，以及为什么更大的上下文窗口从来都不是免费的。

所以答案是：token 变成向量，注意力机制让每个 token 并行地查看所有其他 token，把这个过程堆叠很多次，而全对注意力就是长输入成本更高的原因。接下来的追问：为什么它比 RNN 训练得更快？并行性。注意力演示在 fdeinterviews.com 上。

TL;DR： Transformer 把 token 转换成向量，然后使用自注意力让每个 token 都能从其他所有 token 中提取信息，并将这一操作堆叠数十次来构建语义。它战胜了 RNN，因为注意力可以并行处理整个序列，而不是一步一步进行；而同样的全对注意力也是成本随序列长度平方增长的原因。

核心机制：注意力

在 Transformer 出现之前，像 RNN 这样的序列模型一次只读取一个 token，并向前传递一个不断更新的摘要。这本质上是顺序执行的，因此训练很慢，而且容易遗忘很久之前看到的内容。

Transformer 的思路是摒弃逐步循环，让每个 token 同时直接关注所有其他 token。对每个 token 来说，注意力会问“我应该关注哪些其他 token，关注多少？”并据此融合它们的信息。当模型处理“the trophy did not fit in the suitcase because it was too big”中的“it”时，正是注意力让“it”从“trophy”而非“suitcase”中提取含义。每个 token 都对其他所有 token 这样做，这就是全对成本的来源。

一个 token 如何决定关注谁？每个 token 会生成三个小向量：查询（query），大致表示“我在找什么”；键（key），大致表示“我包含什么”；值（value），即如果被选中它将传递的信息。一个 token 的查询与所有其他 token 的键之间的分数会变成权重，权重被缩放至总和为 1，然后该 token 拉取其他 token 值的加权和。“it”最终在“trophy”上获得高权重，因为它生成的查询与“trophy”生成的键相匹配——这就是上面那句话背后的全部机制。

一个块是如何构建的

Transformer 是由相同的块堆叠而成的。在第一个块之前，一次性地，每个 token 变成一个向量加上一个编码其位置的信号：即 token 和位置嵌入（注意力本身没有内在的顺序概念，所以必须加入位置信息）。然后每个块大致做以下事情：

  • 自注意力。 每个 token 从其他 token 那里收集加权混合的信息。
  • 前馈网络。 一个针对每个 token 的小型变换，让模型能够重塑注意力收集到的内容。
  • 残差连接与层归一化。 该模块将其输出加回输入（即残差）并进行归一化，这能保持梯度稳定，从而可以堆叠很多层而不让信号衰减。这种相加为训练信号提供了一条直达每个模块的路径，因此深层堆叠依然能够学习，而不是在底层逐渐消失。

将这个模块堆叠几十次，你就得到一个逐层构建语义的模型：从早期层的表面模式，到后期层的抽象关系。

三种形态：仅解码器、仅编码器、编码器-解码器

这些形态的区别在于每个 token 允许看到什么：

  • 仅编码器（BERT 系列）让每个 token 看到整个序列，包括过去和未来。这非常适合分类等理解任务以及生成嵌入，但它无法从左到右生成文本。
  • 仅解码器（GPT 系列以及大多数聊天模型）会遮蔽未来：每个 token 只能关注它之前的 token。正是这一约束使模型擅长逐个生成下一个 token。你交互使用的大多数 LLM 都是仅解码器的。
  • 编码器-解码器（Vaswani 等人 2017 年的原始 Transformer，即《Attention Is All You Need》，以及 T5）在输入上运行一个编码器，再由一个解码器同时关注自身输出和编码器的输出，这是翻译等序列到序列任务的天然选择。值得提及，以免把这种分类误认为是二元的。

用文字解释二次方成本

在稠密全注意力下，每个 token 都会对每个位置打分，因此序列长度翻倍大致会使注意力计算量翻四倍。一个 2,000 token 的提示词的成本并不是 1,000 token 的两倍；就注意力步骤而言，更接近四倍。计算很简单：1,000 个 token 在每个注意力头上会生成一个包含 1,000,000 个查询-键条目的稠密打分矩阵，2,000 个 token 则是 4,000,000 个，而且每一层、每个注意力头都要重复这一过程。解码器的因果掩码会隐藏未来位置，因此它只使用其中约一半的条目，但成本仍按平方增长。仅这一个事实就解释了为什么长上下文很昂贵，为什么人们如此执着于 KV cache 以避免在生成过程中重复计算注意力，以及为什么“直接用更大的上下文窗口”从来都不是免费的。

为什么面试官会考察这一点

他们在考察你能否在不借助写满矩阵的白板的情况下解释 transformer，因为作为 FDE，你需要向非技术买家解释它。好的回答是：“token 变成向量，注意力机制让每个 token 并行地关注所有其他 token，你把这一层堆叠很多次，而全对注意力正是长输入成本更高的原因。”他们憋着没问的追问是：“为什么这比 RNN 训练得更快？”答案：并行性。整个序列一次性通过，而不是一步一步处理。

常见误解

  • “Transformer 像 RNN 一样按顺序处理文本。” 它们是并行处理整个序列的；生成是顺序的，但架构本身不是。
  • “注意力机制自己就知道词序。” 并非如此。位置信息必须通过位置嵌入注入。
  • “层数越多理解力越强。” 深度在一定程度上有帮助，但能力来自规模、数据和训练的结合，而不是单靠层数。
  • “编码器和解码器可以互换。” 它们的区别在于每个 token 能看到什么；仅解码器架构会遮蔽未来，这正是实现生成的关键。

核心要点

  • Transformer 先对 token 进行嵌入，然后使用自注意力让每个 token 都能借鉴所有其他 token，并在多个块中堆叠，配合残差连接和归一化。
  • 它战胜 RNN 主要靠并行性：整个序列一次性处理，使训练效率大幅提升。
  • 大多数聊天 LLM 是仅解码器架构，即每个 token 只关注之前的 token，这正是实现从左到右生成的关键。
  • 全对注意力使成本随序列长度的平方增长，这是长上下文昂贵的根本原因。
