版本控制中的提示词：四行提示词提交

原标题：Prompts in Version Control: The Four-Line Prompt Commit

Falkster.AI · 2026-10-26 · 约 8 分钟读完

摘要

文章回应《Becoming Forward Deployed Engineer》第 08 课，主张提示词应纳入版本控制，且每次提交需附四行元数据：评测分数、评测数据集、修改者与回滚版本。作者认为课程只提了分数，并用自己的经历补充另外三项：其分类器在保留集上得分 89%，六周后生产环境降至 61%，原因是数据漂移；其规则库 51 次提交中至少 21 次由 Agent 参与，30 次无法归属。四行记录使 FDE 依据代码库契约可在客户现场当日免评审修改提示词。

要点

  • 提示词是无人检查的代码，评测分数应作为版本字段自动写入。
  • 课程案例：某保险公司提示词被删四行，两周后理赔员发现答案变差却无法追溯。
  • 作者分类器保留集 89%、生产 61%，说明必须记录评测所用数据集及日期。
  • 其规则库 51 次提交中 30 次无法归属，版本需记录修改者与阅读 diff 者。
  • 四行记录支撑 FDE 代码库契约：客户层可当日免评审修改。

《成为前沿部署工程师》第 08 课今早发布，带来了正确的原则，而在我能阅读的部分中，字段清单少了两个字段。这是一次 Agent Drop：四行内容，以及每一行的来源。

简短版本

  • 第 08 课以一家保险公司开场，提示词以三引号字符串的形式存放在 answerer.py 中；某个周四有人为了节省 token 把它缩短了，PR 显示删除了四行，看起来没什么问题，两周后理赔员说答案变差了，却没有任何东西能把这两件事联系起来。
  • 它的原则，在公开部分是：提示词就是没有任何东西在检查它的代码，因此评测分数是版本的一个字段，由运行评测的同一个函数写入。
  • 副标题给出了数字：四种措辞中有一种在四十二个问题里少答对了七个。分数是正确的第一个字段。还缺两个字段。行数（Rows）之所以重要，是因为我上线的一个分类器，用同一个提示词，在留出数据上得分 89%，六周内在生产环境中却只有 61%。
  • 名称（Name）之所以重要，是因为我自己的规则库自 3 月 30 日以来有 51 次提交，其中至少 21 次带有 AI Agent 共同作者标记，还有 30 次我无法归因。这个 Drop 就是在每次提示词变更下附带的四行：分数（Score）、行数（Rows）、名称（Name）、撤销（Undo）。
  • 在 FDE 代码库契约中，客户层可以在同一天变更且无需审查，条件是它有版本控制并且可对比差异；这四行就是差异所携带的内容。

那个周四的修改

这节课在预览之后是付费内容，所以以下只是预览所说的内容，仅此而已。

在 Meridian Mutual，提示词以三引号字符串的形式存放在一个 Python 文件里。某个周四，有人为了节省 token 把它缩短了。PR 显示删除了四行，看起来没什么问题。两周后，理赔员说答案变差了，却没有任何办法把这两个事实联系起来。作者给出的原因是：提示词就是没有任何东西在检查它的代码。没有编译器，没有类型检查器，没有会报错的签名。唯一能发现糟糕修改的，是你有意运行的一次测量，并且它关联着你运行时所针对的那段确切文本。

然后是设计，以它要避免的失败来表述。只对文本做版本控制而不带分数，历史记录只会告诉你改了什么，却永远不会告诉你是否有帮助。所以分数是版本的一个字段，由运行评测的同一个函数写入。

副标题就是那个数字：四种措辞中有一种在四十二个问题里少答对了七个，而代码审查中没有任何东西能告诉你究竟是哪一种。

这是正确的第一个字段，我也会把它放在第一位。而它缺失的两个字段，是我付出代价才学到的。

字段二：行数

阈值卡上有分类器。它在留出数据上得了 89%。上线生产六周后，只剩 61%。提示词没变。同一个分数字段会一直显示 89，因为变了的不是文本，而是数据行。生产流量偏离了计算分数时所用的数据集，而一个没有附带行集的分数，就像一个没有日期的数字。

所以版本要记录它是在哪些行上评分的。不是行本身，而是指针：哪个集合、多少行、什么日期。两周后调参人员来抱怨时，第一个问题是：给周四那次修改打分所用的那批行，是否仍然像调参人员现在问的问题。一半情况下提示词没问题，是行过时了——那是另一种修法。

第三个字段：名字

课程里的周四修改背后有一个具体的人。而在 Agent 维护的仓库里，大多数提示词修改背后没有。

谁在写你的 Agent 规则？我数了数提交记录。就是我数自己提交记录的地方。11 个文件，2,322 行，自 3 月 30 日以来 51 次提交。其中至少 21 次提交带有 Agent 共同作者署名。另外 30 次我完全无法归因于某个人或某个 Agent。库里有 23 行带着我的名字和日期；其余的是某个东西写的，也没有特定的人读过。

一次没有署名的提示词变更，就是没有周四的周四修改。所以版本要写明是谁改的，是人还是 Agent，并单独写明是谁读过 diff。这两个名字不一致的频率比你想象的要高，而第二个才是你该打电话找的人。

这四行内容

每次提示词变更下都写四行。如果提示词在 git 里，就写在提交信息中；如果你有注册表，就写在注册表行中；如果团队两种都看，就两处都写。纯文本，起步不需要任何工具。

分数：由运行过程自动写入的、针对这段确切文本的评测结果，不是手打的。行：它运行所在的行集，数量和日期。名字：谁改的，是人还是 Agent，以及谁读过 diff。撤销：回滚到哪个版本，以及谁能执行回滚。

第四行是没人反对、也没人写的那一行。停止规则讲了缺失撤销的代价：一个没有重跑机制的自主定价 Agent，五周内比基准下滑了 14%，花了两个季度才恢复。一次没人重新评分的提示词修改，就是同样的漂移，只是载体从循环变成了文本；而撤销这一行，能把周五早晨的决策从一场会议变成三十秒的事。

为什么这是一篇 FDE 文章

同一个模型，两倍的账单：FDE 代码库契约在代码库上划出了这条界线。客户层——提示词、规则、阈值、连接器配置，以及客户的评测行——归前沿部署工程师所有。当天修改，无需评审。两个条件：有版本控制，并且一条命令就能与已发布的默认值做 diff。

第 08 课是第一个条件的论证，其中的例子比我的更好。那四行是第二个条件必须承载的内容。一个显示“删除了四行”的 diff 是周四的那次修改；而一个显示删除了四行、并附有针对带日期行集的评测分数、修改者名称、阅读该 diff 的人以及可回滚到的版本的 diff，则是一次 FDE 可以在周二于客户现场完成的变更，无需工程团队的任何人审核。这就是约定，而只有当 diff 是诚实的，这个约定才成立。

这是一篇独立文章，与 The FDE Transition 并列。最接近的部分是代码库契约。

在 AI Product Management 中，论点是 AI 摧毁了 PM 受过训练的那部分工作的成本，而留下了没人受过训练的那部分。写提示词变得廉价了。判断新的提示词是否更好、在哪些行上、由谁修改、以及如何回退，才是没人受过训练的部分，而它就是四行。

本周行动：打开你的仓库或注册表中最近五次提示词变更。对每一次，尝试从已有记录中填出那四行。统计你能完成多少。然后把该区块加入提交模板，让接下来五次变更天然就是完整的。

常见问题

Becoming Forward Deployed Engineer 的第 08 课论证了什么？+

提示词应放入版本控制，而不是字符串。它的例子是一家保险公司，提示词以三引号字符串的形式存放在 answerer.py 中；某人在周四为了节省 token 把它缩短了，拉取请求显示删除了四行、看起来没问题，两周后理赔员说答案变差了，却无法把两者联系起来。其原则，在该文章的公开部分：提示词是没有任何东西检查它的代码，因此评测分数必须作为版本的一个字段，由运行评测的同一个函数写入。该文章在此之后为付费内容，本文不对超出该范围的内容做任何声明。

什么是提示词提交？+

每次提示词变更下的四行内容，写在提交信息或注册表行中。分数：这段确切文本的评测结果。行集：评分所用的行集，数量和日期。姓名：谁修改了它，是人还是 Agent，以及谁阅读了 diff。回退：可回滚到的版本，以及谁能执行回退。

为什么分数本身不够？+

因为分数只对它运行过的数据行有效。我上线的一个分类器，在留出数据上得分 89%，六周后在生产环境中用同样的提示词只剩 61%——数据行变了。一个没有数据行集合及其日期的分数字段，只能说明这个提示词曾在某处一度好用。

为什么版本需要作者字段？+

因为在由 Agent 维护的仓库里，大多数提示词修改并没有人类作者。我自己的规则库自 3 月 30 日以来有 51 次提交，其中至少 21 次带有 Agent 协作者标记，还有 30 次我无法归因于任何人类或 Agent。而课程里那次周四的修改背后有人。版本必须说明你的修改是否有人负责，以及谁审阅了 diff。

这如何契合 FDE 代码库契约？+

客户层（包括提示词）归前沿部署工程师所有，可以当天修改、无需评审，但有两个条件：它有版本管理，并且能用一条命令与已发布的默认版本做 diff。这四行内容正是 diff 所承载的信息，使这一契约得以成立。一个删掉了四行、没有分数、没有数据行、没有名称、也没有撤销方式的提示词 diff，就是那次周四的修改。

跳过重新运行要付出什么代价？+

停止规则里有这个数字：一个没有重新运行的自主定价 Agent，五周内比基准漂移了 14%，花了两个季度才恢复。每次变更后不重新评分的数据行，就是同样的漂移，只不过载体是提示词而不是循环。
