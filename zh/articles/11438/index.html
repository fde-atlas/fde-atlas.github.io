浏览器内部原理手册

浏览器如何把一棵标签树和一堆 CSS 变成以 60fps 滚动、带动画的画面。渲染管线——解析 → 样式 → 布局 → 绘制 → 合成——是有序且相互依赖的，因此一次视觉改动的代价取决于它波及多靠前的阶段。布局（重排）是最昂贵的阶段，因为盒子之间相互依赖（成本随节点数增长）；几何属性变化（宽度、top、新增节点）会触发它，仅影响绘制的改动（颜色）可跳过它，而 transform/opacity 则留在仅合成的快速路径上。此外还有布局抖动（读写交替会每次强制同步重排——应批量处理），以及巨型 DOM 树的虚拟化。附有演算示例和可运行的重排计算器。

TypeScript 手册

为什么 TypeScript 会让来自 Java/C# 的人感到意外：它的类型系统是结构化的，而非名义上的——它按对象的形状匹配，而不是按声明的名称。如果一个值具备某个类型所要求的全部属性且类型匹配，它就可以赋值给该类型（“走起来像鸭子……”），所以更宽的对象（多出额外属性）可以赋给更窄的目标，但缺少属性则绝不可以。对象字面量还有一条额外规则——多余属性检查——用于标记未声明的属性以捕捉拼写错误（这就是为什么提取到变量后类型错误会消失的原因）。此外还涵盖结构化与名义类型的权衡、品牌类型，以及各种陷阱（any 会禁用检查；类型会被擦除，因此要在边界处校验外部数据）。附有演算示例和可运行的赋值兼容性检查器。

React 手册

React 让你以声明式方式编写 UI——返回一个描述界面应该长什么样的描述——并通过协调机制使其保持高效：它构建一个轻量的虚拟 DOM，与上一次的树进行对比，然后只应用最少的真实 DOM 更改。对于列表，它通过 key 匹配条目：新旧两棵树中都存在的 key 意味着原地复用该元素（保留其 DOM 节点和状态），新出现的 key 会挂载，消失的 key 会卸载——因此使用稳定 key 的纯重排操作成本为零。那个著名的 bug：使用数组索引作为 key 在重排/插入时会出错，因为索引是位置而非身份，React 会复用错误的元素，导致状态泄漏到错误的行上。此外还涵盖不必要的重新渲染、memo/useMemo/useCallback，以及为什么虚拟 DOM 并不自动意味着快。附有演算示例和可运行的协调器。

薪资谈判手册

永远反报价的期望值论证。礼貌的反报价以概率 p 被接受，否则雇主只是维持原报价（对于合理的要求，他们几乎从不撤回录用），因此 EV = p·反报价 + (1−p)·原报价，只要 p>0 就优于直接接受——正面你赢，反面你不亏。你的 BATNA（最佳替代方案）是你真正的筹码，也是你的接受底线；在谈判前通过竞争性录用机会来提升它。而且基本薪资的提升会复利累积——其终身价值是一个几何级数，5 年内按 5% 折算，$10k 的加薪约等于 $55k，而不是 $50k。此外还包括具体怎么做（做调研、让对方先出价、书面反报价、谈判整个薪酬包和职级）以及各种陷阱。附有完整的数学演算和可运行的 EV 计算器。

代码评审文化手册

简历与作品集手册

你的简历有两个读者，而第一个不是人类。大多数申请会先经过 ATS（申请人跟踪系统），它根据职位对关键词覆盖率打分——覆盖率 = |简历 ∩ 必需项| / |必需项|——并自动过滤低于阈值的任何简历，因此合格的工程师可能因缺少关键词而被拒。第一步：用职位描述中的原话定制关键词（针对你具备的技能），并采用可被解析的整洁单栏格式，通过机器筛选。第二步：用量化影响力的要点赢得人类读者——带数字的要点（“将延迟降低 40%”）胜过模糊的职责描述（“参与后端开发”）。此外还包括工程师作品集需要什么（几个可运行、文档完善的项目，精选而非堆砌）以及各种陷阱。附有完整的数学演算（ATS 覆盖率 + 门槛、要点影响力）和可运行的简历评分器。

资深工程师行为手册

工程领域最难的晋升——从高级工程师到资深工程师——之所以让人栽跟头，是因为瞄准了错误的目标：写更多/更好的代码，而这一级别真正考察的是影响单位的转变。高级工程师以个人产出衡量；资深及以上则以杠杆衡量——你在他人身上创造的产出（一个解锁三个团队的架构、一个让所有人提速的标准、一个成长起来的被指导者）。总影响力 = 个人产出 + Σ 乘数，团队范围的提升价值等于团队人数 × 人均提升，而资深级别正是杠杆开始主导个人产出的门槛。涵盖 Larson 的四种原型（技术负责人 / 架构师 / 问题解决者 / 左右手）、粘合性工作及其为何得不到应有的认可、如何运作（做重要的事、坚持写作、无职权影响力、放大他人、保持技术可信度），以及各种陷阱（英雄式 IC、架构宇航员、隐形粘合剂）。附带一个可操作的杠杆模型和可运行的代码。

AI 辅助面试

审视那个 95% 的数字

仔细解读企业 AI 中被引用最多的统计数据：据报道，约 95% 的试点没有产生可衡量的损益影响。这句话的关键在两个词。“可衡量”指的是可归因的财务效果——不是准确率，也不是满意度；“试点”指的是有边界的试验，这本身就筛选出了那些在会计期间结束前就终止的项目。这一个数字背后隐藏着三种不同的失败：衡量失败（项目有效但不存在基线，因为没有人第一周就记录改造前的状况，事后无法补救）、归因失败（某项指标改善了，但同一季度还有其他三件事也发生了变化，财务不会把功劳记在你的项目上），以及实际失败（工作流程本身有问题，或者没有人采用它）。前两种失败正是前沿部署工程师这一角色存在的原因——它们都可以通过模型部署之前和之后的工作来解决。内容注明来源与置信度标签（通过媒体报道获得，而非公开的方法论），并附上与之呼应的 a16z 论点。

论文精读

用毛利换取护城河

为什么一家软件公司会刻意雇佣昂贵的工程师来做客户工作。服务驱动增长论点：把毛利率花在部署深度上，因为由此产生的集成很难被替代，而且成果是可证明的——毛利率的损失是为可防御性支付的获客成本，而非低效。决定这一论点是否成立的算术，用一个简单的纸面例子来说明：一名综合成本约 30 万美元的 FDE 每年做 3 次部署，每次部署成本约 10 万美元，占 15 万美元 ACV 的 67%，占 60 万美元 ACV 的 17%——而 REUSE 是唯一随时间改善的变量（0.6 倍，然后 0.4 倍）。这个论点内置的失败模式是付出了毛利率却没得到护城河，而护城河的流失是一次一个“合理例外”地发生的。诊断方法：第 N 次部署是否比第 N−1 次耗时明显更少？此外还有这种职业选择对你职业生涯意味着什么，以及应该问雇主的两个问题。

挑战

两数之和

经典热身题：找出两个相加等于目标值的数字。暴力解法是 O(n²)——用哈希表可以做到一次遍历，O(n)。用 Python 或 TypeScript 在浏览器中直接求解，配有隐藏测试和查看答案按钮。

挑战

有效的括号

经典的栈问题：判断每个括号是否都被正确类型、按正确顺序闭合。栈能把嵌套匹配变成一次遍历。用 Python 或 TypeScript 求解，配有隐藏测试。

挑战

Fizz Buzz

著名的筛选题。打印 1…n，但 3 的倍数变成 "Fizz"，5 的倍数变成 "Buzz"，两者兼是则变成 "FizzBuzz"。很简单——陷阱在于要按正确的顺序判断整除。用 Python 或 TypeScript 求解。

挑战

Softmax

每个分类器和语言模型末尾的函数：把原始分数（logits）转换为概率分布。实现数值稳定版本，避免大的 logits 溢出。用 Python 或 TypeScript 求解。

挑战

余弦相似度

每个嵌入搜索和 RAG 系统背后的度量：两个向量的对齐程度如何，而忽略其长度？点积除以模长的乘积——相同为 1，正交为 0，相反为 -1。用 Python 或 TypeScript 解决。

挑战

Top-K 检索

RAG 中 "R" 的核心：给定一个查询嵌入和一组文档嵌入，按余弦相似度返回最相似的 k 个文档的索引，并使用稳定的平局规则。用 Python 或 TypeScript 解决。

挑战

Token 级 F1

问答评测（SQuAD 等）背后的指标：预测答案作为词袋与参考答案的重合程度如何？计算 token 精确率和召回率，然后计算它们的调和平均 F1。用 Python 或 TypeScript 解决。

挑战

找出 AI 代码中的 Bug

一个助手写了一个聊天历史裁剪器，看起来没问题，能通过显而易见的用例，但一旦对话变长就会悄悄丢弃系统提示词。审查 AI 代码意味着要抓住的正是这种问题：自信、看似合理，却在关键用例上出错。找到 bug 并修复它。用 Python 或 TypeScript 解决，包含隐藏测试。

挑战

阅读代码库，修复 Bug

AI 无法替你伪造的技能：进入陌生的代码，追踪各部分之间如何相互调用，并修复出错的那一处而不破坏其余部分。一个分布在三个函数中的逆波兰计算器把减法和除法弄反了——阅读操作数的流转，然后从源头修复。用 Python 或 TypeScript 解决，包含隐藏测试。

挑战

重构遗留 ETL

你接手了一个没人能解释清楚的聚合逻辑，而且总计结果是错的。三个埋下的缺陷——规范要求的是包含列表却写成了排除列表、去重键缺少一个字段、以及本不应出现的预置客户。这是 FDE 重构环节。用 Python 或 TypeScript 解决，包含隐藏测试。

挑战

修复传播遍历

接手的代码计算某事物在联系人图谱中的传播范围，但答案在小规模输入下看不出问题的错误。一个单向邻接表、一个没有去重的边界集合，以及一个更新晚了一步的已见集合。用 Python 或 TypeScript 解决，包含隐藏测试。

挑战

LRU 缓存，逐个约束实现

增量编码环节的完整呈现：一个缓存先变成有界的，然后是最近最少使用的，再然后加入统计——每个阶段都会推翻上一阶段的实现方式。测试你的第一版代码能否吸收下一个需求。用 Python 或 TypeScript 解决，包含隐藏测试。

挑战

深拷贝，逐个约束实现

增量式题目，问题中第三阶段会真正打破显而易见的设计：复制一个对象，然后是嵌套结构，然后是包含循环引用的结构，最后是两个键必须仍共享同一个克隆的结构。用一个 visited 集合来防止崩溃，并在最后一个阶段失败。用 Python 或 TypeScript 解决，附带隐藏测试。

挑战

限流器，逐条约束推进

第三个增量式题目，第二阶段会直接推翻第一阶段：固定窗口计数器变成滑动窗口，然后按键区分，再加入突发流量配额。考验你能否冷静地说出“这个计数器必须扔掉”并进行重构。用 Python 或 TypeScript 解决，附带隐藏测试。

实验室 5

实验室

分解轮，模拟版

Don't read about the FDE decomposition round — sit it. Pick a case (taxi fleet, emergency response, fraud unification, marketplace) and get scored on the five clarifying questions you ask <em>before</em> the propose button unlocks, then on which sub-problems you attack and in what order, then on the two things you explicitly refuse to build. Premature solutioning scores negative, exactly like the real round. Ends with an interviewer verdict and a band. The signature Palantir-style round, interactive nowhere else.

实验室

客户角色扮演模拟器

真正决定部署成败的四场对话，以分支对话形式呈现：你的演示在他们的 CTO 面前崩溃，一位利益相关者坚持要错误的功能，安全团队拒绝放行数据，以及一位团队不断缩小的经理持续提出反对意见。你的每一次回复都会移动一个实时信任度量表，并改变他们接下来的说法。最后会根据 FDE 面试官筛选候选人的四个信号给出评分结论——这是每份指南都让你找朋友排练的那一轮。

实验室

学习轮，模拟版

Learn a library that does not exist. You get the internal docs for <code>flowpkg</code> — a package installer with dependency stages, a barrier between them, ordered post-install hooks and idempotent installs — in three unlocking sections with comprehension gates. Two rules are deliberately buried, and the last question can only be answered by combining rules from different sections. Tests reading strategy, not recall, exactly like the real round.

实验室

利益相关者博弈实验室

部署死于组织架构图，而非架构。客户处的六个人，每人用一句话描述——将他们归类为经济买方、拥护者、最终用户、阻碍者或数据守门人，并做好头衔至少两次误导你的准备。然后处理真正终结项目的三种情况：从不说不但也从不授予访问权限的守门人、其团队正被你自动化的团队负责人，以及在第五个月辞职的拥护者——同时一个联盟量表会追踪谁还站在你这边。

实验室

领域知识冲刺

The FDE meta-skill, drilled on three real verticals — insurance claims, hospital revenue cycle, or legal discovery. Learn the vocabulary that turns out to be codes (<code>status 7</code>, <code>CO-45</code>, TAR), reconstruct the workflow people actually follow rather than the one on the diagram, then pass expert gates including the one that asks which rule lives only in a practitioner's head. Scored on whether you could hold a conversation with them on Monday.

交互式工具 4

工具

交互式容量估算器

拖动 DAU、每用户请求数、载荷大小和读写比例，实时观察 QPS、每年存储量、带宽、分片数量和缓存内存的重新计算——每个数字都附带其背后的公式。面试官期望的餐巾纸数学，做成了交互式。

工具

AI 薪资探索器

对 2026 年 AI 和软件岗位总薪酬范围的快速、透明估算。选择角色、级别和公司层级，它会显示一个指示性区间，基于公开的基础薪资以及清晰标注的层级和级别乘数构建，而非黑箱。经过校准，使锚点与公开数据相符——大厂资深 AI 工程师约在 20 万美元出头，前沿实验室资深工程师接近七位数。这些是用于定位和谈判准备的自报市场范围，不是 offer 或建议——请务必在 Levels.fyi 等来源上实时核实。

工具

FDE 薪酬探索器

前沿部署工程师薪酬，逐项拆解。选择雇主层级（前沿实验室、Palantir、AI 基础设施、垂直领域初创公司、大厂、国防）、级别和市场，查看基本工资/股权/奖金的拆分，而非一个笼统数字——外加公开的薪酬区间、底层来源的置信度标签，以及改变任何 offer 实际含义的六个问题。一个透明的乘数模型，锚点和来源均已注明，而非抓取的表格。

工具

需求界定问题日志

针对每次需求探索电话真正考察的技能的演练。两个欠明确的客户需求，每个有十二个候选问题，预算为六个——花掉它们，看看客户真正说什么，每个问题都会根据“答案是否会改变你要构建的东西”来评分。最后会生成一份可复制的需求界定文档、覆盖六个维度的覆盖图，以及你发现或错过的真正问题所在。

关于面试准备

技术面试在压力下抽样考察几项技能：你能否讲清一个系统的权衡、干净地实现一个核心算法，并解释你如何知道你的方案有效？本主题将网站上所有相关内容指向这一循环——AI 和系统设计手册、语言问答、DSA 路线图以及可运行的编程挑战。

最可靠的准备不是临时突击，而是真正理解少数几个反复出现的模式，然后反复练习直到熟练。大声讲解一个设计方案，亲手实现一个指标或算法，这样你走进面试房间时，靠的是真才实学，而不是死记硬背的答案。
