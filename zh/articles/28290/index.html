前沿部署工程，从基础讲起

原标题：Forward deployed engineering, from the basics

Abhinav Bhatia · 2026-10-20 · 约 8 分钟读完

摘要

作者 Abhinav Bhatia 推出免费的十部分系列，讲解前沿部署工程师（FDE）的工作内容与实操方法。系列以 Google Cloud、Microsoft、OpenAI、Anthropic 等公司的公开招聘描述为依据，并用虚构公司 Acme Consumer Brands 的案例贯穿始终，与另一套 Production-ready agents 系列配套阅读。

要点

  • FDE 指驻扎在客户组织内、让产品在客户真实系统上落地并反馈经验的软件工程师。
  • 系列分四个阶段：理解角色与问题、在客户环境中设计与构建、交付与支持、证明成果。
  • 每部分引用公开 FDE 招聘描述的原文，解释其实际含义及做好该工作的方法。
  • 虚构案例 Acme 的营销数据在 BigQuery，供应数据在 Databricks，读者扮演 FDE 用 Gemini Enterprise 解决问题。
  • 本系列讲项目全流程，代码细节则链接到配套的 agents 系列，避免重复。

一个免费的十部分系列，介绍前沿部署工程师做什么以及如何做好这份工作，内容基于公开的 FDE 职位描述的要求。一个虚构的客户项目贯穿每一部分，与“生产就绪的 Agent”系列并行。

让一个 AI Agent 在演示中回答一个问题，现在只需要一个下午。而让同一个 Agent 在一家真实公司里运行——使用它的数据、接入它的身份提供商和网络规则，并且它的工程师之后能够自行运行——则需要长得多的时间。负责弥合这一差距的人，如今越来越多地被称为前沿部署工程师（FDE）。

这个头衔现在出现在 Google Cloud、Microsoft、OpenAI 和 Anthropic 的公开招聘信息中。在与合作伙伴的工作中，我发现人们对“前沿部署”这个词的理解，远不如他们对 Agent 代码的理解。本系列从基础讲起，解释这份工作：FDE 做什么，以及如何做好工作的每个环节。

这个系列适合谁？

  • 构建 AI 系统的工程师，想知道当系统必须在客户的环境中而不是自己的项目里运行时，会有什么变化。
  • 架构师、客户工程师和顾问，他们的工作与前沿部署工作有重叠，希望对整个客户项目有一个清晰的全貌认识。
  • 合作伙伴和技术负责人，他们负责为这些项目配置人员、界定范围或主持项目，需要一套共同的术语。

这是一个关于工作本身的系列。它解释这份工作包含什么以及如何做好，而不是一份求职指南。

什么是前沿部署工程师？

简短版本：前沿部署工程师是一种软件工程师，他们在一家客户的组织内部工作，编写并交付让产品在该客户真实系统上运行的代码，并把学到的经验带回构建产品的团队。Google Cloud 的一份公开招聘信息将该角色描述为“一名嵌入式构建者，弥合前沿 AI 产品与客户内部生产级现实之间的差距”。

第 1 部分会详细解读这个定义，包括这个术语的来源，以及该角色与解决方案架构师、客户工程师、顾问或产品软件工程师的区别。

一个客户项目是什么样的？

本系列的大部分内容会跟随一个客户项目（一项有约定目标、有开始和结束的工作）的完整过程。这些阶段与公开职位描述中所描述的相同，每个阶段都有独立的一部分。

从头到尾的一次完整项目合作，以及本系列中涵盖每个阶段的部分；构建和加固阶段在“生产就绪 Agent”系列中有更深入的讲解

每一部分都以一个名为 “这在 FDE 的职位描述中如何体现？” 的章节开头。它引用或近乎逐字地摘录两到四行来自公开招聘信息的文字，然后解释这些内容在实际工作中意味着什么，以及如何把这项工作做好。我引用的每一条招聘信息都在该部分的“来源”中附有链接。

贯穿全文的示例是什么？

同一家虚构公司贯穿本系列和生产就绪 Agent系列。Acme Consumer Brands 开展了一次广告营销活动。市场部说它是成功的，供应部说它是失败的，而且双方都是对的。广告数据存放在 BigQuery（Google Cloud 的数据仓库）中，而交付数据存放在 Databricks（一个独立的数据平台）中，没有人把两者放在一起对比过。

Acme 故事的两半：campaign_performance（每个广告活动、地区和周一行，由市场部拥有，通过 BigQuery 读取）和 supply_service（每个品牌、地区和周一行，由供应部拥有，存放在 Databricks 中），图中显示的是西欧地区的 Acme Pure

Agent 背后的业务术语和数据解释了每一列的含义以及两张表如何关联。

在本系列中，你是驻扎在 Acme 的 FDE。你的任务是通过 AI Agent 解答市场部和供应部的问题，这些 Agent 要能让 Acme 自己的员工在 Gemini Enterprise（Google 面向企业的 AI 助手平台）中使用，并且在你离开后，Acme 自己的工程师也能继续运行它们。Acme 及其数据都是虚构的；但产品、协议和实践都是真实的。

本系列如何与 Agent 系列搭配？

这两个系列设计为配套阅读。Agent 系列是构建过程：三个 Agent，逐步编写和加固，并附有代码。本系列是围绕构建的项目合作：需求探索、在他人系统内进行设计、数据与集成、调试、性能，以及向高管证明成果。

本系列与生产就绪 Agent 系列的搭配方式：左侧的每个项目合作主题都链接到右侧深入讲解的构建部分

如果某个主题已经在 Agent 系列中构建完成，我会直接链接过去，而不是重复讲解。例如，本系列第 7 部分讲解如何将原型推向生产环境，并链接到 Agent 系列中关于身份认证、防护栏、评测以及部署与成本的文章以获取代码。

这十个部分是什么？

本系列的十个部分分为四个阶段：理解角色和问题、在客户的系统内设计和构建、交付和支持、证明成果

阶段 1：理解

第一部分：前沿部署工程师到底做什么。 这个术语的由来、公开职位描述中的要求、该角色与四个常见角色的对比、一次客户合作从入驻到交接的完整流程，以及所需的多项技能组合。

第二部分：需求探索：从业务问题到可构建的方案。 问题陈述、业务与技术成功指标、可行性评估、首个用例的选择、需要询问的数据与访问权限问题、何时应该说不，以及一页纸的合作简报。

阶段二：设计与构建

第三部分：在别人的技术环境中做设计。 前期技术设计：数据存放在哪里、归谁所有、身份提供商、网络路径与私有连接、合规边界与安全审查，并附第一周的问题清单和设计评审检查清单。

第四部分：数据准备与从零构建 RAG。 文档如何变成答案：解析、分块、嵌入、向量与混合搜索、重排序、依据与引用、Google Cloud 上的托管方案、如何评估检索效果，以及答案出错的原因。

第五部分：企业集成、API、连接器与身份。 REST API 与身份验证、内容管理连接器、Gemini Enterprise 连接器与数据存储、身份标准（SAML、OIDC 和 SCIM），以及作为集成层的 MCP 服务器，并以 Gemini Enterprise 与 Databricks Genie 的构建作为完整示例。

第六部分：Agent 框架对比。 ADK、LangGraph、CrewAI 与微软的 AutoGen（截至 2026 年 10 月，AutoGen 已归档，由 Microsoft Agent Framework 取代）逐一对比；常见模式（ReAct、反思、监督者与图）；用两个框架完成同一个小任务；如何选择框架；以及 A2A 和 MCP 如何让用不同框架构建的 Agent 协同工作。

阶段三：交付与支持

第七部分：几天做出原型，几周上线生产。 有意构建一次性原型、AI 辅助编码、加固检查清单，以及通过运维手册、明确负责人和培训向客户团队交接。

第八部分：现场调试。 阅读陌生代码、复现故障、日志与追踪、区分客户环境问题与产品缺陷、临时解决方案，以及一份产品与工程团队可以直接行动的缺陷报告模板。

第九部分：LLM 原生性能：延迟、Token 与成本。 首 Token 响应时间、每秒 Token 数、上下文大小及其成本、缓存、流式输出、模型规模选择、批处理与单次请求成本，以及为什么优化之前要先测量。

阶段四：验证成效

第十部分：与高管沟通并证明成果。 将技术障碍转化为业务影响、成果指标与基线、项目进展汇报、范围与期望管理、结项评审，并对整个系列进行回顾。

我们学到了什么？

  • 前沿部署工程师在一家客户的组织内部工作，交付让产品在该客户的真实系统上运行起来的代码，并把学到的经验带回产品团队。
  • 本系列的大部分内容围绕一次客户合作展开：从入驻与需求探索，到设计、构建与加固，再到交接与验证成果。
  • 每一部分都从公开的 FDE 职位描述的要求出发，然后讲解如何把这项工作做好。
  • 一家虚构公司 Acme Consumer Brands 贯穿本系列和生产就绪的 Agent 系列，其营销数据存放在 BigQuery 中，供应数据存放在 Databricks 中。
  • Agent 系列是构建本身，本系列是围绕构建的客户合作，因此两者相互链接而不重复内容。

第 1 部分从最基础讲起。第 1 部分：前沿部署工程师到底做什么 解释了这个术语的由来、公开职位描述的要求、该角色与你已熟悉的技术角色有何不同，以及一次客户合作如何从入驻走到交接。
