你可以在 FDE 带回家作业中使用 ChatGPT 吗？规则说明

原标题：Can you use ChatGPT on an FDE take-home? The rules

FDE Interview Prep · 2026-09-25 · 约 15 分钟读完

摘要

这篇文章梳理了各公司对求职者在家测试（take-home）中使用 AI 的公开规定，并给出实用建议。核心结论是：以测试说明为准，其次看公司候选人 AI 政策页，两者都未提及时应书面询问招聘人员。各公司规定差异很大，甚至相互矛盾。文章还提供了可套用的 AI 使用披露模板和口头回答思路。

要点

  • Snowflake、IBM、Accenture、Deloitte 等公司默认禁止在测评中使用 AI。
  • Anthropic 要求默认不用 Claude 完成 take-home，除非另有说明。
  • Palantir 的 Build to Apply、Coframe、Namastex 等鼓励使用 AI 并要求披露细节。
  • 规定不明时应提前书面询问招聘人员，并保留记录。
  • 文章提供 AI 使用披露模板，强调记录工具出错之处以证明自己核查过。

因此，按照我们的理解，权威顺序是：

  • 任务说明本身。 如果带回家作业说明了你可以使用什么，那就是该作业的规则。
  • 公司的候选人 AI 使用页面。 如果任务说明没有说明，这就是默认规则。
  • 招聘人员的书面答复。 如果两者都没有说明，这是你获得一条可以援引的规则的方式。

当任务说明没有提及：书面询问

当任务说明和公司页面都没有提到 AI 时，不要猜测，也不要从论坛帖子中推断规则。直接询问。OpenAI 的指南说明它解释了准备材料中允许的内容，并建议不确定的候选人应在面试前询问招聘人员。Source 8面试指南发布方OpenAI来源类型公司招聘页面Source 9OpenAI 面试指南（Wayback Machine 存档）发布方OpenAI（由 Internet Archive 存档）来源类型存档的公司页面 在我们看来，这在任何公司都是好建议。

我们的经验法则包括三个部分：

  • 在开始之前询问，而不是截止前一晚才问。答案可能会改变你对工作的规划。
  • 以书面形式询问，通过电子邮件或申请门户，这样答案就有据可查。
  • 明确点名询问灰色地带。“AI”这个词很模糊。编辑器中的内联补全、让聊天机器人解释错误、让它校对你的 README，都属于使用 AI。

以下是一条你可以改编的消息：

“感谢发来这份带回家的测试题。在开始之前，能否确认一下本次测评对 AI 工具的政策？具体来说：我可以使用 AI 编程助手（包括编辑器中的内联补全）吗？我可以使用聊天助手来查询资料或校对文档吗？如果允许使用 AI，你们希望以什么格式说明我的使用方式？”

如果答案是“不允许使用 AI”，请在整个任务期间关闭内联补全。如果在需要开始时仍未得到答复，就按不允许使用的方式来做，并在 README 中说明：“我未收到关于 AI 工具的答复，因此在没有使用它们的情况下完成了此任务。”

一条可改编的披露说明

当允许使用 AI 时，请予以披露。GitLab 的页面要求候选人披露他们使用了哪些 AI 工具，而 Coframe 的任务说明则要求列出每一个工具及其如何影响了结果。Source 10在面试流程中使用 AI发布方GitLab来源类型公司招聘页面Source 11Coframe Forward Deploy — Take-Home发布方Coframe（GitHub）来源类型公司网站 即使在没人要求的情况下，我们也建议写一份：只需十分钟，就能在别人提问之前先回答这个问题。

这个模板是我们的。把它放在 README 的末尾，单独设一个标题：

## How I used AI tools

Tools: [assistant name],
[editor completion]

Used for:
- Boilerplate: project setup, the CLI
  wrapper, test scaffolding
- Lookup: library API signatures
- Proofreading this README

My own work:
- The scope and the assumptions above
- The retry and error-handling design
- The eval set and the failure analysis

Checked: I read and ran every generated
line. Two suggestions were wrong: [what,
and how I caught each one].

Logs: [link or folder], if you want them.

一个填写好的示例

以下是一个示例版本，针对类似 Coframe 的任务说明，该说明要求实现一个将电子表格同步到 API 的集成。细节是虚构的，用以展示我们期望达到的具体程度。

## How I used AI tools

Tools: a chat assistant,
editor inline completion

Used for:
- Project setup and test scaffolding
- The request client's boilerplate
- Proofreading this README

My own work:
- Scope: one-way sync only (see
  "Not built")
- Which failures to retry, and how
- The test fixtures and edge cases

Checked: I read and ran every generated
line. Two suggestions were wrong:
- It retried every failed request,
  including 400s. I limited retries to
  429 and 5xx with backoff: a 400 fails
  the same way every time.
- It read the sheet's header row as
  data. A two-row test fixture caught it.

三个细节让它发挥作用：

  • 明确区分工具的工作和你的工作。“全程使用了 AI”对审阅者毫无帮助。“重试设计是我做的；测试脚手架是生成的”则告诉他们应该在哪里寻找你的判断力。
  • 记录工具出错的地方。在我们看来，这是证明你检查过输出而非直接粘贴的最有力证据。
  • 提供日志，或在被要求时附上。 Namastex 的任务简报要求随代码一起评估 AI 对话记录。来源 12Desafio Técnico — FDE / AI Engineer (Namastex)发布方Namastex (GitHub)来源类型公司网站 一份由候选人于 2026 年 8 月发布的 Tavily FDE 简报要求提供工作过程的记录，例如编码 Agent 的聊天历史或会话日志。来源 18Tavily - FDE - Take Home Assignment发布方azamkhan99 (GitHub)来源类型候选人的带回家作业仓库 如果可能需要分享日志，就要以“有人会阅读它们”的心态来工作。

当他们问“你在这个项目里是怎么使用 AI 的？”时，该怎么回答

如果允许使用 AI，请在后续电话中准备好这个问题。以下是我们基于上面示例会给出的口头回答。措辞是我们的，请替换成你自己的细节：

“我用聊天助手和编辑器补全来搭建环境、生成测试脚手架以及请求客户端的样板代码。范围、重试规则和测试用例都是我自己定的。我阅读并运行了它生成的所有内容，其中有两次是错的。关键的一次是：它对 bad-request 错误也进行重试，而这类错误永远不会成功，所以我把重试限制在限流和服务器错误上，并加入了退避机制。如果再多一天，我会加一个 dry-run 模式，让客户在写入任何内容之前先预览同步效果。”

四个步骤，按顺序：工具做了什么、你做了什么、一个具体的发现，以及你接下来会做什么。用你会对带回家作业做哪些改动？（免费，附有参考答案）以及你如何使用 AI 编码工具，以及你在哪些方面不信任它们（Pro 版）来练习。

使用 AI，同时让评审者仍然看到你的判断力

我们的方法：让工具打字，把决策留给自己，并让它们清晰可见。

把这些留给自己。 范围以及你排除了什么。在简报未说明之处你做出的假设。测试用例，尤其是客户会遇到的边界情况。权衡取舍以及你接下来会改进什么。这些是你需要在现场答辩的部分。

我们会避免的错误，以及各自的解决办法：

  • 你解释不了的代码。 一份候选人发布的简报明确指出，即使代码是 ChatGPT 写的，你也必须能够解释它。来源 19Hippocratic AI Coding Assignment发布方akshay-menta (GitHub)来源类型候选人的带回家作业仓库 解决办法是在每一行生成的代码进入项目之前，先阅读并运行它。如果你说不出它为什么在那里，就删掉或重写它。
  • 听起来像宣传册的 README。 在我们看来，没有具体细节的通用华丽文字是最先暴露“这是生成的”的迹象。解决办法是自己撰写假设和权衡取舍，用平实的句子写出真实的细节。
  • 代码量远超时间限制所允许的范围。 一位候选人发布的 Tavily 题目说明写得很直白：“我们宁愿看到一件小事做得好，也不愿看到一件大事做得潦草。” 来源 18Tavily - FDE - Take Home Assignment发布者azamkhan99 (GitHub)来源类型候选人的 take-home 仓库。正确的做法是把一件小事做好，并清晰列出你选择不构建的内容。
  • 一个未披露的工具却出现在演示讲解中。 正确做法是在提交之前写好上面的披露说明。

在开始任何 take-home 之前

  • 阅读题目说明中关于 AI 工具的表述
  • 在开始当天阅读公司的候选人 AI 政策页面
  • 如果两者都没有提及，给招聘人员发邮件并保留回复
  • 如果答案是不允许，在整个任务期间关闭编辑器自动补全
  • 如果答案是允许，边做边记录，以备披露说明之用
  • 提交之前，确保你能解释每一行代码
