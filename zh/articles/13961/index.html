FDE 招聘启事怎么写：前线部署工程师 JD 模板

FDE Times · 2026-11-04 · 约 6 分钟读完

摘要

文章以 Palantir、OpenAI 和 Anthropic 的真实 FDE 招聘启事为范本，提出一套六段式写作框架：使命、团队目标、职责范围、具体工作、任职要求和后勤安排。核心主张是用具体交付物（如 MCP 服务器、子 Agent）和客户方角色替代空泛描述，用数字写明出差比例和薪资区间。对团队负责人，这是招聘工具；对求职者，可倒推简历应证明的能力。

要点

  • 六段式框架：使命、团队目标、职责范围、具体工作、任职要求、后勤安排。
  • 职责每行应含动词、交付物和客户方人员，避免“支持集成”式空话。
  • 硬性要求与加分项分开写，Palantir 经验门槛仅毕业后一年。
  • 后勤用数字：出差最多 25%，薪资区间如 135,000–200,000 美元。
  • 求职者应倒读招聘启事，让简历逐条对应具体职责。

一行写明交付 MCP 服务器、子智能体和技能，撑起一套六段式模板，帮负责人招对人，也告诉求职者简历要证明什么。

要点速览

  • Palantir 以公司使命开篇，OpenAI 用一句话说明 FDE 团队的目标。两种写法都能让候选人明白团队为什么存在。
  • 好的招聘启事会列出具体交付物，例如 MCP 服务器和子 Agent，并写明工程师要和客户方的哪些人合作。
  • 后勤部分要给出数字：最多 25% 的出差时间、各业务线特有的安全要求，以及类似 135,000–200,000 美元的薪资区间。

Anthropic 的前线部署工程师（FDE）招聘启事里有一行字，写清了新人要交给客户的东西：MCP 服务器、子 Agent 和 Agent 技能。启事没有停在“支持集成”这类含糊的说法上。读到这一行，候选人马上就能想象出这份工作的一周是什么样子。

写出这么具体的一行字并不难，但需要一个框架，告诉你每一部分要回答什么问题。本指南搭建一个六部分的框架，每一部分都参照 Palantir、OpenAI 或 Anthropic 真实招聘启事中的一段。

有两个时刻会用到它。如果你是即将成为团队负责人的 FDE，迟早要为自己的团队写招聘启事。如果你想转做 FDE，弄懂招聘启事的结构，就知道简历需要证明什么。

你要做出什么，需要准备什么？

最终产出是一份约一页的招聘启事，分六部分：使命、团队目标、职责范围、具体工作、任职要求和后勤安排。贯穿全文的例子是：假设你在一家虚构的创业公司工作，公司向银行销售发票处理 Agent。

只需要一个终端和一个文本编辑器。Palantir 的招聘启事发布在 Lever 上，可以通过 posting API 获取。OpenAI 和 Anthropic 的招聘启事用浏览器打开即可，分别在 Built In、Greenhouse 和 General Catalyst 的招聘页面上。

第 1 步：动笔之前先读原文

下载 Palantir 的招聘启事，看它如何划分各部分：

curl -s "https://api.lever.co/v0/postings/palantir/dab396d4-2f14-4796-aac0-0d82883dccf0" \
  | python3 -m json.tool > palantir_fdse.json

检查：打开文件，找出各部分标题。介绍公司使命的段落出现在任何岗位细节之前。之后依次是“Core Responsibilities”“What We Require”“What We Value”，以及单独的薪资部分。另外两份招聘启事，记下各部分名称就够了。

第 2 步：从团队为什么存在写起

Palantir 开篇用一段话介绍自家软件在做什么：药物研发、供应链、寻找失踪儿童。OpenAI 更简短，在“About the team”部分只用了一句话：FDE 团队与客户合作，把研究突破变成生产环境中的系统。

## 关于公司
[一段话：产品解决什么问题、为谁解决，附 2-3 个真实例子]

## 关于团队
FDE 团队与[客户类型]合作，把[产品能力]
变成[在生产环境中运行的成果]。

对这家虚构的创业公司，团队那句话可以写成：“FDE 团队与银行合作，把发票识别 Agent 从演示带进银行真实的对账流程。”检查：这句话必须点明客户、产品和最终成果。三者缺一，就重写。

第 3 步：开门见山说清职责范围

Palantir 在职责部分的第一句就写明了自主权：你将在小团队中工作，端到端负责高风险项目的执行。候选人在读具体任务之前就知道自己的范围。这个顺序值得照搬。

Anthropic 在岗位概述中说，希望 FDE 能够自主工作，并在模糊环境中如鱼得水。Anthropic 的 Technical Deployment Lead 招聘启事更进一步，划定了范围：从 SOW 一直到生产环境部署。

## 岗位职责
你将在[规模]人的团队中工作，负责从[起点]
到[终点]的全部工作。遇到[模糊情形的类型]时，你需要自己做判断。

检查：读者必须能回答“我的工作什么时候算完成？”。对这家虚构的创业公司来说，只有 Agent 在银行真实的对账数据上运行起来，工作才算完成，而不是演示通过就完事。

第 4 步：把职责写成交付物和人

这一部分最容易流于空泛。Palantir 把技术工作和与客户方利益相关者的直接合作穿插在一起，对象从工程团队一直到管理层。

OpenAI 列表的第一行是：与战略客户紧密合作，了解其业务问题和技术需求的细节。Anthropic 则逐一点出每类交付物。

含糊的写法

  • 支持客户完成集成
  • 与利益相关者良好沟通
  • 构建 AI 解决方案

改写后的写法

  • 编写 MCP 服务器，把 Agent 接入银行的发票系统
  • 每两周向运营负责人汇报对账结果
  • 构建子 Agent，在问题发票送到人工审核之前先做分拣

最容易上手的技巧是：每一行都要有一个动词、一个交付物和一个客户方的人。检查：把公司名划掉。如果这一行放在任何工程岗位上都说得通，就还不够具体。

第 5 步：分开硬性要求和加分项

Palantir 把两者拆成“What We Require”和“What We Value”两个独立部分。它的工作年限门槛很低：毕业后一年及以上的相关工作经验。

OpenAI 把硬性的经验门槛和一项行为特质放在一起：偏好亲自上手，愿意与客户一起迭代打磨。Anthropic 的“You May Be a Good Fit If You Have”部分写了年限门槛，同时明确表示鼓励曾经的技术创始人申请。

## 必备要求
- [经验门槛，用数字写明]
- [与客户合作时可观察到的行为]

## 加分项
- [领域、工具]
- [希望吸引的非传统背景]

检查：对必备要求中的每一行，问一问它是否会把某类优秀候选人不公平地筛掉。如果会，就把这一行挪到加分项。

第 6 步：后勤安排用数字写

Palantir 在任职要求部分写明了出差比例：最多 25% 的时间在客户现场，可视个人情况灵活调整。Anthropic 则以区间的形式写明出差。

薪资也用数字给出。Palantir 单独的薪资部分估算为每年 135,000 至 200,000 美元。OpenAI 旧金山岗位的招聘启事写明 185,000 至 325,000 美元，Anthropic 的 Technical Deployment Lead 招聘启事也给出了薪资区间。

Palantir 面向美国政府业务线的版本，展示了同一框架如何因领域而变化。它增加了一项硬性要求：持有 Top Secret 及以上级别的有效安全许可，并要求现场办公。

## 后勤安排
- 出差：最多 [X]% 时间在客户现场，[灵活程度]
- 领域特定要求：[安全许可、现场办公、语言]
- 薪资：[下限] – [上限] / 年

检查：这一部分的每一行都必须包含一个数字或一个是/否条件。有了这些信息，候选人在申请前就能自己判断是否合适。

常见错误

第一个错误是让行为标准沦为“有活力”“积极主动”之类的形容词。OpenAI 把它写成可验证的行为：与客户一起迭代打磨。面试时，就可以针对这一行为提问。

第二个错误是一份招聘启事通用于所有领域。更好的做法是保留核心内容，再为每个领域加上特有的硬性要求，就像 Palantir 为政府版本加上安全许可那样。

第三个错误是隐瞒出差情况。FDE 如果入职后才发现在客户现场的时间比预期多，大概率不会待太久。

这项技能在实际工作中用在哪里？

写招聘启事锻炼的正是客户启动会上用到的能力：把含糊的需求变成范围、交付物和验收标准。能在招聘启事里写出“从 SOW 到生产环境”的团队负责人，也能在项目方案里写出同样的一行。

如果你是求职者，就倒着读招聘启事。每一项具体职责都应该能在你的简历里找到对应的一行，带有交付物和你合作过的客户方人员。

例如：“构建 MCP 服务器连接内部系统，向运营负责人做了演示”。如果你做过创始人，把这一点放在简历最上方，因为至少有一家公司明确表示在找这样的人。

描述新人第一周工作的招聘启事，能吸引合适的人。同样写法的简历，能让招聘人员停下来细读。
