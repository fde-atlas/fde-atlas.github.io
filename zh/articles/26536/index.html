吴恩达 Agentic AI 课程怎么学：FDE 重点看评测

FDE Times · 2026-10-08 · 约 4 分钟读完

摘要

文章评析吴恩达在 DeepLearning.AI 上的 Agentic AI 课程，认为对想做 FDE 的人而言，模块 4 的评测与错误分析内容比四种设计模式更有价值。课程共 5 个模块，Coursera 估计需 2 周、每周 10 小时，要求中级 Python 和基本 LLM API 经验。所有模式均用 Python 从零实现、不依赖框架，便于在客户现场调试任意技术栈。文章以银行客服 Agent 的假设错误分析表说明：应先归因错误再决定修复优先级，并建议把客服实验做成带错误分析表的 GitHub 项目写入简历。

要点

  • 课程由吴恩达讲授，中级难度，5 个模块，约需 2 周。
  • 四种模式为反思、工具调用、规划与多智能体，全部用 Python 从零实现。
  • 模块 4 的评测、错误分析、延迟与成本测量最贴近 FDE 日常工作。
  • GPT-3.5 加 Agent 循环在 HumanEval 达 95.1%，超过 GPT-4 零样本的 67.0%。
  • 建议先分析错误再修复，并把客服实验做成带错误分析表的 GitHub 项目。

要点速览

  • “Agentic AI”课程由吴恩达在 DeepLearning.AI 上授课，难度为中级，共 5 个模块。Coursera 估计需要 2 周，每周 10 小时。
  • 每种模式都用 Python 从零实现，不依赖任何框架。
  • 如果想做 FDE，模块 4 最值得细学，内容涵盖评测、错误分析、延迟和成本。

在 HumanEval 基准上，GPT-4 零样本得分为 67.0%。较弱的 GPT-3.5 套上 Agent 循环后，得分达到 95.1%。吴恩达（Andrew Ng）2024 年 3 月 20 日在 The Batch 上引用这组数字，说明围绕模型组织工作的方式，可能和模型本身同样重要。

那篇文章提出了四种设计模式，如今它们有了一门专门的课程：DeepLearning.AI 上的 Agentic AI。课程的完整名称列出了全部四种：反思、工具调用、规划和多智能体工作流。大多数学员会冲着它们报名。

但如果目标是前线部署工程师（FDE）岗位，这门课最有价值的部分并不在标题里。

谁来讲，适合谁？

吴恩达是 DeepLearning.AI 的创始人、Coursera 的联合创始人。这门课由他亲自讲授，难度为中级。官方页面没有给出上线日期，只标注最近更新于 2026 年 8 月 31 日；Coursera 也显示课程在 2026 年 9 月更新过。

先修要求有两条：中级 Python 水平，以便看懂实现代码；对 LLM 及其 API 调用有基本了解。Coursera 把课程分为 5 个模块，估计需要 2 周，每周 10 小时。

如果有两到八年工作经验，也调用过 LLM API，基础部分不会有任何困难。

课程对 Agentic AI 的定义是：一种构建软件的新方式，由 LLM 完成复杂任务中的部分或全部步骤。“部分”二字很关键。并不是每个系统都需要完全自主的 Agent，课程也把高度自主的模式留到了最后一个模块。

四种模式，按自主程度排列

在 5 个模块中，四种模式和评测内容分布在模块 2 到模块 5。模块 2 讲反思，吴恩达的定义是：LLM 检查自己的输出，寻找改进方法。模块 3 讲工具调用，包括 MCP 和代码执行。

模块 5 把剩下两种模式归在“高度自主 Agent 的模式”（Patterns for Highly Autonomous Agents）之下：一是规划，即 LLM 为达成目标制定并执行多步计划；二是多智能体系统。

每种模式都配有具体实验。Customer Service Agent（客服 Agent）实验对应规划，Market Research Team（市场调研团队）实验对应多智能体系统，另有一节课讲 Agent 之间的通信模式。

想做 FDE，最该下功夫的是客服实验。这个 Agent 的输入和输出都很明确，用模块 4 的方法很容易评测。

这门课的独特之处在于教学方法：每种模式都用 Python 从零实现，不借助任何框架。这对 FDE 是实实在在的优势。在客户现场，很少能自己选技术栈；框架出问题时，只有理解底层循环的人才能调试。

为什么模块 4 才是值钱的技能

模块 4 位于工具调用和高度自主模式之间，内容与课程其他部分很不一样。它讲评测、错误分析、组件级评估，以及延迟和成本的测量。其中一节课讲的是先分析错误，再决定下一步优先做什么。

这部分最接近 FDE 的工作。假设你为一家银行部署了客服 Agent，它答错了 15% 的问题。这时多会一种模式帮助不大。

你需要知道：错误来自检索、工具调用还是规划；哪种修复收益最大；每种修复会如何影响延迟和成本。最简单的做法是抽取一批失败的运行记录，把每一条归到导致失败的组件上。

下表是一个假设示例，涵盖这个银行 Agent 的 20 次失败运行。

组件 错误示例（假设） 次数 / 20
检索 取到了去年的收费标准 9
工具调用 向查询 API 传入了格式错误的账号 7
规划 回答前跳过了身份验证 4

从这张表看，应该先修检索，因为它占了将近一半的错误。给整个 Agent 加一层反思循环也许更有吸引力，但连本来正常的步骤也会因此增加延迟和成本。

吴恩达那个 95.1% 的数字也应这样理解。Agent 循环能让弱模型超过强模型，但只有能测量，才知道循环是否真的有用。没有评测，很难判断反思或规划对你的系统到底有没有作用。

应该按什么顺序学？

报名前，先读 The Batch 上那篇 2024 年的文章，了解四种模式当初要解决什么问题。然后按课程自身的顺序学习，先学反思和工具调用，再学高度自主模式。越到后面，Agent 的步骤越多，步骤越多就越难调试。

给模块 4 留出比 Coursera 估计更多的时间，并把其中的方法用在你在模块 2 和模块 3 中搭建的 Agent 上。

把这门课写进简历时，不要只列证书。把客服 Agent 实验做成一个 GitHub 项目，附上类似上表的错误分析表：跑了多少次，每个错误来自哪个组件，先修了什么，为什么。

按课程所教的方式从零写代码，也能向雇主证明，你可以把这些模式用到任何技术栈上。

看 FDE 岗位描述时，留意“evaluation”“error analysis”或“latency and cost”这类字眼。带错误分析表的项目，正好对得上这些要求。

四种模式会随着每一代模型不断变化。先测量、再修复的习惯则会一直有用，不管下一个基准由哪个模型夺冠。
