Agent Harness 为前沿部署工程师带来了哪些改变

原标题：What Agent Harnesses Changed for Forward Deployed Engineers

Falkster.AI · 2026-10-29 · 约 12 分钟读完

摘要

文章以 Anthropic 的 S-1 上市文件为切入点，分析 Agent harness（智能体运行框架）如何改变了前沿部署工程师的工作。文件首次将 FDE 写入定义条款，并提出“模型本身不是 Agent”，harness 才是关键。如今厂商通过 Agent SDK 和 Managed Agents 直接出售 harness，FDE 的交付物从自建编排循环升级为连接器、技能文件、数据集与治理规则。但验证环节没有变快：提示词变更效率提升 45 倍，检查仍靠人工，评测仍是 FDE 的职责。

要点

  • Anthropic S-1 首次将前沿部署工程师写入定义条款。
  • harness 由厂商出售，FDE 不再自建编排循环。
  • 交付物变为技能、连接器与数据集，而非代码仓库。
  • FDE 到场时客户已在用 Claude，首周工作是审计。
  • 变更快了 45 倍，但验证与评测仍靠人工。

Anthropic 于周一提交了 S-1 文件，而前沿部署工程师出现在了第一页。在定义术语部分：“应用 AI 团队（包括前沿部署工程师）与企业合作，设计和部署针对客户自身系统和流程定制的解决方案、专业化工作流以及领域专用实现。”这是我所知的第一份把这一岗位写进术语表的注册声明。

我想钉在墙上的那句话位于一个叫 Harnesses 的标题下。“模型本身不是 Agent。”这份文件将 harness 定义为模型自主规划、调用工具、验证工作并完成任务所需的安全环境、凭证、记忆和编排循环。接着写道：“构建和运营这类基础设施是一项专业化、持续性的工作，直到不久前，每位客户都不得不自行承担。”

直到不久前，这些还是 FDE 来构建的。现在厂商以两种方式出售它。Agent SDK 让“驱动 Claude Code 的同一套生产级 harness 可供所有开发者使用，在他们自己的算力上运行”。Managed Agents 则由厂商来运行，“客户定义其 Agent 的任务、工具和防护栏”。当新模型发布时，“客户无需重建其 Agent 循环”。

三篇报道在同一天提取了这些数字。TechCrunch 的 Rebecca Bellan：年支出 10 万美元及以上的客户中，超过一半同时使用平台和一方应用，而去年年底这一比例约为 30%。The New Stack 的 Matthew Burns：第三季度未使用 Claude Code 的 Claude Enterprise 用户月支出不足 75 美元，而使用它的前 5% 用户支出约为其 20 倍。SuccessVP 的 John Gleeson 统计出文件中有 154 处段落涉及售后工作，并总结出一句话，我愿借用：“模型打开差距。客户成功弥合差距。”

这是《FDE 转型》的第 13 部分。第 12 部分讲的是评测。这一部分讲的是 Claude Code、harness 和 Agent 平台给这个岗位带来了什么改变，而 S-1 正是写这个话题的合适时机：这个岗位最常用工具背后的公司，刚刚在一份它要承担法律责任的文件中，写下了它认为这个工具是什么、这位工程师做什么。

简要版本

  • 工具化把 FDE 的交付物向上提升了一层。
  • 过去，驻场工程师要编写循环、重试逻辑、凭证和集成代码，而这占了工作的大部分。
  • 现在厂商交付 harness，往往在工程师到场之前，而这个岗位的工作正是文件承认仍然缺失的部分：“尚不存在的连接器、尚未编写的治理框架，以及需要从零构建的编排逻辑”，再加上那些“把机构知识转化为 Agent 能力”的技能。
  • FDE 的产出变成了一个技能、一个连接器和一组数据行，而不是一个代码仓库。这样交付回去成本更低，也更容易泛化，而这正是本系列所讨论的循环。
  • 还有一点工具没有改变：没有任何东西检查提示词。变更速度提高了 45 倍，但检查没有。

脚手架从 FDE 的背包里离开了

第 4 部分画出了三层结构：FDE 完全拥有的客户层、通过附带代价的拉取请求进行变更的脚手架层，以及核心层——在那里，关键词是“分叉”。S-1 用一段话命名了这些原语：Agent SDK、Managed Agents、agent skills、多 Agent 编排以及 MCP。“虽然这些 Agent 有不同的连接器和 agent skills，但它们使用相同的 SDK、协议和编排框架。”

把这段话当作一份职位描述来读。每个客户不同的只是连接器和技能。相同的，则是 FDE 过去要亲手构建的一切。

现场本来就不该有人手写重试逻辑，第 4 部分的脚手架税研究也展示了手写版本的结局：同样的模型，双倍的账单。但交接也随之移动了。Colin Jarvis 上周对 OpenAI 团队的记述已经呈现出这种样子：当一个重建的部署移交到下一个团队时，工作内容是更换连接器和“构建全新的评测（我们甚至为此准备了一个技能）”。脚手架之所以没有被提及，是因为它已经存在了。而有了 Managed Agents，《成为前沿部署工程师》第 07 课用整整一课讲解的模型更换，变成了供应商替你完成的事情。那一层已经消失，或者正在消失。

工具在你到达之前就已就位

改变第一周的那句话是：“当我们的直销团队接触客户时，Claude 往往已经在使用中了。”

风险因素用它们自己的语言说明了这一点：扩散是自发的，“由个人用户推动，包括软件开发者和专业消费者，他们采用 Claude 并常常充当内部拥护者”，而不是由庞大的直销组织推动。

所以 FDE 落地时，面对的是十几个开发者已经在运行脚手架的场景：有他们自己写的技能、他们自己接的连接器，以及没有任何人做过版本管理的提示词。第一周不是安装，而是一次审计：什么在运行、谁写的、上次何时变更、什么检查了这次变更。第 3 部分的交接包现在要以一份 FDE 所继承部署的清单作为开头。

招股书也宣称了下一步。“Claude 可以利用积累的上下文来建议下一个值得自动化的工作流，从而减少每次后续部署所需的工作量。”这就是泛化步骤。我会让它提供建议。循环章节把编辑的工作交给了 PM，而编辑不会进入脚手架。

技能是交接的单位

S-1 关于技能的表述：“自定义技能可以涵盖从工程标准、监管流程到专有工具链的任何内容。这些技能将机构知识转化为 Agent 能力。”

这就是 FDE 的工作，以产品功能的形式写下来。驻场工程师深入现场，找出存在于资深理赔员头脑中的规则。第 12 部分说过，评测环节就是它浮现的地方，而技能就是它沉淀的地方。技能是文本，有版本管理，下一个客户的运行框架可以直接加载。它是 FDE 产出的最具通用性的产物，也是最容易过拟合的，因为写一个只在某一家公司里管用的技能成本很低。这正是把泛化率放在它身上的理由。记分卡统计的是从现场带回的东西中最终上线交付的比例。一个技能要么能在第二个客户那里顺利加载，要么不能。Jarvis 的评测编写技能加载成功了。这就是标准。

从业者已经在以这种方式打包这个席位。rpraharaj 在 GitHub 上的 forward-deployed-engineer 仓库按阶段分组提供了 43 个 Claude Code 技能，覆盖从落地到持续维护的全过程，截至我撰写本文时尚未标注日期，其 README 写明其中 37 个未经生产环境测试。这是一个诚实的数字。

没有任何东西检查提示词

《成为前沿部署工程师》第 08 课于周一发布，与 S-1 同一天。“提示词就是没有任何东西检查它的代码。”故事是这样的：“有人在某个周四为了节省 token 把它缩短了。”删掉了四行，拉取请求看起来没问题，大约两周后理赔员说答案变差了，却无法把两件事联系起来。四十二个问题中有七个，只因四种措辞中的一种就答不上了，而代码审查中没有任何东西能告诉你问题出在哪一种。

解决办法是一个提示词注册表，把评测分数作为每个版本的一个字段，由运行评测的同一个函数写入。“只给文本做版本管理而不记录分数，历史只会告诉你改了什么，却永远不会告诉你改动是否有帮助。”我写提示词提交也是出于同样的原因，此前我的一个分类器在相同的提示词、不同的数据行上从 89% 跌到了 61%。

现在把这个和招股书自己的数字放在一起。“2026 年 9 月，我们对代码库的贡献中超过 90% 由 Claude 编写。”每位工程师的代码量是 2024 年的 45 倍以上。该厂商的工程师“越来越多地指导和审查其工作，而不是逐行编写代码”。如果这在实验室内部成立，那么在现场也同样成立。运行框架编写连接器、起草技能，并在某个周四修剪提示词。

45 倍

没有变快 45 倍的是检查环节。运行框架让改动变得廉价，却把验证留在了人的脑子里——除非有人把评测内置到流程之中。第 4 部分把它归入工程职责：每次运行框架变更时，都要用每个客户的数据行跑一遍。再加上厂商替你做的每一次模型更换，以及运行框架修剪的每一个提示词。

那一亿美元的自白

再看一段材料。文件称，Claude Frontier Academy“获得一亿美元的资金支持”，其宗旨是“解决企业 AI 落地的一个关键瓶颈：能够把 AI 从初始用例推进到生产环境的工程师短缺问题”。到 2027 年底培养一万名工程师。旁边还有与 Anthropic 合作的 Ode，这是一家面向中型企业的 AI 服务公司，“将与我们的应用 AI 团队和市场推广团队紧密合作”。

第二部分论证了 FDE 短缺是一个产品问题。厂商的答案是把这一个岗位拆成三样东西：一个产品（harness）、一个培训项目（Academy），以及一家服务公司（Ode）。产品接管了工作中到处都相同的部分，培训则把其余部分转移给客户自己的工程师。留给 FDE 的，正是这份工作真正的核心所在。Gleeson 的说法就其本身而言是对的。harness 弥合了差距的前一半。评测和交接弥合了后一半，而这仍然是人的工作。

这对岗位本身和高层意味着什么

如果你是 FDE：别再自己搭建循环了。你的交付物是一个连接器、一个技能、一组行数据，以及一条客户能看懂的治理规则。如果你在 2026 年还在编写重试逻辑，那你就是在和 SDK 竞争。

如果你负责产品：交接会以一个技能文件和一个评测的形式到来，两者都小到一个下午就能读完。工具会建议下一个工作流，决定权在你。

如果你负责工程：harness 现在处于你的上游。每一次 harness 版本更新、每一次模型更换、每一次提示词修改，都要跑一遍那些行数据。

如果你是买方：harness 是租来的。要问清楚你拥有什么。根据买方合同，你拥有的是技能、连接器、评测和治理，而且其形式要让下一家厂商的 harness 在第一天就能加载。

本周可以尝试的一件事：列出你生产环境部署中正在运行的每一个技能、连接器和提示词。在每一项旁边列三栏：谁写的、上次何时修改、什么机制检查了这次修改。第三栏里的空白，就是下一次反转的来源，而 harness 不会替你填补它们。

常见问题

Anthropic 的 S-1 关于前沿部署工程师说了什么？+

这份日期为 2026 年 10 月 26 日的文件在其定义术语中将应用 AI 定义为一门学科和组织职能，专注于将 AI 能力直接嵌入生产业务环境，并表示包括前沿部署工程师在内的应用 AI 团队与企业合作，设计和部署针对客户自身系统和流程定制的解决方案、专业化工作流程以及领域特定实现。在业务部分，文件指出这些团队与特定客户进行更深入的嵌入，并且这项工作会产生来自用户的反馈和信息，帮助塑造平台和产品路线图。文件还表示公司打算扩大其直接市场推广和应用 AI 团队。

什么是 agent harness，它为什么对 FDE 很重要？+

Anthropic 的 S-1 用一句话概括：仅有模型并不构成 Agent。Harness 是模型所需的安全环境、凭证、记忆和编排循环，使其能够规划、调用工具、验证自己的工作并独立完成任务。文件指出，构建和运营这类基础设施是一项专业化的持续性工作，直到最近，每个客户都不得不自行承担，而现在公司以两种方式出售这一 harness：一是作为可在你自己的算力上运行的 Agent SDK，二是由 Anthropic 运营的 Claude Managed Agents。对于 FDE 岗位而言，这意味着编排循环不再是工程师的交付物。交付物是连接器、治理、客户特定的编排、技能和评测。

既然 harness 已经成为产品，前沿部署工程师现在能向产品团队反馈什么？+

一个技能文件、一个连接器和一组数据行，而不是一个代码仓库。S-1 文件称，自定义技能可以涵盖从工程标准、监管流程到专有工具链的任何内容，并且这些技能能将机构知识转化为 Agent 能力。Colin Jarvis 对 OpenAI FDE 团队的描述提到，当一个重建的部署交付给下一个团队时，已经形成了一套编写评测的技能。技能是文本，可以版本化，并可被下一个客户加载，这使它成为 FDE 迄今产出的最具通用性的产物，同时也是最容易过拟合的产物。哪些技能能够泛化，仍然由产品经理来决定。

S-1 中 Claude Code 的支出差距对 FDE 岗位意味着什么？+

该文件称，在截至 2026 年 9 月 30 日的季度中，未使用 Claude Code 的 Claude Enterprise 用户平均每月支出不足 75 美元，而使用它的前 5% 用户支出约为该数额的 20 倍，并且到 Anthropic 的直属团队接触客户时，Claude 往往已被投入使用。TechCrunch 的 Rebecca Bellan 报道称，年支出达到 10 万美元或以上的客户中，超过一半现在同时使用平台和一款第一方应用，高于去年年底的约 30%。因此，FDE 进入的是一栋开发者已经在运行该工具链的大楼。第一周的工作是对已在运行内容的审计，而不是安装。

对前沿部署工程师来说，工具方面什么没有改变？+

验证。2026 年 10 月 26 日发布的《Becoming Forward Deployed Engineer》第 08 课指出，提示词就是没有任何东西对其进行检查的代码，并讲述了一个故事：某个周四从提示词中删减了四行内容，两周后理赔员提出投诉，却无法将两者联系起来。它的答案是一个提示词注册表，为每个版本存储评测分数，该分数由运行评测的同一个函数写入。Anthropic 的 S-1 称，2026 年 9 月其自身代码库中超过 90% 的贡献由 Claude 编写，且自 2024 年以来每位工程师的代码量增长了 45 倍以上。变更变得更便宜了。检查却没有，而对每次变更进行评测是 FDE 的职责。

什么是 Claude Frontier Academy？+

根据 S-1，Anthropic 于 2026 年 10 月推出了该学院，由 1 亿美元的投入支持，旨在解决文件所称的能够将 AI 从初始用例推进到生产环境的工程师短缺问题。它按照与 Anthropic 自身相同的标准培训客户和合作伙伴的工程师，每位学员都要在自己的组织中主导一次 Claude 部署，目标是到 2027 年底培训 10,000 名工程师。同一部分还描述了与 Anthropic 合作推出的 Ode，这是一家与私募股权公司合作为中型企业服务的 AI 服务公司，它将与应用 AI 和市场推广团队合作。

什么是 The FDE Transition 系列？+

falkster.com 上为前沿部署工程师及其周边团队领导者打造的每周两次系列文章。第 1 部分阐述核心论点：FDE 是从服务部门走出来的产品构建者。第 3 至 6 部分涵盖向产品团队的交接、与工程团队的代码库契约、与销售团队的承诺，以及与客户成功团队的第二个月。第 7 部分是评分卡，第 8 部分是离开这一岗位后的职业发展，第 9 部分是薪酬与股权，第 10 部分是买方契约，第 11 部分是何时不该招聘 FDE，第 12 部分是将评测作为部署产物。第 13 部分讲述工具变革对这一岗位的影响。接下来的部分探讨百人规模的 FDE 组织。
