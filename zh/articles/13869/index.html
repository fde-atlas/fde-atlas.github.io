打造世界一流的 FDE 团队

原标题：Building a world-class FDE team

Cresta · 2026-10-06 · 约 5 分钟读完

摘要

Cresta 的前沿部署工程师团队一年内从 1 人扩展到 50 余人，并获 Propel 26 年度 FDE 团队奖。文章总结其方法论：FDE 隶属工程部门而非市场推广部门，可直接向产品提交代码；核心价值在于弥合原型与生产之间的差距，为客户提供包含不同投入与收益的选项清单；部署通常一至三个月上线，但绝不跳过评测；每次部署的经验沉淀为平台能力，使后续项目起点更高。招聘时更看重行业知识与客户沟通成熟度，而非单纯编码能力。

要点

  • FDE 团队一年从 1 人增至 50 余人，隶属工程部门而非市场推广。
  • 核心价值是弥合原型到生产的差距，客户按选项清单决策。
  • 部署一至三个月上线，任何情况下不跳过评测。
  • 经验沉淀到共享平台，后续部署周期从十二周缩至六周。
  • 面试考察行业知识与客户沟通成熟度，而非编码能力。

仅仅十二个月，我们的前沿部署工程（FDE）团队就从 1 人发展到遍布全球的 50 多名成员。而且我们仍在持续壮大。

我们的快速扩张，加上在 Propel 26 上荣获年度 FDE 团队以及受邀加入 Insight Partners FDE Council，表明我们已经形成了一套成熟的模式，帮助企业在客户将 Cresta AI Agent 从一个有前景的演示转化为可扩展的生产系统，并带来可衡量的价值。

以下是我们用一年时间打造前沿部署工程团队、助力 Brinks、Snap Finance 和 Alaska Airlines 等行业领先品牌提供世界级客户体验所总结的经验。

我们把 FDE 放在工程部门，以优化客户价值

AI 项目很少因为做不出原型而失败。它们往往失败在原型与生产之间的那段距离上。

一个原型可以很快达到 80% 的生产就绪度。剩下的距离需要领域语言、边缘案例、标注数据、真实测试集、权限、合规、集成，以及一套处理故障的流程。大多数项目正是在这里放缓甚至停滞。

我们创建前沿部署工程团队，不仅是为了负责跨越这段距离，还要在产品本身不足以弥合差距时对产品进行调整。

我们的核心理念很简单：客户付费买的不是演示，而是演示与生产之间的那段距离。

弥合这段距离需要两种判断力，我们要求每一位 FDE 都同时具备：

  • 业务判断力： 深入理解客户的业务及其终端客户，从而发现流程卡在哪里、什么问题需要优先解决。当客户提出需求时，FDE 能够构建并呈现一份“菜单”式的可选方案
  • 技术判断力： 如何集成系统、调优模型、构建评测，并让解决方案足够可靠、能在生产环境中运行，处理真实的对话和真实的资金

构建“菜单”意味着列出真实的选项，并标明各自的投入成本与回报。

选项 A 可以是花两周时间妥善完成的完整修复；选项 B 可以是一个小改动，用一小部分的工作量获得 80% 的收益；而选项 C 可以是什么都不做，因为已经上线的功能已经足够好了。

大多数客户会选择选项 B。但这只有在呈现菜单的人也有能力构建选项 A 时才成立。

这一切之所以有效，是因为组织结构：我们的 FDE 隶属于产品工程部门，向工程条线汇报，而不是 GTM、客户成功或专业服务部门。

由于 FDE 身处工程部门，他们可以直接针对产品提交 pull request。这正是价值得以复利增长的原因：一位 FDE 在项目中获得的经验会成为平台的永久组成部分，让下一位客户从更高的起点出发。

我们的一些 FDE 甚至参与设计和构建了全新的产品，例如 Cresta Conductor 和 Cresta CLI。

我们从启动到上线推进迅速，但从不跳过评测

你会注意到，FDE 并不会把所有时间都花在客户身上。单次客户驻场从不超过五天左右，大多数只有两到三天。

驻场时间安排在需求探索和上线阶段前后，因为这是最有价值的学习发生的时候。FDE 会与实际执行工作的运营人员会面，在真实场景中观察工作流程，并解决决定系统能否上线的各种决策问题。

其余工作都在远程完成，团队可以在那里进行构建、评测，并与核心产品团队协作。

在任何时候，一位 FDE 通常会并行推进两到四个项目。每个项目配备两到三名 FDE：一名成员负责技术设计和关键实现，另一名提供同行评审并承接相邻的用例，有时第三名成员担任顾问。

同样值得一提的是，我们绝不会在没有评测的情况下交付产品。我们始终会验证给定的模型、提示词和工具集是否真正适合该垂直领域。

在一个垂直领域表现良好的提示词，在另一个领域可能完全失效。例如，始终保持共情在医疗领域可能是正确的选择。但在金融科技领域，当有人欠款 4,000 美元而 AI Agent 对此表现得过度共情时，客户的感受就很复杂。

我们对 Cresta 和客户的影响会随时间不断累积

将一个有前景的 AI Agent 打造成客户可以信任、使用并衡量的产品，其价值显而易见，但我们的影响不止于此。

当我们在多个客户中看到相同的任务模式时，我们会将其转化为可复用的技能。当缺少连接器时，我们就去构建它。当产品工作流程产生摩擦时，我们就去改进它。当模型的质量难以判断时，我们就基于真实对话创建评测集。

我们不会按小时计费然后留下一个分叉的代码库一走了之。我们的 AI Agent 运行在共享平台上，因此当一位 FDE 改进了我们为某家航空公司处理护栏的方式时，这一改进对下一家航空公司已经生效。

如果第一位 FDE 的早期部署需要十二周才能将解决方案上线到平台，那么下一位只需八周，第三位只需六周。

简而言之：每一次部署都应该比上一次的起点领先很多。

这之所以可行，是因为我们的客户关系更像一家高信任度的 omakase 餐厅，而非单点菜单。我们的客户不只是要求我们已交付的产品。当我们告诉他们“我们有了新东西，还没有人采用过，想不想做第一个？”时，他们会说好。

这并不是他们的天真。而是通过持续拿出真正有效的成果，日积月累赢得的信任。

我们面试 FDE 时看重的是判断力，而非编码熟练度

我们很早就决定招聘有经验的 FDE。而且我们的标准不是“你会不会写代码”。几乎任何人都可以花一个周末用 Claude Code 搭建一个演示效果不错的聊天机器人。

在面试中，我们转而询问真实的生产场景，比如：“当你的 AI Agent 在客户面前犯错时，发生了什么？”以及“当你明知某个功能需求是错的，你是如何处理的？”

这些问题能揭示两点，正是它们将优秀的 FDE 与只会写代码的人区分开来，而这两点在典型的面试中都不会体现。

第一点是行业知识：比如航空公司真正关心什么，金融科技合规到底意味着什么等等。第二点是面向客户的成熟度：懂得如何在不损害关系的情况下说不，并在坏消息自己爆发之前主动传达它。

如果这种理念引起你的共鸣，我们很乐意聊聊。我们正在全球招聘 FDE，他们将做出能在全球最大、最具创新性的公司中不断产生复利效应的决策。
