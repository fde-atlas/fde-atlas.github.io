单点登录

原标题：Single sign-on

FDE Interview Prep · 2026 · 约 2 分钟读完

摘要

本文讲解单点登录（SSO）的工作原理及其在前沿部署工程师面试中的应用。SSO 让用户通过 Okta 或 Microsoft Entra ID 等身份提供方认证一次即可访问多个应用，应用依赖 SAML 断言或 OIDC ID 令牌等签名声明而非自行验证密码。文章强调强答案应区分 SSO 与 SCIM 配置：SSO 只证明登录者身份，不负责账户的创建与注销；缺少 SCIM 时，离职员工的账户、会话和 API 令牌可能仍然有效。部署阶段的瓶颈往往不是协议本身，而是客户 IT 团队注册应用并商定组与角色的映射，因此应第一天就确认客户使用的身份提供方及其负责人。

要点

  • SSO 通过 Okta 或 Microsoft Entra ID 等身份提供方实现一次认证访问多个应用。
  • 应用信任 SAML 断言或 OIDC ID 令牌等签名声明，而非自行校验密码。
  • 强答案需区分 SSO 与 SCIM：后者负责账户的创建与注销（RFC 7644）。
  • 仅靠首次登录自动建户，离职员工的会话和 API 令牌可能仍然有效。
  • 部署瓶颈常是客户 IT 注册应用与角色映射，应第一天就确认身份提供方。

全文

单点登录（SSO）允许用户通过中央身份提供方进行一次身份验证——通常是客户由其企业目录支持的工作force身份提供方（例如 Okta 或 Microsoft Entra ID）——然后即可访问多个应用，无需逐个登录。应用信任来自身份提供方的签名声明，而不是自己校验密码：在（参见 OASIS SAML 技术概览）中是签名断言，在（参见 OpenID Connect Core）中是签名 ID 令牌。

在 FDE 面试中
