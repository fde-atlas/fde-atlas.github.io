SOW-Generator

FDE中国社区 · 2026-07-12 · 约 4 分钟读完

摘要

本文介绍 FDE中国社区 的 SOW-Generator 技能包（v1.1，成熟度 usable），用于生成 AI PoC/MVP 项目的工作说明书。核心问题是 AI 项目范围易漂移、口头约定引发验收争议。技能定义了 SOW 的七个核心章节（目标边界、交付物、里程碑、验收指标、数据权限、风险假设、变更机制），强调 PoC 只验证核心假设、不承诺全量生产。输入为场景卡、干系人地图、预算与合规约束，输出 SOW 正文、里程碑表与验收指标附件。文中给出四阶段门控（PoC 准备到复盘资产化）、FDE 与 AIBP 等角色的协作分工，以及私有化、信创、等保环境的额外约束。案例显示某智能客服 PoC 应用后四周内验收无追加纠纷。

要点

  • SOW 含七个核心章节，PoC 只验证核心假设。
  • 输入场景卡与干系人地图，输出 SOW 正文与验收指标。
  • 四阶段门控：从 PoC 准备到复盘资产化。
  • FDE 主导交付，AIBP 负责 Ground Truth 与业务验收。
  • 覆盖信创、等保等私有化部署约束。

问题定义

AI 项目范围易漂移，口头约定导致验收争议和追加成本纠纷。

方法论框架

SOW 核心章节：目标与边界、交付物、里程碑、验收指标、数据与权限、风险与假设、变更机制。 PoC 原则：只验证核心假设，不承诺全量生产。

输入 / 输出

输入

  • 场景卡
  • 干系人地图
  • 预算与时间约束
  • 合规要求

输出

  • SOW 正文
  • 里程碑表
  • 验收指标附件
  • 变更流程

执行步骤

  • 写里程碑与交付物
  • 绑定验收指标
  • 列假设与风险
  • 法务/商务评审

常见问题 FAQ

Q1：执行【SOW-Generator】时如何避免「范围过大一次做生产」？

A：按 README 方法论逐步执行，在周度 Demo 展示阶段性交付物；若 PoC 材料不齐，先输出「待验证清单」再推进。

Q2：私有化/信创/等保环境下有哪些额外约束？

A：在 prompt 约束段明确部署形态；涉及数据不出域、国产化组件、审计日志时同步引用 Private-Deployment-Gateway 与 RBAC-Audit。

Q3：与 AIBP 分工边界不清怎么办？

A：回到 AIBP-Collaboration-Playbook 更新 RACI；AIBP 负责 Ground Truth 与业务验收，FDE 负责可交付技术资产。

Q4：PoC 通过后如何衔接到 Beta/生产？

A：输出物中标注下一阶段 Skill（如 RAG-Evaluation→Private-Deployment-Gateway→FDE-Adoption-Growth），并在 checklist 触发上线门禁。
