这一轮我在 HackerRank 上完成，时长 90 分钟，需要完成三道题：一道编程题、一道 SQL 题和一道 API 题。收到题目后我就可以立即开始作答。以下是我遇到的面试题目：

题目描述：

给定一个由整数组成的数组

arr

的

n

，通过以下操作使数组为正：每次操作中，选择整数

i

(

0 <= i < n

），并将

arr[i]

改为

x

(

x >= 0

）。当数组中每个长度大于 1 的子数组的和均为非负时，该数组即为“正”。更正式地说，操作之后，对于所有

l

和

r

:

0 <= l < r < n
sum(arr[i] for i in range(l, r+1)) >= 0

目标：

求使数组变为正所需的最少操作次数。

示例：

arr = [2, 5, -8, -1, 2]

假设采用 0 起始索引，取 i = 2 和 x = 10。修改后的数组为 arr' = [2, 5, 10, -1, 2]。此时，每个长度大于 1 的子数组的和均为非负。返回操作次数，即 1。

函数说明：

在下方编辑器中完成函数

getMinOperations

。

getMinOperations

具有以下参数：

int arr[n]

：一个整数数组

返回值：

int

：所需的最少操作次数

约束条件：

  • 1 <= n <= 10^5
  • -10^9 <= arr[i] <= 10^9，其中 0 <= i < n

给定字符串的子序列是通过删除字符串中的零个或多个字符，然后将剩余字符拼接而成的。好子序列是指每个字符出现频率都相同的子序列。给定一个由 n 个拉丁字母组成的字符串，计算它包含多少个好子序列。由于答案可能非常大，请计算其对 (10^9+7) 取模的结果。

注意：空子序列不是好子序列。

word = "abca"

该单词共可形成 15 个非空子序列。

唯一不是好子序列的是 "aba"、"aca" 和 "abca"，因为字符 "a" 的频率为 2，而其他每个字符的频率为 1。

好子序列的总数 = 15 - 3 = 12

上述示例的答案 = 12 对 (10^9+7) 取模 = 12。

请在下面的编辑器中完成函数 countGoodSubsequences。

string word：一个仅由小写拉丁字母组成的字符串

int：好子序列的数量对 (10^9+7) 取模的结果

https://jsonmock.hackerrank.com/api/tvseries

我的技术电话面试是在 Karat 上完成的。这一轮包含三道题。

第一题是投资组合估值问题。我拿到一个包含若干股票的投资组合，以及它们的价格和日期。目标是计算该投资组合在不同日期的总价值。一个关键细节是：如果某只股票在某天没有价格，但在之前的某天有价格，就应使用之前可用的价格。这意味着如果价格保持不变，就直接使用最后一次记录的值。这道题有两种最优解法。常见的方法是使用最小堆对日期排序。另一种方法是使用排序结合指针，为每只股票跟踪上一个可用价格的索引。

第二题是系统设计题。我被要求设计一个监控系统来检测后端服务器的性能。讨论主要集中在如何收集统计数据以及如何处理服务器宕机。我们还简要谈到了系统的扩展。

第三题涉及一个已有的代码库，我需要在其中实现一个新功能。

在这一轮中，主函数已有输入，我需要构建解决方案并将其放入一个单独的方法中。流程是先解释我的思路，面试官认可后，我再开始编码。写完并运行正确的代码后，我被要求讨论时间和空间复杂度。

第一道编码题给出一组成对的列表，例如

(1, 3)

和

(3, 4)

。每一对代表一条边。目标是找出没有父节点以及恰好有一个父节点的节点。我用哈希表解决了这个问题。

第二道编码题同样以成对数据作为输入，要求我判断给定的两个节点是否有共同祖先。我的方法是自底向上构建一个有向无环图（DAG），然后从这两个节点分别执行深度优先搜索（DFS）。我会把路径上的节点放入一个集合中，然后求交集，看是否存在共同节点。

第三题是找出最远的祖先。我时间不够了，所以只解释了我的思路。这是自底向上构建 DAG 方法的延续，但在 DFS 过程中，我会记录路径以及每个节点对应的深度。解决方案就是找出深度最大的节点。

这一轮全是调试。第一题大约有 80 行代码。在一个

if-else

逻辑块中有一个 bug，导致

HashMap

计数不正确。

第二题规模大得多，大约 250 行，抽象层次更多。这个 bug 涉及对被感染接触者的重复计数。我认为如果没有做过类似调试题的经验，这道题会非常具有挑战性且耗时。

Palantir 面试流程的最后一步是 Palantir 招聘经理面试，这一轮让人既兴奋又紧张。我的最终面试是与一位招聘经理进行一小时的面谈。这一轮的重点是我是否适合团队以及 Palantir 的使命。

行为类和技术类问题大致各占一半。招聘经理特别关注我上一段实习经历，询问了我的项目以及遇到的挑战。他们还问了我认为自己职业生涯中最大的失败是什么，以及我在下一份工作中想寻找什么。

Palantir 的面试流程主要分为四个部分：招聘人员电话沟通、技术电话面试、现场面试和招聘经理面试。各环节时长如下：

  • 招聘人员电话沟通（30 分钟）
  • 在线测评（1 小时）
  • 虚拟现场面试（3 小时）
  • 招聘经理面试（1 小时）

招聘人员电话沟通 这是一次 30 分钟的聊天。招聘人员想知道我为什么想加入 Palantir，以及我做过哪些项目。他们还考察了我是否符合公司文化。

在线测评 这一轮持续了大约 90 分钟。我在实时环境中解决编程问题。面试官还穿插了一些行为类问题，所以我需要同时展示技术能力和沟通能力。

虚拟现场面试 我经历了 3 到 5 轮考察不同技能的面试，包括编程、系统设计和重构。其中一轮值得注意的是 Palantir 的问题拆解面试，重点考察我如何拆解问题并阐述自己的思路。

招聘经理面试 这是一轮后续面试。招聘经理重新审视了我之前表现不佳的方面。在这一轮中，我遇到了更多技术类和行为类问题。

Palantir 重视那些能够反思自己的方法、提出有深度的问题并展现成长型思维的候选人。在招聘人员电话沟通中，他们想知道我是否认真对待这家公司，以及我是否符合公司文化。为了准备，我回顾了过去需要协作、解决难题或快速适应的项目。我还练习了用简单的语言解释技术概念，因为清晰的沟通至关重要。

在准备过程中，我重点关注了以下几个方面：

  • 我研究了 Palantir 的使命和近期项目，并思考了我的技能如何能做出贡献。当被问到为什么想加入时，我给出了具体的原因，而不是泛泛而谈。
  • 我清晰地回答问题，并使用 STAR 方法（情境、任务、行动、结果）来阐述我的经历。我没有试图掩盖挫折，而是分享了我从中学到的东西。
  • 我强调了 Palantir 让我感到兴奋的地方，以及我希望如何产生影响力，并将我过去的工作与他们的使命联系起来。
  • 我准备了关于团队文化、成长机会以及如何衡量成功的有深度的问题，避免任何通过简单搜索就能得到答案的问题。
  • 我保持真实，谈论我在意的事情及其原因，因为 Palantir 重视诚实和坦率。
  • 即使有些结果超出了我的控制范围，我也专注于自己能控制的事情：表达清晰、诚实，并展现我对这个职位的真正兴趣。

回顾过去，我意识到在面试中真正起决定性作用的，是专注于解决问题的过程、与他人协作、适应新环境，以及反思自己从挑战中学到了什么。

事实上，他们不可能在所有类型的 Palantir 面试中都看出来，包括 Palantir 部署策略师面试和 Palantir 前沿部署软件工程师面试。

面试流程两者都会考察，但重点放在解决问题和沟通上。虽然你需要具备扎实的算法和数据结构技术基础，但关键在于展示你如何思考复杂、模糊的问题。与其他可能只关注纯编码速度的公司不同，Palantir 想看到的是你将一个大问题拆解成更小、更易处理的部分，并清晰阐述你的思路的能力。在系统设计与拆解环节尤其如此。

这一点非常重要。虽然不要求你有实际操作经验，但你应该对 Palantir 的业务及其产品的运作方式有扎实的了解。行为面试问题，尤其是与招聘经理的对话，往往会探究你想加入 Palantir 的动机以及你对公司使命的理解。了解 Gotham（面向政府）和 Foundry（面向商业客户）之间的区别，能表明你做足了功课、对这家公司有真正的兴趣，这会给你带来显著优势。
