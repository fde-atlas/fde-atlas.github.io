SAML

原标题：SAML

FDE Interview Prep · 2026 · 约 2 分钟读完

摘要

本文面向 FDE 面试，讲解 SAML 2.0 的登录流程：客户的身份提供方签署 XML 断言，应用方验证签名后放行用户，双方通过元数据建立信任。文章强调 SAML 只负责认证，账号的创建与删除需配合 SCIM；并给出工程要点：定期刷新元数据以防证书轮换导致全员无法登录，使用成熟库并防范签名包装、重放等攻击，注意 NameID 格式、属性映射及 IdP 发起登录的风险。SAML 出现在 Okta 三个 FDE 职位的考察清单中。

要点

  • SAML 2.0 是 OASIS 标准，由身份提供方签发 XML 断言，应用验证签名后登录用户。
  • SAML 只做认证，账号生命周期管理需搭配 SCIM。
  • 元数据须定时刷新，否则证书轮换会锁死所有用户。
  • 安全上要防签名包装攻击，校验 Audience、Destination、NotOnOrAfter、InResponseTo。
  • SAML 列入 Okta 三个 FDE 职位的面试考察范围。

全文

SAML 现已发展到 2.0 版本，是 OASIS 标准：客户的身份提供方签署一个 XML 断言，声明用户是谁，而你的应用（即服务提供方）验证该签名并让用户登录。浏览器将断言传送到你的断言消费服务 URL，通常通过 HTTP-POST 绑定；双方通过在初始设置时以及每次证书轮换时交换的元数据建立信任：实体 ID、该 URL 以及签名证书。相关规则见 OASIS SAML Core 规范、SAML Bindings 规范、SAML Metadata 规范 和 SAML Profiles 规范，其中 Web Browser Profile 定义了此处描述的浏览器登录流程。
