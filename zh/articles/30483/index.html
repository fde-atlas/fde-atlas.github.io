FDE 如何在客户代码库安全使用 Claude Code

FDE Times · 2026-10-09 · 约 5 分钟读完

摘要

文章面向在客户代码库中使用 AI 编码工具的 FDE，梳理 Claude Code、Codex 和 Cursor 的默认设置差异与隐私陷阱：Claude Code 默认明文留存会话记录 30 天，ZDR 需按组织单独开启；Cursor 在使用自有 API key 时失去零数据保留承诺。作者强调 CLAUDE.md 只是指令而非围栏，真正的保障来自沙箱与权限模式，并给出会话操作流程、离场清理清单和求职建议。

要点

  • Claude Code 会话记录默认明文本机留存 30 天。
  • ZDR 依赖账号类型，Enterprise 也需按组织单独开启。
  • Cursor 使用自有 API key 时零数据保留承诺失效。
  • CLAUDE.md 只是指令，真正限制 Agent 的是沙箱和权限模式。
  • 项目结束时应按客户要求清理本机会话记录。

Claude Code、Codex 和 Cursor 都能加限制，但默认设置各不相同，违反客户政策的例外藏在隐私文档里。

要点速览

  • 默认情况下，Claude Code 会在本机以明文保存会话记录 30 天，处理客户代码时也一样。
  • 不用于训练的承诺和 ZDR 取决于账号类型和各工具的配置，例如在 Cursor 中是否使用自己的 API key。
  • CLAUDE.md 只是指令。真正限制 Agent 的是沙箱和权限模式。

你在笔记本上打开的每个 Claude Code 会话都会留下痕迹。Anthropic 的文档写明，会话记录以明文形式存放在

~/.claude/projects/

，默认保留 30 天。如果这个会话跑在客户的代码库上，Agent 读过的大量内容和你粘贴进去的东西，可能仍留在你的硬盘里。

对开发内部产品的工程师来说，这一点很少构成问题。对前线部署工程师（FDE）来说则不然。你工作的仓库不属于你，Agent 运行的每条命令都必须符合客户的数据政策。

Claude Code、Codex 和 Cursor 都提供了限制 Agent 行为的手段。但三者的默认设置各不相同，最关键的例外写在很少有人细读的隐私文档里。

Agent 能在你的仓库里做什么？

Anthropic 将 Claude Code 定位为智能体编码工具。它能读取代码库、修改文件、运行命令、连接开发工具，可在终端、IDE、桌面应用和浏览器中使用。每次会话开始时，它都会读取仓库中的

CLAUDE.md

文件，因此这个文件很适合用来记录编码规范和客户的约束条件。

OpenAI 的 Codex 在本地运行时，由操作系统本身将其限制在沙箱中，只能访问被允许的内容。Codex 默认断网运行。另有一套审批策略，决定它在什么时候必须先征求你的同意再行动。

至于 Cursor，最需要细读的是它的数据承诺，这也是 FDE 最常栽跟头的地方。

写提示词之前，先问清账号

一条错误的命令至少会显示在屏幕上，你还能叫停。代码离开本机后去了哪里，却难以察觉得多。所以值得在输入第一条提示词之前把问题问清楚。

Anthropic 表示，如果你使用的是商业条款（Team、Enterprise、API），发送给 Claude Code 的代码和提示词不会用于训练模型；个人套餐则不同，因此首先要问的是账号类型。

即便是 Enterprise 套餐，也不会自动获得零数据保留（ZDR）。Anthropic 的文档说明，ZDR 需按组织单独开启，且要先由客户团队确认该组织符合条件。

Cursor 的陷阱更隐蔽。对团队而言，隐私模式（Privacy Mode）默认对所有成员开启，承诺代码不会被 Cursor 或模型提供商用于训练；管理员还可以在整个组织内强制启用，成员无法关闭。

但使用自己的 API key 时，ZDR 不再适用。设想你在客户现场额度用完了，为了按时完成演示，把个人 API key 接入 Cursor。界面看起来毫无变化，ZDR 承诺却已失效。因此这类改动需要事先获得批准，而不是事后报备。

Claude CodeCodexCursor
默认行为Manual 模式：只读，修改文件或运行命令前先询问操作系统级沙箱，断网团队默认开启隐私模式
限制机制沙箱化 bash，隔离文件系统和网络审批策略决定何时必须询问管理员在全组织强制启用隐私模式
容易出错之处ZDR 须按组织开启；明文会话记录保留 30 天开放网络或放宽权限由你自己决定使用自有 API key 时不适用 ZDR

一个会话示例

假设客户请你修复支付服务里一个失败的测试。在输入第一条提示词之前，先在仓库根目录创建一个简短的

CLAUDE.md

：

# 客户约束
- 不要读取 secrets/ 目录或任何 .env 文件
- 不要调用外部网络服务
- 只能用以下命令运行测试：make test-payments
- 不要提交 commit；只提出 diff，供客户工程师审查

然后以 Manual 模式打开会话。Claude Code 起步时只有只读权限，所以第一个任务应该是让它读代码，解释测试为何失败。

当它提议修改文件或运行

make test-payments

时，逐条读完命令再批准。如果权限提示过于频繁，就切换到已隔离文件系统和网络的沙箱化 bash，而不是闭着眼睛全部批准。

记住，

CLAUDE.md

只是 Agent 在会话开始时读取的内容。它是指令，不是围栏。“不要调用外部网络服务”这一条，只有在沙箱阻断网络时才真正有保障。

用 Codex 完成同样的工作

在 Codex 中，网络围栏已经就位，因为默认就是断网的。假设支付测试需要下载一个本机没有的依赖：命令会失败，Agent 会停下或来询问你，具体取决于审批策略。

这正是最容易犯错的时刻，因为放开网络只需一秒钟。先停下来，问客户的工程师：这个服务是否允许对外调用，允许调用到哪里。得到同意后再放宽权限，并把这个决定写进交接文档。

工具不会替你担责

Anthropic 的安全文档说得很直白：在批准之前审查拟议的代码和命令，是你的责任。在客户现场，这句话有实实在在的后果。一条删除目录的命令，即使是 Agent 提议的，只要你批准了，就是你的命令。

第二个限制在笔记本本身。明文会话记录保留 30 天，意味着项目结束时，只有按客户要求清理完这些目录，交接才算完成。把这一步加入每个项目的离场检查清单。

先学什么，简历上写什么

不要从提示词技巧入手。按顺序学三件事：所用工具的权限模式和沙箱；“商业条款”和 ZDR 的含义；然后是如何为仓库编写约束文件。第一件要练成条件反射，因为这是工具真正强制执行的部分。

阅读岗位描述时，留意该岗位是否需要直接在客户的基础设施或代码库中工作；如果是，这项技能值得在面试中主动提起。简历上写一句“在金融服务客户的代码库上，搭建了在断网沙箱中使用编码 Agent 的工作流程”，比“精通 Claude Code”更能让招聘经理了解你。

客户多半永远不会问你用了哪些工具。但如果他们问起项目的会话记录在哪里，你应该能立刻给出答案。
