AWS SAA-C03 课程学习顺序：FDE 先学 IAM

FDE Times · 2026-11-13 · 约 4 分钟读完

摘要

文章分析 Stéphane Maarek 在 Udemy 上的 SAA-C03 备考课程（约 27.5 小时、399 节课），并针对 FDE 提出与课程默认顺序不同的学习路径：因安全领域占考试 30% 的最高权重，且是客户审查最严的部分，应先学 IAM、KMS 和 SSM，再学数据服务、EC2 与 Serverless。文章以保险公司 Agent 场景说明最小权限策略的写法，并建议配合 Free Tier 实验项目把证书变成实际证明。

要点

  • Maarek 课程约 27.5 小时、399 节课，无需 AWS 基础，练习用 Free Tier。
  • 安全占 SAA-C03 考试 30%，为四领域最高，FDE 应先学 IAM、KMS、SSM。
  • 考试 65 题、130 分钟，720 分及格，采用补偿式计分。
  • 文章用最小权限 IAM 策略示例说明客户环境中的实际需求。
  • 建议搭配 GitHub 实验项目，证书之外展示动手能力。

安全在 SAA-C03 考试中占 30% 的分数，也是到客户那里要过的第一关。

要点速览

  • Stéphane Maarek 的课程时长约 27 小时 25 分钟，不要求 AWS 基础，动手练习使用 Free Tier。
  • 安全占 SAA-C03 总分的 30%，在四个领域中最高，因此 FDE 应先学 IAM、KMS 和 SSM。
  • AWS 希望考生至少有一年动手设计解决方案的经验，只看视频远远不够。

这门课时长 27 小时 25 分钟，共 399 节课，分为 33 个章节。如果下周就要拿到客户 AWS 账号的访问权限，真正要考虑的不是学不学得完，而是先学哪一部分。

Stéphane Maarek 在 Udemy 上的“Ultimate AWS Certified Solutions Architect Associate 2026”，目标是帮学员通过 SAA-C03 考试。但对前线部署工程师（FDE）来说，它的价值在别处：它讲的恰好是在别人的基础设施上部署时要接触的那些服务。

这一点很重要。在客户那里，环境不能按自己的喜好搭建。你得先读懂对方已经在跑的系统，申请合适的权限，再提出对方基础设施团队愿意批准的修改。

谁来讲，讲了什么？

Maarek 在 Udemy 讲师主页上介绍自己是解决方案架构师、顾问和软件开发者。他是 AWS Hero，持有 Solutions Architect Professional 和 DevOps Professional 认证，也是 Conduktor 的联合创始人。据 2026 年 11 月 13 日的课程页面，这门课评分 4.7，约有 30.1 万条评价，学员约 136 万。

课程不要求任何 AWS 基础，练习使用 Free Tier，适合刚接触云的软件工程师。前面几个章节讲 IAM & AWS CLI、EC2、ELB 和 Auto Scaling、RDS 以及 Aurora 和 ElastiCache，然后是 Route 53。

后面的章节扩展到 S3、Serverless（Lambda、DynamoDB、Cognito、API Gateway）、Well-Architected、灾难恢复，以及涉及 KMS、IAM 和 SSM 的安全内容。打开客户控制台时会遇到的东西，基本都在这份清单里。

考试本身已经说明了先学什么

AWS 官方考试指南写明，SAA-C03 考查的是基于 Well-Architected Framework 设计解决方案的能力。也就是说，考的是设计能力，而不只是运维。考试分四个领域：设计安全架构占 30%，设计弹性架构占 26%，设计高性能架构占 24%，设计成本优化架构占 20%。

算一下：考试有 50 道计分题，其中约 15 道与安全有关。总题量为 65 道（含 15 道不计分题），限时 130 分钟，平均每题约 2 分钟。分数范围 100 到 1,000，720 分及格，采用补偿式计分，各领域没有最低分要求。

考试费用为 150 美元；持有有效 AWS 认证的考生，下一次考试可享五折。

补偿式计分意味着某一块薄弱也能通过。但 FDE 不该只为凑够分数而学，因为考试中权重最高的领域，恰恰也是客户审查最严的部分。

设想你到客户那里的第一天

假设客户是一家保险公司，想让一个 Agent 读取 S3 里的文档，把结果写入 RDS。在任何一行代码跑起来之前，你需要三样东西：一个能读取指定存储桶的 IAM 角色，使用加密该存储桶的 KMS 密钥的权限，以及一种不把数据库密码写死在代码里的获取方式。

这三项任务都属于安全领域：IAM、KMS 和 SSM。挂在 Agent 角色上的策略可以精简到这样（存储桶、密钥和参数名称均为示例）：

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::claims-docs/*"
    },
    {
      "Effect": "Allow",
      "Action": "kms:Decrypt",
      "Resource": "arn:aws:kms:ap-southeast-1:111122223333:key/claims-key-id"
    },
    {
      "Effect": "Allow",
      "Action": "ssm:GetParameter",
      "Resource": "arn:aws:ssm:ap-southeast-1:111122223333:parameter/claims-agent/db-password"
    }
  ]
}

注意这里没有什么：没有

s3:*

，没有

"Resource": "*"

，也没有写入存储桶的权限。

所以，FDE 合理的学习顺序和课程自身的顺序不同。先学 IAM & AWS CLI，然后直接跳到 KMS、SSM 和 VPC 安全的章节。

接下来是数据（S3、RDS、Aurora、ElastiCache），然后是 EC2 以及 ELB 和 Auto Scaling。再往后是 Serverless，Well-Architected 和灾难恢复放在最后，那时你已经有足够的知识，能理解一个架构为什么这样设计。

课程里值得记住的三点

第一，访问权限也是架构。对 FDE 来说，安全 30% 的权重提醒你：策略给得过宽，修改很容易在客户那里被拦下。

第二点就写在考试指南里：考试也考查审视现有方案并提出改进。这和 FDE 在客户环境中的工作非常接近——系统在你来之前就在运行，你的任务是指出哪里该改。

第三是课程本身的局限。AWS 表示，理想的考生至少有一年在 AWS 上动手设计解决方案的经验。把 399 节课全部看完，也替代不了亲手搭一个系统、把它弄坏再修好。

把证书变成证明

AWS 把这项认证定位为提升持证者信心的途径。这里的建议是不要止步于证书：配上一个能逐行讲清楚的实验项目。

在 Free Tier 上重建上面的保险公司场景，放到 GitHub 上，附上架构图、一份类似上面的策略，以及一段简短说明，解释每项权限为什么必要。

在简历上，把 SAA-C03 认证和这个仓库的链接写在一起。面试时，讲一次你读懂现有架构并提出三项修改的经历。

Maarek 的课程能把你送进考场。而要赢得客户对其 AWS 账号的信任，要从第一次只申请必要权限、不多要一项开始。
