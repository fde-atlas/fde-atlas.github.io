摘要

文章汇总三条信号，判断企业 Agent 正进入规模化交付阶段：美国退伍军人事务部以最高 16 亿美元、3 年期的企业级协议采购 Salesforce 的 Agentic AI 与协作底座；ITC Infotech 先在自身组织部署 Gemini Enterprise，形成「客户零号—验证—沉淀蓝图—复制给客户」模式；Cisco 与 AMD 把桌面本地 Agent 纳入网络、成本、行为与隔离四类治理。作者认为 FDE 的交付对象正从单一工作流扩展为合同结果、复制蓝图、运行控制三层系统。

要点

  • VA 签署最高 16 亿美元、3 年期 Agentic 企业协议，标志 Agent 进入正式采购。
  • ITC Infotech 先做客户零号，内部验证 Gemini Enterprise 后沉淀蓝图复制给客户。
  • Cisco 与 AMD 为桌面本地 Agent 建立网络、Token 成本、行为与隔离四类控制。
  • FDE 交付对象扩展为合同结果、复制蓝图、运行控制三层系统。
  • 建议 FDE 记录基线与结果，把项目做成可复制的客户零号案例。

今日判断

昨天的重点是 Agent 上线后如何证明业务动作可信；今天的新变化发生在更上游和更大范围：美国退伍军人事务部用最高 16 亿美元的企业级协议采购 Agentic AI、数据与协作底座；ITC Infotech 先把 Gemini Enterprise 部署到自己组织中，形成「客户零号—验证—沉淀蓝图—复制给客户」的交付模式；Cisco 与 AMD 则把桌面本地 Agent 纳入网络、Token 成本、行为和安全四类控制。

三条信号共同说明，企业 AI 规模化已经不只是多做几个 Agent，而是同时回答三个问题：预算如何进入正式采购，实施经验如何变成可复制资产，分散在云端与员工设备上的 Agent 如何被统一看见和约束。对前沿部署工程师（Forward Deployed Engineer，FDE）而言，交付对象正在从单一工作流扩展为「合同结果、复制蓝图、运行控制」三层系统。

重点信号

美国退伍军人事务部：最高 16 亿美元采购 Agentic Enterprise License Agreement

  • 来源：Salesforce ｜ 原文链接
  • Salesforce 7 月 24 日宣布，美国退伍军人事务部（VA）通过其分销网络授予一份最高 16 亿美元、期限 3 年的 Agentic Enterprise License Agreement。合同为 1 年基础期加两个可选续约年。
  • 交付范围：Missionforce 将连接部门内的工作流与系统，提供 24×7 虚拟联络中心、患者分诊、接入与照护协调，并以 FedRAMP High 授权、HIPAA-ready Agent 处理高敏业务。
  • 已有运行基础：VA Health Connect 已处理超过 4,060 万次退伍军人来电；Slack 已部署到 150 多个医疗与门诊中心；SQUARES 有 2,100 多名授权用户。上述数字是既有 Salesforce 基础，不等于本次新合同已新增的结果。
  • 为什么重要：这是企业 Agent 从项目预算进入正式企业级协议的强信号。真正可采购的不是一个聊天机器人，而是合规底座、统一数据、跨系统工作流、7×24 服务和持续交付能力的组合。
  • 证据边界：16 亿美元是合同总上限，不是已确认收入或已经支付金额；合同包含 Salesforce 平台、数据、协作与 Agent 能力，不能全部算作「AI Agent 收入」。

ITC Infotech × Google Cloud：服务商先做「客户零号」，再复制实施蓝图

  • 来源：Google Cloud ｜ 原文链接
  • ITC Infotech 与 Google Cloud 7 月 23 日宣布，ITC Infotech 将在自身组织内端到端部署 Gemini Enterprise，先验证并规模化，再把经过内部实践的实施方法与技术蓝图交付给全球客户。
  • 双方将建立联合卓越中心，覆盖行业解决方案、Agent 与多 Agent 编排、数据现代化、安全治理、主权云及员工技能提升。
  • 交付模式：
    内部部署 → 业务验证 → 结果度量 → 资产沉淀 → 客户复制
    。这比直接拿厂商演示方案向客户销售更接近可持续的 FDE 产品化。
  • 为什么重要：服务商的可信度正在从「懂模型」转向「自己先跑通」。FDE 服务也应把内部工作流和现有项目做成客户零号：公开改造前基线、介入动作、结果数字和可复制资产。
  • 证据边界：公告尚未给出部署覆盖人数、首批工作流、节省时长、收入贡献或客户复制数量，目前只能确认组织与交付模式，不能宣称已经产生量化业务结果。

Cisco × AMD：本地 Agent 从单机工具变成可纳管的企业运行层

  • 来源：Cisco ｜ 原文链接
  • Cisco 7 月 23 日披露与 AMD 共建 Ryzen AI Halo 企业架构，把桌面本地推理和 Agent 从单机能力提升为可观测、可治理、可隔离的企业系统。
  • 四类控制：网络侧只开放必要访问；Tokenomics 区分本地与云端推理并核算成本；行为侧限制文件删除和工具调用等高风险动作；出现严重信任故障时，可通过网络把相关 Agent 或模型隔离。
  • 管理层可以查看单设备上各 Agent 的利用率、吞吐与能耗，并识别哪些云端工作适合迁到本地执行。
  • 为什么重要：企业 AI 的控制面将不只管理云端 API，还要管理散落在员工电脑上的本地模型与 Agent。FDE 需要交付统一资产清单、模型路由、成本归因、行为策略和隔离流程。
  • 证据边界：这是联合方案与架构说明，官方没有公布正式客户、部署规模或节省金额，暂不能宣称已在大型企业中验证。

对 FDE 从业者的启发

  • 把现有项目按「客户零号」方式重做案例：先记录改造前基线，再记录介入动作、业务结果与可复制资产。
  • 服务方案不只列功能，要同时列合同结果、交付资产和运行治理，方便进入企业采购与续约流程。
  • 为云端与本地 Agent 建统一资产清单：部署位置、责任人、数据范围、可执行动作、模型成本和隔离方式。
  • 高客单项目优先设计年度或阶段性协议，用可量化业务结果与持续治理替代一次性交付清单。
