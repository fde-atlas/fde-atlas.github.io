AI 编程之后，工程师如何走向 FDE？

AI 编程之后，工程师如何走向 FDE？

AI 编程工具正在把软件开发中的机械性工作大幅前移。它们不再只是补全下一行代码，而是可以读取代码库、生成文件、修改多个模块、补测试、整理文档，并在一定条件下调用编译器、测试运行器和扫描器。

这带来的变化，不是工程师不再需要技术，而是工程交付的瓶颈发生了迁移。代码实现越来越快以后，问题定义、系统上下文、任务编排和结果评估会变得更重要。FDE，Forward Deployed Engineer，正好提供了一个观察这种迁移的具体角色。

FDE 不是会写 Prompt 的工程师

FDE 的核心不是使用某个模型，而是把真实业务问题变成可以部署、验证和持续运行的系统。

一个企业提出“做一个 AI 客服”，并不等于工程任务已经清楚。工程师还要继续确认：服务面对什么类型的问题，数据来自哪里，哪些角色可以访问，哪些动作可以自动完成，哪些结果必须人工确认，错误时怎样回退，上线后用什么指标判断有效。

这部分工作决定了系统是否值得做，也决定了后续代码是否有明确边界。FDE 需要在业务目标和技术实现之间来回翻译，不是把需求原样转给模型。

从实现一个模块到交付一个可验证结果

传统开发中，工程师经常以函数、模块和 PR 作为阶段性交付物。Agent 参与后，单次实现的成本下降，交付物会逐渐变成一条完整任务链：目标定义、代码变更、测试、审查、部署和运行反馈。

这条链路至少需要四层工程设计。

第一层是上下文。Agent 要能找到相关代码、配置、依赖、接口和历史决策。只把需求复制到聊天框里，通常不足以支撑复杂变更。

第二层是工具。编译器、测试运行器、静态扫描器、日志和指标要能被调用和回读，Agent 才能基于结果修正，而不是凭语言流畅度判断成功。

第三层是边界。输入输出、权限、可修改范围和禁止动作要明确，重要约束尽量用脚本、类型或结构化测试固化。

第四层是反馈。失败原因不能只停留在一次对话里，要回写到文档、测试、工具接口或任务模板，成为下一次执行的上下文。

工程师需要补上的四项能力

1. 问题定义

把“做一个功能”继续拆成使用者、业务结果、输入输出、异常回退和验收标准。没有完成定义，Agent 只能不断生成看似合理的实现。

2. 环境设计

让代码库、项目文档、工具接口和质量规则对 Agent 可读。一个短而清晰的项目地图，通常比一份没有结构的长手册更有效。

3. Agent 编排

不要把多个聊天窗口误认为多 Agent 协作。真正的编排要给研究、实现、测试和审查任务设置清楚的输入输出，并让状态可以被追踪。

4. 评估与责任

Agent 可以做第一轮实现和审查，但工程师仍要理解变更影响，判断架构取舍、性能、安全、可维护性和业务结果。能运行不等于可以交付，测试通过也不等于系统已经解决问题。

一个最小的 Agent-first 交付流程

可以从一个窄场景开始：

  • 先写任务说明，包括目标、范围、依赖和完成定义。
  • 让 Agent 读取代码库并列出受影响的模块、风险和待确认问题。
  • 让 Agent 先写测试或验收样例，再完成第一轮实现。
  • 让测试、扫描和构建结果成为可回读的反馈。
  • 由工程师审查关键设计、权限边界和失败处理，决定是否合并。
  • 把本次错误和修复方式沉淀为项目知识或自动化规则。

这个流程的重点不是让 Agent 多写代码，而是让每次委派都有明确边界，让每次结果都能被验证。

不能把 FDE 简化成“只做判断”

FDE 也不是工程师马上转型成产品经理或项目协调者。面对新问题和复杂系统，工程师仍然必须理解代码，否则无法判断 Agent 的方案是否正确。

OpenAI 的工程实践把责任区分为 Delegate、Review 和 Own：机械工作可以委派，初步结果可以审查，但架构、产品意图和最终质量仍需要有人拥有。Anthropic 的 Agentic Coding 报告也强调，规模化采用要同时处理监督、质量和安全。

真正的变化是，工程师不必把全部时间耗在重复实现上，可以把更多注意力放在系统边界、长期维护和业务结果上。AI 编程会放大组织能力，流程混乱、测试薄弱的团队也可能因此更快地产生更多问题。

普通工程师怎么开始？

我过去做过后端、前端和大数据，后来负责技术管理、项目推进和客户培训，经历过从需求到研发、落地和维护的完整闭环。现在做 Agent、AI 编程和一人企业实践时，我越来越确认，真正能迁移的不是某个具体工具，而是跨层理解。

你可以先挑一个真实的小任务，写清楚它要改变什么结果，再让 Agent 完成第一轮实现。不要只保留代码，把任务说明、测试样例、错误记录和验收标准一起留下来。下一次遇到相似问题时，这些东西才会变成生产力。

FDE 不是工程师离开技术后的新身份，而是工程师把技术能力延伸到业务、系统和交付结果后的一个方向。
