摘要

本文是前沿部署工程系列第五篇，讲解 Agent 如何接入企业系统。作者以虚构客户 Acme Consumer Brands 为例，从 REST API 调用基础讲起，涵盖认证方式（API key、服务账号、代表用户的 OAuth）、Gemini Enterprise 连接器与数据存储的联邦和摄取两种模式、SAML/OIDC/SCIM 身份标准，以及 MCP 服务器为何正成为集成层。作者指出集成占 FDE 工作量最大，并给出 Databricks Genie 实战案例与第一周应向客户平台和安全团队提出的问题清单。

要点

  • 集成占 FDE 日程最多，每个系统 API、认证和故障方式各异。
  • 数据因人而异时应代表用户调用（OAuth），而非服务账号。
  • Gemini Enterprise 连接器分联邦与摄取两种，摄取默认每三小时增量同步。
  • SAML 与 OIDC 负责登录，SCIM 负责用户和组的自动同步。
  • MCP 让每个系统只封装一次，供所有 Agent 复用，正成为集成层。

一个 AI Agent 只有在能够访问工作所在的系统时才有用。本部分从零开始讲解集成：REST API 调用如何工作并进行身份验证、Gemini Enterprise 连接器和数据存储、SAML、OIDC 和 SCIM 等身份标准，以及 MCP 服务器为何正在成为集成层。

在第 4 部分中，我们让 Acme Consumer Brands 的文档具备了可检索性：解析、分块、索引并校验完毕。但文档只是 AI Agent 需要访问的系统之一。订单行数据在 Databricks 中，营销活动支出在 BigQuery 中，供货协议在 SharePoint 中，规格说明书在 Google Drive 中，供应商证书在 Box 中，而实时订单状态则来自 IT 部门通过 REST API 暴露的 ERP 系统。

每一个都是一项集成：两个系统之间的连接，使一方能够读取另一方或对其执行操作。根据我的经验，集成占用的 FDE 时间比构建的任何其他部分都多。每个系统都有自己的 API、自己的身份验证方式，以及在最糟糕时刻出错的独特方式。

在 Acme 我们要连接什么？

以下是第 3 部分的设计方案确定后，FDE 接手的系统全貌：

FDE 在 Acme 需要连接的系统：中间是 Gemini Enterprise，左侧是通过连接器访问的文档存储，右侧是通过 MCP 访问的数据平台和 REST API，最上方是身份提供商

在逐个介绍系统之前，先了解每项集成都会用到的几个术语：

  • API（应用程序编程接口）。一个程序向另一个程序请求数据或执行操作的规范化方式。
  • 端点。 API 中的一个地址，例如 /v2/orders。
  • 身份验证。 证明调用者是谁。授权是决定该调用者可以做什么。这是两个不同的检查，错误信息通常会告诉你哪一项失败了。
  • 连接器。 由平台提供的现成集成，你只需配置它，而无需编写代码。
  • 身份提供商（IdP）。 负责用户登录并知晓其所属组的系统。在 Acme，这是 Microsoft Entra ID。

REST API 调用是如何工作的？

大多数企业 API 遵循 REST 风格（表述性状态转移）：API 所知的每个事物（例如订单）都有一个 URL，你使用标准的 HTTP 方法对其进行操作。

GET

读取，

POST

创建，

PUT

或

PATCH

更新以及

DELETE

删除。数据以

JSON

（一种由键和值组成的纯文本格式）传输。

这是对 Acme ERP 的一次调用，包含四个关键部分：

对 Acme ERP 的 REST 调用的结构：带查询参数的方法和路径、Authorization 头中的 bearer 令牌、响应中的状态码，以及用于下一页结果 的页面令牌

出现问题时，响应中的状态码是首先要看的东西。我在项目中最常遇到的有：

  • 200 OK，以及 201 Created。
  • 400 Bad Request：你的请求格式有误。检查请求体和参数。
  • 401 Unauthorized：身份验证失败。令牌缺失、过期或面向错误的受众。
  • 403 Forbidden：你已通过身份验证，但该身份无权执行此操作。
  • 404 Not Found：路径错误，或对象不存在。有些 API 也会返回 404 以隐藏你不应看到的对象。
  • 429 Too Many Requests：你触发了速率限制（每段时间内的调用次数上限）。等待（最好是 Retry-After 头中指定的时间），然后重试。
  • 5xx：服务器出错。使用指数退避进行重试（每次失败后等待更长时间），并且只重试可以安全重复的调用。

还有两个概念能省去很多麻烦。分页意味着大量结果会一页一页地返回，所以你的代码必须跟随页面令牌直到取完；只读取第一页的 Agent 会给出自信却不完整的答案。幂等性意味着一个调用可以重复执行而不会重复完成工作。读取天然是幂等的；对于写入，许多 API 接受幂等键，这样重试就不会创建第二个订单。

程序如何证明自己的身份？

有三种常见方式，从最简单到最适合 Agent 的方式：

  • API 密钥。 每次调用都附带的长密钥字符串。简单，但它标识的是应用程序而非个人，且难以安全轮换。任何敏感场景都应避免使用。
  • 服务账号或 OAuth 2.0 客户端凭据授权。应用程序为自己获取一个短期的访问令牌。每次调用都使用应用程序自身的权限。
  • 代表用户进行 OAuth 2.0 授权。用户登录一次并同意授权，应用程序获得一个代表该用户的令牌。源系统随后会应用该用户自身的权限。

这两种情况下的令牌通常是持有者令牌（bearer token）：谁持有它，谁就能进入系统，这就是为什么令牌绝不能出现在日志或提示词中。后两种选项之间的区别是 Agent 项目中最重要的集成决策：

程序调用 API 的两种方式：以自身身份使用服务账号令牌，可以看到该账号能看到的一切；或代表已登录用户使用该用户的令牌，只能看到该用户能看到的内容

如果数据因人而异——在企业中几乎总是如此——就应以用户身份调用。Agent 系列中的 Agent 身份一文逐步构建了这一流程，包括如何让令牌远离模型。

什么是 Gemini Enterprise 中的连接器和数据存储？

从零开始为 SharePoint、Box 和 Google Drive 编写集成需要数周时间。Gemini Enterprise 以连接器的形式提供它们。在其文档中，数据存储和连接器指的是同一件事：指向一个源的已配置链接。每个源都有实体（例如 Jira 有问题、附件、评论和工作日志），Gemini Enterprise 会为每个实体创建一个单独的数据存储。

截至 2026 年 10 月，已正式发布的连接器包括 Box、Confluence、Dropbox、GitHub、Google Drive、Jira、Microsoft OneDrive、Outlook、SharePoint、Teams、ServiceNow 和 Slack 等。更长的列表（包括自定义 MCP 服务器连接器）处于公开预览阶段。

每个连接器通过以下两种方式之一访问其数据，有些则两种方式都支持：

Gemini Enterprise 连接器访问数据的两种方式：联合（federation）将每个问题实时发送到源系统，而摄取（ingestion）则按同步计划将内容及其权限复制到 Gemini Enterprise 索引中

  • 数据联合。Gemini Enterprise 在提问时将查询发送到源系统。不复制任何内容，因此无需管理存储或同步，但搜索质量可能较低。文档还警告说，查询文本（可能包含对话的部分内容）会被发送到第三方系统。
  • 数据摄取（索引）。内容按计划复制到 Gemini Enterprise 索引中。搜索质量得到提升，代价是存储开销以及源变更到其出现在答案中之间的延迟。

数据摄取通过同步运行。全量同步会捕获所有内容，包括删除操作。增量同步默认每三小时运行一次，仅捕获自上次运行以来的新增和更新内容，不会捕获删除操作或身份数据。身份数据（用户和群组）有自己独立的调度计划，从每 30 分钟到每 7 天不等。当用户说“我昨天已经删除了那个文件，但 Agent 还在引用它”时，同步调度计划是我首先检查的东西。

连接器还可以提供操作（即会改变某些状态的操作，例如创建工单），在 Gemini Enterprise 中，MCP 术语 tools 与操作（actions）是同一个意思。

身份提供商是如何融入其中的？

SharePoint 中的每个文档都有一个访问控制列表（ACL），即允许打开该文档的用户和群组列表。这些条目引用的是 Entra ID 中的身份。要让 Gemini Enterprise 遵循这些权限，它必须知道是哪个 Entra ID 用户在提问，以及该用户属于哪些群组。三个开放标准使这成为可能：

FDE 在每个企业中都会遇到的三个身份标准：SAML 2.0 和 OpenID Connect 负责用户登录，SCIM 则负责在系统之间保持用户和群组列表的同步

  • SAML 2.0（安全断言标记语言）。身份提供商签署一份 XML 文档，即断言，声明该用户是谁，然后浏览器将其传送给应用程序。这是大多数较老的企业应用实现单点登录（SSO）的方式，即登录一次即可访问多个应用程序。
  • OpenID Connect（OIDC）。 构建在 OAuth 2.0 之上的身份层。身份提供商签发一个描述用户的、经过签名的 JSON ID 令牌。对于较新的 Web 和移动应用程序，它的作用与 SAML 相同。
  • SCIM 2.0（跨域身份管理系统）。一个用于配置管理的 REST API：当用户和群组发生变化时，身份提供商将其推送到其他系统，这样员工离职后无需任何人提交工单，其访问权限就会在所有地方被撤销。

对于 Gemini Enterprise，文档建议新环境使用 Google Identity，而且 Google Workspace 数据源必须使用 Google Identity。支持 OIDC 或 SAML 2.0 的第三方身份提供商（如 Entra ID、Okta 或 AD FS）也可以使用。有一个例外影响了 Acme 的设计：使用数据摄取的 Microsoft 365 数据源（如 SharePoint、OneDrive 和 Outlook）要求使用带有 Workforce Identity Federation（员工身份联合）的 Microsoft Entra ID（这是 Google Cloud 提供的一种方式，让用户无需 Google 账户即可使用外部身份提供商登录）。Workforce Identity Federation 的 SCIM 配置仅适用于 Gemini Enterprise 和 Looker（Looker 处于预览阶段），并且文档指出 SCIM 是基于推送的：如果身份提供商的连接悄然中断，群组数据可能会变得过时。

身份配置就绪后，权限检查会在每次提问时进行：

权限如何延续到答案中：规划者通过身份提供商登录，Gemini Enterprise 知道她所在的群组，搜索索引，剔除她的群组无权阅读的文档，并仅根据她被允许查看的内容来回答

对于 Google Workspace 来源，文档明确阐述了这一原则：用户只能查看并基于他们在来源中已有权访问的信息来生成回答。只有当身份配置正确时，这一特性才成立。

为什么 MCP 服务器正在成为集成层？

连接器覆盖流行的产品，但无法覆盖 Acme 的 ERP、供应商门户或一套有二十年历史的仓储系统。对于这些系统，你编写的集成应该能被每个 Agent 复用，而不是埋在某个 Agent 内部。这正是 Model Context Protocol（MCP） 所提供的。

MCP 是一个用于将 AI 应用连接到工具和数据的开放协议。其规范描述了三种角色：主机（用户使用的应用程序，例如 Gemini Enterprise）、客户端（主机内部的连接器）和服务器（暴露能力的服务）。服务器提供工具（模型可以请求执行的操作）、资源（可读取的数据）和提示（模板）。消息使用 JSON-RPC 2.0，远程服务器使用 Streamable HTTP 传输方式。最新版规范的日期为 2026 年 7 月 28 日，其授权部分将受保护的 MCP 服务器定义为 OAuth 2.1 资源服务器，必须发布 Protected Resource Metadata（RFC 9728），以便客户端能够发现从何处获取令牌。

为什么 MCP 有帮助：没有共享协议时，每个 Agent 都需要为每个系统编写定制代码，三个 Agent 和四个系统就需要十二个集成；有了 MCP，每个系统只需封装一次作为服务器，每个 Agent 只需实现一次 MCP，总共七部分

没有共享协议时，每个 Agent 都需要为每个系统编写定制代码。有了 MCP，每个系统只需封装一次作为服务器，任何支持 MCP 的主机都可以使用它：Gemini Enterprise、ADK Agent 或开发者的 IDE。

Gemini Enterprise 可以将你自己的服务器注册为 Custom MCP Server 数据存储（截至 2026 年 10 月处于公开预览阶段）。文档列出了在实际应用中至关重要的规则：

  • 仅支持 Streamable HTTP 传输方式；不支持较旧的服务器发送事件（SSE）传输方式。
  • 公共和私有服务器都需要由公开受信任的证书颁发机构颁发的 TLS 证书。自签名证书会被拒绝。
  • 每个数据存储的已启用操作数保持在 100 个或更少。
  • 对于按用户访问，请使用文档中提供的重定向 URL，将 Gemini Enterprise 注册为你的身份提供商的 OAuth 客户端。对于 Cloud Run 上的服务器，Gemini Enterprise 会发送 Google 签名的 ID 令牌进行 IAM 身份验证。

一个真实的集成从端到端来看是什么样的？

我关于将 Gemini Enterprise 接入 Databricks Genie的文章是本部分所有内容的一个完整实例。简而言之：

  • 身份优先。 每个查询都通过 OAuth 代理流程，以提问用户的身份在 Databricks 中运行，因此 Unity Catalog 会应用与在笔记本中相同的权限。
  • 四种连接方式，一个后端。 调用 Databricks REST API 的 Cloud Run 网关、调用 Databricks 托管 MCP 服务器的同一网关、直接在 Gemini Enterprise 中注册的托管 MCP 服务器，或者作为前门的 A2A Agent。这四种方式都访问同一套受治理的数据。
  • 协议的选择关乎前门。 MCP 将 Agent 连接到工具；A2A 将 Agent 相互连接。在所有方案中，Databricks 一侧都保持使用 MCP 或 REST。
  • 遇到的坑都是集成方面的坑。 Genie 是异步返回答案的，所以调用方必须轮询。机密 OAuth 客户端不能同时使用 PKCE 和客户端密钥。已停止的 SQL 仓库会让第一个问题面临冷启动延迟。

将 Gemini Enterprise 连接到 Databricks Genie 的四种方式，来自实际案例：调用 REST 的网关、调用托管 MCP 的网关、直接注册的托管 MCP，或作为前门的 A2A Agent；这四种方式都以提问用户的身份访问同一套受治理的数据

Genie 那篇文章解释了何时选择哪种方案，以及每种方案的运行成本。

第一周我应该问些什么？

在第一次集成研讨会之前，我会把这份清单发给客户的平台团队和安全团队。每一个没有答案的问题都是方案的风险。

INTEGRATION QUESTIONNAIRE: one copy per system

System and owner
  - Name, version, hosting (SaaS, cloud, on premises)
  - Business owner and technical owner (names, not teams)

Access
  - API type (REST, GraphQL, SOAP, database, files) and documentation link
  - Is there a Gemini Enterprise connector or a vendor MCP server already?
  - Federation, ingestion, or both? Sync frequency the business accepts

Identity
  - Identity provider for this system (Entra ID, Okta, Google, other)
  - Call as the user (OAuth) or as a service identity? Why?
  - Which scopes or roles are needed? Who approves them, and how long does it take?
  - Are permissions set per document or row? Are they in the identity provider's groups?

Limits and failure
  - Rate limits, page sizes, payload limits, maintenance windows
  - Test environment with realistic data? Test users in each permission group?

Network and compliance
  - Public endpoint, private connectivity, or allowlisted IPs only?
  - Data residency, retention, and what may leave the system in a query

试一试

这是一个封装了 Acme ERP 订单 API 模拟版本的小型 MCP 服务器。它需要 Python 3.11 或更高版本，以及官方 MCP Python SDK（

pip install "mcp[cli]"

）。将其保存为

server.py

:

"""A tiny MCP server that wraps Acme's (fake) ERP orders API."""
from mcp.server import MCPServer

mcp = MCPServer("acme-erp")

# Stand-in for the real REST call. In production this function would call
# GET /v2/orders with the user's token and follow next_page_token.
FAKE_ORDERS = [
    {"id": "SO-88412", "retailer": "northmart", "otif": False, "value": 41200},
    {"id": "SO-88413", "retailer": "northmart", "otif": True, "value": 18950},
    {"id": "SO-88501", "retailer": "freshway", "otif": False, "value": 7300},
]

@mcp.tool()
def late_orders(retailer: str, limit: int = 20) -> list[dict]:
    """List orders for one retailer that were not delivered on time and in full.

    Use this for questions about late or short deliveries. Read-only.
    retailer: lower-case retailer code, for example "northmart".
    """
    rows = [o for o in FAKE_ORDERS if o["retailer"] == retailer and not o["otif"]]
    return rows[: max(1, min(limit, 100))]

使用 Streamable HTTP 运行它：

mcp run server.py --transport streamable-http

，然后在第二个终端调用它：

import asyncio

from mcp import Client

async def main() -> None:
    async with Client("http://localhost:8000/mcp") as client:
        tools = await client.list_tools()
        print([t.name for t in tools.tools])
        result = await client.call_tool("late_orders", {"retailer": "northmart"})
        print(result.structured_content)

asyncio.run(main())

你应该会看到工具名称和一条 Northmart 的迟到订单。然后尝试三件事：

  • 注意类型提示和文档字符串变成了工具的 schema 和描述。描述就是工具与模型之间的契约，与 agents 系列中的你的第一个 Agent：单一任务，狭窄工具完全一致。
  • 用 "limit": 5000 调用它。服务器会将其限制在 100。限制应该放在服务器里，而不是提示词里。
  • 为某家零售商的准时率添加第二个工具。然后问问自己，服务器如何知道是哪个用户在调用——这正是 OAuth 在投入生产之前要解决的问题。

可能出什么问题

  • 默认使用服务账号进行集成。 第一周这样更快，第六周就会成为安全发现。逐个系统做出决定，并把决定写下来。
  • 忽略分页和速率限制。 Agent 只根据第一页数据回答问题，或者一个繁忙的早晨产生一连串 429 错误。用生产规模的数据进行测试。
  • 忘记同步延迟。 用户期望昨天的更改出现在今天的答案中。与业务方商定同步计划，并在引用中显示文档日期。
  • 假设群组都在身份提供商中。 有些系统保留自己的本地群组。如果 ACL 引用了身份提供商不知道的群组，要么没人能看到文档，要么所有人都能看到。
  • 构建已经存在的连接器。 在编写代码之前，先查看 Gemini Enterprise 连接器列表和供应商自己的 MCP 服务器。
  • 把预览版当作生产版。 自定义 MCP 服务器数据存储仍处于预览阶段。锁定配置，告知客户，并保留备用方案。

我现在会怎么做

  • 为你的项目绘制系统架构图，每个系统一个方框，并用集成模式标注每一条连线。
  • 在第一周向每个系统负责人发送集成问卷。
  • 凡是已有托管连接器的地方就使用托管连接器，并针对每个数据源决定采用联合查询还是数据摄取。
  • 在编写代码之前先确定身份问题：身份提供商、代表用户身份还是服务身份，以及由谁审批权限范围。
  • 对于没有连接器的系统，先将其封装为一个带有窄范围、只读工具的小型 MCP 服务器。

我们学到了什么？

  • 集成是一种让一个系统读取或操作另一个系统的连接，每个集成都带有自己的 API、身份验证和各自的失败方式。
  • REST 调用的状态码是出现故障时首先要查看的内容，而分页和幂等性可以防止答案不完整和重复写入。
  • 如果数据因人而异，Agent 应该代表已登录用户调用源系统，而不是以服务账号的身份调用。
  • Gemini Enterprise 连接器通过联合查询或数据摄取来获取数据，而数据摄取在内容和身份数据两方面都依赖于同步计划。
  • SAML 2.0 和 OpenID Connect 负责用户登录，SCIM 保持用户和群组同步，只有这些设置正确，权限才能在答案中生效。
  • MCP 让每个系统只需封装一次，成为任何支持 MCP 的宿主都能使用的服务器，这正是它正在成为集成层的原因。
