FDE是什么？面向初学者解说工作内容、年薪、所需技能以及与SES的区别

摘要

这篇面向初学者的日文文章介绍了FDE（前沿部署工程师）的定义、工作内容、所需技能与年收情况。FDE驻扎在客户现场，负责从需求梳理、原型开发到导入与持续改善的全流程，目标是让自研平台和AI/LLM真正在业务中产生价值。文章还比较了FDE与SES、SIer、解决方案架构师及普通Web工程师的区别，并以OpenAI和LayerX的招聘为例说明该职位需求正在快速上升。

要点

  • FDE驻客户现场，负责需求梳理、设计、实现、导入到改善的全流程。
  • 生成AI从试点转向实际落地，使能将LLM融入现场业务的FDE受到关注。
  • 所需技能包括Python/SQL等编程基础、业务理解力、沟通力与持续学习能力。
  • 与SES按指示开发不同，FDE主动发现问题并反馈至自研产品。
  • 年收因企业、地点、英语能力和LLM经验差异较大，需细看招聘条件。

什么是FDE？

FDE是Forward Deployed Engineer的缩写，大体上属于工程师职业类别。

首先为大家解说FDE是一份怎样的工作、它与一般工程师的区别，以及近年来备受关注的背景。

对FDE这份工作感兴趣的朋友，或将其作为跳槽目标职位及未来职业发展方向的朋友，请务必参考本文。

FDE是工程师职业的一种

“Forward Deployed”原本是军事用语，意为“前线部署”。

在此基础上，FDE（Forward Deployed Engineer）被译为“前沿部署工程师”。

顾名思义，FDE的主要工作是在“客户现场”这一最前线常驻一定时间，从自家平台的导入到落地应用提供一站式支持。

FDE这一职位的定位，不是在自家开发团队里专心做实现，而是被部署在客户所在的现场这一“最前线”。

与传统工程师的区别

传统工程师的主要工作是在公司内部构思功能、进行实现并构建系统。

而FDE则是识别客户课题，并为此进行设计、实现和运营改善。由此，让自家产品在现场得到最优应用正是FDE的职责。

FDE的工作不仅限于开发。为了提供更大的价值，FDE还要利用客户的潜在课题和一手数据等，承担运营机制搭建和咨询等工作。

与传统工程师相比，FDE的特点是与客户距离更近，现场主导的属性更强。

为什么FDE备受关注

为什么现在FDE备受关注？最大的原因在于，近年来各企业正从“导入并试用”生成AI和LLM等技术，转向“活用并在实际业务中取得成果”的阶段。

LLM本身的技术非常通用化。因此，它并不适配特定企业现场特有的业务内容和工作流程。

于是，在理解现场课题的基础上，将LLM融入现有系统和自有数据平台并进行优化的FDE角色便备受关注。

再优秀的AI模型，如果无法在现场被用好，也没有意义。FDE正是承担着从技术和商业两个层面消除这类瓶颈的角色。

FDE的主要工作内容

关于FDE的概况和备受关注的背景如前所述。

那么，FDE具体有哪些工作呢？

FDE的工作通常遵循需求梳理→设计→实现→导入→改善的流程。

下面按照这一流程解说FDE的工作内容。

理解客户课题与需求梳理

首先要在理解客户课题的基础上梳理需求。

对FDE而言，理解课题绝不仅仅是听取规格说明。这是深入客户业务现场、定义真正需要解决的问题的重要过程。

当然，客户并不是能熟练运用AI的IT技术专家。大多数情况下，客户虽然抱有“想用AI来改善”这种模糊的需求，但需要解决的课题并不明确。

因此，FDE要在现场观察日常业务流程和负责人感到困扰的作业等，找出问题和瓶颈潜藏之处。在此基础上，将需求转化为技术上可行且能发挥价值的形式，这就是FDE的需求梳理。

原型开发与正式导入

FDE的工作中，不会一开始就进行大规模开发。

首先要根据需求，以短周期开发原型。让现场用户试用，根据反馈立即改善。

通过这样的反复迭代，在推进敏捷开发的同时不断改善和培育系统，这就是FDE的工作。

此外，正式导入也不是把系统交付出去就结束了。还要进行调整，确保与现场的核心系统顺利实现数据对接，并正确融入业务流程。

利用AI、LLM改善业务

FDE承担着利用OpenAI等AI平台或自家产品改善业务的工作。

不过，并非只要导入就万事大吉。还需要将企业的核心数据与LLM高度融合，实现文本处理、检索和自动化等。

首先要用LLM将客户公司内分散的海量文档、邮件、日志等数据结构化。然后运用RAG（检索增强生成）等技术，将原本需要专门知识的业务实现自动化和高级化。

做到这一点后，就可以实现诸如让AI学习熟练工匠的经验知识以辅助新人的判断、让LLM提出复杂供应链的优化方案等业务改善。

导入后的改善与产品反馈

再强调一次，FDE的工作并不是交付系统就结束了。此后，还要将现场实际运营中获得的经验加以运用，这也是FDE的工作。

导入后，FDE会分析现场用户的行为和数据变化，评估诸如“AI的建议是否被采纳”“业务速度是否提升”等。

通过及时改善在此发现的新需求以及与实际运营之间的摩擦等，不断提升精度。

此外，这些在现场获得的经验需要带回公司反馈给开发团队。由此推动自家产品的改进和进化，也可以说是FDE的重要工作。

FDE所需的技能与适合人群的特征

如前所述，FDE的具体工作内容多种多样。

那么，FDE的工作需要哪些技能？什么样的人适合做FDE呢？

既然是工程师，当然必须具备一定的编程能力。此外，还需要理解客户业务、发现课题的能力等。

下面解说FDE所需的技能与适合人群的特征。

编程与系统设计的基础

既然承担系统设计与实现，当然需要具备一定的编程能力。

此外，不仅需要编写代码的能力，还需要将数据与业务连接起来的系统设计能力。

尤其是高效处理海量数据、并在平台上将其转化为有价值形态的技能（主要是 Python 和 SQL 知识）是必不可少的。

此外，如果还具备 Web 应用、API、数据库、云等相关知识，就更容易将客户的课题落实到实现中。

正确理解业务与课题的能力

对 FDE 而言，“正确理解业务与课题的能力”是与技术能力同等重要的技能。

仅仅照单全收客户的话，是无法完成充分的需求定义的。所需的是深入到专业术语满天飞的一线现场，在复杂的业务流程中识别出隐藏的真实课题的洞察力。

因此，可以说不仅喜欢技术、还对客户的业务和组织机制抱有强烈兴趣的人更适合这一职位。

沟通能力

这里所说的沟通能力，并不是指能和任何人轻松交谈、打成一片的技能。

在 FDE 的工作中，与工程师以外的负责人交谈的场景并不少见。此时需要倾听一线的工作流程和课题感受，反过来还需要对所提供的系统进行讲解。

因此，FDE 需要用商业语言说明技术上的限制，反过来又能将一线的课题转化为系统需求的能力。

应对变化的学习态度

FDE 的工作需要生成式 AI 和 LLM 等技术革新极为激烈的领域的知识。因此，已掌握的知识无法反复套用，需要保持不断收集信息、持续学习的态度。

此外，不仅要追踪新信息，还需要具备快速理解每个客户所处行业的运行规律和数据结构的学习速度。

在“昨天的正确答案今天可能就不再适用”的环境中，能够持续吸收最新知识的人，可以说很适合担任 FDE。

FDE 与相关职位的区别

在 FDE 的周边领域，存在各种相关职位。

为了加深对 FDE 的理解，下面将对比 FDE 与 SES、SIer、解决方案架构师以及普通 Web 工程师之间的区别进行讲解。

对于“FDE 的工作内容我已经了解了，但它和这些职位有什么不同？”抱有疑问的人，请务必参考。

FDE 与 SES 的区别

FDE 和 SES 都经常在靠近客户的地方工作，因此容易被混淆。

SES 通常是以提供劳动力为目的的准委托合同，按照客户的指示进行开发和维护。

而 FDE 的目的则是如前所述，通过业务运用本公司产品和 AI，实现客户课题的解决和产品的改进。

此外，SES 往往处于被纳入客户体制的被动立场。

而 FDE 则会主动从一线数据中识别课题，并一直跟进到对产品的反馈，这是两者的不同之处。

FDE 与 SIer 的区别

SIer 的主要业务是根据客户要求从零开始构建系统的受托开发。多数情况下目标就是系统的完成和交付，重点在于个性化定制。

而 FDE 的工作则专注于如何让本公司的平台适应一线现场并创造价值。

此外，SIer 重视按照规格书进行实现，而 FDE 则是与一线数据对话、主动识别课题，并承担起推动产品成长的反馈工作，这是两者的不同。

FDE 与解决方案架构师的区别

解决方案架构师（SA）的主要职责是将客户的业务需求与云或技术栈衔接起来，绘制最优的设计图（架构）。

他们确保技术上的可行性并指出构建方针，但很少陪伴到实际运营阶段。

相对地，FDE 则对让所绘制的设计图在现实中发挥作用的部署负责。他们始终直面一线现场，反复进行实现、导入和改进，直到本公司的平台深深融入客户的业务之中。

可以说，SA 负责提出并设计最优方案，而 FDE 则负责在现场持续推动直到产生价值。

FDE 与普通 Web 工程师的区别

Web 工程师的客户主要是不特定的广大消费者。因此，其业务中重视的是应对高流量的可扩展性以及 UI/UX 的舒适性等。

而 FDE 则深入特定企业。所处理的是复杂的企业内部数据，而非公开数据。

此外，FDE 不仅仅是进行功能开发，还重视“如何改变一线的决策”，这也是与普通 Web 工程师的不同之处。

FDE 的招聘、录用与职业发展

接下来讲解查看 FDE 招聘信息时的要点。

虽然统称为 FDE，但其核心业务和年薪水平因企业而异。

在查阅招聘信息时，除了明确自己重视的条件之外，还应把握好需要关注的要点。

从 OpenAI 和 LayerX 看 FDE 招聘

实际上，OpenAI 和 LayerX 等企业正在招聘 FDE。

两家公司的共同点是将 FDE 定义为不仅仅是导入支持，而是深入客户、致力于解决课题的工作。

在这类推动 AI 导入的企业中，可以说对 FDE 的需求正在迅速增长。

招聘启事中应关注的业务内容

在查看 FDE 的招聘信息时，可以根据所记载的内容判断该职位更偏向实现还是提案。

例如，如果内容是“构建数据管道”“SDK/API 集成”“基于需求进行原型开发”等，则更重视实务性的技术能力。

反之，如果内容以“业务流程重构”“ROI（投资回报率）的定义”“与利益相关方达成共识”等为中心，则要求的是偏咨询方向的业务。

建议根据您是想将自身技能作为创造工具的能力来发挥，还是作为改变组织的能力来发挥来选择职位。

调查年薪时的注意事项

FDE 的年薪由于是特定技术与商业技能的结合，会因个人条件不同而产生较大波动。

尤其在外资 AI 企业中，英语能力是必备条件，年薪水平往往大幅提升。

此外，工作地点（国内还是全球）以及是否具备 LLM 或 AI 的实现经验等，也是直接影响年薪数额的条件。

因此，在调查 FDE 职位的年薪时，不能仅凭工程师的一般行情来判断，而需要仔细确认招聘信息中记载的条件。

关于 FDE 的常见问题（Q&A）

Q. FDE 的工作需要编程能力吗？

A. 需要。FDE 的工作中，不仅要听取客户需求，还经常需要实际制作原型或系统。因此，能够进行基础开发的编程能力是必备条件。

Q. 没有相关经验也能以 FDE 为目标吗？

A. 完全没有开发经验的人要成为 FDE 比较困难。比较现实的路径是先成为一般的工程师，积累编程、Web 应用开发、数据库等方面的知识和经验，然后再以 FDE 为目标。

Q. FDE 需要英语能力吗？

A. 因企业而异。在需要与外资企业或海外团队协作的企业中，要求英语能力的职位并不少见。不过如果客户以国内企业为主，有时并不特别要求英语能力。

Q. FDE 的工作内容因企业而异吗？

A. FDE 所承担工作内容的侧重点因企业而异。有的企业以实现为主，有的企业则更侧重客户沟通和导入支持。建议仔细查看招聘信息，确认实现范围和客户应对的内容。

Q. FDE 可以远程办公吗？

A. 因企业和项目而异。FDE 的工作还包括与客户的会议和导入支持。有的以线上为主，有的则需要面对面应对。建议仔细查看招聘信息，确认工作内容和劳动环境。

总结

本文讲解了对 FDE 的工作内容、所需技能，以及与 SES 等相关职种的区别。

  • FDE 是识别客户课题，并进行设计、实现和运营改善的工作
  • 不仅需要编程能力，还需要正确理解客户业务和课题的能力
  • 与 SES 不同，FDE 会主动识别课题并跟进到反馈环节
  • 年薪因企业、工作地点、经验、英语能力等因素而异

想从零开始自学以 FDE 为目标的朋友，建议先从基础知识的输入开始，然后逐步动手实践，掌握编程技能。
