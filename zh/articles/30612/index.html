面向 FDE 的数据工程：数据生命周期的 5 个阶段

原标题：Data Engineering for FDEs: The 5-Stage Data Lifecycle

FDE Times · 2026-10-08 · 约 7 分钟读完

摘要

文章面向前沿部署工程师讲解数据工程基础：当 AI Agent 给出错误答案时，问题可能出在数据而非提示词。作者借鉴《Fundamentals of Data Engineering》的五阶段数据生命周期（生成、摄取、存储、转换、服务），以越南岘港分公司“九月无迟到订单”的错误报告为例，演示如何从服务层反向追查到生成层，用三条 SQL 查询在一小时内定位分支代码不匹配和未送达订单漏算两处故障。文章强调 FDE 无需像数据工程师那样构建基础设施，但须熟练读写 SQL、能读懂他人管道，并给出到场第一周的行动清单与常见错误。

要点

  • Agent 答错可能是数据故障，而非提示词或模型问题。
  • 数据生命周期分五阶段：生成、摄取、存储、转换、服务。
  • 案例用三条 SQL 查询反向追查，定位两处数据故障。
  • FDE 不必建基础设施，但须熟练读写 SQL、读懂他人管道。
  • 到场首周应映射五阶段、记录各阶段负责人并备好 SQL 检查。

追踪数据经过从生成到服务的五个阶段，是 FDE 所需的数据工程能力——还不到成为数据工程师的程度。

简要概述

  • 数据经过五个阶段：生成、存储、摄取、转换和服务。故障可能出现在其中任何一个阶段。
  • FDE 不需要像数据工程师那样构建数据基础设施，但必须能够读懂数据管道并熟练编写 SQL。
  • 根据 FDE Academy 的说法，FDE 与数据工程师有两个不同之处：他们直接与客户合作，并且需要处理更广泛的系统。

想象一下你在客户现场的第二周，这是一家物流配送公司。你构建的 AI Agent 说岘港分公司九月没有延迟订单。运营经理看着屏幕，立刻说这是错的：上周他们还收到了关于延迟交付的投诉。

许多工程师首先会去修改提示词或换一个模型。但这个数字可能在模型看到它之前就已经错了。它经过了一系列系统，链条中的任何阶段都可能丢失数据。

你需要做的是沿着这条链条往回追踪。这项技能不会让你成为数据工程师，但它决定了你是站在客户面前猜测，还是能说“故障在这里，今天就能修复”。

什么是数据工程，以及 FDE 的定位

IBM 将数据工程定义为设计和构建大规模收集、存储和分析数据的系统。按照 IBM 的描述，数据工程师是构建和运行组织数据基础设施的软件工程师。

FDE Academy 将数据工程视为 FDE 工作的核心，但指出了一个关键区别：数据工程师通常在内部工作，而 FDE 直接与客户合作。它还指出，数据工程师的调试思维可以延续下来，但他们需要了解的系统范围必须扩大。

在实践中，数据工程师深入了解某一个技术栈，通常是自己团队构建的。而 FDE 在每个客户那里遇到的都是不同的技术栈，由别人构建，并且必须足够快地理解它，以免拖慢部署进度。

五个阶段，每个阶段一个问题

根据 Johnny Winter 对《Fundamentals of Data Engineering》的评述，这本书将数据生命周期分为五个阶段：生成、存储、摄取、转换和服务。这五个阶段也是你追踪故障的地图。

存储是其他所有阶段的基础，因此下表没有按照书中的顺序排列，而是按照调试时数据实际经过的路径排列：生成、摄取、存储、转换、服务。

生成发生在源系统中：ERP、移动应用、仓库软件。这是 FDE 首次接触客户数据的地方，而且这些系统几乎总是由别人负责。

正如 IBM 所描述的，数据摄取（Ingestion）将来自多个来源的数据汇集到一个共享环境中。ETL 管道自动完成数据的提取、格式标准化，并将其加载到数据库中。

存储是写入、组织和保护数据的硬件与软件。IBM 列出了三种类型：文件、块和对象。转换高度依赖 SQL。服务是数据到达用户的环节：仪表板、API，或你的 AI Agent。

阶段FDE 应在现场提出的问题
生成哪个系统创建这些数据？谁负责它？最近有什么变动吗？
摄取数据如何到达？频率如何？上一次运行成功了吗？
存储数据存放在哪里：数据库表、导出的文件还是对象存储？
转换哪个 SQL 查询或作业将原始数据变成屏幕上的数字？
服务用户或 AI Agent 从哪个表、视图或 API 读取数据？

追踪“无迟到订单”这一数字

回到岘港分公司的例子。你从最后一个环节——服务开始排查：AI Agent 从一个名为

late_orders_by_branch

的视图中读取数据。打开视图定义，你会看到它将

orders

与

branches

按

branch_code

进行连接，然后筛选出满足

delivered_at > promised_at

.

两个嫌疑点立刻浮现。第一，连接操作会丢弃分支代码没有匹配项的订单。第二，尚未交付的订单其

delivered_at

为空值，与空值进行比较会将它们从结果中剔除，尽管它们恰恰是最新的订单。

第一个检查针对嫌疑点一。（列别名是越南语：

so_don

是订单总数，

so_don_khop_chi_nhanh

是匹配到分支的订单数。）

SELECT o.branch_code,
       COUNT(*)              AS so_don,
       COUNT(b.branch_code)  AS so_don_khop_chi_nhanh
FROM orders o
LEFT JOIN branches b ON o.branch_code = b.branch_code
WHERE o.created_at >= '2026-09-01'
GROUP BY o.branch_code
ORDER BY so_don DESC;

假设结果显示一个陌生的代码，有几百个订单，而匹配列的值为零。这表明源系统更改了分支代码的写法，而

branches

表中仍保留着旧代码。问题不在 AI Agent，也不在视图的 SQL，而是出在生成阶段。

在下结论之前，先按加载日期统计行数来排除摄取环节的问题，确保昨晚的导出作业确实运行了（假设该表有一个

loaded_at

列；

ngay_nap

是加载日期，

so_dong

是行数）：

SELECT CAST(loaded_at AS DATE) AS ngay_nap,
       COUNT(*)                AS so_dong
FROM orders
GROUP BY CAST(loaded_at AS DATE)
ORDER BY ngay_nap DESC;

第三个查询处理剩下的嫌疑点。已超过截止日期但尚未交付的订单也必须算作迟到，因此该查询将

promised_at

与当前时间进行比较（

so_don_tre

是迟到订单数）。

SELECT o.branch_code,
       COUNT(*) AS so_don_tre
FROM orders o
WHERE o.created_at >= '2026-09-01'
  AND (
        o.delivered_at > o.promised_at
     OR (o.delivered_at IS NULL AND o.promised_at < CURRENT_TIMESTAMP)
  )
GROUP BY o.branch_code
ORDER BY so_don_tre DESC;

如果该查询得出的岘港数字明显高于视图中的数字，你就发现了第二个问题，这次出在转换环节。三条 SQL 查询和不到一小时的时间，就能给运营经理一个具体的答案，外加负责 ERP 的 IT 团队中应该联系的人员姓名。

排查到多深才算够深？

Simplilearn 将 SQL 称为数据工程师的基础技能。对 FDE 来说它更为重要，因为它是阅读任何客户转换逻辑的通用语言。你需要熟练编写 JOIN、GROUP BY 和窗口函数，并能读懂别人写的上百行的视图。

你不需要在构建和运行基础设施方面有深度：比如调优集群或设计企业级数据仓库。那属于客户的数据工程师。你的工作是用他们的术语与他们沟通，并准确指出问题出在哪里。

该书还列出了贯穿整个生命周期的六个“潜流”：安全、数据管理、DataOps、数据架构、编排和软件工程。把它们当作范围界定清单：谁可以查看这些数据，哪个作业编排管道，失败时通知谁。

到达现场后该做什么

在第一周，为你的用例所依赖的特定数据流（而不是整个公司）绘制五个阶段。在每个阶段旁边写上负责人的名字。在客户现场，知道该问谁和知道该问什么同样重要。

接下来，首先申请转换和服务阶段的读取权限，因为那是你能最快验证问题的地方。提前准备一组 SQL 检查：按加载日期统计行数、键不匹配的记录数、关键列中空值的数量。每当数据看起来异常时就运行它们。

当你在别人的阶段发现故障时，不要在自己的代码里悄悄修补。向负责人报告并附上能证明问题的 SQL，然后再商定临时解决方案。

常见错误

最常见的错误是把最终表中的数据当作真相，并把精力投入到修复 AI 上。第二个错误是在 Agent 的代码里修补脏数据，导致每次源系统变更时，你都得修复一个别人不知道的地方。

第三个错误较少受到关注：只理解一种存储类型。如果你只了解关系型数据库，当客户的数据存放在对象存储中的数千个文件里时，你就会陷入困境。这正是从数据工程转向 FDE 工作的人需要积累的系统广度。

如果你的目标是 FDE 职位，请在职位描述中寻找“集成”、“数据管道”和“SQL”等与“面向客户”同时出现的字眼。在简历上，用一句话描述你如何从一个仪表板一路追溯到源系统定位故障，比罗列一堆工具更有说服力。

本周的练习

拿一份你在工作中经常使用的报告，选其中一个数字，沿着全部五个阶段追溯，直到创建它的系统。任何你无法解释的阶段，就是你下一步应该学习的地方。

模型会不断进步。但客户数据仍要经过由许多不同的人负责的五个阶段，而能够跟进整条路径的 FDE（前沿部署工程师）永远会是第一个被召唤的人。
