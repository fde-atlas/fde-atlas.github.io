以利润率换护城河：为什么前沿部署工程师是初创公司最热门的职位

原标题：Trading Margin for Moat: Why the Forward Deployed Engineer Is the Hottest Job in Startups

Andreessen Horowitz · 2025-06-04 · 约 10 分钟读完

摘要

a16z 认为 AI 创业公司应效仿 Salesforce、ServiceNow、Workday 的重实施模式，通过前沿部署工程师等服务团队换取护城河，而非追求早期高毛利率。

要点

  • Salesforce 等企业靠重实施服务成为系统记录，市值远超 PLG 公司。
  • 企业 AI 产品需要深度集成与上下文，实施服务不可或缺。
  • AI 可自动化实施工作，使服务模式比上一代更易扩展。
  • 创业公司应优化总毛利增速而非 80% 毛利率，抢占数据入口。
  • OpenAI、Anthropic 也在招聘 FDE，验证该模式的价值。

事实证明，取代 Salesforce 并不像搭建一个接入 OpenAI 的语音 Agent 那么简单。那些试图用轻量级、套壳式的集成来替换由传统记录系统所掌控的核心工作流的公司，往往发现他们的 Agent 频频出错，甚至彻底失效。

矛盾的是，我们正目睹复杂的 AI 产品在销售、支持和法律领域爆发式增长。那些攻克复杂工作流的企业软件公司，常常在头两年内就从 0 增长到 500 万、1000 万甚至超过 2000 万美元的 ARR。那么，这些新兴 AI 初创公司是如何解决这些复杂用例的呢？

购买 AI 的企业就像拿到 iPhone 的奶奶：他们想用，但需要你帮他们设置好。

对 PLG 的执念与历史现实

在过去十年的大部分时间里，人们普遍认为产品驱动增长（PLG）优于重实施的企业软件。其吸引力显而易见：PLG 承诺更强的可扩展性和更高的利润率。这种执念源于 Atlassian、Slack、Figma、Notion 和 Dropbox（以及近期的 ChatGPT 和 Cursor）等成功案例。这些产品都提供简单的单人模式，无需销售电话即可轻松采用，并且可以直接用信用卡购买——无需冗长的需求界定或企业合同。

然而，在平台转型期间，企业有空间去试验并构建不遵循这种标准化公式的更复杂产品。Salesforce、ServiceNow 和 Workday 在从本地部署向云平台过渡时就做到了这一点。这些公司销售的企业平台都需要大量的实施、服务和支持，这与自下而上的 PLG 恰恰相反。但通过搞定复杂的实施，这些公司凭借可观的市值取得了主导地位：Salesforce 市值 2540 亿美元，ServiceNow 1940 亿美元，Workday 630 亿美元。它们的总价值远超顶级 PLG 公司，而且差距悬殊。

实施的必要性

Salesforce、ServiceNow 和 Workday 之所以能取得成功，是因为它们做了大量的实施工作。企业级 AI 产品对实施的要求甚至更为突出，因为它们需要深度的集成和上下文。为了应对这种复杂性，服务团队承担了将 AI 应用安全连接到内部数据库、API 和工作流的繁重工作，确保模型拥有所需的上下文——历史记录、业务逻辑等——从而创造价值。

Salesforce 和 ServiceNow 这类定义品类的公司之所以变得不可或缺，很大程度上是因为它们能够与企业内部系统和上下文集成：

  • Salesforce 只有在配置了正确的销售数据跟踪字段后才有价值
  • ServiceNow 只有在 ITSM 工作流得到妥善集成和编排时才能发挥作用
  • Workday 需要大量的人力资源数据迁移和配置

这种定制化工作在初期会导致较低的毛利率和较高的资金消耗率。上市时，ServiceNow 的毛利率为 63.2%，而 Workday 仅为 54.1%——远低于软件行业理想的约 80%。即使是通常被视为行业标杆的 Salesforce，据报道在建立合作伙伴生态系统之前，也曾消耗超过 $5200 万 才产生 2200 万美元的收入。

这些复杂的业务最适合在平台变革早期构建，此时工作流仍在成形之中，替换整个记录系统的回报也最高。没有公司会在没有巨大预期投资回报率的情况下替换像 CRM 这样的核心系统。Salesforce 正是乘着从本地部署向云端迁移的浪潮颠覆了 Siebel。实施 Salesforce 所需的 IT 投资要低得多，且无需本地安装，从而为每位用户带来更低的成本和更好的体验。

AI 平台变革不同于以往向云端或移动端的转型——而且在某些方面更令人兴奋——因为实现智能体体验所需的实施工作本身就可以通过 AI 来简化和自动化。历史上的集成工作可能需要与合作伙伴进行沟通协作、映射数据字段、处理不同编程语言之间的数据传输，以及理解各种内部规范。这类工作现在可以借助 AI 更高效地完成（在某些情况下甚至可以完全由 AI 完成！）。想象一下，启动一个智能体浏览器实例来从缺乏 API 的系统中检索信息，或者用一个对话式 Agent 来简化内部和外部沟通中的工作流。

一旦这些工作流和行为得以确立，这些公司便拥有了“护城河”，使它们能够提高价格并构建实施生态系统。这种定价能力体现在毛利率随时间的提升上；2024 年，ServiceNow 的毛利率达到 79%，Workday 为 75%。

Agent 成为主动协作的同事

如今，即使是像 Salesforce、ServiceNow 和 Workday 这样的标杆记录系统也变得脆弱，因为曾经驱动客户锁定的那些工作流和人类行为，现在越来越多地可以由 AI Agent 来处理。这一转变彻底改变了如何最有效地占据数据接入点。

软件不再只是辅助工作者——软件本身就是工作者。软件不再需要数据库之上的图形用户界面才能运行；它可以自主地端到端完成任务。但随着这些任务变得越来越复杂，完成它们的难度也随之增加。要让 AI Agent 真正与人类工作者旗鼓相当，企业需要专业服务来围绕这一全新方式重新设计岗位职能和流程。如果没有落地的实施支持，AI 可能达不到一名尽职员工的标准。然而，在恰当的支持下，Agent 可以承担更全面的职责，释放出远超基础任务自动化的巨大商业价值。

我们已经看到一些早期迹象：企业正在采用实施服务模式——类似于 Salesforce、ServiceNow 和 Workday 所采用的模式——来解决这一问题。只需看看领先 AI 应用公司发布的产品和技术文档即可。它们的共同点比其落地页所展示的要多得多。产品差异化很大程度上来自同一底层技术在不同客户群体中的不同实施和应用方式。

Agent 入职可以借鉴人类入职

让人类员工入职并不容易。让解决销售、支持或法律等领域用例、端到端运作的 AI Agent 完成“入职”也是如此。要发挥作用，先进的 Agent 需要主动管理、引导式学习，以及来自内部系统读写权限的丰富上下文。对人类而言，这一角色通常由经理担任。而对最优秀的复杂 AI 应用公司来说，这一角色往往由专业服务员工承担，有时被重新命名为前沿部署工程师或实施/解决方案专家。

以 Decagon 这样的公司为例，其 Agent 可自动处理客户支持。该公司拥有一支规模可观的人类“Agent 产品经理”团队，他们与客户紧密合作，搭建 AI 支持 Agent。这些产品经理具备较强的技术能力，帮助实施、集成和解决问题，使 Decagon 的 Agent 能够自主处理各种客户支持请求。

专业服务团队可以帮助根据企业的具体需求定制 AI 应用，并确保其成功落地。AI 可以很神奇，但前提是被正确运用。这正是前沿部署团队的用武之地：将模型转化为现实世界中的解决方案。

初创公司应致力于成为工作系统

现有的记录系统之所以有价值，是因为它们掌握着捕获宝贵数据的工作流，这有助于它们成为公司的唯一事实来源。如果新兴的 AI 应用真的想取得成功，它们也应该同样把自己定位为生成、捕获和存储宝贵公司数据的工作系统。在竞相掌控数据摄取层的过程中，为 80% 的毛利率进行优化是短视的。如今企业唯一应该优化的是尽快增长总毛利润。它们应该通过控制数据进入系统的位置和方式来建立持久的护城河。

看到这一机会的不仅仅是新兴应用公司。随着基础模型变得越来越可互换、拥有应用层的重要性日益提升，即使是 OpenAI 和 Anthropic 这样的模型提供商也在招聘前沿部署工程师和解决方案工程师，以在企业市场取胜。截至撰写本文时，OpenAI 招聘页面上的 311 个空缺职位中有 22 个属于这些类别。

团队构建首个服务团队的最佳实践

在与打造了精英服务组织的公司领导者交谈时，我们总结出几个关键主题：

    • 聪明地销售。选择合适的客户，并从小范围起步。年轻的公司和产品不可能满足所有人的所有需求。确定一个在系统和用例上至少有某些共性的 ICP，以最大化学习效果。
    • 优化激励结构： 前沿部署团队需要与客户经理紧密协同。定价和薪酬应体现这一点。愿意承担销售配额的实施负责人很少见，而且这也可能导致适得其反的行为。相反，应设计允许服务按成本销售的激励结构。随着 ACV 的增长，唯一重要的就是成功（以及客户留存）。
    • 深思熟虑地设计系统： 构建通用的软件库，并以易于集成和理解的方式设计 API，使这些集成更容易。考虑向客户提供哪些公开的 API 和接口。虽然提前对此进行深思熟虑可能会在早期拖慢开发速度，但它为未来的快速增长奠定了基础。
    • 留下痕迹。 外包给生态系统提供商需要清晰且一致的文档。在设计时就考虑到这一未来，并记录一切。
    • 构建/购买自动化工具： 在服务模式中追求最大速度和可扩展性。这是让复杂 AI 应用公司比上一代更快扩张——并且可能以更低最低 ACV——的关键解锁点。一流公司正在尽可能自动化整个流程，包括流程挖掘、数据管道自动化、系统集成以及梳理 API 文档等任务。这种速度会不断累积，并随时间形成竞争优势。
    • 雇佣充满好奇心的实干家： 这类实施工作不需要博士学位，但需要拼劲。最优秀的实施负责人具有高度的主观能动性和永不满足的好奇心。在某些情况下，将这些素质与对所服务行业（如法律或汽车行业）的一定了解相结合会有所帮助，但关键是要雇佣那些对现状抱有健康的不满态度的人。
    • 建立正确的反馈闭环： 前沿部署团队——无论是否为技术团队——离客户最近。在前线和产品团队之间建立正确的反馈闭环和干净的信息共享至关重要。消除“传话游戏”，加速开发。
    • 亲自到场： 这句话成为陈词滥调是有原因的。显然，拜访客户可以让销售过程更容易，但它也能提高专业服务的成功率。在理清内部权力关系和推动新工具落地采用时，亲身到场会很有帮助。

回应反对意见

对这种方法的批评者可能会认为，依赖专业服务模式限制了可扩展性，较低的毛利率反映了产品同质化，而且专业服务应该由生态合作伙伴而非公司自身来完成。这是因为在理想世界中，每家公司都希望成为漂亮的、自下而上的 PLG 赢家。然而现实是，在绝大多数情况下，这种方法都难以奏效。更持久、更深度融合的模式始终包含某种形式的亲身支持，例如前沿部署工程师或解决方案工程师。

实地支持还能帮助年轻公司承接更大的合同，相比轻触式方法，有可能带来更快、更持久的营收增长。这些早期服务合同还能验证客户的付费意愿，并预示未来合同规模的可能形态。随着时间推移，生态系统可以成为实现可扩展性和保护利润率的有力工具。然而，正如从创始人主导销售过渡到专职销售团队一样，年轻公司需要先学会自己做，才能教别人去做。Salesforce、ServiceNow 和 Workday 都已证明，高毛利率的业务正等待着粘性强的记录系统。对于这些新型工作系统而言，同样高的毛利率成果触手可及，而且很可能比历史上的先例来得更快，因为如今的这些服务运营的可扩展性已大大提高。

当今任何顶尖 AI Agent 应用的关键要素：服务

AI 的兴起创造了千载难逢的机会来构建新的工作系统，但成功的实施需要接受一个硅谷长期拒绝的事实：有时必须依靠人力密集型的服务才能打造变革性的软件。正如 Salesforce、ServiceNow 和 Workday 在成为如今庞大的软件企业之前，都不得不在实施、支持和集成服务上投入巨资一样，最有前景的 AI 应用也应遵循同样的路径。

那些执着于毛利率和可扩展性、却忽视了拥有工作系统所需的艰难问题解决的创始人，可能会因小失大。我们相信，将主导这一平台变革的公司，不会是那些拥有最漂亮界面或第一年利润表最干净的公司——而是那些有效地用 AI 取代人工工作流、捕获关键公司数据、并解决真实业务问题的公司，即使这意味着在此过程中要埋头苦干实施工作。通过今天拥抱专业服务模式，AI 创业公司正在为成为明天的记录系统奠定基础，并最终获得随之而来的市值和高利润率。
