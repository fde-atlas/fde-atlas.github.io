企业 AI 的竞争正从

FDE百科 · 2026-07-20 · 约 3 分钟读完

摘要

文章基于 WAIC 2026 的观察，认为企业 AI 交付正在发生三个转变：MCP、Skills、提示词等交付物被产品化为可复用资产；验收标准从单点提效转向业务周期指标；信通院推动互联协议与评测等标准化建设。作者以神州信息、医药 CSR 报告、华为云金融生态为例，指出 FDE 的复利来自每个项目沉淀可复用资产，而非单纯多做项目。

要点

  • 神州信息将银行客户经理上岗周期从 6-12 个月缩短至 1-3 个月。
  • 医药 CSR 报告初稿从数月压缩到数小时，效率提升超 90%。
  • 华为云联合多家银行共建金融专区，沉淀 MCP 与 Skills 行业资产。
  • 中国信通院发布互联治理倡议、ASL 协议与评测平台等五项成果。
  • 建议 FDE 每个项目沉淀四类资产，并用业务周期指标验收。

今日判断

WAIC 2026 进入尾声，今天出现了比"又发布了多少 Agent"更值得抓的新变化：

1. 交付资产开始被正式产品化。 MCP、Skills、提示词、语义层、行业规则不再只是项目附件，而是可复用、可审计、可持续迭代的组织资产。

2. 流程结果开始取代单点提效。 银行客户经理培养周期、医药 CSR 报告周期等业务指标开始成为 Agent 项目的验收语言。

3. 标准与互联开始补位。 中国信通院在 WAIC 同时发布互联治理倡议、案例汇编、研究报告、安全可信互联协议与评测平台，说明产业开始处理跨厂商协作和规模化治理问题。

合起来看：

  • 下一阶段高客单交付不应只卖"知识库 + 工作流"，而应卖行业资产库 + 流程重构 + 运行治理 + 业务指标验收。
  • FDE 的复利不来自多做项目，而来自每做一个项目就多一块可复用资产。

重点信号

神州信息：银行客户经理上岗周期从 6-12 个月缩短到 1-3 个月

  • 来源：神州信息 ｜ WAIC 典型实践项目；对公智能营销助手产品页
  • 7 月 19 日 WAIC 论坛后，神州信息披露其对公智能营销助手已在华东某城商行落地。产品由客户洞察、产品匹配、方案生成等多 Agent 组成，新客户经理上岗周期缩短 50%。
  • 为什么重要：这不是"回答更快"，而是把资深客户经理的洞察、产品匹配与方案结构沉淀成新人可以调用的工作系统。FDE 的价值落在缩短岗位胜任周期，而不是模型调用次数。

医药 CSR 报告：传统数月流程压缩到数小时，效率提升超过 90%

  • 来源：人民网 ｜ AI管理创新论坛举行
  • 7 月 20 日报道 WAIC"AI 管理创新论坛"案例。以 AI for Process 重构医药 CSR 报告流程，让多个智能体承担数据提取、内容生成、协同审阅和合规校验，报告初稿从数月压缩到数小时。
  • 为什么重要：真正的生产化不是给原流程加一个写作助手，而是重画端到端流程，并把审阅、合规、知识沉淀一起纳入系统。Agent 项目的最小单位不是任务，而是流程。

华为云金融生态：MCP 与 Skills 开始变成可沉淀、可复用的行业资产

  • 来源：智东西 ｜ 华为云 WAIC 拆解智能体规模化落地步骤
  • 7 月 18 日 WAIC 华为云企业智能体产业论坛提出，规模化落地的重要步骤是沉淀和共享 MCP、Skills 等行业资产。联合工行、银联、邮储银行及十余家生态企业共建智慧金融专区。
  • 邮储银行已实现智能体执行引擎 7×24 小时值守、分钟级情报获取。天眼查预集成 160 余项 MCP 能力，并将六类风控能力转为 Skills。
  • 为什么重要：FDE 做完一个项目后，最值钱的不是留下一套 Prompt，而是把接口、规则、经验、审批和异常处理变成可复用资产。交付组织未来需要同时经营 MCP 资产库 + Skills 资产库 + Eval/AgentOps。

中国信通院：智能体产业从单点产品进入互联、协议与评测阶段

  • 来源：中国日报 ｜ WAIC 2026 从大模型到智能体论坛
  • 7 月 18 日论坛集中发布五项成果：智能体互联治理倡议、智能经济实践汇编、《互联网智能体发展研究报告》、智能体安全可信互联协议（ASL）和终端智能体评测平台。
  • 工信部相关负责人明确判断：国内智能体正从单点验证走向系统协同、从试点示范迈向规模化应用。
  • 为什么重要：当 Agent 需要跨厂商、跨平台、跨部门工作时，FDE 不能只管单体效果，还要管身份、协议、互信、评测和责任边界。这是中国版 Agent 交付标准化的重要前置信号。

对 FDE 从业者的启发

  • 把交付升级为"资产工程"：不仅整理资料，还要形成可调用、可授权、可测试、可版本化的 Skill 与工作流资产。每个项目至少留下四份可复用资产：场景清单、Skill/规则库、验收集、异常与人工接管清单。
  • 每个项目必须选一个业务周期指标：如新人上岗周期、报告初稿周期、方案产出周期、响应时延、一次通过率。用业务周期而不是"提效百分比"来验收。
  • 关注可复用资产的沉淀率：FDE 的复利不来自多做项目，而来自每做一个项目就多一块可复用资产。MCP 工具、Skills 规则、Eval 验收集、异常处理规则都是资产。
  • 对外表达升级：从"帮企业做 Agent"升级为"把企业经验装进流程，并对业务结果负责"。
