不使用任何库构建 TF-IDF 检索

原标题：Build TF-IDF retrieval with no libraries

FDE Interview Prep · 2026 · 约 7 分钟读完

摘要

这是一篇 FDE 面试练习题解析，要求不借助任何库从零实现 TF-IDF 检索。文章给出完整答题框架：先确定以段落而非文件为检索单元，再明确写出词频、平滑 IDF 和余弦相似度的公式选择，用倒排索引只对候选段落打分，最后用已知正确答案的小型相关性测试验证排序。附有完整 Python 实现和模型答案，并指出常见陷阱：只顾解析边界情况而不测试相关性。文中还讨论了权限过滤、规模化瓶颈及何时转向 BM25 或向量检索。

要点

  • 以段落而非文件作为检索单元，文档频率按段落统计。
  • 先写明公式选择：次线性词频、平滑 IDF、余弦相似度。
  • 用倒排索引只对候选段落打分，返回带路径和位置的 top k。
  • 必须用已知答案的排序测试验证，如稀有词应胜过重复常见词。
  • 生产场景需按权限预过滤候选，并分别度量检索与答案忠实度。

如何回答

一个没有排序测试的检索器只是一个返回结果的函数。截至 2026 年 9 月，Cohere 的 Agentic Platform 职位要求具备构建和部署 Agentic 应用的经验，以及构建衡量准确性、安全性和延迟的评测框架的能力。来源 1前沿部署工程师，Agentic Platform发布方Cohere（Ashby 招聘板）来源类型公司职位发布。这道题考察的正是其中检索的部分，以及衡量检索的习惯，而且是在最小的规模上。

目标是按顺序展示三件事：你知道 TF-IDF 实际计算的是什么，你检索的是段落而不是文件，以及你能证明排序是合理的。答案的结构也应如此。

  • 首先确定检索单元。 说：“段落是我返回和打分的单位，所以文档频率是按段落而不是按文件统计的。” 然后选择一个你能为之辩护的分块器：按空行切分，把短段落（如标题）合并到下一段，直到段落达到最少字数，只对长段落用带重叠的滑动窗口，并在每个段落上保留文件路径和块位置。
  • 在写代码之前先写下权重公式。 说明你的词频（原始计数，或 1 + log(tf)，以免一个词重复十次就占据主导）、你的逆文档频率（平滑处理，并说明平滑的作用），以及在长度归一化向量上的余弦相似度。说出每个选择；这正是让代码可审查的关键。
  • 用简单的方式分词，并说明你放弃了什么。 小写化，按非字母数字字符切分，一个简短的停用词列表。不做词干提取，所以 “refund” 和 “refunds” 不会匹配；要把这一点说出来。
  • 只对候选打分。 从词到段落的倒排索引意味着查询只会触及与它共享某个词的段落。用堆返回前 k 个结果。
  • 用一个小型相关性测试来证明。 构造一个正确答案显而易见、且只有 IDF 才能产生该答案的测试用例，并断言排序顺序。然后说明你实际会如何衡量：一个带标注的查询集合和 k 处的命中率。

陷阱是把时间花在解析边界情况上，而从不测试相关性。代码可以完美无缺，但排序仍然错误，只有用已知正确答案的测试才能发现这一点。

追问

当你的第一个回答摆上桌面后，面试官接下来可能会问什么。

  • 一个词出现在每段文本中。它占多大权重，而这正是你想要的吗？
  • 你如何判断对分块器的改动让检索变好了还是变差了？
  • 文件夹增长到数百万段文本。最先出问题的是什么？

答案容易出错的地方

  • 对整个文件而非段落打分，或者比较未做长度归一化的原始词频，导致最长的文件在每次查询中都胜出。

参考答案

“我会对段落而不是文件建立索引，因为调用方拿回的就是段落。分词是小写字母数字串，去掉少量停用词；不做词干提取，所以单复数是不同的词，这一点我会再斟酌。词频采用次线性形式，

1 + ln(tf)

。IDF 为

ln((1 + N) / (1 + df)) + 1

。外层的加一意味着出现在每段文本中的词权重为 1.0，即该公式给出的最低值而非零，因此它仍能打破平局。内层的加一相当于假设多了一段包含所有词的文本，这在极小语料上能抑制极端权重；它们还能避免对没有任何段落包含的词做除以零的运算，不过那些词我本来就会丢弃。向量做了 L2 归一化，所以点积就是余弦相似度，长段落不会因为长而胜出。”

次线性词频和余弦归一化与 Manning, Raghavan and Schütze, Introduction to Information Retrieval, chapter 6 中一致，其 IDF 是未平滑的

log(N / df)

。平滑形式是 scikit-learn 在

smooth_idf=True

(

TfidfTransformer documentation

).

“余弦相似度也会奖励短段落：一段只有标题‘Refunds’的文本对退款查询会得到满分，却回答不了任何问题。所以分块器会把短段落向前合并进下一段。”

import heapq
import math
import re
from collections import Counter
from pathlib import Path

# Letters and digits in any script
TOKEN = re.compile(r"[^\W_]+")
STOP = {"the", "a", "an", "and", "or", "of", "to", "in",
        "is", "for", "on", "with"}


def tokens(text: str) -> list[str]:
    return [t for t in TOKEN.findall(text.lower())
            if t not in STOP]


def chunk(text: str, min_words: int = 25,
          max_words: int = 120, overlap: int = 30) -> list[str]:
    """Merge short paragraphs (headings, sign-offs) forward;
    window long ones."""
    out: list[str] = []
    buf: list[str] = []
    for para in re.split(r"\n\s*\n", text):
        buf += para.split()
        if len(buf) < min_words:
            # A bare heading waits for its paragraph
            continue
        step = max_words - overlap
        last = max(len(buf) - overlap, 1)
        for start in range(0, last, step):
            out.append(" ".join(buf[start:start + max_words]))
        buf = []
    if buf:
        # A short tail joins the last passage
        if out:
            out[-1] += " " + " ".join(buf)
        else:
            out.append(" ".join(buf))
    return out


class Index:
    def __init__(self, folder: Path):
        self.passages: list[tuple[str, int, str]] = []
        for path in sorted(folder.rglob("*.txt")):
            text = path.read_text(encoding="utf-8",
                                  errors="replace")
            # Relative path, so two faq.txt files stay distinct
            rel = str(path.relative_to(folder))
            self.passages += [(rel, i, c)
                              for i, c in enumerate(chunk(text))]

        counts = [Counter(tokens(text))
                  for _, _, text in self.passages]
        n = len(counts)
        df = Counter(term for tf in counts for term in tf)
        self.idf = {t: math.log((1 + n) / (1 + d)) + 1
                    for t, d in df.items()}

        self.vectors = [self._weigh(tf) for tf in counts]
        self.postings: dict[str, list[int]] = {}
        for i, vec in enumerate(self.vectors):
            for term in vec:
                self.postings.setdefault(term, []).append(i)

    def _weigh(self, tf: Counter) -> dict[str, float]:
        vec = {t: (1 + math.log(c)) * self.idf[t]
               for t, c in tf.items() if t in self.idf}
        norm = math.sqrt(sum(w * w for w in vec.values()))
        if not norm:
            return {}
        return {t: w / norm for t, w in vec.items()}

    def search(self, query: str, k: int = 5):
        """Top k as (score, path, chunk index, text)."""
        # Terms the corpus has never seen drop out here
        q = self._weigh(Counter(tokens(query)))
        candidates = {i for t in q for i in self.postings[t]}
        scored = (
            (sum(w * self.vectors[i].get(t, 0.0)
                 for t, w in q.items()), i)
            for i in candidates
        )
        top = heapq.nlargest(k, scored)
        return [(round(s, 4), *self.passages[i]) for s, i in top]

“每个结果包含分数、路径、块索引和文本。路径和块索引是生成的答案所引用的内容，读者可以据此打开确切的段落。语料中从未出现过的查询词没有 IDF，因此会被丢弃，只由这类词构成的查询会返回空列表而不是抛出异常。如果文件带有标题标记，我还会给长章节的每个窗口加上其标题作为前缀。我最关心的测试是一个我知道答案的排序测试：”

def test_rare_term_outranks_repeated_common_term(tmp_path):
    files = {
        "refunds.txt": "Refunds go back to the original card "
                       "after billing approves them.",
        "team.txt": "For billing, ask billing support "
                    "or the billing team.",
        "invoices.txt": "Billing sends invoices monthly.",
        "plans.txt": "Billing plans renew each year.",
    }
    for name, text in files.items():
        (tmp_path / name).write_text(text)
    top = Index(tmp_path).search("billing refunds", k=2)
    assert [path for _, path, _, _ in top] == [
        "refunds.txt", "team.txt"]
    # A wide margin, so a small tokenizer change can't flip it
    assert top[0][0] > 1.5 * top[1][0]

“‘billing’出现在每个文件中，所以它的 IDF 被压低，而唯一包含‘refunds’的文件胜出，即使

team.txt

中‘billing’出现了三次。在该文件夹上运行，搜索返回：”

“去掉 IDF 后

team.txt

胜出，0.5454 对 0.4714，这正是该测试要捕获的回归。设置余量断言是因为一个险些通过的测试可能因一次无关紧要的停用词改动而翻转，那样它就不再能证明任何东西。

实际使用中，我会从将要提问的人那里收集几十个问题，标注出回答每个问题的段落，并跟踪命中率

k

每次我改动分块器或分词器时都是如此。在更大规模下，最先出问题的是内存，因为每个向量都存在 Python 字典里；我会把倒排索引移到磁盘上，或改用支持 BM25 的搜索引擎——BM25 能饱和词频，并让长度归一化可调；当查询和文档段落用不同的词表达同一事物时，我才会引入嵌入向量。

在客户部署中，每个段落都带有其源文件的访问控制列表，我在打分之前（而不是之后）按调用者的权限过滤候选内容，这样受限段落既不会影响结果，也不会通过摘要片段泄露。当模型基于这些段落回答时，我会把每个段落连同其路径和分块索引一起传入，并要求答案引用它们，然后分别衡量检索效果（命中率

k

）和答案对其段落的忠实度，这样我就能知道是哪一半出了问题。”
