数据与 SQL 工程

基础SQL 窗口函数窗口函数在与当前行相关的一组行上计算数值，而不会将它们折叠成一行，因此你可以在保留每一行的同时进行排名、与相邻行比较或计算累计总和。这是分析师用纯 SQL 回答“与什么相比？”这类问题的方式，大多数面试官也用它来区分“懂 SQL 的人”和“只懂 GROUP BY 的人”。

生产环境 AI 系统设计

基础从概念验证到生产环境一个在演示中正确回答了一个问题的 notebook 并不是交付物。生产环境是那些不体面却必不可少的工作：把一次性的成功变成客户能够运行、信任并在你不在场的情况下自行运维的系统。弥合这一差距正是 FDE 工作的大部分内容。

基础重试、指数退避与抖动当调用因瞬时错误而失败时，立即重试是最糟糕的做法：它会给本已不堪重负的服务叠加负载，并让所有客户端同步形成踩踏。指数退避可以拉开重试的间隔，而抖动则让客户端去同步化，使它们不再齐步到达。

面向客户的技艺

基础需求发现需求发现的工作是找出隐藏在客户明确诉求背后的真实问题。他们交给你的请求（“给我们做一个聊天机器人”）几乎从来不是真正的需求；能够弄清楚谁在使用它、成功是什么样子、实际存在哪些数据、以及为什么截止日期就是截止日期的 FDE，才能交付出人们真正使用的东西。

基础界定模糊问题界定一个开放式命题（“某城市想缩短 911 响应时间”）是一种结构化的操作，而非灵光一现：澄清输入和约束，大声说出你的假设，切分出最小可用的 MVP，明确你正在选择的准确性/成本/延迟权衡，并规划失败时该怎么办。直接跳到某个模型或架构上，是候选人在模拟环节被淘汰的最常见原因。

基础向非工程师解释权衡高管并不在乎你选择了 RAG 还是微调；他们关心的是成本多少、何时交付、以及可能出什么错。翻译技术权衡意味着把准确性、成本和延迟转化为业务实际正在做的决策，用他们的语言把每个选项框定为带有后果的选择，并回答他们最终都会问的问题：为什么 AI 每次给出的答案都不一样，以及为什么这不是 bug。
