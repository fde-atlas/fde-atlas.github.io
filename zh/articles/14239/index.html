模型上下文协议

原标题：Model Context Protocol

FDE Interview Prep · 2026-07-28 · 约 2 分钟读完

摘要

这篇资料介绍 Model Context Protocol（MCP）及其在前沿部署工程师面试中的考察方式。MCP 是开放协议，客户端通过 JSON-RPC 2.0 连接 MCP 服务器，服务器可向模型暴露工具、资源和提示模板，本地用 stdio、远程用 Streamable HTTP 传输。Anthropic 与 Notion 的 FDE 职位都要求交付 MCP 相关产物，有候选人的 take-home 测试即要求构建查询库存并下单的 MCP 服务器。文章强调高分回答应聚焦信任边界：服务器须使用独立签发的令牌、不得透传客户端令牌，工具结果应视为不可信输入以防提示注入，写操作需人工确认并记录审计日志。最后指出单一 Agent 调用单一系统时直接函数调用更简单，多个客户端复用工具时 MCP 才划算。

要点

  • MCP 是开放协议，用 JSON-RPC 2.0 连接服务器，暴露工具、资源与提示模板。
  • Anthropic 和 Notion 的 FDE 职位均要求交付 MCP 服务器等产物。
  • 面试高分点在信任边界：独立令牌、不透传客户端凭证。
  • 工具结果视为不可信输入，防提示注入，写操作需人工确认并留审计日志。
  • 单 Agent 单系统用普通函数调用即可，多客户端复用工具时才值得上 MCP。

全文

模型上下文协议（MCP）是一种开放协议，运行 MCP 客户端的应用程序通过它将模型连接到 MCP 服务器；MCP 服务器可以暴露模型可调用的工具、应用程序可作为上下文附加的资源，以及用户可调用的提示模板。消息是

JSON-RPC 2.0

，对于本地服务器通过 stdio 传输，对于远程服务器则通过 Streamable HTTP 传输，而需要授权的远程服务器充当资源服务器（

MCP specification, authorization

）。本课将任何向 AI Agent 暴露工具的服务称为工具服务器；MCP 是构建工具服务器的一种标准方式。

在 FDE 面试中

招聘信息中提到了它：Anthropic 的招聘信息将 MCP 服务器、子 Agent 和 Agent 技能列为 FDE 为客户交付的技术产物之一，Notion 的招聘信息则描述了使用 MCP 构建自定义 Agent 和 AI 工作流。来源 1Forward Deployed Engineer (New York City, NY; San Francisco, CA; Seattle, WA)发布方Anthropic（Greenhouse 招聘网站）来源类型公司招聘信息来源 2Forward Deployed Engineer, GTM, AMER @ Notion发布方Notion（Ashby 招聘网站）来源类型公司招聘信息一位候选人在 2026 年 8 月创建的一个仓库（被描述为 Duvo FDE 任务测评）中报告，构建了一个 MCP 服务器，让 Agent 能够查询门店库存并向一个桩系统提交补货订单，并在其 README 中写道，任务说明中明确表示被测试的并不是集成管道部分。来源 3StoreLink MCP server发布方AlexHumpert（GitHub）来源类型候选人的家庭作业仓库

一个出色的回答会超越管道层面，深入到信任边界。规范要求服务器只接受为其签发的令牌，并禁止将客户端的令牌透传给上游 API（MCP 规范，授权安全注意事项），因此当服务器调用客户的系统时，它使用为该系统单独签发的令牌，并将权限限定在工具所需的范围内。将每个工具结果都视为可能携带提示注入的不可信输入，像撰写提示一样仔细地撰写每条工具描述，因为模型会将其当作提示来读取；在任何会执行写入操作的工具前加入人工确认，并记录每次调用以备审计。然后说明你何时会跳过 MCP：如果你拥有的一个 Agent 只调用一个系统，那么普通的函数调用运维成本更低；而当多个客户端（例如客户自己的助手）复用相同的工具时，服务器才物有所值。
