AI FDE 评测框架：离线评估 LLM 输出

原标题：AI FDE eval harness: grading LLM output offline

FDE Times · 2026-11-19 · 约 3 分钟读完

摘要

《Forward Deployed AI Engineering》一书的配套代码库 ghanemzadeh/ai-fde 提供了一个 Python 评测框架，含 36 个测试，可离线运行，无需 API key。其演示流程对六份虚构合同备忘录按评分标准打分并报告失败原因。框架由四部分组成：确定性检查、模型裁判、裁判与人工评分的校准、以及仪表盘，其中校准环节最常被忽略。代码采用 MIT 许可，可复用于客户项目；模板、提示词和插图受版权保护，可改编但不得整套转载。文章建议求职者 fork 该框架、替换为自己的领域数据并手工校准裁判，以此展示评测能力。

要点

  • ghanemzadeh/ai-fde 是该书的配套代码库，含模板、提示词与评测框架。
  • 评测框架用 Python 编写，36 个测试，离线运行，无需 API key。
  • 演示流程对六份虚构合同备忘录打分并指出失败项。
  • 框架包含确定性检查、模型裁判、人工校准和仪表盘四层。
  • 代码为 MIT 许可，模板与提示词可改编但不可整套转载。

《Forward Deployed AI Engineering》一书背后的代码库展示了如何衡量一个 AI 试点是否足够好、可以投入生产。

简要概述

  • ghanemzadeh/ai-fde 代码库是《Forward Deployed AI Engineering》一书的配套资源，包含模板、提示词、评测框架和插图。
  • 该框架用 Python 编写，包含 36 个测试，可离线运行；其试运行会为六份虚构的合同备忘录评分，并标出未通过的部分。
  • 框架代码采用 MIT 许可证；模板、提示词和插图受版权保护，可以改编使用，但不得整套重新发布。

六份合同审查备忘录（均为虚构）会根据评分标准进行评分。运行结束时，工具会报告哪些未通过以及原因。这就是 ghanemzadeh/ai-fde 代码库中的试运行，该代码库是《Forward Deployed AI Engineering》一书的配套资源，且无需 API 密钥即可运行。

该代码库包含本书的模板、提示词、评测框架、插图和参考资料。全书共五部分二十章，配有十二个模板。README 对其用途直言不讳：其中的一切都是为了被复制和改编而存在的。

对于 FDE 来说，评测框架是最应该首先打开的部分。Gyde 将这一角色描述为围绕 AI 试点与 AI 投入生产之间的差距展开。HatchWorks 则认为，FDE 负责整个闭环，从“要构建什么”这一问题开始，一直到系统上线并拥有真实用户。

在这个闭环的中间，有一个每个客户最终都会问的问题：你怎么知道输出足够好？一个无法用数字回答这个问题的试点，通常只能停留在试点阶段。

四个组件，各自捕捉不同类型的失败

该框架是一个包含 36 个测试的 Python 项目。它结合了确定性检查、一个充当裁判的模型、一个将裁判评分与人工评分进行校准的步骤，以及一个仪表板。理解它最简单的方式是把它看作一组层层过滤的过滤器。

确定性检查既便宜又确定：必需的章节是否缺失，格式是否正确？模型裁判则处理正则表达式无法捕捉的内容，例如推理是否真正基于合同的条款。

校准是最常被跳过的组件。模型裁判终究还是模型，它可能以无人预料到的方式过于宽松或存在偏差。

假设客户的律师对全部六份备忘录重新评分，只在四份上与裁判意见一致。那两处分歧就暴露了评分标准或裁判提示词需要修正的地方——在任何人向董事会展示仪表板之前。

由于该框架可离线运行，整个评分流程无需在 API 调用上花费任何费用即可阅读。这使它成为学习评测的更好方式，胜过幻灯片演示：运行它，看看哪份备忘录未通过，然后回溯到导致其未通过的代码。

有多少可以安全地复用？

许可分为两部分。框架代码采用 MIT 许可证，可以用于客户项目。模板、提示词和插图受版权保护：可以为你的工作进行调整，但不得作为合集重新发布。对于作品集，请发布你改造过的框架，而不是模板集的副本。

这些模板值得与代码一起阅读，因为 FDE 的工作并不止于工程。HatchWorks 将 FDE 描述为半个顾问、半个产品经理、半个资深工程师，并且是唯一承担问责的人。

想转入 FDE 工作的开发者有一个现成的练习。Fork 这个框架，用你熟悉的领域的输出替换六份合同备忘录，编写你自己的确定性检查，并人工评阅一个小样本以校准评判器。

在简历上，诸如“构建了一个评测框架，将评判器与人工评阅者进行校准，并报告一致率”这样的描述，比任何“LLM 经验”的声明都更有说服力。在浏览招聘信息时，留意提到评测或衡量输出质量的公司：它们很可能是直接重视这项技能的地方。

当客户问你怎么知道系统回答正确时，不要凭直觉回答。最有说服力的答案是一次能准确列出问题所在之处的运行。
