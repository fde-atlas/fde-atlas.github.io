Zep（2025）FDE 解读

原标题：Zep (2025) Explained for FDEs

FDE Interviews · 2026-10-18 · 约 4 分钟读完

摘要

本文解析 Zep 及其引擎 Graphiti：一个为 AI Agent 提供持续更新的知识图谱记忆服务。图谱分三层存储原始对话、实体与事实边、社区摘要，核心是双时间模型——每条事实记录生效与失效时间，新事实与旧事实矛盾时关闭旧区间而非覆盖，因此既能回答现状也能回溯历史。检索结合余弦相似度、BM25 与图搜索并重排。在 LongMemEval 上，Zep 用约 1600 token 达到 71.2%（gpt-4o），超过塞入 115K token 全历史的 60.2%，延迟降低约 90%。作者提醒：论文未测量摄取成本，错误的实体合并与矛盾判断会静默改变 Agent 的认知，需预留预算并建立纠错工具。

要点

  • Graphiti 用三层知识图谱存储对话记忆：原始 episode、实体与事实边、社区摘要。
  • 双时间模型区分世界时间与系统时间，事实带生效区间，矛盾时关闭旧区间而非覆盖。
  • 检索融合余弦相似度、BM25 关键词与图搜索，返回带日期范围的事实。
  • LongMemEval 上约 1600 token 得分 71.2%，胜过 115K 全上下文的 60.2%，延迟降约 90%。
  • 摄取成本未测量，错误合并与矛盾判断会静默污染记忆，需纠错工具。

一分钟读懂这篇论文

Zep 是一项面向 AI Agent 的商业记忆服务，这篇论文介绍了其引擎 Graphiti——一个从对话和业务数据中持续更新的知识图谱。

该图谱分为三层。Episode 无损地保存原始输入（消息、文本或 JSON）。LLM 从每个 episode 中提取实体和事实（两个实体之间的关系，以边的形式存储），并使用之前四条消息作为上下文。新实体通过嵌入相似度、全文搜索和 LLM 判断与现有实体进行匹配，因此"Priya"和"Priya Shah"会合并为一个节点。社区将联系紧密的实体分组，并携带摘要。

其独特之处在于时间。Zep 采用双时间线模型：每条事实边记录它在现实世界中何时成立、何时失效（valid_at、invalid_at），以及系统何时创建和停用它（created_at、expired_at）。诸如"两周前"之类的相对日期会根据消息的时间戳进行解析。当 LLM 发现一条新事实与同一时期的一条现有事实相矛盾时，旧边的有效期会在新事实的起始时间处关闭。任何内容都不会被覆盖，因此系统既能回答"她现在住在哪里？"，也能回答"她三月份住在哪里？"

检索通过余弦相似度、BM25 关键词搜索和广度优先图搜索进行，对结果重新排序，并将排名靠前的事实连同其日期范围以及实体摘要一起格式化输出。

在 LongMemEval 上，Zep 击败了将全部 115,000 token 历史记录放入上下文的做法，且仅使用了约 1,600 个 token。

助手需要记住会变化的事实：客户搬家、换岗位、取消订单。对原始聊天记录的检索会同时找到过时和最新的陈述，而将长篇历史塞入提示词既缓慢又昂贵。大多数记忆系统要么覆盖事实，要么保留每个版本却无法判断哪个是当前有效的。

将记忆存储在三层中：原始 episode、提取出的实体和事实边，以及社区摘要。为每条事实赋予一个现实世界中的有效期区间，并记录系统何时获知或撤回该事实（双时间线模型）。当 LLM 发现一条新事实与旧事实矛盾时，关闭旧事实的区间。通过语义、关键词和图搜索进行检索，重新排序，并连同日期一起返回事实。

在 LongMemEval 上，历史记录平均为 115,000 个 token，Zep 使用 gpt-4o-mini 得分 63.8%，使用 gpt-4o 得分 71.2%，而完整上下文分别为 55.4% 和 60.2%，同时仅使用约 1,600 个 token，并将延迟降低约 90%。提升最大的是偏好、时间和多会话类问题；关于助手说过什么的问题则表现变差。

为什么这对 FDE 很重要

企业助手记住的信息会过时：客户的套餐、联系人的职位、收货地址、项目的状态。如果记忆只是一堆检索到的聊天片段，模型会同时看到“我住在奥斯汀”和“我们搬到了丹佛”，只能靠猜。如果记忆是覆盖式的，你就会丢失历史，无法回答“我们开发那张发票时知道什么？”

即使你从不使用这个产品，Zep 的设计也提供了三个值得借鉴的想法。

为事实存储有效期区间。 一个事实从某个日期到另一个日期为真。关闭一个区间会保留历史；随每个事实返回日期范围，让模型能够回答“现在”和“当时”的问题。

将世界时间与系统时间分开。 当助手在四月得知某人三月搬家时，记录应同时显示两者。这让你能够重建 agent 在行动时所相信的内容，这对审计和投诉处理很重要。

保留来源。 每个事实都链接回它所来自的片段。当提取或实体匹配出错时——这一定会发生——你可以找到由坏片段创建或关闭的每个事实，并将其回滚。

弱点在于论文没有衡量的部分。每条消息都要经过多次 LLM 调用（提取、消解、日期提取、矛盾检查），而论文没有报告摄入成本或延迟。错误的合并和错误的矛盾判断会悄悄改变助手所相信的内容。为这两者预留预算，并构建纠错工具。
