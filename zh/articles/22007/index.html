仅限拥有5年以上实际工作经验的工程师

高单价・直接签约案件信息

自由职业工程师的“单价”，是指客户支付的按月计算的业务委托报酬。与正式员工的“月薪”不同，其中包含以下要素。

  • 劳动的对价（技术能力・工作时长）
  • 社会保险费（不含客户负担部分）
  • 带薪休假・奖金的替代部分

通常单价以“月额○○万日元（按140〜180小时计算）”的形式呈现。例如标注为“月额80万日元、工作160小时”的案件，换算成时薪约为5,000日元。

单价的计算公式：

時給換算 = 月額単価 ÷ 月間稼働時間
例）800,000円 ÷ 160時間 = 5,000円/時

此外，当出现超出或不足的工作时长时，合同中会设置“结算幅度”，例如“结算幅度为140〜180小时，超出单价为月额÷180，不足单价为月额÷140”等条件会明确写入合同。由于结算幅度直接影响实际到手收入，因此在选择案件时务必确认这一项。

另外，根据2024年11月1日实施的《自由职业者及经营者间交易适当化等法》，发包经营者在将业务委托给自由职业者时，必须明示交易条件，报酬原则上须在收到给付之日起60日内支付（参考：厚生劳动省“致以自由职业者身份开展业务者及委托业务经营者等”、公正交易委员会自由职业法特别页面）。单价和结算条件，请在签约前通过明示的交易条件进行确认。

自由职业工程师遇到的单价表示形式主要有3种。

表示形式说明主要案件示例
月额单价按每月工作量支付的报酬。多为SES・准委托合同常驻型系统开发、远程开发支持
时薪单价按每小时支付的报酬。多为短期案件・副业案件代码审查、技术顾问、副业开发
日额单价按每天支付的报酬。多为咨询・上游工程案件IT咨询、PMO支持

换算参考（每月工作160小时・20个工作日的情况）：

  • 月额60万日元 ≒ 时薪3,750日元 ≒ 日额3万日元
  • 月额80万日元 ≒ 时薪5,000日元 ≒ 日额4万日元
  • 月额100万日元 ≒ 时薪6,250日元 ≒ 日额5万日元
  • 月额120万日元 ≒ 时薪7,500日元 ≒ 日额6万日元

比较案件时，统一换算为月额进行比较最为清晰明了。

“听说单价80万日元好像很高，但实际到手是多少？”这样的疑问非常多。公司职员与自由职业者在税务和保险制度上有很大差异。

月额80万日元（年销售额960万日元）的自由职业工程师的情况：

项目金额（概算）
销售额（月额单价）800,000日元
经费（交通费・设备・书籍等）△30,000〜50,000日元
国民健康保险费△40,000〜50,000日元/月
国民养老保险费△16,980日元/月（2026年度）
所得税・居民税（概算）△80,000〜100,000日元/月
实际到手收入（月额概算）约580,000〜620,000日元

另一方面，公司职员月薪45万日元（税前）的情况下，到手约为35万日元左右。自由职业者需全额自行承担税费和保险，但如果善用经费列支和蓝色申报特别扣除（最高65万日元），即使年收入相同，也可以增加实际到手收入。

工作方式的不同也会导致单价波动。

工作方式对单价的影响特点
常驻（每周5天、到办公室通勤）基准单价〜+5〜15万日元单价较高但受约束时间长。容易与客户建立关系
每周4天以下常驻基准单价〜±0在减少工作时长与单价之间取得平衡的中间形态

2024〜2026年期间，完全远程的案件数量呈增加趋势，与常驻的单价差距正在缩小。尤其是AI、数据类案件以远程为主，即使是高单价案件也多为完全远程。

“相同的工作年限、相同的技术栈，为什么单价会有如此大的差距？”——这个问题的答案可以归纳为以下7个因素。

这是最基本的因素。不过，相比单纯的“工作年限”，“经历过多少次深入的技术决策”对单价的影响更大。

具体能够带来高单价的经历示例：

  • 参与设计、架构决策的经验
  • 处理大规模数据处理、高负载系统的经验
  • 在0→1产品开发中进行技术选型的经验
  • 团队领导、指导新人的经验

相比“5年的编码经验”，“3年内承担到架构设计的经验”在市场上会获得更高的价值评价。

所负责的工程环节越靠近上游，单价越倾向于越高。

工程环节对单价的贡献
需求定义、业务分析高（需要业务理解能力）
概要设计、架构高（需要技术判断力）
详细设计、实现中（因技能水平而产生差距）
测试、QA低〜中（具备自动化技能则可提升）
运维、维护低〜中（具备基础设施知识则可提升）

从“只写代码”的岗位成长为“能够承担需求梳理、设计决策的工程师”，是提升单价的最短路径。

拥有需求多、供给少的技术，工程师的谈判能力会大幅提升。

截至2026年能够带来高单价的稀缺、热门技术：

  • LLM应用开发（RAG、LangChain、LlamaIndex）
  • AI Agent开发（AutoGen、CrewAI等）
  • 数据平台设计（dbt、Airflow、Snowflake）
  • Kubernetes、平台工程
  • Rust、WebAssembly
  • 零信任安全架构

只要掌握其中1〜2项技术，就可能作为现有技能的“附加单价”，产生每月10〜30万日元的差距。

所谓“商流”，是指客户（终端用户企业）与自由职业工程师之间介入了多少家中介公司。这对单价的影响非常大。

【エンド直案件】
エンドユーザー企業 → フリーランスエンジニア
例：月額100万円の案件で、エンジニアが受け取る金額：95〜100万円

【1次下請け案件】
エンドユーザー企業 → SES会社A → フリーランスエンジニア
例：月額100万円の案件で、エンジニアが受け取る金額：70〜80万円

【2次下請け案件】
エンドユーザー企業 → SES会社A → SES会社B → フリーランスエンジニア
例：月額100万円の案件で、エンジニアが受け取る金額：50〜65万円

据说即使是业务内容相同、技能要求相同的案件，仅因商流不同，就可能产生每月30〜50万日元的差距（上述例子是扣除中介费后的到手收入的理论值）。如果你感到“为什么单价这么低”，也值得怀疑一下是否是商流的问题。

【本公司实际数据】在本公司已公开的183件案件（全部登记了商流）中，PM、PMO类案件（22件）因单价水平特别高且商流分布不均，故剔除后统计，平均单价为：终端直签78.2万日元（65件）、总包直签76.0万日元（86件）、三次分包70.0万日元（10件），可以确认商流层级越深单价越低的趋势。不过差距最大约为8万日元，并没有上述理论值（每月30〜50万日元）那么大（三次分包仅10件，仅供参考。所载单价为月额，并非扣除返还率后的到手收入）。此外，仅就目前招募中的17件来看，有15件（约9成）为终端直签。

工作天数、工作形态会直接影响单价。如前所述，远程每周3〜4天比常驻每周5天的单个案件单价倾向于更低，但通过并行承接多个案件，可以实现总收入最大化。

月收入最大化的模式示例：

  • 远程每周4天（月单价60万日元）× 1个案件 ＝ 月60万日元
  • 远程每周3天（月单价50万日元）× 2个案件 ＝ 月100万日元（同时承接多个案件）
  • 常驻每周5天（月单价85万日元）× 1个案件 ＝ 月85万日元

单价谈判在“合同续签的时机”成功率最高。下面讲解实际工作中可用的谈判方法。

谈判的合适时机：

  • 合同续签前 1～2 个月（最重要）
  • 刚掌握或验证了新技术、新技能之后
  • 在项目中取得重大贡献成果之后
  • 收到其他代理公司高单价项目的邀约时（竞争性提案）

单价谈判的步骤：

  • 把握市场行情： 通过注册多家代理公司并进行咨询，确认自己技能的市场价值
  • 整理业绩： 准备“在该项目中实现了○○，将处理速度提升了 30%”等定量化的业绩
  • 明确提案依据： 以“市场行情、其他公司邀约、自身业绩”作为依据提出
  • 提出替代方案： 如果难以提高单价，可提出“减少工作时间”“改为远程”等替代条件
  • 让多家代理公司形成竞争： 将其他代理公司所报的单价作为谈判筹码

谈判时的错误示范：

  • 没有依据地要求“希望再提高一些”
  • 在谈单价的同时还要求放宽工作条件（要求过多）
  • 谈判不顺就立即解除合同（在没有下一个项目准备的情况下解约风险很高）

在实现单价最大化方面，获得终端直签项目（直接对接客户的项目）最为有效。获得终端直签项目的方法主要有三种。

①利用专注于高单价、终端直签项目的代理公司

选择终端直签项目比例较高的代理公司，可以缩短商流链条，提高到手单价。选择代理公司时，务必确认“终端直签项目的比例”和“平均单价”。

②通过 SNS 和技术内容输出获得直接邀约

通过在 X（原 Twitter）、Zenn、Qiita、GitHub 上持续输出技术内容，来自企业招聘负责人和 CTO 的直接邀约越来越多。尤其是“LLM 与 AI”“云架构”“产品开发”领域的内容输出反响较大。

③通过人脉和内推获得项目

来自现有客户的介绍或工程师朋友的项目推荐，由于不经过代理公司，单价往往更高。参与社区（学习会、技术大会、Slack）并建立人脉，有助于长期提升单价。
