FDE 作品集的制作方法｜5 种媒介的分工与按经历选择题材

原标题：FDEポートフォリオの作り方｜5媒体の役割分担と経歴別の題材選び

FDE総研 · 2026-11-18 · 约 11 分钟读完

摘要

FDE総研（VACAN Technologies运营）面向想成为前沿部署工程师的工程师，讲解作品集的构建方法。文章指出FDE作品集的核心不是展示技术广度，而是证明“导入的可再现性”，即能否在其他客户现场重复完成从课题定义、现场实施到落地定着的全过程。作者将可再现性拆为三要素，并给出首页、案例页、README、演示视频、面试五种媒介的分工，强调定量成果需写明基准值、测量方法、期间与个人负责范围，保密信息应抽象化处理。最后按经验年限、现职、英语能力、目标企业规模给出选题建议，并提醒公开前检查保密、凭证、链接与复现步骤。

要点

  • FDE作品集的核心是证明导入的可再现性，而非技术广度。
  • 可再现性分为课题定义、约束下的实施判断、定着机制三要素。
  • 首页、案例页、README、演示视频、面试五种媒介各答一个问题。
  • 定量成果须写明基准值、测量方法、期间与个人负责范围。
  • 选题按工程缺口、语言要求、经验年限的优先级决定。

FDE（Forward Deployed Engineer，前沿部署工程师）是一种深入客户现场、负责从课题定义到实现再到现场落地的职业，由 Palantir 首创。由 VACAN Technologies 运营的 FDE 总研，用“责任范围”和“可复现性”这同一把尺子来衡量 FDE 的职业发展与实务。本文将从“5 种媒介的分工”和“按经历选择题材”这两个维度，梳理立志成为 FDE 的工程师应如何制作作品集。文书的写法已在FDE 履历书的写法中总结，这里介绍文书之外的展示方式。

什么是 FDE 作品集？招聘方所看的“引入的可复现性”是什么？

FDE 作品集是一套证据集，用来证明你能够复现 Palantir 式的课题定义、现场实现、落地落地这三个阶段。

普通工程师的作品集展示的是“能做出什么”。与此相对，FDE 作品集需要展示的是“能否在其他客户的现场同样完成引入”。Palantir 的官方博客将 Forward Deployed Software Engineer 的一天，介绍为从与客户对话到数据对接和实现的一系列连续工作。

招聘方想确认的不是技术广度，而是引入的可复现性

FDE 的招聘负责人想确认的，不是会用的技术数量，而是能否在其他客户那里重新完成同样的引入。

FDE 的分配岗位不同，客户的行业和数据也会不同。因此，仅有一个成功案例很难获得评价。Gergely Orosz 的新闻通讯 The Pragmatic Engineer 也将 FDE 介绍为在客户身边进行工程工作的职业。最好预设读者会以“每个现场条件都不同”为前提来阅读。

FDE 总研将引入的可复现性分为 3 个要素

FDE 总研将引入的可复现性分为“课题定义的思路”“约束下的实现判断”“落地的机制”三个要素来评价。

表 1：引入可复现性的 3 要素与作品集中应展示的证据（FDE 总研编辑部整理，截至 2026 年 11 月）

要素作品集中应展示的证据常见缺失之处
课题定义的思路被委托的内容与实际解决的课题之间的差异只写了照原样实现委托内容的经过
约束下的实现判断预算、数据、权限的约束以及未采用的方案只罗列了所采用的技术名称
落地的机制交接资料、运维流程、使用情况的确认方式写到发布就结束了

从在 VACAN Technologies 查看引入项目的立场来看，比起演示能否运行，我们更看重是否有确认现场负责人之后是否持续使用的记录。第三个“落地”是个人开发中难以展示的要素。即便如此，只要事先设计好如何查看使用日志，就能与其他应聘者拉开差距。

FDE 作品集应该在哪种媒介上放什么？首页、项目页面、README、演示视频、面试的分工是什么？

FDE 作品集将首页、项目页面、README、演示视频、面试这 5 种媒介，根据读者愿意投入的时间来区分使用。

如果把同样的内容在 5 个地方重复书写，读者会不知道该看哪里。FDE 总研建议让每种媒介只回答“一个问题”。

表 2：FDE 作品集 5 种媒介的分工（FDE 总研编辑部整理，截至 2026 年 11 月。读者时间仅为参考）

媒介主要读者与时间参考要回答的问题应放的内容不应放的内容
首页书面筛选负责人／大致浏览是解决什么课题的人3 件左右代表性项目的一句话摘要只有技术栈清单
项目页面现场 FDE、EM／仔细阅读如何解决了什么课题、约束、判断、结果、局限客户名称或内部数值
README工程师／动手验证如何运行架构图、安装步骤、设计上的权衡面向销售的宣传语
演示视频包括非技术背景的面试官在现场如何被使用以使用者视角操作的流程没完没了的代码讲解
面试整个招聘团队为什么那样判断没写出来的失败以及从中学到的东西朗读页面上已写的内容

首页和项目页面应先展示“解决了什么”

在 FDE 作品集的首页和项目页面中，应先写解决的课题和客户的约束，而不是先写用过的技术。

项目页面按“状况→判断→结果→局限”四段来写，面试中被深挖的场景就会直接成为标题。重要的是不要省略最后的“局限”。因为 FDE 的面试中，如何传达不顺利的地方往往是被考察的重点。

README 和演示视频负责“如何运行”，面试负责“为什么那样判断”

FDE 作品集的 README 和演示视频是展示“可运行证据”的载体，判断的理由则默认留到面试时再讲。

README 中要简短写明可按步骤复现的环境搭建方法，以及考虑过但最终放弃的设计方案。演示视频不要以代码画面为主，而要以现场用户的操作为中心来编排。这样，非技术背景的业务面试官也能理解其价值。

FDE 作品集的优秀范例和反面案例的区别是什么？定量成果和保密信息该怎么写？

FDE 作品集的优秀范例是以附带测量方法的前后对比来展示成果，保密信息则按照个人信息保护委员会的思路进行抽象化处理。

表3：FDE 作品集的优秀范例与反面案例（FDE 总研编辑部整理，截至2026年11月）

视角优秀范例反面案例
成果结合基准值、测量方法、期间来描述变化只写“大幅提升了效率”
担当范围区分自己做出判断的部分和团队的成果把团队整体的成果写得像自己的成果
课题并列呈现委托的内容和最终解决的课题从技术选型开始讲起
保密抽象到行业、规模、课题类型为止保留能识别客户的画面或公司名称

定量成果要用“基准值、测量方法、期间、自己的担当范围”这4点来写

FDE 作品集的定量成果，只有同时具备基准值、测量方法、期间、担当范围这4点，才能成为可被评价的材料。

如果手头没有数据，请不要勉强编造数字。取而代之，写明“采用了用哪个指标来测量的设计”。招聘方想看的不是数字的大小，而是你能否自己设计出衡量成果的机制。

保密信息要抽象到行业、规模、课题类型为止，并事先取得公开许可

在 FDE 作品集中处理保密信息时，要改写到无法识别客户的抽象程度，并事先确认前公司的规定和公开许可。

“零售业、数百家门店规模、库存数据割裂”这样的粒度，就能传达出课题的类型。画面截图和示例数据要使用重新制作的假数据。如果前公司的工作规则或保密协议的范围不明确，放弃公开也是现实的选择。

根据工作年限、现职、英语能力、企业规模，FDE 作品集的题材会有什么不同？

FDE 作品集的题材会因工作年限、现职、英语能力、企业规模这4个条件而不同。FDE 总研建议优先选择能弥补现职中缺失环节的题材，并对照FDE 职种解说来选择。

用工作年限和现职决定题材的“主角”

作为 FDE 作品集主角的题材，应优先选择能弥补现职中经验不足环节的内容。

表4：按工作年限、现职选择题材（FDE 总研编辑部整理，截至2026年11月）

前提条件作为主角的题材补充的题材
工作经验不足3年的 SWE自己定义身边业务课题的小型导入对用户的访谈记录
工作经验5年以上的 SWE担当到正式上线运营的改进案例从需求定义开始参与的经过
IT 咨询顾问把建议亲自落实到实现环节的原型README 和可复现的代码
PdM用自己提出假设的原型进行验证的案例数据对接的实现
SIer重新把握规格背后业务课题的案例上线后推广落地的用心

根据英语能力和目标企业规模调整载体的语言和粒度

FDE 作品集的语言和粒度，根据目标是外资大企业还是国内初创公司来调整，是比较现实的做法。

如果目标是外资或全球化招聘的企业，要用英语准备 README 和项目页面的摘要，并预设面试中用英语说明的场景。如果目标是国内初创公司，用日语写到业务背景层面更容易获得好评。关于英语准备，FDE 所需的英语能力也可供参考。

当条件之间发生冲突时，优先考虑“环节缺失”

当 FDE 作品集的各条件发生冲突时，FDE 总研按“环节缺失→语言要求→工作年限”的顺序优先判断。

例如，英语能力强但工作年限短的人。比起先充实英语资料，应优先制作一个从课题定义到落地推广全流程都经历过的小型案例。英语能力可以在面试中展示，但经历过一系列环节这一点，没有题材就无法展示。

面向 SWE、IT 咨询顾问、PdM、SIer 的作品集与面向 FDE 的有何不同？什么样的人不适合 FDE？

面向 FDE 的作品集，其不同之处在于把 SWE、IT 咨询顾问、PdM、SIer 的优势，汇总展示在Palantir式的单一导入案例中。

各职种的作品集“成果的切分点”各不相同

SWE、IT 咨询顾问、PdM、SIer 的作品集，在成果从哪里切分这一点上，与面向 FDE 的作品集不同。

表5：各职种作品集的比较（FDE 总研编辑部整理，截至2026年11月）

职种展示的核心内容成果的切分点面向 FDE 需补充的内容
SWE代码质量与设计合并、发布如何定义客户课题
IT 咨询顾问分析与建议建议被采纳自己实现的部分
PdM规划与路线图功能发布现场的数据对接
SIer按规格交付验收参与到运营落地为止
FDE导入的可复现性在现场取得成果时（把这一列的全部内容贯穿于一个案例中）

各职种的区别也在FDE 与 SWE 的区别、FDE 与 IT 咨询顾问的区别、FDE 与 SIer 的区别中进行了比较。

不适合 FDE 的人在制作作品集的阶段就会显现出来

不适合 FDE 的倾向，容易体现在制作作品集时是否想回避课题定义和用户访谈上。

想专注于规格已确定的开发的人，或与客户反复沟通会感到强烈压力的人，可能更适合在 SWE 或产品开发的岗位上发挥实力。关于是否适合的整体分析，请参见适合 FDE 的人。

公开或提交 FDE 作品集之前应该确认什么？

FDE 作品集在公开前，需确认保密、凭证、链接失效、应聘对象要求这 4 点，凭证可通过 GitHub 的密钥扫描 等方式进行检查。

公开前的检查清单：确认 4 点

在公开 FDE 作品集之前，要按顺序确认保密信息、凭证、链接失效、复现步骤这 4 点。

  • 客户名称、个人信息、内部数据是否残留在截图、代码、提交历史中
  • API 密钥和令牌是否包含在仓库中（包括过去的提交）
  • 演示的 URL 和视频链接是否失效
  • 是否能按照 README 的步骤，在本地以外的环境中运行

应聘手续应在官方招聘页面完成，作品题材按应聘对象重新排序

由于应聘 FDE 的手续只能在各公司的官方招聘页面完成，因此 FDE 作品集方面需要根据应聘对象调整题材的排列顺序。

分析应聘方的招聘要求是重视数据平台，还是重视 LLM 的生产环境运维。在此基础上，调整首页展示的代表性案例的顺序。应聘对象候选名单整理在 招聘 FDE 的企业，面试对策整理在 FDE 面试常见问题。
