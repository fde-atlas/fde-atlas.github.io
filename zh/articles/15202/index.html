摘要

FDEInterviews 发布的付费指南《Agentic System Design Round》包含 10 个原创设计案例，共 39 页，围绕客户约束讲解 AI Agent 系统设计，如权限校验、退款超时对账、审批绑定与评测局限，并附 15 个 Python 校验脚本。

要点

  • 10 个案例均以客户约束驱动架构设计。

  • 所有场景为教学示例，非真实面试题。

十个需要围绕其进行设计的客户约束。

  • 案例 01 权限背后的答案 对检索到的文档进行授权，并在派发答案前检查访问权限。
  • 案例 02 超时的退款 将未知结果与失败区分开来，并在下一次写入前完成对账。
  • 案例 03 带审计轨迹的发票 将抽取证据与人工审核容量及 ERP 过账决策连接起来。
  • 案例 04 权限边界很小的 MCP 网关 将工具参数与权限分离，并让凭据保持在模型上下文之外。
  • 案例 05 在早晨前完成批处理 根据截止时间规划工作进程并发数、Token 配额与重试开销。
  • 案例 06 让无法完成的 AI Agent 停下来 在模型之外强制执行执行限制，并保留一次有用的交接。
  • 案例 07 在计划变更后依然有效的审批 将审批绑定到确切的提案上，并处理重复派发。
  • 案例 08 在不失控的前提下替换规则引擎 保持唯一权威写入者，并定义回滚后遗留的修复工作。
  • 案例 09 能够阻止发布的评测 将被禁止的效果与平均质量区分开来，并正确解读零失败。
  • 案例 10：带支出上限的研究 Agent 用关键路径、证据要求和共享预算来论证并行化的合理性。

不是。案例、对话、工作负载和价格均为原创的合成教学示例。一手工程参考资料支持其中的机制，但并不代表雇主的面试形式或招聘结果。

配套材料验证什么？

十五项确定性 Python 检查会重新计算演算数字并测试选定的合成不变量，包括退款重放和审批绑定。它们仅使用标准库，无需 API 密钥。它们不验证真实的服务提供商、LLM 质量或并发数据库行为。

我应该如何使用在线学习路径？

在阅读案例的演算设计之前，先尝试自己完成该案例。然后利用链接的概念、问题和课程内容，研究你无法论证的那个决策。这些资源保持其现有的访问级别。
