FDE 在项目结束时留下什么

原标题：What an FDE Leaves Behind at the End of an Engagement

Falkster.AI · 2026-11-19 · 约 2 分钟读完

摘要

文章认为传统交接文档记录的是结论，一旦客户情况变化便失效。作者以 LivePerson 的 Marco Di Santo 为例，介绍用视频转录自己推理过程来构建决策 Agent 的方法，该 Agent 基于客户规模、合同结构、风险偏好、监管环境和续约临近度五个维度回答问题，能覆盖文档无法穷尽的组合。

要点

  • 交接文档记录结论，情况一变就失效。
  • Marco Di Santo 在 LivePerson 用视频转录构建决策 Agent。
  • Agent 基于五个维度回答问题，覆盖完整决策树。
  • 关键是在离职前一周完成录制，而非离开之后。

全文

我见过的最好的交接文档详尽、准确，但到第二周就没用了。

它详尽，是因为离职的工程师很用心；它准确，是因为他在离开前一周凭记忆写成的；它到第二周就没用，是因为它描述的情形并不是后来实际出现的情形。

文档是在撰写时所处的条件下对结论的记录。而 FDE（前沿部署工程）工作所处的条件在不断变化。客户的优先级会变，合同会以不同的条款续签，新的利益相关者会接手这段关系。文档不会自我更新。而那些本可以应对这些变化的工程判断力，早已随人而去。

决策 Agent 能捕捉什么

Marco Di Santo 在离开 LivePerson 的职位之前，构建了一个决策 Agent。原始素材是他自己针对真实决策进行推理的视频转录稿。不是结论，而是出声的推理过程。

这个 Agent 基于五类问题运行：

  • 这项建议会因客户规模和战略重要性的不同而如何变化？
  • 它会因合同结构（用量、席位、基于成果）的不同而如何变化？
  • 它会因客户明确表达的风险承受度不同而如何变化？
  • 它会因监管环境的不同而如何变化？
  • 它会因距离续约时间的远近而如何变化？

这五个维度并不是别人让他使用的分类。转录稿揭示了他本来就在隐式使用的结构。他做出的每一个真实决策，都可以用他所权衡的那五个维度的组合来解释。

文档无法捕捉到这一点。文档只给你某一种组合下的答案，而这个 Agent 掌握的是完整的决策树。

最后一周该构建什么

视频转录方法之所以有效，是因为它能挖掘出你不会想到要写下来的推理过程。另一种方法是：把自己回答以下五个问题的过程录下来，就像在向接替者讲解一样。

先从那些你会放慢脚步而不是直接推进的情形开始。然后是哪些捷径是安全的，哪些看似安全实则不然。然后是这个客户说他们想要什么与实际需要什么。然后是每一次重大决策沟通中应该有谁参与。最后是什么样的条件成立时，你会建议暂停这个项目。

没有任何文档能为五个维度的 32 种组合保存这些答案。决策 Agent 可以。关键在于，要在你离开的前一周把它构建好，而不是在你走后的一周。
