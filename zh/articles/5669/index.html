第 37 天：用户研究与客户云 | AI FDE 课程

原标题：Day 37: User research and customer cloud | AI FDE Course

Plank · 2026-10-25 · 约 10 分钟读完

摘要

本文是 Plank 的 AI FDE 课程第 37 天，主题为用户研究与客户云环境交付。WorkBot 已在隔离环境中就绪，但尚未验证客户团队能否自行接管。课程内容涵盖发布检查清单、面向客户安全评审的单页说明、研究计划、五场可用性测试（由 Agent 扮演部署工程师、运维负责人、安全评审者、值班工程师和财务经理五个角色），以及将观察整理为带证据和严重程度的发现页。参考实现中发现了 API 缺失与顺序错误、问卷时态失实等问题，最严重的三项当天修复，其余进入待办清单。

要点

  • 交付测试：他人仅凭 runbook 部署 WorkBot，全程观察不插手
  • 五场可用性测试由 Agent 扮演客户五个角色完成
  • 发现须包含行为、证据与后果，区别于观点
  • 参考实现中三个 Google Cloud API 及服务 Agent 缺失或顺序错误
  • 最严重三项发现当天修复，其余记入待办

全文

发布检查清单

在任何人使用 WorkBot 之前，先确认客户依赖它时必须满足哪些条件。检查清单把这些条件转化为可以标记为“已完成”、“计划中”或“待处理”的项目，每一项都注明检查的位置。

先学习

  • 了解在 WorkBot 服务客户之前必须满足哪些条件。评测和负载测试在发布版本上通过，坏的发布版本可以回滚，系统可以从代码恢复。密钥、加密、备份、监控、支出告警和隔离均已就绪。运维手册已存在，保留策略已强制执行，安全审查包已准备好，并且有负责人随时待命。
  • 阅读 Google 站点可靠性工程（Site Reliability Engineering）一书中关于可靠的产品发布章节中的发布检查清单。其检查清单的每个领域，从依赖和容量到故障模式和发布流程，都有相应的问题及其引出的行动项。

构建

  • 编写 docs/release-checklist.md，将每一项标记为已完成、计划中或待处理，并注明检查的位置。当某一项需要云账户时，请说明。在参考运行中，检查清单是针对第 35 天和第 36 天的本地集群运行的，该集群由流水线脚本从零重新创建。
  • 用代码弥补检查清单发现的缺口。在 /api/health 上添加正常运行时间检查，并添加一个每月 预算，在 50%、90% 和 100% 时发出告警。将两者都放在 infra/gcp 中，并在其测试中进行断言。

完成标准

  • 每一项都已完成，或明确说明它在等待什么。
