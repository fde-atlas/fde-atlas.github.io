使用 Python 从 Greenhouse API 获取 FDE 薪资数据

原标题：FDE Salary Data from the Greenhouse API with Python

FDE Times · 2026-10-29 · 约 7 分钟读完

摘要

这篇教程用约 40 行 Python 调用 Greenhouse 公开的 Job Board API，抓取美国州薪酬透明法要求披露的薪资区间，筛选前沿部署工程师职位并导出 CSV。文章强调金额以“分”为单位需除以 100，并提醒保留无薪资区间的职位以反映数据覆盖率。文中引用 Valletta Software 2026 年 9 月 8 日的数据：Palantir 52 个美国职位中仅 21 个公布薪资区间，并给出 Anthropic、OpenAI、Palantir 的基准薪资供校验。作者指出这类技能正是 FDE 在客户现场处理陌生 API 与脏数据的日常。

要点

  • Greenhouse Job Board API 无需密钥，但须加 pay_transparency=true 才返回薪资区间。
  • 薪资字段 min_cents 与 max_cents 以分为单位，5000000 实为 5 万美元。
  • Palantir 52 个美国 FDE 职位中仅 21 个公布薪资区间，缺失数据须保留统计。
  • 基准：Anthropic 28 万至 32 万美元，OpenAI 18.5 万至 30 万，Palantir 12.5 万至 20 万。
  • 作者认为抓取、清洗、报告数据缺口的流程正是 FDE 的日常工作技能。

大约 40 行 Python 代码就能提取各州透明度法律强制要求在招聘广告中公布的薪资范围，然后写入 CSV 文件。

简要说明

  • Greenhouse 职位板的 GET 端点无需 API 密钥，但只有传入 pay_transparency=true 才能获得薪资范围
  • 金额存储在 min_cents 和 max_cents 中，因此 5000000 表示 50,000.00 美元
  • 没有薪资范围的职位很常见：Palantir 的 52 个美国职位中只有 21 个列出了薪资范围

Greenhouse 文档中的一个数字就可能让整张薪资表出错：

"min_cents":5000000

。如果忘记它以“分”为单位，你会以为某个职位的年薪是 500 万美元，而实际数字是 50,000.00 美元。

本指南将展示如何避开这类小陷阱。你将编写一个简短的 Python 脚本，调用 Greenhouse 的公开职位 API，筛选出前沿部署工程师职位，把薪资范围转换为易读的单位，并将结果写入 CSV 文件。

最终你会得到一张自己动手构建的 FDE 薪资表，附带数据来源和拉取日期，而不是口口相传的数字。

这张表在你准备谈判录用条件时很有用。更大的收获是这项技能：调用陌生的 API、阅读其数据结构、统一单位、处理缺失数据，这些都是面向客户的前沿部署工程师日常工作的一部分。

为什么 API 里会有薪资范围？

主要是因为法律。据律师事务所 Foley & Lardner 称，科罗拉多州要求每个招聘广告都包含薪资信息，如果雇主在该州至少有一名员工，这一要求也涵盖远程职位。加州要求受该法规约束的雇主在招聘广告中注明薪资范围，包括由第三方发布的广告。

纽约市也要求招聘广告注明至少部分在该市执行的工作的最低和最高年薪，或时薪。这就是为什么旧金山或纽约的 FDE 职位通常带有薪资范围，而 Greenhouse 通过其 API 公开这些数据。

请记住这一后果。你收集的数据主要反映的是法律强制要求披露薪资的美国市场。不要用它来推断其他市场的薪资水平。

写代码之前需要准备什么？

你需要 Python 3 和

requests

库（

pip install requests

）。无需 API 密钥：Greenhouse 文档说明职位板数据是公开的，因此 GET 端点无需身份验证。

你需要自己找到的是 board token，即公司在 API 路径中的标识符。最快的方法是打开该公司的招聘页面。如果该页面由 Greenhouse 托管，公司标识符通常会出现在 URL 中。把它当作一个实用捷径，然后通过下面的第 1 步加以确认。

第 1 步：调用端点并在信任它之前检查其结构

职位列表端点的形式为

GET https://boards-api.greenhouse.io/v1/boards/{board_token}/jobs

。添加

content=true

因此每个职位发布都包含完整描述、部门和办公室。添加

pay_transparency=true

以接收

pay_input_ranges

数组；一篇 Greenhouse 支持文章也证实，只有开启此参数时才会返回薪酬数据。

import requests

BOARD = "company_board_token"
URL = f"https://boards-api.greenhouse.io/v1/boards/{BOARD}/jobs"

resp = requests.get(
    URL,
    params={"content": "true", "pay_transparency": "true"},
    timeout=30,
)
resp.raise_for_status()
data = resp.json()
print(data.keys())

检查：调用不会引发 HTTP 错误，并打印顶层键。以下代码假设职位发布位于

jobs

键下，且每个职位发布都有一个

title

字段。这是一种简化，因此请对照你刚打印的输出进行确认。

第 2 步：筛选 FDE 职位

并非每家公司都使用完全相同的职位名称。简单的方法是根据标题中的字符串进行筛选，然后自己通读列表。

jobs = data.get("jobs", [])
fde_jobs = [
    j for j in jobs
    if "forward deployed" in (j.get("title") or "").lower()
]
print(len(jobs), len(fde_jobs))
for j in fde_jobs:
    print(j.get("title"))

检查：打印每个筛选后的标题。如果你看到不属于该职位的标题，或者你知道该公司对该职位的称呼不同，请立即调整筛选条件，而不是等到表格生成数字之后再调整。

第 3 步：将“分”转换为货币单位，并保留没有薪酬范围的职位发布

这一步决定表格是否正确。Greenhouse 文档中的示例 JSON 显示，每个薪酬范围都有

min_cents

,

max_cents

和

currency_type

，因此你必须除以 100。代码使用

.get()

，这样缺少某个字段的范围不会使脚本中途停止，符合“绝不盲目信任数据结构”的原则。

def cents(value):
    return value / 100 if value is not None else None

def to_rows(job):
    ranges = job.get("pay_input_ranges") or []
    if not ranges:
        return [{"title": job.get("title"), "min": None,
                 "max": None, "currency": None}]
    return [{
        "title": job.get("title"),
        "min": cents(r.get("min_cents")),
        "max": cents(r.get("max_cents")),
        "currency": r.get("currency_type"),
    } for r in ranges]

rows = [row for j in fde_jobs for row in to_rows(j)]

用文档中的数字测试：5000000 除以 100 得到 50,000.00，7500000 除以 100 得到 75,000.00 美元。如果你的表格中某个工程职位的数字达到七位数，那你几乎肯定是忘了除以 100。

为什么要保留未列出薪酬的职位发布？因为它们的数量比你想象的要多。根据 Valletta Software 于 2026 年 9 月 8 日整理的数据，Palantir 的前沿部署软件工程师薪酬范围仅出现在 52 个美国职位发布中的 21 个里。去掉其余 31 个，你就无法知道你的表格代表了市场的多大比例。

第 4 步：写入 CSV 并统计有薪酬信息的职位发布数量

一个职位发布可以包含多个薪酬范围，因此 CSV 中的行数并不等于职位发布的数量。因此，覆盖率统计必须按职位发布进行，这样你的数字才能与“52 个职位发布中的 21 个”之类的数据相比较。

import csv
from datetime import date

with open(f"fde_pay_{BOARD}_{date.today()}.csv", "w", newline="") as f:
    w = csv.DictWriter(f, fieldnames=["title", "min", "max", "currency"])
    w.writeheader()
    w.writerows(rows)

covered = sum(1 for j in fde_jobs if j.get("pay_input_ranges"))
print(f"{covered}/{len(fde_jobs)} postings with a pay range")

检查：打开文件并阅读几行，然后将此处打印的职位发布数量与第 2 步的结果进行比较。文件名包含数据拉取的日期，因为薪酬范围会变化，你的表格仅在运行它的那一刻是准确的。

你如何知道你的表格是正确的？

将其与已公布的薪酬范围进行比较。同样根据 Valletta Software 于 2026 年 9 月 8 日整理的数据，以下是三个基准：

公司基本薪酬范围比较时需注意的事项
Anthropic$280,000 至 $320,000职位发布地点为纽约、旧金山、西雅图
OpenAI$185,000 至 $300,000该范围之外还有股权
Palantir$125,000 至 $200,000股权和奖金在该范围之外

如果你的表格与这些基准相差甚远，先怀疑你的筛选逻辑或除法运算，而不是怀疑市场。最后一列还提醒了一个常被遗忘的事实：这些是基本工资，而非总薪酬。在不提及股权的情况下，将 Palantir 的中位数（162,500）与 OpenAI 的（242,500）进行比较是有缺陷的比较。

最常见的错误

最常见的错误是忘记

pay_transparency=true

并由此得出该公司不公布薪酬的结论。其次是忘记除以 100、在同一列中平均不同货币的数值，以及将没有薪酬范围的职位视为薪酬为零。

一个更隐蔽的错误是在循环中反复调用 API 而没有停止条件。不需要密钥的 API 并不意味着可以随意调用；对于薪酬表格来说，每天运行一次就足够了。

这项技能在客户现场如何体现？

想象你在一家物流客户处的第一周：你需要从一个从未见过的系统中提取订单数据。流程几乎完全相同：发起一次请求，打印结构，确认单位（是分还是美元，是秒还是毫秒），然后在构建任何仪表板之前，先统计有多少记录缺少关键字段。

所以表格完成后，不要把它据为己有。把它放到 GitHub 上，并附上一个 README，说明数据日期、包含薪酬的职位占比，以及表格的局限性。

在简历上，诸如“构建了一条流水线，用于收集公开薪酬范围、统一单位并报告缺少薪酬数据的职位占比”这样一句话，能让 FDE 招聘人员确切地看到他们想看的东西：你能够处理真实、杂乱的数据，并清楚地说明它的可信程度。

薪酬表格几周后就会过时。但先打印结构、再统计缺失的习惯在每个客户那里都适用。
