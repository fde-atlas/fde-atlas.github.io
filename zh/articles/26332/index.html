FDE 薪资怎么查：用 Greenhouse API 自建薪资表

FDE Times · 2026-10-29 · 约 6 分钟读完

摘要

本文是一篇技能教程，讲解如何用约 40 行 Python 调用 Greenhouse 公开的 Job Board API，抓取薪酬透明法要求公布的薪资范围，自建 FDE 薪资表并写入 CSV。关键陷阱包括：必须加 pay_transparency=true 参数才会返回薪资数据；金额单位是分，5000000 实为 5 万美元；需保留未标薪资的岗位并统计覆盖率。文章还提醒数据主要反映美国市场，并给出 Anthropic、OpenAI、Palantir 的基准薪资范围供校验。

要点

  • Greenhouse 公开接口无需密钥，但需加 pay_transparency=true 才返回薪资范围。
  • 金额字段单位是分，5000000 表示 5 万美元，忘记除以 100 是最常见错误。
  • Palantir 美国 52 个岗位中仅 21 个标明薪资，缺失数据应保留并统计覆盖率。
  • 薪酬公开源于科罗拉多、加州和纽约市的法律要求，数据不能推广到其他市场。
  • 文中流程与 FDE 客户现场工作高度相似：先看结构、确认单位、统计缺失。

约 40 行 Python 抓取薪酬透明法强制公开的薪资范围，并写入 CSV。

要点速览

  • Greenhouse Job Board 的 GET 接口不需要 API 密钥，但只有传入 pay_transparency=true 才会返回薪资范围
  • 金额存放在 min_cents 和 max_cents 中，5000000 表示 50,000.00 美元
  • 不标薪资范围的岗位很常见：Palantir 在美国的 52 个岗位中只有 21 个标明了薪资

Greenhouse 文档里有一个数字，足以让整张薪资表出错：

"min_cents":5000000

。忘了它的单位是分，你会以为这个岗位年薪 500 万美元，而实际是 50,000.00 美元。

本文教你避开这类小陷阱。你将写一个简短的 Python 脚本：调用 Greenhouse 的公开岗位 API，筛选出前线部署工程师（FDE）岗位，把薪资范围换算成易读的单位，再把结果写入 CSV 文件。

最终你会得到一张自己动手做的 FDE 薪资表，注明数据来源和抓取日期，而不是口口相传的数字。

如果你正准备谈 offer，这张表会有用。但更大的收获是技能本身：调用陌生的 API、读懂数据结构、统一单位、处理缺失数据，正是 FDE 在客户现场的日常工作。

为什么 API 里会有薪资范围？

主要是法律要求。据律所 Foley & Lardner 介绍，科罗拉多州要求每个招聘岗位都附上薪资信息，只要雇主在该州至少有一名员工，远程岗位也包括在内。加州要求受监管的雇主在招聘信息中列出薪资范围，第三方发布的招聘信息同样适用。

纽约市也要求，凡是至少部分在该市工作的岗位，招聘信息都须写明最低和最高年薪或时薪。所以旧金山、纽约的 FDE 岗位通常带有薪资范围，Greenhouse 也通过 API 提供这些数据。

要记住这一点带来的后果：你收集到的数据主要反映美国市场，因为那里的法律强制公开薪资。不要用它推断其他市场的薪资。

写代码之前需要准备什么？

你需要 Python 3 和

requests

库（

pip install requests

）。不需要 API 密钥：Greenhouse 文档写明 Job Board 数据是公开的，GET 接口无需认证。

需要自己找的是 board token，也就是 API 路径中的公司标识。最快的办法是打开公司的招聘页面：如果页面托管在 Greenhouse 上，公司标识通常就在 URL 里。这只是一个实用的捷径，找到后再用下面的第 1 步确认。

第 1 步：调用接口，先查看结构再信任它

岗位列表接口的形式是

GET https://boards-api.greenhouse.io/v1/boards/{board_token}/jobs

。加上

content=true

，每个岗位会带上完整描述、部门和办公地点；加上

pay_transparency=true

，才会返回

pay_input_ranges

数组。Greenhouse 的一篇支持文章也确认，只有开启这个参数才会返回薪资数据。

import requests

BOARD = "company_board_token"
URL = f"https://boards-api.greenhouse.io/v1/boards/{BOARD}/jobs"

resp = requests.get(
    URL,
    params={"content": "true", "pay_transparency": "true"},
    timeout=30,
)
resp.raise_for_status()
data = resp.json()
print(data.keys())

检查：调用没有抛出 HTTP 错误，并打印出顶层的键。下面的代码假设岗位位于

jobs

键下，且每个岗位都有

title

字段。这是一种简化，请对照刚才打印的输出确认。

第 2 步：筛选 FDE 岗位

不同公司的岗位名称不一定完全相同。简单的做法是按标题中的字符串过滤，然后自己逐条看一遍。

jobs = data.get("jobs", [])
fde_jobs = [
    j for j in jobs
    if "forward deployed" in (j.get("title") or "").lower()
]
print(len(jobs), len(fde_jobs))
for j in fde_jobs:
    print(j.get("title"))

检查：打印出每个筛选后的标题。如果看到不相关的标题，或者你知道这家公司对该岗位另有叫法，现在就调整过滤条件，别等表格算出数字之后再改。

第 3 步：把分换算成货币单位，保留没有薪资范围的岗位

这一步决定了表格对不对。Greenhouse 文档中的示例 JSON 显示，每个薪资范围都有

min_cents

、

max_cents

和

currency_type

，所以必须除以 100。代码使用

.get()

，这样某个范围缺少字段时脚本不会中途停止，这也符合“绝不盲目信任数据结构”的原则。

def cents(value):
    return value / 100 if value is not None else None

def to_rows(job):
    ranges = job.get("pay_input_ranges") or []
    if not ranges:
        return [{"title": job.get("title"), "min": None,
                 "max": None, "currency": None}]
    return [{
        "title": job.get("title"),
        "min": cents(r.get("min_cents")),
        "max": cents(r.get("max_cents")),
        "currency": r.get("currency_type"),
    } for r in ranges]

rows = [row for j in fde_jobs for row in to_rows(j)]

用文档里的数字测试一下：5000000 除以 100 得到 50,000.00，7500000 除以 100 得到 75,000.00 美元。如果你的表里工程岗位出现了七位数的薪资，几乎可以肯定是忘了做除法。

为什么要保留没有标薪资的岗位？因为它们比你想象的多。根据 Valletta Software 整理的 2026 年 9 月 8 日数据，Palantir 的 Forward Deployed Software Engineer 薪资范围只出现在美国 52 个岗位中的 21 个上。丢掉另外 31 个，你就不知道自己的表代表了多大比例的市场。

第 4 步：写入 CSV，统计标明薪资的岗位

一个岗位可能有多个薪资范围，所以 CSV 的行数不等于岗位数。覆盖率必须按岗位统计，这样你的数字才能和“52 个岗位中有 21 个”这类数据对比。

import csv
from datetime import date

with open(f"fde_pay_{BOARD}_{date.today()}.csv", "w", newline="") as f:
    w = csv.DictWriter(f, fieldnames=["title", "min", "max", "currency"])
    w.writeheader()
    w.writerows(rows)

covered = sum(1 for j in fde_jobs if j.get("pay_input_ranges"))
print(f"{covered}/{len(fde_jobs)} 个岗位标明了薪资范围")

检查：打开文件读几行，再把这里打印的岗位数和第 2 步的结果对比。文件名包含数据抓取日期，因为薪资范围会变，你的表只在运行那一刻准确。

怎么知道表格是对的？

和已公开的薪资范围对比。同样根据 Valletta Software 2026 年 9 月 8 日的数据，以下是三个基准：

公司基本薪资范围对比时注意
Anthropic$280,000 至 $320,000岗位位于纽约、旧金山、西雅图
OpenAI$185,000 至 $300,000范围之外另有股权
Palantir$125,000 至 $200,000股权和奖金不在范围内

如果你的表和这些基准相差很远，先怀疑过滤条件或除法，再怀疑市场。最后一列也提醒了一件常被忽略的事：这些是基本薪资，不是总薪酬。拿 Palantir 的中位数（162,500）和 OpenAI 的中位数（242,500）比较却不提股权，这样的对比是有缺陷的。

最常见的错误

最常见的错误是忘了

pay_transparency=true

，然后断定公司没有公开薪资。其次是忘了除以 100、把不同币种放在同一列里求平均，以及把没有薪资范围的岗位当作薪资为零。

更隐蔽的错误是在循环里反复调用 API，没有终止条件。不需要密钥的 API 并不意味着可以随意调用；做薪资表，每天跑一次就够了。

这项技能在客户现场怎么用？

设想你在一家物流客户的第一周：需要从一个从未见过的系统中拉取订单数据。步骤几乎一模一样：发一次请求，打印结构，确认单位（分还是元，秒还是毫秒），然后在搭建任何看板之前，先统计有多少记录缺少关键字段。

所以表格做完后，别只留给自己。把它放到 GitHub 上，在 README 里写明数据日期、标明薪资的岗位占比，以及这张表的局限。

在简历上写一句“搭建数据管道收集公开薪资范围，统一单位，并报告缺失薪资数据的岗位占比”，正好向 FDE 招聘方展示了他们想看到的东西：你能处理真实而杂乱的数据，并清楚说明它可信到什么程度。

薪资表几周后就会过时。先打印结构、再统计缺口的习惯，在每个客户那里都用得上。
