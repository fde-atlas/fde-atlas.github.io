摘要

这篇由DeFactory代表德满翔平撰写的日文长文，系统介绍IT架构师的定义、职责与职业路径。文章将IT架构师定位为把业务需求翻译为系统整体设计的角色，与SE、技术负责人、PM的职责和考核指标不同。文中列出应用、基础设施云、数据、企业级四大专业方向及各自月单价区间，指出AI代码生成降低了实现成本，反而推高了架构决策者的市场价值，并给出自由职业者获取高单价案件的技能、资质与人脉策略。文末附带DeFactory的自由职业平台宣传信息。

要点

  • IT架构师负责将业务需求翻译为系统整体架构，与SE、PM职责不同。
  • 四大专业方向：应用、基础设施云、数据、企业级，月单价约80万至250万日元。
  • AI代码生成降低实现成本，架构决策者的市场价值反而上升。
  • 高单价依赖三大核心技能：技术俯瞰力、非功能需求权衡判断、沟通翻译能力。
  • 超高单价案件多经人脉或特定中介流通，个人品牌是关键。

结论： IT架构师的本质是“翻译者”。其职责是将模糊且动态的业务课题，通过技术选项的比较与权衡判断，翻译为可实现、可运营的系统整体蓝图。他们是承担“在编写代码之前发生的最有价值的决策”的角色。

IT架构师的主要职责整理如下。

  • 业务需求的解释：从经营战略和业务流程中提取对系统的要求
  • 架构设计：定义系统的整体结构、组件划分和数据流
  • 技术选型：选择编程语言、框架、云服务和中间件
  • 非功能性需求的定义：确定可用性、性能、扩展性、可维护性和安全性的目标值
  • 权衡判断：平衡成本、速度、质量和未来扩展性
  • 设计准则的制定：完善开发团队遵循的设计原则和编码规范
  • 架构评审：持续验证实现中的代码是否与设计意图一致

尤其是“非功能性需求的定义”和“权衡判断”，是AI无法替代的、人类独有的判断领域。即使AI代码生成不断进化，“该系统需要99.99%的可用性，还是99.9%就足够了”这类判断，由于涉及对业务背景的理解和责任承担，仍将持续留给人类IT架构师。

结论： IT架构师对“系统本身的质量”负责，PM对“项目进度管理”负责，SE对“个别功能的实现”负责。他们在同一个项目中并肩工作，但被评估的指标（KPI）完全不同。

基于这些背景，IT 架构师被定位为工程师职业中尤其“市场价值不易下降”的职位。

结论： IT 架构师大致分为 4 个专业领域，即“应用”“基础设施与云”“数据”“企业”4 种类型，各自所需的技能、涉及的层级以及典型的单价均有所不同。根据自身背景和目标职业方向选择专业领域非常重要。

结论： 应用架构师是“设计业务应用软件结构”的专家。包括微服务拆分、领域驱动设计（DDD）、API 网关设计等，可以说是最贴近代码层面的架构师职位。月单价主要集中在 90 万～130 万日元的区间。

应用架构师的主要设计对象如下。

  • 组件拆分：定义领域边界、微服务 vs 模块化单体（Modular Monolith）选型
  • 设计模式应用：CQRS、事件溯源、Saga 模式等的选择
  • API 设计：REST、GraphQL、gRPC 的区分使用、API Gateway 架构
  • 前端结构：BFF、SPA、SSR、PWA 的设计选型
  • 测试策略：单元、集成、E2E 测试的责任划分、测试金字塔设计

这一职位是“与代码密切相关的架构师”，仍保留着现役工程师的色彩。作为从 Tech Lead 自然晋升的方向，是人气很高的职位。

结论： 基础设施与云架构师是设计“让系统稳定运行、并在需要时能够扩展的基础平台”的专家。以 AWS、Azure、GCP 等云设计为中心，端到端地承担网络、安全与成本优化。月单价主要集中在 100 万～150 万日元。

结论： 数据架构师是“整合企业内分散的数据，设计能够支撑分析与 AI 应用的基础平台”的专家。需要具备数据湖仓（Lakehouse）、ETL/ELT、数据治理、主数据管理（MDM）方面的知识。月单价主要集中在 100 万～160 万日元的区间，是生成式 AI 时代最受关注的领域之一。

数据架构师的典型设计职责如下。

  • 数据平台架构：数据湖、DWH、数据集市（Data Mart）的架构设计
  • 数据管道：ETL/ELT/Reverse ETL 的编排设计
  • 数据建模：3NF、维度建模、Data Vault 的选型
  • 数据治理：数据目录、血缘（Lineage）、质量规则的完善
  • 主数据管理：客户主数据、商品主数据的整合与同步设计
  • 访问控制：行级、列级安全、PII 保护的设计
  • AI/ML 集成：特征存储、向量数据库、RAG 数据平台的整合

这一职位与生成式 AI（RAG）的生产环境运维需求密切相关，在 2025～2026 年市场价值迅速攀升。从数据工程师晋升是主流路径，但能否深入到数据的“设计”“质量”“治理”层面则是分水岭。

结论： 企业架构师（EA）是“整合经营战略与 IT 战略，设计企业整体 IT 投资优化”的最高级别架构师。其对象不是单个系统，而是企业整体的 IT 组合（Portfolio）。月单价在 150 万～250 万日元以上的区间，其特点是多担任外部 CIO 助理、IT 战略顾问之类的职位。

EA 的主要框架包括 TOGAF（The Open Group Architecture Framework）、Zachman Framework、ArchiMate 等。同时具备这些体系化知识以及多个行业实施经验的人才，能够获得月薪超过 200 万日元的单价。这一职位也往往被视为 CTO、VPoE 经历者自然的进阶方向，关于组织技术领导力的详细内容，我们在VPoE 与 CTO 的区别是什么？角色定义与高单价独立之道中另行解说。

结论： 高单价 IT 架构师共通的 3 项核心技能是：①“对广泛技术栈的全局把握能力”，②“非功能性需求的定义与权衡判断能力”，③“连接经营层与一线的沟通能力”。只有同时具备这 3 项，月薪超过 150 万日元的单价才能成立。

结论： IT 架构师所需要的，与其说是“对特定技术的深度专业性”，不如说是“以一定分辨率俯瞰广泛技术领域的能力”。不依赖单一语言、单一云平台，能够比较多个选项并阐述其权衡，是赢得信任的前提条件。

尤其在 2026 年的当下，最下方的“AI/ML”正迅速成为与其他架构师差异化的重要因素。现实中，“其他都懂但只有 AI 不懂”的架构师，可选的项目范围正在缩小。

结论： 真正考验 IT 架构师价值的是“非功能性需求的权衡判断”。提高可用性会增加成本，提升性能会增加复杂性，保障可扩展性会拖慢初期开发——能够根据业务背景立即对这一多维优化问题作出判断的能力，是最受评价的能力。

下面整理非功能性需求的典型权衡。

权衡维度例 1例 2
可用性 vs 成本99.99% 运行＋每月 100 万日元99.9% 运行＋每月 30 万日元
性能 vs 复杂性多级缓存＋复杂的失效处理简单架构＋响应稍慢
可扩展性 vs 开发速度微服务＋延迟 3 个月单体架构＋1 个月上线
安全 vs UX强制 MFA＋流失率上升仅密码＋便利性
一致性 vs 可用性（CAP 定理）强一致性＋可用性下降最终一致性＋持续运行

这些权衡的本质在于“没有标准答案”。同样是“Web 服务”，金融服务和内部工具所应选择的设计截然相反。专业的 IT 架构师拥有能够立即说出“就贵公司的业务而言，应选择此方案，理由是……”的判断标准。

结论： IT 架构师必备的第 3 项技能，是“在经营层与一线工程师之间双向翻译语言”的沟通能力。用“投资回报”向经营层阐述技术选型的理由，用“设计约束”向一线传达业务需求——这种翻译能力，正是能够驱动组织的架构师的本质价值。

下面整理构成这项技能的具体行为特征。

  • 与经营层的对话：能够从“业务连续性风险、合规风险、机会损失”3 个维度阐述技术风险
  • 对工程师的指示：能够将抽象需求翻译为设计约束（例如：“API 响应须在 200ms 以内”）
  • 与供应商的谈判：能够从技术上分解报价依据，识破不合理的高价报价
  • 利益相关者协调：能够将多个部门相互对立的要求转化为优先级讨论
  • 失败时的说明责任：发生故障时，能够冷静地向经营层说明状况、影响与对策
  • 资料制作能力：能够用一张架构图引出决策的可视化能力

尤其是最后的“一张图引出决策的架构图”，正是 IT 架构师大显身手之处。将复杂的系统构成压缩到经营层 10 分钟内即可理解的粒度，并明确标示判断要点——这种图示能力，是长年职业积累的无形资产。

结论： 随着 2025 至 2026 年生成式 AI 的普及，IT 架构师的设计对象正从“人类使用的应用程序”向“AI Agent 与人类协作的系统”发生范式转变。RAG、Agent、评测框架、治理等新领域，正被纳入 IT 架构师的必备知识。

结论： 架构的演进趋势是“单体→微服务→AI Agent 集成型”。2026 年的现在，在人类调用 API 的基础上，以 AI Agent 编排为前提的设计正在成为标准。

下面整理架构范式的变迁。

时代代表性范式设计上的关注点

2010 年代面向服务（SOA）服务间的 ESB 集成
2015 年起微服务独立部署、API 集成、Saga
2020年起无服务器、事件驱动无运维、异步处理
2024年起AI Agent 集成型LLM 调用、工具选择、评测框架

在 AI Agent 集成型架构中，除了传统的“确定性 API 调用”之外，还结合了“LLM 进行情况判断并选择工具的非确定性处理”。由此，设计时产生了“失败时的回退”“幻觉对策”“成本管理”等新的关注点。AI Agent 实现的详细内容请一并参阅AI Agent 开发完全指南。

结论： 将 RAG 或外部 LLM API 引入业务系统时，需要与传统不同的安全与数据治理设计。“不将敏感数据发送到外部 API”“保证 LLM 响应的可靠性”“保持访问权限的一致性”——如今已成为 IT 架构师必须掌握的三大新设计原则。

下面梳理 LLM 时代的新设计原则。

  • 数据最小化原则：将发送给 LLM 的数据降至最少，并预先对 PII 和敏感信息进行脱敏
  • 访问权限一致性：设计上确保 RAG 的检索结果不超过用户原本的访问权限
  • 模型供应商分离：不依赖单一 LLM 供应商，设计多模型回退机制
  • 提示注入对策：明确分离系统提示与用户输入
  • 响应评测框架：建立持续评测生产环境中 LLM 响应质量的机制
  • 成本上限控制：设计请求数与 Token 数的上限，防止失控导致的计费事故
  • 日志与审计：追踪谁在何时用哪个提示调用了 LLM

这些新原则与传统 Web 应用设计的最佳实践是两回事。能够设计 LLM 架构的 IT 架构师在 2026 年极为稀缺，即使月薪范围在 180 万～250 万日元，项目也能成立。LLM 工程的详细技能组合在LLM 工程师完全指南中单独讲解。

结论： 随着 GitHub Copilot、Claude Code、Cursor 等 AI 代码生成工具的普及，“实现”的边际成本正在急剧下降。另一方面，决定“应该做什么”“如何进行结构化”的 IT 架构师判断难以被 AI 取代，其市场价值反而在上升。

AI 无法替代的是“伴随责任的判断”“行业语境的解读”“与经营层达成共识”“失败时的问责”。这些全部是 IT 架构师的核心工作，随着 AI 的普及反而变得更加重要。出身工程师的人如果想提高职业生涯的“AI 抗性”，转向 IT 架构师是战略选项之一。

结论： IT 架构师是工程师职业生涯中“市场价值最不容易下降、即使在 AI 时代单价也持续上涨”的职种之一。从高级工程师进阶、成为自由职业者独立执业、拓展至技术顾问或外部 CIO 辅助、活用全球认证——多种职业路径可供选择。

结论： 从技术负责人进阶到 IT 架构师，需要有意识地在 3～5 年内积累从“单个系统设计”扩展到“全公司视角设计”的经验。通过公司内部兼职、主导 PoC、在外部学习会上发声、出版书籍等方式拓宽设计判断的广度，是王道之路。

对于IT架构师自由职业独立来说，关键在于“最初半年到1年的项目选择”。如果在第一个项目中拿不到合理单价，之后的单价行情往往会走低。要客观把握市场行情，比较考察多个面向自由职业工程师的代理机构是现实的选择。

结论： 月薪超过150万至200万日元的IT架构师项目，几乎只能通过“人脉渠道”或“特定代理机构渠道”流通。它们不会出现在公开招聘中，“指名性”和“个人品牌”是决定单价的关键因素。中长期构建个人品牌，是获得超高单价的关键。

下面整理获得超高单价项目的销售策略。

  • 构建个人品牌：通过技术博客、出版书籍、演讲、OSS贡献获得认知度
  • 参与行业社区：持续参加JAWS-UG、Cloud Native Days等活动
  • 维护与过往客户的关系：很多情况下，3至5年后的再次委托会带来单价提升
  • 代理机构选择：筛选出2至3家擅长高单价区间的代理机构
  • 工作形式的灵活性：能够提出每周工作2至3天＋同时服务多家公司的方案
  • 顾问合同的提案能力：能够提出“顾问（每周1至2天）”的合同形式
  • 明确专业领域：如“金融×AI”“制造业×IoT”等双轴专业性

“外部CIO辅佐”“技术顾问”这类职位，往往采用月薪50至100万日元×多家公司的组合，总收入有可能达到3,000万至5,000万日元的区间。实际情况是，“多家公司的中长期顾问合同”比“单次项目月薪200万日元”更容易同时实现收入的稳定性和单价。

IT架构师是“将业务需求转化为系统整体最优解的设计者”，虽然与SE、PM、技术负责人相邻，但承担着明确不同的职责。IT架构师分为“应用”“基础设施与云”“数据”“企业级”四个专业领域，各自的单价区间、所需技能和职业路径均不相同。

高单价IT架构师共同具备以下三项核心技能。

  • 对广泛技术栈的全局把握能力：不依赖特定技术，能够对多种方案进行比较
  • 非功能性需求的权衡判断力：对可用性、性能、扩展性、可维护性的多维优化
  • 在经营层与一线之间架起语言桥梁的沟通能力：在投资回报与设计约束之间进行双向翻译
