什么是影子AI？仅靠禁止无法防范的风险，以及在一线行之有效的对策

原标题：シャドーAIとは？禁止では防げないリスクと、現場で効く対策

FDE Consulting · 2026-10-06 · 约 10 分钟读完

摘要

这篇文章解释了“影子AI”——即员工在未经IT部门批准的情况下使用AI工具——并指出其相关安全事件比例在一年内翻倍，达到43%（IBM数据）。文章通过Samsung的源代码泄露等案例，列举了数据外流、浏览器扩展和AI Agent等五大风险，并论证了禁令和规则无法解决问题。作者提出了一个四步对策：可视化使用情况、按数据敏感度分级、构建更优于个人账户的官方AI环境，以及每月进行审查。文章最后将FDE（前沿部署工程师）定位为构建员工实际会采用的官方AI环境的方法。

要点

  • IBM调查显示，涉及影子AI的安全事件比例从20%升至43%。
  • Verizon数据显示，67%的用户通过个人账户使用AI服务。
  • Samsung工程师曾将内部源代码上传至ChatGPT，导致公司全面禁用。
  • 调查显示，即使有公司指南，仍有约47%的员工使用非官方AI工具。
  • 文章提出了四步对策：可视化、分级、官方环境和月度审查。

所谓影子AI，是指员工在未经IT部门正式批准或监督的情况下，将AI工具用于工作。例如把内部资料粘贴到个人账号的生成AI中、安装公司不知情的AI浏览器扩展、用AI录制并总结会议内容。这些行为的当事人只是想尽快完成工作，并无恶意。

尽管如此，到了2026年，影子AI开始明显出现在信息泄露的统计数据中。IBM的「Cost of a Data Breach Report 2026」显示，涉及影子AI的安全事件比例从前一年的20%翻倍至43%。IPA（信息处理推进机构）的「信息安全十大威胁 2026」中，“围绕AI使用的网络风险”也首次进入组织类第3位。

本文将梳理影子AI的定义、2026年的数据、风险与实际案例，并以4个步骤提出不依赖“禁止”的应对措施。

什么是影子AI

IBM将影子AI定义为“员工或最终用户在未经信息技术（IT）部门正式批准或监督的情况下使用AI工具或应用程序”。

典型的使用方式如下。

  • 将公司内部的邮件、资料、源代码粘贴到个人账号的生成AI中
  • 安装公司不知情的AI浏览器扩展（摘要、翻译、写作）
  • 用AI会议纪要服务录制并总结会议
  • 在未确认设置的情况下，使用业务所用SaaS后来追加的AI功能
  • 将内部系统或邮件的访问权限授予AI Agent

与影子IT的区别

IBM解释说，两者的区别在于：影子IT聚焦于未经授权的应用程序和服务，而影子AI聚焦于AI特有的工具、平台和使用场景。在现场制定对策时，以下差异会产生实际影响。

シャドーIT シャドーAI
对象各类未经许可的应用和服务AI工具、AI功能
主要风险数据的存储地点脱离管理除了输入数据的保存和处理之外，输出的错误还会混入业务决策
发现难易度通过新服务的签约或通信被发现混在现有SaaS的AI功能、浏览器扩展、个人账号中，难以发现
上手难易度引入需要花费功夫免费且几分钟即可开始使用

表中的“发现难易度”和“上手难易度”是我们的整理。影子AI比影子IT传播得更快、更隐蔽。

值得关注的是最后一行。管理层自以为已经掌握情况，而现场近半数员工却在管理之外使用AI。Okta的日本受访者只有87人，样本较少，应作为趋势来解读，但我们认为，这种偏差正是影子AI对策的出发点。

影子AI的5大风险

1. 输入信息的泄露

最严重的是机密信息被发送到公司管理之外的服务。根据Verizon 2026年的报告，发送给生成AI的数据中最多的是源代码，在DLP（信息泄露防护机制）违规中有3.2%是将研究、技术文档发送给了未经许可的AI。

发送出去的信息，公司方面无法收回。后文将提到的Samsung，也在面向员工的通知中表示担忧：发送给AI服务的数据会保存在外部服务器上，难以收回或删除。

2. 浏览器扩展与AI Agent的读取

一些AI浏览器扩展为了理解上下文，会收集并保留正在浏览的页面内容。Verizon的报告指出，如果浏览内部网站的浏览器中装有此类扩展，连非公开的数据都可能被吸走，并报告称在一般企业中，安装了未经许可的AI扩展的用户超过15%。在将邮件或内部系统权限授予AI Agent的使用方式下，影响范围会进一步扩大。

3. 不留记录

如果AI是在公司环境中使用的，可以留下谁输入了什么的记录。而个人账号则不会留下记录。即使发生问题，也无法事后查明什么内容被发送到了哪里。

4. 输出错误混入业务

IPA的十大威胁 2026也将“对AI加工、生成的结果未加充分验证便全盘接受”所引发的问题，纳入围绕AI使用的风险之中。对于管理之外的AI，甚至连AI的输出被用在了哪些业务决策中都无从知晓。

5. 罚款与信誉

IBM 2026年的调查显示，涉及影子AI的泄露中约每5件就有1件导致了监管机构的罚款。如果将个人信息或从交易对象处受托的信息输入外部AI，可能触犯法律法规或合同约定。

实际发生的事例：Samsung的案例

2023年4月，Samsung Electronics的技术人员将公司内部源代码上传到ChatGPT，导致其外泄。该公司于次月禁止在公司配发的电脑、平板、智能手机及内部网络上使用生成式AI（Bloomberg，2023年5月2日）。

这一事件中，泄露的入口不是攻击者，而是想加快工作进度的技术人员。影子AI的风险，不在于被外部攻破，而在于被内部人员出于善意带出去。

为什么仅靠禁令和规则无法减少

像Samsung那样停止使用的应对方式容易理解。但从日本的调查来看，仅靠规则约束，影子AI并不会减少。

  • 根据角川ASCII综合研究所的调查，即使是已建立全公司统一指南的企业，也有46.9%的人曾在工作中使用非官方AI，与部分建立指南企业的50.0%相差无几。即使在全公司已建立指南的企业中，也有45.1%回答“规则跟不上现场的实际情况”
  • 根据Eltes的调查（公司职员及公务员300人），在回答“对上传非公开信息有抵触”的78人中，64.1%实际上曾上传过
  • 根据SIGNATE总研的调查，影子AI使用者对内部标准AI功能不足以及申请流程繁琐表示不满

即使有顾虑也照样使用。即使有规则也照样使用。因为比官方渠道更方便。我们认为，不应把影子AI当作“取缔的对象”，而应把它当作“反映现场哪些业务需要AI的信号”来对待。

影子AI对策的4个步骤：让官方渠道成为最省事的选择

步骤要做的事具体做法最终成果
1. 可视化掌握谁在使用哪个AI、输入了什么匿名问卷调查、通信日志、浏览器扩展的盘点、确认在用SaaS的AI功能设置AI使用清单和数据流向图
2. 分类确定可以输入的信息“公开信息”“内部信息”“机密·个人信息”三个分类，以及每个分类可使用的AI一页规则表
3. 官方环境提供让现场愿意切换的官方AI确认企业合同·API设置、使用公司账号登录、记录留存、常用业务的模板官方AI环境和各业务的使用方法
4. 运营持续审视规则和环境每月一次查看使用记录和问卷，确认缺失的官方功能和新出现的影子AI月度审视记录

顺序很重要。如果从第2步的规则制定开始，跳过第1步和第3步，正如角川ASCII综合研究所的数据所示，即使有规则，非官方AI仍会被继续使用。

1. 可视化：首先不指责，先倾听

问卷应设计为匿名，且不指责使用行为本身。要询问的是四件事：正在使用的AI、用于哪些业务、输入的信息类型、不使用官方AI的理由。最后一个答案会告诉我们第3步应该做什么。

通信日志和浏览器扩展的盘点，是为了捕捉问卷中未反映的使用情况。应事先向全公司说明，目的不是处分个人，而是掌握整个公司的数据流向。

2. 分类：不是列出禁止清单，而是明确可使用的范围

仅有“不得输入机密信息”的规则，会把什么算机密的判断留给现场。应为三个分类分别列出具体例子（客户名称、报价金额、源代码、人事信息等），并写明“属于这个分类，就可以输入这个AI”。超过一页的规则，现场是不会看的。

3. 官方环境：做得比个人账号更方便

这一步最有效。如果官方AI比个人账号慢、功能弱、申请麻烦，现场就不会回来。Verizon的调查中67%的使用者使用个人账号，大概就是因为它最方便。

官方环境需要把握以下四点。

  • 通过合同和设置，确认输入不会被用于AI训练
  • 要求使用公司账号登录，并能在离职或调动时停用
  • 保留输入和输出的记录
  • 为会议纪要、邮件、资料制作、代码审查等现场常用业务准备模板

4. 运营：规则从制定之日起就开始过时

AI的工具和功能以数月为单位更替。每月一次查看使用记录和问卷结果，确认官方环境缺失的功能以及新出现的影子AI。规则的更新也在此时进行。

影子AI对策检查清单

#确认事项
1有员工在工作中使用的AI工具清单
2可输入信息的分类已确定，并附有具体例子
3有官方AI环境（企业合同·API）
4官方AI已设置为输入不用于训练
5官方AI使用公司账号登录，并可在离职时停用
6保留官方AI的使用记录
7已确认在用SaaS新增AI功能的设置
8有关于是否允许安装AI浏览器扩展的规则
9授予AI Agent的权限按业务控制在最小限度
10每月至少一次审视使用情况和规则

如果有3项以上不符合，建议从第1步的可视化开始。

深入现场，打造“会被使用的官方环境”

影子AI对策的成败取决于第3步。规则和监控工具可以买到，但符合现场业务的官方AI环境，不深入了解业务就无法打造。

我们实践的FDE（Forward Deployed Engineer），是一种工程师深入现场、拆解业务、打造实际会被使用的AI机制，并持续改进直至落地生根的工作方式。通过影子AI可视化发现的“现场需要AI的业务”，可直接成为官方环境中首批打造的候选对象。
