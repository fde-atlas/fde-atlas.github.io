Anthropic FDE是什么？招聘要求・工作方式・与其他公司FDE的区别

原标题：Anthropic FDEとは？求人要件・働き方・他社FDEとの違い

FDE総研 · 2026-10-13 · 约 10 分钟读完

摘要

本文基于Anthropic官方招聘信息，梳理前沿部署工程师（FDE）的工作内容、任职要求与工作方式。Anthropic FDE需深入客户现场，用Python将Claude落地为生产系统，客户现场走访占比25%至50%。文章还对比了Palantir与OpenAI的FDE岗位差异，并给出应聘准备建议。

要点

  • Anthropic FDE负责将Claude嵌入客户业务并运行于生产环境。
  • 核心要求：Python实现能力、LLM生产运维经验、high agency、客户探索能力。
  • 客户现场走访占比25%至50%，结合远程开发。
  • 与Palantir、OpenAI的差异在于核心技术（Claude）与勤务条件。
  • 应聘者应积累Claude Agent开发与评测的实战成果。

Anthropic FDE 是什么样的职位？

Anthropic FDE 是深入客户现场、亲自设计和实现基于 Claude 的生产系统的工程师职位。

Anthropic FDE（前沿部署工程师）负责将 Claude 集成到客户企业的业务中，并承担到在生产环境实际运行为止的责任。从 2025 年前后开始，OpenAI 和 Anthropic 等 AI 公司陆续公开招聘 FDE，这一由 Palantir 首创的职位名称也开始在生成式 AI 行业中使用。本文将以 Anthropic 的官方招聘（Greenhouse 上发布的招聘启事）为基础，梳理工作内容、招聘要求、工作方式、与其他公司 FDE 的区别以及应聘准备。

正如“Forward Deployed（部署在前线）”这一职位名称所示，主要的工作场所不是自家办公室，而是客户一方。推销 Claude 是销售和解决方案团队的职责。Anthropic FDE 负责更进一步的工作，打造让 Claude 在客户业务流程中持续被使用的状态。

项目Anthropic FDE 的内容（基于官方招聘）
主要工作场所客户现场（面对面拜访与远程开发相结合）
核心技术Claude（提示词设计、Agent 开发、生产运维）
主要实现语言Python
客户现场拜访比例25～50%
成果的衡量标准在客户业务中被实际使用并产生成果

在客户现场做什么？

与客户一起深入挖掘课题，设计、实现并测试集成 Claude 的工作流，最终完成生产应用。

从招聘启事的要求中可以读出的工作流程，大致分为以下 4 个阶段。

  • Discovery：通过与客户的对话，找出需求背后的真正业务课题
  • 设计：决定集成 Claude 的工作流、提示词和 Agent 架构
  • 实现与测试：用 Python 实现，使其在客户的系统上运行
  • 生产落地：解决生产环境中出现的异常和精度问题，使其持续被使用

从实施支持的现场来看，使用 LLM 的系统往往在演示阶段能正常运行，但在面对实际业务数据、权限管理和异常处理时就会停滞不前。Anthropic FDE 可以说是为了跨越这最后一步而设立的职位。

与解决方案工程师和 SWE 有什么不同？

区别在于责任范围。Anthropic FDE 不会止步于技术提案，而是用自己写的代码交付最终成果。

视角Anthropic FDE解决方案工程师SWE（产品开发）
主要对象个别客户企业商谈中的潜在客户不特定的众多用户
主要交付物在客户环境中运行的生产应用演示、技术提案、PoC通用产品的功能
编写代码的量多（生产级质量）视项目而定（以验证为主）多（生产级质量）
成功的标准在客户业务中被使用并产生成果赢得订单、在技术上获得认可按规格正常运行

如果说 SWE 的工作是“把一个功能交付给众多客户”，那么 Anthropic FDE 的工作就是“为眼前的客户把众多功能全部实现”。这个职位常被误解为会议繁多，但其工作的核心是编写代码。

Anthropic FDE 的招聘要求是什么？

招聘要求的核心是 4 项：Python 实现能力、LLM 生产运维经验、high agency、与客户进行 discovery 的能力。

Anthropic 的官方招聘中列出了以下 4 项要求。

要求招聘启事中的意图在实际工作中的含义
Python 实现能力能用 Python 编写高水准的代码能以可在客户环境中生产运维的质量编写代码
LLM 生产运维经验具备高级提示词设计和 Agent 开发的经验不仅是尝试，还要有在生产环境中稳定运行的经验
high agency即使在模糊的情况下也能自主推进无需等待指示，就能推进前所未有的项目
与客户的 discovery具备与客户共同探索课题的高超沟通能力不是照单全收需求，而是能够重新定义课题

技术要求达到什么水平？

Python 实现能力是基础，在此基础上还要求有在生产环境中运行 LLM 的经验。两者都以实际工作水平为前提。

这 4 项要求并非并列关系，把它们理解为层层递进的关系会更容易理解。最底层是“Python 实现能力”，其上是“LLM 生产运维”，再往上是“high agency 与客户 discovery”。虽然有客户对接方面的要求，但这并不意味着实现能力的要求会降低。Anthropic FDE 需要在达到与 SWE 相同的技术水准之上，还具备客户对接的能力。

LLM 生产运维中被考察的，并不是能否调用 Claude。而是是否具备涵盖评测设计、提示词的持续改进、Agent 失败时的处理方式在内的运维经验。

非技术要求考察的是什么？

考察的是即使在模糊的情况下也能自主推进的能力，以及与客户一起重新定义课题的对话能力。

高主观能动性听起来比较抽象，但在 FDE 的工作现场会体现为具体的行动。例如，在需求确定之前先制作小型原型来观察客户的反应，如果公司内部没有先例就自己进行验证并准备判断依据，诸如此类的工作方式。在申请材料和面试中，能否具体讲述自己超越指示范围主动行动的经历，很可能是成败的关键。

Anthropic FDE 的工作方式与出差比重如何？

Anthropic 的招聘信息中规定客户现场拜访占 25～50%，比一般开发岗位的出差比重高出不少。

官方招聘信息中写明的客户现场拜访比例为 25～50%。简单计算的话，相当于预计将工作时间的四分之一到一半在客户现场度过。其前提是将现场拜访与远程开发相结合的工作方式。

一周的时间分配是怎样的？

虽然因项目而异，但基本形式是在客户现场的沟通与公司内部的实现、验证之间往返。

以 25～50% 的拜访比例为前提，大致整理时间的使用方式如下。

业务主要场所内容
Discovery・需求梳理客户现场（面对面）・线上对业务负责人的访谈、重新定义课题
实现・测试公司内部・远程工作流、提示词、Agent 的开发
验证・反馈客户现场・线上用真实数据确认精度并改进
内部协作公司内部将现场获得的知识分享给产品团队

※比例因招聘而异，请在申请前通过各自的招聘信息确认。

出差比重对职业发展有何影响？

虽然出差负担较重，但这是近距离学习行业业务知识和客户决策过程的宝贵机会。

深入客户现场，可以接触到业务的例外处理、内部政治、审批流程等规格说明书中没有写到的信息。由于生活方面的负担不轻，应在申请前理清家庭情况和居住地之间的平衡。在此基础上，能够在短时间内积累领域知识和直面客户的经验，这正是 Anthropic FDE 独有的价值。

Anthropic FDE 与 Palantir、OpenAI 的 FDE 有何区别？

在客户现场进行实现这一点是 Palantir、OpenAI、Anthropic 的共同点。不同的是，所处理的核心技术和工作条件。

推广 FDE 这一职位名称的是 Palantir Technologies。Palantir 通过 FDSE（Forward Deployed Software Engineer）和 Deployment Strategist 这两个角色，确立了向客户组织内部派驻人员的方式。OpenAI 和 Anthropic 继承了这一理念，并将其应用于基础模型的落地。

所处理的技术和产品有何不同？

Palantir 将数据平台，OpenAI 和 Anthropic 将基础模型和 Agent 实装到客户现场。

视角PalantirOpenAIAnthropic
核心资产Foundry／Gotham（数据集成与分析平台）API、ChatGPT Enterprise、Agents SDKClaude（API・Agent 开发）
现场工作的中心数据集成、本体设计模型评测、提示词与 Agent 设计提示词设计、Agent 开发、生产运维
职位构成FDSE＋Deployment StrategistFDEFDE
在日本的动向2019 年与 SOMPO 成立合资公司 Palantir Technologies Japan2024 年 4 月开设东京办公室通过各招聘信息确认

Anthropic 自主发布了 Model Context Protocol（MCP，2024 年 11 月公开）、Contextual Retrieval（2024 年 9 月公开）、关于上下文工程的技术博客（2025 年 9 月公开）等内容。如果以 Anthropic FDE 为目标，掌握符合这些一手资料的设计方法，无论在面试还是现场工作中都会更容易沟通顺畅。

工作条件和语言要求有何不同？

Anthropic 要求客户现场拜访 25～50%，OpenAI 东京则要求每周 3 天到岗、国内出差、日英双语为必备条件。

OpenAI 东京据点的 FDE 招聘信息中，明确列出了每周 3 天到岗、国内出差、具备日英双语能力等条件（OpenAI 官方）。Anthropic 的招聘信息中，客户现场拜访 25～50% 是工作方式的参考标准。

视角Anthropic FDEOpenAI FDE（东京）
与现场的互动方式客户现场拜访 25～50%每周 3 天到岗、国内出差
语言要求因招聘岗位而异，通过招聘信息确认日英双语必备

工作地点和语言要求因岗位而异。不要武断地认为“如果是 Anthropic FDE 就一定是这样”，通过应聘岗位的招聘信息确认才是稳妥的做法。不过，既然是全球性企业，最好做好内部文档和设计讨论将以英语进行的心理准备。

以 Anthropic FDE 为目标应该做哪些准备？

打造在生产环境中运用 Claude 的实绩，并将解决客户课题的经验整理成能够作为成果讲述的形式，这是捷径。

FDE 是以实绩来评价的职位，资格证书和学习经历相对不受重视。比较现实的做法是，按照招聘要求的 4 个项目，分别为每一项准备一个能够佐证的经历。

技术方面应该积累什么？

在生产环境或接近生产的环境中，完整经历使用 Claude API 进行 Agent 开发和评测设计。

  • 用 Python 编写生产级质量的代码：包括测试、错误处理、日志在内进行实现
  • 用 Claude 构建 Agent：按照 Anthropic 的「Building effective agents」所建议的，从简单的结构开始，在需要时再进行复杂化
  • 搭建评测机制：准备测试集，每次修改提示词时测量精度
  • 用 MCP 连接外部工具：实现与内部数据和现有系统的集成
  • 在运用中改进：让真实用户使用，基于失败案例持续改进

如果当前工作场所没有将 LLM 投入生产环境的机会，可以选择像内部业务改进工具这样虽小但有真实用户的题材。这样你就能积累可以讲述“谁的、哪项业务、发生了怎样的变化”的经验。

在申请材料和面试中应该展示什么？

除了技术深度之外，还要具体展示你自主重新定义模糊问题并推动其取得成果的经验。

招聘要求需要准备的证据写法与说法示例
Python 实现能力公开仓库、在生产环境中运维过的系统说明在设计中做了哪些判断，以及为什么这样做
LLM 生产环境运维使用 Claude 等构建的产品的运维经验展示评估指标、改进前后的差异以及对失败的处理
high agency（高度主动性）自主推进前所未有的问题的经验讲述接手无人负责的问题的经过
客户 discovery（需求探索）重新定义需求的经验展示最初的需求与实际解决的问题之间的差异

如果继续以 SWE 身份积累经验，以下三点会很有效：列席需求定义会议、参与客户访谈、在发布后亲自确认产品是否在现场被使用。即使职位名称不是 FDE，在将生成式 AI 实现到客户业务中的 SaaS 企业或 AI 导入支持企业中，也有从需求定义到落地应用全程负责的职位。先在这样的工作中做出成绩，再申请 Anthropic FDE，对大多数工程师来说是一条现实的路径。
