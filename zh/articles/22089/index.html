《构建 AI 浏览器 Agent》课程值得学吗？

原标题：Building AI Browser Agents course: is it worth it?

FDE Times · 2026-11-16 · 约 6 分钟读完

摘要

文章评析 DeepLearning.AI 的 65 分钟课程《Building AI Browser Agents》，由 AGI Inc 联合创始人 Div Garg 与 Naman Garg 讲授。作者认为对 FDE 而言，两节带代码的实操课最有价值，AgentQ 与 MCTS 部分只需了解大意。文章强调应把成功率读成失败率：Agent Q 在预订任务上将 Llama-3 70B 的成功率从 18.6% 提升到 81.7%，但仍有近两成任务失败；REAL 基准上最强模型也只有约 41%。建议 FDE 先自建任务集评测、用错误分类表指导修复，并用开源 AGI SDK 做对比。

要点

  • 课程仅 65 分钟，只需基础 Python，两节代码课是核心价值。
  • AgentQ 与 MCTS 属理论内容，FDE 略读即可。
  • Agent Q 成功率 18.6% 升至 81.7%，仍意味着约五分之一任务失败。
  • REAL 基准上前沿模型最高约 41%，近六成任务失败。
  • 建议自建任务集评测并带错误分析表见客户，而非单次演示。

简要概述

  • 《构建 AI 浏览器 Agent》是 DeepLearning.AI 的一门时长 1 小时 5 分钟的课程，由 AGI Inc 联合创始人 Div Garg 和 Naman Garg 讲授

成功率从 18.6% 提升到 81.7%。Agent Q 论文报告了这一结果：团队将该方法应用于 Llama-3 70B 的零样本模式，在一个真实世界的预订任务上完成。

这是单一任务上的结果，另外还有一个在 WebShop（一个模拟电商环境）上的独立实验。它并非跨多个基准测试的平均值。

尽管如此，这个数字解释了为什么一门仅 1 小时 5 分钟、正是基于这项研究的课程值得 FDE 花一个晚上的时间。

这门课程是 DeepLearning.AI 的《构建 AI 浏览器 Agent》，由 AGI Inc 联合制作，由 AGI Inc 联合创始人 Div Garg 和 Naman Garg 讲授。课程于 2025 年 4 月 17 日发布，旨在帮助学习者了解自主网页 Agent 的工作原理、当前的限制，以及 AgentQ 如何帮助 Agent 纠正自身的错误。

FDE 为什么应该关注？在许多客户那里，并非所有数据都在 API 之后。大量数据仍存在于内部网页门户、合作伙伴网站以及员工每天手动点击填写的表单中。当客户问“Agent 能不能自己完成这件事？”时，你需要既知道如何构建它，也知道它会在哪里出问题。

一小时的课程，但并非每一分钟的价值都相同

这门课程定位为中级，但唯一的先决条件只是基础 Python。在它的 9 个章节中，有两节是带代码的课程：一节构建简单的网页 Agent，另一节构建自主网页 Agent。此外还有对 AgentQ 和 MCTS 的深入讲解。

这两节带代码的课程是需要认真学习的部分，要自己动手敲代码，而不只是看视频。想象一个在许多项目早期都会出现的场景：客户需要一个 Agent 访问他们每天使用的网站并从中提取信息。这两节课正是让你练习这类工作的地方。

深入讲解则是另一回事。AgentQ 和 MCTS 是关于 Agent 如何自我改进的理论，而不是一项部署技能。给在职 FDE 的建议是：掌握核心思想即可，除非你的项目需要，否则不要试图精通算法的每个细节。

第一个要点：Agent 需要有空间尝试多个分支

Agent Q 论文于 2024 年 8 月 13 日提交至 arXiv，提出将引导式蒙特卡洛树搜索（MCTS）与自我批评机制相结合，使 AI Agent 能从成功和失败的运行中学习。课程页面将 AgentQ 描述为一个结合 MCTS、自我批评和 DPO 的框架，让 Agent 能够纠正自己的错误。

用程序员的话来说：Agent 不是从首页到“预订”按钮走一条直线，而是权衡几种可能的操作序列，并自行评估哪些步骤看起来有希望。

值得保留的思想不在 MCTS 的细节中，而在其出发点：在该方法应用之前，零样本模型的成功率不到五分之一。这足以让我们警惕那些一路直行、从不回溯、从不自我检查的 Agent。

第二个思想：把成功率读作失败的任务

在 81.7% 的成功率下，每 100 次预订中仍有大约 18 次失败。

假设客户希望一个 Agent 每周处理 500 个预订请求。即使恰好达到这个水平，也会有 90 多个请求需要人工重做。因此，首先要与客户确定的是：谁来处理失败，以及如何检测这些失败。

更宏观的图景更为严峻。由 AGI Inc 及其合著者构建的 REAL 基准测试，使用 11 个网站的确定性副本，包含 112 个任务。在该测试上，前沿模型最高达到 41%；AGI Inc 的博客记录了 Claude-3.7-Sonnet-Thinking 的成绩为 41.1%。每 100 个任务中，近 60 个失败。

第三个思想：先测量，再承诺

AGI Inc 将其研究网站呈现为一本手册，面向构建、测量和评审 Agent 系统的人。对于 FDE 来说，这三项任务的顺序值得记住：构建 Agent 只是第一步，而不是全部工作。

想象一下，你在一个公开网站上刚构建了一个 Agent，为它编写 20 个任务，然后把每次运行归入且仅归入一个类别。一个假设的结果表可能如下所示：

结果任务数下一步修复
成功13保留为回归测试套件
未找到元素3检查选择器，等待页面加载完成
误读页面2审查 Agent 实际看到的内容
结果不完整2修复提示词，添加评分标准

解读这张表：13/20 即 65%，也就是说每 20 个请求中有 7 个需要人工审查。最后一列告诉你应该先修复什么，这里是“未找到元素”错误，因为它们最常见。每次修复后重新运行同样的 20 个任务，并把这张表带到客户会议上，而不是只带一个成功运行过一次的演示。

如果你想要一个共享的衡量标准，而不只是自己的任务集，开源的 AGI SDK 是顺理成章的下一步。它可以通过 pip 安装，并在 REAL 任务上运行测试框架，让你可以将自己的 Agent 与大型模型正在被评分的同一个“迷你互联网”进行比较。

谁应该学习它，以及按什么顺序学习

如果你是想转型做 FDE 工作的软件工程师，而且从未构建过 AI Agent，这里是一个温和的起点：这门课程很短，只需要基础的 Python 知识。如果你已经了解 AI Agent，可以直接学习两个带代码的课程，然后进入 AGI SDK。

对新手来说，一个合理的顺序是：先阅读 arXiv 上 Agent Q 论文的摘要以了解全貌，认真完成两个带代码的课程，浏览 AgentQ 和 MCTS 的深度解析，然后在你自己的任务集上评测你的 AI Agent。

在简历上，短期课程证书说明不了什么。但一个小型代码仓库就不同了：一个在公开网站上运行的网页 AI Agent，附上你自己编写的任务集上的成功率表格和错误分类，再加上几个 REAL 任务的得分。

阅读 FDE 招聘广告时，留意“agent”、“automation”和“evaluation”这类词：那个代码仓库一次性回答了这三点。

这门课程教你在一个晚上构建一个 AI Agent。真正的 FDE 工作是从你统计它在 100 个任务中失败多少次开始的。
