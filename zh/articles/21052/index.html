美式“FDE”与日本的客户驻场似是而非，企业应改变认识

原标题：米国流「FDE」は日本の客先常駐とは似て非なるもの、企業は認識を改めよ

日経クロステック（Xtech） · 2025-12-05 · 约 3 分钟读完

摘要

日经Cross Tech撰文指出，美国科技业兴起的FDE（前沿部署工程师）与日本的客先常驻模式形似而实异。文章以Treasure Data为例：该公司2025年上半年设立FDE团队，配合2024年推出的AI Agent Foundry工具，派工程师进入客户营销部门，协助其基于CDP中的客户数据开发自有AI Agent。CEO太田一树解释，传统SaaS是确定性系统，输入A必得B；而基于LLM的AI Agent是概率性系统，同样输入可能产生不同输出，因此需要FDE驻场支持。作者承认自己此前误将FDE等同于客先常驻，呼吁日本业界重新认识这一角色。

要点

  • 作者承认曾误将FDE等同于日本客先常驻模式。
  • Treasure Data于2025年上半年设立FDE团队并派驻客户现场。
  • AI Agent Foundry让客户无需写SQL即可组合AI Agent做数据分析。
  • CEO太田一树：SaaS是确定性系统，AI Agent是概率性系统。
  • FDE的职责是在客户营销部门协助开发定制AI Agent。

全文

AI（人工智能）工具和SaaS（软件即服务）供应商正在大力培养和部署Forward Deployed Engineer（FDE）。日本IT行业中有一种非常相似的形态——“客户驻场”，但FDE所需承担的角色却大不相同。包括笔者在内，看来有必要重新认识这一点。

IT供应商的工程师进驻用户企业的使用部门，在充分了解现场需求的基础上开发定制应用程序的FDE，笔者本人不久前还在专栏中将其解释为“日本所说的‘客户驻场型’系统开发模式”。

然而，在采访实际正在培养FDE并将其部署到用户企业现场的IT供应商后，我们发现其实际情况与传统客户驻场模式大不相同。

2025年上半年在企业内部设立FDE团队并开始向用户企业部署的一家公司，是总部位于美国硅谷的Treasure Data（Treasure Data）。该公司提供CDP（Customer Data Platform，客户数据平台）SaaS，将从各种渠道收集的客户数据统一管理并用于营销分析。

Treasure Data于2024年开始提供AI Agent开发工具“AI Agent Foundry”，用于利用CDP中积累的客户数据。该工具通过接入Treasure Data已开发好的AI Agent“Treasure Data AI Agent”，帮助用户企业开发自己的AI Agent。

Treasure Data预先准备的AI Agent包括：基于客户属性信息和行为历史等对客户进行分类（细分）的“受众Agent”，以及在分析内外部数据的基础上为每个目标客户制定营销活动方案等的“深度研究Agent”等。用户企业无需编写SQL查询等，只需向AI Agent发送指令（提示词），即可执行各种类型的数据分析。

AI Agent Foundry的用户通过组合这些Treasure Data制造的AI Agent，可以创建用户企业自己的“营销效果分析Agent”、“营销活动邮件创建Agent”、“营销活动邮件效果分析Agent”等。

传统SaaS与AI Agent，特性大不相同

Treasure Data的FDE的工作，就是前往用户企业的营销部门等现场，协助开发用户企业自己的AI Agent。Treasure Data联合创始人、CEO（首席执行官）太田一树表示：“由于传统SaaS与AI Agent的特性大不相同，因此需要设立FDE团队。”

究竟有何不同？据太田CEO介绍，最大的区别在于：SaaS是“输入A就必定输出B”这种以决定论方式运行的系统，而基于LLM（大语言模型）的AI Agent则是“即使输入A，输出可能是B，也可能是D或G”这种以概率方式运行的系统。
