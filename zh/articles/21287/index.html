从 Citrix 或 VMware 管理员到云与 AI 工程师

原标题：From Citrix or VMware Admin to Cloud and AI Engineer

Cloud Soft Solutions · 2026-10-06 · 约 12 分钟读完

摘要

文章面向 Citrix、Horizon 和 vSphere 管理员，主张向云计算延伸而非转行，因为银行、医院等受监管行业仍依赖 VDI，只是控制平面迁到了云端。作者给出三条路径：转向 Azure Virtual Desktop、Intune 和 Entra ID；转向云与平台工程（Terraform、Kubernetes）；在第二条路径基础上进阶到 AI 与前沿部署工程师方向，学习 Python、RAG、Agent 和评测。文章逐项映射现有技能到云与 AI 场景，提供每条路径的差距清单、起步行动、作品集项目及六个月学习计划，并建议用成果导向方式重写简历。

要点

  • 核心论点：虚拟化技能应延伸到云，而非视为夕阳技术另起炉灶。
  • 三条路径：Azure EUC（AVD、Intune）、云平台工程、进阶到 AI 与 FDE。
  • 技能映射：身份、网络、镜像管理、故障排查均可迁移到云与 AI 工作。
  • 实操建议：PowerShell 转 Python、掌握 Git、完成作品集项目。
  • 附六个月计划与简历改写方法，强调用结果而非产品清单描述经验。

如果你现在在运行 Citrix、Horizon（现称 Omnissa Horizon，前称 VMware Horizon）或 vSphere，务实的职业选择是向云方向拓展，而不是放弃虚拟化。 银行、医院、保险公司和 GCC IT 团队仍然需要 VDI 和虚拟化技能，而且许多这类环境现在正在 Azure 和 AWS 上重建，而不是被关停。本指南将把你已有的知识对应到云、Azure Virtual Desktop 和 AI 工作上，然后给出三条路径，每条路径都包含技能差距、前三步行动和一个作品集项目，外加一个下周就能开始的六个月计划。

如果你想更全面地了解 Citrix 职业阶梯本身，从 L1 支持到架构师，请阅读 Citrix 职业路线图：从新手到架构师。

为什么这是拓展，而不是转行

Citrix 管理员的职业转型常被描述为逃离一项“垂死”的技术。这种说法是错误的，它会让人们丢弃自己最有价值的资产。发布桌面和应用仍然是受监管机构向承包商、离岸团队和临床医生提供敏感系统受控访问的方式。改变的是这些桌面运行的位置以及管理它们的方式。

  • 控制平面迁移到了云端。 Citrix DaaS、Azure Virtual Desktop 和 Windows 365 将代理层置于云服务中，因此管理员的工作从修补 Delivery Controller 转变为在 Azure 中设计网络、身份和镜像。
  • 设备管理迁移到了 Intune 和 Entra ID。 组策略和本地 Active Directory 仍然存在，但新的构建越来越假设使用 Entra ID 加入、条件访问和 Intune 策略。
  • 虚拟化环境正在被重新评估。 Broadcom 收购 VMware 以及随后的许可变更，促使许多组织重新审视他们的 vSphere 资产。无论他们是迁移到 Azure 或 AWS、转向云中的托管 VMware，还是维持现状，他们都需要了解现有环境的人才。
  • AI 正在进入服务台。 面向最终用户计算的知识助手、工单分类和故障排除 AI Agent 已经是真实的项目，它们需要知道登录故障是什么样子的人才。

你的可迁移技能对照表

在学习任何新东西之前，先盘点自己。下表展示了每项核心 EUC 和虚拟化技能在云、AVD 和 AI 工作中的应用场景。

你已有的技能在云和 AVD 中的应用在 AI 工作中的应用
Windows Server、Active Directory、组策略使用 Entra ID、AD DS 或 Entra Domain Services 为会话主机实现混合身份，将 GPO 迁移到 Intune 设置目录策略将用户组映射到文档权限，使助手只检索每个用户有权查看的内容
网络（VLAN、防火墙、DNS、负载均衡器、NetScaler）VNet 和 VPC 设计、中心辐射型架构、专用终结点、DNS 转发、RDP Shortpath、连接数据中心的 ExpressRoute 或 VPN让模型和向量搜索流量走安全团队会批准的专用路径
存储（SAN、NAS、数据存储、配置文件共享）用于 FSLogix 配置文件容器的 Azure Files 或 Azure NetApp Files、托管磁盘、存储分层和备份设计源文档、嵌入向量和日志的存放位置及保留时长
镜像管理（MCS、PVS、黄金镜像、App Layering）Azure Compute Gallery、Azure VM Image Builder、Packer、跨环境推广的版本化镜像同样的规范应用于提示词、索引和模型配置：版本化、测试、推广
高压排障（登录缓慢、黑屏、打印问题）阅读 Azure Monitor 和 Log Analytics，跨身份、网络和主机追踪故障通过追踪调试 AI 回答：是检索、提示词、数据还是工具调用出了问题？
企业变更控制（CAB、维护窗口、回滚计划）基础设施即代码评审、分阶段发布、策略即代码AI 变更的发布门禁、执行操作的 Agent 的审批环节、审计证据

云和 AI 两列的技能大多相同，只是工具不同，这就是为什么这条路径对有经验的管理员来说是现实的。

从 EUC 和虚拟化出发的三条路径

根据你的兴趣和当前雇主的发展方向选择一条路径。第三条路径建立在第二条之上。

Citrix / VMware 管理员 | +-- 路径 1：Azure 上的 EUC | AVD、Intune、Entra ID | +-- 路径 2：云 / 平台 | AWS 或 Azure、Terraform、K8s | | | +-- 路径 3：AI / FDE | Python、RAG、Agent

路径 1：从 EUC 到 Azure（AVD、Intune、Entra ID）

这是最短的跨越，对 Citrix 管理员来说通常也最自然。你仍然留在终端用户计算领域，只是转向其云原生版本。Citrix 通常运行在 Azure 之上，所以两者都懂是一种优势。

需要弥补的差距：

  • Azure 基础：订阅、资源组、基于角色的访问控制、VNet、Azure Monitor。
  • AVD 架构：主机池、应用程序组、工作区、Windows 多会话、缩放计划、Azure 存储上的 FSLogix。
  • 云原生身份和终端管理：Entra ID 加入与混合加入的对比、条件访问、Intune 合规性和配置策略、通过 Intune 部署应用。
  • 成本思维：在数据中心，闲置主机不产生额外费用；在 Azure，它们每小时都出现在账单上。

前三步行动：

  • 创建一个带预算警报的 Azure 订阅，然后通过门户手动部署单个 AVD 主机池，以了解每个组成部分。
  • 将几台测试设备和会话主机注册到 Intune，并把三个你熟悉的 GPO 设置迁移为 Intune 策略。
  • 撰写一页对比文档，将你当前的 Citrix 或 Horizon 设计与对应的 AVD 设计进行比较：代理分发、配置文件、镜像、打印、监控。

作品集项目： 为一家虚构医院的离岸计费团队搭建 AVD 环境。使用来自 Azure Compute Gallery 的自定义镜像的池化主机池、Azure Files 上的 FSLogix 配置文件、要求 MFA 的 Entra ID 登录与条件访问、由 Intune 管理的会话主机、非工作时间自动关机主机的缩放计划，以及针对三种最常见用户投诉的简短运维手册。记录每项设计决策。

Azure Virtual Desktop 培训和Microsoft Intune 培训完整覆盖了这条路径，而现有的 Citrix 工程师可以通过Citrix 培训课程保持其 DaaS 技能的更新。

路径 2：从虚拟化到云与平台工程

这条路径适合那些更喜欢基础设施而非桌面的 VMware 和 vSphere 管理员。从 VMware 管理员转型为云工程师，关键在于把你熟悉的概念（集群、资源池、端口组、数据存储、模板、vMotion）转化为云上的对应概念，然后学会用代码描述一切。

需要弥补的差距：

  • 深入掌握一个云平台，AWS 或 Azure：计算、网络、存储、身份和监控，以及它们如何映射到你的 vSphere 环境。
  • 迁移模式：重新托管、重新平台化和重构，外加用于发现和迁移工作负载的工具（Azure Migrate、AWS Application Migration Service），以及每个云中的托管 VMware 选项。
  • Terraform：模块、状态、拉取请求中的计划、环境。
  • 容器与 Kubernetes：许多应用在迁移后落地的平台。

前三步行动：

  • 画出你当前的 vSphere 环境，并为每个组件标注其 AWS 和 Azure 对应物。在没有清晰对应物的地方（例如 DRS 或共享数据存储），写下需要做出的改变。
  • 仅用 Terraform 在云端重建一个小型三层实验环境，不点击控制台，反复销毁并重建，直到它可靠为止。
  • 将一个简单应用容器化，并在托管 Kubernetes 服务上运行，这样你就能谈论 VM 迁移之后会发生什么。

作品集项目： 为一家虚构零售商编写迁移运维手册，将十几台 VM 从 vSphere 迁移到 AWS 或 Azure。包括发现清单、分波计划、用于落地网络和目标计算的 Terraform、每一波的回滚计划，以及简短的成本比较方法（输入为假设值并清晰标注）。

这条路径的有用课程包括：针对你迁移来源环境的VMware 培训、针对目标平台的AWS 培训或Azure 培训，以及用于基础设施即代码的Terraform 培训。

路径 3：迈向 AI 与前沿部署工程

这条路径建立在路径 2 的基础上。前沿部署工程师会驻扎在客户现场，在其环境中交付一个可运行的 AI 系统，把 AI 演示转化为企业级成果。EUC 和基础设施人员能为这项工作带来难得的优势：他们了解企业网络、身份管理和变更控制在实际中是如何运作的。姊妹篇从云工程师转型为 FDE 详细介绍了从云到 AI 的转型步骤；这里我们聚焦于与你的背景相关的特定内容。

需要弥补的差距：

  • 将 Python 作为应用开发语言，而不仅仅是脚本语言：API、测试、错误处理。
  • 检索增强生成：文档如何被分块、嵌入、检索和引用。
  • Agent 与工具：让模型调用 API，并设置限制和对高风险操作的人工审批。
  • 评测：用测试集而非主观印象来证明答案质量。
  • 面向客户的工作：需求调研、范围界定以及面向非技术决策者的演示。

前三步行动：

  • 先完成路径 2 的云基础知识。无法通过安全审查的 AI 系统是无法上线的。
  • 学习足够的 Python，构建一个小型 API，调用 Azure 或 AWS 上的托管模型服务。
  • 阅读 面向终端用户计算工程师的 AI，了解 AI 已经如何融入 Citrix、AVD 和 VDI 运维，并从你自己的工作中选择一个用例。

作品集项目： 一个 EUC 故障排查助手。索引一组关于登录缓慢、配置文件损坏和打印问题的匿名化运行手册和知识文章。构建一个带引用来源的 RAG 服务，按用户组限制结果范围，并添加一个只读工具，例如查询会话主机健康状况。编写一组真实场景的测试问题，并报告答案正确且有据可依的频率。

设想一个位于海得拉巴的 GCC IT 团队，为一家全球银行的虚拟桌面提供跨多个时区的支持。夜班工程师花费大量时间在旧工单中搜索已知问题的修复方法。一个能搜索已批准的运行手册、展示来源并拒绝猜测的助手是一个规模适中的项目，而 EUC 工程师比普通开发者更理解它：谁能看到哪份运行手册、哪些操作需要变更工单，以及对用户来说“已修复”意味着什么。

计划先转向云托管桌面？对于大多数 Citrix 和 Horizon 管理员来说，AVD 课程 是最直接的下一步，并且可以作为另外两条路径的基础。

从 PowerShell 到 Python，再加上 Git

大多数 EUC 管理员已经会写 PowerShell，这是一个真正的先发优势。概念可以迁移，但习惯需要改变。PowerShell 对于 Windows、AVD 和 Intune 自动化仍然不可或缺，所以你是在 PowerShell 之上增加 Python，而不是取代它。

PowerShell 习惯需要学习的 Python 等价做法
Pipeline of objects (
Get-* | Where-Object
)		 Lists, dictionaries and comprehensions
使用 Invoke-RestMethod 调用 API使用 requests 或 httpx 库，并设置超时和重试
ConvertFrom-Json 和 CSV 导出使用 json 和 csv 模块，然后通过类型化模型进行数据验证
共享文件夹中的模块虚拟环境、包和依赖文件

一个很好的入门练习：用 Python 重写一个你已经信任的 PowerShell 脚本，例如会话主机健康报告，针对相同的 REST API。

Git 是另一个不可妥协的工具。将每个脚本、Terraform 文件和运行手册都存入仓库，进行小步提交并附上清晰的提交信息，在分支上工作，即使你是唯一的审查者也要发起拉取请求。拉取请求就是你已经熟悉的 CAB 流程：提议变更、审查、批准、记录。如果你更喜欢有指导的练习，Python 培训课程是一个结构化的选择。

简历定位

管理员往往罗列产品而非成果，而“Citrix、VMware、NetScaler、PVS”对云招聘经理来说几乎没有信息量。把每一行重写为问题、行动和结果，且不使用夸大的数字。

  • 较弱：“管理 Citrix Virtual Apps and Desktops 环境。”
  • 更强：“负责某医院临床和计费用户的发布桌面平台；重新设计配置文件管理，消除反复出现的慢速登录问题；通过变更控制流程主导每月镜像更新，并记录回滚方案。”

然后添加一个板块展示你的新工作：作品集项目，每个项目附上仓库链接、简短的架构描述以及你会改进之处。关于作品集结构以及审查者如何阅读它的更完整论述，请参阅构建 FDE 简历与作品集指南，它同样适用于云和 AVD 职位。

六个月计划

该计划假设你全职工作，并每周稳定投入学习时间。坚持比速度更重要。

第一和第二个月：基础

选择你的路径。学习一个云的基础知识（路径 1 选 Azure，路径 2 选 AWS 或 Azure）。开始在工作中和家里对你写的所有内容使用 Git。开始 PowerShell 到 Python 的重写练习。到月底，部署一个小型云环境，并能解释其网络和身份体系。

第三和第四个月：深入

路径 1：端到端完成 AVD 和 Intune 作品集项目。路径 2：认真学习 Terraform 并完成迁移运行手册。路径 3 的学习者完成路径 2 的工作，并添加一个调用托管模型的 Python API。在当前工作中主动承担一项小型云或自动化任务。

第五和第六个月：证明与定位

把一个作品集项目打磨到陌生人仅凭 README 就能部署的程度。路径 3 的学员会构建 EUC 故障排查助手及其评测报告。重写你的简历，并开始申请那些能将你现有深度与新技能相结合的职位：AVD 工程师、云 EUC 工程师、云基础设施工程师，或专注于 Windows 的平台工程师。

对于那些目标不止于云、还想进军企业级 AI 交付的人来说，Cloudsoft 的 FDE PRO 项目 是在云基础之后的下一步，为期 12 周，通过五个企业级项目和一个模拟客户交付，涵盖 RAG、AI Agent、MCP、评测与部署。

常见问题

2026 年 Citrix 仍然是不错的职业选择吗？

Citrix 和 VDI 技能在受监管的行业和 GCC（全球能力中心）仍有需求，但相关工作越来越多地在云平台上运行。最稳妥的定位是将 Citrix 深度与 Azure、AVD 和自动化技能相结合。

VMware 管理员应该先学 AWS 还是 Azure？

学习你当前雇主或目标雇主使用最多的云。如果你在以微软为主的环境中工作，且身边有 Citrix 或 AVD，那么 Azure 通常是自然的选择。只要精通一个云，核心概念在各个云之间都是相通的。

从 VDI 转向云需要学编程吗？

需要，但对于路径 1 和路径 2 来说，不必达到软件开发者的水平。你需要熟练的 PowerShell 或 Python 脚本编写能力，以及 Terraform 和 Git。通往 AI 的路径 3 则需要更强的 Python 能力，因为你要构建和维护应用服务。

AVD 和 Windows 365 有什么区别？

Azure Virtual Desktop 让你能在自己的 Azure 订阅中控制主机池、镜像、缩放和多会话主机。Windows 365 则提供托管的云电脑（Cloud PC），采用更简单的按用户计费模式，需要管理的基础设施更少。许多组织会针对不同的用户群体同时使用两者。

Citrix 管理员可以转向 AI 工程吗？

可以，但要先从云入手。打好云和 Python 基础，然后学习 RAG、AI Agent 和评测。EUC 方面的身份、网络和故障排查知识在企业级 AI 项目中确实很有用，尤其是在服务台和 IT 运维助手方面。

我的 VMware 或 Citrix 认证还有用吗？

它们体现了你在企业基础设施方面的深度，在混合云岗位中仍然相关。将它们与一项云认证搭配，更重要的是，再配一个能证明你能在云中构建的作品集项目。

如果我目前的工作纯粹是本地部署，如何获得云经验？

在工作中主动承担任何与云相关的任务，比如 AVD 试点、Intune 推广或迁移评估，并在自己的订阅中构建作品集项目，同时设置预算告警。有清晰设计决策的实验记录在面试中会被认真对待。
