安全与合规快速参考（FDE）

原标题：Security & Compliance Quick-Ref (FDE)

Vibe Engines · 2026-09-03 · 约 12 分钟读完

摘要

这篇面向FDE的安全与合规速查手册指出，SOC 2、HIPAA、GDPR等框架本质上是同一组控制措施的不同表述：明确数据内容、加密、限制访问并记录日志、最小化留存、管理供应商并制定事故预案。文章逐一介绍各框架的适用场景，讲解数据处理、密钥管理、AI/LLM特有风险（如提示注入、PII脱敏、零数据保留）、日志与泄露报告时限，并以诊所病历摘要试点为例演示HIPAA合规流程，还提供数据流一页纸模板、PII脱敏代码和最小权限申请等实操配方，强调带着证据（数据流图、访问模型、已填问卷）提前接触安全团队是通过审查的最快路径。

要点

  • 合规框架核心是同一组控制：加密、最小权限、日志、最小化留存与供应商管理
  • SOC 2是审计报告而非认证，Type II需3-12个月观察期，买家通常要求Type II
  • HIPAA要求先签BAA；GDPR泄露须72小时内上报监管机构，删除请求一个月内答复
  • LLM使用需确认不用于训练、脱敏PII、按用户权限过滤RAG检索
  • 通过安全审查的最快方式：提前介入并带上一页数据流图和已填问卷

足以赢得安全团队“同意”的知识：SOC 2 / HIPAA / GDPR 实际要求什么，如何处理数据和密钥，以及审查会检查哪些内容。

各类合规框架大多只是同一小撮控制项用不同术语表述：清楚你掌握哪些数据、对其加密、限制并记录谁能访问、只保留必要数据、管理接触数据的供应商，并为出问题时准备好应对方案。安全团队的职责是核实这些控制项确实存在，因此最快获得他们同意的方式是带着证据上门：数据流图、访问模型和已填好的问卷。

这是面向工程师的入门介绍，并非法律建议；最终决定权在客户的安全、隐私和法律团队。

各类框架（它们关注什么）

  • SOC 2
  • 信任控制项：访问控制、加密、变更管理、监控、供应商风险。是一份报告，不是法律。
  • SOC 2 Type I 与 Type II
  • Type I：控制项在某一时间点设计良好 · Type II：在 3–12 个月内被证明持续有效
  • ISO 27001
  • 可认证的信息安全管理体系国际标准
  • HIPAA
  • 美国健康数据（PHI）。需要签署 BAA、加密、访问日志和最小必要访问。
  • BAA
  • 商业伙伴协议（Business Associate Agreement）——任何供应商（包括 LLM API）接触 PHI 之前都必须签署
  • GDPR
  • 欧盟个人数据。需有合法依据、数据主体权利（访问/删除）、数据驻留和 DPA。
  • CCPA / CPRA
  • 加州隐私法：知情权、删除权以及选择退出数据出售或共享的权利
  • PCI-DSS
  • 银行卡数据。最简单的应对方式：完全不接触——使用令牌化或支付处理商。
  • FedRAMP
  • 向大多数美国联邦机构销售云服务所需的联邦授权；流程缓慢且成本高昂
  • 欧盟 AI 法案
  • 按风险分级的 AI 规则：某些用途被禁止，高风险系统和通用模型需承担相应义务

数据处理

  • 全面加密
  • 传输中使用 TLS；静态存储加密。这是不可妥协的基本要求。
  • 数据驻留
  • 明确数据必须保留在哪个区域/网络。这决定了部署目标。
  • 最小化 + 保留策略
  • 只收集所需数据；按计划删除。数据越少 = 风险越小。
  • PII 纪律
  • 在日志和提示词中对 PII 进行脱敏/遮蔽。未经批准，绝不将客户 PII 粘贴到第三方 API。
  • 数据分类
  • 将数据标记为公开、内部、机密或受监管——所有控制项都基于该标签
  • 假名化
  • 用令牌替换标识符；在 GDPR 下，只要映射关系存在，它仍属于个人数据
  • 真正有效的删除
  • 覆盖备份、日志、缓存、搜索索引和向量存储，而不仅仅是主表

密钥与访问

  • 代码/仓库中不存放密钥
  • 使用客户的 vault/KMS + 环境变量注入。定期轮换。绝不记录令牌。
  • 最小权限
  • 将密钥范围严格限定在所需内容；优先使用短期密钥而非长期密钥。
  • 审计追踪
  • 记录谁在何时做了什么。不可篡改、可导出——审计人员一定会问。
  • MFA + SSO
  • 与客户的身份提供商集成；不要另建一套并行登录。
  • 服务账号
  • 每个工作负载一个，权限范围要窄——绝不在自动化中使用个人凭据
  • 密钥扫描
  • 扫描代码仓库和 CI 日志中的泄露密钥，一旦发现立即轮换
  • 应急访问
  • 紧急管理员访问，需记录日志、限时使用并在事后审查

AI 与 LLM 专项

  • 提供商数据条款
  • 在合同中确认输入数据不用于训练，以及保留时长
  • 零数据保留
  • 部分提供商为敏感工作负载提供 ZDR；确认它排除了哪些功能
  • 提示词中的 PII
  • 发送前先脱敏或令牌化；提示词日志只存放在经批准、受访问控制的地方
  • 提示词注入
  • 将检索到的文档视为不可信输入，并限制模型可调用的工具
  • 权限感知 RAG
  • 在查询时按用户访问权限过滤检索结果，而不仅在索引时
  • AI 数据驻留
  • 当数据不能离开某司法辖区时，使用区域端点或自托管模型

日志与事件

  • 记录什么
  • 登录、管理员操作、数据导出和权限变更：谁、做了什么、何时
  • 绝不记录
  • 密码、令牌、完整卡号，或充满个人数据的提示词和载荷
  • 日志保留
  • 审计日志按框架或合同要求的期限保存，并防止被篡改
  • 泄露通报时限
  • GDPR：知悉后 72 小时内通报监管机构 · HIPAA：60 天内通报个人
  • 事件应对手册
  • 联系谁、如何遏制、由谁决定是否通报——在需要之前就写好

供应商与分包处理者

  • 分包处理者清单
  • 列出所有接触客户数据的第三方；客户可能对变更提出异议
  • DPA
  • 数据处理协议：GDPR 要求在控制者与处理者之间签订的合同
  • SCC
  • 标准合同条款——将欧盟数据转移至境外的常用法律依据
  • 供应商审查
  • 入驻前要求提供安全问卷、SOC 2 报告和渗透测试摘要

安全审查

  • 带上答案
  • 数据流图、数据存储位置、加密方式、访问模型、分包处理者。
  • 要求越少，批准越快
  • 请求最小范围 + 有限的系统足迹；要求过多会拖延进度。
  • 尽早让安全团队参与
  • 最后关头的否决会毁掉交易。在需求发现阶段就让安全团队参与进来。
  • 问卷
  • SIG、CAIQ 或客户自带的表格——建立一份已批准答案的答案库
  • 渗透测试报告
  • 一份近期的第三方测试摘要可以一次性回答许多问题
  • 架构图
  • 数据流、信任边界以及加密应用的位置——审查人员从这里开始
  • 例外情况书面化
  • 当某项控制无法满足时，记录补偿性控制并获得签署批准

实例演示：规划 HIPAA 试点：诊所就诊记录的 AI 摘要

一家诊所（HIPAA 覆盖实体）希望用 LLM 起草就诊记录摘要。在编写任何代码之前，先按以下阶段梳理数据记录：

  • 分类。 与患者关联的就诊记录属于 PHI。这使你的公司成为业务伙伴（business associate），而所有接触这些记录的供应商（云托管商、模型提供商、错误跟踪工具）都是需要签署 BAA 的分包商。拒绝签署 BAA 的供应商，无论其模型多好，都应排除在外。
  • 最小化。 只发送就诊记录本身，而不是整个病历。如果试点可以在去标识化数据上运行，Safe Harbor 方法会移除 18 类列出的标识符，例如姓名、病历号以及除年份以外的所有日期要素；以这种方式去标识化的数据不再是 PHI。
  • 存储与使用。 静态加密，通过诊所的 SSO 将访问权限限制在试点团队，并记录每一次查看和导出就诊记录的行为。不要将提示词和输出写入通用的应用日志。
  • 保留与删除。 约定草稿的保留时长，并按相同的时间表从备份和任何向量索引中删除它们。HIPAA 的政策、程序和风险分析本身必须保存 6 年。
  • 为糟糕的一天做计划。 必须在发现泄露后无不当延迟地、且在 60 天内通知受影响的个人。涉及 500 人及以上的泄露同样须在 60 天内上报 HHS；影响某州 500 名以上居民的泄露还须通知该州的主流媒体；较小的泄露则记录在案，并在每年年末后 60 天内报告给 HHS。

交给诊所安全审查的交付物是一页纸的数据流文档，其中包含上述每个问题的答案、已签署的 BAA 以及访问权限清单。这一页纸通常比任何演示都更能加快试点的推进。

实用方案

审查者要求的一页纸数据流摘要

Data:           support tickets with names and emails (PII); no payment or health data
Flow:           customer helpdesk → our API (TLS 1.2+) → Postgres in eu-west-1 (encrypted at rest)
LLM use:        ticket text sent to the model provider under no-training, limited-retention terms
Access:         SSO + MFA; 4 engineers with production access; every query logged
Retention:      raw tickets 90 days, then deleted from the database, backups and the vector index
Subprocessors:  cloud host, model provider, error tracker (listed in the DPA)

提前回答这六个问题，可以预先化解安全问卷中的大部分内容，并向审查者表明你已经以他们的思维方式思考。

在数据进入日志或提示词之前脱敏 PII（Python）

import re

EMAIL = re.compile(r"[\w.+-]+@[\w-]+\.[\w.-]+")
CARD = re.compile(r"\b\d(?:[ -]?\d){12,15}\b")

def redact(text: str) -> str:
    text = EMAIL.sub("[email]", text)
    return CARD.sub("[card]", text)

正则表达式只能捕获明显的格式；对于姓名、地址和自由文本，应使用专用的 PII 检测器，并在边缘进行脱敏，使原始数据永远不会落入日志。

针对集成的最小权限访问申请

Need:    read-only access to orders from the last 30 days
Grant:   a dedicated service account with role orders.read, scoped to one project
Avoid:   an admin's personal API key, wildcard scopes, keys that never expire
Rotate:  every 90 days, stored in the customer's vault, injected at runtime
Audit:   every call logged with the service account ID and reviewed monthly

更小的权限申请能更快获得批准，并在凭据泄露时限制损害——这正是审查者所权衡的。

处理 GDPR 删除请求

1. Verify the requester's identity
2. Find every copy: database, replicas, backups, logs, caches, search and vector indexes, analytics
3. Delete or anonymize, and record what was removed and when
4. Tell your processors and subprocessors to do the same
5. Reply within one month (extendable when requests are complex)

期限从收到请求之日起算，而人们容易遗忘的副本（如备份、导出文件和嵌入向量）正是审计中发现缺口的地方。

何时适用，何时不适用

合规框架依附于数据和客户，而不是你的技术栈。根据触发条件判断哪些框架适用：

如果你……预期结果
向美国企业销售软件收到 SOC 2 Type II 报告请求和安全问卷
向欧洲买家或全球企业销售ISO 27001，常与 SOC 2 并列或作为其替代方案被接受
向欧盟用户提供服务，或为欧盟客户处理数据GDPR，即使没有欧盟办事处也需要：数据处理协议（DPA）、合法处理依据、数据主体权利
为美国受监管实体处理健康数据作为业务伙伴适用 HIPAA，首先签署 BAA
接触到卡号PCI DSS；使用托管支付页面或令牌化支付处理商可将你的合规范围缩小到最小的自我评估
向美国联邦机构销售云服务FedRAMP

HIPAA 的适用范围比人们想象的窄：不为受监管实体工作的消费级健康应用通常不在其范围内，不过州隐私法和 FTC 的《健康数据泄露通知规则》可能仍然适用。情况不明确时，由客户的律师决定，而不是工程师。

权衡与局限

方案换来什么代价
先做 SOC 2 Type I无需等待观察期即可获得报告许多买家仍然坚持要 Type II
自托管模型数据不离开你的环境；解决数据驻留问题GPU 和运维成本，而且模型往往不如最好的托管模型
零数据保留服务商不存储提示词需要存储状态的功能可能不可用
假名化数据集泄露时暴露更少；数据仍然可用只要密钥存在，在 GDPR 下仍属个人数据
匿名化完全脱离 GDPR 管辖实际操作很难；信息丰富的记录常常可以被重新识别
长期保留日志数月后仍可做取证分析需要保护的个人数据更多，而且在删除请求时更难查找

每项控制措施还需要证据支撑。审计师要看到它在实际运行，例如带有签字确认的、注明日期的访问审查；无法展示的控制措施，就报告而言，等于不存在。

常见错误

  • 把 SOC 2 称为认证。 它是审计师的鉴证报告：你得到的是一份报告，而不是认证。ISO 27001 才是真正的认证，评审者会注意到这个区别。
  • 对邮箱做哈希就称之为匿名。 通过对一份已知地址列表做哈希并比对，即可逆向还原邮箱的 SHA-256。这属于假名化的个人数据，仍需承担所有 GDPR 义务。
  • 在测试环境使用生产数据。 用于测试的客户数据库副本与生产环境承担同样的合规义务，而且通常访问控制更弱、没有审计日志。请使用合成数据或脱敏数据。
  • 添加供应商却不更新子处理者清单。 任何能接触客户数据的新错误追踪工具或 LLM API 都属于合同变更；许多 DPA 要求提前通知，以便客户提出异议。
  • 把“静态加密”当作访问问题的答案。 磁盘加密防的是硬盘被盗，防不了合法的查询。评审者想知道谁能查询数据，以及这些查询记录在哪里。

自我检查

你的团队在周一 09:00 得知发生了一起个人数据泄露事件。根据 GDPR，监管机构必须在何时得知此事？

必须毫不迟延地通知，且在可行的情况下，最迟在周四 09:00 之前，即知悉后 72 小时内，除非该泄露不太可能给个人带来风险。若延迟通知，必须说明延迟的原因。

一项 GDPR 删除请求于 3 月 3 日送达。你必须在何时之前回复？

一个月内，即 4 月 3 日之前。对于复杂或大量的请求，可以再延长两个月，但必须在第一个月内告知当事人延长一事及原因。

你使用一家 LLM 提供商来总结欧盟客户的支持工单。必须具备哪些文件？

与该提供商签订的数据处理协议（DPA）；将该提供商列入你的次级处理者名单，并按你的客户 DPA 所要求的通知方式进行通知；此外，如果数据离开欧洲经济区（EEA），还需要传输机制，例如标准合同条款（SCC），或针对已认证美国公司的充分性认定，如欧盟-美国数据隐私框架。

一位客户需要 SOC 2 Type II 报告；你上个月刚完成 Type I。还缺什么？

时间。Type II 涵盖一个观察期，通常为 3 到 12 个月，在此期间审计师会抽样取证，证明控制措施确实在运行。Type I 只能证明控制措施在某一日期设计得当。

关于《安全与合规速查手册》（FDE）的问题

SOC 2 Type I 和 Type II 有什么区别？

两者都是独立审计师依据 AICPA 信任服务准则（最常见的是安全准则）出具的鉴证报告。Type I 报告说明所述控制措施在单一时间点设计得当。Type II 报告则说明控制措施在一个观察期（通常为三到十二个月）内基于抽样证据有效运行。企业买家通常期望 Type II，因为它证明控制措施在日常运作中确实有效。初创公司往往先取得 Type I，然后在第一个观察期结束后再取得 Type II。

我可以把客户数据发送到 LLM API 吗？

只有在客户批准且条款合适的情况下才可以。查看提供商的数据使用政策，其中应声明 API 输入不会用于训练，确认提示词和输出的保留时长，并签署数据处理协议，若涉及 HIPAA 下的健康数据还需签署商业伙伴协议（BAA）。数据驻留要求可能需要使用区域端点或自托管模型。只发送任务所需的最少数据，尽可能对个人数据进行脱敏，并在客户文档中将该提供商列为次级处理者。

对供应商的安全审查通常检查什么？

审核人员想知道你会接触哪些数据以及如何保护这些数据。请准备好回答关于数据流和数据存储位置、传输中和静态加密、身份验证和单点登录、贵公司哪些人员可以访问客户数据以及如何记录这些访问、密钥和漏洞管理、事件响应流程、子处理者，以及 SOC 2 或 ISO 27001 等认证的问题。携带数据流图、预先填写的问卷和范围狭窄的访问请求，是最快通过审核的方式。

根据 GDPR，数据泄露必须在多长时间内报告？

控制者必须毫不迟延地通知相关监管机构，并在可行的情况下，在知悉个人数据泄露后 72 小时内通知，除非该泄露不太可能对个人权利和自由造成风险。当对个人的风险较高时，还必须毫不迟延地告知数据主体，处理者也必须毫不迟延地通知控制者。合同通常会规定更短的期限，因此事件响应手册应明确由谁决策、由谁通知，以及哪些客户必须最先得知。
