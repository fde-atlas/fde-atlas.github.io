Cursor 如何在企业内部署 AI

原标题：How Cursor deploys AI inside the enterprise

Prismix · 2026-07-01 · 约 7 分钟读完

摘要

Cursor 前沿部署工程负责人 Pauline Brunet 在 Latent Space 采访中介绍其团队定位与愿景：FDE 深入客户现场，围绕客户工作流部署高度定制的 AI Agent，目标是打造覆盖软件开发生命周期全流程的“AI 软件工厂”。团队全部由五年以上经验的软件工程师组成，年底前计划扩张十倍。她指出企业采用仍集中在少数早期采用者，需要高层支持与内部推动者配合，并建议有志者通过端到端交付生产级项目积累经验。

要点

  • FDE 定位为驻场定制部署，而非开箱即用支持。
  • 愿景是 AI 软件工厂，覆盖规划到运维全生命周期。
  • 团队全为工程师，年底前拟扩张十倍。
  • 企业采用集中于早期采用者，需高层与推动者支持。
  • 建议通过端到端生产项目并讲清设计权衡来入行。

前沿部署工程已迅速成为企业 AI 领域最突出的角色之一。前沿部署工程师（FDE）处于软件工程、产品开发和客户实施之间，直接与各组织合作，落地 AI 能力。

在 Cursor，这一角色的定位尤为宏大。公司前沿部署工程副总裁 Pauline Brunet 正在组建一支团队，与各组织合作，在整个软件开发生命周期中落地 AI Agent。

在 AI Engineer World’s Fair 期间接受 Latent Space 采访时，Brunet 谈到了 Cursor 对“AI 软件工厂”的愿景、将 AI Agent 的采用从个人爱好者扩展到更大范围的挑战，以及工程师若想转向前沿部署工作需要展现出哪些能力。

前沿部署工程在 Cursor 意味着什么

Latent Space: 首先，你如何定义前沿部署工程？

Pauline Brunet: 前沿部署工程取决于业务、产品和客户。你必须考虑应用的可配置程度。它是客户开箱即用的东西，还是你在部署一个复杂且高度可配置的系统？

你还必须考虑客户处于其旅程的哪个阶段。

我不认为前沿部署工程是支持传统开箱即用部署的团队。我把它看作一支深入现场、在客户的系统和工具内部工作、并部署能够大规模解决挑战的应用或平台的团队。

这些部署高度可配置，并围绕客户的工作流、流程、系统和工具进行定制。

Latent Space: Cursor 的客户主要是工程师。FDE 角色如何应用于他们使用产品的方式？

Brunet: Cursor 是一个 AI 编程平台和编程助手。我们与客户合作开展 AI 辅助编程、同步与异步 AI Agent，以及最终的 AI 软件工厂理念。

如今，我们与众多行业的客户合作，包括金融服务、电信、软件开发、技术和半导体。

我们帮助转型负责人、IT 负责人和 CTO 组织在整个运营中构建 AI 软件工厂。这包括他们如何规划和设计软件、如何编写代码、如何测试和审查代码，以及如何大规模部署和维护应用。因此，非常专注于从头到尾的软件开发生命周期。

组建 Cursor 的 FDE 团队

Latent Space: Cursor 的 FDE 团队规模有多大？

Brunet: 我们正在快速增长。我们的目标是在 12 月底之前将团队规模扩大十倍。

Latent Space: 你们目前的 FDE 员工主要是工程师，还是团队中也包括产品专家？

Brunet: 他们都是工程师。我们招聘拥有至少五年经验、并且具备丰富面向客户经验的软件工程师。

这些人是在生产环境中开发和发布过代码的人。他们构建和设计过系统，能够做出权衡决策，并评估应该使用哪些系统或技术。

他们还需要有面向客户的经验。我们的团队成员曾就职于 Spotify、Rippling 和 Palantir 等公司，并为客户部署过生产系统。

从编码助手到软件工厂

Latent Space: 你提到了“软件工厂”这个词，它在行业中出现得越来越频繁。这个词对 Cursor 来说意味着什么？

Brunet: 对 Cursor 来说，它指的是从头到尾的软件开发生命周期：你如何规划、设计、编写、审查、测试和部署代码。

如今，这些阶段通常由不同的团队负责。你可能有一个设计团队、一个开发团队，以及与他们协作的产品经理。每个团队可能都在用 AI 辅助编码来优化自己的工作，但整个流程仍然是割裂的。

我们希望在整个生命周期中帮助客户。你应该能够说：“这是我想开发的功能”，然后让长时间运行的 Agent 在每一个步骤中与你协作。这可能包括制定计划和产品需求文档、制作功能可能呈现的演示、编写和测试代码、将其投入生产并进行维护。

问题反馈和产品反馈也应该回流到同一个生命周期中。对我们来说，软件工厂意味着由长时间运行的 Agent 在整个过程中为人们提供帮助。

Latent Space: 所以它比单纯的 Agent 编排范围更广？

Brunet: 没错。正是如此。

超越个人 AI 使用者

Latent Space: 企业在尝试落地 Agent 技术时遇到了哪些问题？

Brunet: 一个挑战是，采用仍然集中在早期采用者身上。

在一个组织中，可能有 10% 或 20% 的人是热情的早期采用者。他们在自己的任务中使用本地 Agent 和云端 Agent 做出了出色的工作，并且变得非常高效。

下一阶段所缺失的，是跨团队、跨流程和跨工作流使用长时间运行 Agent 的能力。

这需要组织高层的更多支持。领导层必须明确表示：“这是优先事项，这就是我们希望自动化或改变这个流程的方式。”

因此，对于 FDE 团队来说，在组织内部找到合适的拥护者非常重要：这些人是真正希望对业务产生实质性改变的人，他们会与我们以及他们的内部团队合作，共同转变工作的完成方式。

用云端 Agent 实现工作标准化

Latent Space： 本地 AI 似乎正在兴起，部分原因是开源模型越来越容易获取。你们是否在为客户做更多的本地 AI 实施工作？

Brunet： 我们有本地 Agent，用户可以通过桌面应用或 CLI 运行，这种体验基本上是自助式的。人们以惊人的速度采用了这项技术，尤其是在 Cursor 的用户群体中。

我们也看到人们开始采用云端 Agent，因为他们很兴奋能够运行任务而不必让笔记本电脑半开着。Agent 现在可以在云端处理以前在本地运行的任务。

有趣的是当这超越了 Agent 帮助某个人完成工作的范畴。下一个问题是 Agent 如何跨职能、跨团队或跨组织工作，从而一致地实现流程自动化。例如，你可以让一个 QA Agent 在多个开发团队中应用相同的流程。

我们收到了很多客户关于这类用例的提问。

客户部署如何影响 Cursor 的路线图

Latent Space： 这些部署中的经验教训是否会反馈到 Cursor 的核心产品中？

Brunet： 是的。前沿部署工程团队与客户在他们的用例上紧密合作，因此我们自然而然地成为产品和工程团队了解客户下一步想构建什么的一个良好渠道。

我们与这些团队紧密合作，在帮助塑造 Cursor 的产品路线图方面发挥着重要作用。

前沿部署工程师角色的变化

Latent Space： 随着 Agent 变得更加自主，你预计 FDE 角色将如何演变？

Brunet： 我认为这个角色将发生巨大变化。我常说，如果我们还在做六个月前做的同样的工作，那我们就做错了什么。

目前，人们仍在寻找他们可以解决的用例方面的灵感，因此我们希望提出新的可能性。

例如在软件开发中，我们可以展示设计师和产品经理如何与开发人员和测试团队一起在 Cursor 中无缝协作。

我们还可能询问一家公司是否考虑过使用长时间运行的 Agent 来从头到尾处理呼叫中心或工单流程。

随着我们在医疗保健、生命科学、公共部门、零售和消费包装商品等行业开展工作，我们将继续在营销、销售和供应链运营中发掘用例。FDE 角色将随着这些可能性一同演进。

工程师如何为 FDE 职业生涯做好准备

Latent Space: 这场大会上有大约 7,000 名 AI 工程师。对于想转入前沿部署工程的开发者，你有什么建议？

Brunet: 今天我已经进行了五六次这样的对话。我们寻找的是具备软件工程经验的构建者：那些发现问题并从零到一构建出生产级应用或系统的人。

你应该亲自设计、开发、测试它，并让它投入生产、服务真实用户。

我的建议是在你的组织内部寻找这类项目，并从头到尾负责它们。确保你理解自己做出每个设计决策的原因。

你是如何选择数据库的？你是如何挑选不同的服务的？为什么用那种特定方式设计系统？权衡取舍是什么？

你还应该理解可衡量的投资回报，既包括传统商业意义上的回报，也包括通过评测来证明你为内部客户创造的价值。

如果你想进入前沿部署工程领域，就要熟悉这类项目，积累交付它们的经验，并学会解释你所做的决策。
