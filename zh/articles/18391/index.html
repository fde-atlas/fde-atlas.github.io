DS+FDE 混合团队设计｜面向日本企业的 AI 实施组织论

原标题：DS+FDEハイブリッドチーム設計｜日本企業のためのAI実装組織論

FDX株式会社 · 2026-06-26 · 约 10 分钟读完

摘要

这篇文章面向日本企业，提出由部署策略师（DS）与前沿部署工程师（FDE）组成的混合团队设计方法。标准配置为1名DS搭配2至3名FDE，因为一名DS最多只能并行管理2至3条实施线。文章给出小规模、中规模、企业级三种体制模式，并设计了日次站会、周次三层评审、月度经营汇报与季度撤退判定的沟通机制。导入路线分为业务理解与KPI设计、试点、正式上线与内制培养、自走化与撤退四个阶段，最短12个月、标准18个月。作者还指出三大反面模式：无DS只配FDE、DS完全远程、实施方不撤退导致依赖。撤退条件应在合同中明文化，并将成果报酬与KPI挂钩。

要点

  • 标准比率为1名部署策略师搭配2至3名FDE。
  • 体制分小规模、中规模、企业级三种模式。
  • 导入分四阶段，最短12个月、标准18个月。
  • 季度撤退判定与合同明文化撤退条件是关键。
  • 三大反面模式：无DS、DS远程、实施方不撤退。

结论：DS+FDE以「1:2〜3」「三层评审」「季度撤退判定」来运转

  • 构成比率：1 DS : 2〜3 FDE是标准。1名DS能同时照看的实施流最多2〜3条，超过这个数量DS侧就会成为瓶颈，导致整体停滞。
  • 沟通设计：每日站会 + 每周三层评审（经营 / 指导 / 实施）+ 每月经营报告进行同步。用Notion + Loom + Slack实现异步化。
  • 导入顺序：Phase 0（业务理解 / KPI设计）→ Phase 1（PoC）→ Phase 2（正式上线 / 内制培养）→ Phase 3（自主运转 / 撤退）4个阶段。最短12个月，标准18个月。

体制的3种模式

模式A：小规模（年投资5〜15亿日元）

构成：1 DS + 2 FDE + 1〜2名内制王牌

适用场景

  • 单一事业部1个业务领域的AI实施
  • 希望在6〜12个月内完成从PoC到正式上线的阶段
  • 没有内制组织，但有1〜2名内制王牌候选人

运作

  • DS直接向事业负责人汇报
  • FDE与现场负责人每周进行指导评审
  • 内制王牌与FDE并肩工作，在12个月内完成技术交接

人数少，决策快，沟通损耗也少。撤退判定也容易做出。但另一方面，不适合横向推广，且对负责的DS / FDE个人依赖度高的弱点明显。

模式B：中规模（年投资30〜60亿日元）

构成：2 DS + 5〜7 FDE + 内制团队3〜5名

适用场景

  • 向多个业务领域横向推广的阶段
  • 内制团队虽已成立，但还难以独立运作的时期
  • 新设AX推进室，目标2年内实现内制化

运作

  • 2名DS共同向CDO / 事业本部长汇报
  • 1名DS担任“战略负责”，另1名DS担任“实施统筹”
  • 5〜7名FDE分散配置到多个项目（业务领域）
  • 每月整体经营报告 + 按项目的每周指导评审

优势在于可以同时着手多个业务，并与内制团队培养并行推进。但2名DS之间如何同步信息将决定成败，跨项目的资源协调也会一下子变得复杂。

模式C：企业级（年投资超100亿日元）

构成：3+ DS（按事业部）+ 10+ FDE（按业务）+ 内制AX组织10〜30名

适用场景

  • 全公司横向的AX推进阶段
  • 多事业部、多业务领域同时并行
  • 计划在24〜36个月内建立30〜50名的内制组织

运作

  • 每个事业部配置1名DS
  • FDE按业务领域（销售 / 市场 / 制造 / 客户支持等）编组
  • 在CDO直属下新设AX推进室，纳入内制DS / FDE
  • 每月全公司AX委员会 + 按事业部的每周指导评审

能将全公司的AI投资作为结构加以整合，内制组织也能伴随规模成长。但体制本身庞大，初期搭建需要6〜12个月，部门间的政治性协调成本也不容忽视。

异步沟通

  • Notion / Confluence：统一管理决策日志 / 业务KPI仪表板 / 规格书 / 撤退判定标准。以经营层也能读懂的粒度撰写。
  • Loom / 视频报告：将每周评审以5〜10分钟的视频留存，让未能参加的利益相关者事后也能掌握。
  • Slack / Teams：每日进度 + 阻塞事项 + 业务方的提问。频道按“经营报告”“指导”“实施”“业务提问”4分法是惯例做法。

报告设计

面向经营层的报告以每月“ROI故事”形式为主流。

  • 本月KPI改善实绩（业务KPI / 业务应用率）
  • 当初投资假设与实绩的差异
  • 下月的主要里程碑
  • 撤退 / 扩大判定材料的进展

甘特图和任务列表对经营层来说并不需要。应聚焦于决策材料。

面向日本企业的四阶段导入路线图

Phase 0：业务理解 / KPI 设计（0〜3 个月）

目的：DS 完成业务理解和 KPI 设计，与经营层就实现范围和成功标准达成一致。

主要活动

  • 业务访谈 / 现场跟岗观察
  • 业务 KPI 的定量化
  • 识别可用 AI 驱动的指标
  • 与经营层就 PoC 的范围和成功标准达成一致

交付物：业务 KPI 仪表盘 / 成功标准书 / PoC 计划书

此阶段 FDE 有 1 名左右参与即可。如果在实现阶段开始之前就让 FDE 全职投入，会在业务理解尚浅的情况下开始实现，之后产生返工。

Phase 1：PoC（3〜6 个月）

目的：FDE 实现 PoC，证明业务 KPI 可以通过 AI 驱动。

主要活动

  • 数据获取 / 整备
  • AI 模型 / Agent 实现
  • 与业务侧用户的 UX 集成
  • 对照成功标准进行评测

交付物：可运行的 PoC / 评测报告 / 生产化判定材料

此阶段让 1 名内制王牌（候选人）参与。开始跟随 FDE 学习，为 Phase 2 之后的技术移交做好准备。

Phase 2：生产化 / 内制培养（6〜12 个月）

目的：将 PoC 投入生产运营，推进内制团队的培养。

主要活动

  • 生产系统构建 / 运营设计
  • 监控 / 告警 / SLI/SLO 的整备
  • 内制工程师培养（OJT / 代码评审）
  • 横向推广候选业务的选定

交付物：生产系统 / 运营手册 / 内制团队培养完成报告

这是 DS / FDE 负荷最高的阶段。坚持月度经营汇报和周度指导，加强与内制团队的并行协作。

Phase 3：自主化 / 撤退（12 个月以后）

目的：完全移交给内制团队，DS / FDE 撤退。

主要活动

  • 将修改 / 扩展的主导权移交给内制团队
  • DS 在撤退前 1〜3 个月，仅参与月度经营汇报
  • FDE 在撤退前 2〜3 个月，缩减为每周 1〜2 天的临时支援
  • 撤退后 1〜3 个月提供远程支持（仅答疑）

交付物：自主化完成报告 / 移交完成书 / 撤退记录

如果撤退设计模糊，就会变成“实现合作伙伴赖着不走”的状态，内制组织的主动性无法培养起来。应将撤退条件在合同中明确写明（参考：AI 内制化的推进方法｜摆脱外包依赖的 5 个步骤）。

三个反模式

反模式 1：不设 DS，只投入 FDE

典型模式是认为“先放上工程师就能出成果”。实际上“做什么”无法确定，PoC 泛滥，也无法进行生产化判定。

规避方法：务必先配置 DS。不设 DS 只招 FDE，等同于“没有设计图就开始施工”。

反模式 2：DS 不下现场（专职远程）

如果 DS 专职远程，无法捕捉现场的隐性知识，业务 KPI 的设计会流于表面。Palantir / Anthropic / OpenAI 重视 DS 的实地驻在，正是出于这个原因。

规避方法：DS 每周 2〜3 天在客户办公室实地驻在。完全远程不适合企业级 AI 实现。

反模式 3：FDE 在 PoC 之后不撤退（制造依赖）

如果实现合作伙伴一方持有“赖着不走”的激励，内制组织就无法成长，会永久性地依赖外包。这种情况在“撤退条件未写入合同”“绩效报酬与 KPI 不挂钩而与工时挂钩”时容易发生。

规避方法：将撤退条件、自主化的定义、内制化里程碑落实到合同中，并将绩效报酬与 KPI 达成而非工时挂钩。用合同从根源上消除“赖着不走”的激励。

FAQ

Q1. DS 与 FDE 的比例为什么是 1:2〜3？

1 名 DS 能同时并行支持的实施流上限为 2〜3 条。要在经营层对话 / 业务理解 / KPI 设计 / 撤退判定之间分配时间，同时承担 3 条以上并不现实。

反过来，如果 1 名 DS 只与 1 名 FDE 并行，DS 的成本无法收回。1:2〜3 是从经济合理性和运营质量的平衡中得出的比例。

Q2. 现有员工能否转型为 DS / FDE？

可以。但转型需要时间。

  • 战略咨询出身 → DS：3〜6 个月（补强经营对话经验）
  • 事业部 PM 出身 → DS：6〜12 个月（补强 KPI 设计 / 经营对话）
  • SE / 程序员出身 → FDE：6〜12 个月（补强业务理解 / 客户对话）
  • 数据科学家出身 → FDE：3〜6 个月（补强运营设计 / 业务应用）

详情请参阅“将 FDE 融入组织｜技能地图与评价标准”。

Q3. 哪些角色可以兼任？

  • DS 与 FDE：原则上不可兼任。例外是超小规模（仅限 PoC 启动后的 1〜2 个月）
  • DS 与 PM：可以兼任，但要减轻 PM 的负荷
  • FDE 与内制王牌：可以。FDE 兼任内制王牌候选人的情况在培养上是理想的

Q4. 汇报线是经营层直属还是事业部？

原则上经营层直属。如果事业部直属，AX 推进会被事业部的利益牵制，全公司横向推广无法推进。

但在深入绑定特定事业部业务的阶段，有时会临时将汇报线改为事业部。Phase 2后半段至Phase 3容易出现这种情况。

Q5. 撤退判定的判断标准是什么？

三个标准

  • 业务KPI的改善是否持续：改善停滞 → 重新审视假设 / 撤退
  • 内制团队能否独立运营：已独立 → DS / FDE撤退
  • 是否能看到横向推广候选：能看到 → 扩大范围 / 看不到 → 撤退

每季度按上述三个标准进行评审，并明确作出判定。不作判定而继续下去是最糟糕的模式。

Q6. DS / FDE是专属一家公司，还是同时服务多家公司？

在企业级项目中，DS为专属（1家公司1个项目），FDE为专属或1人最多2个项目是标准做法。同时承担的项目增多，业务理解的深度会下降，PoC会流于形式。

在初创项目或PoC初期阶段，DS有时会同时承担多个项目，但需以质量下降为前提来运营。

FDX的DS+FDE体制提供

FDX株式会社以从模式A（小规模）到模式B（中规模）的阶段性扩展作为标准提供。

  • 初期6个月：以1 DS + 2 FDE启动（模式A）
  • 6〜12个月：扩展至2 DS + 5 FDE（过渡到模式B）
  • 12个月以后：交接给内制DS / FDE → 撤退

企业级项目（模式C）也可承接，但原则是“从小规模开始，在附带撤退条件的前提下扩展”的设计。退出条件事先写入合同，自主运营完成后即退出。通过这种方式，从结构上防止“对实施伙伴的依赖”。

总结

  • DS+FDE混合团队的标准比例是1 DS:2〜3 FDE。1名DS能够并行跟进的实施流上限为2〜3条
  • 体制有小规模、中规模、企业级3种模式，根据投资规模和内制化计划来选择
  • 沟通机制按每日站会＋每周三层评审＋每月经营报告＋每季度撤退判定来设计
  • 面向日本企业，Phase 0〜3的4阶段、最短12个月（标准18个月）的导入路线图较为现实
  • “没有DS的FDE投入”“DS远程专职”“不撤退的实施伙伴”是三大反模式
  • FDX株式会社以从小规模开始、在附带撤退条件的前提下扩展的阶段性设计作为标准提供
