搭建你的外勤工具包

原标题：Setting up your field kit

LMVersity · 2026-09-02 · 约 6 分钟读完

摘要

这是 LMVersity 培训路径的入门实验课，指导学员在写代码前先搭好“野外工具包”：可用的终端环境（Windows 需装 WSL2）、Python、Git、Docker，并强调必须通过实际运行命令来验证安装。课程要求注册一个云账户（AWS、GCP 或 Azure），依次开启 root 账户 MFA、创建非 root 的 IAM 用户、设置低额账单告警。还需建立一个公开 GitHub 仓库，存放证据作品集索引和第一人称日志，日志要写下自己对前沿部署工程师的定义及已具备与欠缺的职责。文章强调公开仓库和诚实日志是九个月后供招聘方查看的成长记录，并警告不要用 root 日常操作、不要跳过账单告警、不要中途更换云服务商。

要点

  • 所有工具须通过实际运行验证，而非默认安装成功。
  • 云账户三步走：root 开 MFA、建非 root 用户、设账单告警。
  • 公开仓库同时承载作品集索引与第一人称日志。
  • 日志是 Phase 08 的对照基线，须诚实记录。
  • 全程坚持一家云服务商，避免中途重学概念。

配置你在接下来九个月中要使用的笔记本电脑、账户、云免费套餐、公开仓库和日志，并在写下第一行代码之前先写下你的第一篇日志。

  • 通过实际运行来确认终端环境可用，包括 Python、Git 和 Docker——而不是装完就默认它没问题。
  • 创建一个启用了 MFA 的云账户，一个用于日常工作的非 root 用户，并在配置任何资源之前设置好账单告警。
  • 建立一个公开仓库，存放你的证据作品集索引和第一人称日志，并且每一项都要有真实的第一篇内容。

这条路径上的每个实验室、演练、训练营和毕业项目都假设在开始之前已有四样东西存在：一台你可以信任的笔记本电脑、一个你了解其成本的云账户、一个可以存放作品的公开场所，以及记录所发生事情的习惯。本实验室将建立这四样。现在就认真做好，之后你就不必再操心，直到 Phase 05 要求你使用超出免费套餐范围的云账户功能。

你要构建什么

不是一个完美的环境，而是一个可用的环境，其中每一部分都通过实际运行得到确认——因为“我装好了”和“它能用”是两种不同的说法，而它们之间的差距正是真实项目中第一周调试真正发生的地方。

步骤

1. 确认你实际要使用的终端。

如果你使用 Windows，请安装 WSL2，并在其中完成本路径的所有工作，而不是在 PowerShell 中——FDE 会用到的大多数工具（Docker、

ssh

,

grep

,

awk

）都假设使用 Linux shell，现在学会这个转换层比以后调试它更划算。如果你使用 macOS 或原生 Linux，你已经有终端了；确认它能快速打开，并且你知道如何不费周折地找到它。

echo $SHELL

2. 安装并确认 Python。

python3 --version
python3 -m venv --help

两条命令都应返回输出，而不是“command not found”。如果 Python 缺失或版本过旧，请通过你平台的包管理器（

apt

,

brew

或 WSL 发行版的包管理器）安装当前版本，而不是从随机网站下载安装包。

3. 安装并确认 Git，如果没有 SSH 密钥则生成一个。

git --version
ls -la ~/.ssh
# if no id_ed25519 or id_rsa exists:
ssh-keygen -t ed25519 -C "your_email@example.com"

现在就把公钥添加到你的 GitHub 账户。在本路径的每个仓库中，你都将使用 SSH，而不是粘贴密码的 HTTPS，因为这是你希望在 Phase 01 的 Git 模块之前养成的习惯，而不是之后。

4. 安装并确认 Docker。

docker --version
docker run hello-world

第二条命令应拉取一个小镜像并打印成功消息。如果它因权限问题失败（Linux 上的常见问题：你的用户不在

docker

组中），请立即修复——Phase 01 的容器模块假设这已经可以正常工作。

5. 选定一个代码编辑器，并确认一个扩展：内置终端。 在这条路径中，VS Code 是默认选择，因为它的扩展对 Python、Docker 和远程 SSH 会话的支持都很完善，但如果你已经对某个编辑器形成了真正的肌肉记忆，用哪个都可以。重点不在编辑器本身，而在于你可以在不切换窗口的情况下编辑文件并对其运行命令，因为这种循环你将重复成千上万次。

6. 创建一个云账户，且只创建一个。

根据免费额度选择 AWS、GCP 或 Azure，并在整条路径中坚持使用它——Phase 01 的云模块和后续多个实验都假设你保持一致，而不是让你在第二家云服务商上重新学习 IAM 概念。AWS 是本路径实验中最常见的选择，其免费额度覆盖面也最广；如果你已有偏好 GCP 或 Azure 的理由，它们同样适用。

在你开通任何资源之前，按顺序完成以下三件事：

  • 注册后立即为根账户启用 MFA。
  • 创建一个非根 IAM 用户（或等效身份），只授予你实际需要的权限，此后所有命令都使用它。绝不要以根账户或账户所有者的身份进行日常操作。
  • 设置账单提醒。 阈值要低——相当于几美元——一旦超过就给你发邮件。这不是可选项。免费额度的限制是真实存在的，但很容易意外超出（一个忘关的实例、一个不断增长的存储桶），设置提醒的意义在于让你从邮件中得知，而不是从账单中得知。
# AWS example: confirm the CLI is configured against the IAM user, not root
aws sts get-caller-identity

输出应显示 IAM 用户的 ARN，而不是账户根用户的 ARN。

7. 创建你的公开仓库。

一个公开仓库，用于存放接下来九个月你要用到的两样东西：上一课的成果证据组合索引，以及你的日志。现在就初始化它。

mkdir fde-field-kit && cd fde-field-kit
git init
echo "# FDE Field Kit — [your name]" > README.md
mkdir portfolio journal
touch portfolio/index.md
touch journal/2026-09-02.md
git add .
git commit -m "Initialise field kit: portfolio index and journal"

将其推送到 GitHub 作为公开仓库。选择公开而非私有是有意为之：这个仓库本身就是你成果证据组合中的第一件作品，招聘负责人应该能够看着它在接下来的九个月里不断成长，这与你最后才展示的私有仓库相比，是一种不同且更有力的信号。

8. 今天就用第一人称写下你的第一篇日志。

不是待办清单，而是一段坦诚的文字。其中要回答两个问题，均来自之前的引导页面：一是用你自己的话、在你还了解不多的时候，写下你对“前沿部署工程师是什么”的一段话定义；二是对照“前沿部署工程师实际做什么”中的十三项职责，指出哪些是你在以往任何工作、项目或社团中真正做过的，哪些是你从未接触过的。没有就写“无”。这篇日志是你在 Phase 08 中进行对比的基线，而一个美化你的基线对你日后毫无用处。

完成标准

  • python3、git、docker run hello-world 以及编辑器的集成终端都能成功运行，并且由你能亲眼看到的输出确认，而不是“安装程序说装好了”。
  • SSH 密钥已生成并添加到 GitHub；你可以通过 SSH 执行 git push 而无需输入密码。
  • 一个云账户：根账户已启用 MFA，已配置一个非根 IAM 用户并确认它是你的 CLI 所使用的身份，已设置并确认账单提醒（如果服务商允许，可触发一次小规模测试，或核实提醒配置确实已保存，而不是只是填进一个静默提交失败的表单里）。
  • 一个公开的 GitHub 仓库已存在，包含 README、一个为 Phase 09 的成果准备好的空 portfolio/index.md，以及今天的 journal/ 条目，用第一人称诚实回答两个提示问题。

这可能出问题的地方

以云账户根账户或所有者的身份进行日常工作。 它一直有效，直到失效为止——泄露的根账户凭据意味着整个计费账户被攻破，而不是一个你可以在几秒内吊销的 IAM 用户。这条路径上的后续每个实验都假设你已经养成了最小权限访问的习惯；现在就养成这个习惯吧，此时赌注还只是一个免费层沙盒，而不是客户的 VPC。

以“我会一直待在免费层”为由跳过账单提醒。 说这话的人正是那些发布免费层恐怖故事的人。设置提醒只需两分钟，而不设置的代价是真金白银和一个糟糕的下午。

把日志当作私密内容。 如果你在写的时候知道永远没人会读，那么当 Phase 08 要求你从中挖掘一个第一人称案例研究时，它读起来会空洞无物。写每一条日志时都要假设招聘经理最终可能会看到，因为到第 36 周，真的可能会有。

选择一个以后会更换的云服务商。 基础、部署以及多个毕业项目都假设你在同一个服务商上积累熟悉度。中途更换意味着重新学习你已经付费学过一次的 IAM、网络和计费概念。现在就选定一个，只有在你有真正、具体的理由时才重新考虑这个选择。

一套可用的笔记本电脑环境、一个设置了账单提醒的云账户、一个包含 README 和第一篇日志的公开仓库，全部由你自己运行的命令确认，而不是靠一份你草草扫过的清单。
