本体

原标题：Ontology

FDE Interview Prep · 2026 · 约 2 分钟读完

摘要

本文解释本体（ontology）概念：在客户的数据表之上建立统一的业务对象模型（如工厂、工单、货物），定义属性、关联与操作，使人和应用使用同一套术语。文中引用 Palantir 的 Ontology 文档，将其描述为对象、属性、链接和操作类型组成的运营层；并提到 AWS 让前沿部署工程师在客户账户中部署语义层，为 AI Agent 提供受治理的知识图谱。文章还区分了本体与 BI 工具中的语义层，并给出面试建议：先定义对象再画数据管道，写出示例结构，指明各属性的权威来源系统和定义归属者，说明跨系统实体匹配规则与人工审核流程，并涵盖用户可执行的操作。若面试 Palantir 相关岗位，应使用其术语。

要点

  • 本体是在数据源之上统一业务对象、属性、关联与操作的共享模型。
  • Palantir 将 Ontology 描述为含操作类型的运营层，可编排决策并对接现有系统。
  • AWS 的前沿部署工程师在客户账户内部署语义层，供 AI Agent 推理使用。
  • 面试时应先定义对象、指定权威数据源与定义归属者，再设计管道。
  • 跨系统实体匹配规则、未匹配记录处理和审核流程是设计难点。

全文

在工作中，本体（ontology）是客户业务对象（如工厂、工单和货运）的共享模型，包含其属性及对象之间的关联，并映射到底层数据表，使人和应用程序使用相同的术语。Palantir 的 Ontology 文档将其描述为构建在集成数据集、虚拟表和模型之上的对象、属性和关联的操作层，其中动作类型从使用者那里采集数据，并编排与现有系统相连的决策。这一理念并不限于 Palantir：AWS 表示其 FDE 团队会在客户自己的 AWS 账户中部署一个语义层，发布受治理、带版本管理的知识图谱，供 AI Agent 进行推理。来源 1AWS invests $1 billion to embed AI forward deployed engineers with customers发布方About Amazon来源类型公司博客 在 BI 工具中，“语义层”通常指数据仓库之上的共享指标定义，这与本体相近，但并不相同。

为什么这在面试中很重要

当设计或拆解类题目涉及多个对“客户”“资产”或“订单”定义各不相同的系统时，这个理念就派上用场了。优秀的候选人会在画数据管道之前先说出对象，写出其中一个（

WorkOrder { id, asset_id, opened_at, status }

关联到

Asset

），说明每个属性以哪个源系统为准，并指出每个定义由谁负责。然后说明当维护系统与 ERP 对

Asset

的标识方式不同时，如何为其赋予统一身份：匹配规则是什么、未匹配的记录去往何处、由谁审核。这正是设计变难的地方，所以面试官很可能会追问到这里。还要说明用户可以执行哪些操作，例如关闭工单，而不仅仅是能读取什么。

如果你面试的是基于 Palantir 平台的职位，就使用它的术语：对象类型、属性、关联类型和动作类型。Palantir 在 2026 年 4 月的一篇博客文章中指出，围绕 Palantir Ontology 构建的软件架构是其 AIP AgentCamps 的关键差异化优势。来源 2Connecting Agents to Decisions (Palantir Blog)发布方Palantir Blog来源类型公司博客
