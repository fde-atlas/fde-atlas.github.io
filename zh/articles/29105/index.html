AIBP-Collaboration-Playbook

FDE中国社区 · 2026-07-12 · 约 4 分钟读完

摘要

这是一份面向 FDE 与 AIBP（AI 业务伙伴）的协作方法论技能包，用于解决两者职责模糊、Ground Truth 缺失、演示与业务效果脱节等常见问题。核心分工是：AIBP 负责业务结果与真值样本，FDE 负责稳定交付与技术资产。文档给出六步执行流程（定义 RACI、共创场景卡、周度 Demo、共建 Golden Dataset、联签上线门禁、运营移交），并列出四阶段门控表，其中生产门禁要求评估指标达到 80% 以上。还覆盖 PoC 组队、验收争议、运营移交等五个触发场景、常见误区、信创与等保环境约束，以及可导入 Claude、Cursor、Codex 等工具的完整技能包（checklist、evaluation、prompt 等文件）。适合国内 FDE 团队参考双负责人协作模式。

要点

  • 核心分工：AIBP 管业务结果与 Ground Truth，FDE 管交付与技术资产。
  • 六步流程：RACI、场景卡、周度 Demo、Golden Dataset、上线门禁、运营移交。
  • 生产门禁要求 RBAC、评估、人审、日志检查通过，指标达 80% 以上。
  • 列出四大误区，如 AIBP 不参与样本、FDE 独自定义验收。
  • 技能包可导入 Claude、Cursor、Codex 等 Agent Skills 工具复用。

问题定义

FDE 与 AIBP 职责模糊，Ground Truth 缺失，Demo 与业务效果脱节。

方法论框架

分工：AIBP=业务好结果+Ground Truth；FDE=稳定交付+技术资产。 机制：场景卡共创、周度 Demo 双负责人、失败样本共审、上线门禁联签。 会议：Kickoff/场景评审/周度Demo/失败复盘/上线门禁。

常见问题 FAQ

Q1：执行【AIBP-Collaboration-Playbook】时如何避免「AIBP 不参与样本」？

A：按 README 方法论逐步执行，在周度 Demo 展示阶段性交付物；若 PoC 材料不齐，先输出「待验证清单」再推进。

Q2：私有化/信创/等保环境下有哪些额外约束？

A：在 prompt 约束段明确部署形态；涉及数据不出域、国产化组件、审计日志时同步引用 Private-Deployment-Gateway 与 RBAC-Audit。

Q3：与 AIBP 分工边界不清怎么办？

A：回到 AIBP-Collaboration-Playbook 更新 RACI；AIBP 负责 Ground Truth 与业务验收，FDE 负责可交付技术资产。

Q4：PoC 通过后如何衔接到 Beta/生产？

A：输出物中标注下一阶段 Skill（如 RAG-Evaluation→Private-Deployment-Gateway→FDE-Adoption-Growth），并在 checklist 触发上线门禁。
