Agent

原标题：Agent

FDE Interview Prep · 2026 · 约 2 分钟读完

摘要

本文解释 Agent 与 workflow 的区别：Agent 由模型逐步决定调用哪个工具及何时结束，循环运行直到成功、失败或达到上限；workflow 则由代码预先固定调用顺序。文章引用 Anthropic 的《Building effective agents》与 ReAct 论文，并结合 Google FDE 面试经验（Blind 上 2026 年的 L4 与 Senior FDE 报告），说明系统设计轮可能涉及 Agent 编排、安全护栏、死循环处理与人在回路。作者给出答题框架：从 workflow 出发，仅在无法预先固定路径处加入自主性，并明确每项限制的执行方式，包括步数预算（约为成功轨迹 p95 的两倍）、成本上限、循环检测、按用户权限限定工具、副作用工具用幂等键保证可重试、以及附带轨迹的人工交接。最后建议在黄金集上对整条轨迹（含工具调用与最终答案）评分。

要点

  • Agent 由模型逐步决定工具调用与结束时机，workflow 则预先固定流程。
  • Google FDE 面试系统设计轮涉及编排、护栏、死循环与人在回路。
  • 答题应从 workflow 起步，只在必要处增加自主性。
  • 限制包括步数预算、成本上限、循环检测、权限与幂等键。
  • 评测应覆盖整条轨迹，不只看最终答案。

全文

Agent 是一种系统：语言模型逐步决定下一步调用哪个工具、任务何时完成，并在循环中运行，直到成功、失败或达到你设定的上限。这正是它与工作流的区别——工作流中你的代码预先固定了模型调用的顺序，模型只负责填充每一步（Anthropic，Building effective agents）。许多 Agent 设计背后的“推理—行动—观察”循环在 ReAct 论文 中有描述。

一个出色的回答应从工作流出发，只在路径无法预先固定的地方加入自主性，然后说明每个限制如何强制执行：

  • 根据成功运行的轨迹设定步骤预算（max_steps ≈ 2 × p95(steps)），而不是凭空猜测；
  • 每个任务的成本上限；
  • 循环检测——当 Agent 以相同参数重复调用同一工具时终止运行；
  • 每个工具的权限范围限定为 Agent 所代表用户的权限；
  • 每个有副作用的工具都通过幂等键确保可安全重试；
  • 附带轨迹转交给人工处理。

然后说明你如何知道它有效：在黄金集上对完整轨迹评分，包括工具调用和最终答案。步骤预算的经验法则是我们提出的。
