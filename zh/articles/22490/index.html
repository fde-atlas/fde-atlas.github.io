Decagon 的 FDE：从定制化到自助服务

原标题：FDE chez Decagon : du sur-mesure au libre-service

SFEIR AI · 2026-11-10 · 约 4 分钟读完

摘要

SFEIR 评述 Decagon 前沿部署工程负责人 Sunny Rekhi 在 AI Engineer World's Fair 2026 的 18 分钟演讲。Decagon 提供客服 AI Agent，一年内从约 50 人扩张到 500 人，其核心理念是“定制最终变为自助服务”：团队在手工写了第 25 个 CRM 集成后转向自助化路径。演讲将 FDE 工作分为配置 Agent“大脑”与类产品工程两部分，并随规模增长拆分为 agent builders 和 agent software engineers 两个角色。作者认为最有价值的观点是：在 AI 编码工具让临时开发变得廉价的时代，克制——为后续客户设计通用方案而非交付黑盒——才是稀缺能力。文章肯定其组织模型与 Hertz 等案例，但批评演讲几乎没有任何量化指标，且含自我宣传成分，原创性与信息质量均评 3/5。

要点

  • Decagon 一年内从约 50 人扩张到 500 人，主打客服 AI Agent。
  • 第 25 个手工 CRM 集成促使其转向自助服务，即“定制变自助”。
  • 角色拆分：agent builders 负责配置，agent software engineers 负责产品化。
  • AI 编码时代，克制与通用化设计成为稀缺能力。
  • 演讲缺乏量化数据，含自我宣传，评分为 3/5。

在手写第 25 个 CRM 集成之后，Decagon 团队不再计数，而是构建了一条自助服务路径（约 12:08 处）。这段轶事印证了 Decagon 前沿部署工程 CTO Sunny Rekhi 在演讲结尾反复强调的格言：“custom becomes self-serve”（定制变为自助服务）。Decagon 销售可通过电话、电子邮件或聊天响应客户的客服 AI Agent，据他介绍，公司一年内从约 50 人增长到 500 人。

同一头衔下的两种职业

Decagon 通过复杂的入站支持切入客户，随后设法帮他们赚钱（约 2:03 处）。他讲述道，在 Hertz，为支持业务构建的集成如今被用于主动联系客户以延长租车期限。

FDE 工作的一部分是像培训人类一样配置 AI Agent 的“大脑”（约 3:05 处）：指令、品牌语气、允许的操作、成功标准、需转接给人工客服的请求。另一部分则类似产品工程：当一家企业提出某项功能需求时，工程师会为接下来几乎必然会提出同样需求的四家企业进行设计。Sunny Rekhi 甚至表示，在 Decagon，前沿部署工程与产品工程融为一体：同样的要求标准，同样的汇报关系，往往还是同一个团队。

增长带来的变化

随着人数从 50 增至 500，agent software engineer 这一通才角色一分为二（约 7:06 处）。agent builders 负责配置 AI Agent，主要在界面上操作，并了解驱动平台的模型。agent software engineers 则处理大客户的功能需求，并将其反馈到产品中。

演讲中最精辟的观点关乎克制（约 8:08 处）。借助 Codex 或 Claude Code，产品工程师几分钟内就能完成重要客户昨天就想要的一次性开发。稀缺的能力变成了懂得节制的能力：设计出能服务于后续客户的方案，避免交付一个由提示词和临时补丁组成的黑盒——客户作为自己 AI Agent 的所有者，将无法掌控它。

实践合理，数据寥寥

演讲的其余部分列举了一些合理的实践。从最初的对话开始就用书面形式定义成功：指标、渠道（电话、电子邮件、短信、WhatsApp）、预期结果。既然代码成本已经很低，就把更多时间投入到需求上。为金融行业的新客户分配曾服务过前三个同类客户的人员，以便用客户的语言交流。尽快证明价值，而不是等上几个月。扮演顾问的角色：Decagon 分析客户的支持历史，为其推荐应首先自动化的流程，有时与客户最初要求的并不相同（约 14:08）。

这场演讲几乎没有给出任何数字：既没有首次成果的平均周期，也没有 FDE 团队的规模，更没有 agent builder 与 agent software engineer 之间的比例。Sunny Rekhi 开玩笑说市场团队禁止他展示客户 logo，而对 Decagon 成功的解释（一支努力工作、快速行动的团队）带有自我推销的成分。

对 IT 服务公司而言

Decagon 的座右铭描述了 IT 服务公司的知识沉淀问题：每个项目产出的定制成果，下一个项目又要重做一遍。25 次集成的故事给出了滞后沉淀成本的量级，而 agent builder 与 agent software engineer 的分工则为在 AI 交付团队中区分配置工作与工程工作提供了一个模型。

结论

原创性：3/5。 在代码自动生成的时代，克制作为一种稀缺能力，是一个正确且少有人提及的观察。其余内容（回到产品的反馈循环、自助服务、顾问姿态）与 Kevin Bai 和 Pauline Brunet 所讲的内容重合。

信息质量：3/5。 有清晰的组织模型和生动的例子（Hertz、25 次集成），但没有任何指标，且带有一定的自我推销成分。

如果你的 FDE 团队扩张迅速，而你还在犹豫是否要细分角色，值得一看，尤其是 6:06 到 9:08 的部分。否则，Leo Mehr (Ramp) 用更短的时间覆盖了部分相同的内容。
