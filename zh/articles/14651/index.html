Microsoft Copilot 评测：合成企业数据

原标题：Microsoft Copilot Evaluation: Synthetic Enterprise Data

AISOLO Technologies Private Limited · 2026-10-30 · 约 7 分钟读完

摘要

Microsoft Research 于 2026 年 10 月 30 日发布行业评测数据生成平台，用完全合成的企业环境（制药、资本市场、IT/软件）测试 Copilot，避免使用真实客户数据。平台基于 O*NET、招聘信息和 SEC 文件等公开数据构建含时间演化的假公司，并用六阶段流程自动生成测试问题。微软称合成数据质量较初版提升 39%，每个数据集约节省 10 万美元，但这些均为公司自报数字，无公开数据集，也未公布 Copilot 的实际准确率结果。

要点

  • 微软用合成企业环境替代客户数据测试 Copilot，覆盖制药、资本市场和软件三个行业。
  • 假公司基于 O*NET、招聘信息和 SEC 文件构建，模拟数周内演化的邮件、会议与组织变化。
  • 六阶段自动化流程生成测试问题，合成质量较初版提升 39%，部分环境得分超 0.9。
  • 微软估计每个数据集约节省 10 万美元，且同配置可复现，便于回归测试。
  • 文章提醒：数字未经独立验证，且未公布 Copilot 在这些环境上的实际表现。

Microsoft Research 在2026年10月30日发布的博客文章中表示，现在使用完全合成的公司而非客户数据来测试 Microsoft Copilot。该系统名为行业评测数据生成平台，构建虚假的制药、资本市场和软件公司，填充电子邮件、会议和文档，并自动生成测试问题。Microsoft 报告称，相比其最初的方法，质量提升了 39%，每个评测数据集节省约 10 万美元。

这是公司自行报告的结果，没有公开数据集，因此应将这些数字视为 Microsoft 的说法。但对于任何正在发布企业 AI 助手的团队来说，这种方法仍然很有价值，因为它解决了每个此类团队都会遇到的问题：你无法在真实客户数据上进行测试，而玩具测试集又不像真实的工作场所。

为什么 Copilot 需要合成公司？

Copilot 会回答关于你的会议、电子邮件和文件的问题。要判断它是否正确，必须有人将其答案与底层数据进行核对。Microsoft 的文章给出了一个简单的例子：用户要求 Copilot 总结一场会议并提取行动项。这个总结是否准确、完整，并且有会议记录作为依据？

你无法在客户租户上大规模运行这种测试。Microsoft 将这一“核心矛盾”表述为：既需要具备“真实组织全部复杂性”（汇报结构、项目历史、沟通模式、领域工作流程）的数据，又不能接触真实数据。手工构建的小型测试夹具缺乏这种复杂性，而通用基准测试又无法发现特定领域的失败。

这是一场更大转变的一部分。各大实验室和工具供应商发现，标准的公开基准测试无法预测模型在特定工作场所中的表现；我们在面向前沿部署工程师的基准测试 FDE-Gym中看到了同样的主题——前沿模型在现实的客户部署任务上表现挣扎，在面向 Agent 的持续学习考试中也是如此。

一台机器在生产绿色瓷砖，旁边放着几块灰色的，代表用于 Copilot 评测的合成企业测试数据

这些合成企业是如何构建的？

Microsoft 描述了三大支柱：合成企业环境、自动化查询生成和结构化质量框架。

基于公开数据构建

每个合成租户都是一个隔离的组织，拥有自己的用户、数据和配置。为了保持真实性，Microsoft 使用了三个公开来源：

  • O*NET，美国劳工部的职业数据库，用于使角色和职责真实可信，并校准每个角色的工作活动的组合和频率，包括临床试验审查或投资组合更新等行业工作流程。
  • 在线招聘信息，用于获取真实的职位名称、汇报层级和部门构成。
  • SEC 文件，用于获取组织规模、业务部门结构和财务背景。

Microsoft 表示，所有这些数据都是公开的，并已通过其法律和政策部门的审查和批准。

随时间演变的组织

这些环境并非静态快照。它们模拟会议历史、项目时间线、在数周内不断发展的邮件往来，以及组织变动。这一点很重要，因为许多 Copilot 查询是具有时间感知的，例如“团队上周四决定了什么？”或“自上次季度审查以来有什么变化？”只有当数据具有真实的时间线时，这些查询才有测试意义。

测试问题是如何生成的？

虚构数据只是基础；你还需要真实的问题。手动编写数千条有据可依、针对特定行业的查询既缓慢又成本高昂，因此 Microsoft 构建了一个六阶段流水线。该文章将其概括为一个流程，它：

  • 从一个庞大的常见职场任务库出发，
  • 将其缩小到与特定行业相关的内容，
  • 使用领域特定的语言和上下文对其进行调整，
  • 利用 AI 生成基于合成环境数据的查询，
  • 重写这些查询，使其听起来更自然、更像人类，并且
  • 验证每条查询的准确性和唯一性。

用 Microsoft 的话说，其结果是一组用于可扩展评测的“高质量、逼真的查询”。Microsoft 在这篇文章中并未公布各阶段的具体提示词或最终查询集的规模。

Microsoft 如何评判合成数据本身？

合成基准测试的好坏取决于其真实程度，因此 Microsoft 使用内部语义评估框架从四个维度对环境进行评分：

维度考察内容
结构保真度汇报层级、团队规模和跨职能关联是否看起来真实？
情境相关性查询和工作流是否能代表实际的企业使用场景？
行为真实性模拟用户的沟通与协作是否像真人？
内容安全性内容是否不含有害或可识别个人身份的信息，并避免冒充真实人物？

最核心的结果是：与最初的生成方法相比，综合质量指标提升了 39%，部分行业环境得分超过 1.0 分中的 0.9。但需注意两点。第一，这是微软自己的指标，因此该分数衡量的是与其自身对“真实性”定义的相似程度。第二，39% 的提升是相对于团队的首次尝试，而非真实数据或任何公开基线。它表明迭代有效，但并不能证明这些合成租户与真实租户相符。

自动化改变了什么？

微软列出了手动创建数据集的四个问题：可复现性、规模（行业和配置太多，无法手工构建）、迭代速度（每个数据集需要数天）以及跨团队一致性。自动化将耗时数天的手动流程转变为自动化运行，微软估计这为每个评测数据集节省约 10 万美元，整个项目节省约 30 万美元。这些是作者的估计，文章并未展示计算过程。

更实际的说法是：任何团队都可以基于相同的配置重新生成数据集，并获得完全一致的结果。对于跨 Copilot 版本的回归测试而言，这种可复现性可以说比节省的成本更有价值，因为你可以将新版本与同一基线进行比较。

那隐私呢？

微软将“任何阶段都不使用真实客户数据”视为不可妥协的原则。它列出的保障措施包括：在引用真实世界统计分布时采用保护隐私的聚合方式、对每个公开来源进行法律审查，以及数据溯源追踪。由于数据是合成的且经过安全筛查，微软表示团队可以“无需隐私审查开销”地复用这些数据，这正是它预期该方案在公司内部被广泛采用的原因。

请注意这一说法的局限。“流程中不含客户数据”是针对输入的陈述。它并未回答 Copilot 在真实世界中的表现是否与其在合成世界中的表现相符，而这才是客户真正关心的问题。

最后一行是值得注意的差距。这篇文章描述了微软如何进行测量，而不是 Copilot 的得分如何。由于没有准确率数字，读者还无法判断该平台是否发现了故障、发现了哪些类型的故障，以及修复速度有多快。

这对构建者意味着什么？

如果你要发布一个会接触私人工作数据的 AI 助手，这套方法可以直接套用：

  • 构建一个虚构的组织，而不是一个虚构的文件。 包含人员、角色、历史以及随时间的变化，因为时间相关的问题正是 AI 助手容易出错的地方。
  • 以公开统计数据为基础（职位分类、申报文件），这样规模和角色构成显得合理，又不会暴露任何人。
  • 从模板生成查询，然后改写并验证。 这种分阶段的流水线既避免了重复的测试问题，也避免了不自然的测试问题。
  • 给你的合成数据打分。 把真实感当作可以测量的东西，就像微软那样进行结构性、上下文、行为和安全检查。
  • 确保可复现。 相同的配置、相同的数据集，这样回归问题才能显现出来。
  • 下一步转向 Agent 评测。 微软表示，它正在攻克多轮 Agent 交互以及会采取行动而不仅仅是生成文本的 AI。对于会采取行动的 Agent，安全检查与准确率同样重要；参见 APEX-Harm，一个 Agent 安全基准，并考虑使用 explainx.ai 团队推出的运行时防护工具，例如 AgentBeam。

关于相关技术，请参阅另一家初创公司如何凭空生成训练数据：Adaption 的面向零种子合成数据的 Invent API。

这在微软的 Copilot 战略中处于什么位置

Copilot 正在从问答转向长时间运行的 Agent，这提高了评测的门槛。微软最近发布了 Copilot Harness 和 Foundry Agent Service 更新，其编程模型也在不断扩展，例如 在 Windows 上本地运行的 MAI-Code-1.1 Flash。关于 Copilot 的经济效益和模型来源的报道也不断涌现，例如 对微软所报告的 Anthropic 支出的“声称与核实”分析。一个标准的内部评测基线是一种不起眼的基础设施，却能让公司有相当的信心发布所有这些产品。

接下来值得关注什么

  • 公布结果。 微软是否会分享 Copilot 在这些环境中的得分或故障类别。
  • 开放发布。 合成租户或生成代码是否会公开，这将让外部人员能够复现这项工作。
  • Agent 化扩展。 微软将多轮 Agent 交互以及随数月或数年演变的组织列为下一步方向。
  • 独立验证。 第三方将合成环境中的得分与真实世界的用户结果进行对比。
