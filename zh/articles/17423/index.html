Agent 工程师 vs AI 工程师 vs ML 工程师

原标题：Agent Engineer vs AI Engineer vs ML Engineer

Zarif Automates · 2026-09-26 · 约 8 分钟读完

摘要

文章基于 2026 年 9 月的真实招聘信息，区分 Agent Engineer、AI Engineer 与 ML Engineer 三种岗位：ML 工程师对模型负责，AI 工程师对基于基础模型的产品功能负责，Agent 工程师对模型执行动作后的结果负责。文中对比了 Ramp、WRITER、Sierra、Anthropic、Scale AI 等公司的职位描述、技能要求与薪酬区间，指出职位名称常与实际内容不符，并给出从动词、技能、数据类型、失败场景和团队名称五个信号判断岗位真实性质的方法，以及针对不同背景（后端、全栈、数据科学）的转型建议。

要点

  • 三种岗位的核心区别：ML 看模型，AI 看功能，Agent 看动作。
  • Agent 岗位分产品与平台两类，Anthropic 平台岗要求八年以上经验。
  • Ramp 同城两个岗位对比：Applied AI 用基础模型，ML 自建反欺诈模型。
  • 职位标题常失真，应从动词、技能、失败场景等信号判断。
  • 文中列出各公司薪酬区间，Anthropic Staff+ 岗位年薪 40.5 万至 48.5 万美元。

Agent、AI 和 ML 工程师各自负责什么，以及如何判断一则招聘启事真正描述的是哪种职位——基于 2026 年 9 月的真实招聘启事解读。

Ramp 同时发布了应用 AI 工程师和机器学习工程师两个职位。两者都要上线生产环境，都要求后端技能，也都提到 AI。

但它们是不同的工作。一个是在别人训练好的大型通用模型之上构建产品功能；另一个是用公司自己的数据训练模型来识别欺诈。

再加上“Agent 工程师”，界限就更加模糊了。区分它们最简单的方法是：ML 工程师以模型论成败；AI 工程师以围绕模型构建的产品功能论成败；Agent 工程师以模型被允许执行操作后产生的结果论成败。阅读招聘启事，看它真正在意的是哪一点，这比职位名称更能说明问题。

本文比较的招聘启事于 2026 年 9 月 26 日打开。职位会关闭，薪资范围会变化，因此在依赖任何细节之前，请先打开链接确认。

这些是下文招聘启事中的常见模式，而非规则。接下来的章节将展示每一列的依据来源。

Agent 工程师：负责模型被允许做什么

Agent 工程的招聘启事更多谈论操作、工具和测试，而非模型本身。这类工作分为两种：为产品或客户构建 Agent，以及构建其他 Agent 运行其上的平台。

在产品侧，Harvey 的资深软件工程师，Agents 要求工程师“为智能体化的专业工作设计环境和动作，做出模型选型决策，管理上下文窗口，创建最优工具，并开发评测”。Sierra 的软件工程师，Agent 负责“在生产环境中构建、调优和演进 AI Agent”。Scale AI 的 Frontier Agents 工程师（Applied AI） 则列出了“Agent 防护栏、降级策略、追踪、监控和评测流水线”。

在平台侧，Sierra 的软件工程师，Agent Runtime 隶属于平台工程团队，负责“编排引擎、运行时以及定义 Agent 如何推理、执行动作并与用户和系统交互的基础组件”。Anthropic 的 Staff+ 软件工程师，Claude Managed Agents 设计“持久化的会话与事件存储、沙箱编排、流式处理、调度以及多租户隔离”。这是大规模系统的工作，而且该职位要求至少八年的相关经验。

这些职位的共同点在于对模型做出决策之后可能出问题的担忧。WRITER 的软件工程师，agents 说得很直白：“确保所有 Agent 组件的可靠性、监控和可观测性。”

Anthropic 自己的指南 Building effective agents 是这样划分界限的：在工作流中，由代码决定每一步；而在 Agent 中，模型自主决定自己的步骤并选择自己的工具。Agent 工程师要决定这条线划在哪里，并让结果能够安全运行。

这份 Agent 工程师职业指南 将这项工作拆分成若干部分，并配有一个可供练习的作品集项目。

AI 工程师：交付基于基础模型构建的功能

AI 工程师的职位范围更广。工程师将模型接入产品并交付成果。Agent 只是多种可能成果中的一种。

Ramp 的应用 AI 工程师 要求工程师“端到端地交付全栈 AI 项目”，并希望候选人“有从事全栈 AI 项目的工作履历，尤其是涉及 LLM 生产级用例的项目”。同一职位还涵盖“支持生产级推理和微调的 AI 基础设施组件”，以及面向其他工程师的内部工具。重点在于广度和交付能力。

WRITER 的 AI 工程师 向 AI 工程负责人汇报，将“推动智能体和 AI 驱动功能的开发”。该职位还要求掌握 PyTorch、TensorFlow 或 JAX，以及“用于管理 AI 生命周期的 MLOps 工具”。这就是一个职位中的重叠之处：Agent 是工作的一部分，而模型工具链也是——后者在 Agent 工程师的职位描述中很少提及。

与 Agent 工程师的实际区别在于你在单一问题上钻研的深度。AI 工程师的考核标准是功能是否对用户有效；而 Agent 工程师的考核标准是模型执行的动作是否正确、是否被允许，以及出现故障时是否能够恢复。

AI 工程师职业指南涵盖了更宽泛的角色，其中包含一个查找文档和测试答案的项目。

ML 工程师：负责模型

ML 工程师的职位描述从数据开始。工程师针对某个特定问题训练、测试和部署模型，模型本身就是产品。

Ramp 的机器学习工程师隶属于数据部门，与反欺诈工程团队合作。该职位要求工程师“构建原型并将机器学习模型和基于规则的系统投入生产，以保护 Ramp 及其用户免受欺诈”。它要求“扎实的 Python 经验（numpy、pandas、sklearn、pytorch 等）”以及“将机器学习模型部署到生产环境的经验”。

把它和 Ramp 的应用 AI 工程师职位放在一起比较。两者都要交付到生产环境，也都需要后端技能。ML 工程师处理的是统计学、特征数据和公司自有的模型；应用 AI 工程师处理的是由别人训练的基础模型。两个职位都没有提到 AI Agent 可以修改什么，以及审批流程如何运作。

头衔模糊之处

有三种模式出现得足够频繁，值得留意。

  • 构建 AI Agent 的 AI 工程师。WRITER 的 AI 工程师职位描述中包含“智能 Agent”。如果大部分条目都是关于工具、操作和测试的，那就要为 AI Agent 工程面试做准备。
  • 实际上是平台工程师的 AI Agent 工程师。Anthropic 的 Claude Managed Agents 和 Sierra 的 Agent Runtime 职位都是平台类工作。了解 AI Agent 很重要，但面试考察的是存储、客户隔离以及规模化后会出现什么问题。
  • 与客户打交道的 AI Agent 工程师。Decagon 的高级软件工程师，Agent 产品将“与大型企业级客户进行大规模集成”。这更偏向前沿部署工程，FDE 与解决方案架构师对比中有相关介绍。

“Agent Engineer”这个确切头衔目前仍然少见。在为本文查阅的招聘网站上，Scale AI 的 Frontier Agents Engineer 和 Elastic 的 Agentic AI Engineer最为接近。大多数雇主发布的都是“软件工程师”职位，并附上一个 AI Agent 团队的名称。

如何判断职位描述到底是哪一种

在相信头衔之前，先阅读以下信号。大多数职位描述都会混合多种特征，所以要数一数哪一栏占多数。

职位描述中的信号偏向 AI Agent 工程师偏向 AI 工程师偏向 ML 工程师
主要动词设计工具、编排、防护、评测 AI Agent集成、交付、构建功能训练、调优、建模、分析
明确列出的技能工具调用、上下文管理、评测框架、追踪LLM API、全栈框架、云平台统计学、sklearn、PyTorch、特征工程
处理的数据追踪记录、工具结果、任务结果提示词、文档、用户反馈标注数据集、特征、模型指标
担心的失败错误或未经授权的操作、卡死的循环答案质量差或功能响应慢漂移、误报、模型不再具备泛化能力
团队名称Agent、Agent 平台、Agent 运行时应用 AI、AI 产品数据、ML 平台、或某个领域团队（如反欺诈）

如果职位描述仍未说明清楚，请在第一次通话时询问：

  • 这个产品中的模型会执行改变记录的操作，还是只返回文本？
  • 测试集由谁负责？你们现在如何衡量 Agent 的质量？
  • 团队是自己训练或微调模型，还是只使用托管模型？
  • 上个季度生产环境中出了什么故障，是谁修复的？

哪个方向适合你的背景

如果你来自后端或大规模系统方向，Agent 工程是最接近的一步，尤其是平台侧。差距在于测试：学会衡量一个每次运行输出都可能不同的任务。

如果你来自产品或全栈工程方向，AI 工程是最自然的切入点，而 Agent 工作是其中的一个专业方向。先从一个功能做起，然后添加一个模型可以调用的工具。

如果你来自数据科学或统计学方向，ML 工程可以直接用上你已有的技能。转向 Agent 工作则意味着学会运营一个服务：登录与权限、重试机制，以及可安全重复执行的写入操作。

如何成为 Agent 工程师指南将每种背景与网站 Agent 课程中的相应课程对应起来。
