通过 MCP 从 Claude Code 查询账户上下文：为工程师和编码 Agent 提供客户上下文

原标题：Querying account context from Claude Code via MCP: giving engineers and coding agents the customer's context

Tandem · 2026-08-28 · 约 8 分钟读完

摘要

Tandem 介绍如何通过 MCP 将客户账户上下文接入 Claude Code，让工程师和 AI Agent 在会话中直接查询客户的承诺、决策与风险，无需打扰 FDE。文章给出配置步骤、推荐查询方式及会话结束后的同步方法，并以 Aircall 的实践为例：每位工程师的上线次数从 5 次提升到 15 次，合同到切换的时间缩短 30%。文章还对比了粘贴文档、CLAUDE.md 等方案的局限，强调账户上下文应存于带来源链接的团队记忆中，而 CLAUDE.md 仍适合存放代码约定。

要点

  • 通过 MCP 一次性接入，工程师和 AI Agent 可在会话中查询客户账户上下文
  • 30% 的开发者对 AI 生成代码信任不足，上下文缺失是原因之一
  • Aircall 工程师经 MCP 查询上线上下文，人均上线次数从 5 提升到 15
  • CLAUDE.md 只适合代码约定，账户状态应存于带来源的团队记忆
  • 同步回写需人工触发和批准，判断力无法通过 MCP 转移

TL;DR: 通过 MCP 将团队记忆连接到 Claude Code 一次，项目上的每位工程师和编码 Agent 就能在会话中途获取客户的承诺、决策和风险，而不必去打扰 FDE。上下文同样是提升质量的关键杠杆，因为 30% 的开发者表示对 AI 生成的代码几乎没有或完全没有信任。在 Aircall，工程师通过 MCP 借助 Claude 查询部署上下文，实现了每位工程师 3 倍的部署量（5 → 15）。本指南将介绍具体设置、值得运行的查询，以及会话结束时的同步回写。

一位工程师在为从未谋面的客户构建集成时，在某个特定方面是盲目的。代码上下文都在——在代码仓库里，在 CLAUDE.md 里。但客户账户上下文不在：客户的 IT 团队拒绝了哪些端点、FDE 在启动会议上承诺了什么、哪个日期是冻结的。于是工程师只好打断前沿部署工程师，或者凭猜测行事，而他们的编码 Agent 也跟着一起猜。

一家垂直领域 AI 创业公司的 FDE 描述了他想要达到的状态："工程师们……使用 Claude Code，他们感觉……这个产品在帮助他们快速掌握上下文。"这正是本文要做的事。这是一份操作指南，教你如何通过 Tandem MCP 将客户账户上下文接入 Claude Code，让"我们向这个客户承诺了什么"这个问题在会话中就能从源头得到解答，无需 FDE 介入。

为什么你的编码 Agent 需要客户的上下文

编码 Agent 的输出质量取决于其输入上下文，而通常缺失的输入并不是技术层面的。Sourcegraph 将上下文工程定义为"刻意设计大语言模型在每次推理调用时所看到的内容"，而对于客户工作来说，模型需要看到的是客户账户的真实情况：约束条件、承诺和历史记录。如果不提供这些，你就会得到看似合理却瞄准了错误目标的代码，这也是 30% 的开发者仍然表示对 AI 生成的代码几乎没有或完全没有信任的原因之一。

更深层的代价是组织层面的。当客户账户上下文只存在于 FDE 的脑海中时，工程师和他们的 Agent 无法绕过这一个人去获取每个问题的答案来进行开发，FDE 就成了客户与代码库之间的传话人。这是共享上下文问题最昂贵的表现形式，因为它恰恰卡住了那些被雇来扩大交付规模的人。部署与产品之间的反馈循环也会以同样的方式断裂。

为什么不直接把上下文粘贴进去？

你可以把状态文档复制到每个会话里，很多团队也确实这么做。问题在于，粘贴是按会话、按人进行的工作，而且粘贴的快照在客户动态变化的那一刻就已过时。Model Context Protocol 的存在正是为了取代这种仪式。MCP 是一个连接 AI 应用与外部系统的开源标准，其官方文档将其描述为“AI 应用的 USB-C 接口”，并得到 Claude、ChatGPT、VS Code 和 Cursor 的支持。只需注册一次连接，每台已配置机器上的每个会话都能查询实时数据源。那些推动在 Claude 各界面间建立共享层的用户，要求的正是这一特性：一次设置，处处可用。

以下是将客户背景信息引入会话的各选项对比。

  • 电子表格 + Slack（复制粘贴进来）。新鲜度：粘贴时即过时，因团队而异。每次会话的工作量：高，每个人都要重复。附带来源：无。无需提示即可供 Agent 使用：否。
  • CLAUDE.md 中的客户备注。新鲜度：在有人修改仓库之前一直过时。每次会话的工作量：设置完成后很低。附带来源：无。无需提示即可供 Agent 使用：部分支持，启动时加载。
  • 将文档或对话记录上传到会话。新鲜度：仅为快照。每次会话的工作量：中等，每个会话都要做。附带来源：原始、未经核对。无需提示即可供 Agent 使用：否。
  • 通过 MCP 的团队记忆（Tandem MCP）。新鲜度：查询时实时。每次会话的工作量：设置后接近于零。附带来源：有，每条事实都附有引用链接。无需提示即可供 Agent 使用：是，Agent 可在任务中途查询。

为什么 CLAUDE.md 无法承载客户状态

把 CLAUDE.md 当作客户档案很诱人，因为它已经通过 git 共享。但记忆文档指出了相反的方向：项目记忆用于约定和指令，自动记忆是机器本地的，而且加载预算很小——MEMORY.md 只有前 200 行或 25KB 会进入上下文。客户状态以通话的速度变化，而仓库以 PR 的速度变化，并且最需要了解承诺信息的同事从不克隆仓库。我们在 Claude Code 团队记忆一文中对此做了详细拆解。让 CLAUDE.md 专注于代码上下文，为客户上下文提供一个专门构建的家——一个带来源和核对机制的项目大脑。

如何在 Claude Code 中连接 Tandem MCP

Tandem 是面向实施与部署团队的 AI 工作区，通过名为 Tandem MCP 的 MCP 服务器提供客户大脑，可从 Claude、Claude Code 或 ChatGPT 访问。设置只需一次。

  • 在 Claude Code 中将 Tandem MCP 添加为服务器。像注册任何 MCP 服务器一样注册它，使用 claude mcp add 或在项目的 .mcp.json 中添加条目。无需构建管道，该服务器就是产品的入口。
  • 使用你的 Tandem 工作区进行身份验证。登录后，连接即可知道它可以读取哪个团队的大脑，以及哪些客户账户。
  • 在会话中验证连接。 询问 Claude Code Tandem MCP 暴露了哪些工具，或者直接跳到一个关于活跃账户的简单问题，并检查答案是否附带来源。
  • 提交项目级配置，让团队自动继承。 配置签入仓库后，连接会随克隆传递给每位工程师，这与共享 CLAUDE.md 起作用的分发技巧相同。
  • 把首次查询纳入开工流程。 在写代码之前先拉取账户简报，就像拉取分支一样。一位种子前初创公司的创始 FDE 用一句话评价了这个工作流：“我大量使用 Claude Code。这个功能我会非常乐意使用。”

会话中查询什么

连接建立后，三个查询就能完成大部分工作。

简报

在动手之前，先询问账户的当前状态。简报按需生成（或按计划生成，可投递到包括 Slack 在内的任何地方），它回答定义共享上下文的四个问题：承诺了什么、决定了什么、有什么风险、接下来做什么。五分钟的阅读取代了与 FDE 的三十分钟电话讲解。

风险检查

在确定方案之前，先询问大脑该账户存在什么风险。风险检查返回一份风险列表，每项都附带解释、原因以及背后的来源和引述。如果你即将采取的方案与三月份告知客户的内容相冲突，问题会在这里浮现——此时改变方向仍然代价低廉。

承诺与决策

任务进行中，Agent 无需你提示即可查询具体事实：商定了哪个迁移日期、为什么选择轮询、客户的安全团队排除了什么。这是 Aircall 在生产环境中运行的查询模式。那里的工程师通过 MCP 经由 Claude 查询上线上下文（承诺、迁移日期、集成决策），其高级软件工程师 Paul Yi 这样描述结果：“同样的问题，同样的答案，无论谁问。”

将会话同步回去

连接是双向的。当会话产生了团队应当保留的决策时，你可以通过同一个 MCP 连接将其推送到大脑，并精确选择要推送的内容。完整的闭环，包括什么能让同步的决策在数月后依然有用，在从 Claude Code 会话中提取产品决策中有详细介绍。简而言之：进入时查询，离开时同步你选择的内容，大脑就能为下一位工程师的第一步保持活跃。多人可以推送到同一个大脑，警报接收人可配置，因此 FDE 无需状态会议就能看到工程团队学到了什么。

哪些保持手动

同步由你触发。除非有人主动选择，否则会话中的任何内容都不会流入团队记忆，而且针对大脑的每一次 Agent 操作都需要人工批准。这是有意为之，也意味着捕获的习惯仍然是一种习惯。

检查点自动重新同步功能尚未发布。一位工业 AI 公司的 FDE 曾询问会话能否“在每次检查点结束时，自动重新同步回你的大脑”。目前还不行。你只能在选定的时刻进行同步。

判断力无法通过 MCP 传递。大脑能告诉工程师承诺过什么、为什么做出某个决策，但是否要就客户冻结的日期提出异议，仍然是由人来做的判断，通常是 FDE，任何查询都无法替代。

让每个会话共享同一份记忆

接入之后，这一模式会改变谁能胜任这项工作。工程师可以运营自己从未参与过电话会议的客户账户，Agent 编写的代码瞄准客户的实际约束条件，而 FDE 不再只是一个查询服务。Aircall 的成果：每位工程师的上线次数提升 3 倍（5 → 15），从签约到切换的时间缩短 30%。观看 Tandem 在你自己的一个实际实施项目上回答“什么在阻碍切换”，演示视频。

常见问题

这只在 Claude Code 中有效吗？

不是。Tandem MCP 可以从 Claude、Claude Code 或 ChatGPT 访问，因此同一个大脑可以在终端里回答工程师，在 Claude 聊天中回答经理，简报也会发送到 Slack。MCP 是连接器标准，而不是 Claude Code 的专属功能。

工程师真的可以在没有 FDE 参与的情况下查询客户背景信息吗？

可以，而这正是带来回报的运营变革。在 Aircall，工程师通过 MCP 在 Claude 中查询承诺事项、迁移日期和集成决策，得到的答案与 FDE 给出的完全一致，且同样有据可查。FDE 转而负责维护记忆，而不是把同一个问题回答四十遍。

风险检查实际返回什么？

一份风险列表，每项风险都附带解释、被标记的原因，以及背后的来源和引文。这是一个可以验证的答案，而不是一个分数，这正是它能在持怀疑态度的工程师或客户面前使用的原因。

我的编程 Agent 会自行修改大脑吗？

不会。Agent 可以自由查询，但向团队记忆写入任何内容都是需要人工触发、人工批准的操作，并且由你决定同步什么。在检查点自动重新同步是用户提出的需求，而非已发布的功能。

如果有了 Tandem MCP，我们还需要 CLAUDE.md 吗？

需要。CLAUDE.md 仍然是存放代码规范、命令和仓库知识的正确位置，并通过 git 共享。Tandem MCP 补充了 CLAUDE.md 从未打算承载的那一层——客户的实时账户状态。两者结合，覆盖了 Agent 所需上下文的两半。

关键术语

共享上下文：整个团队及其 Agent 都可查询的账户记忆，回答承诺了什么、决定了什么、有什么风险、下一步是什么，并附有来源。

账户大脑：Tandem 的产品组成部分。一个按客户划分、带来源链接的记忆库，具备风险检测、Tandem Agent 和客户工作区。

简报：按需或定时生成的账户当前状态摘要，可发送到任何地方，包括 Slack。

风险检查：一个返回风险列表的查询，每项风险都附带说明、原因以及来源和引文。相当于大脑自我审视是否存在问题。

MCP（Model Context Protocol，模型上下文协议）：用于将 AI 应用连接到外部系统的开放标准，由 Claude、ChatGPT、VS Code 和 Cursor 支持。

Tandem MCP：Tandem 的 MCP 服务器。它是 Claude、Claude Code 或 ChatGPT 查询账户大脑并将选定的更新推送回去的连接通道。

上下文工程：设计模型在每次推理调用时所看到的内容。对于客户工作而言，这意味着账户的真实情况，而不仅仅是代码仓库的内容。
