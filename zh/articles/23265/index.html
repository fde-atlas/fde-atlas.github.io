这篇来自日本 DeFactory 公司代表德满翔平的指南，面向 IT 自由职业工程师讲解技能清单（スキルシート）的写法。文章指出技能清单不同于简历，是供中介和 PM 在 30 秒至 2 分钟内快速判断候选人与项目匹配度的结构化文件，其质量直接决定单价与成单率。作者基于审阅数千份技能清单的经验，介绍了 Excel、Notion、GitHub README 等格式的分工用法，给出必备项目清单与按职种（后端、前端、基础设施、PM、数据/AI 工程师）突出重点的写法，并强调 2025 年后生成式 AI 相关技能与量化成果是拉开差距的关键，还提供用 ChatGPT、Claude 打磨文案的提示词示例。

要点

  • 技能清单是供中介和 PM 快速筛选的结构化文件，通常 5 至 15 页。
  • 开头 3 至 5 行摘要与最近项目决定第一印象。
  • 成果必须量化，如 API 响应从 500ms 降至 150ms。
  • 生成式 AI 技能（RAG、LLM API、向量数据库）成为高单价差异化要素。
  • 应按案件微调内容，并做成中介易于推荐的格式。

技能清单的本质在于“将技术栈和项目经历整理成一览表，以便最快判断是否适合案件”。中介和PM会用30秒到2分钟左右快速浏览技能清单，决定“是否应该与这个人面谈”。能否在这段短暂的时间内传达出“自己的优势”和“与案件的匹配度”，决定了简历能否通过。

尤其是在自由职业领域，技能清单之所以受到高度重视，有以下几个原因。

  • 案件匹配的即时性：中介会针对一个案件筛选数十到数百份技能清单，因此结构化的信息不可或缺
  • 技术栈匹配确认：需要瞬间判断候选人的技能是否与案件要求的必备技能（语言・框架・云服务等）相匹配
  • 可参与阶段的判断：希望了解候选人从需求定义到运维的哪个阶段能够发挥作用
  • 单价谈判的依据：如果业绩、技能、经验年限被量化，中介更容易推进单价谈判
  • 多个案件的并行考量：在将候选人匹配到多个案件时，以可检索的形式记载会更加便利

在求职活动中，尤其是在IT行业，由于“仅凭职务经历书无法了解技术实力”，越来越多的情况会同时提交技能清单。当CTO或技术负责人等负责技术判断的人参与选拔时更是如此，技能清单的质量直接决定能否突破选拔。

其中最重要的是“开头的摘要”和“最近的案件”。这两项决定了招聘负责人的第一印象，也决定了对方是否会继续阅读后面的详细内容。如果开头3～5行无法吸引读者，即使后面的页面再充实，也可能无人问津。因此，最值得花功夫的就是开篇部分。

Excel版技能清单在日本IT行业被广泛使用的原因如下。

  • 易于结构化：以表格形式整理项目经历和技能组合非常方便
  • 中介熟悉的形式：在日本IT行业中流通最广
  • 易于编辑：添加项目、调整顺序、添加注释都很直观
  • 易于打印和转成PDF：可根据对方要求灵活输出

业务摘要（Summary）相当于整个技能清单的“预告片”，是非常重要的部分。可以说，30秒的快速浏览大多取决于这里。

整理出好的摘要不可或缺的3个要素。

  • “能做什么的人”（专业领域）：后端工程师、AI架构师等专业职位
  • “什么规模”（经验年限、业绩规模）：经验年限、所负责项目的规模、数据量
  • “优势、差异化要素”（独特性）：与其他候选人形成差异化的具体经验

OK例（后端工程师）

拥有10年以Java、Go为主的大规模BtoB SaaS后端开发经验。最近3年负责处理每月1,000万次请求的微服务架构的设计与运维，曾实现API响应速度提升50%、运维成本降低30%的业绩。还主导过AWS环境下的基础设施自动化（Terraform、GitHub Actions），能够从需求定义到运维全流程贯通应对。

NG例

拥有10年工程师经验。从后端、前端到基础设施都有广泛涉猎。请多多关照。

OK例与NG例的区别可以归结为3点：“是否具体”“是否有数字”“能否看出与其他人的不同”。如果是OK例，读者能立刻想象出“这个人能做什么、水平如何、可以委以什么任务”。

即使技能清单的素材已经齐备，呈现方式和展示技巧的不同也会让简历通过率产生巨大差异。这里整理一下一线专业人士实际使用的技巧。

为了让招聘负责人能立刻判断出“这个人符合项目的要求”，针对每个应聘项目调整技能清单，可以大幅提升简历通过率。

调优的检查要点

  • 开头摘要的改写：融入与项目必备条件、加分条件相符的关键词
  • 近期项目排序的调整：将与应聘项目相似度高的经历排在前面
  • 技术栈的顺序：将项目中必备的技术放在表格靠前的位置
  • 工作内容的详略：加厚对应聘项目所需阶段、领域的描述
  • “期望业务”栏的活用：明确写出结合应聘项目关键词的期望

但过度调整会适得其反。绝对不要“写没有的实绩”“夸大工作年限”。原则上应仅限于“调整展示方式”的范围。

以下整理在不触及保密义务（NDA）的前提下传达项目规模的主要方法。

机密信息抽象化示例
客户企业名称“大型制造企业”“BtoB SaaS 企业”“金融机构”
营收规模“年营收数百亿日元规模”“B 轮创业公司”
用户数量“数百万 MAU”“数万家企业使用”
合同金额“数亿日元规模的项目”
产品名称“支付平台”“需求预测系统”
故障信息“减少 ◯ 起影响业务的故障”

模糊化处理的诀窍在于“隐藏公司名和产品名，同时传达行业、规模和问题的本质”。只要让读者能够想象出“这是多大规模、多么复杂的项目”，就能获得充分的评价。

工作之外的活动，作为在技能清单中形成差异化的素材，其分量正逐年增加。以下整理主要的活用方式。

  • OSS 贡献：Pull Request 数量、贡献的 OSS 名称、自研 OSS 的 GitHub URL
  • 技术分享：Qiita/Zenn/个人博客的粉丝数、主要文章的浏览量
  • 演讲实绩：大会名称、主题、年月
  • 书籍与文章写作：技术书、专栏、客座投稿的实绩
  • 个人开发：MAU、GitHub Star 数、变现实绩
  • 社区运营：组织学习会、运营 Discord/Slack 社区
  • 竞赛：Kaggle、AtCoder 等的排名

这些活动作为展示“仅靠工作实绩无法完全传达的技术能力和热情”的素材非常有力。尤其是对 OSS 的贡献和技术分享，招聘负责人和中介容易将其作为“外部佐证”加以核实，因此在自由职业项目的单价谈判中也很有利。

2025 年以后，使用生成式 AI（ChatGPT、Claude 等）来打磨技能清单正逐渐成为常态。以下整理用好它的提示词技巧。

自我介绍・摘要生成提示词示例

你是一名面向 IT 自由职业者的职业教练。请根据以下我的工作内容和实绩，用 3〜5 行撰写技能清单中的“工作摘要”。【条件】包含“能做什么的人”“经验规模”“优势”3 个要素，加入定量数值（%、件数、金额）可以使用专业术语（读者是工程师）使用“ですます”敬语体 【我的工作内容和实绩】 （以条目形式列出 5〜10 项）

项目经历润色提示词示例

请将以下项目概要整理为 IT 技能清单用的“工作内容”和“成果”两个部分。成果务必用定量化的数值来呈现。【项目概要】 （以条目形式列出工作内容）

使用生成式 AI 时需要注意的要点如下。

  • 严禁篡改事实：AI 生成“看似合理”的表述，不是为了夸大事实
  • 不要过度抽象化：具体的技术名称、数值不要交给 AI 抽象化，要自己写
  • 比较多个方案：不要凭一次输出就定稿，要尝试多个版本
  • 最终检查靠人：AI 生成的文字务必自己重读一遍，修正不自然的表达

通过中介（Agent）投递案件时，如果能把技能清单整理成“便于中介推荐”的形式，简历通过率会大不一样。下面整理中介讨厌和喜欢的地方。

中介讨厌的要素（应避免）

  • 陈旧的项目经历排在开头（应把最近的案件放在上面）
  • 技术栈只是罗列，没有写明熟练度和经验年数
  • 超出保密范围、写明具体公司名或产品名
  • 未填写联系方式和可工作日期
  • 格式不统一（字体、颜色、大小杂乱）
  • 单个案件的说明过长（理想是每个案件不超过一页）
  • 自我介绍以“干劲、热情”为主，缺乏具体性

中介喜欢的要素（应采用）

  • 开头用3～5行的摘要概括优势
  • 用技能表明确标出熟练度、经验年数和最近使用时间
  • 最近的案件排在上面，每个案件使用统一格式
  • 用复选框可视化所负责的阶段
  • 成果经过量化
  • 已做保密处理、同时保有具体性的业务内容
  • 期望单价、工作天数、是否可远程都明确

中介会同时向多个案件推荐候选人。因此，他们倾向于优先推荐那些拥有“易读且条理清晰的技能清单”的人。整理技能清单的格式，是提升简历通过率方面投入产出比最高的改进。

想了解中介所经手案件的单价范围和特点，可以通过自由职业 IT/Python 案件一览（每日更新）查看当前正在进行的案件。了解市场动向后，技能清单中应该突出的重点也会更清晰。

写明年龄的好处在于，可以提前判断“从年龄上看是否适合这个职位”，从而避免浪费双方的时间。对于资深人士来说，年龄往往能成为“经验丰富”这一积极因素，尤其是40岁以上的自由职业者，建议写明年龄。

证件照在一般的自由职业项目中并不需要。但如果目标是外部顾问或Fractional CXO这类高端职位，那么在完善LinkedIn资料的基础上使用证件照会更有优势。

在打磨技能清单、争取高单价项目的工程师中，最近备受关注的职业选择是FDE（Forward Deployed Engineer，前沿部署工程师）。FDE是可以争取月薪120～150万日元级别项目的职位，其武器是一份将工程师的实现能力与解决商业问题的能力相结合的技能清单。

结论： IT工程师的技能清单，无论是自由职业项目、求职活动还是SES的推销，都是决定“文件通过率”“单价”“项目质量”的最重要文件。将开头的摘要、技能集表格、项目经历这三部分通过整理和数字加以打磨，并融入生成式AI技能等新趋势，就能打造出在市场上“被选中”的技能清单。

本文介绍了面向IT工程师的技能清单模板、写作范式、不同职种的突出重点，以及提高文件通过率的技巧。最后，再次总结一下要点。

  • 技能清单是“项目匹配判断文件”，其目的、读者和形式都与职务经历书不同
  • 以Excel为基础，同时并用Notion/GitHub/LinkedIn等现代格式是2025年以后的标准做法
  • 开头3～5行的工作摘要，能立即传达“能做什么、在什么规模下、优势是什么”，这是文件通过率的关键
  • 技术技能表必须包含“经验年数＋熟练度＋最近使用时间”三个维度
  • 项目经历应结构化地记载“负责阶段・角色・使用技术・成果（量化）”
  • 生成式AI相关（LLM、RAG、AI Agent、MLOps）的实绩是获得高单价的决定性差异化要素
  • 在兼顾保密义务的同时，将规模和成果抽象化表达的技巧，能兼顾可信度与说服力
  • 已进入利用ChatGPT、Claude等生成式AI来打磨技能清单的时代
  • 通过中介提交时，整理成“便于推荐的形式”，可大幅提升项目匹配率

技能清单不是“做一次就完事”的东西，而是需要随着每个项目、每个职业节点持续更新的。养成在每次项目结束时，将工作内容、成果和所学用文字记录下来的习惯，那么无论是文件筛选还是面谈，都能以最有说服力的方式展示自己。

掌握这些技术和知识的工程师市场价值非常高，如果以精心打磨的技能清单为武器作为自由职业者独立出来，月薪超过150万日元的高单价项目也可以现实地争取到。希望大家将技能清单作为通过中介和直接项目两种途径拓展自己职业发展的武器，持续打磨下去。
