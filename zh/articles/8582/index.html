基础Token 化与 Token语言模型读取的不是字符或单词，而是 token：由分词器产生的子词片段，每个片段映射到模型嵌入的一个整数。Token 是上下文窗口和计费的单位，而文本如何切分成 token 解释了大量令人意外的模型怪癖，这也是几乎所有面试流程都从这里开始的原因。

基础上下文窗口上下文窗口是语言模型一次能够关注到的固定 token 数量，输入和输出共享同一预算。理解它，正是能够合理设定提示词规模、控制成本与延迟、并判断何时该使用 RAG 的工程师，与那些只是把所有内容一股脑粘贴进去然后祈祷的工程师之间的分水岭。

基础嵌入与向量表示嵌入将一段文本转换为一组数字，其位置使得含义相近的内容在空间中彼此靠近，从而让你可以按语义而非关键词进行搜索。嵌入是 RAG、语义搜索、聚类和去重背后的引擎，因此 FDE 面试流程期望你能解释余弦相似度，以及那些会悄悄破坏向量索引的陷阱。

基础Transformer 的直观理解Transformer 是所有现代大语言模型背后的架构，其核心是自注意力机制，让每个 token 可以并行地关注其他所有 token。FDE 面试流程不要求数学推导；他们希望你用高管或同事都能听懂的通俗语言，解释注意力机制为何胜过 RNN、decoder-only 意味着什么，以及为什么长上下文的成本很高。

基础Temperature、Top-p 与采样在每一步，模型都会为每个可能的下一个 token 输出一个概率分布，而 temperature、top-p 和 top-k 等采样设置决定了如何将这个分布转化为实际的选择。FDE 面试循环会测试这一点，因为它控制着确定性与创造性之间的旋钮：知道何时为信息抽取设置低值、为头脑风暴设置高值，以及为什么同一个提示词给出不同答案是预期行为而非 bug。
