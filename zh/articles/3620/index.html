新员工入职 - 手册

原标题：New starter onboarding

PostHog · 约 7 分钟读完

摘要

PostHog 公开的前沿部署工程师（FDE）新人入职手册，介绍其以自助为主的首月流程：第一天与 Simon 见面并参加站会，第一周通过自建演示应用学习产品并录视频复盘，第二至三周接手客户任务与支持工单，第三周线下入职，第四周独立运行 intake。手册强调发现文档缺口时由本人补齐，并列出关键 Slack 频道。

要点

  • FDE 录取率约 1/400，入职以自助为主，无集中培训。
  • 第一周自建演示应用，手动集成 PostHog 各产品并录 Loom 复盘。
  • 第二至三周参与客户任务并每天处理 1-2 个支持工单。
  • 第四周目标：完成首次 intake、工单可见可审查、改进团队流程。
  • 发现手册缺口时，新人应自行补写，方便后来者。

目录

欢迎加入 PostHog 前沿部署工程团队！我们大约每 400 名申请者中只录用 1 人，所以你能走到这一步已经非常出色了！

这里的入职流程主要是自助式的——我们不会让你在会议室里接受两周的培训，而且与许多公司不同，我们更希望你能够快速上手。如果你不确定下面某件事应该由谁来做，那负责人几乎肯定就是你自己。

下面是你第一个月的大致计划——把它当作指南，而不是合同。本手册本身也在不断完善中，所以在你熟悉工作的过程中会发现一些空白，以及一些你需要知道却没有写下来的内容。这很正常，当你发现空白时，你的任务就是把它补上，让下一个人更轻松。

第 1 天

  • 与 Simon 见面，他会带你过一遍这个计划，并回答你的任何问题。此外，请准备好谈谈你在工作方式上的任何偏好（例如工作时间安排、陪伴家人的时间等）。
  • If you start on a Monday, join your first FDE standup.
    • 我们每周都会在这次会议之前填写一个 GitHub issue，以便为讨论话题做好准备。请让一位 FDE 同事把你的 GitHub 用户名添加到创建 sprint issue 的自动化流程中。
  • If you start on a Monday, join your first PostHog All Hands (at 4.30pm UK/11.30am ET).
    • 建议：你应该准备一个关于自己的趣事，并准备好对“披萨上该不该放菠萝”这个话题发表鲜明的观点。

通用入职 / 工具设置

  • 完成我们的运营平台中的入职任务，把自己设置为 PostHog 员工。如果第 1 天没能全部完成也没关系。
  • 安装你喜欢的 LLM。
  • 设置 Zoom、Gong、Granola 和 Calendly 等工具，以便按照我们的标准方式与客户沟通。我们的售前和 CSM 同事有一份关于如何设置我们标准通话工具栈的指南。请向 Simon 申请这些工具的访问权限。
  • 阅读手册中的 FDE 部分。

第 1 周剩余时间

第 1 周的剩余时间用于掌握作为 FDE 你最常接触到的 PostHog 概念。

自主学习产品知识：

完成以下每个步骤后，录制一段短视频（我们主要使用 Loom），解释你做了什么、学到了什么，并分享到你的入职频道中。我们特意没有在本节中提供文档链接，以便你学会浏览我们的网站和文档。

  • 使用你喜欢的 JS 框架和服务器端语言构建一个演示应用（当然前提是它们在我们的支持库范围内）。
  • 在应用中设置 PostHog。避免使用向导/其他辅助工具，因为你遇到的大多数客户都是通过手动集成流程完成的。
  • 在客户端和服务器端都设置身份识别。确保你的用户在客户端和服务器之间被正确地关联起来。
  • 实现合理的会话回放控制。
  • 实现客户端功能开关（feature flags）以及一个使用这些开关的真实实验。
  • 将你的功能开关改为使用服务端本地评估。两种方式的流程有什么区别？我们如何对这两种方式分别计费？
  • 在客户端和服务端都集成错误追踪。
  • 按你的判断添加其他产品。我们有一个实用的框架可以作为指南。
  • 使用 PostHog Wizard 重新运行上面的集成，看看它有多简单，然后让它审计你的应用。这就是其他团队在把范围讨论带给 FDE 团队之前进行自助探索的方式。

在周末结束时，与团队分享一份完整的复盘，总结你所做的工作和学到的东西，并向本页面提交一个 PR，为未来的新成员改进它。

第 2 周 – 开始与客户合作

FDE Vault 是我们分享工作进展的地方。每当你接手一个工单、任务或需求受理时，请按照我们的共享格式将其记录到 vault 中，以便其他 FDE 能够轻松跟进并给出反馈。从仓库根目录的 README 中进行设置，并在记录自己的工作时学习其余内容。

这时你开始与你的客户合作。向 vault 询问我们当前进行中的项目，然后与负责该项目的 FDE 合作，看看你可以接手哪些任务。完成后请他们进行评审。接手任务时，向 vault 询问我们曾如何为其他客户解决类似问题。

支持工单：

在第 2 周和第 3 周，还要接手支持工单，通常每天 1-2 个，视你的工作量而定。工单是对你第 1 周所学内容最快的检验：一个真实的客户问题、你的回答以及他们的回复。

  • 阅读一下 FDE 团队如何与支持团队合作以及如何给自己分配工单
  • 处理一些工单
  • 记录下每一个看起来需要 FDE 介入而不是简单回答的工单，以及原因。在第 3 周结束时把这些记录带给团队。它们从支持的角度展示了支持与 FDE 之间的界线。

第 3 周和第 4 周 – 承担更多客户工作

我们通常会在第 3 周进行现场入职培训——主要围绕对你前几周工作的回顾、更广泛的 GTM 组织如何运作，以及针对以下内容的现场工作。

继续处理你的项目任务，并自己承担更多的工作。

同时，对于你第二周之后出现的任何新项目，开始为这些项目进行需求受理（vault 应该能帮你了解该怎么做）

第 4 周结束时，什么样的表现算优秀

如果出现以下情况，说明进展顺利：

  • 与入职时相比，你的 PostHog 产品知识有了显著提升
  • 你的工作是可见且可评审的：已记录在 FDE Vault 中并通过其检查
  • 你已经开始参与客户项目
  • 你已完成第一次需求收集
  • 你已回复支持工单，并能判断哪些工单需要 FDE 参与
  • 你已改进了我们团队的工作方式

第二个月及以后

到第二个月结束时：

  • 你将完成第一次端到端的客户合作
  • 你将继续改进我们的工作方式
  • 你将为 PostHog（产品）回馈一些有价值的东西

新员工常见问题

有哪些实用的 Slack 频道？

PostHog 在沟通方面拥有透明的文化，因此这里有一些实用的 Slack 频道。你可以自行加入这些频道，无需请求许可：

  • #team-fde：前沿部署工程团队。这是我们大部分时间相互协作的地方。
  • #group-cs-sales-support：所有负责客户的成员进行跨团队讨论的频道。
  • #team-customer-success：客户成功团队。
  • #team-product-led-sales：产品驱动销售团队。
  • #team-new-business-sales：新业务销售团队。
  • #team-onboarding：入职引导团队。
  • #team-people-and-ops：任何与运营相关的话题。
  • #customer-churn：讨论潜在和实际的客户流失。
  • #changelog：产品发布。
  • #incidents：用于通知可能影响客户的事故。请务必将其设置为每条消息都提醒你，以便你了解何时出现问题。
  • #ask-max：专注于内部流程和问题的机器人。如果你需要自助寻找答案，这里应该是你的首选。
  • #ask-posthog-anything：当你无法通过我们的手册、文档、Slack、代码仓库或 #ask-max 自助找到问题答案时使用。
  • #tell-posthog-anything：用于全公司范围的公告，或关于 PostHog 人员、产品、政策、项目等的通知。
  • #team-fde-tests：用于测试任何自动化 / Slack 工作流的频道（避免刷屏主频道 #team-fde）

在 PostHog，我们并非 24/7 全部围绕工作，所以这里还有一些有趣的频道：

  • #random：用于与 PostHog 无关的内容。
  • #whereintheworld：分享来自世界各地的酷炫事物
  • #merch：任何与周边商品相关的内容（因为我们热爱周边）
  • #no-context-posthog：如果我们告诉你这个频道的用途，那就等于提供了上下文。

这里还有一些 Slack 使用技巧：

  • 请一位同事将你加入 Team FDE Slack 用户组。这样，任何人在任何聊天中提到 @fde 时，你都会收到通知。
  • 设置“频道关键词”，以便你收到自己关心话题的通知。我们建议将 "fde" 作为第一个关键词，但也可以随意添加你自己的关键词。
  • 为了帮助你专注于最重要的通知，你可以将特定的人设为 VIP，让他们的消息更加醒目。也许你的 FDE 同事可以成为 VIP？
