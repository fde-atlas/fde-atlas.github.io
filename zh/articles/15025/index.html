SCIM

原标题：SCIM

FDE Interview Prep · 2026 · 约 1 分钟读完

摘要

本文面向 FDE 面试准备，讲解 SCIM 用户开通协议：其 REST 端点、RFC 7643/7644 规范，以及与 SAML/OIDC 登录的分工。文章指出弱回答常忽略用户删除处理，并强调两个常见上线故障：未实现 filter 导致重复账号或 409 错误，以及 Okta 与 Microsoft Entra ID 的 PATCH 格式差异，建议在切换日前用客户的真实身份提供商做测试。

要点

  • SCIM 是身份提供商通过 REST 端点管理应用内用户与群组的协议。
  • 规范基于 RFC 7643（资源模式）与 RFC 7644（协议），登录本身走 SAML 或 OIDC。
  • 强候选人应以 externalId 为键，将 active: false 视为立即吊销会话与令牌的事件。
  • 未实现 GET /Users 过滤会导致重复账号或 409 Conflict。
  • Okta 与 Microsoft Entra ID 的 PATCH 格式不同，须按客户实际身份提供商测试。

全文

SCIM 是一种 REST 协议，客户的身份提供方通过调用你暴露的端点（例如

POST /Users

,

PATCH /Users/{id}

和

/Groups

）在你的应用中创建、更新和停用用户与群组。资源模式定义在

RFC 7643

，协议（包括 PATCH 操作和过滤）定义在

RFC 7644

。登录本身通过

SAML

或进行；SCIM 决定账户是否存在。

externalId

或你自己的

id

作为用户的主键，将

active: false

视为立即撤销活跃会话和 API 令牌的事件，而不仅仅是下次登录时生效，并能说明目录群组如何映射到你产品中的角色。

有两件事会破坏上线。在创建用户之前，身份提供方会用

GET /Users?filter=userName eq "..."

进行搜索：如果你没有实现该过滤器，或者它没有返回通过即时登录已创建的用户，身份提供方就会尝试再次创建，导致账户重复或

409 Conflict

错误。此外，Okta 和

Microsoft Entra ID

构造 PATCH 请求的方式不同，因此针对其中一个测试过的服务器在另一个上可能会失败；在切换日期之前，务必针对客户实际使用的身份提供方进行测试。
