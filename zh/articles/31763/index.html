摘要

这是一门面向 FDE 的实践课程，以虚构保险公司 Bramfield Mutual 为唯一案例，完整走一遍客户交付流程：从首次会面、发现与界定范围、接入客户遗留系统，到数据清洗、构建 AI 试点、评测验证、在客户 AWS 账户内上线，再到交接与扩展。课程共 63 课、8 个部分，目前发布 18 课，约 15 小时，含 10 个实验（8 个在学员自己的 AWS 账户中）和 400 多张图表。内容强调最小权限访问、个人数据脱敏、评测与影子模式、安全审查和可审计的决策日志等真实工程细节。

要点

  • 以虚构客户 Bramfield Mutual 贯穿全部 63 课。
  • 已发布 18 课，约 15 小时，10 个实验中 8 个用学员自己的 AWS 账户。
  • 覆盖从发现、试点、评测到客户环境内生产部署的全流程。
  • 强调最小权限、数据脱敏、影子模式与可审计日志等实操细节。
  • 免费课开放试读，其余需购买，新课完成后陆续发布。

第 1 部分

这份工作与客户

这份工作究竟是什么，从招聘该职位的企业中解读，它与周边角色的区别，以及你在课程剩余部分将接手其系统的客户。

6 课，全部已发布

  • 前沿部署工程师做什么一个客户，多种能力：Palantir、OpenAI、Salesforce 和 Ramp 如何用自己的话描述这项工作，以及真实的一周是什么样的。免费
  • 这份工作与解决方案工程师、顾问和产品工程师的区别谁编写生产代码，谁对结果负责，谁在演示完幻灯片后就离开——从真实的招聘启事中解读。已锁定
  • 认识本课程的客户 Bramfield Mutual一家虚构的宾夕法尼亚州保险公司，面临理赔积压、老旧的理赔数据库、每晚的文件传输以及对个人数据的严格规定；你在 AWS 上构建其系统并阅读需求简报。免费](1)
  • 客户合作项目如何运行探索、试点、生产、交接和扩展，每个阶段必须产出什么，以及由两名工程师和一名策略师组成的小组。已锁定
  • 第一天进入并非你构建的系统以只读权限梳理 Bramfield 的服务器、数据库、文件投递和服务，并绘制你整个课程都要使用的系统地图。已锁定
  • 工作笔记、决策日志和每日更新让任何其他人都能接手你账户的三份文档，从第一天起就保存在 Git 中。已锁定

第 2 部分

探索与范围界定

第一次会议、账户上的关键人物、在客户自己的数据上测量的基线、第一周的安全问题，以及试点的工作范围。

7 节课，全部已发布

  • 第一次会议：“我们想要用于理赔的 AI”第一个小时要问的问题、如何听出请求背后的真实问题，以及会后发送的笔记。已锁定
  • 账户上的关键人物理赔负责人、理赔员、IT、安全、合规、供应商风险以及签字的人，以及他们每个人需要从你这里得到什么。已锁定
  • 把愿望变成可衡量的数字从 Bramfield 自己的理赔数据库测量今天的结案天数、积压量和主管转交量，以及每延迟一天损失多少美元，从而为试点建立基线。已锁定
  • 数据真的在那里吗？在做出任何承诺之前，先对理赔表、文件投递和文档进行剖析，找出缺口、重复项和负责人。已锁定
  • 安全与合规探索州保险数据安全法、加州隐私法、HIPAA 是否适用、SOC 2 问卷，以及要求数据保留在美国区域：第一周要问安全团队的问题。已锁定
  • 当答案不是 LLM 时三个 Bramfield 的请求，其中规则、查询或更好的表单胜过模型，在同样的 200 条理赔上测量，以及如何礼貌地说明这一点。已锁定
  • 工作范围与试点计划利用你测量的数字，撰写试点范围、成功指标、范围外内容、时间线、风险登记册以及试点以美元计的成本。已锁定

第 3 部分

进入客户的系统

工程师要花整整几周做的集成工作：最小权限访问、客户的单点登录、一个老旧的 SOAP 服务、每夜文件投递、增量加载、安全的写回、私有网络、企业代理和密钥。

已发布 9 节课中的 3 节

  • 以正确的方式获取访问权限：范围受限的账户，而非全局管理员请求并测试对 Bramfield 数据库、文件和 AWS 账户的最小权限访问，并拒绝“给管理员权限省时间”的提议。已锁定
  • 通过客户的身份提供商登录使用 OIDC 通过 Keycloak 将 Bramfield 的员工登录到你的应用，读取并验证真实的 SAML 登录，测量被禁用用户的最后一个令牌还能工作多久（我们这次运行中为 286 秒），并修复四个真实的登录失败：轮换的密钥、时钟偏差、更改的密码和缺失的组声明。已锁定
  • 调用旧版 SOAP API：分页与速率限制在不使 Bramfield 的 SOAP 保单服务过载的前提下读取 20,000 份保单：将请求节奏控制在低于与客户自身任务共享的速率限制之下，只重试那些有可能成功的错误，使用崩溃后可恢复的游标，以及运行中途新增保单时偏移分页的隐蔽 bug。已锁定
  • 每夜文件投递从 Bramfield 的 SFTP 服务器获取 CSV 导出文件，其中包含两种日期格式、三种金额写法、重复行、仍在写入中的文件、带字节顺序标记的 Windows-1252 文件，以及时钟回拨那一夜凌晨 2 点的投递。即将推出
  • 只加载变更的数据，以及其中隐藏的 bug基于“updated_at 大于上次运行时间”的加载会静默遗漏行，逻辑复制作为解决方案，并在复制槽填满磁盘之前将其删除。即将推出
  • 写回数据而不产生重复在 Bramfield 的工作队列中创建任务，确保超时和重试永远不会造成任何重复。即将推出
  • 无公共互联网：私有方式访问系统通过私有子网、VPC 端点和 Session Manager 访问 Bramfield 的系统，而不是开放端口和 SSH 密钥。即将推出
  • 企业代理与证书错误每个出站调用都经过一个检查 TLS 的代理；你在真实的模型调用中复现 CERTIFICATE_VERIFY_FAILED，并使用客户的证书包修复它。即将推出
  • 保存并轮换客户的密钥将凭据存储在 Secrets Manager 中，在运行时读取它们，并在服务不停机的情况下轮换其中一个。即将推出

第 4 部分

从混乱数据到安全数据

清理理赔数据，在变更的列破坏加载之前捕获它，在任何模型接触数据之前对个人数据进行脱敏，读取理赔文档，与理赔团队一起构建黄金标准集，并记录每个数字的来源。

6 节课，即将推出

  • 清理理赔数据使用 DuckDB 和 pandas 对导出文件进行剖析、清理和加载，并让测试在出现问题时大声报错，而不是加载坏行。即将推出
  • 当上游团队更改列时一个被重命名的列，要么在凌晨 2 点破坏加载，要么悄悄地用空值填满它，而数据契约可以提前捕获这个问题。即将推出
  • 在模型接触数据之前发现并脱敏个人数据理赔备注中的姓名、电话号码、SSN 格式数字、驾照号码和 VIN，使用 Microsoft Presidio 加上你自己编写的识别器进行脱敏，并在标注样本上进行测量，包括有效性检查会错误跳过的那些数字。即将推出
  • 读取理赔文档与保单表单将 PDF 和扫描表单转换为可信赖的文本和表格，并检查过程中丢失了什么。即将推出
  • 与理赔团队一起构建黄金标准集300 个理赔案例，其正确答案由 Bramfield 的理赔负责人确认，这样之后的每个数字才有意义。即将推出
  • 每个数字的来源记录数据血缘，让你在数月后仍能回答“这个决策用了哪个文件和哪些行？”即将推出

第 5 部分

试点：一个能胜任工作的 AI

选择模型及其运行位置、代码可校验的决策、来自保单表格的答案、对数据的安全提问、理赔分诊 Agent 及其 MCP 服务器、由理算员审批每一份草稿、一条隐藏指令，以及一个诚实的演示。

10 课，即将推出

  • 选择模型及其运行位置不保留数据的供应商 API、部署在 AWS us-east-1 区域内的模型，或自行托管的模型，从数据位置、每件理赔的美元成本和速度进行对比，使用相同的提示词。即将推出
  • 代码可校验的理赔决策模型返回经 Pydantic 校验的结构化决策，绝不输出自由文本，错误的格式会在任何人看到之前被捕获。即将推出
  • 从保单表格中作答使用 RDS 上的 pgvector 对 Bramfield 的保单表格进行检索，每个答案都引用具体条款。即将推出
  • 找不到正确条款时怎么办混合搜索与重排序，并在黄金集上对比前后的召回率。即将推出
  • 安全地回答关于理赔数据的问题通过只读数据库角色实现 Text-to-SQL，每条查询都经 sqlglot 对照允许列表进行校验。即将推出
  • 理赔分诊 Agent一个 LangGraph Agent，读取理赔、核查保障范围、寻找欺诈信号并起草决策说明，仅使用只读工具。即将推出
  • 将 Bramfield 的系统封装为 MCP 服务器把保单服务、理赔数据库和工作队列封装为一个 MCP 服务器，让任何 Agent 都使用同一套经过校验的工具。即将推出
  • 由人来审批每个决策使用 interrupt 暂停 Agent，让理算员批准、编辑或拒绝每份草稿，并在执行前用代码重新核查理赔。即将推出
  • 隐藏在理赔文件中的指令一份诱导 Agent 批准赔付的理赔记录，一个会服从它的简单 Agent，以及层层设防、最终守住底线的防御体系。即将推出
  • 讲真话的试点演示向理赔主管展示真实案例，包括失败案例，以及为什么在简单案例上打磨精美的演示日后会失去信任。即将推出

第 6 部分

证明它有效

与客户就“有效”的含义达成一致、分析失败案例、每次变更都用代码为 Agent 打分、将 LLM 评审员与理赔负责人进行对照校验、在影子模式下与理算员并行运行，以及诚实地呈现结果。

6 节课，即将推出

  • 对 Bramfield 来说“有效”意味着什么在测试之前与客户就衡量标准达成一致：决策正确性、错误赔付的美元金额、漏检的欺诈、结案天数和每件理赔成本。即将推出
  • 分析失败案例对 Agent 的 100 条真实轨迹进行错误分析，归纳为少数几种真正重要的失败类型。即将推出
  • 评测框架在黄金集上运行 Agent，并在每次提示词、模型或工具变更时通过代码进行评分。即将推出
  • 针对理赔决定记录的裁判，与理赔主管核对书面记录的 LLM 裁判，在获得信任之前先与理赔主管自己的评级进行比对。即将推出
  • 影子模式：AI 与理赔员并肩工作两个模拟周，Agent 默默地对每一起理赔做出决定，并与理赔员实际的处理结果进行对比。即将推出
  • 试点结果汇报撰写并向 Bramfield 的高管展示结果，包括置信区间、以美元计算的成本与节省，以及坦率说明的失败案例。即将推出

第 7 部分

客户围墙内的生产环境

部署在客户自己的 AWS 账户中的生产技术栈、私有服务、绝不外泄的追踪数据、每起理赔的成本明细、预演过的供应商故障、一次一个州的逐步推广、无需 shell 的调试、安全审查，以及审查员能读懂的审计轨迹。

9 课，即将推出

  • 在客户的 AWS 账户中构建用 Terraform 编写的生产技术栈，部署在 us-east-1，位于 Bramfield 自己拥有的账户中，并使用其团队可以审计的角色。即将推出
  • 在私有子网中运行服务ECS Fargate 上的容器位于内部负载均衡器之后，任何地方都没有公开地址。即将推出
  • 绝不离开客户的追踪与日志OpenTelemetry 发送到 Bramfield 网络内部的收集器，在存储任何内容之前先剔除个人数据。即将推出
  • 每起理赔的成本与模型网关所有模型调用共用一个网关：按团队设置限额、缓存、备用模型，以及每起理赔以美元计的成本明细。即将推出
  • 当模型供应商出现故障时超时、速率限制和完全中断，有意进行预演，同时理赔队列仍可手动运作。即将推出
  • 先在一个州推广每个州一个功能开关，先让一小批理赔员使用，以及你真正演练过的回滚方案。即将推出
  • 在没有 shell 的情况下调试他们的环境403 错误、VPC 内无法解析的名称，以及只在那个环境中变慢的调用，用 Session Manager、日志和追踪来解决。即将推出
  • 通过安全审查用你自己技术栈中的证据回答 Bramfield 的供应商安全问卷：加密、访问、保留策略、数据存储位置，以及 SOC 2 报告能覆盖和不能覆盖的内容。即将推出
  • 审查员能读懂的审计轨迹每项决定、审批和模型调用都记录在无人能篡改的日志中，以及能回答州保险审查员问题的查询。即将推出

第 8 部分

交接、采用与下一个项目

让理赔团队用起来，交接一个他们能自行运行的系统，向产品团队反馈现场报告，把一次部署变成可复制的模式，扩展方案，一个由你亲自执行的毕业项目，以及你的作品集与面试。

7 节课，即将推出

  • 让理赔团队用起来培训理赔员，从日志中衡量真实使用情况，并解决人们退回旧做法的原因。即将推出
  • 运行手册与交接向 Bramfield 的团队交付一个他们能够自行运维的系统：运行手册、值班说明，以及一次与他们共同演练的故障。即将推出
  • 反馈给产品团队的现场报告哪些是你构建的、只有 Bramfield 需要的东西，哪些是每家保险公司都会需要的，以及如何撰写才能让产品团队据此行动。即将推出
  • 把一次部署变成可复用的模式将连接器、评测和 AI Agent 打包，让第二个团队在几天内启动，并衡量第二个团队真正启动所需的时间。即将推出
  • 扩展提案针对房屋保险理赔的商业论证，以美元计算，基于你在车险试点中衡量到的成本和结果。即将推出
  • 毕业项目：端到端服务一个新部门一场冰雹过后，Bramfield 的房屋保险理赔团队寻求帮助；你亲自完成需求调研、试点、评测和上线，然后将其全部拆解。即将推出
  • 你的作品集与 FDE 面试把 Bramfield 的工作转化为作品集，并练习问题拆解、客户、调试和设计等面试环节。即将推出
