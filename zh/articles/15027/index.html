OpenID Connect

原标题：OpenID Connect

FDE Interview Prep · 2026 · 约 2 分钟读完

摘要

本文讲解 OpenID Connect（OIDC）作为 OAuth 之上的身份层：授权服务器返回签名的 ID token（JWT），包含 iss、sub、aud、iat、exp 等必需声明，nonce 用于绑定登录请求。客户端通过 /.well-known/openid-configuration 发现文档获取端点与签名密钥；RFC 9700 要求公共客户端在授权码流程中使用 PKCE。文章面向 FDE 面试：客户身份团队通常已决定用 OIDC 或 SAML（Okta 招聘要求两者都会），优秀候选人应通过统一 broker 支持两者，使每个客户连接只是配置而非代码，并说明 OIDC 校验要点：验签、iss、aud、过期与 nonce；固定算法、按 kid 拉取新密钥、校验 issuer 防止跨租户 token 登入；以 issuer 加 sub 作为用户主键而非邮箱；不要把 ID token 当 bearer token 调 API，应使用 access token。

要点

  • OIDC 在 OAuth 上增加身份层，ID token 是含 iss、sub、aud、iat、exp 的签名 JWT。
  • 通过 /.well-known/openid-configuration 发现端点与密钥；RFC 9700 要求公共客户端用 PKCE。
  • FDE 面试中 OIDC 与 SAML 由客户决定，Okta 招聘要求两者都支持。
  • 校验签名、iss、aud、过期、nonce，并防止其他租户的有效 token 登入。
  • 用户主键用 issuer 加 sub，不用邮箱；API 调用用 access token 而非 ID token。

全文

OpenID Connect 是 OAuth 之上的一个身份层：授权服务器还会返回一个 ID 令牌，这是一个经过签名的 JWT，其必需的声明说明了由谁签发（

iss

）、谁登录（

sub

）、签发给哪个客户端（

aud

），以及签发时间（

iat

）和过期时间（

exp

）。如果客户端发送了

nonce

，令牌会将其带回，以便客户端将其与自己的登录请求关联起来。客户端通常通过提供商位于

/.well-known/openid-configuration

(

OpenID Connect Discovery

）来查找其端点和签名密钥，而当前的安全指南

RFC 9700

要求浏览器和移动应用等公共客户端在授权码流程中使用 PKCE，并建议其他所有客户端也使用它。ID 令牌及其检查内容见

OpenID Connect Core

.

固定允许的算法，当令牌指定了一个你没有的密钥 ID（

kid

）时重新获取提供商的密钥，并检查签发者是否是为该客户配置的那个：在使用多租户身份提供商时，否则来自其他公司租户的有效令牌可能会让人登录到该客户的工作区。以签发者和

sub

对作为用户的键，绝不要用电子邮件，因为 OIDC Core 只保证

sub

在一个签发者内唯一且稳定，而人们会更换电子邮件地址。绝不要将 ID 令牌作为持有者令牌发送给你的 API；那是访问令牌的用途。
