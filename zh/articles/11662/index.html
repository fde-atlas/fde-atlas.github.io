SWE-agent (2024) 面向 FDE 的解读

原标题：SWE-agent (2024) Explained for FDEs

FDE Interviews · 2026-10-17 · 约 4 分钟读完

摘要

Princeton 团队提出 SWE-agent，核心观点是语言模型 Agent 需要专门设计的工具层，即 Agent-计算机接口（ACI）。在 SWE-bench 上，GPT-4 Turbo 配合该接口解决了 12.5% 的真实 GitHub issue，远超此前 3.8% 的最佳方案；同一模型仅用 shell 时为 11.0%，加上 ACI 升至 18.0%。消融实验显示：搜索返回简洁摘要优于逐条展示；拒绝引入语法错误的编辑可提升约 3 个百分点；展示完整文件或保留全部历史反而降低表现；失败运行更慢更贵（平均 21 步、2.52 美元，成功为 12 步、1.21 美元）。对 FDE 的启示是：工具设计应与提示词同等重要，需限制输出、校验输入并返回可操作的错误信息。

要点

  • SWE-agent 提出 ACI 概念：为 Agent 专门设计工具层
  • SWE-bench 解决率 12.5%，远超此前 3.8%
  • 简洁搜索摘要优于逐条展示结果
  • 语法检查守卫单独带来约 3 个百分点提升
  • 失败运行平均 21 步、2.52 美元，成本高于成功

一分钟速览论文

人类工程师不会在原始终端里修复 bug。他们使用带有搜索、语法高亮和代码检查功能的编辑器。普林斯顿团队想知道语言模型 Agent 是否也需要专门为其构建的工具，答案显然是肯定的。

他们将这一工具层称为 agent-computer interface（ACI，Agent-计算机接口）：即 Agent 可以运行的命令以及返回内容的格式。SWE-agent 的 ACI 刻意保持精简。

find_file

和

search_dir

命令返回某个词出现位置的简短摘要，并在命中过多时拒绝执行，要求使用更精确的查询。文件查看器每次显示 100 行，附带行号以及上下方的行数信息。一个

edit

命令替换一段行，显示结果并运行 linter；如果编辑引入了语法错误，该编辑会被拒绝，并告知 Agent 原因。此外还有用于运行代码和测试的常规 shell。

在 SWE-bench（要求 Agent 解决真实 Python 仓库中的真实 GitHub issue，并用项目自身的测试来验证结果）上，使用 GPT-4 Turbo 的 SWE-agent 解决了 12.5% 的 issue。此前最好的方法——检索文件并生成补丁而不与仓库交互——只解决了 3.8%。在包含 300 个 issue 的 Lite 子集上，同一模型仅使用 shell 解决了 11.0%；而使用 ACI 则达到了 18.0%。

消融实验是这项工作最持久的贡献：在模型保持不变的情况下，它们展示了哪些接口设计有帮助、哪些有害。

只配备 Linux shell 的 Agent 在真实软件任务中举步维艰：冗长的输出淹没了它们的上下文，用 sed 或重定向进行编辑容易出错，而一个错误会引发连锁反应。

设计一个 Agent-计算机接口（ACI）：少量用于查找、查看和编辑代码的简单命令，每次操作后给出简洁的反馈，以及拒绝损坏编辑的语法检查。

当时的 SWE-bench 最优水平（解决了 12.5% 的真实 GitHub issue，此前为 3.8%），以及展示哪些接口设计真正起作用的消融实验。

为什么这对 FDE 很重要

大多数 agent 项目都是从选择模型开始，然后把客户现有的 API 接成工具。这篇论文指出，工具本身值得与提示词同等的设计投入，并展示了优秀的工具设计是什么样的。

反馈格式会改变行为。 一个像编辑器的“查找下一个”那样逐条显示结果的搜索命令，会让 Agent 翻遍每一个匹配项并耗尽预算。它的表现甚至比没有搜索命令还差（12.0% 对 15.7%）。返回紧凑摘要的搜索效果最好。返回分页 JSON 的客户 API 也需要同样的处理：摘要、限制上限，并告诉 Agent 如何缩小请求范围。

护栏能阻止级联失败。 拒绝破坏语法的编辑并给出清晰的错误信息，仅此一项就提升了三个百分点。一次编辑失败后，最终成功的概率从 90.5% 降至 57.2%。在工具输入改变任何东西之前先进行验证，并返回可操作的错误信息。

更少的上下文可能更好。 显示整个文件而不是 100 行的窗口，使性能从 18.0% 降至 12.7%；保留完整历史记录而不是最近五条观察结果，使其降至 15.0%。更多信息并不意味着更多帮助。

失败既缓慢又昂贵。 成功的运行中位数为 12 步、花费 $1.21；失败的运行平均为 21 步、花费 $2.52，且 93% 的成功运行在耗尽预算之前提交了结果。提高预算大多只是换来更昂贵的失败。
