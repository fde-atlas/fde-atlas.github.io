Tülu 3（2024）FDE 解读

原标题：Tülu 3 (2024) Explained for FDEs

FDE Interviews · 2026-10-17 · 约 4 分钟读完

摘要

本文解读 AI2 与华盛顿大学发布的 Tülu 3 开源后训练方案：在 Llama 3.1 基础模型上依次进行 SFT、长度归一化 DPO 和全新的 RLVR（可验证奖励强化学习），并公开全部数据、代码与评测套件。70B 版本平均分 76.2，超过 Llama 3.1 70B Instruct 和 Claude 3.5 Haiku。作者强调数据去污染（某代码数据集与 HumanEval 重叠达 70.7%）、保留未见评测集防止过拟合，以及偏好调优带来的最大提升。对 FDE 而言，这是客户模型定制的最佳公开实践手册：先定义任务与指标，再收集数据，可用代码校验的输出可直接作为 RL 奖励。

要点

  • Tülu 3 是完整的开源后训练流水线：数据、代码、评测与中间检查点全部公开。
  • 四阶段配方：提示词整理、约 93.9 万条 SFT、长度归一化 DPO、RLVR。
  • RLVR 用规则校验（如数学答案正确）给 0/10 奖励，无需奖励模型。
  • 70B 平均 76.2 分，超过 Llama 3.1 70B Instruct（74.1）与 Claude 3.5 Haiku（75.3）。
  • 去污染发现某开源代码数据集与 HumanEval 重叠 70.7%，会虚高评测分数。

一分钟速览论文

预训练模型只会预测文本；后训练把它变成一个助手。OpenAI、Anthropic 和 Meta 等实验室会发布结果，却很少公开产生这些结果的数据和方法。Tülu 3 由 Allen Institute for AI 和华盛顿大学（Nathan Lambert、Hannaneh Hajishirzi 等众多研究者）推出，是一套完整的开源后训练流水线：数据、代码、评测套件、中间检查点，以及一份详述哪些方法有效、哪些无效的长篇报告。

该配方在 Llama 3.1 基础模型（8B、70B 和 405B）之上分为四个阶段。第一，为目标技能（知识、推理、数学、编程、精确指令遵循、对话和安全）整理提示词，来源包括公开数据集和新的合成数据，并剔除任何与评测重叠的内容。第二，在约 93.9 万条按技能逐一调校的样本混合集上进行监督微调。第三，使用长度归一化的 DPO 变体进行偏好调优，配对样本通过从模型池（包括 Tülu SFT 模型本身）中为每个提示词采样四个回答，再由 GPT-4o 打分构建。第四，作者称之为可验证奖励强化学习（RLVR）的新阶段：采用 PPO，当校验器确认答案正确（数学答案匹配、指令的约束条件满足）时奖励为 10，否则为 0，且不使用奖励模型。

结果。在 70B 规模上，Tülu 3 在开发套件上平均得分为 76.2，高于 Llama 3.1 70B Instruct（74.1）、Qwen 2.5 72B Instruct（72.8）、Claude 3.5 Haiku（75.3）和 GPT-4o mini（69.6）。在 405B 规模上，它与 DeepSeek V3 和 GPT-4o 相当。在 8B 规模上则表现参差：它击败了 Llama 3.1 8B Instruct，但平均得分略低于 Qwen 2.5 7B Instruct。

这份报告的持久价值在于其方法论：区分开发评测与未见评测、严格的去污染处理、细致的数据消融实验，以及一份坦诚列出哪些方法没有奏效的清单。

研究笔记：问题、方法与结果

提示词整理、SFT、DPO 和可验证奖励强化学习，全部开源发布

最终混合集中的监督微调样本数

他们的去污染处理在一个流行的开源代码数据集中发现的 HumanEval 样本占比

强大助手背后的后训练配方一直是保密的，而开源配方已经落后。大实验室之外没有人能看到哪些数据和方法真正重要。

公开一切：用整理好的数据和合成数据覆盖目标技能，针对评测进行去污染，然后运行 SFT、长度归一化的 DPO，以及一个只奖励可验证正确答案的新 RL 阶段。

Tülu 3 70B 在开发套件上平均得分为 76.2，高于 Llama 3.1 70B Instruct（74.1）和 Claude 3.5 Haiku（75.3）。405B 模型在同一套件上与 DeepSeek V3 和 GPT-4o 相当。

为什么这对 FDE 很重要

大多数客户模型定制工作都是 Tülu 3 大规模做法的小型版本：在示例上进行监督微调，可能再加上偏好调优，并按照客户关心的指标进行评测。这份报告是做好这件事的最佳公开指南。

从技能和评测出发，而不是从数据出发。 团队首先列出他们想要的技能以及衡量这些技能的基准测试，然后构建数据来提升这些数字。对客户而言：先定义任务和指标，再收集数据。

用你的测试来检查你的数据。 他们的去污染分析发现，一些广泛使用的开源数据集包含大量标准基准测试的内容；其中一个代码数据集与 HumanEval 的重合度达 70.7%。在这样的数据上训练会虚高分数，却不能真正提升模型。对客户数据与客户的评测集运行同样的检查。

保留一个从不用于调优的评测集。 团队留出了一个从未见过的测试套件，结果发现他们对一些开发基准过拟合了，尤其是 MATH 和精确的指令遵循。留出一些开发期间无人查看的真实案例。

可验证的奖励适合企业任务。 如果一个输出可以通过代码检查，例如 schema、总和、格式规则或通过的测试，那么这个检查就可以作为强化学习的奖励，无需奖励模型。报告也揭示了陷阱：当唯一的检查是格式时，模型会学会生成格式正确但毫无内容的东西。

偏好调优带来了最大的单次提升。 在 70B 规模上，DPO 将平均分从 72.6 提升到 76.2，聊天胜率从 26.3% 提升到 49.6%。如果监督微调效果平平，偏好对可能是缺失的一步。
