实现销售到客户入驻无缝交接的技巧

原标题：Tips for a seamless sales-to-customer-onboarding handoff

Rocketlane · 2022-09-09 · 约 4 分钟读完

摘要

Rocketlane 社区讨论销售与客户入职交接不畅的问题：销售为达成目标仓促签约，客户技术准备不足会拖慢首次价值实现时间（TTFV）。文章给出多项实操建议，帮助入职团队避免交接信息缺失造成的下游延误。

要点

  • 让高管发起人了解客户准备度对 TTFV 的影响，并指定专人负责。
  • 在售前阶段就向客户说明准备度要求，并交接可追踪的在线清单。
  • 与客户负责人一起尽早实现一个依赖少的小胜利，建立推进动力。
  • 每周向高管发送摘要，突出依赖项及其对 TTFV 的影响。
  • 在启动会前锁定客户方工程资源的明确时间承诺，如每周若干小时。

使用以下方式总结博客

销售团队必须完成目标，这意味着成交时间往往比客户入职团队所期望的更早。客户入职的挑战之一是客户是否准备好提供技术集成点。这可能会造成停滞，延误客户达到“首次价值时间”（time-to-first-value）。

在这次讨论中，Preflight 社区的成员们探讨了如何避免信息不充分的交接对入职团队造成的重大下游影响。Preflighter 们讨论了如何应对这类情况，以及哪些做法能帮助入职团队规划顺畅的集成。

  • 确保高管支持者了解所需的准备就绪程度及其对首次价值时间（TTFV）的影响。此外，确保高管支持者指定一名对准备工作负责的人。
  • 在售前演示或讨论中提供准备工作要求的概览。
  • 将预先构建好的清单交给负责人。如果这份清单是在线的、可填写的、可追踪的，并且能在错过里程碑时发出提醒——那就更好了！
  • 与你的支持者（即负责人）共同确定一个“胜利”，它可以在依赖最少的情况下实现，并且早于预期价值的估计时间线。这能带来一定的进展感和成就感，也能推动快速满足其他要求或解决依赖问题。
  • 每周向支持者发送一份高管摘要，突出依赖问题及其对 TTFV 的影响。在与高管支持者的月度成功评审中使用这份摘要。尽量在入职阶段每月进行一次，然后转向季度业务评审。
Irit Eizips 的首次价值交付框架：如何创造早期胜利

在客户入职前进行系统成熟度调查是处理这个问题的一种方式。

我认为，针对每个垂直行业的“解决方案”标准包准备一份就绪清单会很有帮助。以下是一些示例：

（i）电商基础——列出所涵盖的用例，以及需要哪些组织、内容和 API 方面的准备

（ii）电商进阶——列出所涵盖的用例，以及需要哪些 API 方面的准备

（iii）电信基础——入门用例以及需要哪些 API 等

从最适合他们的通用包开始，评估他们的准备情况。这可能就是最小可行且依赖最少的胜利！

  • 在部署的每个“阶段”，确保在开始时获得客户方“开发人员时间”的承诺，以便快速修复 API 问题等。

通常情况下，购买你解决方案的客户可能无法优先安排其组织内工程资源的时间。最好确保他们在开始之前已获得内部支持并落实工程资源，例如未来四周内每周 X 小时的工程时间。在项目启动前完成这一点，可以让整个组织就优先推进这项工作达成一致。

入职引导团队负责确保销售交接不会在客户旅程的后续阶段造成任何瓶颈。通过这些简单的技巧和预防措施，入职引导团队可以确保交接顺畅，并为客户带来愉悦体验。

前沿部署工程师（FDE）会深入客户环境，负责实施、定制复杂产品并使其落地运行。他们打通集成障碍、修复数据问题、调整工作流程、弥合工程缺口——大幅加速客户入职引导、产品采用和价值实现，远超传统售后角色的作用。

70–85% 资源利用率。G2 评分 94%。

企业级实施失败，是因为客户不遵循流程，或未能按时提供干净的数据。大多数延误纯粹是“客户侧”的问题。

实施失败，是因为复杂的环境需要实时的技术问题解决。FDE 能够打通传统入职团队无法独立解决的工作流、集成和未知约束。

获取更出色的全能 PSA

将工程师直接派驻到客户处的公司，相比传统售后模式，其企业客户留存率显著更高——因为驻场工程师能发现工单队列中永远不会浮现的“未知问题”。
