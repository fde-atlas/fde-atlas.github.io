摘要

这份136页指南面向前沿部署工程师，讲解如何围绕冻结的模型构建 harness（代理运行层）。核心论点是模型决定做什么，harness 决定能否做、何时做及结果是否算数。指南提出七层参考架构，引用2026年公开证据：固定权重下 harness 改动使基准提升3至14分，且当年多起代理事故源于 harness 失误。内容涵盖指令、上下文、工具、权限、沙箱、成本、评测与安全审查，附可运行的 Python 教学代码（69项测试）和9份工作表。

要点

  • harness 是冻结模型之外使其成为 Agent 的全部软件层
  • 固定权重下 harness 改动使公开基准提升3至14分
  • 提出控制、指令、上下文、能力、策略、执行、保障七层架构
  • 2026年多起代理事故被归因于 harness 层的失误
  • 附69项测试的 Python 教学代码与9份工作表

测试框架是围绕冻结模型使其成为 Agent 的一切。模型是一个从 token 到 token 的函数；它无法读取文件、运行测试、记住昨天，也无法拒绝删除数据库。这些每一项都是软件，而这些软件共同决定了同一个模型是一个演示，还是客户愿意无人值守运行的系统。

到 2026 年，证据不再是轶事。在权重保持不变的情况下，已发布的测试框架改动使公开基准提升了 3 到 14 分；同一个模型单独运行时产出了一个损坏的应用，而在测试框架内则产出了一个可用的应用；且当年最严重的 Agent 事故都是测试框架的失败：文件中一个权限过大的 token、位于其保护对象爆炸半径内的备份、一个没有门禁的破坏性端点。本指南同时涵盖这两方面，收益与失败，每项论断旁附有一手资料。

全书围绕七个平面组织：控制、指令、上下文与记忆、能力、策略、执行和保障。每一章都指明机制、证据及其失效方式，并以指向 FDEInterviews 中相关概念、问题、课程和论文解析的链接收尾。

  • Harness

  • 拒绝规则

  • 证据阶梯
  • 从最便宜到最真实的验证；只有顶端才算完成。
  • pass^k
  • 在全部 k 次试验中都解决任务的比例；无人值守工作的可靠性指标。
  • 配对比较
  • 对匹配的任务和种子结果的比较，披露缺失评分，并跨任务计算不确定性。
  • 覆盖层
  • 客户拥有的层：指令映射、技能、脚本、oracle、策略、评测。

Harness 工程是围绕冻结的语言模型进行的一切设计，使其成为可运行的 Agent：循环、它读取的指令、它在每一轮看到的上下文、它在会话之间保存的状态、它可以调用的工具和连接器、判断工作是否完成的检查、界定它能触及范围的权限、凭证和沙箱，以及它所做操作的审计记录。模型决定做什么；harness 决定是否、何时、何地、如何做，以及结果是否算数。

已发表的相同模型比较表明，harness 的改动可以显著影响任务成功率和成本。它们的收益取决于工作负载、计算预算和评测方法；这些比较并不能证明 harness 总是比模型更重要。本指南在复现这些比较时保留了其条件，并展示了仅基础设施配置就使一个基准提升了六分，因此它也教你如何诚实地测量自己的 harness 改动。

适合在客户环境中采用、扩展或构建 Agent harness 的前沿部署工程师和平台工程师，以及准备 Agent 和系统设计面试轮次的候选人。本指南假设你能编写生产级软件，并在 Agent 循环中使用过模型 API；但不假设你曾无人值守运行过六小时，或向安全团队解释过相关情况。
