摘要

要点

  • Build to Apply 要求在 Foundry 和 AIP 上构建项目并提交演示视频。
  • 视频须少于 5 分钟，以非公开 YouTube 链接提交，构建期 7-10 天。
  • 六个职位年薪估计 11 万至 17 万美元，四个城市要求 Top Secret 安全审查。
  • 选题需满足四条过滤器：明确用户、周期性决策、合法数据、AIP 有实际作用。
  • 作者建议按“行走骨架”思路七天完成端到端工作流，AIP 步骤占两天。

选择一个客户愿意花钱解决的问题

Palantir 自己的年报描述了 AIP 训练营能在几天内基于真实客户数据交付实际工作流，这正是招聘启事要求你展示的东西。来源 11Palantir Technologies 2025 财年 Form 10-K发布方Palantir Technologies (SEC EDGAR)来源类型公司 SEC 文件 而基于知名数据集做出的通用仪表盘则逊色得多。

以下是我们用来筛选问题的过滤器。这是我们的方法，并非 Palantir 公开的内容。只有通过全部四项，才保留这个想法：

  • 一位具名的用户。 是一个职位名称，而不是“利益相关者”：比如消防检查排班员、拨款专员、仓库规划员。
  • 一个反复出现的决策。 是那个人每天或每周都要做的决定，比如检查哪些站点、优先审核哪些理赔、派哪些卡车。
  • 合法获取的数据。 公开数据最安全：城市的开放数据门户、来自 USAspending.gov 的联邦支出数据，或来自 OpenFEMA 的灾害声明。或者使用你自己生成的名义数据，职位描述明确欢迎这样做。来源 1部署策略师，Build to Apply - 美国政府（华盛顿特区）- Palantir on Lever发布方Palantir Technologies (Lever)来源类型公司职位发布 切勿使用来自雇主或客户的数据。
  • 让 AIP 有真正的工作可做。 语言模型可以在决策过程中读取、起草或推荐某些内容，并由人来审核。如果 AIP 只是给应用做装饰，那就重新选一个。

这些职位是针对美国政府岗位的，因此公共部门用户很自然地契合，尽管我们发现的内容并不要求这一点。以下是对三个初步想法应用的筛选标准：

初步想法问题改写
展示所有联邦支出的仪表板没有用户，没有决策一位拨款官员对哪些资助项目优先审查进行排序
基于城市文件的 AI 聊天机器人决策不清晰一位许可证审查员获得一份起草好的缺陷通知函供其批准
按风险排序的消防检查通过保留它，指名排班员，并添加一份 AIP 简报

这些改写正是策略师在首次客户会议上所做的事情：把“我们想要 AI”转化为一个人、一个决策和一个衡量指标。我们关于利益相关者与成功指标的课程讲解了如何选择客户已经信任的衡量指标，而关于从应用的事件数据构建一个功能的免费问题正是同一思路的缩影。

界定一个可运行的工作流

以消防检查的想法为例。市消防局长办公室的排班员每周挑选要检查的企业。如今这意味着靠电子表格和记忆。你的作品为他们提供一份带理由的排序清单、为每次检查准备的 AI 起草简报，以及据此安排日程的方式。

将其界定为一个：每一层都很精简，并端到端地连接起来。用 Foundry 的术语来说，大致是：

  • 数据输入。 加载该市的检查与违规历史及其营业执照清单，并在管道中进行清洗。记录每一条清洗规则。
  • 用户思考所用的对象。 在本体中将企业、检查和违规建模为对象类型，并建立它们之间的关联。
  • 用户在其中操作的界面。 一个应用视图：排序清单，以及显示每家企业上榜原因的详情面板。
  • 一个可写回的操作。 “安排检查”会记录该决策，使工具能够改变后续发生的事情，而不仅仅是展示数据。
  • AIP 步骤，位于中心。 一个 AIP Logic 函数从系统中读取商户、其检查记录和违规记录，并起草两样东西：给检查员的简短简报，以及针对本次走访的建议关注点（“检查厨房排烟罩灭火系统；它已两次未通过”）。它的修改会被暂存，供调度员审核，而不是盲目应用。Palantir 的 AIP Logic 概述指出，Logic 的修改可以自动应用，也可以暂存以供人工审核。

这就是全部构建内容。没有登录页面，没有第二个用例，没有模型训练。行走骨架的经验教训解释了为什么薄而完整胜过深而局部，以及哪些内容可以造假。在演示中，你可以造假数据量和用户数量。但你不能造假工作流或 AI 输出：如果简报在某些输入上是错误的，就展示一个并说明原因。

一份针对这一周窗口期的计划，由我们自己调整，而非 Palantir 的：

  • 开始之前。 选定用户，找到或生成数据，写出那句话的问题陈述。
  • 第 1 天和第 2 天。 数据导入、清洗，并建模为对象。
  • 第 3 天。 应用视图和回写操作。
  • 第 4 天和第 5 天。 AIP Logic 函数：它读取什么、起草什么、提示词，以及暂存审核。在十个商户上测试它，并记录它出错的地方。
  • 第 6 天。 故意把它弄坏：缺失字段、没有历史记录的商户、一份凭空捏造违规的简报。
  • 第 7 天。 写脚本、录制、回看、提交。之后的一切都是空闲时间，不属于范围。

AIP 步骤之所以占两天，是因为招聘信息表明它会被评估。来源 1Deployment Strategist, Build to Apply - US Government (Washington, D.C.) - Palantir on Lever发布方Palantir Technologies (Lever)来源类型公司招聘信息来源 2Deployment Strategist, Build to Apply - US Government发布方Palantir Technologies (Lever)来源类型公司招聘信息

构建过程中使用 AI

招聘信息明确指出：在你构建的过程中，允许并鼓励使用 LLM、AI 及其他技术工具。来源 2Deployment Strategist, Build to Apply - US Government发布方Palantir Technologies (Lever)来源类型公司招聘信息 在它们最能节省时间的地方使用它们，并检查它们产出的一切。

好的用法。 起草管道转换和清洗代码。解释你不熟悉的 Foundry 功能。生成虚构记录和糟糕的测试用例：没有地址的商户、日期在未来的一次检查。在你写完脚本之后润色它。

需要保持主导的地方。 选择问题、确定排序规则，以及决定 AIP 步骤可以自主做什么。这些正是视频要展示的判断力，所以它们应该属于你。

在视频里说出来。 一句话就够了：“我用了一个助手来起草清洗代码和测试记录，并且我逐条对照原始数据手工检查了每条规则。”这会把 AI 的使用从一个疑问变成良好流程的标志。

谈论时要区分两类 AI。编码助手帮助你完成构建；AIP 是产品的一部分。只有后者才是招聘启事所考察的能力。

这种许可只涵盖构建环节。任何后续的正式上线环节，请先询问你的招聘人员再做假设。

为视频写好脚本

时长限制在 5 分钟以内，所以要争取提前完成留出余量。来源 2Deployment Strategist, Build to Apply - US Government发布方Palantir Technologies (Lever)来源类型公司招聘启事 把视频拍成客户演示，而不是你点击了什么的导览。以下时间安排是我们的建议。

0:00

用户、决策及其原因。

从应用界面开始，而不是 Foundry 的主屏幕。“这是为城市消防局长办公室的调度员制作的。每周他们都要选择检查哪些企业，而如今这靠的是电子表格和记忆。我选择这个场景是因为检查数据是公开的，而且这个决策每周都会重复，所以更好的工具每周一都能带来回报。”

0:30

数据，简要介绍。

“它基于城市的公开检查历史和营业执照运行，通过管道清洗，并在 Ontology 中建模为企业、检查和违规。”展示对象图几秒钟，然后继续。

1:00

实时运行，点名 AIP。

打开排序列表并选择排名靠前的企业。然后说明：“这是 AIP Logic 函数。它从 Ontology 中读取该企业的违规历史，起草一份简报和给检查员的建议重点。在调度员批准之前，任何内容都不会保存。”编辑一行，批准它，并安排检查。展示记录的更新。

2:45

一个决策。

说出评审者会质疑的选择、备选方案及其原因。“我按距上次检查的时间长短和过往违规的严重程度排序，而不是按模型评分，因为调度员必须能向企业主解释为什么他们被选中。我把 AIP 用于简报，因为错误的措辞会在审核中被发现。”

3:30

局限在哪里，下一步是什么。

展示一个失败案例。“对于没有历史记录的企业，简报没有依据可用，所以它会如实说明而不是猜测。如果使用该办公室自己的数据，我会加入执照年限和投诉电话。”以你与该客户的下一步行动作为结尾。

4:15

停止。

这样在时长限制下就留出了余量，以应对页面加载缓慢的情况。

关于录制失误和权衡的准确措辞，take-home 演示视频帖中有逐个镜头的脚本。有三点对这段视频尤其适用：

  • 在未登录状态下检查链接。 提交前，在隐私窗口中打开未公开的 YouTube 链接。
  • 放大画面。 Foundry 的界面信息密集。放大浏览器，直到手机观众能够看清列表。
  • 隐藏不属于你的内容。 关闭标签页、通知以及任何非公开或非虚构的内容。

人们常问的问题

什么是 Palantir Build to Apply？

这是 Palantir 美国政府部署策略师职位的一种申请途径。招聘启事要求申请者构建一个 Foundry 和 AIP 项目并提交演示视频，并表示提前展示作品可以获得加快审核的机会。来源 1Deployment Strategist, Build to Apply - US Government (Washington, D.C.) - Palantir on Lever发布方Palantir Technologies (Lever)来源类型公司招聘启事来源 2Deployment Strategist, Build to Apply - US Government发布方Palantir Technologies (Lever)来源类型公司招聘启事

申请 Palantir Build to Apply 需要安全审查许可吗？

这取决于工作地点。截至 2026 年 9 月，Fayetteville、San Diego、Honolulu 和 Colorado Springs 的招聘启事要求持有至少绝密（Top Secret）级别的有效美国安全审查许可。Washington, D.C. 和 New York 的招聘启事则接受有效许可，或具备获得许可的资格并愿意申请。来源 1Deployment Strategist, Build to Apply - US Government (Washington, D.C.) - Palantir on Lever发布方Palantir Technologies (Lever)来源类型公司招聘启事来源 2Deployment Strategist, Build to Apply - US Government发布方Palantir Technologies (Lever)来源类型公司招聘启事来源 3Deployment Strategist, Build to Apply - US Government (New York, NY) - Palantir on Lever发布方Palantir Technologies (Lever)来源类型公司招聘启事来源 4Deployment Strategist, Build to Apply - US Government (Colorado Springs, CO) - Palantir on Lever发布方Palantir Technologies (Lever)来源类型公司招聘启事来源 5Deployment Strategist, Build to Apply - US Government (Fayetteville, NC) - Palantir on Lever发布方Palantir Technologies (Lever)来源类型公司招聘启事来源 6Deployment Strategist, Build to Apply - US Government (Honolulu, HI) - Palantir on Lever发布方Palantir Technologies (Lever)来源类型公司招聘启事

如何获得用于 Build to Apply 的 Foundry 访问权限？

招聘启事要求你创建一个带 AIP 的 DevTier 账户，并将其用于你的项目。它们指向 learn.palantir.com 提供的速成课程，以及 Palantir Developer Community 供提问，并且欢迎使用公开数据或你自己创建的模拟数据。来源 1Deployment Strategist, Build to Apply - US Government (Washington, D.C.) - Palantir on Lever发布方Palantir Technologies (Lever)来源类型公司招聘启事

Palantir 在 Build to Apply 视频中评估什么？

招聘启事说明你的工作流程必须同时使用 AIP 和 Foundry，并且会根据你将这些能力整合到演示中的效果进行评估。他们还想了解你为什么选择这个问题、你如何使用他们的产品来解决它，以及你构建的解决方案。来源 1Deployment Strategist, Build to Apply - US Government (Washington, D.C.) - Palantir on Lever发布方Palantir Technologies (Lever)来源类型公司招聘启事来源 2Deployment Strategist, Build to Apply - US Government发布方Palantir Technologies (Lever)来源类型公司招聘启事

Build to Apply 视频应该多长？

Palantir 的 Build to Apply 招聘启事要求提交一段 5 分钟以内的演示视频，以非公开的 YouTube 链接形式提交，并在开始构建后的 7 到 10 天内完成。来源 2Deployment Strategist, Build to Apply - US Government发布方Palantir Technologies (Lever)来源类型公司招聘启事

我可以在 Palantir Build to Apply 中使用 ChatGPT 或 Claude 吗？

可以。招聘启事说明在构建项目期间，允许并鼓励使用大语言模型、AI 和其他技术工具。来源 1Deployment Strategist, Build to Apply - US Government (Washington, D.C.) - Palantir on Lever发布方Palantir Technologies (Lever)来源类型公司招聘启事来源 2Deployment Strategist, Build to Apply - US Government发布方Palantir Technologies (Lever)来源类型公司招聘启事

Build to Apply 和 Palantir FDSE 申请是一样的吗？

不一样。招聘启事的职位名称是 Deployment Strategist, Build to Apply, US Government。在 Palantir 的招聘网站上，部署策略师职位所属的团队与前沿部署软件工程师职位不同。来源 1Deployment Strategist, Build to Apply - US Government (Washington, D.C.) - Palantir on Lever发布方Palantir Technologies (Lever)来源类型公司招聘启事来源 7Forward Deployed Software Engineer发布方Palantir Technologies (Lever)来源类型公司招聘启事来源 8Deployment Strategist发布方Palantir Technologies (Lever)来源类型公司招聘启事来源 9Software Engineer - Apollo Platform发布方Palantir Technologies (Lever)来源类型公司招聘启事

我应该为 Palantir Build to Apply 构建什么问题？

选择一个会反复做出某项决策的具体用户，使用公开或虚拟数据，并构建从原始数据到该决策的完整路径，其中包含一个 AIP 环节。一个能端到端运行的窄工作流程比一个宽泛的仪表盘更能展示能力。这是我们的方法，不是 Palantir 公布的规则。
