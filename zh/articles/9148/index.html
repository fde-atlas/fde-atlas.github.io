检索与 AI Agent

基础检索增强生成（RAG）RAG 通过在查询时检索相关段落并将其放入提示词中，使语言模型基于你自己的数据作答，从而让模型依据真实来源而非记忆来回答。它几乎是所有企业级 FDE 部署的默认模式，因此几乎每个循环都会测试它。

基础向量数据库向量数据库将嵌入向量与元数据一同存储，并使用近似索引快速回答最近邻查询。真正的面试问题不是它们如何工作，而是你何时真正需要一个向量数据库，而不是一个库或带 pgvector 的普通 Postgres。

AI 生产环境系统设计

基础从概念验证到生产环境在演示中正确回答了一个问题的笔记本并不是交付物。生产环境是那些不显眼的工作，它将一次性的成功转化为客户无需你在场就能运行、信任和运维的系统。弥合这一差距是 FDE 工作的大部分内容。

基础重试、指数退避与抖动当调用因瞬时错误而失败时，立即重试是最糟糕的做法：它会给本已不堪重负的服务增加负载，并使所有客户端同步形成踩踏。指数退避将重试间隔拉开，而抖动则使客户端去同步化，让它们不再齐步到达。

数据与 SQL 工程

基础SQL 窗口函数窗口函数在与当前行相关的一组行上计算一个值，同时不会将这些行折叠合并，因此你可以在保留每一行的同时进行排名、与相邻行比较或计算累计总和。分析师正是用它在纯 SQL 中回答“和什么相比？”这类问题，而大多数面试官也用它来区分懂 SQL 的人和只懂 GROUP BY 的人。

面向客户的技艺

基础需求挖掘需求挖掘是找出隐藏在客户明确诉求背后的真实问题的工作。客户交给你的请求（“给我们做一个聊天机器人”）几乎从来不是真正的需求；能够挖掘出谁在使用它、成功是什么样子、实际存在哪些数据、以及为什么截止日期就是截止日期的 FDE，才是能交付出人们真正会使用的东西的人。

基础篇界定模糊的问题界定一个开放式提示（“某城市想缩短 911 响应时间”）是一种结构化的操作，而不是灵光一现：澄清输入和约束，大声说出你的假设，划分出最小可用的 MVP，明确你在准确率/成本/延迟之间做出的取舍，并规划失败时的应对方案。直接跳进模型或架构是候选人在模拟轮中被淘汰的最常见原因。

基础篇向非工程师解释取舍高管并不关心你选择了 RAG 还是微调；他们关心成本、上线时间以及可能出错的地方。解释技术取舍意味着把准确率、成本和延迟转化为业务真正要做的决策，用他们的语言把每个选项框定为带有后果的选择，并回答他们最终都会问的问题：为什么 AI 每次给出的答案都不一样，以及为什么这不是 bug。
