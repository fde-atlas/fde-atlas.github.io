基于成果的销售：Pendo 如何停止按小时销售

原标题：Outcome based selling: how Pendo stopped selling hours

Rocketlane · 2026-09-30 · 约 13 分钟读完

摘要

Pendo 按每小时售出的交付量运作，随后客户流失了。基于成果的销售：五个里程碑和一次强制性的需求探索会议。

使用以下工具总结博客

有一个项目，大多数专业服务团队至少都交付过一次：客户购买了 20 次课程，你把 20 次全部交付完毕。每次课程都排上了日历，每份状态报告都是绿色，项目按计划收尾。六个月后，客户流失了。

这正是 Pendo 过去的运作方式，而Gabi Sicher（Pendo 专业服务高级总监）对此毫不讳言：“我们交付了卖出的每一个小时。”交付本身没有问题，问题在于“完成”的定义。所谓完成，指的是课程次数用完了，而不是客户实现了他们购买 Pendo 的初衷。

这也是为什么她在演讲结束时留下了一个值得带回自己团队思考的问题：“完成”到底意味着什么？如果答案是课程次数或小时数，那你只是在出售工时。

Gabi 负责 Pendo 在 EMEA 地区的客户工程和专业服务团队。在伦敦举办的PropelX 2026上，她讲述了 Pendo 大约在两年前如何围绕成果重构交付体系，并坦诚地分享了这一路上出现的种种问题。

多年来，Pendo 的交付一直以产品为先。一次课程讲如何标记页面，下一次讲如何构建引导，团队逐个功能地讲解产品。这些课程他们执行得很好，因为这已成为肌肉记忆，他们对产品了如指掌。但没有任何东西把工作与客户业务真正关心的成果联系起来，而在旧模式下，这种联系是可有可无的。

反馈来自四面八方。专业服务团队离开后，客户举步维艰。销售代表听到了抱怨。客户成功团队对专业服务团队说：“你们没做好自己的工作。”在 Gabi 看来，SaaS 公司的专业服务应该成为增长的杠杆，帮助确保续约，而没有人会因为交付了固定数量的工时而续约。如果产品没有 ROI，那你就没戏了。

基于成果的销售意味着围绕客户想要的结果来规划、打包和定价服务，而不是围绕实现结果所需的投入。在 Pendo，这个结果始终归结为三个 PBO（即积极业务成果）之一：增加收入、降低成本或减少风险。

Pendo 是一个构建在客户软件之上的产品体验平台。它展示用户的行为方式、他们在哪里遇到障碍，并帮助他们发布诸如应用内引导之类的改进来优化体验。因此，在新模式下，每个里程碑、每次课程和每一项赋能都必须与这三个成果之一相关联。任何不符合这一点的都只是无效活动。

大约两年前，Pendo 围绕五个价值里程碑重构了交付体系，并在每次项目中使用统一的语言：

现在服务包按里程碑而非小时来定价。规模更大、更复杂的项目会一直推进到“成果可衡量”，而面向下沉市场、预算较少的小型服务包则可能止步于“可投入使用”。这让项目范围界定和客户期望第一次有了真正的锚点。

Pendo 将一个环节设为强制要求：在每个项目开始时进行深入的使用场景探索会议。这不是可选的，不取决于客户是否恰好提到，也不依赖销售在前几天听到的内容。后续所有工作都必须与该会议中商定的使用场景挂钩。

难点在于突破客户最初通常模糊的回答，找到与真金白银挂钩的业务指标。Gabi 承认团队在这方面仍有困难，但这是不可妥协的，因为“只有先证明客户的 KPI，我们才能证明自己的 KPI”。这与制定一份强有力的客户成功计划的原则相同，只是把它直接移到了起点。

Gabi 的入职（onboarding）示例展示了这条链条。在 Pendo 中，客户可以看到某个用户在界面上点击操作时卡住了。客户在该卡点处发布一条应用内引导，用户第一次就顺利完成，从而更快完成入职。单看这一点，这只是一个小小的行为改变。但规模化之后，更快的入职意味着用户采用更多功能、更早升级、流失更少，而这最终会体现在 PBO 上。如果最后你只能说“一条引导上线了”，那只是活动，而不是客户能带进续约或 ROI 谈话的成果。

转向成果导向并不意味着抛弃团队已有的知识。在旧模式下，每个客户都会获得相同的五场通用会议，内容涵盖打标签、分析、引导和细分。当这些会议用完时，就是“再见”。

在新模式下，有入职使用场景的客户仍然学习打标签，但团队打的是他们入职流程的标签。他们仍然构建细分，但那是新用户细分。他们发布一条入职引导，然后衡量激活率。技能和知识是相同的，只是围绕一个成果重新打包，项目在 Pendo 承诺的里程碑处结束，而不是在任意设定的会议次数处结束。

Gabi 在这里表现出了难得的坦诚。她说，每场大会演讲展示的都是每次都行之有效的干净框架，但几乎没有一场会展示它实际落地推广的过程。变革管理是这件事成败的关键，而 Pendo 也犯了不少错误。

在内部，团队仍然按会议次数做计划，但新模式要求灵活适应客户：在客户需要时对某个主题加倍投入，跳过不相关的内容，或在某个领域投入远超预期的时间。顾问们不断询问是否真的应该在一个客户需要的主题上多花时间（是的，应该）。销售则不断追问：“这个服务包里他们能获得多少场会议？”

Gabi 不得不在整个市场推广团队中反复重新阐述这一点，她说，改变人们对项目合作方式的认知，比任何流程或模板的变更都要困难。

在日历上添加一次需求探索会议，并不能教会任何人如何主持这样的会议。最困难的部分是基线：你需要一个基线来证明成功，但当你向客户索要时，他们往往会说没有。Gabi 的回应是：“事情是这样的。基线是存在的。”它可能只是一个小小的轶事，或埋在报告里的一个数字，但你必须提出不同的问题，并发挥创造力才能把它挖掘出来。

Pendo 的团队了解产品和这套方法论，但这种创造性的业务价值挖掘对他们来说是全新的。一轮网络研讨会式的培训只能起到有限的作用。人们需要练习、实时辅导和持续反馈，就像培养任何一项面向客户的技能一样。

Gabi 说，如果你从她的演讲中只记住一件事，那就是这个：Pendo 把这次转变当作一次流程推行来对待，设置了新的里程碑、新的模板和新的跟踪表，以为一切都没问题。事实并非如此。这是一次思维模式的转变，它的影响超越了交付环节，延伸到整个市场推广团队，甚至延伸到客户。用她的话说：“如果你把它当作流程推行来规划，而不是思维模式的转变，那么旧习惯终将占上风。”对于专业服务领域几乎任何变革管理来说，这都是真理。

“任何告诉你做完一次转型就大功告成的人，都是在撒谎，”Gabi 说。她列出了 Pendo 仍在努力解决的四个问题：

  • 需求探索能力： 在 PropelX 前几周，团队在整个一线团队开展了强化培训，并开始使用 Granola recipes 在客户通话后提供实时反馈，让大家能够持续练习。
  • 退出标准： 行为改变需要时间来衡量，因此很难知道一个项目合作何时真正完成——既不能过早撤出，也不能让它拖得太久。
  • 采购： 告诉采购部门这是基于成果的固定价格，对方的回应往往是“很好，那这相当于多少小时？”，接着就会试图反推出一个小时费率并压价。有时这是一场你无法干净利落地脱身的对话，尤其是在固定价格报价的情况下。
  • 跟踪： Pendo 仍需要更清晰地了解自己在哪些地方过度交付、项目因此耗时多久，以及这对利润率有何影响。

“幻灯片里的模型只是一种愿望，”Gabi 说。要让它成为现实，它必须存在于团队每天打开的工具中，而对 Pendo 来说，这个工具就是Rocketlane。

每个服务包都有一个项目模板，里程碑作为可跟踪的检查点。当 Salesforce 中的交易完成时，计划会自动重塑，调整各阶段以匹配所售内容，并通过Salesforce 集成按角色分配任务。

Gabi 最兴奋的部分是可追溯性。由于每个里程碑都有跟踪记录，团队可以看到每个里程碑耗时多久、项目在哪里停滞，这也是她接下来想深入研究的方向。正如她所说，你不是单纯地推行一套方法论，而是在你的记录系统中推行它。

Gabi 很谨慎，没有夸大整个公司的投资回报率，因为 Pendo 的交付团队仍在建立自己的度量能力。她也承认了其中的讽刺之处：“在 Rocketlane 之前，我们没有任何基线数据。这不是很讽刺吗？”但她分享了一个客户成果。一家财富 500 强的福利平台想要削减其支持成本。

团队找到了摩擦点，上线了应用内引导，并对照基线进行了衡量。支持来电减少了 15%，客户将其价值评估为约 100 万美元的节省，而这正是那种价值故事，让续约和追加销售的谈判变得容易得多。

  • 工时不等于价值。 即使交付了你售出的每一场会议，如果客户从未实现价值，也无法阻止他们流失。
  • 用里程碑取代会议次数。 按客户在价值里程碑上推进的程度来划分套餐规模，而不是按工时。
  • 需求调研是强制性的。 在交付开始之前，将每一次合作都与一个关联真金白银的客户 KPI 挂钩。
  • 这是一种思维转变。 要为交付、销售和采购团队数月的观念重塑做好准备，而不仅仅是推出一个新模板。
  • 把它放进系统里。 一个模型只有存在于团队每天使用的工具中才能发挥作用。
  • 重新定义“完成”。 将你最畅销套餐的“完成”定义为一个里程碑加一个客户 KPI，而不是会议次数。
  • 让需求调研成为强制环节。 在每一次合作中开展用例调研会议，并挖掘基线数据。
  • 现场辅导需求调研。 利用通话反馈和实战演练，而不是一次性的网络研讨会，来培养这项技能。
  • 为采购环节做好准备。 对“这需要多少工时？”这个问题准备好清晰的回答，并不断把话题引回成果上。
  • 跟踪里程碑耗时。 衡量每个里程碑所需的时间，以发现停滞和过度交付。

Rocketlane 是一个由 AI Agent 驱动的专业服务自动化（PSA）平台，专为执行复杂实施的服务团队而打造。

其 AI 层 Nitro 部署了具名的 Agent 来实际完成工作，而不仅仅是标记问题：

  • Migration Agent — 数据准备与转换
  • Workforce Agent — 大规模的可重复配置
  • Documentation Agent — 在通话和邮件中保持项目上下文最新
  • Project Governance — 主动执行交付标准
  • Nitro Signals — 在账户风险升级之前将其暴露出来

核心区别在于：Nitro 的 Agent 会产出交付成果或执行关卡。大多数平台只是提供建议，而 Rocketlane 付诸行动。

使用 Rocketlane 的团队能更快交付项目，通过更严格的治理挽回利润，并在无需按比例增加人手的情况下扩展交付规模。

  • 成果 vs 产出：将客户成果转化为可衡量的成功：David Dixon 的逆向推导框架，用于证明客户成果。
  • 实施合作伙伴管理：100 万美元保障承诺如何重塑我们的部署服务：Fin 如何围绕成果保障重构项目范围界定与交付。
  • 2026 年专业服务趋势：为什么交付是新的护城河：Sri Ganesan 谈为什么资源利用率作为专业服务指标正在失去意义。

专业服务中的基于成果的销售，是指围绕客户想要实现的业务结果来打包、界定范围和定价服务，而不是固定的会话次数或小时数。在 Pendo，每一次客户合作都绑定一个客户用例，并以积极的业务成果来衡量：增加收入、降低成本或减少风险。它与基于成果的计费密切相关。

价值里程碑是以客户结果而非投入时间来定义进展的检查点。Pendo 使用五个里程碑：确定用例、完成安装、具备运营条件、激活体验、衡量成果。服务包的规模取决于包含多少个里程碑，这是将服务产品化的一种实用方式。

用例探索会议会在交付开始之前，将客户合作与一个与真实金额挂钩的客户 KPI 联系起来。没有这一步，专业服务团队就无法设定基线，也无法在项目结束时证明成果。Pendo 将这一会议设为每次客户合作的必经环节，而它作为结构化启动会议的一部分效果最佳。

据 Pendo 的 Gabi Sicher 所说，最大的挑战包括：改变内部团队和销售对客户合作的思维方式、培养探索能力、设定明确的退出标准，以及应对那些仍试图把固定价格换算回小时费率的采购团队。如何追踪超额交付及其对项目计费的影响，则是另一个尚未解决的问题。

即使客户说他们没有基线，专业服务团队也应该深入挖掘，可以通过不同的问题、小的案例故事或现有报告来寻找。Pendo 发现基线几乎总是存在的，而且在记录系统中追踪里程碑，使衡量结果成为可能，例如支持来电减少 15%，这是价值实现时间的明确信号。

积极业务成果（PBO）是 Pendo 用来锚定每一次客户合作的三个结果：增加收入、降低成本和减少风险。每个里程碑和每项赋能工作都必须与其中至少一项挂钩，这使交付始终聚焦于客户所购买的价值交付。

Pendo 按专业服务套餐包含多少价值里程碑来划分规模。更大、更复杂的项目会一直做到“成果可衡量”，而较小的下沉市场套餐可能止步于“运营就绪”。这为客户提供了明确的承诺，而无需将价格与会话次数挂钩，并使专业服务定价更具可预测性。

采购团队常常试图从固定的、基于成果的价格反推出小时费率，以便据此砍价。Pendo 的做法是不断把对话拉回到成果本身，解释价格涵盖的是达成里程碑，而与工时无关，同时也接受有些对话无法完全避免。清晰的 SOW 条款会有所帮助。

新的里程碑、模板和跟踪器很容易推出，但如果人们的思维方式不改变，他们仍会按会话和工时来规划。在 Pendo，顾问、销售代表和采购人员都默认使用会话次数，因此团队不得不反复重新界定项目框架。如果只把它当作流程上线来对待，旧习惯就会占上风。

Pendo 为每个套餐使用一个 Rocketlane 项目模板，并将价值里程碑作为可跟踪的检查点。当 Salesforce 中的交易成交后，计划会调整其阶段以匹配所售内容，并按角色分配任务。里程碑跟踪可以显示每个阶段耗时多久、项目在哪里停滞，为 Pendo 提供了此前缺失的交付可见性。
