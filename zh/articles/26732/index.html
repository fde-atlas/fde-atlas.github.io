重写

100 个答案

核心产品经理工件与流程正在如何为 AI 时代被重写。

  • 当没有人在场批准时，AI Agent 应如何处理权限？在允许、询问和阻止之外增加第四档：搁置。Agent 完成工作，在风险步骤前停下，并报告等待中的事项。
  • 对话是否正在取代应用界面？是的，作为工作的起点。Salesforce 把它的 CRM 放进了 Claude，12 周后 Microsoft Copilot 也这样做了。应用界面仍保留为检查工作的地方。
  • 2027 年设计师的作品集应该展示什么？工具熟练度曾是敲门砖，这道门槛已经移动了。作品集的问题如今关乎判断力：构建哪个工具，以及何时把它扔掉。
  • 如何审计按解决次数计费的计量系统？先读争议队列，设计争议处理路径，再抽样那些沉默的案例。一条 48 小时沉默规则每周产生了 200 多个争议案例。
  • 应该聘请有经验的前沿部署工程师，还是培养新人？取决于站点。Boaz Francis 在新的 Wonderful 站点聘用有经验者，在成熟站点聘用早期人才。先为站点写下四行说明。
  • 当 AI 生成初稿时，设计评审应如何改变？Copilot 采用者每月多花 1.4 小时协作来审核 AI 输出。把评审拆开：AI 发现，人来排序和淘汰，并把理由记录下来。
  • 是否应该用一个用你的决策方式训练出的 AI Agent 来交接你的角色？Marco Di Santo 构建了一个能按他的方式回答决策问题的 Agent。用它来传递理由，并为每个决策指定新的负责人、翻转条件和日期。
  • 应该由人审查 AI Agent 的工作，还是让它独立运行？Nielsen：在 420 项研究中，人加 AI 输给了单独使用更好的一方。在我的扫描中，42 次运行里有 13 次需要人工介入一次，直到提示词中的一句话终结了这一现象。
  • LangChain 评测驱动三步中，哪一步属于产品经理？LangChain 的评测驱动开发有三个步骤。产品经理拥有第一步——“好”的规格说明，并在第三步阅读数据行。
  • Uvik 的 50 票基准是否证明了规格驱动开发有效？部分成立。规格工作流合并了 80% 的大型工单，而无规格时为 50%，但在修复 bug 上没有回报。完整性胜过框架：89% 对 60%。
  • 如果没人阅读，研究资料库还值得维护吗？Nielsen 称未被使用的研究是昂贵的归档。在每个已上线的修复下保留一条带日期的论断：42 份扫描报告显示哪些论断最先失效。
  • 当用户是 AI Agent 时，你该如何设计产品？Ravi Mehta 的 UX 定义现在包含了 Agent。Agent 永远看不到屏幕，所以要阅读它的请求，并测试它能否在一次请求中获得事实。
  • 如何测试语音 Agent 界面中的话轮转换？Sierra 的 Mossy 在收到一条评论后用两个状态修复了话轮转换。用一条评测标准来测试：一个陌生人在一秒内说出该状态，通过或不通过。
  • 当 PM 和工程师都能生成界面时，设计应该负责什么？所有权在于谁来做最终裁决，而不是谁产出工作。设计负责约束、范围、评测标准、拒绝逻辑和错误路径。PM 负责问题和顺序。
  • 为什么 PM 职位空缺在上升，而 PM 招聘却在下降？TrueUp 显示，自 2023 年以来 PM 空缺增加了 56%。外部 PM 招聘下降了 18%。招聘要求变了：LLM、Claude 和评测位居技能列表前列。这意味着什么。
  • 设计是否必须胜过纯 AI 版本才能上线？买家为纯 AI 游戏支付的价格比业余者的游戏高出 27%。在设计上线之前，用真实用户而非模拟用户，将其与纯 AI 版本进行对比测试。
  • 在签署合同之前，你应该问 AI Agent 供应商什么问题？Marco Di Santo 的五个问题正是该问的五个，而且销售能凭记忆回答。请他们提供两个季度前上线的一个账户在第 60 天的页面。
  • Ramp 的 7,000 个非工程师 PR 对 PM 意味着什么？Ramp 的非工程师在一个季度内提交了 7,000 个 PR。当构建自行到来时，PM 的一天就变成了一连串等待决策的队列。
  • 对于 Agent 未经询问就做出的决策，你该怎么办？Nielsen 报道的一项研究列出了 Agent 在运行中途未经请求做出的决策。对每个决策回答一次，然后将其作为规则或参数写进需求简报。
  • Marty Cagan 的产品岗位三角色模型中，有前沿部署工程师的位置吗？Cagan 按运营模式将产品角色分为三种定义。FDE 不属于其中任何一种，其需求增长了 2,100%，而评测工作归属于看到案例的人。
  • 当 AI Agent 来挑选功能时，功能发现是否已经终结？Elena Verna 说 AI 使功能发现变得不再必要。它转移到了 harness 中，成为工具列表，同样存在采用曲线和 token 账单。统计调用次数。
  • 对 Agent harness 的更改是否应被视为重新设计？Jakob Nielsen 说应将模型更改视为重新设计。用户能感受到的变化是 harness：周四的一次提示词削减。每次 harness 提交都要附上六行说明。
  • Salesforce 在招聘 AI PM 时看重什么？Salesforce 的 Agentforce 部门招聘 AI PM 时看重两项技能——原型设计和评测，以及一个首要特质：你能否说清楚“好”是什么样子？
  • 最后一英里的设计反馈是否应该回流到设计系统中？Luke Wroblewski 的 Agent 借助设计系统能把屏幕做到 90% 正确，并在屏幕上补完其余部分。记录修复，并在第三次出现时将其提升进设计系统。
  • 什么是修复率，为什么设计应该负责它？修复率统计用户重新提问、换一种说法提问，或表示无法理解 AI 回答的频率。它是针对无法预测的输出的实时信号。
  • 当解决率下降时，Agent 控制台应该首先回答什么？Sierra 的 Agent Studio 能在一次对话中回答解决率为何下降。第一个答案必须是哪个解决率。我给出的 48 小时定义在 98% 的情况下成立。
  • 合成用户能取代真实用户测试吗？不能。数字孪生可以填充“在哪里”这一列：卡点和边缘情况。但只有被问到的真实的人才能填充“感受”这一列。我的引导 Agent 上线时这一列是空白的。
  • 当 AI Agent 会读取设计系统时，如何保持设计系统的时效性？当 Agent 在每次调用时都读取设计系统时，要限制始终加载的内容，在每条规则旁写明原因，在模型升级时进行修剪，并对每周的差异进行签署确认。
  • 语音 Agent 应如何复述更正后的姓名或号码？以差异的形式：旧值、新值，以及档案中记录的是哪一个。Sierra 发现只有 24% 到 37% 的复核错误值会被修正，所以要让替换过程可以被听到。
  • AI Agent 的写入操作可以在有人查看之前保留多久？在 SaaStr 的两次 Agent 删除事件之后，Jason Lemkin 命名了副本。没人命名的是时间窗口：写入操作在被指定读者看到之前的分钟数。
  • 什么取代设计产物，作为判断已经发生的证明？设计决策记录。一页纸，四个字段：决策本身、背后的约束、放弃了什么，以及能证明决策错误的信号。
  • 设计应该向工程团队交付什么来取代设计稿？当原型以生产形态的代码交付时，设计向工程团队交付的是行为规格，形式为测试行：硬性失败项、分级底线、失败夹具。
  • 如何在上线前衡量人机团队？Jakob Nielsen 的联合认知系统门槛评估准确性、速度和错误恢复。再加上第四列：与纯人工相比的拒绝率。
  • 原型仪表盘除了采用率还应衡量什么？Reddit Proto 有 700 个原型和 100% 的采用率。它的仪表盘需要两列：已交付（注明评审人）和已落地（注明行为发生了改变）。
  • 当客户在合作中途更换模型提供商时，什么必须随之迁移？界面中有两项设置需要迁移。每个界面的评测阈值必须在切换后保留，在列出回退方案之前运行一次，并在回退触发时再运行一次。
  • 通宵运行的 Agent 第二天早上应该向你展示什么？在下一次会话中展示三行内容：它做了什么、它正在做什么，以及你还能撤回什么，并在会话间隔旁标注撤销窗口。
  • 合作结束时，前沿部署工程师会带走什么？运营知识，Milos Mandic 说，其中约 70% 应该转化为产品。不要问什么被带走了。在三个时间点获取交接包。
  • 谁来为 AI 生成的原型中的决策签字？AI 原型承载着无人做出的选择。PM 认可哪些内容回答了问题，设计认可行为，而模型做出的选择则在等待一个责任人。
  • 为什么设计师在交付阶段较少使用 AI？一项针对 443 名设计师的调查显示，AI 在探索阶段的使用率为 72%，在交付阶段为 41%。Nielsen 指出，后期的错误会被发布出去。之所以被发布，是因为没有人事先编写失败清单。
  • 设计师应该成为 PM 原型的质量关卡吗？不应该。以人作为关卡会把吞吐量限制在一个人能评审的范围内。设计编写评分标准，评分标准就是关卡，PM 原型到达时已带有评分。
  • 如何判断产品策略是否在起作用？不是看团队投入了多少精力。当策略在本周产生了一个有代价的“不”时，它才在起作用。为这些“不”记一本账。
  • 什么是 Figma Specs，它为设计团队带来了什么改变？Figma Specs 是一个用于团队设计语言的 Markdown 编辑器，可供人和 Agent 阅读。它将设计的核心产出从界面转移到了规格说明。
  • 2026 年 SaaS 公司如何为 AI 收费？在 41 个软件品牌中，21 个采用席位加 AI 点数的模式，只有 4 个按成果收费。为什么点数模式胜出，以及应该向任何供应商询问的三个数字。
  • 如何衡量一项研究发现是否真正落地，而不仅仅是发布？用代码本对下一季度的用户评论重新编码，并报告哪些主题减少了。为什么 fixfluence 需要第二个动词，附 31 通电话与 3 通电话的主题对比。
  • 一个常驻 AI Agent 的章程应包含什么？除了职责之外的三行内容：一个时段、一条预算科目和一个读者姓名。来自一个机队的经验：39 个 Agent 中有 13 个在同一时间窗口内触发，而 13 个从未被阅读。
  • AI 试点的成本估算应包含什么？四行内容：每个已回答问题的成本、乘数及其触发条件、每个乘数旁的责任人姓名，以及三个复查日期。总有一个数字会被增长超越。
  • 什么时候应该对团队进行新 AI 工具的培训？在每个人的第一周。提示词习惯大约在 5 次会话内定型，因此在上线数月后才培训，等于要求人们先忘掉已养成的习惯。
  • 产品构建者只是会使用 AI 的 PM 吗？不是。构建者要对生产环境中的某些东西负责：一套评测集、每次请求的成本和一个回滚条件。每 8 个 AI PM 职位中只有 1 个提出这一要求。
  • 产品经理是否应该在前沿部署工程中轮岗？Atlassian 明确要求每位 PM 都应成为 FDE。可以去体验一番，但首先要指定一位 PM，在两周内向一线交付一份书面决策。
  • 谁应该批准对 AI Agent 规则的例外？第二个 Agent 可以标记并修复违规。但每一个被批准的例外都应由人来阅读，并按规则计数。我曾按每周 50 个例外建模，结果得到了 600 个。
  • 当高管支持者离开时，定价迁移会发生什么？除非承诺是为这个职位而写的，否则它会在低谷期被重新争论。我的 18 个月计划列出了四个人，却没有为其中一人离开留出预案。
  • 基于结果的定价是个神话吗？Scott Woody 说要为产出定价，而不是为结果定价。一张已解决的工单是可以计数的，但它每周仍引发 200 起争议案例。选择你承受得起的争议。
  • 自动评测工具应该替你选择第一个评测吗？不应该。让它找出候选失败案例，然后阅读五十条输出，按数量乘以客户成本排序。我的一个功能在平均值上通过了，却在五分之一的案例中失败。
  • 客户数字孪生能在发布前告诉你什么？你的问题和流程是否站得住脚。而不是人们对一个尚不存在的功能会有什么感受。我的引导 Agent 就是数字孪生会漏掉的情况。
  • 应该发布一个有 3% 幻觉率的 AI 功能吗？不要只盯着那 3%。找出是哪个流量切片承载了它，然后指明第六周由谁来衡量它。两个发布数字、五分之一的流量以及 89% 到 61% 的变化说明了原因。
  • 原型工具应该报告什么，而不是“已创建的原型数”？不是已创建的原型数。应报告结果分布（已发布、已替换、已砍掉）以及砍掉的中位时间。Stripe 的 Harbor 有 12,000 个原型；这里缺的是那一个指标。
  • 当 Agent 跨多个界面运行时，谁拥有观测记录？四个界面共用一条记录，这是对读取方式的一种主张。无论哪个界面保留了最丰富的本地追踪，它都会成为真正的记录系统。
  • llms.txt 足以让网站对 AI 助手有用吗？llms.txt 是索引，不是内容。Anthropic、Vercel 和 Supabase 都发布了它。780 多个这样做的网站仍然缺少什么，以及接下来该发布什么。
  • 为什么精美的模型图不再是信念的证据？精细度曾是衡量工作背后思考深度的代理指标。AI 打破了这一点，所以如今看起来最完成的作品反而得到最肤浅的评审。
  • 你应该做底层的平台，还是上层的应用？Glean 和 Alation 都退回到了底层。你无法同时拥有一个日常习惯又做中立的管道。用续约机制来决定。
  • 当 AI 生成界面时，设计师该做什么？绘图变便宜了，决策没有。设计师的工作从产出制品转向定义行为：约束、范围、评分标准，以及错误路径。
  • 当交付物消失时，如何为 PM 定级和晋升？当 AI 崩塌了 PM 晋升所依赖的文档时，定级就必须衡量判断力。从 L4 到 Principal，每个层级什么才算证据。
  • 落地一个产品与构建一个产品，各需要多少成本？构建成本崩塌了，落地成本没有。每种成本在哪里产生、由谁支付、何时发生，以及为什么组织资助便宜的那一半而让另一半挨饿。
  • “落地产品”而不只是“交付产品”意味着什么？交付是代码上线，发布是对外宣布，落地是持久的行为改变并实现价值。定义与四种失败模式。
  • 在组织中，谁负责产品的落地？落地处于产品、市场、销售和客户成功之间的缝隙地带，各方在用户采用之前就交接了。为什么这不是任何人的职责，以及三种解决方案。
  • 为什么 Whatnot 用这么少的产品经理运营产品？Whatnot 用约 22 名资深产品经理运营一个 GMV 达 80 亿美元的市场，从 31,832 名申请者中只录用了 1 人，并将产品经理映射到问题而非小组。永远不要默认招聘。
  • 为什么在 AI 时代产品经理的职业阶梯正在崩塌？产品经理的晋升阶梯以产出物作为晋升依据。当 AI 摧毁了文档，它也就摧毁了这个阶梯赖以校准的货币。
  • 如果现在构建变得廉价，产品构建者的真正约束是什么？构建不再是瓶颈。2026 年 CPO 报告显示，上市速度成为 CPO 面临的首要挑战。约束已转移到落地，而非发布。
  • AI 会淘汰产品总监吗？AI 不会先淘汰产品经理或产品 VP。它暴露的是产品中层管理——即那些主要工作是上下传递信息的总监和 Group PM。
  • 持续探索适用于 AI 原生产品吗？Teresa Torres 的持续探索适合以人为中心的 SaaS，但对 Agent 产品失效。替代方案是间歇式探索：60/40、三周冲刺。
  • 如何招聘构建型产品经理？旧的产品经理招聘流程考察的是演示能力和框架，而这些 LLM 已经很容易伪造。招聘应看候选人在四小时内能交付什么，而不是他们怎么说。
  • AI 如何改变产品经理与工程师的比例？1 比 7 的产品经理比例从来不是关于工程师的。它衡量的是一个产品经理能指挥多少构建产出。AI 提高了每个工程师的产出，打破了这个算式。
  • AI 如何改变产品经理的角色？AI 优先的公司招聘的是产品构建者，而不是规格撰写者。产品经理角色现在奖励六项技能，其中快速原型和贴近客户位居前列。
  • 敏捷已死吗，什么将取代它？敏捷是应对构建缓慢且昂贵的权宜之计。AI 消灭了这两个前提条件。取代它的不是瀑布式开发，而是规格优先的循环。
  • 成为产品构建者是否意味着要写代码？不。产品构建者从来不是指产品经理要学 React。它是指消除决策与制作之间的距离，并消灭协调税。
  • AI 优先是产品决策还是工具决策？AI 优先是产品决策，而不是工具决策。使用 AI 只是把旧流程跑得更快。AI 优先则是把流程重建为仿佛 AI 从第一天就存在。
  • 产品管理死了吗？产品管理没有死，它逃出了产品团队。每个部署 AI 工作流的职能，在结构上都是一个需要构建者的产品团队。
  • Scrum 对 AI 原生团队来说过时了吗？Scrum 已经过时，市场正在用招聘投票。替代品有一个名字：一个四到六人的构建小组，没有仪式税。
  • PM 作为翻译者的角色死了吗？十五年来，PM 是专业的中间件，把客户输入重新格式化成给工程师看的演示文稿。AI 和 MCP 剥掉了三层翻译。
  • PRD 死了吗？PRD 死了，因为构建变得廉价。一个可点击的原型、一页纸文档、一段 5 分钟的 Loom 视频和一次 30 分钟的对话取代了它。
  • PM 和产品构建者有什么区别？PM 交付文档并执行交接。产品构建者交付原型、编写评测，并端到端地负责一个产品界面。逐条对比的区别。
  • PRD、规格说明和简报各应包含什么？PRD 把三件事都做得很糟。把它们拆开：简报承载“为什么”和押注，评测承载承诺，原型承载解决方案。
  • 你应该自称 AI PM 吗？不应该。AI 原生描述的是工具熟练度，而不是决策所有权，而且它无法通过简历筛选。说出你负责的成果，比如我负责激活率。
  • 你应该合并 PM 和产品负责人这两个角色吗？合并 PM 和产品负责人治的是症状，不是病因。真正的解法是砍掉 Scrum 框架——PO 这个角色本来就是为它而设的。
  • 取代 PRD 的三个工件是什么？一页纸简报、一次性原型和评测。每个都承担 PRD 做得很糟的一项职责：记忆、对齐和承诺。附模板。
  • 2026 年董事会期望产品部门交付什么？2026 年 CPO 的董事会演示文稿只有七页：成果账本、单位经济、评测记分卡、Agent 清单、周期时间、人头产出比、下行风险。
  • 什么是一页纸简报，里面应该写什么？一页纸简报用六个部分取代 PRD：问题、证据、附原型链接的解决方案、指标、风险和所需支持。
  • 什么是 AI 产品工程师？AI 产品工程师集 PM 战略、设计和工程于一身，AI 放大每一项能力。过去需要三人团队做的事，现在一个人就能完成。
  • 什么是产品组织的双轨转型？双轨转型让传统 SaaS 及其 Agent 原生的继任者按两个时钟运转：两种节奏、三类人才、六个 CEO 指标、三项例行机制。
  • 什么是服务即软件？在服务即软件模式中，AI Agent 完成工作，人类负责审查和处理边缘情况。它改变了 UX、可靠性、定价以及 PM 角色本身。
  • 什么是基底优先工程？基底优先工程意味着工程师构建的是让非工程师能够安全交付产品的平台，而不是功能本身。它由四个部分组成。
  • 什么是 AI 噪音税？AI 噪音税是三种模式带来的信誉成本：吹嘘超能力的 LinkedIn 帖子、生硬附加的 AI 侧边栏，以及 PM 争论原型制作会破坏同理心。
  • 什么是 AI 产品运营模式？AI 产品运营模式保留了授权团队和持续探索，但 Agent 消灭了 PRD，并将探索周期从四周压缩到四天。
  • AI 产品公司的组织架构是什么样的？AI 编程工具提升了开发者的产出，但组织速度却原地踏步。新的组织架构要修复三个层面：采用、评审，以及中间的协调层。
  • 产品构建者的职级阶梯是什么样的？一个从 L4 到 Principal 的四级 Builder PM 阶梯。五个维度随职级扩展，但运营模式不变：原型、评测、用户验证。
  • 到 2028 年什么将取代产品组织？针对 2028 年年中产品组织的十条可验证预测：团队中位数六人、第一周出代码、评测成为首要技能、混合定价、APM 项目消亡。
  • 2026 年的 PM 职位描述应该是什么样的？我审计了 200 份 PM 职位描述，其中 196 份放在 2022 年也毫无违和。死掉的 JD 的四个特征、活着的 JD 的四个特征，以及如何重写。
  • AI 正在杀死哪些软件品类？三股力量正在瓦解软件品类：搜索变成答案、工具变成 Agent、订阅变成成果。一份按类别划分的 PM 实战指南。
  • 为什么在 AI 时代分发胜过产品？AI 让产品构建变得廉价，因此产品质量一个下午就能被复制。分发——渠道、品牌和安装基础——是仅存的护城河。
  • AI 会取代产品经理吗？不会，但 AI 会取代大多数 PM 80% 的日常工作。幸存的 20% 是客户同理心、判断力、领导力和愿景，而这将变成全部。

淘汰清单

62 个答案

该停止做什么，以及如何执行淘汰，让组织真正放手。

  • SaaStr 用 1.5 个人和大约 20 个 AI Agent 完成销售。销售 Agent 归谁管，CPO 还是 CRO？CPO 的组织像产品一样交付销售 Agent。CRO 负责营收数字和人工判断决策。一份清单列明每个 Agent 的负责人。
  • 平台协同效应和运营切换成本有什么区别？平台协同效应需要一项集成才能成立。切换成本则独立存在。Mailchimp 的交易展示了把它们按同一价格定价时会发生什么。
  • AI 产品还应该提供免费试用吗？应该，前提是试用有价格。设定金额上限、固定使用廉价模型，并限制每次请求的步骤数。Claire Vo 在遭遇代币欺诈后取消了免费试用；这里是另一种做法。
  • 当 Figma 称设计为差异化优势、设计类开放职位处于历史低位时，设计团队还应该向 CPO 汇报吗？应该。在每 3.8 个开放 PM 职位对应 1 个设计职位的情况下，大多数初稿来自设计团队之外。质量门槛必须在 CPO 负责的发布流水线中运行。
  • 任务型 Agent 和目标驱动型 Agent 有什么区别？任务型 Agent 执行一条命令。目标驱动型 Agent 持有一个目标，按计划运行，并交付一份供你阅读的结果。区别在于产品本身。
  • 按合并 PR 计算的成本是编码 Agent 的好指标吗？归因不错，但标题错了。这个计数止步于合并。评审工时、留存下来的内容以及没有 PR 的工作都在它之外。我上线的 39 个 Agent 中有 13 个从未被使用。
  • 当 AI 设计满足 99% 的需求简报时意味着什么？据 Nielsen，15 个模型在 160 份设计简报中超过 90% 达标，人类为 98%。一个人人都能通过的检查只是底线。我那套永远打 4 分（满分 5 分）的评分表也一样失效了。
  • 当 Agent 一周内预订了 4 次 Uber 时，ChatGPT 的业务档案该由 CPO 还是 CMO 负责？在一个 3.2 亿次行程的星期里，Agent 预订了 4 次 Uber，而 ChatGPT 现在有了业务档案、信息流和 Agent。CPO 的团队负责它们，原因如下。
  • 规格驱动开发（IDSD 或 SDD）值得吗？SDD 和 IDSD 是同一套方法论，只是贴了不同的标签。两者都跳过。原型就是规格，评测就是验收测试。
  • 应该由单一基准测试分数决定 AI Agent 是否上线吗？Salesforce 的 EGI-Bench 将六项能力加权成一个分数，而没有任何模型在全部六项上都领先，所以权重决定了赢家。上线前应基于 200 行切片评测。
  • CPO 应该汇报什么来替代 Agent 交互次数？monday.com 统计了 7500 万次外部 Agent 请求和 600 万次 Agent 交互。应该改为汇报经核实的已完成任务，覆盖每条路径，并附上每项任务的成本。
  • 节省的工时应该作为 AI 采用度指标吗？Atlassian 的开发者中，认为 AI 每周节省 10 小时以上的比例从 68% 降到了 26%。节省的工时是自我报告。应该统计署名交付的成果和落地为行为改变的成果。
  • PM 与设计师的比例是衡量设计健康度的正确数字吗？Lenny 的报告显示每个设计岗位对应 3.8 个开放的 PM 岗位。这个比例衡量的是绘图产能，而 Figma 的试用改变了绘图本身。应该用评分表来统计界面。
  • 客户成功应该向 CPO 汇报吗？一半应该。HubSpot 的 Agent 一个季度解决了 200 万个问题，Atlassian 的 FDE 缩短了从请求到交付的时间。采用度如今就是产品工作。
  • 在前沿部署项目中，应该由客户选择记分卡吗？John Cutler 建议原型化三种项目评分方式，让客户选择。而在 FDE 项目中，评分标准在签约时就已固定。客户只能选择页面。
  • Canva 的“单一产品组织”对谁向 CPO 汇报意味着什么？Canva 在一次涉及 22% 员工的重组中合并了产品、增长和平台。下一步：设计、PMM 和 FDE 也应向 CPO 汇报。
  • 应该用“给我惊喜”来指示设计 Agent，然后挑选你喜欢的方案吗？Figma 的工作流实验室用“给我惊喜”作提示，挑选设计师喜欢的选项，最后才写规格。在提示之前先写下三条通过或不通过的判定标准。
  • Slack 反馈频道是 FDE 到产品的闭环吗？Salesforce 的 Agentforce 组织将 FDE 反馈汇入一个带两个标签的 Slack 频道。频道只是一个收件箱。闭环是一个数据包、日期和一条回复的决策。
  • 硬性预算上限是 AI Agent 合适的成本控制手段吗？Salesforce、Snowflake 和 Atlassian 在一周内都上线了 Agent 预算上限。上限是在支出发生后才触发。重新评估那个设定成本归集键的变更。
  • 一个 PM 技能包应该自动激活多少项技能？Paweł Huryn 的技能包自动激活了 43 项技能中的 39 项。Figma 的 PM OS 有 31 项。在我的技能库中，51 项里有 30 项没有作者。默认自动关闭，统计触发。
  • AI 原生 CSM 应该亲自修复客户的 Agent 吗？不应该。CSM 应按层分诊，指明客户侧持有修复密钥的人，并了解召回规则。亲自修复会让 CSM 变成第二个 FDE。
  • AI 推理成本应该记入损益表的哪个位置？服务成本应归入收入成本，并按功能拆分。Anthropic 的 S-1 将算力记为运营费用，结果其毛利率读起来是 85% 或约 45%。
  • 设计负责人每个月应该亲手构建什么？不是一个组件，也不是一个提示词。而是为一个真实上线界面构建一套约束集，配上 20 个真实案例，并把界面覆盖率作为你要汇报的数字。
  • 当 AI 能做入门级工作时，产品组织还应该招聘初级 PM 吗？应该，而且要有意识地招。Anthropic 的初级技术岗招聘比例从 27% 降到 9%，PM L1 占比降到 11%。停止从底层招聘的 CPO 会失去人才储备。
  • 点赞和点踩的反馈应该用来训练你的 AI 模型吗？点赞让 GPT-4o 变得谄媚。一次点赞只是对整个输出的一比特信息。在任何训练开始之前，先把它关联到评分维度、输出 ID 和数据切片。
  • 企业应该如何处理来自个人 AI Agent 的流量？Salesforce 表示个人 Agent 每隔几小时就会调用一次；应该用企业 Agent 来应对它们。在用户看到的 URL 上发布它们正在轮询的字段。
  • AI Agent 框架应该自建还是购买？Ramp 用六周构建了 Laminar。构建成本这一栏坍缩了，落地成本没有。备忘录之前的三行：客户、追踪读取器、值班安排。有一项空白就意味着购买。
  • 评测框架应该由 CPO 还是 CTO 负责？双方都要，但要清晰分工。CTO 负责运行和执行评测的平台。CPO 负责评测所依据的标准。两者共同签署进入生产的门禁。
  • AI Agent 交付给团队之后，谁应该负责修复它？使用它的团队：一名有响应时限的指定负责人、一个带撤销功能的版本化层，以及一套上线评测集——构建者保持其冻结状态，并在每次变更时重新运行。
  • 如何衡量审查 AI Agent 输出的成本？不能只看审查时间。在生成的输出旁边，统计无人打开的输出数量。我的 39 个 Agent 中有 13 个产出的成果从未被任何人阅读。
  • AI Agent 的发布应该以互动率作为主打指标吗？不应该。互动率对任何访客无法绕过的聊天机器人来说都成立。主打指标应该是在明确定义下的解决率，用三种方式评分，再加上转人工次数。
  • CEO 应该用 AI 方面的什么标准来考核 CPO？不是上线了多少 AI 功能或节省了多少小时。而是每项 AI 押注的增长指标、每个成果的成本、产品团队自身工作方式的改变，以及每季度砍掉一个项目。
  • 长时运行的 Agent 应该按最终成果定价吗？不应该。把终点线保留为续约数字，只对客户愿意签字的那一段定价。一个定义曾带来每周 200 起争议；而接力赛每次交接只有一起。
  • 当原型变得廉价时，CPO 应该负责什么？不是路线图。而是运营模式：底层基座、倾听回路、评测门槛、以 Product Builder 为基本单元的组织形态，以及利润率。
  • 让人在回路中就能让 AI Agent 安全吗？只有当这个关卡很少触发、携带上下文、并且被度量时才成立。当批准率超过 95% 或每次决策少于 2 秒时，人其实已经离开了回路。
  • 按每次调用定价是比较 Jev 这类决策模型的正确方式吗？不是。按次定价是你选对时的付出。应该按选错后挽回的成本给每个分支排序。我的分类器准确率从 89% 掉到了 61%。
  • 既然 AI Agent 能在 20 分钟内构建一个内部工具，你就应该去建吗？不应该。构建时间已不再是筛选条件。我在 80 天里批准了 39 个廉价的 Agent 构建，其中 13 个成了无人问津的孤儿项目。应该以负责人、工作流程和停用日期作为门槛。
  • 产品经理应该隐藏进度缓冲吗？不应该。按 70% 的产能做计划，并且明说。隐藏的缓冲对每个利益相关者只能用一次。为每个日期公布 ETA 偏差，并报告是什么消耗了缓冲。
  • AI 能把支持成本中心变成收入引擎吗？只有当未被满足的需求就在自动化工作旁边时才行。IKEA 具备这个条件：8,500 名员工、一个 13 亿欧元的渠道。大多数支持队列并不具备。
  • 承诺消耗量是衡量 AI 采用的好指标吗？不是。它衡量的是相对于承诺的支出。我有 12 个账户支付着承诺的最低额度，实际用量却低于最低额度。应该改为报告所购买的结果。
  • SaaS 厂商应该按 API 调用次数对 Agent 访问收费吗？本季度先封顶费率，在迁移期内让注册 Agent 逐步取代席位，到第 18 个月再按成果定价。在席位上装一个按次计量的仪表，这三步全都做不到。
  • 作为记录系统仍然是护城河吗？ServiceTitan 切断了 Podium，保住了 1,000 个客户，却没有带来任何新增收入。记录是留存护城河，不是增长引擎。两行字就能取代那页幻灯片。
  • 应该砍掉哪些设计仪式，用什么来替代？九种只产出“回执”而非决策的设计仪式，每一种都附上替代方案，再加上让砍掉真正落地的四步协议。
  • OKR 对 AI 产品还值得吗？OKR 是为每周构建、每月反馈信号的时代设计的。对于每天都有信号、四小时就能做出原型的 AI 产品，请用滚动成果账本来取代它。
  • CPO 如何在不陷入停滞的情况下赢得 AI 转型？软着陆转型只是幻想。要靠设定退役日期、重写薪酬方案、提前铺垫毛利率低谷，并按顺序执行七项决策来取胜。
