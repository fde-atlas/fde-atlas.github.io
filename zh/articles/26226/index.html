当 AI Agent 完成部署时，FDE 仍然负责什么

原标题：What the FDE Still Owns When Agents Do the Deployment

Falkster.AI · 2026-11-18 · 约 11 分钟读完

摘要

文章认为，随着 AI Agent 接管现场部署工作，前沿部署工程师的角色收缩为四项决策：选择自动化哪些流程、提炼客户专家的判断、定义上线的评测标准、把经验回馈产品。作者以 IBM 与 Microsoft 的 Imagine Enterprise（含 6000 多个 Agent）、Microsoft 的 Shatzkamer 和 ServiceNow 的 Zavery 等言论为据，主张部署 Agent 本身是产品，应由 CPO 统管，并以“每次上线的人工小时数”作为核心指标。

要点

  • IBM 与 Microsoft 发布 Imagine Enterprise，附带 6000 多个 AI Agent 与前沿部署工程师支持。
  • Agent 接管连接系统等构建工作，人保留四项决策：选择、判断、标准、回馈。
  • 部署 Agent 是产品，需要产品经理、路线图和质量标准，归 CPO 管。
  • 核心指标是每次上线的人工小时数，应逐季下降，其中决策小时不可归零。
  • 作者预测 2028 年前后岗位要求将转向评测设计与流程判断。

11 月 10 日，IBM 和微软宣布推出 Imagine Enterprise，一个面向受监管行业的 Agent 平台。看看这份发布稿描述客户能获得什么时的顺序。IBM Consulting 带来“超过 6,000 个 AI Agent 和资产的机队”。然后，对于符合条件的合作项目，“两家公司的前沿部署工程师可以帮助客户从实验走向生产”。负责 IBM Consulting 的 Mohamad Ali 将整个项目描述为把“人类专业知识与数字劳动力结合在一起”。

Agent 先到。工程师随后附上。

两周前，微软前沿部署工程的企业副总裁 Kevin Shatzkamer 用同样的方式描述了部署单元：小型团队，“辅以编码助手和部署 Agent”。同一天，在 ServiceNow 的财报电话会议上，Amit Zavery 表示公司正在构建“AI 实施 Agent”，并且当客户上线时，“大量繁重的工作由 AI 完成”。

三家最大的企业级厂商，在两周之内，都在说现场构建正在转向 Agent。那么人类还拥有什么？四项决策，以及一个接收这些决策的地址。

这是The FDE Transition的第 17 部分，属于The Product OS的一部分。

简短版本

  • 当 Agent 执行现场构建时，前沿部署工程师保留的是决策权：自动化哪个工作流、放过哪个工作流，客户最优秀的人如何做出艰难的判断，什么才算达到可以上线的标准，以及产品应该为所有人吸收什么。
  • IBM 和微软现在随附超过 6,000 个预构建 Agent 和资产出货，符合条件的合作项目还附带工程师；微软自己的 FDE 领导层描述了辅以部署 Agent 的团队；ServiceNow 的首席产品官正在构建实施 Agent。
  • 剩下的构建工作本身就是一个产品——部署 Agent——它需要一个拥有路线图的负责人。这个负责人就是产品团队。
  • 人类在现场花费的每一个小时，要么是一项只有人才能做出的决策，要么是部署 Agent 的一个缺口，而唯一能区分这两者并据此采取行动的组织，就是现场和路线图向同一个人汇报的组织——CPO。
  • 衡量现场工作的指标是每次上线的人工小时数，而且它应该每个季度都在下降。

部署 Agent 是一个产品

看看是谁在说话。Zavery 是 ServiceNow 的总裁、COO 兼首席产品官。实施 Agent 归他管。在那次电话会议上，CFO 估算了随附工程师的成本，而第 16 部分讲的是为什么客户不为这些工程师付费。摆脱这一成本的出路来自产品席位：“这不是一个长期合作项目。”

Decagon 之前已经写下了这一点。其实施总监 Katherine Xiao 在六月表示，“Agent 开发经理现在几乎承担了所有曾经需要工程师完成的构建工作”，而且每个 Agent 的定制工程量下降了 80%。过去需要工程师花整整一个冲刺周期才能完成的策略变更，现在只需一个下午。这些是她对自己公司的数据，所以请将其视为供应商的说法。但这个方向与本月其他所有信息一致。

第 13 部分 讲述了工具链从工程师背包中脱离出来。这是下一步。连接连接器、加载预构建 Agent、起草技能并运行第一轮测试的东西是软件，而每次部署都会运行的软件就是一个产品。它有用户——首先是你们自己的现场团队，然后是客户的工程师。它有需求清单和质量标准。如果产品组织中没有人负责它，那它就只是你最好的 FDE 在飞机上写的一堆脚本文件夹。

这就是本季度的决策。指定负责部署 Agent 的产品经理，并把它放到路线图上，与你们销售的产品并列。

Agent 得不到交付的东西

Menlo Ventures 于 11 月 3 日发布了其企业 AI 现状报告，由 Tim Tully、Joff Redfern、Deedy Das 和 Derek Xiao 撰写，基于 Morning Consult 对近 400 位美国企业决策者的调查。（Menlo 投资了其涵盖的多家供应商。）报告将企业在 AI 部署上的支出定为 1768 亿美元，一年内增长了 5.4 倍，其中有两句话读起来就像一份现场岗位的职位描述。Agent 在条件就绪的地方才能工作，而“大多数企业市场缺乏这些条件”。创造这些条件意味着“将 Agent 连接到它们所需的全部碎片化系统和上下文，让隐性知识和流程变得可访问，并设计评测来帮助 Agent 改进。”

连接系统是交给 Agent 和预构建资产的部分。另外两项则是人赢得席位的地方，而我想在两侧各加一项。

选择。 先自动化哪个工作流，以及哪个工作流永远不该自动化。Xiao 对此有一句最好的话：“稀缺的技能是克制和远见。”Agent 会构建你指向的任何东西。总得有人决定不要指向哪里。

判断。 客户的资深人员如何决定棘手的案例。Marco Di Santo 昨天写道，交接文档记录的是你知道的东西，而之后的问题则是关于你会如何决策。这对理赔员或信贷员来说，与对即将离职的同事一样成立，而把这些从他们脑中提取出来是访谈工作。我在同一天写了关于他的文章的内容。

标准。 达到可上线水平意味着什么，要以客户自己的人撰写并签署的行数为依据。第 12 部分 论证了评测由 FDE 来写。在 Agent 进行构建的情况下，这几乎就是 FDE 所写的全部内容。

交接。 这次部署教会了我们什么，是每位客户都应该获得的。负责编辑 FDE Hub 的 Milos Mandic 最近在 Sycamore 担任了一次 FDE 职位，并用两句相辅相成的话描述了这项工作：“我一天中的大部分时间都花在指挥各种 Agent 上”，以及“我与客户坐在一起，弄清他们真正需要什么，并把这些需求带回产品中。”

指挥 Agent 是方式。第二句话才是这份工作本身。

Shatzkamer 在 Microsoft 的 Frontier Company 内部表达了几乎相同的观点。一次客户合作的目标是“向客户移交运营能力”，而“反馈到产品路线图（以及模型）的闭环仍然至关重要”。他还写道，头衔中的“工程师”部分“仍然不可妥协”。我同意，理由很简单：如果你自己都造不出来，你就无法评判一个 Agent 的构建质量。

每次上线所需的人工小时数

一旦构建工作归属于 Agent，这个领域就有了一个新的指标，而且很简单：统计从签约到上线之间的人工小时数，然后对它们进行分类。

有些小时是决策：选择、判断、标准、交接。这些就是那个职位。其余的则是缺口。一个 Agent 写不出来的连接器。一个它不理解的权限模型。一个它本应运行却没有运行的测试。每一个缺口小时都是针对部署 Agent 的一份缺陷报告。

第 7 部分的记分卡统计的是泛化率，即为所有人交付的现场工作占比。每次上线所需的人工小时数是同一理念在部署本身上的应用。如果连续两个季度这个数字持平，说明没有人在改进 Agent。而如果决策小时数降到零，那就要警惕了，因为已经没有人在做决策。

为什么这属于 CPO 的组织

这是整个 OS 论证中属于这个职位的部分。只有当记录缺口小时数的人与负责部署 Agent 路线图的人向同一位高管汇报时，缺口小时数才能转化为产品。在销售体系下，缺口小时数是交易的成本。在服务体系下，它是可计费的——或者说如果有人付费的话就是可计费的。而在 CPO 体系下，它是一张有明确负责人的工单，并且因此下一个季度的部署需要更少的人。

决策小时数也需要同样的归属。选择是产品战略的输入。判断和标准是规格说明，这正是设计和 Product Builder 接手的地方；周一关于 PM 的部分论证了规格说明如今就是一份评测，其中的条目来自一线现场。交接则是路线图。

第 15 部分从记分卡的角度论证了汇报线。部署 Agent 让另一方的论点更难成立。当构建本身是产品，而人类产出的是产品决策时，现场工作中已经没有多少是游离于产品之外的了。The CPO Transition 提供了来自高层的视角。

我的预期

这些是我的预测，而非事实。

到 2027 年底，至少有一家大型厂商公布其上线项目中无厂商工程师到场的比例。ServiceNow 是最明显的候选者，因为它已经表示工程师并不打算长期驻留。

到 2027 年，FDE 人数持续上升，而每次上线的人工工时却在下降，因为部署数量的增长快于 AI Agent 接管工作的速度。Menlo 的 5.4 倍数据正是我如此判断的原因。人们预测的这个岗位的裁员会比他们想象的来得更晚，而且首先落在那些从未统计过工时的团队头上。

到 2028 年，职位描述将发生变化。评测设计与工作流判断在任职要求中的位置将超过集成代码，像 Decagon 的 Agent Development Manager，或 Menlo 报告中与前沿部署工程师并列的“Agent PM”这样的头衔将变得普遍。这个岗位从两个方向都更接近产品。

本周可以尝试的一件事

拿出你最近一次上线项目，列出从签约到上线之间人类所做的每一件事。每件事一行。在每一行标注 D（决策）或 G（缺口）。

在每个 G 旁边，写下部署 Agent 要完成这件事需要什么。把这份清单指名发给某位产品经理。如果你想不出该写谁的名字，那你就找到了本季度要做的决策。

保留 D 清单。它就是 2028 年这个岗位的职位描述。

常见问题

当 Agent 完成部署时，前沿部署工程师还负责什么？+

四个决策。选择：先自动化哪个工作流，以及哪个永远不该自动化。判断：客户的高层人员如何裁定疑难案例，这必须从他们的头脑中挖掘出来。标准：达到什么程度才算可以上线，写成由客户自己的员工签署的评测行。还有移交：这次部署学到了什么，每个客户都应该获得。连接系统——过去占据工程师一天时间的部分——正在转向部署 Agent 和预构建资产。

IBM 和微软在 2026 年 11 月 10 日宣布了什么？+

发布了 Imagine Enterprise，一个面向行业特定流程的 Agent 平台，从金融服务、保险和零售行业起步。发布说明称，IBM Consulting 带来了一支由 6,000 多个 AI Agent 和基于 IBM Consulting Advantage 构建的资产组成的车队，微软提供 AI、云和安全技术，两家公司的前沿部署工程师可以在符合条件的合作项目中帮助客户从实验走向生产。客户可以让 IBM Consulting 部署并运营它，与 IBM Consulting 共同创新，或者自行管理。

什么是部署 Agent，谁应该拥有它？+

它是执行现场构建的软件：连接连接器、加载预构建 Agent、起草技能，并运行第一轮测试。微软的 Kevin Shatzkamer 描述了由编码助手和部署 Agent 增强的 FDE 团队，ServiceNow 的首席产品官 Amit Zavery 在 2026 年 10 月 28 日的财报电话会议上表示，公司正在构建 AI 实施 Agent。每次部署都运行的软件是一个产品，所以它需要一个产品经理、一个待办事项列表和一个质量标准。Falk 的观点是产品部门应该拥有它，隶属于 CPO。

什么是每次上线的人工小时数？+

从合同签订到上线之间的人工小时数，分为两类。决策小时数是选择、判断、标准和移交，它们是核心。差距小时数是部署 Agent 本应完成却未能完成的工作，比如它无法编写的连接器或没有运行的测试。每一个差距小时数都是针对部署 Agent 的一份缺陷报告。这个数字应该每个季度都在下降，如果决策小时数降到零，就没有人在做决策了。

为什么部署 Agent 加强了 FDE 组织向 CPO 汇报的理由？+

因为只有当记录差距小时数的人和拥有部署 Agent 路线图的人向同一位高管汇报时，差距小时数才能转化为产品。在销售部门下，差距小时数是交易的成本；在服务部门下，它是可计费的时间。在 CPO 之下，它是一张有负责人的工单。决策小时数也是产品输入：选择为战略提供依据，判断和标准就是规格说明，移交则是路线图。

Falk 对 Agent 部署的 FDE 岗位有哪些预测？+

标注为预测，而非事实。到 2027 年底，至少有一家大型厂商会公布“上线项目中无厂商工程师到场”的占比，ServiceNow 是最明显的候选。FDE 人数在整个 2027 年持续上升，而每次上线的人工工时下降，因为部署增长的速度快于 AI Agent 接管工作的速度。到 2028 年，该岗位的招聘要求将把评测设计和流程判断置于集成代码之上，像 Decagon 的 Agent Development Manager 这样的头衔将变得常见。

什么是 The FDE Transition 系列？+

这是 falkster.com 上的一个每周系列，属于 The Product OS，面向前沿部署工程师以及围绕他们构建团队的领导者。第 1 部分提出了 FDE 是从服务部门走来的产品构建者这一论点。第 15 部分论证了 FDE 组织应向 CPO 汇报，第 16 部分讨论了由谁为现场团队买单，第 17 部分则探讨当 AI Agent 完成现场构建后，人类 FDE 仍然掌握哪些职责。
