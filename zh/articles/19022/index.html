什么是开放权重模型？与开源的区别及商用使用

原标题：オープンウェイトモデルとは？オープンソースとの違いと商用利用

FDX株式会社 · 2026-08-24 · 约 12 分钟读完

摘要

这篇来自FDX株式会社的文章澄清了“开放权重模型”与“开源LLM”的混淆：多数所谓开源模型其实只公开了权重，不含训练代码与数据。文章比较了闭源API、开放权重、开源三种公开形态，指出权重公开不等于可自由商用，并列出法务需确认的5项许可要点。文章还分析了企业自建推理的4个收益（数据不出域、固定成本、版本固定、微调）及应回避的场景，建议先确定适用业务、用闭源API验证后再评估自建。

要点

  • 开放权重仅公开权重，多数“开源LLM”实为开放权重。
  • 权重公开不等于可商用，许可条件因模型而异。
  • 法务需确认商用、规模限制、输出物、衍生模型、禁止用途5项。
  • 自建优势：数据不出域、固定成本、版本固定、可微调。
  • 建议先定业务、用API验证，再评估自建与成本分界点。

本文要点（发布日期：2026年8月24日） 定义：已公开训练好的权重、可下载并在自家环境中运行的LLM。与开源的区别：开放权重公开的只是权重。开源则除权重外，连训练代码和训练数据也一并公开。商用：即使权重已公开，也不一定可以无限制地商用。条件因许可证而异，请与法务确认这5个要点。想比较模型的读者：21个模型的一览表和GPU速查表已汇总在开放权重模型一览｜本地LLM对比2026中（每月更新）。

“开放权重”“开源LLM”“本地LLM”经常被当作同义词使用，但它们所指的对象并不相同。如果在区分模糊的情况下就考虑引入，可能导致遗漏许可证条件、错误估算运维体制等问题。

本文将模型的公开形态整理为3类，并讲解如何判断是否在企业内部使用开放权重模型。各模型的性能比较和推理基础设施的搭建，将在另一篇文章“本地LLM对比2026”中讨论。

本文的目标读者

  • 正在考虑在企业内部运用生成式AI、希望理清其与封闭API区别的信息系统部门人员
  • 需要确认模型许可证条件的法务、采购部门人员
  • 正准备以“开源所以可以免费自由使用”的理解推进内部审批的推进负责人

“权重已公开”与“可以自由使用”是两回事。这一点在实际工作中最容易引起误解。

3种公开形态的区别

形态公开的内容能否在自家环境运行典型使用方式
封闭（API提供）无（仅API端点）不可按量计费调用API
开放权重训练好的权重可获取权重，在自家基础设施上进行推理
开源权重＋训练代码＋训练数据可可深入到复现训练、修改模型

一般被称为“开源LLM”的模型，大多数严格来说属于开放权重。公开训练数据构成和训练代码的模型很有限，大多数情况下公开的只是权重及其使用条件。

术语混淆产生的原因

在软件领域，长期以来形成了只要公开源代码就称为“开源”的习惯。LLM中相当于“源代码”的，不是代码，而是训练数据和训练流程。然而，仅公开权重的模型也习惯性地被介绍为“开源”，因此这种混淆便固定了下来。

对实际工作的影响有以下两点。

  • 高估了修改的自由度：仅有权重无法复现训练。无法进行“重新训练以消除特定知识”之类的操作
  • 未确认许可证就推进：由于“开源”这一措辞，容易误解为商用利用是无条件许可的

开放权重为企业带来的4个选择

1. 数据不出外部即可进行推理

这是最大的优势。输入数据不会离开企业的管控范围，因此即使涉及禁止外部传输的信息的业务也能适用。如果合同或规章中的数据外带限制成为引入的障碍，这种形态有时会成为唯一的选择。

2. 成本结构从按量计费转变为固定成本

封闭API的费用随使用量成比例增加。开放权重的自建运营则以GPU、电力、运维人力等固定成本为主。当使用量超过一定规模后，自建运营会转为有利，但这个分界点因配置不同而差异很大。具体测算的思路在“本地LLM对比2026”中有讨论。

减少Token消耗本身的设计，对两种形态都有效。也可参考“LLM Token节省5种模式”。

3. 可以在企业内部固定模型版本

在API服务中，提供方会自行决定模型的更新与废止。这可能导致Prompt行为发生变化，已验证的业务流程需要重新验证。而使用开放权重，可以做出保持特定版本继续运营的决策。

但反过来看，这也意味着企业要承担自行引入安全修复和性能改进的责任。选择不更新，就必须对不更新所带来的风险进行管理。

4. 可以通过微调进行调整

可以使用企业自有数据进行追加训练。但以此为主要目的来决定引入应当慎重。许多业务问题可以通过RAG（检索增强生成）、Prompt设计或业务流程的重新设计来解决，而无需追加训练。微调的前提是建立持续进行训练数据整理、评估和再训练的运维体制。

许可证的解读方法

即使权重已公开，使用条件也因模型而异。实际工作中存在以下几种类型。

类型内容
宽松型如Apache 2.0、MIT等，广泛允许商用、修改和再分发
自有许可证型由提供方自行规定条件。可能包含用途限制，或要求达到一定规模的经营者取得额外许可
非商用限定型仅限研究和评估目的，不允许商用
附加政策并存型除许可证正文外，还另行适用使用政策（禁止用途清单）

应确认的5个要点

在做出引入决策之前，应与法务共享的确认事项有以下5项。

  • 是否允许商用：业务使用是否包含在许可范围内
  • 规模条件的有无：是否存在根据使用规模或企业规模要求额外许可的情况
  • 输出物的处理：能否将模型输出整合到自有产品与服务中，是否需要标注归属
  • 派生模型的处理：微调后的模型能否再分发，以及此时的条件
  • 禁止用途：在适用单独使用政策的情况下，自有用途是否触及禁止事项

各模型的具体条件（销售额与用户数的门槛、标注义务、按业务类型另行签约），每月都会在文章22的Q2中确认。

许可证会被修订。不能只在引入时确认一次就结束，而要在更新模型的时机重新确认，需要建立这样的运营机制。

应选择开放权重模型的场景／应避免的场景

判断情况
应选择数据无法按合同或内部规定带出外部
应选择使用量大，按量计费难以预测费用
应选择模型版本固定已成为业务要求
应避免尚处于验证阶段，适用业务尚未确定
应避免缺乏承担 GPU 基础设施运营的体制
应避免所需质量只有最顶级的闭源模型才能达到

常见的引入失败模式是在适用业务确定之前就从基础设施入手。先采购 GPU 再寻找用途的做法，容易导致投资先行而看不到效果。关于这一结构，我们在《AI PoC 失败的 5 个结构性原因与规避方法》中进行了梳理。

引入决策的实务步骤

  • 先确定适用业务：明确用于哪些业务的哪个环节，用工时和削减预期来定位
  • 确认数据约束：在合同和内部规定层面确认该业务的数据是否可以外发
  • 先用闭源 API 验证：如果没有约束，先通过 API 确认质量和业务适配性。这一阶段不需要基础设施投资
  • 估算用量与成本的分界点：比较假设用量下的按量计费金额与自有运营的固定成本
  • 与法务确认许可证：确认前述 5 个项目
  • 确定运营体制：明确模型更新、安全修复、故障处理的负责人

顺序很重要。跳过第 1 和第 2 步直接从第 4 步入手，作为比较前提的用量就无法估算。按业务单位判定工时和适用性的步骤，我们在《AI 评估是什么？业务盘点与投资回报设计》中进行了讲解。

常见问题（FAQ）

Q1. 开放权重模型与开源 LLM 有什么区别？

A. 公开的对象不同。开放权重是仅公开训练后权重的形态，开源则是指除权重外还公开训练代码和训练数据的形态。一般被称为“开源 LLM”的模型，大多数严格来说属于开放权重。仅有权重无法复现训练，也无法去除特定的训练内容。

Q2. 开放权重模型可以免费商用吗？

A. 权重的获取是否免费，与是否无条件允许商用是两回事。既有像 Apache 2.0 和 MIT 那样广泛授权的宽松型许可证，也有通过提供方的专有许可证限制用途、或对达到一定规模以上的企业要求额外许可的情况。还存在仅限研究用途、不允许商用的模型。引入前，需要与法务确认商用可行性、规模条件、输出物的处理、派生模型的处理、禁止用途这 5 个项目。

Q3. 本地 LLM 与开放权重模型是同一个意思吗？

A. 所指的对象不同。开放权重是指模型公开形态的用语，本地 LLM 是指运行环境（在自有管理下运行）的用语。在自有环境中运行开放权重模型就成为本地 LLM，但也存在通过外部云推理服务使用开放权重模型的架构，这种情况下就不是本地运行。

Q4. 自有运营会比闭源 API 更便宜吗？

A. 取决于使用量。闭源 API 按量计费，费用与用量成正比；自有运营则以 GPU、电力、运营人力成本等固定成本为主。超过一定用量后自有运营更有利，但分界点因架构和运营体制而有很大差异。容易被忽视的是运营人力成本，仅比较 GPU 费用会让自有运营显得过于有利。估算思路在《本地 LLM 比较 2026》中有介绍。

Q5. 应该从哪里开始入手？

A. 从确定适用业务开始。基础设施的考虑可以放在之后。如果业务的数据外发没有约束，先通过闭源 API 验证质量和业务适配性，这一阶段不进行基础设施投资。等验证后掌握了用量预期，再进入与自有运营的比较。先采购 GPU 再寻找用途的顺序，容易导致投资先行而看不到效果。

Q6. 一直固定模型版本会有问题吗？

A. 在业务流程稳定方面有优势，但需注意不更新的责任会转移到本公司。需要建立自行判断安全修复和已知问题的应对、必要时予以引入的机制。固定版本时，不应固定后置之不理，而应设计定期评估是否更新的运营机制。

总结

  • 开放权重模型是指已公开训练好的权重、可在自有环境中运行的LLM
  • 公开形态有3种：封闭（仅API）、开放权重（仅权重）、开源（权重＋训练代码＋训练数据）。一般被称为“开源LLM”的大多是开放权重模型
  • 优点有4个：数据不出外部的推理、以固定成本为主的成本结构、版本固定、微调
  • “权重已公开”与“可以自由使用”是两回事。需与法务确认5个项目：是否允许商用、规模条件、输出物的处理、派生模型的处理、禁止用途
  • 应选择的情形是：有数据约束／使用量大／版本固定为需求的场景。应避免的情形是：应用业务未定／没有GPU运营体制／必须最高品质的场景
  • 推进步骤是“确定应用业务 → 确认数据约束 → 通过API验证 → 估算分岔点 → 确认许可证 → 决定运营体制”。不要从基础设施入手
