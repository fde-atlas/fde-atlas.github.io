AI Agent 与 FDE 的基于成果定价

原标题：Outcome-based pricing for AI agents and FDEs

FDE Times · 2026-10-09 · 约 6 分钟读完

摘要

文章分析 AI Agent 按结果计费模式对前沿部署工程师的影响。Sierra 只在 Agent 完成任务时收费，Intercom 的 Fin 每个结果收 0.99 美元，但“已解决”的定义存在争议，有客户质疑人工介入后仍算作 Fin 的成果。文章引用 Sequoia 提出的三个条件：为每个客户定义成功、可靠度量结果、稳定交付，并指出这三项都是 FDE 的工作。按结果计费使解决率直接成为收入杠杆，工程师需先保证数字诚实再提升它。

要点

  • Sierra 只在 Agent 完成任务时收费，Fin 每个结果收 0.99 美元。
  • “已解决”的定义存在争议，如人工回复后仍计为 Fin 成果。
  • Intercom 借助 AWS 与 Anthropic 使 Fin 部署 30 天内解决率达 56%。

Intercom 可以把客户在 Fin 回答后的沉默计为一次解决，而驻扎在客户身边的前沿部署工程师正是负责度量并为此辩护的人。

简要概述

  • Sierra 只在其 Agent 完成任务时才收费。Intercom 对每次 Fin 的结果收取 0.99 美元。
  • “已解决”的定义确实存在争议：一位 Intercom 客户提出异议，认为当人工客服给出最终回复时，不应把功劳记在 Fin 头上。
  • Sequoia 提出了三个条件：为每个客户定义成功标准、可靠地度量结果、稳定地交付成果。这三项都落在 FDE 身上。

Sierra 是 Bret Taylor 创办的公司，政策很明确：只有当其 Agent 为客户完成任务时才获得报酬。Intercom 将 Fin 定价为每个结果 0.99 美元，不按席位或按 token 收费。

然而在 Intercom 自己的社区论坛上，一位客户写道，每当 Fin 之后有人工客服回复客户时，公司就应停止默认 Fin 已解决了问题。

这三个细节指向同一个方向。当只有问题被解决后资金才会流动时，什么算“已解决”这个问题就直接决定了收入。回答这个问题、对其进行度量并推动数字上升的人，正是与客户并肩工作的工程师。

如果你想转型进入 FDE 岗位，这一点值得认真理解。当客户按席位付费时，工程师的工作可以在交付日结束。而当客户按结果付费时，工程师部署和运行 Agent 的方式会直接影响供应商能收到多少钱。

“已解决”是一个合同条款，而不是一种感觉

Sierra 将结果定义为业务事件：一次已解决的客服对话、一次成功挽回的取消、一次追加销售、一次交叉销售。未解决的对话基本免费。这听起来很公平，直到有人必须编写统计它们的代码。

Intercom 的定义显示了难点所在。当客户完成一个工作流时可以计为一次结果，但当客户在 Fin 回答后没有进一步提问时也可以计为一次结果。换句话说，沉默被视为解决。这是一种假设，而每一种假设最终都会遇到质疑它的客户。

Intercom 论坛上的投诉就是一个典型例子。设想一个具体场景：客户询问退款事宜，Fin 作了回答，随后一名员工介入，因为 Fin 的回答不够充分。系统记录了一次 Fin 的解决，而客户的客服团队则认为自己是在为自家员工完成的工作付费。

Manny Medina 在 Sequoia 的一篇分析中指出了这一模糊之处。结果是处理时长吗？是客户关闭工单后还购买了更多产品？是 CSAT？还是 NPS？每种答案都对应不同的度量流水线，而这个选择必须在部署阶段做出，不能只留在销售演示的幻灯片上。

解决率的每一个百分点都是收入

一份关于 Intercom 和 Anthropic 的 AWS 案例研究指出，Fin 在部署后的前 30 天内平均解决率达到 56%。对于一家按结果收费的供应商来说，这个数字不再只是质量指标，而是一个收入杠杆。

做一个假设计算：某客户每月有 10,000 次对话，按 56% 计算，就是 5,600 个可计费结果。

如果一名工程师发现 AI Agent 经常答错的三类问题，修复知识库和工具调用流程，把解决率提升到 60%，那么供应商每月就能多获得 400 个结果，而无需签下任何新合同。

这个计算反过来也成立。如果结果的定义过于宽泛，比如把每一位沉默的客户都视为已解决，仪表盘看起来很漂亮，但客户信任会下降，正如论坛上的投诉所示。

因此，一名优秀的 FDE 不会不惜一切代价去提高这个数字。这项工作的首要任务是让数字变得真实可信，然后才是去提升它。

Sierra 也明确表示，工作并不会在上线后就停止。该公司写道，上线之后，它会继续开展有针对性、有方向性的优化工作，以持续提升 AI Agent 的表现。在按结果计费的模式下，来自结果的收入正是为这些工作买单的来源。

Sequoia 提出的三个条件全都是 FDE 的工作

Sequoia 对 Agentic AI 公司定价模式如何成熟的分析，列出了按结果收费之前需要满足的条件。其一是对每位客户而言成功是什么样子的清晰定义。另外两个条件是可靠的结果度量以及稳定的结果交付。

注意“每位客户”这几个字。一家电信公司可能把留住即将取消订阅的用户视为最重要的结果，而一个电商市场平台关心的则是有多少退货在没有人工介入的情况下完成处理。没有一种定义适用于所有人，所以必须有人与每位客户坐下来，就其定义达成一致。

可靠的度量同样是真正的工程工作。它意味着要识别客户系统中哪个事件标志着案例完成，处理员工介入的情况，并决定沉默持续多久才算作结束。这些决策需要由既懂 AI Agent 日志又懂客户运营的人来做。

把新旧定价模式放在一起对比，可以看出 FDE 工作的变化。下表是根据上述事实推断出来的，并不描述任何特定公司。

维度按席位或 Token 计费按结果计费
AI Agent 答错时谁承担风险主要是客户供应商，因为未解决的案例大多不计费
向客户提出的第一个问题有多少用户，需要集成哪些系统对这位特定客户来说，什么才算一个已解决的案例
工程师的工作何时结束通常在上线时不会结束，因为上线后的优化是收入来源

Sierra 为什么称这些人为 Agent 工程师

Sierra 的 Natalie Meurer 认为，FDE 的最佳定义方式是对客户负责，而不是看角色的形态或所涉及工作的类型。

尽管如此，Sierra 仍刻意将这一角色命名为“Agent 工程师”。该公司解释说，头衔应当体现工作的技术性质，而不仅仅是对客户的投入。

这两个理念与定价模式相契合。根据 ZenML 对一场 Sierra 演讲的总结，这些工程师的职责与具体成果挂钩，例如完成一笔销售或解决一个客户请求。而这些正是出现在账单上的内容。

Bret Taylor 在给供应商的建议中总结了所需的态度：以合作伙伴的身份走近客户，帮助他们解决紧迫的业务问题。在按结果付费的模式下，这不仅仅是一句口号。如果客户的问题没有解决，供应商就没有收入。

如果你想要这份工作，应该练习什么

这里最稀缺的技能不是提示词编写，而是把一个模糊的业务目标转化为可衡量的定义，然后在客户的运营团队和你自己的销售团队面前捍卫这个定义。构建过客服系统、CRM 或分析流水线的开发者已经具备了一半的基础。

阅读职位描述时，留意诸如“解决率”“结果”“成功指标”和“Agent 工程师”之类的措辞。看到这些词时，直接询问雇主：上线之后工程师是否对这个数字负责，还是只负责做集成。

在面试中，你还可以询问公司如何判定一个案例已解决，以及谁有权更改这个定义。

在简历上，诸如“构建了一个客服聊天机器人”这样的描述几乎说明不了什么。不如写清楚你如何定义指标、用哪个事件来衡量、如何处理异常情况，以及这个数字最终提升了多少。

一个能够描述自己如何发现旧的统计方法在虚增结果并将其修复的候选人，会比只炫耀高解决率的候选人更令人印象深刻。

按结果付费迫使供应商与客户共担风险。能够与客户就“完成”的含义达成一致，并在上线后保持统计真实可信的工程师，将是公司最难替换的人。
