FDE 技能排名：1,000 条招聘启事要求什么

原标题：FDE Skills Ranked: What 1,000 Job Postings Ask For

FDE Times · 2026-10-19 · 约 6 分钟读完

摘要

文章基于 Bloomberry 对 1,000 份前沿部署工程师（FDE）职位的分析，统计各技能出现频率：Python 以 66% 远超其他技能，TypeScript、AI Agent、AWS、LLM 经验集中在约三分之一。作者提醒各百分比相互重叠不能相加，建议深入学习一个云平台（首选 AWS）而非泛泛涉猎，并结合 OpenAI 与 Palantir 的真实职位说明客户沟通经验和实际交付案例的重要性。文章还指出 68% 的职位要求出差驻场，60% 面向 3 至 5 年经验的中级候选人，并给出三层次学习计划与简历写法建议。

要点

  • Python 出现在 66% 的职位中，几乎是第二名的两倍。
  • TypeScript、AI Agent、AWS、LLM 各占约三分之一，构成差异化层。
  • 各技能百分比相互重叠，不能相加得出结论。
  • 68% 的职位要求前往客户现场，客户经验是关键加分项。
  • 60% 的职位面向 3 至 5 年经验的中级候选人。

在 1,000 个职位中，TypeScript、AI Agent、AWS 和 LLM 经验都集中在三分之一左右，这把基础要求与进阶要求区分开来。

简要概述

  • 在 Bloomberry 分析的 1,000 个 FDE 职位中，66% 提到 Python。TypeScript 和 AI Agent 并列 35%，LLM 为 31%，AWS 为 32%。
  • 这些百分比相互重叠，不能相加。深入学好一门云平台，比浅尝辄止地学三门更有价值。
  • 据 Paraform 称，Python 和 JavaScript 只是入场门槛。真正让候选人脱颖而出的是交付过真实的 LLM 或 Agent 系统，并且理解客户。

你打开一个前沿部署工程师的职位描述，数出十几条甚至更多的要求：Python、TypeScript、一个云平台、LLM、Agent、利益相关者沟通、愿意出差。此时问题不再是“我够不够格？”，而是“我应该先学什么？”

凭感觉猜测很容易让你走错方向。Bloomberry 分析了 1,000 个 FDE 职位，统计了每项技能出现的频率，这提供了更好的依据。

一旦你知道哪些技能出现在三分之二的职位中，哪些出现在不到五分之一的职位中，你就有了学习和撰写简历的优先级顺序。

有条理地阅读职位描述正变得越来越有价值。Paraform 的招聘数据显示，FDE 职位数量在 2025 年第一季度到 2026 年第一季度之间增长了 350%。职位越多，噪音越大，能够过滤出核心要求的人才能投对地方。

三分之二的职位要求同一种语言

以下是 Bloomberry 样本中的技术技能，按出现频率排序。第三列将每个百分比换算成 1,000 个职位中的数量，以便更直观地感受规模。

技能提及该技能的职位占比等效数量
Python66%660 个职位
TypeScript35%350 个职位
AI Agent35%350 个职位
AWS32%320 个职位
LLM 经验31%310 个职位
GCP22%220 个职位
Azure18%180 个职位

Python 远远领先于其他所有技能：66%，几乎是第二名 TypeScript 的两倍。随后是集中在三分之一左右的紧密群体：TypeScript、Agent、AWS 和 LLM。换句话说，Python 接近于入场券，而第二群体才是候选人开始拉开差距的地方。

除了技术技能之外，还有一个数字值得记住：68% 的职位要求前往客户现场出差。

为什么这些百分比不能相加

这是解读数据时最常见的错误。把 AWS、GCP 和 Azure 相加得到 72%，但你不能由此得出 72% 的职位要求云平台的结论。一个职位可能同时提到 AWS 和 GCP，因此同一个职位被计算了两次。

把每项技能当作一个独立的数字来读，分别对照这 1,000 条招聘帖进行计算。正确的问题是：如果我再多学一样东西，哪一样能打开最多的招聘帖？就云平台而言，答案是 AWS，出现在 320 条招聘帖中，而 GCP 只有 220 条。

这种读法还能防止你学得过于宽泛。一位熟悉 AWS、亲自部署过、自己调试过 IAM 并跟踪过成本的工程师，比一个把三大云平台都浅尝辄止的人更有说服力。一旦深入理解了一个平台，再到客户现场切换到另一个平台就会快得多。

拆解一条真实招聘帖：OpenAI 纽约职位

现在把频率表应用到 OpenAI 在纽约的 FDE 招聘帖上。该职位要求 5 年以上的技术或部署经验，其中包括一些直接与客户合作的工作。候选人需要用 Python 或 JavaScript 编写生产代码，并且必须构建或部署过由 LLM 或生成式模型驱动的系统。

将每项要求与表格对比。Python 是最常见的技能（66%）。JavaScript 没有单独的数字，因为 Bloomberry 只统计 TypeScript（35%），但 Paraform 把 Python 和 JavaScript 都列为“基本门槛”，即入行的最低要求。LLM 要求（31%）则是这条招聘帖开始体现筛选性的地方。

下一行是最容易被略过的。OpenAI 的招聘帖希望候选人能与工程师、产品团队和客户利益相关方清晰沟通。

Paraform 还指出，真正区分候选人的是部署过真实的 LLM 或 Agent 系统，以及理解客户等软技能。OpenAI 的招聘帖恰好印证了这两点：它要求候选人构建或部署过 LLM 系统，并且能与客户方良好沟通。

Palantir 针对其美国政府业务的前沿部署软件工程师招聘帖则呈现出另一种模式。它要求候选人熟练使用 Python、Java 或 C++ 编程，并且需要最高机密安全许可。

安全许可是与这条招聘帖的政府工作绑定的，因此最合理的理解是把它视为该公司特有的门槛，而不是普遍的市场信号。

Palantir 的招聘帖还提到一点很有用：FDSE 需要自主工作、独立决策，并经常与客户沟通。当你看到这样的描述时，请准备一个面试故事，讲述你曾在无人审批的情况下独自做出决策的经历。

从频率表到学习计划

上面的表格可以分为三个层级。第一层级是生产级 Python：经过测试、完成打包、具备完善的错误处理。

第二层级是从三分之一区间中选一到两项技能：如果你经常为客户构建界面，就选 TypeScript；如果想瞄准 AI 公司，就选 Agent 和 LLM。

第三层级是掌握一门云平台，如果没有特别的理由，就选 AWS。

贯穿这三个层级的共同点，是证明你曾直接与客户合作。当 68% 的职位要求出差，而 OpenAI 的职位说明中明确指出经验必须包括与客户合作时，招聘人员最想看到的是：你曾为真实用户、在他们的现场环境中构建过实际可用的东西。

到了简历环节，比较两种写法。较弱的版本：“具有 LLM、Agent、AWS 经验”。一个更强的假设版本：“为一个 12 人的会计团队构建了发票读取 Agent，运行在 AWS Lambda 上，将对账时间从两天缩短到半天”。

第二种写法恰好回答了职位描述想知道的三件事：你构建了什么、谁在使用它，以及它是否真的能运行。

三个会让技能清单适得其反的错误

最常见的错误是试图勾选清单上的每一项。频率表是用来决定舍弃什么的，而不是用来收集一切的。一个精通 Python、熟悉一种云平台、并且交付过一个真正能运行的 Agent 项目的候选人，排名会高于一个对全部七项技能都只是略知一二的人。

另一个错误是把工作年限当作一堵墙。Bloomberry 发现，60% 的职位面向拥有 3 到 5 年经验的中级候选人，而入门级仅占 12%，在 1,000 个职位中大约只有 120 个。

如果你的经验不足三年，就直接瞄准那一小部分职位，同时在当前工作中积累面向客户的经验。

最后一个错误是简单地罗列关键词。自动筛选系统可能会在你的简历上识别出“LLM”，但面试官会问你把什么投入了生产环境、它在哪里出了问题、你又是如何修复的。一个带有真实数字的、准备好的故事，胜过十个关键词。

练习：自己数五个职位

从你真心想加入的公司中挑选五个 FDE 职位。把每项要求复制到电子表格的单独一行中，合并同一技能的不同表述，然后进行统计。将结果与上表对比：吻合之处是市场信号；分歧之处则特定于你所瞄准的那批公司。

Bloomberry 的表格让你了解市场的整体情况。你自己统计的五个职位则告诉你下周一该学什么。
