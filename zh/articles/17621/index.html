印度 FDE 职位：19 倍增长及招聘要求解析

原标题：FDE Jobs in India: 19x Growth and What Listings Ask

FDE Times · 2026-10-23 · 约 6 分钟读完

摘要

文章分析印度FDE岗位需求：据Indeed数据，2026年招聘量同比增长近19倍，6月达到峰值。但CIEL HR估计完全胜任该角色的工程师仅约1200人，含邻近技能约6000人。需求高度集中：班加罗尔占近一半，与德里—NCR、海得拉巴合计约80%。对比三份招聘启事可见门槛分化：HuntingCube仅要求1—3年经验，实习和调用LLM API的副业项目也算数；NTT DATA要求8年以上，GlobalLogic要求5—10年，两者都明确要求客户沟通与生产环境评测能力。资深岗位年薪70—90 lakh，初级为35—45 lakh。TCS CEO表示希望1%—1.5%的员工可称为FDE，约5900—8900人，暗示内部转岗可能是主要路径。作者建议求职者用LLM API项目加评测数据构建作品集。

简要概述

  • 根据 Indeed 的数据，2026 年印度的 FDE 职位发布量同比增长近 19 倍，并在 6 月达到峰值。
  • GlobalLogic 要求 5-10 年经验，NTT DATA 通常要求 8 年以上；而 HuntingCube 的班加罗尔职位只需 1-3 年经验，实习经历和个人 LLM API 项目也算数。
  • 两个高级职位都明确要求客户工作经验和生产环境中的评测经验，因此这些正是新人应该尽早学习的内容。

近 19 倍。根据 People Matters 引用的 Indeed 数据，这就是 2026 年印度前沿部署工程师职位发布量与一年前同期相比的增长幅度。职位发布量在 6 月达到峰值，到 8 月仍远高于一年前的水平。

人才供给则远为稀缺。CIEL HR 的研究估计，印度只有约 1,200 人能够完全胜任这一职位，如果把具备相关技能的人算在内，也仅约 6,000 人。

在需求飙升而合格人选稀少的情况下，值得追问的是：企业究竟在选择什么样的人，依据又是什么。仔细研读公开的职位描述可以发现，这是一个缺人但并未全面降低标准的市场：经验较少的人有一扇门可以进入，而高级职位则要求非常具体的能力。

需求集中在三个城市

根据 Indeed 的数据，印度的 FDE 职位分为六个地区组：班加罗尔、海得拉巴、金奈、新德里、孟买和远程。这份名单看起来相当分散，但 CIEL HR 的数据显示需求要集中得多。班加罗尔占全年 FDE 需求的近一半，其次是德里国家首都辖区（Delhi-NCR）和海得拉巴，三者合计占职位发布量的近 80%。

具体的职位发布也印证了这一图景。NTT DATA 正在班加罗尔招聘 FDE。GlobalLogic 开设了一个横跨班加罗尔、海得拉巴和诺伊达的混合办公职位，而诺伊达属于德里国家首都辖区。HuntingCube 发布的职位则位于班加罗尔东部。

如果你在印度之外，并瞄准远程这一组，申请前请仔细阅读每个职位描述。标注为远程的职位可能只是指无需到办公室上班，并不意味着接受来自任何国家的候选人。最快的办法是在第一条消息中就直接向招聘人员询问居住地要求和合同类型。

三个职位，三道门槛

根据 People Matters 引用的雇主的说法，他们需要能够与客户坐在一起、厘清真正的问题并让技术在实践中落地的工程师。在招职位涵盖多个领域：企业 AI、数据工程、流程自动化、基础设施和医疗健康。

但在撰写职位描述时，每家公司设定的门槛各不相同。

地点班加罗尔混合办公：班加罗尔、海得拉巴、诺伊达班加罗尔东部

NTT DATA 的招聘信息明显偏向咨询。它希望招聘的人已经习惯与企业客户打交道，能够独立主导从需求探索到原型开发的全过程。GlobalLogic 的招聘信息则偏向平台，并与特定技术栈绑定：Google Cloud 和 Vertex AI。

HuntingCube 的招聘信息是最值得注意的例外。它只要求 1-3 年的软件工程师经验，在产品公司的实习经历也算数，而且一个使用 LLM API 的项目——哪怕是工作之余业余搭建的——也被视为经验。对于职业早期的人来说，这是一个真正的机会。

在高级岗位上，客户经验和评测能力是必备条件

这两个高级岗位的招聘信息在同一个点上不谋而合。NTT DATA 要求具备生成式 AI、Agent 系统和 RAG 的应用知识，以及在生产环境中运行系统所需关注的问题，例如评测、安全和可观测性。GlobalLogic 则直接在职位描述中写明，FDE 必须构建自动化评测循环，以衡量模型性能、漂移和准确率。

为什么评测会出现在一个面向客户的岗位的职位描述中？因为评测是 FDE 向客户证明系统正常运行的方式，也是在系统开始出问题时及时发现它的手段。

想象一下，你为一个医院部署了一个回答内部流程问题的 RAG 助手。你编写 50 个带有参考答案的问题，每次修改提示词或更换模型时都重新运行一遍，并记录有多少答案是正确的。

如果第一次运行答对了 41 个，而修改提示词后只答对 37 个，你立刻就知道自己刚刚把系统改差了——在任何医生察觉之前。

按所需年限的顺序阅读这三份招聘信息，一条路径浮现出来。在 1-3 年阶段，一个调用 LLM API 的项目就已经算作经验；要晋升到 5-10 年这一档，招聘信息明确指出，你必须懂得如何衡量，并且能够站在客户面前为这些数字辩护。

人才短缺会拓宽这扇门吗？

不一定。CIEL HR 表示，需求最旺盛的是拥有 5-8 年经验的候选人，而 NTT DATA 和 GlobalLogic 的职位空缺都落在这个范围内或更高。不同级别之间的薪酬差距也很大：初级 FDE 职位的年薪为 350 万至 450 万卢比，而经验丰富的专家则能拿到 700 万至 900 万卢比。

由于现成候选人如此稀缺，对企业来说，一个明智的途径是从现有员工中培养 FDE。TCS 首席执行官的言论表明，至少有一家大公司正在朝这个方向思考。

他表示，公司希望员工队伍中有 1%-1.5% 的人可以被称为 FDE，按《今日商业》（Business Today）的估算，这相当于大约 5,900 到 8,900 人。文章还指出，目前尚不清楚这意味着招聘新员工还是对现有员工进行再培训。

无论如何，对大型服务公司的工程师来说，信号很明确：成为 FDE 的路径可能是通过内部转岗，而不是跳槽。如果你的公司正在为这一职位寻找人选，请尽早主动请缨，并申请加入与客户直接接触的项目。

把职位要求转化为个人作品集

这个市场看重的是证据，而非头衔。如果你有 1-3 年的经验，就用 LLM API 构建一个能为真实用户解决问题的项目，并附上一个评测集和一份 README，记录每次改进前后的数据。

LLM API 这一部分符合 HuntingCube 职位说明中认可的条件；评测部分则是为 GlobalLogic 在 5-10 年级别明确列出的要求所做的提前准备。

如果你已经有 5-8 年的经验，差距通常不在技术，而在客户方面。重写你的简历，让每个项目都讲清楚三件事：你与客户明确了什么问题、你构建了什么原型，以及你如何衡量结果。

NTT DATA 职位说明中的“探索与原型设计”这一表述应该出现在你的简历上，并有真实案例作为支撑。

阅读高级职位说明时，注意两个信号：它是否清楚说明你将与客户方的哪些人合作，以及它是否提到评测或可观测性？两者都缺失的高级职位说明，可能只是一个挂着时髦头衔的老式工程岗位。

面对 1,200 名现成人才和一个增长近 19 倍的市场，这些空缺职位可能会在一段时间内持续存在。填补这些空缺的不一定是经验年限最长的人，而是那些能够拿出评测数据、并能讲述与客户坐下来深入交流故事的人。
