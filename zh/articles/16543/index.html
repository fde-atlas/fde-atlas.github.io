认识 Cresta 前沿部署工程师：Hanze Li

原标题：Meet a Cresta Forward Deployed Engineer: Hanze Li

Cresta · 2026-05-18 · 约 8 分钟读完

摘要

这篇访谈介绍了 Cresta 创始 FDE 团队成员 Hanze Li 的职业经历与工作方法。他从编程、硬件、机器学习研究到学生组织，看似零散的经历最终都服务于 FDE 角色。文章讨论了 FDE 的日常工作分配、与客户 Brinks Home 的深度信任合作、基于评测数据验证 AI Agent 方案的实践，以及他对企业 AI 未来两三年内改善客服体验的展望。

要点

  • Hanze Li 的多元背景印证了 FDE 需要技术、沟通等综合能力。
  • FDE 应做问题的 owner，为客户提供多个方案而非只执行需求。
  • 与 Brinks Home 的合作采用“omakase”式信任模式，共同推进新功能。
  • 生产级 AI Agent 必须依靠数据集与评测验证，不能凭感觉编码。
  • 他预计两三年内企业 AI 将大幅缩短客服等待时间。

全文

Hanze Li 是 Cresta 的创始前沿部署工程师之一。他的背景横跨硬件、机器学习研究、软件工程和学生自治组织，完美体现了定义 FDE 角色的“连接点滴”理念。我们在盐湖城举办的首届 FDE 团队聚会上与 Hanze 坐下来聊了聊他的故事。

谈谈你的背景吧——听起来是一段相当曲折的旅程。

确实是一段旅程。我八岁在中国开始学编程——父母送我去了一个课余编程兴趣班，但我很讨厌它。我告诉自己再也不碰代码了。

快进到在加拿大上大学：我选了一个我以为不需要太多编程的专业，但读了一两年后，我彻底爱上了编程。从那以后我尝试了很多方向——我做过 FPGA 和 Verilog 硬件实习，坐在实验室里测试真实的硅芯片。我说“不，这不适合我”，又回到了软件领域。后来我被机器学习研究吸引，发表了三四篇论文，一度考虑读基础模型训练方向的博士。本科论文写到一半时，我又说“不，这也不是我想要的”。

最终我在多伦多大学读了 AI 方向的硕士，与此同时，我和许多朋友共同创办了那里至今仍是最大的机器学习学生社团之一：多伦多大学机器智能学生团队（UTMIST）。我还作为学生代表参与了管理委员会的竞选活动。当时这一切看起来毫无关联。然后我加入 Cresta 成为一名 FDE，突然间，那段背景中的每一块拼图都派上了用场。

这些经历是如何与 FDE 角色联系起来的？

我总是想起 Steve Jobs 的一个类比——他著名的“连接点滴”理论。他搞过技术、硬件，学过书法，还去过印度旅行。这一切看起来都像是在浪费时间，直到某一天它不再是。对 FDE 来说也是一样：你不需要成为对基础设施了如指掌的资深后端工程师，也不需要成为开发基础模型的研究科学家。但如果你在所有这些方面的综合能力都高于平均水平——编程、机器学习、客户沟通，甚至公开演讲——那你就会成为一名非常、非常出色的 FDE。

每一位 FDE 几乎就像创业公司的 CTO：技术过硬，能直接负责客户对接，但更愿意在技术层面发力，而不是纯粹的商业层面。你需要与客户建立信任，共同制定一个好的方案来推动事情落地。这不是盲目地客户要什么就做什么——而是一场基于信任、经验和能力的对话。

常见的陷阱是传统软件工程的思维模式：产品经理给你一个任务单，你说“我马上做，两周，高质量交付”。作为 FDE，这可能并不是最佳方式。你必须理解客户真正想要什么，提出多个方案，并推动优先级排序。方案一：彻底改好，两周，完美。方案二：小改动，达到百分之八十的效果，投入最小。方案三：什么都不做——其实已经够用了。大多数客户会选择中间那个方案。作为 FDE，你就是那个提供这份“菜单”的人。

你典型的一天是什么样的？

官方说法是三分之一做 AI Agent 开发，三分之一做客户沟通，三分之一做产品相关工作。实际上，这个比例会随时间变化。

我刚加入时，可能一半以上的时间都花在 AI Agent 开发上——熟悉我们的基础设施、像 Claude Code 这样的工具，以及各种智能体工程的基础组件。这些都是效率倍增器，能在之后为你节省大量时间。

大约六个月后，我的时间分配发生了反转。现在写代码的时间不到三分之一。即使是复杂的使用场景，我也能在一两天内做出一个可演示的版本。其余时间用于测试、评测和客户沟通。虽然我不是 FDPM，但我也承担业务侧的工作——我是解释技术世界的代表。当客户提出需求时，我可以说“这个功能看起来复杂，其实很容易”，或者“这个看起来简单，但后端影响很大”。这种来回沟通、建立真正的信任，是工作中非常重要的一部分。

加入 Cresta 后有一件事让我深受启发：很多听起来是技术问题的问题，最终其实是靠人际沟通能力解决的。客户报告一个 bug。其实那并不是真正的 bug——而是我们尚未交付的功能，或者我们可以绕过的问题。关键技能在于如何清晰地呈现各个选项，让客户做出明智的决定，并快速推进正确的事情。在 LLM 的世界里，无论你多么仔细地处理边界情况，总会有一些幻觉出现，所以你真正需要的是排定优先级，而不是一味地修复。

你与 Cresta 的客户 Brinks Home 合作。这种合作关系是怎样的？

Brinks Home 是一个非常特别的客户。我合作过不少客户，Brinks 的独特之处在于信任的程度——我们共同前进。不是“Cresta 做出产品，然后 Brinks 决定是否购买”，而是：“我们有了新东西。我们确信它有效，但还没有人采用过。你想成为第一个吗？”而 Brinks 总是回答“好”。

我常用的比喻是 omakase（主厨发办）式。在传统的 omakase 餐厅里，你完全信任主厨；他们会把最好的东西端给你，而你的任务就是以开放的心态去品尝。Brinks 对我们也抱有同样的信任。我们确保带来的每一样东西都是安全、经过测试、并且是我们能做到的最好水平。因为过去我们表现出色，所以他们愿意在下一步继续信任我们。

我们最近刚和 Brinks 一起上线的一个产品叫 Agent Operations Center——这是一个面向 AI Agent 的人在回路系统。它不是取代人工客服，而是让 AI Agent 处理简单、重复的工作，并在遇到复杂情况时举手求助，比如折扣请求、罕见的边缘情况，任何你不希望 AI 独自决定的事情。AI Agent 会呈现相关背景，后台的主管回复“给百分之二十的折扣”或“拒绝”，然后 Agent 无缝地继续对话。这和真实的人工客服非常相似——他们在处理复杂或敏感事务时，也需要资深主管不时提供帮助。

作为那次上线的主导 FDE，你必须把每一个边缘情况都想清楚。如果没有主管在线怎么办？如果被呼叫的人忘了回复怎么办？如果 AI Agent 理解错了指令怎么办？第一次做某件事时，所有这些问题都是悬而未决的。第二次就容易多了，因为你有经验，产品也已经成熟。但第一次，你必须把一切都想透，而这正是这份工作最令人兴奋的部分之一。

FDE 是如何进行测试和评测的？

这一点我感受很深。构建一个 AI Agent 是一个研究问题——你总能快速做出一个凑合能用的东西，但你永远不知道它是否是对客户或所在行业而言最好的版本。

举个例子：总是表现出共情在医疗领域可能是好事，但在金融科技领域，如果有人欠银行两三千美元，而 AI Agent 表现得过度共情，人们的感受会很复杂。不同的行业、不同的客户想要的东西不同。某个在某一行业表现完美的功能工具或提示词，在另一个行业可能完全失效。

答案是数据。构建数据集，构建基准，验证你对功能工具、提示词和可复用 Agent 模块的选择确实是最佳选择——这需要时间。不能是“我试过这个，在这个客户那里有效，所以它一定最好”。你需要运行正式的评测，比较方案 A、B 和 C，用数据驱动的方法来看哪个真正更好。

我们现在在某些工作流中使用 GPT-4.1。当我们升级到更新的模型版本时，我们的提示词还是最佳实践吗？我们不知道——除非我们有基准。目标是：对于这个行业，使用这些提示词、这个基础模型，对话依然表现良好。这样我们就能快速迭代、加入新的模型能力，并确信回归测试依然通过。

这正是 Cresta 的秘诀所在：我们拥有如此多的客户合作和数据点，只有我们才能为企业级 AI Agent 构建这种基准。Vibe coding 在演示和玩具 Agent 上效果很好，但在生产环境中，如果没有足够的数据和评测支撑，你永远不能信任它。

对于考虑 FDE 职业道路的人，你有什么建议？

多尝试不同的东西。硬件、软件、机器学习研究、学生会、创业工作——一切都能联系起来。你永远不知道什么时候一段不寻常的经历会帮助你赢得技术领导者的信任，或者帮助你以更系统的方式解决问题。

心态的转变也很重要：做主人，而不是执行者。不要想“PM 给了我一个任务，我来完成它”。要始终理解大局，提出不同的方案，并采用数据驱动的方法。代码本身只是让事情发生的一种方式。架构设计、商业模式以及与客户的关系现在可能更加重要——未来更是如此。

我面试过三十多位 FDE 职位的候选人。很多人说“我在家里做了一个聊天机器人”。但深入挖掘后，会发现他们遗漏了真正的生产级聊天机器人所需的很大一部分东西。你当然可以读博客，但如果没有跨不同用例和垂直领域的真实生产经验，你就无法看到全貌。任何行业都有很多隐性知识——只有身在其中，某些东西才像是常识。你不知道自己不知道什么。

你认为企业级 AI 在未来几年会走向何方？

在两三年内，我希望没有人再需要打一个小时的等待电话去联系航空公司。你表达你的意图，系统记住你的账户，几分钟内问题就得到解决。然后我们就可以花更多时间陪伴家人、读书、去滑雪——专注于真正重要的事情。

这正是 FDE 工作努力的方向。不只是聪明的演示，而是可靠、值得信赖、真正让使用者受益的 AI Agent。加入 Cresta 时，我感觉我的所有背景都没有浪费。所有这些点以一种我无法预料的方式连接了起来。
