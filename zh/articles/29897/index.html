吃进痛点 → 输出产品：FDE 实战手册

原标题：Eat Pain --> Excrete Product: The FDE Playbook

Tailwinds · 2025-11-26 · 约 3 分钟读完

摘要

本文基于对 OpenAI 前沿部署工程负责人 Colin Jarvis 的访谈，阐述 FDE 模式：将核心工程师嵌入客户现场，从高风险场景切入，通过评测驱动开发与迭代建立信任，并强调必须把定制工作沉淀为可复用产品，否则只是变相咨询。

要点

  • FDE 的核心是工程师与行业专家紧密协作，从定制方案中提炼可复用产品。
  • Morgan Stanley 案例显示技术管线六到八周可用，但建立信任花了六个月，最终采用率达 98%。
  • 每段 LLM 代码都需配套评测验证，并刻意权衡概率性与确定性组件。
  • CEO 必须明确 FDE 的目的：是服务收入还是产品押注，失败常源于被短期服务收入拖累。
  • OpenAI 的 Agent SDK 与 Agent Kit 正是从 Klarna 和 T-Mobile 的定制项目中产品化而来。

全文

当一项足够先进的技术能够变革多个行业时，会出现一个耐人寻味的规律：最终胜出的技术供应商，并不仅仅是那些拥有最好产品、最高智商模型或最炫演示的公司，而是那些找到了让技术在企业运营的复杂现实中真正落地的公司。

于是，前沿部署工程（FDE）应运而生。

这个概念很简单：让精通核心技术的工程师直接嵌入行业专家团队中，以紧密的迭代方式工作，深入理解业务领域，构建适用于特定场景的解决方案——然后再提炼出可泛化的部分，使其能在类似问题中复用。

正如 Palantir 首席技术官 Shyam Sankar 所说：FDE 的职责是“吸收痛苦，产出产品”。

学习 OpenAI 的 FDE 打法

本周我与 OpenAI 前沿部署工程负责人 Colin Jarvis 进行了一次交流。与 Palantir 一样，OpenAI 正在以惊人的规模开展 FDE 工作——这些项目的目标客户价值从数千万到数亿美元不等，有时甚至达到数十亿美元的量级。Colin 分享了指导他们实践的几项原则：

从真正高风险的问题入手。 成功应用生成式 AI 的公司不会选择业务边缘的边缘案例。Morgan Stanley 在其财富管理业务——他们最大的业务部门之一——全面部署了 GPT-4。OpenAI 合作的一家半导体公司则请他们解决整个价值链中最大的浪费来源。

通过迭代建立信任，而不仅仅依靠技术卓越。 与 Morgan Stanley 的合作中，核心技术管道在六到八周内就已跑通。但经过六个月的试点、评测和迭代，财富顾问们才足够信任它，愿意将其用于服务客户。最终结果是：98% 的采用率和研究报告使用量增长 3 倍。

采用评测驱动的开发方式。 每一段 LLM 编写的代码，在拥有一套验证其有效性的评测之前都不算完成。这为建立信任以及在 FDE 项目结束后向内部团队交接奠定了基础。

有意识地权衡确定性与概率性。 将 LLM 用于它们最擅长的事情——处理细微差别和复杂性。但要用确定性的防护机制包裹它们，以确保那些必须 100% 正确的事情万无一失。

给考虑 FDE 的 CEO 的建议

Colin 最犀利的建议是：对目标要有毫不妥协的清晰认识。

“你必须非常清楚你的 FDE 团队要达成什么目标，”他说。“你是打算把服务收入作为一项关键收入来源？还是押注于这些项目中成功的产品投入所能带来的收入增长？这是两种截然不同的模式。”

他反复看到的一种失败模式：公司怀有成为产品公司的愿景，却因为服务收入在短期内更容易获取而被拖向这个方向。“突然之间，你就失去了战略视角。”

所需的自律是在困难时刻说不，即使有人为不符合战略方向的工作开出可观的价钱。

北极星指标：离开时必须留下产品。 FDE 是一种从零到一的动作。第一次合作可能只有 20% 可复用。再做两三次，就能达到 50%。然后把它推进业务的规模化部分。OpenAI 的 Agent SDK 和 Agent Kit 正是这样诞生的——从 Klarna 的定制工作开始，在 T-Mobile 得到扩展，最终产品化面向所有人。

如果你不是在朝着可复用的方向构建，那不过是多了几道步骤的咨询而已。

希望你喜欢我与 Colin Jarvis 的对话。
