基础分词与 Token语言模型并不读取字符或单词，而是读取 token：由分词器产生的子词片段，每个片段映射为一个模型嵌入的整数。Token 是上下文窗口和计费的单位，文本如何切分成 token 解释了大量模型怪癖，这也是几乎每个面试流程都从这里开始的原因。

基础上下文窗口上下文窗口是语言模型一次能够关注的固定 token 数量，输入和输出共享同一预算。理解它，正是能够合理设计提示词、控制成本与延迟、并决定何时使用 RAG 的工程师，与那些只是把所有内容粘贴进去然后祈祷的工程师之间的分水岭。

基础嵌入与向量表示嵌入将一段文本转换为一组数字，其位置使得含义相近的文本在空间中彼此靠近，从而让你可以按语义而非关键词进行搜索。嵌入是 RAG、语义搜索、聚类和去重背后的引擎，因此 FDE 面试流程期望你能解释余弦相似度，以及那些会悄悄破坏向量索引的陷阱。

基础Transformer 的直观理解Transformer 是所有现代大语言模型背后的架构，建立在自注意力机制之上，使每个 token 能够并行地关注其他所有 token。FDE 面试流程不要求数学推导；他们希望你用高管或同事都能听懂的通俗语言，解释注意力机制为何胜过 RNN、decoder-only 意味着什么，以及为什么长上下文的成本高昂。

基础Temperature、Top-p 与采样在每一步，模型都会为每个可能的下一个 token 输出一个概率分布，而 temperature、top-p 和 top-k 等采样设置决定了如何将这个分布转化为实际的选择。FDE 环节会测试这一点，因为它控制着确定性与创造性之间的旋钮：知道何时为信息抽取设低值、为头脑风暴设高值，以及为什么同一个提示给出不同答案是预期行为而非 bug。

Glean 的前沿部署工程师环节会提出 llm 与 genai 基础问题，例如“什么是 embeddings，它们如何让语义搜索生效？"、“为什么点积是注意力和 embeddings 中的相似度分数，什么时候应该归一化为余弦值？"、“你的提示加上检索到的文档超出了上下文窗口。你有哪些选择和权衡？"。Token、上下文窗口、提示工程 vs RAG vs 微调、幻觉、评测、成本与延迟：这是每个 AI 原生 FDE 环节首先考察的概念核心。完整题集按由易到难排序并附专家答案，见下文。
