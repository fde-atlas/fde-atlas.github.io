MCP 究竟是什么

MCP 是一个用于将 AI 应用连接到外部系统的开源标准：包括文件和数据库等数据源、搜索和计算器等工具，以及专用提示等工作流（modelcontextprotocol.io）。

有三个参与者很重要，而人们经常混淆这些术语：

参与者它是什么示例
MCP Host协调一切的 AI 应用Claude Desktop、Claude Code、VS Code
MCP Client宿主内部的连接器，每个服务器对应一个由宿主自动创建
MCP Server提供上下文和操作的程序你即将编写的内容

宿主为每个服务器创建一个客户端，每个客户端持有一条专用连接。这里的“服务器”并不表示代码运行在哪里：stdio 传输上的本地服务器与宿主运行在同一台机器上，而 Streamable HTTP 传输上的远程服务器则运行在别处，通常服务于多个客户端。

在底层，MCP 有一个数据层（定义各种原语的 JSON-RPC 2.0 消息）和一个传输层（本地进程使用 stdio，远程使用 Streamable HTTP）。SDK 隐藏了其中大部分细节，这就是为什么你无需从头到尾读完规范也能构建出有用的东西。

什么是 MCP 服务器？

MCP 服务器是一种程序，它通过 Model Context Protocol 让 AI 应用能够访问某个特定系统，例如数据库、文件存储或内部 API。它将该系统暴露为 AI 可以调用的工具、可以读取的资源以及可以复用的提示，并且任何 MCP 宿主（如 Claude Desktop、Claude Code 或 VS Code）都可以连接到它，而无需自定义集成代码。它可以在本地通过 stdio 运行，也可以通过 Streamable HTTP 远程运行。

服务器可以暴露的三类东西

  • 工具： AI 可以调用的可执行函数，用于执行某种操作，例如查询数据库或调用 API。通过 tools/list 发现，通过 tools/call 执行。
  • 资源： 提供上下文的数据源，例如文件内容或数据库模式。只读取，不执行。
  • 提示： 用于构建交互结构的可复用模板，例如系统提示或一组少样本示例。

一个好的心智模型：工具是动词，资源是名词，提示是菜谱。我们的示例服务器使用了工具和一个资源。

2026-07-28 规范中的变化

值得了解，因为网上大量 MCP 教程内容仍在描述旧的设计，会误导你。

  • MCP 现在是无状态协议。 每个请求都在 _meta 字段中携带协议版本和能力信息，因此服务器不会从之前的请求中推断任何内容。
  • 发现通过 server/discover 进行， 这是每个服务器都必须实现的请求，它返回支持的版本和能力。客户端可以选择是否调用它，其响应是可缓存的。
  • 采样（Sampling）自 2026-07-28 起已弃用。 它以前允许服务器请求客户端的应用进行模型补全。新的实现被建议直接集成 LLM 提供商的 API。
  • 日志（Logging）也已弃用。 新的服务器应在 stdio 模式下将日志输出到 stderr，或使用 OpenTelemetry。
  • 引导询问（Elicitation） 现在是重要的客户端原语：它允许服务器通过 elicitation/create 向用户请求更多信息或确认某个操作。
  • 变更通知是可选的。 客户端打开一个长期存续的 subscriptions/listen 流，指明它想要的通知类型。

如果你看到的教程让你的服务器通过采样请求补全，那你读的就是基于旧版协议编写的内容。

3. 编写服务器

创建

orders.py

。注意导入部分：服务器类是

MCPServer

，从

mcp.server

.

import sqlite3
from pathlib import Path

from mcp.server import MCPServer

mcp = MCPServer("orders")

DB_PATH = Path(__file__).parent / "orders.db"
MAX_ROWS = 50


def query(sql: str, params: tuple = ()) -> list[dict]:
    """Run a read-only query and return rows as dictionaries."""
    conn = sqlite3.connect(f"file:{DB_PATH}?mode=ro", uri=True)
    conn.row_factory = sqlite3.Row
    try:
        rows = conn.execute(sql, params).fetchmany(MAX_ROWS)
        return [dict(r) for r in rows]
    finally:
        conn.close()

这个辅助函数中的三个决定是本文的核心，我们会在下文详细讨论：连接以

mode=ro

方式打开，查询使用参数化，结果上限设为

MAX_ROWS

.

接下来是工具。SDK 会读取你的类型提示和文档字符串来生成工具定义，所以文档字符串不是装饰：它是模型在决定是否调用你的工具时所看到的内容。

@mcp.tool()
async def find_order(order_id: str) -> str:
    """Look up a single customer order by its ID.

    Args:
        order_id: The order reference, for example ORD-1004
    """
    rows = query(
        "SELECT order_id, customer, city, amount_inr, status, placed_on "
        "FROM orders WHERE order_id = ?",
        (order_id,),
    )
    if not rows:
        return f"No order found with ID {order_id}."

    o = rows[0]
    return (
        f"Order {o['order_id']}\n"
        f"Customer: {o['customer']} ({o['city']})\n"
        f"Amount: INR {o['amount_inr']:,}\n"
        f"Status: {o['status']}\n"
        f"Placed on: {o['placed_on']}"
    )


@mcp.tool()
async def orders_by_status(status: str) -> str:
    """List orders with a given status, most recent first.

    Args:
        status: One of pending, shipped, delivered or cancelled
    """
    allowed = {"pending", "shipped", "delivered", "cancelled"}
    if status.lower() not in allowed:
        return f"Unknown status '{status}'. Use one of: {', '.join(sorted(allowed))}."

    rows = query(
        "SELECT order_id, customer, amount_inr, placed_on FROM orders "
        "WHERE status = ? ORDER BY placed_on DESC",
        (status.lower(),),
    )
    if not rows:
        return f"No orders with status '{status}'."

    lines = [
        f"{r['order_id']}  {r['customer']:<18} INR {r['amount_inr']:>8,}  {r['placed_on']}"
        for r in rows
    ]
    return f"{len(rows)} order(s) with status '{status}':\n" + "\n".join(lines)


@mcp.tool()
async def revenue_by_city(min_amount: int = 0) -> str:
    """Total delivered revenue grouped by city.

    Args:
        min_amount: Only include cities whose total is at least this amount in INR
    """
    rows = query(
        "SELECT city, SUM(amount_inr) AS total, COUNT(*) AS orders FROM orders "
        "WHERE status = 'delivered' GROUP BY city HAVING total >= ? ORDER BY total DESC",
        (min_amount,),
    )
    if not rows:
        return "No delivered orders matched that threshold."

    lines = [f"{r['city']:<12} INR {r['total']:>9,}  ({r['orders']} orders)" for r in rows]
    return "Delivered revenue by city:\n" + "\n".join(lines)

然后是一个资源，让模型可以读取 schema 而不是猜测列名，最后是入口点：

@mcp.resource("schema://orders")
def orders_schema() -> str:
    """The orders table schema, so the model knows what it can ask for."""
    rows = query("SELECT sql FROM sqlite_master WHERE type = 'table' AND name = 'orders'")
    return rows[0]["sql"] if rows else "orders table not found"


if __name__ == "__main__":
    mcp.run(transport="stdio")

是什么让演示服务器区别于可部署的服务器

编写能用的工具只需要一个下午。而编写你敢让 AI 助手指向客户生产数据库的工具则是另一回事，而这正是真正让你配得上这个职位头衔的部分。上面代码中有四处正是在做这些工作。

连接是只读的，由数据库强制执行

以

file:{path}?mode=ro

方式打开意味着即使某个工具出错，或者以后有人添加了一个尝试写入的工具，写入也无法发生。针对示例数据库测试，删除操作会在引擎层被拒绝：

>>> query("DELETE FROM orders")
OperationalError: attempt to write a readonly database

在你能触及的最低层强制实施安全。只读数据库用户更好，因为它在你的代码被替换后依然有效。

每个查询都使用参数化

模型会选择你工具的参数，而这些参数来自它被给予的文本，其中可能包含用户或文档故意放入的内容。将工具参数视为不可信输入，就像对待网页表单一样。使用

?

占位符时，注入尝试只是一个匹配不到任何内容的字符串：

find_order("ORD-1001' OR '1'='1")
-> No order found with ID ORD-1001' OR '1'='1.

切勿通过插值工具参数来构建 SQL。这是快速编写的 MCP 服务器中最常见的严重错误。

输入通过允许列表进行验证

orders_by_status

会对照一组已知状态检查状态，并返回有用的提示信息，而不是直接用收到的任何内容进行查询。这为模型提供了可以据此行动的纠正信息：

orders_by_status("banana")
-> Unknown status 'banana'. Use one of: cancelled, delivered, pending, shipped.

输出是有界的

fetchmany(MAX_ROWS)

对每个结果都设置了上限。对真实客户表执行无界查询，返回的数据量将远超上下文窗口的容量，而每一个 token 你都要付费。限制行数，只选择所需的列，并在服务器端进行汇总，而不是把原始表格直接发给模型。

一个你不应在生产环境中才发现的风险

MCP 服务器是你交给模型的一组能力，而模型会读取不可信的文本。如果模型处理的文档、电子邮件或网页中包含指令，这些指令就可能影响它调用哪些工具以及使用什么参数。这就是提示注入，而给模型真实的工具会大大提高其风险。

实用的防御措施并不花哨，而且与安全领域文献反复得出的结论一致：保持每个工具的职责狭窄，而不是暴露一个通用的

run_sql

，在数据层而非提示词中实施权限控制，对有重大影响的操作要求人工确认（

elicitation/create

正是为此而设计的），记录工具调用及其参数以便事后可还原事件，并且在写入确实无法避免之前优先使用只读访问。MCP 文档中有一页

security best practices

内容值得在任何客户部署之前阅读。

我们在 Jev 与结构化 AI 决策一文中介绍过一个具体的、有据可查的注入文本影响 AI 系统决策的例子。

什么时候不该构建 MCP 服务器

下面是一份合理的清单，因为当前的热情似乎让人想为一切都构建一个：

  • 只有你自己的应用需要这些数据。 如果没有外部 AI 客户端会使用它，一个普通的内部函数更简单、更快。
  • 任务只是单个确定性步骤。 如果答案总是用相同参数执行的相同查询，那就写个脚本并定时运行。让模型参与其中只会增加成本和不确定性。
  • 数据不能离开其环境。 在构建之前而非之后，弄清楚模型在哪里运行以及合规立场是什么。这个问题扼杀的企业 AI 试点比任何技术问题都多。
  • 底层 API 本身才是难点。 MCP 只是标准化了访问方式。它无法修复一个缓慢、缺乏文档或不可靠的上游系统，用协议包装它也不会让它变得可靠。

下一步该做什么

在这个之后值得构建的三样东西，按能学到多少排序：一个通过 HTTP API 而非数据库提供服务的服务器，这会迫使你处理超时、重试和速率限制；同一个服务器改用 Streamable HTTP 传输并加上身份验证，这是远程部署真正需要的；以及一个带有写入工具且受

elicitation/create

限制的服务器，在这里你会体会到确认设计有多重要。

什么是 MCP 服务器？

MCP 服务器是一种程序，它通过 Model Context Protocol 让 AI 应用能够访问某个特定系统，例如数据库、文件存储或内部 API。它将该系统暴露为 AI 可以调用的工具、可以读取的资源以及可以复用的提示，并且任何 MCP 宿主（如 Claude Desktop、Claude Code 或 VS Code）都可以连接到它，而无需自定义集成代码。它可以在本地通过 stdio 运行，也可以通过 Streamable HTTP 远程运行。

什么是 MCP（模型上下文协议）？

MCP 是一个开放标准，用于将 AI 应用连接到数据库、API 和文件等外部系统。官方文档将其比作 AI 的 USB-C 接口：你只需构建一个服务器，任何兼容 MCP 的客户端都可以使用它，而无需为每个助手编写定制集成。

MCP 解决了什么问题？

在 MCP 出现之前，将 AI 助手连接到某个系统意味着要为该特定助手编写专门的集成。MCP 将接口标准化，因此一个服务器可以与任何兼容的客户端配合使用。当多个 AI 应用需要访问相同的系统时，这能显著减少集成工作。

MCP 服务器可以暴露什么？

三种原语。工具（Tools）是模型可以调用的可执行函数，例如数据库查询。资源（Resources）是模型可以读取的数据，例如模式或文件内容。提示（Prompts）是用于构建交互的可复用模板。工具是动词，资源是名词，提示是菜谱。

MCP 主机、客户端和服务器有什么区别？

主机是 AI 应用，例如 Claude Desktop 或 VS Code。客户端是主机内部维护一条专用连接的连接器。服务器是你编写的、提供上下文和操作的程序。主机为它连接的每个服务器创建一个客户端。

我需要哪个 Python 版本和 SDK？

mcp Python SDK 目前版本为 2.2.0，要求 Python 3.10 或更高版本。使用 uv add "mcp[cli]" 或 pip install "mcp[cli]" 安装。服务器类的导入方式为：from mcp.server import MCPServer。

当前的 MCP 协议版本是什么？

撰写本文时为 2026-07-28。该版本使 MCP 成为无状态协议，引入了强制性的 server/discover 请求，并弃用了采样（sampling）和日志（logging）。描述服务器端采样的教程是基于较旧的协议版本编写的。

MCP 支持哪些传输方式？

两种。stdio 传输将服务器作为本地进程运行，通过标准输入和输出进行通信，Claude Desktop 对本地服务器使用的就是这种方式。Streamable HTTP 传输使用 HTTP POST 以及可选的 Server-Sent Events，用于服务多个客户端的远程服务器。

MCP 只适用于 Claude 吗？

不是。MCP 是一个得到广泛支持的开放协议。Claude、ChatGPT、VS Code、Cursor 等工具都可以作为 MCP 主机。这个标准的意义在于你只需构建一次服务器，它就能在所有兼容的客户端上工作。

如何将我的 MCP 服务器连接到 Claude Desktop？

在 claude_desktop_config.json 的 mcpServers 键下添加它，提供命令以及项目目录的绝对路径，然后重启应用。如果服务器没有出现，通常原因是 uv 不在桌面应用可见的路径中，因此请使用 which uv 返回的绝对路径。

将 AI 助手连接到生产数据库安全吗？

只有在采取审慎控制措施的情况下才安全。使用只读连接或数据库用户，对每个查询进行参数化，根据允许列表校验输入，限制返回的行数，让每个工具保持窄范围而不是暴露通用 SQL 执行，记录每次工具调用，并对有重大影响的操作要求人工确认。

MCP 工具参数会被用于 SQL 注入吗？

会，如果你通过字符串拼接构建 SQL。模型是从它收到的文本中选择工具参数的，其中可能包含被刻意放置的文本，因此要把每个参数都当作不可信输入。使用占位符的参数化查询会让注入尝试变成一个匹配不到任何内容的普通字符串。

在 MCP 的语境下，什么是提示注入？

当模型处理包含指令的不可信文本时，这些指令可能影响它调用哪些工具以及使用什么参数。给模型真实的工具会提高风险。防御措施包括窄范围工具、在数据层而非提示中强制执行权限、日志记录，以及对有重大影响的操作进行人工确认。

什么是 MCP 中的引导（elicitation）？

引导是一种客户端原语，允许服务器通过 elicitation/create 方法向用户请求更多信息或确认某个操作。它是将写入或其他有重大影响的操作置于明确人工批准之下的正确机制。

为什么采样（sampling）和日志记录（logging）被弃用了？

两者都在协议版本 2026-07-28 中被弃用。以前通过采样请求模型补全的服务器现在被指引直接集成 LLM 提供商的 API，而使用协议日志记录的服务器应在 stdio 上将日志输出到 stderr，或改用 OpenTelemetry。

什么时候不应该构建 MCP 服务器？

当只有你自己的应用需要这些数据且不会有外部 AI 客户端使用它时；当任务是一个单一确定性步骤、用脚本更合适时；当合规要求阻止数据离开其环境时；或者当底层 API 本身不可靠时。MCP 标准化的是访问方式，它无法修复糟糕的上游系统。

为什么前沿部署工程师需要了解 MCP？

因为它现在已被直接写进职位要求。Anthropic 的前沿部署工程师招聘中列出了交付 MCP 服务器和面向生产工作流的 Agent 等技术产物，并部署在客户系统内部。MCP 正在成为将模型连接到客户现有系统的标准方式。
