Celonis FDE 与部署工程师对比：各自的职责是什么

原标题：Celonis FDE vs Deployment Engineer: what each does

FDE Times · 2026-11-25 · 约 6 分钟读完

摘要

文章分析 Celonis 的招聘信息，指出其 FDE 头衔实际对应 Value Engineer（价值工程师）角色，负责客户全生命周期（获取、扩展、采用、续约），要求母语级法语或德语；而真正的技术部署工作归 Deployment Engineer，负责指挥 AI Agent Apollo 构建数据模型、KPI 和仪表盘，只需英语。作者提醒求职者不要只看头衔，应阅读职位描述中的职责动词，判断岗位实质，并据此准备简历与面试。

要点

  • Celonis 的 FDE 实为价值工程师，负责客户全生命周期。
  • Deployment Engineer 才做技术部署，只需英语。
  • 部署工程师指挥 Apollo Agent 构建模型与仪表盘。
  • Agent 输出需人工核对，避免数据错误。
  • 求职应看职责动词而非头衔。

大多数工程师听到 FDE 时想到的动手实操工作，其实属于另一个头衔——部署工程师（Deployment Engineer），由 AI Agent 构建仪表板，而且只需会英语。

简要总结

  • 巴黎的高级 FDE 招聘信息将该职位描述为价值工程师。该职位与慕尼黑的 FDE 招聘信息都负责完整的客户生命周期：签约、扩展、采用、续约。
  • 部署工程师招聘信息负责的是动手实操工作：指挥 Apollo Agent 构建数据模型、KPI 和仪表板。它只要求英语。
  • 在申请之前，请阅读招聘信息正文中的职位描述及其职责动词，因为职位头衔并不能告诉你实际会做什么。

Celonis 正在巴黎招聘“高级前沿部署工程师”。在招聘信息的几行之后，该职位以另一个名称出现：价值工程师，即端到端负责客户价值旅程的人。

与此同时，名为部署工程师的招聘信息描述的正是大多数工程师听到 FDE 这几个字母时想到的工作。首席部署工程师招聘信息称受聘者是直接负责在客户处部署 Celonis 的人。部署工程师招聘信息则将指挥 AI Agent 构建数据模型和仪表板的工作分配给该职位。

这一点很重要，因为在同一家公司内，这两个头衔要求两种不同的技能组合。仅凭头衔选择工作的人，可能会申请错误的职位、准备错误的面试，并在一年后发现实际工作与自己的预期完全不同。

在 Celonis，FDE 头衔对应的角色负责完整的客户生命周期

巴黎的 FDE 招聘信息用四个动词概括其职责：签约、扩展、采用、续约。慕尼黑的“前沿部署工程师 – CPG/零售”招聘信息也使用了同样的四个词。这是客户账户的语言，而不是部署项目的语言。

慕尼黑的招聘信息从未使用“价值工程师”这一术语。但完全相同的动词组合表明，这两条招聘信息描述的是同一类角色，尽管只有巴黎明确写出了名称。

扩展意味着扩大客户对产品的使用范围。续约意味着延长合同。当这两个词出现在职位描述中时，受聘者的责任一直延伸到客户是否留存并购买更多，远远超出让系统运行起来的范畴。

Celonis 自己的招聘网站证实了这一解读。一篇介绍价值工程团队的帖子说，价值工程师端到端负责每一位 Celonis 客户的完整价值旅程。

同一网站上的另一篇帖子描述了日常工作：构建演示、商业案例和价值验证项目，并将 CEO 的战略目标转化为高影响力的用例。

巴黎的职位描述对方法说明得更具体。Value Engineer 负责主持业务价值工作坊，并使用 Celonis 来发现、然后验证流程改进机会。

语言要求清楚地表明了这个岗位的性质。巴黎的职位要求母语水平的法语；慕尼黑的职位要求母语水平的德语。慕尼黑还解释了原因：入职者必须用德语主持工作坊、向高管汇报并与利益相关者合作。

Deployment Engineer 负责技术工作

Lead Deployment Engineer 的职位描述让入职者直接负责客户的部署工作，包括主持需求探索工作坊。在技术方面，要求掌握 SQL 和 Python。对 ERP 的要求也写得非常详细：SAP MM/SD/PP、S/4HANA、APO/IBP，或 Oracle、Kinaxis、o9 和 Blue Yonder 等同类系统。

发布在 Accel 招聘板上的 Deployment Engineer 职位要求掌握 PQL（Celonis 的流程查询语言），以及 SQL 和 Python。它还要求具备 ERP 知识。

最能说明问题的是语言要求。Deployment Engineer 的职位只要求英语，其他语言为加分项。对于既不会德语也不会法语的工程师来说，这是两个头衔之间最大的区别。

当 AI Agent 构建仪表板后，你的工作是检查它

Deployment Engineer 的职位描述说，工程师指挥 Celonis 名为 Apollo 的部署 AI Agent 来构建数据模型、流程分析、KPI 和仪表板。如果 AI Agent 完成了大部分构建工作，工程师的时间就转向向 AI Agent 下达指令、审阅其输出，并在数字出错时向客户作出解释。

举一个假设的例子。客户在 SAP 中有 1,000 行订单，每张订单分 2 次发货。AI Agent 将订单表直接连接到发货表，而没有按订单分组，结果返回了 2,000 行。此时准时交付 KPI 是按发货而不是按订单计算的，而仪表板看起来仍然完全合理。

只会向 AI Agent 写提示词的工程师会把这个数字直接带进客户会议。而理解数据模型的工程师会在连接前后核对行数，发现数字翻倍并追问原因。

在真实客户现场，第一步是核对几个业务用户烂熟于心的数字，比如上月的订单总数，然后才能信任任何图表。

同样的流程挖掘根基，坐在桌子对面的人却不同

下表将三组职位描述的要求并排列出，差异一目了然。

逐行来看，共同点在于客户的系统：Lead、部署工程师和慕尼黑的职位描述都提到了 ERP 或 SAP 式企业软件。

工作坊出现在 Lead 职位描述和两个标注为 FDE 的职位描述中，区别在于坐在桌子对面的人是谁。探索工作坊服务于构建解决方案；价值工作坊和高管汇报则服务于说服客户继续投入资金。

流程挖掘对候选人有什么要求？

纵观这三组职位描述，技能要求分为三个层次。底层是 SQL、Python 以及构建数据模型的能力。中层是 PQL，这是一项与 Celonis 产品紧密相关的技能。顶层是理解业务流程如何在 ERP 中运行，从采购、销售到生产计划。

后端工程师通常已经具备底层能力。如果你的德语或法语达不到母语水平，进入 Celonis 的现实路径是部署工程师职位，该职位只要求英语；在申请之前，学习 PQL 并深入研究一个 SAP 模块，例如 MM 或 SD。

要瞄准 FDE 这个标签，你需要一些技术文档无法教给你的东西：用客户的母语主持价值工作坊并构建商业案例的能力。

像读合同一样读职位描述

第一条建议适用于任何公司：在职位描述正文中找到角色说明。Celonis 在其巴黎 FDE 职位描述中直接写明了“Value Engineer”，只看标题的人会错过这一点。

接下来，数一数职责动词。如果职位描述提到 build、data model 和 dashboard，那就是部署类职位。如果出现 expand 和 renew，就直接问招聘人员这个职位的成功如何衡量。

对于部署工程师职位，你的简历应该展示你知道如何验证自动化输出。一条好的要点应说明你在 ERP 数据中发现了什么错误、如何发现的，以及因为数字正确客户做出了什么决策。

在 Celonis，FDE 标签和部署工作分属两个不同的职位描述。申请之前，不要只看标题，要看实际的工作内容，然后选择成功衡量标准与你希望被评判的标准相匹配的职位。
