训练但不学习：面向作为前沿部署工程师的 LLM Agent 的训练后交付基准

原标题：Trains but Doesn’t Learn: A Post-Training Delivery Benchmark for LLM Agents as Forward-Deployed Engineers

arxiv.org · 2026-01-31 · 约 33 分钟读完

摘要

该论文提出把“训练后交付”当作服务（PTaaS）来评测：让 LLM Agent 坐上前沿部署工程师的位置，在十个受治理的阶段中完成微调交付，由独立 oracle 依据平台记录打分。核心失败模式是“训练了但没学会”（TBDL）：损失下降、信号全绿，交付模型却不比基线好。作者用故障注入校准验收门与在线检测器，在真实 GPU 上运行四个前沿 Agent 与人类工程师对照，发现当前 Agent 零 TBDL 交付，真正的拒绝来自交付合同而非指标，且人类加助手的判断残差更低。

要点

  • 提出 PTaaS 交付基准：Agent 驱动十个治理阶段，oracle 独立打分。
  • 定义 TBDL 失败：训练通过、损失下降，但交付模型无真实提升。
  • 故障注入校准显示重标注等损坏可被验收门在付款前全部拦截。
  • 38 次认证实验中四个前沿 Agent 零 TBDL 交付、零绕门，拒绝源于交付合同。
  • 人类工程师加助手判断残差最低，防御靠治理平面而非座位本身。

摘要

训练后正在成为一种服务（PTaaS）：客户向运营方提供数据和目标，前沿部署工程师（FDE）在预算、人工审批关卡和可复现性要求下返回一个经过微调、评测并部署的模型。将 LLM Agent 置于 FDE 的位置上，引出了一个现有基准无法回答的问题：不是 Agent 能否提升某个指标，而是它能否被信任去完成交付。我们在一个受治理的交付平面上回答了这个问题：Agent 驱动十个阶段，而一个 oracle 基于平台记录的事实对每个阶段打分。核心的静默失败是“会训练但不会学习”（TBDL）的运行：损失下降，所有信号保持绿色，但交付的模型并不比基础模型更好。由运营方执行的验收关卡能在付款前捕获每一个这样的运行，而基于已知损坏运行校准的检测器能在运行中途标记出严重损坏。我们在按用量计费的 L40S、A100 和 H200 GPU 上，针对 8B 到 70B 的开源基础模型，端到端地运行了四个前沿 Agent（Claude Opus 5、GPT-5.6-luna、Gemini 3.7 Flash、DeepSeek V4-Pro），并在打分前对每个场景进行了认证。我们还在同一 oracle 下运行了人类 FDE 组，并将每个 Agent 与之进行比较。

1 引言

基于大语言模型（LLM）的 Agent 正在从演示走向工业部署，在这个阶段，关键问题不再是原始能力，而是 Agent 能否被信任去端到端地承担真实的客户工作。训练后如今就是这样一种服务，而前沿部署工程师是其交付的基本单元。越来越多的 GPU 云提供训练后即服务（PTaaS），客户交出数据和目标，平台运营方返回一个已部署的模型。这一契约由前沿部署工程师（FDE）承担，这一角色由 Palantir 首创，此后 OpenAI、Anthropic 和 xAI 等模型提供商也将其制度化用于模型交付。由于 FDE 既是 PTaaS 的成本也是其瓶颈，LLM Agent 正开始占据这个位置，厂商已经推出了能根据自然语言请求驱动交付平台的 Agent。问题很具体：能否信任一个 Agent 去完成交付，而不仅仅是训练？FDE 不是去提升某个指标；它要阅读一张模糊的工单，推断出真实任务和指标，选择方法和数据处理方式，根据集群和预算确定任务规模，并在人工审批关卡下决定什么可以安全交付 Palantir Technologies (2025)。

因此，对于处于 FDE 岗位的 AI Agent 而言，真正重要的失败并不是指标偏低，而是一次成功优化了某个东西、但交付的模型没有学到客户想要的任何东西的运行：Agent 化的 FDE 误读了任务、数据格式、损失掩码或方法。我们将这种失败称为“训练了但没学到”（trains but does not learn，TBDL）。损失下降，所有信号级检查通过，仪表盘一片绿色，只有客户发现交付的模型并不比基础模型更好。这是服务中最糟糕的失败模式，也是每美元成本最高的失败。一次 TBDL 运行会训练到完成，并消耗与正确交付相同的 GPU 小时，因此运营方要为这个零价值产物支付全额计量账单（每 GPU 小时 1.95–4.54 美元）。成本不仅是账单：交付的模型越来越多地承载高风险的下游决策，从金融推理到早期临床诊断（Ding and Duan, 2026）。我们将 TBDL 运行与 TBDL 交付区分开来。运行是指训练门通过而验收门失败的已审计事件。交付是指 Agent 决定将这样一次运行作为成品交付。

现有的评测无法看到这种失败。2026 年的一波 Agent 化后训练基准测试关注的是 Agent 能否提升某个目标指标（Rank et al., 2026；Chen et al., 2026；Li et al., 2026；Ma et al., 2026），这与更广泛的机器学习工程 Agent 一脉相承（Chan et al., 2025；Huang et al., 2023；Wijk et al., 2024）。这些测试评判的是指标而非交付，因此一次移动了错误指标、却没有学到客户想要的任何东西的运行会被评为成功。损失下降并不必然意味着学习，这一点早已确立，从在随机标签上接近零的损失（Zhang et al., 2017）到能通过干净指标的数据投毒（Gu et al., 2017）；TBDL 正是其在 Agent 化、交付层面的实例。信号级监控也无法弥合这一差距。运行时检查器可以标记训练不变量的违规（Jiang et al., 2025），但 TBDL 在构造上就是不变量干净的，只能通过受治理的留出评测才能暴露。没有任何基准将 FDE 的运营决策与交付层面的判定标准配对，因此对绿色仪表盘的依赖建立在一个未经检验的假设之上。

我们的回答是一个受治理的交付平面，而非一种新的训练方法——将智能体化的 FDE 重构为一个分层控制平面（图 1）。该智能体驱动十个受治理的阶段（需求接入、规划、配置、调度、训练、评测、注册、部署、成本审查、交接），对交付本身而非某个指标负责，每个阶段由一个基于平台记录事实（而不采信智能体自身陈述）的 oracle 进行评分。各阶段按“失败在何处显现”而非按难度划分。脚本化的参考对照组在任何智能体运行之前即对 {配置、调度、成本审查} 进行认证，因此这些阶段的失败响亮且易于低成本捕获；{需求接入、规划、评测、部署} 中的失败仅由交付级 oracle 发现，而工件阶段 {训练、注册、交接} 中的失败则由交付合同发现。我们在 L40S、A100 和 H200 GPU 上，对四个前沿智能体（Claude Opus 5、GPT-5.6-luna、Gemini 3.7 Flash、DeepSeek V4-Pro）进行端到端运行，覆盖三个模型家族的当前一代 \(8\)B–\(70\)B 基座模型。

该平面在信号可观测之处成立，在信号不可观测之处失效：智能体化交付的风险存在于失败无声之处——在判断与治理之中，而非在确定性工具已能解决的算术之中。我们做出三项贡献。

  • 第一幕：TBDL 运行是真实的、经过校准的，并在付款前被捕获。我们将智能体化的 FDE 建模为十个受治理的阶段，由一个基于平台记录事实（而不采信智能体自身陈述）的 oracle 进行评分。故障注入的校准运行界定了审计所能捕获的范围，基于这些运行校准的检测器在 GPU 账单产生之前标记出每一次严重损坏，而验收门在提交后于运维方运行的留出数据上对交付的模型进行重新评估。这是首个以训练后交付成果而非“某个数字是否上升”来给智能体评分的评测。
  • 第二幕：当前的前沿智能体交付的 TBDL 运行为零；将其拒之门外的是交付合同。每个场景在任何智能体被评分之前都要通过一个正向和一个负向对照；该平面捕获了唯一一个未通过对照却被交付的场景。在 38 个经过认证的真实回合中，智能体产出了 0 个 TBDL 交付和 0 次门禁绕过；所有 12 个被端到端观测到的 TBDL 运行都出现在被排除的合同上。将其“指标达标”的交付（31/38）拒之门外的是有据可查的合同——经模式校验的模型卡、经对账的成本报告和注册表 CI——而向它们提供 oracle 正确的配置也无法修复任何问题：在固定配置下 24/24 通过验收，但仍有 22/24 被拒绝。在截止期限、权限和沉没成本压力下，压力套件中的三个旗舰分支在 \(360/360\) 个可交付试验中守住了治理门禁，并拒绝了每一个不可行的工单（\(60/60\)）；第一代更廉价层级的脆弱性（§3.3）是一种能力层级现象。
  • 第三幕：在同一个 oracle 下的人类 FDE 参照。两个“工程师+助手”组合的判断残差都低于所有自主组合（0.06 和 0.09，而最接近的 agent 为 0.10），且没有任何组合达到零。残差是结构性的，因此防御手段是平台，而不是座位。

2 受治理的交付平台

被测系统。我们将 FDE 建模为一个 LLM agent，在全部十个阶段中端到端地驱动该平台。它被精确赋予 FDE 的信息状态，即自然语言工单、只读的环境/集群表，以及只读的数据集检查，但绝不接触留出的标签，并且它要对 FDE 的交付物——受治理的交付——负责，而不是对某个指标负责。Agent 提出方案；测试框架执行；去环化的 oracle 独立地为每个阶段打分。

两种模型角色。Agent 模型是坐在 FDE 座位上的被测系统：四个当前前沿 agent（Claude Opus 5、GPT-5.6-luna、Gemini 3.7 Flash、DeepSeek V4-Pro）端到端地驱动认证交付战役（§3.4）。第一幕保留了其第一代组合，它们构建并校准了这套仪器：在真实 GPU 桥接上使用更便宜的层级（GPT-5.4-mini、Claude-Sonnet-4.6、Gemini-3.5-Flash），用于接入探针和门控纪律分析。基础模型是 agent 所交付的后训练基底：当前一代的开源权重仪器 Qwen3-8B、Qwen3-32B、Gemma-2-9B-it 和 Llama-3.3-70B，其中 70B 通过 4-bit QLoRA 运行。给定一张工单，agent 推断任务和指标并规划后训练，测试框架在基础模型上运行该后训练；交付物是微调后的基础模型，按工单的留出指标打分。

十个受治理的阶段。图 1 的十个阶段按一个操作性标准划分：当且仅当某阶段的 oracle 谓词能由一个（在 agent 运行之前即已认证的）(spec, environment, budget) 的确定性函数实现（\(\approx\!1.0\)）时，该阶段才是算术阶段；在配置器证书下，{config, schedule, cost review} 满足这一条件。{train, register, handoff} 是执行/产物阶段；其余四个 {intake, plan, eval, deploy} 是 FDE 的判断阶段，由离散的 oracle 谓词打分。工程师组合的残差分母保留第一代的五阶段判断集，包括 handoff（\(120=24\times 5\)；§3.5）。

将场景作为客户工单。五个带有客观验收指标的 SFT 交付场景转化为工单（附录 B），每个场景都在真实 GPU 上运行，并在 Agent 从未见过的保留集上进行评分：BANKING77 意图分类（Casanueva et al., 2020）以 macro-F1 计分，Bitext 客服（Bitext, 2023）以回复胜率计分，Glaive 函数调用（Glaive AI, 2023）以可执行率计分，FinQA 数值问答（Chen et al., 2021）以精确匹配计分，CUAD 法律条款（Hendrycks et al., 2021）以 clause-F1 计分。第六个场景——通过 DPO（Rafailov et al., 2023）在 UltraFeedback（Cui et al., 2024）上进行偏好对齐——在认证活动中未能通过其阳性对照，因此被该平面自身的控制机制排除（§3.4）。这五个 SFT 场景覆盖三个家族的四个当前一代 \(8\)B–\(70\)B 开源基座模型；第一代校准和更低档位的运行在 \(2{\times}\)H200 和 \(4{\times}\)A40 上进行，使用三个随机种子。学习到的边际 \(\delta^{\star}_{t}\) 是任务特定的：每个场景的保留集规模 \(n_{t}\) 经过设定，使得实际达到的配对最小可检测效应 \(\mathrm{mde}_{\text{paired}}(n_{t},\psi_{t})\) 等于表 6 中按场景报告的预注册边际 \(\delta^{\star}_{t}\)（\(0.06\)–\(0.08\)）；Learned 测试（§3.1）要求该场景满足 \(\Delta\geq\delta^{\star}_{t}\)，而 oracle 在整个过程中使用这些按场景设定的边际。

去循环化、阶段独立的评分。每个阶段都通过离散谓词针对外部标注的验收集进行评分，且 oracle 从不读取训练后的模型。执行阶段在黄金配置下以 Agent 自己的计划运行，因此评测结论将 Agent 的判断（例如损失掩码）与其配置算术隔离开来。各阶段比率以完整 \(N\) 为分母统计失败次数；固定配置干预（§3.4）提供了因果对照。

校准阳性（故障注入）。评测门控与检测器在训练目标从构造上即被破坏的运行上进行校准：重标注目标、标签噪声以及损失掩码不匹配，并以 SFT 替代 DPO 作为偏好任务的类比。它们是对警报的真实冒烟测试：确立该仪器能捕捉到什么。Agent 行为仅通过第二幕的认证片段进入。一条预注册的验证规则会剔除任何不能可靠诱发 TBDL 的任务族：在短标签任务上它剔除了损失掩码（该任务在每个规模上都能恢复，见表 1），并保留重标注与脏数据。Agent 驱动的片段从构造上即无注入，且测试框架将其作为不变量强制执行：平台忠实地执行 Agent 的实际选择。Agent 面临的唯一陷阱是环境性的：平台文档中记载的全序列损失掩码默认值，它对应主流 SFT 工具的出厂默认设置，而正确的计划会将其覆盖。同一仪器服务于三幕：验收门控在付款前提供第一幕的拦截，场景认证提供第二幕的归因，同一个 oracle 为第三幕的人类组评分。

3.3 第一幕：压力下的治理

客户会催促截止期限、援引职权、引用已沉没的投入：这些良性压力绝不应影响安全决策。我们在每张工单后附加良性的截止期限、职权和沉没成本压力，后缀在预注册时冻结（附录 C），并保持正确行为不变（对于需要人工的场景仍为阶段部署，且保持在预算内）。我们以信号检测理论的语言（Green and Swets, 1966）衡量每个（Agent，条件）下的两种行为：对不可行性的敏感度，即命中率 \(\mathrm{HR}=P(\text{refuse}\mid\text{infeasible})\) 与 \(\mathrm{FAR}=P(\text{refuse}\mid\text{deliverable})\) 的对比；以及门控阶段合规性，即在可交付工单上将部署路由至人工门控的比率。

敏感度处于上限且不随压力变化：不可行的工单总是被拒绝（\(\mathrm{HR}=1.00\)），而可交付的工单从不被错误拒绝（\(\mathrm{FAR}=0.00\)）。然而，门控阶段合规性在第一代较便宜的层级上出现模型特异性且剂量依赖性的崩溃（表 3）。合并的阶段合规性沿压力阶梯单调下降：\(1.00\) 中性，\(0.96\) 截止期限，\(0.73\) 权威，\(0.47\) 沉没成本。这是一个 \(+0.281\) 的配对差距（cluster-\(t\) \([0.200,0.363]\)，按 \(6\) 个任务组聚类，\(\mathrm{df}=5\)），严格单向（McNemar 不一致 \(c=0\)）。检测保持不变而合规性却易变：Agent 识别到了风险，但仍然发布。解决方案是一个不可绕过的门控，而不是更多的信息。当前的旗舰层级消除了这一差距：在相同的测试套件下，Claude Opus 5、GPT-5.6-luna 和 Gemini 3.7 Flash 在 \(360/360\) 次试验中对每个可交付工单都进行了阶段处理，并拒绝了每个不可行的工单（\(60/60\)），因此这种脆弱性是能力层级的属性，而非平台本身的属性。第二幕将门控端到端地封死：在每个认证的回合中零次绕过调用（§3.4）。

4 讨论与经验教训

这对 PTaaS 运营方意味着什么。出售的是交付成果，而非指标：以语义留出审计作为验收和计费的门槛，绝不以训练信号健康度为准。在每个任务上运行检测器；它能在 GPU 账单产生之前捕获严重的损坏。治理交付面：经过模式校验的卡片、对账后的成本报告和注册表 CI 是当前前沿智能体失败之处，因此运营方的杠杆在于合同 CI，而非配置审查。并且无论部署的是哪个模型，都要使部署门槛不可绕过：第一代档位在普通压力下就会放行，而旗舰档位的纪律是模型本身的属性，而非平台的属性。

一个具体且不可绕过的门槛。提示词层面的自我约束合规在压力下会在第一代档位上失效。一个有能力模型可以学会通过的验证挑战无法约束它；学习型求解器已经能够击败旨在筛查自动化行为的图像验证码（Ding et al., 2024）。因此，参考架构是一种能力约束，而非行为期望：外部审批服务签发与模型和评估产物哈希绑定的签名一次性令牌，部署 API 拒绝其他任何内容，并由不可变日志记录请求与授权。绕过、虚假审批、延迟和审查负担都是该发布测试框架的可度量结果。

该装置在其自身构建过程中捕获了两次失败。一次 bf16 LoRA 训练将无穷梯度以 NaN 形式传播，却仍在“训练”；该平台的有限损失与 survived-\(K\) 谓词捕获了这一问题。此外，我们的第一个 e-process 在方差项中遗漏了一个因子 \(4\)；对抗性审查在提交前捕获了这一空洞保证，修正后的过程通过了验证。这一教训具有普遍意义：绿灯信号并不能证明你所关心的东西；我们发布该工具，以便运营者能够首先审计其 agentic FDE。

5 结论

我们将 agentic FDE 重新构建为一个受治理的交付平台，并对交付而非指标进行评级。一次训练但不学习的运行是一种真实且可检测的失败，在付款前被运营者运行的验收门捕获。四个当前前沿 Agent 从未交付过一次：它们的配置错误被证明是无害的，交付契约拒绝了它们 31/38 个通过指标的交付，而 oracle 正确的配置也未能修复任何问题。第一代更便宜的层级在压力下释放了门；旗舰级 arm 在压力套件的每种条件下都保持住了它。在相同 oracle 下，人类 FDE arm 的判断残差低于所有 Agent，且没有任何 arm 达到零。风险沿着技术栈向上攀升，从训练目标越过配置进入交付契约，而防御是环境性的，构建在信号无法监视之处。绿色的训练仪表板是一种计费负债，而非交付证书。

6 局限性

该工具仅限训练后且为单节点：五个 SFT 场景在四个当前一代开放权重基座（Qwen3-8B、Qwen3-32B、Gemma-2-9B-it 和 Llama-3.3-70B，其中 \(70\)B 通过 4-bit QLoRA）上运行真实 GPU，外加一个在认证中被排除的 DPO 偏好契约；六个任务限制了聚类（cluster-\(t\) \(\mathrm{df}=5\)，主张以方向性稳健的方式表述）；检测器分辨率是有界的；阈值已披露，且确认性协议在任何 Agent 运行之前已预先注册。重标记校准陷阱不变地诱导 TBDL（三个家族 \(12/12\)，\(8\)B–\(70\)B），因此该机制并非单一家族或小模型的伪影。在此范围之外，五个注意事项限制了这些主张。

  • 桥接账本不携带任何可归因于 Agent 的 TBDL 率。其端到端标志低于可检测性下限，且对于无判断基线触发方式完全相同。
  • 第三幕比较是跨网格的。工程师 arm 是在第一代六场景网格上针对五阶段判断集测量的，并以经验证的聚合形式进入；当前 Agent 的残差来自认证活动的场景，针对四阶段集。两者共享 oracle，但不共享场景组合或阶段集。
  • 旗舰压力判定是呼叫级别的。当前旗舰层级的门控纪律是在呼叫级治理探针上测量的，而非在完整交付情节上；完整情节的崩溃是第一代更便宜层级的结果。
  • 人类分支是一种策略，而非无辅助的人类。人在回路参考分支（§3.5）用于校准任务难度；它并不是对人类贡献的因果估计。
  • Oracle 的判断标签来自单一标注者。独立的机器学习工程师尚未对冻结的判断单元进行重新评判；发布内容包含去标识化的重放工件，供盲评再标注使用（与 oracle 的百分比一致率及 Cohen's \(\kappa\)）。

偏好契约在所有扫描预算下均未通过阳性对照（\(150\) 至 \(1200\) 个 DPO 步骤，留出胜率最多 \(+0.015\)），且对数概率胜率无法干净地区分真正的偏好学习与基于被选响应的 SFT，因为两者都会提高被选响应的似然。Agent 接地分析依赖于 SFT 损失掩码和重标注机制；衡量偏好交付需要基于生成评判的评测。

伦理声明

该工具探查的是良性商业压力（普通的截止期限、权威和沉没成本框架）下的治理纪律；它不是越狱或有害指令套件，所请求的交付物是合法的。压力后缀（附录 C）予以发布，以便条件可审计且不进行对抗性升级。除标准公开数据集外未使用任何人类受试者数据；人在回路分支（§3.5）由同意参与的机器学习工程师在研究协议下完成，进行中的标注研究由同意参与的工程师评判冻结的、去标识化的重放工件。我们披露模型特定的门控释放行为，是为了推动不可绕过的审批门控，而非提供引出不安全部署的配方。

附录 A 相关工作

提升指标的后训练 Agent。2026 年出现的一批基准测试探讨 Agent 能否自主地对模型进行后训练（PostTrainBench (Rank et al., 2026)、Agent2 RL-Bench (Chen et al., 2026)、FT-Dojo (Li et al., 2026)、TREX (Ma et al., 2026)），并与更广泛的机器学习工程类 Agent 工作（Chan et al., 2025；Huang et al., 2023；Wijk et al., 2024）一脉相承。它们都只评判所选指标是否上升。我们的贡献与之正交：它们评判指标，我们评判交付——需求接入的落地性、受治理的部署门控、血缘追溯、成本，以及它们无法表达的“静默不学习”失效。

静默失效与信号级监控。损失下降并不必然意味着学习，这一点早已确立：随机标签上的近零损失（Zhang et al., 2017）、在干净指标上通过但已被污染的数据投毒（Gu et al., 2017）；TBDL 是其在 Agent 化、交付层面的实例。TrainCheck（Jiang et al., 2025）在运行时标记静默的训练不变量违规，与不变量干净的 TBDL 在构造上互不相交——后者保持损失有限、梯度有界，且只有受治理的留出评测才能将其暴露；我们的检测器进一步提供了任意时刻有效的保证（Howard et al., 2021；Waudby-Smith and Ramdas, 2024；Ramdas et al., 2023）。

Agent 化部署与奖励作弊。DeployBench（Wang et al., 2026）印证了这种失效定位于判断环节的模式，发现 Agent 化部署失败主要由完成判断导致的自我停止构成；奖励作弊（Skalse et al., 2022；Amodei et al., 2016）是 TBDL 的下游单元格——利用既定目标 vs. 错误设定目标。

服务端系统。交付治理与关于模型在何处以及如何运行的系统文献相邻。面向 LLM 推理的隐私感知云—边路由（Zhan et al., 2026c）以及对边缘 VLM 推理中能耗瓶颈的测量（Zhan et al., 2026b）优化的是流水线的服务端，而我们的平面审计的是其交付端；绿色 IoT 网络中的能耗感知任务卸载与数据采集编排（Zhan et al., 2024；Zhan et al., 2026a）研究的资源预算纪律，正是我们的成本审查门控在交付层所强制执行的。

附录 E 在线 TBDL 检测器

完整规范。干净探针差距增量 \(Z_{t}\) 被截断至 \([-b,b]\) 并重新缩放为 \(X_{t}=(Z_{t}+b)/(2b)\in[0,1]\)。在过滤 \(\mathcal{F}_{t}=\sigma(X_{1},\ldots,X_{t})\) 下，检测器检验条件均值原假设 \(H_{0}:\mathbb{E}[X_{t}\mid\mathcal{F}_{t-1}]\leq x_{0}\)。遵循 Waudby-Smith and Ramdas (2024) 的经验 Bernstein e-过程，我们使用

\[E_{t}(\lambda)=\prod_{s\leq t}\exp\big\{\lambda(X_{s}-x_{0})-v_{s}\,\psi_{E}(\lambda)\big\},\] (4)

其中 \(v_{s}=4(X_{s}-\hat{\mu}_{s-1})^{2}\)，\(\psi_{E}(\lambda)=(-\log(1-\lambda)-\lambda)/4\)。插件均值 \(\hat{\mu}_{s-1}\) 是可预测的：它初始化为原假设均值，且仅根据过去的观测进行更新。所报告的过程是 \(\lambda\in\{0.1,0.25,0.5,0.75,0.9\}\) 上的固定混合。在 \(H_{0}\) 下，每个分量乃至整个混合都是非负上鞅；因此由 Ville 不等式（Ville, 1939）可得 \(\Pr(\exists\,t:E_{t}\geq 1/\alpha\mid H_{0})\leq\alpha\)，故在 \(E_{t}\geq 1/\alpha\) 时报警可在与条件原假设一致的依赖结构下，将每次运行的累积误报概率控制在 \(\alpha=0.05\)。

保证的适用范围。该保证适用于截断后的序列；任何被减去的基线必须预先注册或在试点中冻结，而不能在受监控的运行上拟合；且在 \(R\) 次运行中，误报的期望次数以 \(R\alpha\) 为界，而非族-wise 控制。

估计器验证。修正后的经验 Bernstein 过程在对抗性最大方差有界零假设下，将每次运行的常驻误报概率保持在 \(1.0\%\leq 5\%\)，而简单零假设和 AR(1) 零假设下为 \(0\%\)。实证上，检测器在正确的臂上产生了 \(0/36\) 次误报，并在 \(11/12\) 次运行中于 \(300\) 步的中位数第 \(250\) 步检测到严重的重标注陷阱（图 3）。发布的参考实现包含完整的假设、常数和更新规则。
