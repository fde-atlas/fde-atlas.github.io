用 Python 解析混乱的 CSV：FDE 编程面试指南

摘要

这篇文章以一道常见 FDE 编程面试题——解析一份脏 CSV 文件——为例，讲解完整解法：先检查编码、分隔符和表头，用 csv 模块而非手动切分，按明确规则规范化日期、金额和姓名，无法确定的值一律拒绝而非猜测，并生成带原因的拒绝报告。文章还演示了如何用文件哈希、upsert 和事务让加载可安全重跑，并引用 Palantir、Tangible、Concourse 等公司的面试资料说明这类题目的普遍性。

要点

  • 脏 CSV 考察的是客户能否信任你加载的数据。
  • 先读字节再解析：处理 BOM、cp1252 回退和分隔符嗅探。
  • 歧义值如 03/04/2026 应拒绝并询问，而非猜测。
  • 拒绝报告需含行号和原始文本，供数据源负责人处理。
  • 用哈希、upsert 和单事务保证重复运行结果不变。

为什么坏行才是重点

一个干净的文件测试的是你能否调用

csv.reader

。而一个脏文件测试的是客户能否信任你加载的内容。The Pragmatic Engineer 在 2025 年 8 月报道，时任 OpenAI 前沿部署工程负责人的 Colin Jarvis 表示，客户在需求界定阶段所描述的情况，往往与实际的数据和系统现状不符。来源 1

What are Forward Deployed Engineers, and why are they so in demand? (Gergely Orosz)

发布者The Pragmatic Engineer来源类型新闻报道 这个混乱的 CSV 正是那个差距，被缩小到一轮面试的规模。

这道题并不新鲜。一位候选人在 2016 年 10 月的 Glassdoor 评价中报告，在 Palantir 该职位的电话面试中被要求“写一个解析 CSV 文件的方法”。来源 2Palantir Technologies 前沿部署软件工程师面试问题（存档）发布者Glassdoor（由 Wayback Machine 存档）来源类型候选人个人记述 Palantir 自己的编程面试指南也告诉候选人要考虑边界情况以及代码可能出错的方式。来源 3Writing Good Code发布者Palantir来源类型公司招聘页面 我们关于 FDE 编程轮考察内容的课程 列出了哪些公司的报告指向这类实战型构建。

把每一行坏数据都当作你理应发现的问题。我们衡量答案的标准有三个部分：

  • 没有任何数据凭空消失。 每一行最终要么被加载，要么被跳过并计数，要么被拒绝并附上原因。
  • 没有任何内容被默默猜测。 一个有两种解读的值应被标记出来，而不是随意选定。
  • 有人能对结果采取行动。 拒绝报告是为拥有源系统的人而写的。

解析之前先观察：编码、分隔符和表头

先花两分钟阅读，而不是打字。三项检查可以在编码、分隔符和表头问题变成令人困惑的错误之前发现它们。

import csv, pathlib

def read_text(path):
    raw = pathlib.Path(path).read_bytes()
    for enc in ("utf-8-sig", "cp1252"):
        try:
            return raw, raw.decode(enc), enc
        except UnicodeDecodeError:
            continue
    raise ValueError("unknown encoding: ask")

def sniff(text):
    sample = "\n".join(text.splitlines()[:20])
    return csv.Sniffer().sniff(sample, ",;\t|")

字节顺序标记。 由 Windows 工具保存为 UTF-8 的文件通常以字节顺序标记开头。如果用普通的

utf-8

解码，你的第一列会被命名为

﻿id

，于是查找

id

就会失败，你会浪费十分钟。

utf-8-sig

编解码器会在标记存在时跳过它，在不存在时正常读取 UTF-8，正如

the Python docs for the utf-8-sig codec

所描述的那样。

回退编码。 如果这些字节不是有效的 UTF-8，文件很可能来自较旧的 Windows 导出。要明确说出

cp1252

几乎能解码任何字节，因此解码成功并不能证明什么。记录你使用的编码，并检查像

Café Lumen

这样的名字能否正确读取。

分隔符。

csv.Sniffer

会从样本中猜测方言，将其限制为四种可能的分隔符可以防止它选中某个字母。它仍可能猜错，或抛出

csv.Error

，所以要把表头当作真正的检验：如果必需的列不在表头中，就停下来并说“文件错误或分隔符错误”，不要硬着头皮继续。分号也是一个线索。Microsoft 的

guide to importing and exporting text files

指出，当小数分隔符为逗号时，Excel 会使用分号作为列表分隔符，所以要预期出现像 1.234,56 这样的金额。

不靠猜测来规范化日期、金额和姓名

我们的原则是：只有一种解读的就修正，有两种解读的就拒绝，并说明哪个是哪种。 多余的空白只有一种解读。

03/04/2026

则有两种。

import re
from datetime import datetime

class Reject(Exception):
    def __init__(self, reason, detail):
        super().__init__(detail)
        self.reason = reason

FORMATS = ("%Y-%m-%d", "%d.%m.%Y", "%d %b %Y")
SLASH = re.compile(r"(\d{1,2})/(\d{1,2})/\d{4}")

def parse_date(s):
    if m := SLASH.fullmatch(s):
        both = max(int(m[1]), int(m[2])) <= 12
        why = ("ambiguous_date" if both
               else "slash_date")
        raise Reject(why, f"{s!r}: order not set")
    for fmt in FORMATS:
        try:
            return datetime.strptime(s, fmt).date()
        except ValueError:
            pass
    raise Reject("bad_date", f"{s!r}: no such date")

日期。 列出你接受的格式并逐一尝试。绝不要把整列交给逐行猜测的解析器，比如

dateutil.parser.parse

，或带

format='mixed'

:

03/04/2026

会被解析成三月四日，

13/04/2026

会被解析成四月十三日，而且没有任何警告。

strptime

还会拒绝不存在的日期，所以

2026-06-31

会成为一条

bad_date

拒绝记录，而不是崩溃。当两部分都可能是月份时，斜杠日期是

ambiguous_date

；当只缺少整个文件的统一顺序时，则是

slash_date

。像 04.03.2026 这样的点分日期，在使用它们的地区按惯例是日在前；这仍然是一种假设，所以要明确说明。

import unicodedata
from decimal import Decimal

SYMBOLS = {"€": "EUR", "$": "USD", "£": "GBP"}
CENT = Decimal("0.01")
# decimal comma: decided once for this file
EU = re.compile(r"(\d{1,3}(?:\.\d{3})+|\d+)"
                r"(?:,(\d\d?))?")

def parse_money(s):
    sym = s[:1] if s[:1] in SYMBOLS else s[-1:]
    body = s.removeprefix(sym).removesuffix(sym)
    m = EU.fullmatch(body.strip())
    if sym not in SYMBOLS or not m:
        raise Reject("bad_amount", f"{s!r}")
    whole = m[1].replace(".", "")
    value = Decimal(f"{whole}.{m[2] or 0}")
    return value.quantize(CENT), SYMBOLS[sym]

def clean_name(s):
    s = unicodedata.normalize("NFC", s)
    return " ".join(s.split())

金额。 三个决定，每一个都要说出来：

  • 使用 Decimal，绝不用 float，因为货币需要精确到分。该模式最多允许两位小数，且每个金额都输出恰好两位小数，因此 €99 和 €99,00 比较相等。
  • 对整个文件一次性确定小数分隔符并加以确认。这个模式是小数逗号版本；对于小数点文件，把 \. 和 , 互换。千位分隔符只能出现在恰好三位数字之前，所以 €12.50 会被拒绝，而不会被读成一千二百五十。
  • 把货币保留为独立字段，绝不进行换算。以文件自身格式书写的美元金额，比如 $2.000,00，会以货币 USD 加载，所以在摘要中给出每种货币的计数。

姓名和邮箱。 合并空白并应用 Unicode NFC，这样同一个带重音符号的名字无论怎么输入都能比较相等。邮箱转为小写。不要把姓名转为首字母大写形式：那会破坏

McDonald

和

van der Berg

，客户会注意到的。像

Acme Ltd

和

ACME Limited

这样的近似重复姓名是另一个问题；

deduplicating fuzzy customer records

上的问题涵盖了它。

拒绝记录报告：每一行被丢弃的数据及其原因

首先，用一个函数把一行单元格转换为记录，把导出文件的列名映射到你的列名。任何失败都会抛出

Reject

.

REQUIRED = ("id", "name", "renewal", "amount")

def to_record(cells, header):
    if len(cells) != len(header):
        n = len(cells)
        raise Reject("field_count", f"{n} fields")
    row = dict(zip(header, cells))
    if empty := [k for k in REQUIRED if not row[k]]:
        raise Reject("missing_field", ", ".join(empty))
    value, currency = parse_money(row["amount"])
    renewal = parse_date(row["renewal"])
    return {
        "account_id": row["id"],
        "account_name": clean_name(row["name"]),
        "renewal_date": renewal.isoformat(),
        "contract_value": str(value),
        "currency": currency,
        "owner_email": row.get("email", "").lower(),
    }

接下来是读取循环。它记住每条记录起始的行号，因为带引号的地址可能跨越多行。

import io
from collections import Counter

def records(lines, dialect):
    reader = csv.reader(lines, dialect, strict=True)
    start = 1
    while True:
        try:
            cells = [c.strip() for c in next(reader)]
        except StopIteration:
            return
        except csv.Error as e:
            cells = Reject("bad_quotes", str(e))
        end = reader.line_num
        span = f"{start}-{end}" if end > start \
            else str(start)
        raw = "".join(lines[start - 1:end])
        yield cells, span, raw
        start = end + 1
def parse(text, dialect):
    lines = io.StringIO(text, newline="").readlines()
    rows = records(lines, dialect)
    header = [h.lower() for h in next(rows)[0]]
    if missing := set(REQUIRED) - set(header):
        raise ValueError(f"wrong file? no {missing}")
    good, rejects, skipped = [], [], Counter()
    for cells, span, raw in rows:
        try:
            if isinstance(cells, Reject):
                raise cells
            if not any(cells):
                skipped["blank_line"] += 1
            elif [c.lower() for c in cells] == header:
                skipped["repeated_header"] += 1
            else:
                rec = to_record(cells, header)
                good.append((span, raw, rec))
        except Reject as r:
            why = (r.reason, str(r))
            rejects.append((span, *why, raw))
    loaded = dedupe(good, rejects, skipped)
    return loaded, rejects, skipped

最后是重复项。完全相同的副本会被跳过。当同一个 ID 带着不同的值出现时，所有版本都会被拒绝，因为选择哪一个由客户决定。

def dedupe(good, rejects, skipped):
    first, clash = {}, {}
    for row in good:
        key = row[2]["account_id"]
        if key not in first:
            first[key] = row
        elif first[key][2] == row[2]:
            skipped["exact_duplicate"] += 1
        else:
            clash.setdefault(key, [first[key]])
            clash[key].append(row)
    for key, versions in clash.items():
        del first[key]
        why = f"{len(versions)} versions of {key}"
        for at, raw, _ in versions:
            rejects.append((at, "conflict", why, raw))
    return [rec for _, _, rec in first.values()]

每种选择能带来什么：

  • strict=True 会让格式错误的引号（例如 "Harbor "Blue" Foods"）抛出 csv.Error，而不是悄悄地把文本合并在一起。读取器会从下一行继续，所以一个坏引号只损失一行。
  • 原始文本连同其行号范围一起写入报告，这样负责人可以在自己的系统里找到它。一个从未闭合的引号会表现为一条覆盖多行的拒绝记录，例如 8-40，这能告诉你去哪里查找。
  • 结构被跳过并计数，数据被拒绝。 空行和重复的表头不是坏数据。重复的表头通常意味着有人把两个导出文件粘贴在了一起，这正是需要检查重叠的理由。
  • 完全相同的重复项被跳过；冲突的项全部拒绝。 两行具有相同 ID 但值不同时，需要人来决定哪一行生效，因此两行都不加载。

让运行可以安全地重复

加载作业会中途失败并被重试。客户会把同一个文件发送两次。可安全重跑意味着第二次运行同一个文件不会改变任何东西。

import hashlib

# needs: accounts.account_id TEXT PRIMARY KEY
#        loads.sha256 TEXT PRIMARY KEY
UPSERT = """
INSERT INTO accounts (account_id, account_name,
  renewal_date, contract_value, currency, owner_email)
VALUES (:account_id, :account_name, :renewal_date,
  :contract_value, :currency, :owner_email)
ON CONFLICT (account_id) DO UPDATE SET
  account_name = excluded.account_name,
  renewal_date = excluded.renewal_date,
  contract_value = excluded.contract_value,
  currency = excluded.currency,
  owner_email = excluded.owner_email"""
SEEN = "SELECT 1 FROM loads WHERE sha256 = ?"
LOG = """INSERT INTO loads (sha256, n_rows, loaded_at)
VALUES (?, ?, datetime('now'))"""

def load(conn, raw, recs):
    digest = hashlib.sha256(raw).hexdigest()
    with conn:  # one transaction: all lands, or none
        if conn.execute(SEEN, (digest,)).fetchone():
            return "already loaded"
        conn.executemany(UPSERT, recs)
        conn.execute(LOG, (digest, len(recs)))
    return f"loaded {len(recs)}"

三个层次，各自应对不同的故障：

  • 文件指纹。 原始字节的哈希值连同时间戳一起存入 loads 表，这样相同的文件会被跳过，而且你能说出它是什么时候加载的。
  • 基于稳定键的 upsert。 有重叠的导出会更新行而不是复制行。ON CONFLICT 的目标必须是主键或唯一列，这就是注释中指明该约束的原因。SQLite 的 upsert 语法 是 ON CONFLICT ... DO UPDATE 子句；Postgres 也有同样的子句。
  • 单个事务。 中途崩溃不会留下加载了一半的文件，因此重试可以从干净状态开始。

然后在面试官指出之前，先说出这些限制。如果导出文件可能乱序到达，一个带有新哈希的旧文件会覆盖较新的值，因此要存储导出的时间戳，并且只在更新时才写入。而且 upsert 永远不会删除：本周文件中缺失的账户仍然会保留在系统中。找出两次导出之间被删除或更改的内容，正是 diffing two exports 中讨论的问题。将同样的幂等性思路应用于 API 调用，见 our post on the API integration round。

像与客户对话一样进行讲解

上面的代码只是这个环节的一半。另一半是你在编写代码时所说的话。这些话术是我们的方法论，而不是任何面试官要求的标准脚本；请用自己的话来表达。

解析之前： “在写任何代码之前，我想先看一下原始文件。我看到有字节顺序标记和分号，所以我会以 UTF-8 读取并去掉该标记，同时根据表头确认分隔符。”

遇到第一个含义不明确的值时：“这个日期可能是4月3日，也可能是3月4日。我不会去猜，因为错误的续约日期比缺失的日期更糟糕。我会以理由拒绝它，并把它列入问题清单，交给负责这份导出文件的人。”

设置文件级规则时：“由于存在分号和欧元金额，我假定这个文件使用逗号作为小数分隔符。这是针对整个文件的一个决定，而不是逐行判断，而且在正式运行之前，我会先与客户确认。”

最后：“加载了三行，全部为欧元，五条被拒绝，两条被跳过，十行全部有着落。拒绝文件中包含每一行、其行号和原因。在下一次加载之前，我需要三个答案：日期的顺序、为什么有一个金额使用了不同的格式，以及没有 ID 的那一行是否是真实账户。”

最后这句话是值得反复练习的。它把一个解析任务变成了工作关系的开端，这正是客户轮次要求你展示的技能。要练习这一半，请运行免费练习案例：它会让你面对一个只回答你所提问题的 AI 客户，登录后即可免费使用。关于输入、负责人和时效性的课程会更深入地讲解如何询问每个数据源的负责人及其新鲜程度。当文件是一个开放式提示的开端而非加载任务时，我们关于用数据集进行分解的文章会从这些列继续展开。

可能遇到的追问

“文件放不进内存。”用流式处理。把打开的文件传给

csv.reader

而不是行列表，只保留当前记录的原始文本，只保存已见 ID 的集合及每条记录的哈希值，边处理边把拒绝行写入磁盘，并按每批几千行进行 upsert。

“客户在中间加了一列。”表头是按名称匹配的，所以不会有任何错位，新列会被忽略。对未知列记录一条警告：导出格式变了，负责人应该知道。

“我能直接用 pandas 吗？”先问，如果可以，仍然要统计输入和输出的行数。在我们的测试文件上，使用较新版本的 pandas，

read_csv(..., dtype=str, keep_default_na=False, encoding="utf-8-sig", sep=None, engine="python")

只加载了九行：Harbor 那一行被无声地丢弃了，而作为

on_bad_lines

传入的可调用对象从未被调用。使用

sep=";"

和默认引擎时，十行全部加载，但名称被弄乱成了

Harbor Blue" Foods"

。无论哪种方式，你仍然需要自己的拒绝清单。

代价最大的错误

  • line.split(",)。它在遇到第一个带引号的分隔符时就会出错，比如分号文件中的 "Nordic; Oslo"，或逗号文件中的地址。请使用 csv 模块：它的默认方言能处理带引号的分隔符以及写成两次的引号（""），即 Excel 的写法，这也是 RFC 4180 所描述的引号规则。
  • except: continue。输出看起来很干净，但缺失的行几周后才会在有人核对总额时暴露出来。每个 except 都应该把记录追加到拒绝清单中。
  • 修复那些你应该主动询问的问题。 货币换算、补造缺失的 ID 或在冲突的行之间做出选择，都是业务决策。要把它们标记出来。
  • 没读完就动手写代码。 在编写解析器之前，先列出会破坏它的输入；先问边界情况这个问题正是针对这个习惯的练习。
  • 结尾保持沉默。 如果你不说明丢弃了多少行以及原因，面试官就得追问，而你也失去了展示判断力的最佳机会。

常见问题

在编程面试中如何处理混乱的 CSV？

解析前先检查文件，使用真正的 CSV 解析器而不是按逗号切分，用明确的规则规范化每个字段，并把每一行无法修复的数据连同原因一起送入拒绝列表。最后报告成功加载和被拒绝的行数，以及你会向数据负责人提出的问题。

应该丢弃坏行还是修复它们？

只修复只有一种合理解读的情况，比如多余的空白或重复的表头行。当值有歧义时，比如一个日期可能是日在前或月在前，就拒绝或标记它并明确说明，因为默默猜测会污染客户信任的数据。

什么是可安全重跑的数据导入？

同一个文件运行两次的结果与运行一次相同。用稳定的标识符作为每条记录的键并进行 upsert，或者记录哪些文件已经加载过，这样崩溃后的重试就不会产生重复数据。Tangible 的公开 FDE 家庭作业要求对客户的持仓 CSV 进行可安全重跑的导入。来源 4家庭作业：客户持仓数据接入发布方Tangible (tangiblemarkets on GitHub)来源类型公司网站

在 CSV 编程面试中可以用 pandas 吗？

问面试官。标准库的 csv 模块能处理引号转义且无需安装，而 pandas 在处理大规模数据转换时写起来更快。无论用哪个，都要统计输入和输出的行数，并保留自己的异常记录报告，因为 pandas 可能会丢弃或损坏格式错误的行而不做任何提示。
