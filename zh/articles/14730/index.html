OpenAI 和 Anthropic 的 FDE 团队：采用率差距

原标题：OpenAI and Anthropic FDE teams: the adoption gap

FDE Times · 2026-10-08 · 约 6 分钟读完

摘要

文章引用 Epoch AI 的招聘数据分析 OpenAI 与 Anthropic 的前沿部署工程师岗位趋势：Anthropic 的采用类岗位占比从 5% 升至 11%，OpenAI 从 11% 升至 17%，说明客户难以独立用好模型。两家实验室均将 FDE 业务拆分为独立公司并引入外部资本，OpenAI 收购 Tomoro 以一次性获得约 150 名 FDE。文章结合 a16z、The Pragmatic Engineer 与 Palantir 10-K 的观点，归纳出四个驱动因素，并建议开发者以真实部署经历而非技术清单来构建简历。

要点

  • 采用类岗位占比：Anthropic 从 5% 升至 11%，OpenAI 从 11% 升至 17%。
  • 两家实验室均把 FDE 业务拆分为独立公司并引入外部资本。
  • OpenAI 收购 Tomoro，一次性获得约 150 名前沿部署工程师。
  • a16z 认为 FDE 本质是换了名称的专业服务型实施工作。
  • Palantir 10-K 指出 FDE 是发现研发机会的第一线传感器。

简要概述

  • 在职位发布中，采用类岗位的占比在 Anthropic 从 5% 升至 11%，在 OpenAI 从 11% 升至 17%，这表明客户仅凭自身难以从模型中获得全部价值。
  • OpenAI 和 Anthropic 都已将各自的 FDE 业务剥离为引入外部资本的独立公司；就 OpenAI 而言，官方给出的理由是让实验室能够专注于构建模型。
  • 对于开发者（包括越南的开发者）而言，让系统在混乱的客户环境中跑起来的经验，正是如今 AI 公司愿意付费购买的能力。

在 Anthropic，专注于采用的职位发布占比已从 5% 升至 11%。在 OpenAI，这一比例从 11% 升至 17%。这两家实验室仍被视为在模型质量上相互竞争，但 Epoch AI 的职位发布数据显示，它们正将越来越多的员工投入到帮助他人真正使用其产品的工作中。

Epoch 对这些数字的解读恐怕不是行业愿意听到的：客户难以从 OpenAI 和 Anthropic 的产品中获得全部价值。模型的发展已经超出了企业的消化能力。而这两者之间的差距，正是 FDE 出现的地方。

如果你是正在考虑转向 FDE 工作的开发者，这些数字比任何新模型发布都更值得你关注。它们表明，需求并非来自某一家公司，而是来自市场结构本身，而各实验室的应对方式正在勾勒出一条相当清晰的职业路径。

采用差距不是客户的错

人们很容易认为企业行动缓慢是因为缺乏人才。a16z 的 Joe Schmidt 提出了不同的看法：企业级 AI 产品所需的实施工作量甚至超过上一代企业软件。这是产品本身的特性，而非买方的失败。语言模型只有在接入真实数据、真实流程以及无人写明的约束条件后，才具有价值。

这正是 a16z 得出结论的原因：有时需要劳动密集型的服务，才能打造出真正改变组织运作方式的软件。它对其余部分直言不讳：在最优秀的复杂 AI 应用公司中，这一角色通常被重新命名为前沿部署工程师或实施专家。换言之，FDE 这个头衔在很大程度上只是给熟悉的专业服务工作贴上的新标签。

Decrypt 用一个贴切的比喻描述了这项工作：FDE 空降到客户组织中，在其混乱的中心开展工作。这一模式借鉴自 Palantir。最直观的想象方式是：一家银行签署了 API 合同，但六个月后仍没有一个用例投入生产，因为它的数据分散在三个遗留系统中，而合规团队尚未签字批准。

坐在他们身边、逐一解开这些死结的人，既不是客户经理，也不是研究员。

资金追随部署速度

The Pragmatic Engineer 指出了一个更务实的原因：对实验室而言，AI 解决方案部署得越快，产生的收入就越多。如果 token 没有被消耗，签署的合同就赚不到钱。客户每多挣扎一个月，就是一个月的递延收入，而训练模型的成本已经支付。从这个角度看，FDE 就是缩短签约与开票之间距离的人。

但如果 FDE 真的如此重要，为什么 OpenAI 和 Anthropic 都没有把他们留在实验室内部？据 The Pragmatic Engineer 报道，OpenAI 已将这项工作放入一个由外部私募股权支持的独立法律实体，Anthropic 也为其 FDE 咨询业务设立了一家由外部资金支持的独立公司。对 OpenAI 来说，公开的理由是让实验室能够专注于构建更好的模型。

至于 Anthropic，The Pragmatic Engineer 只记录了其结构：一家由外部资金支持的独立公司。结合 OpenAI 的逻辑来看，两家实验室选择了相同的结构，这表明他们在解决同一个问题：让研究免受服务业务节奏的干扰。

值得注意的细节是速度。Decrypt 报道称，OpenAI 收购 Tomoro 是为了让新部门从第一天起就拥有约 150 名 FDE。如果认为可以在一年内逐步招聘到这些人，没有人会为了 150 名员工而收购一家公司。当实验室选择收购而非自建时，它是在表明这项技能稀缺且急需。

四个原因，一个结论

将这四个驱动因素并排放在一起，每一个都对 FDE 提出了不同的技能要求。

驱动因素谁指出了它对 FDE 的要求
客户没有从模型中获得全部价值Epoch AI，基于招聘数据充分理解模型，能够看出客户尚未发现的用途
AI 产品比传统软件需要更重的实施工作a16z与混乱的数据和流程进行集成
更快的部署能更早带来收入The Pragmatic Engineer衡量成果，并优先推进能赚钱的用例
FDE 是研发创意的第一来源Palantir，10-K 文件从一线捕捉模式，并将其带回产品团队

最后一行最容易被忽视。Palantir 在 2020 财年的 10-K 报告中写道，其 FDE 是为平台发现研发机会的第一线。换言之，这一模式不只是消耗现有产品，还会反哺产品。对于实验室而言，坐在银行或工厂里的那个人，是感知模型在现实世界中何处失效的最早传感器。

分拆出独立公司，说明了这份工作的什么

两家实验室都将 FDE 放在独立法律实体中，这对你有两层截然相反的含义。一方面，这表明 FDE 工作是作为服务业务来运营的，与研究团队的节奏分离，这符合 a16z 对专业服务的描述，只是换了个新名字。另一方面，外部资本和成立之初就有 150 人，说明这不是一个支持性职能，而是一家有意为之打造的企业。

如果你的目标是进入某个实验室的部署部门，最值得投入的是证明你曾让一个系统在并非为其设计的环境中运行起来。这条建议直接来自 Decrypt 对这份工作的描述：空降到客户的组织中，并生活在其复杂性之中。

在外包行业工作或为国内企业构建解决方案的越南开发者在这方面拥有意想不到的优势：他们习惯了脏数据、手动流程，以及那些直到看到演示才知道自己想要什么的客户。

因此，你的简历应该改变重心。与其罗列框架，不如讲述一个部署的故事：什么系统、客户那边有哪些障碍、你如何清除这些障碍，以及随之而来的可衡量的结果。阅读职位描述时，要寻找诸如“客户环境”“生产部署”“与客户现场协作”之类的措辞，而不是技术清单。这才是寻找 FDE 的人所使用的语言。

正如 Epoch 从招聘数据中解读的那样，只要客户仍在努力从模型中获得完整价值，站在实验室与企业交汇点上的人才就会一直被需要。

当一家实验室选择直接买下 150 名工程师而不是等待时，你的问题已不再是这份工作是否真实存在，而是你是否已经有一个可以讲述的部署故事。
