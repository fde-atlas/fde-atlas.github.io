SkillsBench (2026) 解读：面向 FDE

原标题：SkillsBench (2026) Explained for FDEs

FDE Interviews · 2026-10-17 · 约 4 分钟读完

摘要

SkillsBench 是首个系统测量 Agent Skill 是否真正有效的基准。BenchFlow 组织社区从 400 个提交中筛选出 87 个真实任务，在 18 种模型与运行环境组合下，分别带和不带专家编写的 Skill 各跑三次。结果显示平均通过率从 33.9% 升至 50.5%，专业领域收益最大，而 Agent 自写 Skill 反而降低成绩。

要点

  • 87 个真实任务在 18 种模型与运行环境组合下成对测试
  • 平均通过率从 33.9% 提升到 50.5%，各组合均有提升
  • 自然科学、媒体制作领域收益最大，数学和软件工程最小
  • 每个任务 1-3 个精简 Skill 效果最好，长文档几乎无增益
  • Agent 自己写的 Skill 使成绩下降 8-12 分

一分钟速览论文

Agent Skill 是一个 Agent 在工作时能够发现并加载的文件夹：包含一份必需的

SKILL.md

指令文件，以及可选的脚本、模板和参考文件。Anthropic 提出了这一格式，Claude Code、Codex CLI、Gemini CLI 和 OpenHands 等运行环境均支持它。Skill 介于提示词和工具之间。它承载流程（“我们这里如何做 X”），并且可以附带可执行代码，而无需改动模型。据作者的快照统计，社区合集已收录约 200 万个不同的 Skill。但此前没有人衡量过它们是否真的有用。

SkillsBench 是由 BenchFlow 牵头的一项大规模社区协作，通过成对运行的方式进行衡量。作者从 142 位贡献者那里收集了 400 份任务提交，经过自动检查和人工评审后保留了 87 个。每个任务都是容器中的真实工作，例如安全分析、科学信号处理、媒体转换、金融或软件工程，配有由人工编写的指令、参考解决方案和确定性测试套件。每个任务都附带由领域专家独立于任务编写的 Skill，其中包含针对该类问题的通用专业知识，但绝不包含答案。指令从不提及这些 Skill；Agent 必须自己去发现它们。

每个任务在 18 种模型与运行环境的组合下，分别在不使用 Skill 和使用 Skill 的情况下各运行三次。精选 Skill 将平均通过率从 33.9% 提升到 50.5%。所有配置都有提升，从 +4.1 到 +25.7 个百分点不等。在模型了解最少的领域收益最大，例如自然科学（+28.8）和媒体制作（+24.1），而在数学（+9.7）和软件工程（+11.6）中收益最小。每个任务使用一到三个 Skill 的效果优于四个或更多，而且精简的 Skill 胜过详尽的文档——后者几乎没有带来任何提升。当 Agent 在解题前先自己编写 Skill 时，结果反而变差了。

研究笔记：问题、方法与结果

在 18 种模型–运行环境配置下，精选 Skill 带来的平均通过率提升

详尽、全面的 Skill 文档带来的提升，相比之下精简或标准 Skill 的提升为 +19 到 +21.5

Agent 先自己编写 Skill 再使用时的变化

Agent Skill 传播迅速，社区合集中已发布数百万个，但此前没有人衡量过添加一个 Skill 是否真的对 Agent 有帮助、帮助多大，或者何时反而有害。

在 18 种模型与运行环境配置下，将 87 个带确定性测试的真实任务各运行两次，一次不使用 Skill，一次使用专家编写的 Skill，并比较成对结果。

平均通过率从 33.9% 升至 50.5%。按配置不同，提升幅度从 +4.1 到 +25.7 个百分点不等，在专业化领域最大，并且一到三个聚焦的 Skill 优于冗长的 Skill。

为什么这对 FDE 很重要

Skills 是一种将客户的操作流程植入 agent 的实用方法，无需 fine-tuning：他们如何排版报告、按什么顺序调用哪些内部 API、数据的各种怪癖。本文是对其效果的首次测量。

写操作规程，不要写手册。 胜出的 Skills 简短而具体：带合理默认值的可执行脚本、权威数据源及其 parsing 怪癖、确切的输出格式约束、答案必须满足的不变量。面面俱到的文档只带来 0.7 分，而聚焦的 Skills 带来约 19 到 21 分。只放入 agent 自己无法推断出的内容，其余省略。

每个任务的 Skills 要少。 配备四个及以上 Skills 的任务，收益大约只有配备一到三个的一半。把团队写过的每个 Skill 都塞进每个 agent 会稀释指引，还可能相互冲突。

每个 Skill 都要做有和无的对照测试。 87 个任务中有 13 个在开启 Skills 后平均表现更差，通常是因为某个 Skill 规定了一条繁重的流水线，挤掉了 agent 更简单的默认做法。在发布 Skill 库之前，把客户的任务两种方式都跑一遍。

运行环境很重要。 同一个模型在不同运行环境中收益不同：Claude Opus 4.7 在 Claude Code 中达到 61.2%，在 OpenHands 中为 53.1%。要在客户实际使用的运行环境中评测 Skills。

不要让 agent 自己写 Skill。 agent 为自己生成的 Skills 使分数降低了 8 到 12 分。人类专家的操作规程才是真正的资产。
