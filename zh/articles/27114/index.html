Google 把企业 Agent 上线前必须问的 20 个问题写成了正式清单，Agent 的采购、分发、授权和治理路径开始产品化——企业 AI 正在从

摘要

文章汇总近三日的企业 AI 动态，核心判断是 Agent 正在从工具能力变成可采购、可分发、可授权、可审计的企业正式运营单元。Google Cloud 于 2026 年 7 月 8 日发布企业 Agent 上线前必答的 20 个问题清单，涵盖委派权限、中央注册表、语义策略、网关与威胁检测，并提出 SaaS 正演进为 Agents-as-a-service，配套 Marketplace 采购、预算管控、Agent Gallery 内部分发等路径，作者中还包括 Lovable 的 FDE。Databricks 的 Omnigent 则把治理从静态白名单推进到会话状态治理，支持每会话预算上限与风险累积升级。AWS 发布基于 Bedrock AgentCore 的内部 IT 支持 Agent，把调查时间缩短 30-45 分钟。作者认为下一阶段高价值 FDE 需设计采购路径、权限模型与运行治理，而非只做 Demo。

要点

  • Google 发布企业 Agent 上线前必答的 20 个问题清单。
  • SaaS 正演进为 Agents-as-a-service，采购与授权路径产品化。
  • Databricks Omnigent 引入会话状态治理与每会话预算上限。
  • AWS 用 Bedrock AgentCore 收束内部 IT 支持流程。
  • WAIC 2026 议题聚焦智能体、AI Coding 与 OPC。

今日判断

过去 24-72 小时里，企业 AI 最关键的新变化，不是又多了一个案例，而是头部厂商开始把 Agent 的分发、采购、授权、预算、运行治理明确产品化。

如果说前几天的主线是"企业 AI 开始进入结果负责型交付阶段"，那今天的新推进是：企业 AI 正在进入正式运营与治理编制化阶段。最强的新信号开始回答这些真正会卡住大客户预算的问题：

1. Agent 怎么进入企业正式采购和分发体系？

2. 谁来批准、注册、授权、记账和审计？

3. Agent 的权限、预算、风险累积和异常行为，怎么在运行时被持续管住？

4. 业务部门到底能不能把 AI 用成一个日常工作入口，而不是另一个零散工具？

合起来看，今天的核心结论：

  • 企业 AI 的下一轮竞争，不只是"谁的 Agent 更聪明"，而是"谁能把 Agent 变成企业正式可采购、可分发、可授权、可审计的工作单元"。
  • 下一阶段高价值 FDE，不只是做一个可用 Demo，而是把采购路径、权限模型、运行治理、业务接入口接成一套能通过甲方审查的落地系统。

重点信号

Google 直接把"企业 Agent 上线前必须问的 20 个问题"写成了正式清单

  • 来源：Google Cloud Blog ｜ 原文链接
  • Google Cloud 于 2026 年 7 月 8 日发布该文，不是泛泛讲趋势，而是按企业落地过程，直接列出 20 个必答问题。
  • 文中明确提出：企业必须处理 delegated authority（委派权限）、central agent registry（中央注册表）、semantic policies（语义策略）、agent gateway（网关）、Threat Detection（威胁检测）等能力。
  • Google 直接把 shadow AI and agent sprawl（影子 AI 与智能体蔓延）点出来，强调未被监控的 agent 会造成数据碎片化与合规风险。
  • 为什么重要：头部厂商已经默认企业 AI 的问题不再是"会不会做 Agent"，而是"怎么把 Agent 纳入正式治理体系"。这套问题清单，其实就是下一阶段企业 AI 交付的验收清单。FDE 的价值越来越像"企业 AI 项目的总装和总控"。

Google 开始把第三方 Agent 的采购、注册、授权和调用路径正式产品化

  • 来源：Google Cloud Blog ｜ 原文链接
  • Google Cloud 于 2026 年 7 月 8 日发布该文，直接提出：SaaS is evolving into Agents-as-a-service（AaaS）。
  • 文中给出了一整套企业路径：Google Cloud Marketplace 采购、Billing Administrator 控预算、Discovery Engine Administrator 注册与授权、Agent Gallery 内部发现、用户首次使用时做 OAuth authorization。
  • 值得注意：文章作者之一直接标注为 Forward Deployed Engineer, Lovable，说明前沿部署型角色已经进入第三方 Agent 商业化路径。
  • 为什么重要：Agent 正在从"工具能力"变成"可采购、可分发、可授权、可记账的企业软件单元"。未来企业采购的可能不是一套软件，而是一组在内部 Agent Gallery 里被批准和分发的工作单元。FDE 的工作会进一步前移到采购路径设计、注册接入、权限开通和内部推广。

Databricks 开始把 Agent 治理从"静态白名单"推进到"会话状态治理"

  • 来源：Databricks Blog ｜ 原文链接
  • Databricks 于 2026 年 7 月 7 日发布官方博客，明确说 Omnigent 的 contextual policies 可以跟踪一个 session 到目前为止做过什么，再决定下一个动作是否允许继续。
  • 官方直接给出可用场景：per-session spending caps（每会话预算上限）、风险随会话累积而升级、least-privilege security model（最小权限模型）。
  • 这套策略层可以套在 Claude Code、Codex 和自定义 agent 之上。
  • 为什么重要：企业 AI 治理正在从静态走向动态。风险往往不是某一次工具调用决定的，而是"它前面已经看过什么、花了多少钱、碰过哪些外部内容"。未来高价项目里，真正稀缺的不是会配白名单的人，而是会设计状态驱动策略、预算边界和条件式放权的人。

AWS 开始把内部 IT 支持场景写成标准化的 MCP AgentCore 工位

  • 来源：AWS Machine Learning Blog ｜ 原文链接
  • AWS 于 2026 年 7 月 7 日发布该文，指出处理一次基础设施事件时，工程师往往要在控制台、CloudWatch、文档、社区帖子和支持工单之间反复切换，每次调查在真正解决问题前会多花 30-45 分钟。
  • 这套 Support Companion 使用 Amazon Bedrock AgentCore，通过 MCP 连接 AWS 服务，把文档查询、指标查看和创建 support case 收束到单一会话接口。
  • 为什么重要：这类场景非常接近企业内部最容易先落地的 AI 工位——不是面向外部用户的炫酷 Agent，而是面向内部 IT/运维/支持的工作台。价值不在"回答更漂亮"，而在"少切屏、少找文档、少绕路"。ROI、责任边界和人工接管点都更清楚，更容易被企业接受。

WAIC 2026 议题覆盖智能体、AI Coding 和 OPC，中国本土议题正在聚拢

  • 来源：上海发布 / WAIC 2026 新闻发布会 ｜ 相关报道
  • 2026 年 7 月 7 日上海市政府新闻办举行 2026 世界人工智能大会新闻发布会。本届 WAIC 将于 7 月 17 日至 20 日举行，设 140 余场论坛，1400 余位中外嘉宾参与。
  • 本届议题覆盖开源智能体、AI Coding、Token 经济、OPC 等。首次设立 OPC 专属展示区，180 家企业入驻。
  • 为什么重要：中国市场的公开议题也开始从"模型热闹"转向"智能体、治理、产业组织和现场生产力"。FDE 不必等中国先出现同名岗位，相关工作形态和产业语言已经在聚拢。

对 FDE 从业者的启发

  • 从"做 Agent"升级到"做 Agent 的正式运营体系"：Google 的 20 问清单本质上就是企业 AI 交付的验收标准。FDE 方案里应该加入采购路径、权限模型、运行治理和审计接口的设计，而不仅仅是"功能跑通了"。
  • 会话状态治理是下一个高价值技能：静态权限白名单已经不够用了。学会设计动态策略——每会话预算上限、风险累积升级、条件式放权和人工接管触发点——这将区分高价和低价 FDE。
  • 内部支持工位是最佳切入点：IT 支持、运维分析、财务查询这类半封闭场景，比面向外部客户的 Agent 更容易落地、更容易算清 ROI。如果你的客户不知道从哪开始，建议从"员工每天最烦的重复查询"切入。
  • 关注 WAIC 2026 的 OPC 和智能体论坛：7 月 17-20 日的 WAIC 是中国 AI 产业最大的年度事件，今年议题和 FDE 高度相关。
