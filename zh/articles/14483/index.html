OpenAI Presence 企业级 AI Agent — 2026 年 7 月

原标题：OpenAI Presence Enterprise Agents — July 2026

AISOLO Technologies Private Limited · 2026-07-24 · 约 5 分钟读完

摘要

OpenAI 于 2026 年 7 月 22 日发布企业级 Agent 产品 Presence，覆盖语音与聊天渠道，主打策略、护栏、评测与人工升级机制。产品不提供自助服务，由 OpenAI 前沿部署工程师与系统集成商主导交付，定价按用例单独商定。OpenAI 自有客服电话约 75% 的问题无需人工处理，Codex 改进循环在 10 天内将人工转接率降低 15 个百分点。BBVA、SoftBank、IAG 为设计伙伴。文章提醒证据有限、安全面扩大，并给出采购时应追问的问题。

要点

  • Presence 面向语音与聊天场景，内置策略、护栏与评测工具。
  • 仅限有限 GA，由 FDE 与系统集成商交付，无自助购买。
  • OpenAI 自用客服约 75% 无需人工，人工转接降 15 个百分点。
  • BBVA、SoftBank、IAG 为设计伙伴，探索银行与保险用例。
  • 文章提示证据有限，建议在 RFP 中追问评测归属与回滚机制。

2026 年 7 月 22 日，OpenAI 发布了 Presence——这不是又一张模型卡片，而是一款已部署的企业级产品，用于将 AI Agent 落地到真实的客户和内部工作流中，并配备策略、护栏以及人工介入的升级路径。

这一卖点印证了每家企业都已用惨痛教训换来的认知：演示很便宜；当产品和来电者发生变化时仍能遵守策略的可靠生产级 Agent 才是昂贵的。Presence 将这一整套技术栈打包，并搭配前沿部署工程师一同出售。

Presence 为何而生

OpenAI 的表述很直白：瓶颈已不再是“Agent 能否工作？”——而是在策略、SKU 和来电者行为不断漂移的情况下，如何保持它们的可靠性。

Presence 的每次部署都从一项任务开始（账单处理、保险理赔、员工 IT 工单）。Agent 只获得该任务所需的知识和系统访问权限。企业可以设定：

  • Agent 可以做什么
  • 何时需要审批
  • 何时由人工接管

这是 Agent 框架 + 治理，而不是一个聊天小部件。它与企业 AI 控制平面思维以及先评测再购买的指导思路一脉相承——成果和评测胜过模型品牌名气。

产品包含哪些内容

组件作用
策略 / SOP跨部署共享的行为规范
护栏当会话超出公司边界时进行干预
经批准的操作对公司系统进行范围受限的工具调用
仿真 + 评分器上线前检查：结果、策略、工具、升级
评测工具随时间推移衡量准确性和性能
Codex 改进闭环根据生产信号提出上线后的更新建议

企业可以决定哪些内容在各工作流中保持一致（策略、评测、升级规则），哪些内容因渠道或用例而不同——因此第二个 Agent 不必从零重写。

目前支持语音和聊天——并非所有渠道

在发布时，Presence 支持实时语音和聊天：支持、外呼销售、高风险内部流程。

OpenAI 描述的账单处理示例路径：理解请求 → 验证客户身份 → 查询账户 → 应用策略 → 执行经批准的操作。

如果你已经在 OpenAI 的技术栈上构建过双工语音，请保持查看 GPT Live / Realtime 和 Realtime-2 API 指南——Presence 是一个位于模型 API 之上的托管产品，OpenAI 表示现有客户的 API 语音访问将继续保留。

上线前、上线中与上线后的信任保障

面向用户之前：模拟常见请求、边缘情况和较高风险的场景。评分器检查结果、政策遵守情况、工具使用和升级处理。

上线之后：生产会话、升级处理和质量信号会显示随着产品和行为变化，Agent 在哪些场景有效、在哪些场景失效。Codex（Presence 插件）会进行调查并建议更新；团队针对线上版本进行测试，然后批准受控发布。

当某个用例超出产品范围时，OpenAI 的 FDE 和合作伙伴会对其进行扩展——这也是为什么 Presence 读起来更像一种部署型公司的运作方式，而不只是一个 SaaS SKU。这与我们全年持续关注的 FDE 需求激增 和 面试准备 的故事相吻合。

可用性、定价以及买家应该询问的问题

主题官方立场 / 买家问题
可用性有限 GA · 符合条件的企业 · 客户团队
交付方式OpenAI FDE + 精选全球系统集成商
自助服务暂未提供
定价未公布；按用例范围定价（更广泛的定价“即将推出”）
模型锁定配置可能随工作流变动——请询问合同条款
与 Workspace Agents 对比Presence = 托管式生产环境；Workspace = 自助构建器（AgentForger 教训 仍适用于任何 Agent 构建器）

应写入 RFP 的问题：

  • 哪些工作流在 GA 支持范围内 / 范围外？
  • 交接之后，评测框架和黄金对话记录由谁负责？
  • 模型和政策变更如何进行版本管理并回滚？
  • 当 Presence 与人工意见不一致时，升级处理的 SLA 是什么？
  • 数据落在哪里，与现有的 ChatGPT Enterprise / API 合同有何关联？

坦诚的局限性

  • 不是 DIY 产品——如果你想要的是一个控制台和一个 API 密钥，这次发布并非如此。
  • 语音 + 聊天优先——不要因为路线图幻灯片看起来很宽泛，就假设电子邮件或所有渠道都已 GA。
  • Proof 是 OpenAI 自己的联络中心加上三家具名合作伙伴——请索取您所在行业的参考案例通话。
  • 安全攻击面扩大——拥有已批准操作的 AI Agent 会继承连接器的风险；请将 Presence 评审与 Workspace Agent CSRF 教训和企业级 Agent 治理结合使用。
