Docker Deep Dive 怎么读：FDE 必读六章

FDE Times · 2026-11-18 · 约 4 分钟读完

摘要

文章针对 FDE 给出《Docker Deep Dive》2025 版的阅读路径：先读第 6 至 9 章掌握镜像、容器化与 Compose 打包，再读第 15、16 章解决数据持久化与安全审查问题。作者建议购买 2025 年 5 月 12 日更新的 Leanpub 版本，因其新增 Docker Scout、Docker Debug 和多架构镜像等客户现场实用的内容；新增的 LLM 部分可暂缓，因为其聊天机器人本质仍是 Compose 应用。文章还提醒交付前避免三个错误：只构建单一架构、数据库忘挂卷、镜像未做漏洞扫描。

要点

  • 优先读第 6 至 9 章，学会用 Dockerfile 和 Compose 打包应用。
  • 第 15、16 章讲卷与安全，是客户现场最容易出问题的地方。
  • 选 2025 版：新增 Docker Scout、Docker Debug 和多架构镜像。
  • 新增 LLM 内容可后读，聊天机器人本质仍是 Compose 应用。
  • 交付前避免三个错误：架构不匹配、漏挂数据卷、未扫漏洞。

要点速览

  • 买 Leanpub 上的 2025 版，最近一次更新是 2025 年 5 月 12 日。新版增加了 Docker Debug、Docker Scout 和多架构镜像。
  • 最重要的是六章：第 6 至 9 章讲打包，第 15、16 章讲如何在客户系统上安全运行。
  • 2025 版新增的 LLM 内容可以以后再看，书里搭的聊天机器人说到底仍是一个 Compose 应用。

Nigel Poulton 在 2025 年 5 月 12 日最后一次更新了《Docker Deep Dive》2025 版。新版加入了 Docker Model Runner 和 Docker Scout，前者用于在本地机器上运行 LLM，后者用于扫描镜像漏洞。

一本容器入门书，如今专门有一部分讲怎样用 Compose 搭建 LLM 聊天机器人。从这个细节可以看出，部署工作变化有多大，这本书也随之变了多少。

对前线部署工程师（FDE）来说，学 Docker 很少是出于好奇。这份工作要求把软件带进一个自己无法掌控的环境，并且第一次就跑起来。这本书正好讲这些，前提是知道哪六章该先读，哪些内容可以留到以后。

买哪个版本

这本书目前有两条版本线。第二版由 Packt 于 2023 年 7 月 20 日出版，共 266 页，副标题是“Zero to Docker in a Single Book”。书的引言明确说明，读者不需要任何 Docker 基础。

2025 版在作者的 Leanpub 页面上销售。在 Apple Books 上，它由作者自己的公司 Nigel Poulton Ltd 发行，共 262 页。

Leanpub 的宣传称它是最畅销、内容最全的 Docker 书，新手和有经验的开发者都适用。这类营销话术不必全信。

即便如此，仍应选 2025 版。它讲了 Docker Scout、Docker Debug，以及能同时在 x86 和 ARM 上运行的多架构镜像。这三项都直接用得上客户项目：交付前扫描镜像，排查启动不了的容器，构建一次就能适配各类服务器。

前四章教的是打包

在 2025 版目录中，第 6 章讲镜像，第 7 章讲容器，第 8 章是“Containerizing an app”。第 6、7 章讲任何应用运行都离不开的基本操作。第 8 章讲如何把自己的软件做成镜像，是全书最该慢读的一章。

第 9 章讲用 Compose 运行多容器应用。在客户那里，应用连同依赖一起运行，通常就靠这种方式。以一个同时需要数据库和队列的 API 服务为例。

读完第 8 章，这个 API 的最简 Dockerfile 大致如下：

FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
USER 1000
CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]

读完第 9 章，三个组件可以放进同一个 Compose 文件：

services:
  api:
    build: .
    ports:
      - "8000:8000"
    environment:
      DATABASE_URL: postgresql://app:app@db:5432/app
      QUEUE_URL: redis://queue:6379
    depends_on:
      - db
      - queue
  db:
    image: postgres:16
    environment:
      POSTGRES_USER: app
      POSTGRES_PASSWORD: app
    volumes:
      - dbdata:/var/lib/postgresql/data
  queue:
    image: redis:7
volumes:
  dbdata:

没有这个文件，就得给客户的 IT 团队发一长页说明，交代启动顺序、环境变量和网络端口。有了它，一切归结为一条

docker compose up

。这个文件同时也是一份部署文档，客户的运维团队能直接看懂。

2023 版的章节顺序相同：镜像、容器、容器化、Compose，之后才是网络、卷和安全。据 Hoopla 介绍，这一版还讲了 Swarm 和 stack。如果目标是让软件在某个客户的机器上跑起来，这两部分都可以先放一放。

出问题的往往是数据和安全

第 15 章讲卷和持久化数据，第 16 章讲 Docker 安全。这两章排在书的后部，很容易被拖到最后。但在客户那里，如果容器一重启，客户的数据就跟着消失，演示做得再漂亮也救不回来。

上面 Compose 文件里

db

服务的

volumes

一行，就是为此而写。安全方面，客户的安全团队通常要先弄清镜像里装了什么，才会允许它在内网运行。2025 版新增的 Docker Scout 能让你在对方开口之前就备好答案。

交付镜像前要避开的三个错误

第一，只为自己机器的架构构建。你的笔记本可能是 ARM，客户的服务器却是 x86。2025 版讲的多架构镜像，能省下在现场白白调试一下午的时间。

第二，忘了给数据库挂卷。先在自己机器上测试：删掉容器，重新启动，看数据还在不在。如果没了，去客户那里之前把第 15 章再读一遍。

第三，镜像不做漏洞扫描就交付。附上一份 Scout 报告，和安全团队的会议就从争论变成逐项核对清单。

新增的 LLM 内容留到以后

2025 版新增了用于本地运行 LLM 的 Docker Model Runner、Wasm 容器，以及一个用 Compose 搭建的多容器 LLM 聊天机器人。对做应用 AI 的 FDE 来说，这部分很有吸引力，尤其是客户不希望数据离开自家基础设施的时候。

但只有把上面六章练到烂熟，这部分才真正有用，因为那个聊天机器人说到底仍是一个 Compose 应用。

看 FDE 招聘信息时，留意有没有提到 on-prem、客户环境或容器化。如果有，简历上不要只写“熟悉 Docker”。

而应写明：把某个服务做了容器化，用 Compose 让它和数据库一起运行，并在交付前扫描了镜像，再附上能证明这些的代码仓库链接。

这本书的厚度超出了去客户那里第一周所需，这反而是优点。上面六章足以应付第一次部署。其余内容，等到哪天客户问起能否在自家基础设施里运行 LLM，就派上用场了。
