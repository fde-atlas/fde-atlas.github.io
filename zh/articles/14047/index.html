解决方案架构师到前沿部署工程师：差距所在

原标题：Solutions architect to forward deployed engineer: the gap

FDE Interview Prep · 2026-09-25 · 约 15 分钟读完

摘要

文章面向想转型为前沿部署工程师（FDE）的解决方案架构师，指出两者核心差距在于是否亲自编写并负责客户环境中的生产代码。作者引用 OpenAI、Anthropic、Google、Cursor 等公司职位说明及 Ramp、Palantir 面试官言论，说明 FDE 需通过与软件工程师相同的编码面试，并给出三步准备计划：完成一个生产级项目、限时编码练习、调试他人代码，以及把架构师经历改写为体现代码所有权的交付故事。

要点

  • FDE 与解决方案架构师的关键区别：亲自在客户系统写生产代码并负责上线后运维。
  • 客户发现、范围界定、架构判断等技能可直接迁移，是转型优势。
  • Ramp 和 Palantir 要求 FDE 候选人通过与软件工程师相同的编码面试。
  • 建议三步准备：生产级构建、限时编码练习、调试他人代码。
  • 面试故事需体现代码所有权，回答离职动机时避免贬低原岗位。

你已经在做需求探索电话、绘制目标架构、构建能赢得全场的演示。而这个循环要求你证明一件工作中很少被要求证明的事：你能在客户的系统里编写生产代码，并在上线后负责维护它。从解决方案架构师转型为前沿部署工程师是现实可行的，而且你的客户技能是一个真正的先发优势。差距在于你负责过的代码，我们的计划分三部分来弥补：一次生产级构建、限时编码与调试练习，以及以你亲自上线的代码为核心的面试故事。想了解两个角色的完整对比，请先阅读 FDE 与解决方案架构师指南。无论你的目标是 AI 实验室还是企业软件公司，这份指南都适用。

The Pragmatic Engineer 在 2025 年 8 月报道称，在 OpenAI，分界线在于谁写代码：FDE 直接在客户基础设施上使用客户工具编写代码，而解决方案架构师更多是顾问角色，很少在客户基础设施上写代码，通常在匿名化或离线的数据子集上构建概念验证。来源 5什么是前沿部署工程师，为什么他们如此抢手？(Gergely Orosz)发布方The Pragmatic Engineer来源类型新闻报道

一个小例子：离线数据子集与实时数据流

假设你在客户分析师为你清洗过的一份导出数据上构建了一个试点报告。这是概念验证代码，在试点数据上它能正常运行：

from decimal import Decimal

def total_by_region(rows):
    totals = {}
    for r in rows:
        region = r["region"]
        amount = Decimal(r["amount"])
        prev = totals.get(region, 0)
        totals[region] = prev + amount
    return totals

现在把它指向实时数据流。有一行包含

"1,200.00"

，一行金额为空，一行是

"West "

且末尾带空格，还有一行完全没有地区字段。我们运行了它：含逗号的那行和金额为空的那行抛出了

InvalidOperation

，没有地区的那行抛出了

KeyError

，而其中任何一个都会毁掉整个任务。末尾空格会悄悄地出问题：它会把那一行归入一个名为

"West "

.

自有版本则预期这种混乱并报告出来：

from decimal import Decimal, InvalidOperation

def parse_amount(s):
    s = (s or "").replace(",", "")
    try:
        d = Decimal(s)
    except InvalidOperation:
        return None
    return d if d.is_finite() else None

def total_by_region(rows):
    totals, rejects = {}, []
    for n, r in enumerate(rows, start=1):
        region = r.get("region") or ""
        region = region.strip()
        amount = parse_amount(r.get("amount"))
        if not region or amount is None:
            rejects.append(n)
            continue
        prev = totals.get(region, 0)
        totals[region] = prev + amount
    return totals, rejects

在同样的实时数据行上，它返回 West 的总额（去除末尾空格并删除逗号），外加它无法读取的行号。这个

is_finite()

检查很重要：

Python’s 
Decimal

接受

"NaN"

和

"Infinity"

，而一行

"NaN"

数据就会悄悄把整个总额变成

NaN

。它还假设逗号是千位分隔符。这是该问客户的问题，而不是猜测：这个数据源用的是哪个地区设置？真正变化的是背后的问题：当数据出错的那一天会发生什么，以及谁会发现？

这个问题也是在会议室里应该大声说出来的：“一行坏数据应该停止整个运行，还是我们应该跑完并把被拒绝的行交给某个人？那个人是谁？”SA 会在设计评审中提出这个问题。FDE 会把答案写进代码里。

弥补差距的计划

这个计划是我们自己的。它是我们如何为一名 SA 准备面试流程，而不是任何面试官用来给你打分的标准。

第一部分：生产级构建

构建一个真实用户会运行的小型项目，并把它做到底。目标不是聪明的模型，而是演示中留给客户团队处理的部分：

什么才算生产级构建

  • 一个具名的用户，以及一个你没有手工清洗过的混乱输入
  • 在任何功能开发之前，先端到端部署一个行走骨架
  • 测试，包括针对你遇到并修复过的某个故障的测试
  • 每个外部调用都加上重试和超时
  • 日志能告诉你哪条记录失败了，以及为什么
  • 一份 README，说明你省略了什么，以及为什么

作品集项目文章 涵盖了如何选择项目以及如何展示它。

第二部分：限时编码练习

如果你大部分代码都写在 notebook 和演示仓库里，独自编写、没有时间限制，那么面试环节会感觉截然不同：计时器、有人在看着你，以及一道你没见过的题目。请在这种条件下练习。

从最贴近工作的实战构建开始：解析混乱的文件，以及调用一个会分页、限流并出错的 API。免费的混乱 CSV 题目 就是上面那个实时数据流示例的面试规模版本。不稳定的 API 集成题目（Pro 版）涵盖 API 部分，而 API 集成编码环节文章 用 Python 实现了它：带退避的重试、游标分页和幂等键。

如果你的目标公司有算法初筛，也要加上简单和中等难度的题目。不要因为这份工作“不是 LeetCode”就跳过它们：上面那份 2024 年 4 月的 Blind 报告，来自一个职位名称中带有“Solutions Architect”的岗位初筛。来源 13Anthropic Solutions Architect/Forward Deployed Engineer Codesignal发布者Blind (teamblind.com)来源类型Blind 上的候选人报告 上面链接的编码环节课程按公司提供了更多最新证据。

第三部分：调试别人的代码

在我们看来，这是最符合 FDE 特点的技能，也是构建演示类工作最少练习的技能。在实际工作中，bug 出在你没写过的代码里，运行在一个你无法重启的系统上，而客户还在等着。

练习方法，而不是答案：

  • 在动任何东西之前，先复现故障。
  • 写一个能捕获该故障的失败测试。
  • 一次只提出一个假设，并大声说出来。
  • 修复最小的问题，然后重新运行测试。
  • 说明如何防止它再次发生。

先完成那道陌生 bug 题，然后写一个能复现已报告 bug 的失败测试。这两项都能把 SA 已经擅长的讲解能力用在代码上。

把架构师故事改写成交付故事

你的故事是差距的另一半。SA 最好的故事往往在交接时就结束了，而行为面试环节会找出这个边界。

Leo Mehr 在 2026 年 7 月发布的一期播客中说，他通过询问候选人做过的决策以及他们负责什么来评估 ownership。来源 15Leo Mehr - Ramp's $44B Bet on Services（YouTube 自动生成的英文字幕）发布者Basil Chatha，YouTube来源类型录音演讲或访谈 如果面试官像他那样追问，那么你提到的每个项目都会遇到这个问题：哪一部分是你做的？

下面是一个虚构的前后对比。

改写前：“我为理赔流水线设计了参考架构，主持了工作坊，客户的团队按期完成了构建。”

追问不言自明：“你写了什么代码？”如果没有，这个故事展示的就是一位顾问。

改写后：“客户的团队在试点期间人手不足，所以我亲自编写了数据摄取服务。我选择每晚批处理而不是流式处理，因为他们的源系统在白天会锁定表。第一次运行丢失了数据行，我找到了编码 bug，添加了对账检查，并交付了一份运维手册。上线后他们的团队接手了。”

第二个版本包含决策、一次失败、一次修复和一次交接，全部以第一人称叙述。对你打算讲的每个故事做一次 ownership 审计：每个决策都要有明确的负责人，客户团队做的任何事都要归功于他们。

如果审计后你发现自己没有负责过任何代码，解决办法是换一个故事，而不是换更好的代词。有两种方法可以获得这样的故事：

  • 在职期间，申请之前：主动负责试点中的一个集成，一直负责到上线，包括演示之后的部分。
  • 靠自己：第一部分的构建项目就成了你的故事。

然后练习两个直接考察这一点的问题：一个最终进入生产的原型，它奖励那些概念验证比原计划活得更久的 SA；以及一个你端到端负责的项目。

回答“为什么要离开解决方案架构？”

无论是招聘人员还是招聘经理，都可能会问这个问题。糟糕的回答会让面试官感到担忧：

  • “我想做更技术性的工作。”这会引来“那为什么不去做软件工程？”
  • “我厌倦了销售那一面。”FDE 工作同样要面向客户，面试官会怀疑你是否也会厌倦这一点。
  • “这是现在最热门的岗位。”这完全没有说明你是什么样的人。

更有力的回答会把你的过去与这份工作联系起来，并附上证据。以下是一个框架，细节为虚构：

“几年来，我设计的集成方案由客户团队负责构建。在一次试点中，我最终亲自编写了数据接入服务，并一直负责到上线。那正是我工作中最想多做的部分：拥有真正交付的东西，而不仅仅是提出建议。作为 FDE，客户工作和生产代码本来就是同一份工作，而我已经具备了客户那一半。”

这个回答简短，有一个证明时刻，并且不贬低 SA 工作或销售。关于桥梁故事的课程会基于你自己的经历构建这个回答，并用后续追问来检验它。

准备好应对三个后续追问：

  • “为什么不去做软件工程岗位？” 你的答案就是客户那一半。关于为什么选 FDE 而不是软件工程的课程有一个示范回答。
  • “你独立交付过的最大东西是什么？” 说出它的名字、它的用户以及它的故障模式。
  • “对于在别人的环境里负责代码，你怎么看？” 说明你第一天会要求什么：访问权限、日志、测试环境，以及对方指定的联系人。

如果今天觉得这一步跨得太远，有一些岗位介于两者之间，而且它们的招聘要求里明确要求写代码。

  • 前沿部署架构师。 Notion 的前沿部署架构师招聘要求 5 年以上技术服务或咨询、解决方案架构、实施、客户工程或类似面向客户岗位的经验。来源 17Forward Deployed Architect @ Notion发布方Notion (Ashby job board)来源类型公司招聘信息 解决方案架构明确列在其中。

无论你瞄准哪个头衔，都要尽早问招聘人员这个职位的级别是如何划分的。

头衔在两个方向上都会模糊，所以要读招聘内容，而不是只看头衔。关于区分 FDE、SA、售前工程师和 SWE 岗位的课程展示了判断的关键界线，关于识别伪装成 FDE 的 SA 岗位的文章则将这些界线应用到 FDE 招聘信息上。

解决方案架构师能成为前沿部署工程师吗？

可以，而且一些 FDE 招聘信息也明确提到了这一点：Adobe 的 Experience Platform FDE 招聘信息将解决方案架构列在典型背景之中。更难的部分是编码门槛。Ramp 的工程总监曾表示，那里的 FDE 候选人必须通过软件工程面试流程。来源 1Senior Forward Deployed Engineer (Bucharest)发布方Adobe（Workday 招聘网站）来源类型公司招聘信息来源 11What is a Forward Deployed Engineer? 解决方案架构师和 FDE 的主要区别是什么？

谁来编写并负责生产代码。Google Cloud 的 GenAI FDE 招聘信息将该角色与传统咨询型角色进行对比，描述的是能在客户环境中编码、调试并共同交付解决方案的人。Cursor 的 FDE 招聘信息说得更直白：“这不是一个演示角色。”来源 7Forward Deployed Engineer IV, GenAI, Google Cloud — Google Careers发布方Google来源类型公司招聘信息来源 8Forward Deployed Engineer发布方Cursor（Ashby 招聘板）来源类型公司招聘板

我应该先申请应用 AI 架构师岗位吗？

他们可以成为桥梁。Anthropic 的应用 AI 架构师职位将其称为售前架构师，但仍要求其交付可运行的原型和接近生产环境的示例代码。一旦你能展示自己负责过的生产代码，就可以瞄准 FDE 职位。来源 16Anthropic 应用 AI 架构师（商业化）职位申请发布方Anthropic (Greenhouse)来源类型公司招聘信息
