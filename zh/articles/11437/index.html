技术初筛

技术初筛在问其他任何问题之前，先问这个。

面试经典

技术初筛中反复出现的十道题。掌握这些，热身环节就稳了。

你亲手构建的数据结构

别再直接 import 了。亲手写出数据结构本身，包括那些概率型的。

  • 并查集（连通分量） 从这里开始 Kruskal 最小生成树和网络连通性背后的不相交集合：通过按……合并，以近乎常数的时间回答“这两个元素是否连通？”
  • 实现 Trie（前缀树）自动补全和拼写检查背后的前缀树：在正比于单词长度的时间内实现 insert、search 和 startsWith。
  • 布隆过滤器一个微小的位数组，只用集合内存的一小部分就能回答“我见过这个吗？”——偶尔出现误报，但绝不会漏报……
  • 流式中位数延迟监控面板每秒都在做这件事：维护一个数据流的中位数，而无需对每个事件重新排序。
  • 蓄水池采样从未知长度的数据流中均匀随机抽取 k 个元素——只需一遍遍历，O(k) 内存。
  • HyperLogLog 基数估计器用几千字节而不是一个巨大的集合，统计数据流中出现过多少个不同的元素——可达数十亿个。
  • 跳表插入与查找仅用链表和快速通道实现 O(log n) 的查找和插入——这就是 Redis 有序集合背后的结构。

图、字符串与解析器

最短路径、字符串匹配，以及两个真实的解析器——你能讲得清清楚楚的递归。

  • Dijkstra 最短路径 从这里开始 每个路由表和地图应用都依赖的算法：非负权重下的单源最短路径。
  • 网格上的 A* 寻路游戏和机器人内部的寻路器：A* 按“已花费代价 + 预估剩余代价”扩展节点，因此启发式函数能聚焦搜索……
  • 矩阵快速幂用 O(log n) 次乘法而不是 n 次将矩阵自乘到 n 次幂——这个技巧能几乎瞬间算出第十亿个斐波那契数……
  • KMP 失败表让 KMP 字符串搜索达到 O(n) 的预计算：对每个前缀，找出它最长的、同时也是后缀的真前缀。
  • 最长公共子序列"git diff" 和 DNA 序列比对背后的动态规划：两个字符串的最长公共子序列（保持顺序，允许间隔）。
  • 表达式计算器像解释器那样，对带优先级和括号的算术字符串求值。
  • JSON 解析器（递归下降）编写每个 API 和配置文件背后的解析器：把 JSON 字符串转换成原生的对象、数组、数字、字符串、布尔值和……
  • 迷你正则匹配器（. 和 *）用 "." 和 "*" 实现正则匹配——经典的面试难题。

AI 工程

LLM 产品背后的基本原理，全部手工实现。

模型内部

从 Softmax 到注意力机制：模型内部的数学，每个约二十行代码。

  • Softmax 从这里开始 每个分类器和语言模型末端的函数：将原始分数（logits）转换为概率分布。
  • 交叉熵损失训练几乎所有分类器和语言模型的损失函数。
  • 层归一化包裹在每个 Transformer 子层周围的稳定器：将向量重新居中并重新缩放至均值 0、方差 1，然后让学习…
  • K 近邻最简单的分类器：要给新点打标签，就看最近的 k 个已标记点，让它们投票。
  • BPE 合并步骤每个分词器词表的构建步骤之一：统计语料库中相邻符号对的频次，选取最高频的（平局时…
  • 单头注意力每个 Transformer 的核心操作：缩放点积注意力。

推理与解码

Token 实际如何生成：温度、约束、束搜索、投机解码、KV 缓存。

  • 带温度的 Softmax 从这里开始 控制语言模型“创造力”的旋钮：温度在 softmax 之前缩放 logits——低温使分布更尖锐…
  • 受限解码（Logit 掩码）如何强制 LLM 只输出合法 JSON 或语法允许的 token？对 logits 做掩码：将所有不允许的 token 设为 −∞…
  • 束搜索解码器贪心解码只取最佳的下一个 token 且从不回头——一头栽进歧义路径。
  • 投机解码：接受步骤投机解码加速 LLM 推理：小型草稿模型提出 token，大型目标模型一次前向传播验证它们。
  • KV 缓存淘汰（注意力汇聚）LLM 的 KV 缓存随每个 token 增长，因此长对话必须丢弃旧条目而不损害质量。

RAG 与检索

分块、嵌入、打分、排序，然后进行评估。完整的检索路径，全部实现。

  • 余弦相似度 从这里开始 每个嵌入搜索和 RAG 系统背后的度量：忽略长度，两个向量的对齐程度如何？点积除以…
  • 语义分块器（Token 预算）在为检索嵌入文档之前，将其切分成符合 token 预算的块——且不切断句子。
  • TF-IDF支撑搜索数十年的打分方法——至今仍是混合检索的基础。
  • BM25 打分每个花哨的检索器仍必须击败的关键词排序函数。
  • Top-K 检索 RAG 中"R"的核心：给定查询嵌入和一组文档嵌入，返回最相似的 k 个文档的索引…
  • MMR 重排序按相似度取 Top-k 会返回同一段落的五个副本。
  • Token 级 F1QA 评测（SQuAD 及同类）背后的指标：预测答案与参考答案作为词袋的重叠程度如何？…

Agent 与循环工程

预算、重试、解析工具调用、闭合循环——然后审查 AI 写的代码。

  • 将历史裁剪到 Token 预算 从这里开始 每一轮 Agent 交互都会重新发送整个对话，因此历史必须装进上下文预算。
  • 指数退避重试 工具会超时，API 会限流——生产级 Agent 会重试，但不会狂轰滥炸。
  • 解析工具调用 当模型想要执行操作时，它会发出类似 search(query=cats, limit=5) 的调用。
  • 运行目标循环 循环工程的核心引擎：尝试前置任务，让独立的验证器评判结果，在状态不变的情况下重试失败项…
  • 构建你自己的 Agent 循环 剥去“AI Agent”的神秘外衣，剩下的就是一个循环：读取模型的下一步动作——工具调用还是最终答案——执行工具…
  • 编写验证器 在基于可验证奖励的强化学习中，验证器就是奖励本身——而一个可被钻空子的验证器比没有更糟，因为每一个误报都…
  • 找出 AI 代码中的 Bug 一个助手写了一个聊天历史裁剪器，看起来没问题，能通过显而易见的用例，却在某一刻悄悄丢掉了系统提示词…
  • 读懂代码库，修复 Bug 这是 AI 无法替你伪造的技能：进入陌生的代码，追踪各部分之间如何相互调用，并修复出错的那一处…
  • 发布还是停止 一轮自我改进循环又完成了，仪表盘上的每个数字都在上涨。

生产与一线工作

能在真实流量、真实数据和真实客户面前存活下来的代码。

系统、限制与分布式

缓存、限流、熔断器、哈希环，以及三个分布式系统原语。

  • LRU 缓存 从这里开始 每个有容量限制的缓存背后的淘汰策略：当空间用尽时，丢弃最近最少使用的内容。
  • LFU 缓存 淘汰使用频率最低的内容——频率相同时，淘汰最近最少使用的。
  • 令牌桶限流器 大多数生产级限流器内部的算法——而且它从不运行计时器。
  • 滑动窗口限流器 在滚动窗口内最多允许 N 个请求——守护真实 API 的限流器。
  • 熔断器 阻止一个故障依赖拖垮整个集群：连续失败后跳闸，打开期间快速失败，超时后探测一次…
  • 一致性哈希环 分布式缓存如何决定哪个节点拥有某个键——节点加入或离开时只有极小的数据迁移。
  • 向量时钟合并 向量时钟让没有共享时间的进程就“哪个事件导致了哪个事件”达成一致。
  • CRDT：只增计数器 一个由多个副本独立递增、无需协调的计数器，同步后总能收敛到相同的总数——…
  • Raft 领导者选举（多数派）Raft 共识算法的心跳：候选者只有赢得集群的严格多数票才能成为领导者——…

集成与混乱的数据

分页、校验、脱敏、对账：前沿部署工程师真实的一周。

  • API 分页采集器 从这里开始 客户的 API 每次通过游标返回 100 行数据。
  • 幂等键处理器 网络会重试。
  • 配置校验器 一半的“在客户那边不好使”都是配置问题——缺一个键、该是整数的地方放了字符串、一个不被允许的环境变量。
  • 带完全抖动的指数退避 当客户的 API 抛出 503 时，所有人按同样的倍增节奏重试，会同步地把它踩踏一空。
  • 校验 Webhook 签名 每个真正的集成都会发送带签名的 webhook——而每个 FDE 都必须校验它们。
  • PII 脱敏器 在客户数据进入日志行——或第三方 LLM——之前，个人信息必须被清除。
  • CSV → Schema 映射器 每个客户都会交给你一份混乱的导出文件。
  • 数据对账差异 客户信誓旦旦说迁移成功了。
  • 采集一个不稳定的分页 API 供应商的 API 有分页、偶尔返回 500、在未文档化的情况下限流，并且当数据变…时返回重叠的页面。
  • 对账两个互相不一致的系统 客户确信 ERP 和 CRM 是一致的；他们从未核对过。

面试升级题

五个分阶段的轮次，会在解题过程中改变需求，就像真实的现场面试一样。

  • 重新设计一个遗留 ETL 从这里开始 你接手了一个没人能解释清楚的聚合逻辑，而且总数是错的。
  • 修复传播遍历 继承来的代码计算某事物在联系人图谱中的传播范围，而答案错在一种在…上不可见的方式。
  • LRU 缓存，逐条约束加入 增量编码轮的完整打包：一个缓存先变成有界的，再变成最近最少使用淘汰，再加上监控埋点——每个阶段…

编程挑战——常见问题

这些编程挑战是什么？

每个挑战都是一道经典的面试风格题目，你在浏览器中解决。你会得到一个代码桩、一份带示例的题目描述和隐藏测试。用 Python 或 TypeScript 编写你的解决方案，点击运行，测试会立即告诉你是否正确——无需账号、无需配置、无需安装任何东西。

没有服务器，代码究竟是怎么运行的？

完全在您的浏览器中运行。Python 以编译为 WebAssembly 的真实 CPython（Pyodide）运行；TypeScript 则即时转译。本站是一个没有后端的静态网站，因此您的代码绝不会离开您的机器。

如果卡住了，可以查看解答吗？

可以。每个挑战都提供提示和一个一键“显示解答”按钮，会在编辑器中插入一份带注释的清晰参考实现。目标是建立直觉——先自己思考，再将您的解法与标准解法对比。

这些对编程面试有帮助吗？

有帮助。这些挑战针对技术面试中经常出现的数组、字符串、哈希表、栈和双指针模式。亲手解题——再用隐藏测试验证——比阅读解答更能形成持久的练习效果。许多挑战还链接到动画可视化工具，让您看到底层算法的运行过程。

这些挑战是免费的吗？

完全免费，无需注册。您的解题进度会保存在浏览器本地，目录会记住您已完成的内容。
