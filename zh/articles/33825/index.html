部署工程之旅

原标题：Deployed Engineering Journey

GSDC · 约 10 分钟读完

摘要

GSDC 发布的 FDE 职业入门指南，面向有意成为前沿部署工程师的读者。文章介绍该角色的五步工作流程（理解业务问题、技术调研、方案设计、实施部署、业务成果），给出技能地图：编程与 API 是基础，AI 工程（RAG、工具调用、评测）是核心能力，部署运维与业务沟通贯穿始终。文中提供一份 12 周学习计划，从编程基础、系统集成、AI 应用、Agent 工作流到部署与作品集，并给出两个实战项目示例：AI 知识助手和连接业务工作流的 AI Agent。此外还涵盖面试准备、30 天行动计划、作品集展示方法及常见学习误区，强调先理解业务问题再动手实现。

要点

  • FDE 角色包含五步流程：从理解业务问题到交付业务成果。
  • 技能优先级：编程与 API 为基础，AI 工程为核心，部署与沟通贯穿全程。
  • 提供 12 周学习路线，从 API 调用逐步进阶到部署与作品集。
  • 两个示例项目：AI 知识助手与受控工具调用的 Agent 工作流。
  • 强调先做业务调研再实现，并附面试准备与 30 天行动计划。

Global Skill Development Council (GSDC)

角色介绍

认识前沿部署工程师

FDE 与客户或业务团队紧密合作，理解真实问题，并实施适合其环境的技术解决方案。编码、集成、咨询和部署之间的比重因公司而异。

01 业务问题

理解问题：目标、挑战、工作流程、技术约束。

02 技术调研

设计解决方案：将需求转化为可实施的方案。

03 解决方案设计

构建与集成：原型、API、数据源、AI 驱动的应用。

04 实施

测试与部署：在客户环境中验证可靠性。

05 业务成果

改进成果：反馈、监控、评估。

示例

一家公司希望用 AI 回答员工关于内部政策的问题。FDE 找到政策存放的位置，了解访问权限要求，设计启用检索功能的解决方案，连接各系统，并测试答案是否准确且具备适当的授权。

FDE 将技术实施、业务理解和现实世界的问题解决融为一体。

学习优先级

FDE 技能图谱：先学什么

编程和 API 是基础，AI 工程是核心技术能力，部署是运营能力，而业务沟通贯穿于一切之中。

编程与软件基础

Python 或类似语言；函数、模块、数据结构、错误处理、Git、调试、基础测试、JSON。

API 与企业集成

HTTP 和 REST；身份验证与授权基础；请求与响应；SQL

和数据库；webhooks。

AI 工程基础

语言模型及其局限；提示词设计；结构化输出；嵌入与语义搜索；RAG；Agent 工作流与工具调用；评测与幻觉管理。

部署与可靠性

环境变量与密钥；基础云部署；Docker；日志与监控；测试；故障处理；安全。

商业与沟通贯穿始终

需求挖掘；流程梳理；问题分解；文档撰写；利益相关者沟通；解释权衡取舍。

以上是常见技能领域，而非通用清单。具体要求因职位、行业、资历和技术栈而异。

示例：12 周计划

成为 FDE 的分步路线图

适用于具备基本技术基础的人；初学者可能需要更多时间。

第 1–2 周 / 基础

学习：编程基础、Git、HTTP/JSON/API、SQL。任务：编写一个调用公共 API、处理数据并处理错误的程序。里程碑：获取、检查并处理外部数据。

第 3–4 周 / 系统如何连接

学习：REST 操作、身份验证、数据库查询、请求校验、错误处理。任务：开发一个获取 API 数据并将选定记录存入数据库的应用。里程碑：将应用连接到外部服务和数据存储。

第 5–6 周 / AI 应用开发

学习：语言模型 API、提示词、结构化响应、RAG、基础评测。任务：开发一个返回来源引用的文档问答应用。里程碑：一个基于所提供信息的基本 AI 应用。

第 7–8 周 / Agent 工作流

学习：工具调用、工作流设计、输入/输出校验、敏感操作的人工审批、故障处理。任务：添加一个受控工具，例如工单状态查询。里程碑：使用已审批工具的 AI 工作流。

第 9–10 周 / 集成与部署

学习：配置、密钥、基础部署、日志与监控、集成测试。任务：部署到测试环境并编写部署文档。里程碑：项目能在本地机器之外运行。

第 11–12 周 / 作品集

学习：README、架构图、演示视频或截图、测试用例与已知局限、清晰的问题与解决方案说明。里程碑：一个展示你技术决策的项目。

提醒：持续的练习和完成的项目，胜过不加理解地匆忙堆砌工具。

项目 1

构建一个 AI 知识助手

业务问题：员工在内部文档中搜索日常问题的答案时耗费大量时间。目标：构建一个基于已批准文档集合回答问题并提供来源引用的助手。

回答流程

用户 → 应用界面 → 请求验证 → 文档检索 → 相关上下文 → 语言模型 → 输出验证 → 带来源引用的回答

独立的摄取流程

文档 → 解析 → 分块 → 索引 → 可搜索的知识库

构建模块化应用

使用 Python、语言模型 API、检索库或框架以及一个简单的界面；保持模块化，以便可以替换工具。摄取示例文档、执行搜索、提供带来源引用的有据回答、处理无法回答的问题，并记录错误和评测结果。

超越正常路径进行测试

直接回答；跨越多个章节的回答

文档未覆盖的问题；措辞含糊的问题

检索到的文档中的恶意指令

试图访问用户不应看到的信息

打包证据

交付一个可运行的演示、包含配置说明的 README、架构图、示例测试数据集、评测结果、已知局限性和改进方向。

使用示例或经授权的数据。未经批准，不要将机密的公司文档或个人信息上传到第三方 AI 工具。

项目 2

将 AI Agent 连接到业务工作流

一个支持团队不断收到重复的工单状态和信息查询请求。构建一个助手，它可以检索知识、通过模拟 API 查询工单，并推荐下一步操作。

受控执行流程

用户请求 → 请求分类 → Agent 运行时 → 工具选择 →

权限检查 → 模拟工单 API 或知识搜索 → 结果验证 →

对用户的响应 → 日志记录与评测

保持工具执行受控

对请求进行分类、搜索知识并检索工单状态。

验证工具参数；处理缺失的工单 ID 和 API 故障。

将只读操作与修改记录的操作分开。

记录工具调用；对含糊或敏感的情况进行升级处理。

“工单 1042 的状态是什么？”

识别操作，验证 ID，调用经批准的查询工具，验证结果，

并报告返回的状态。如果 API 失败，应说明无法获取状态，

而不是编造答案。

让工程能力可见

展示 API 集成、工具调用、结构化输入、错误处理、工作流控制、

日志记录、测试以及权限感知设计。

交付演示、工具与 API 文档、架构图、错误处理测试、

执行轨迹，以及对工程决策的说明。

展示该解决方案如何与业务工作流交互。

面试准备

如何准备 FDE 面试

面试形式因雇主和资历而异。请为技术问题解决、系统设计、沟通和实际实现做好准备。

编程与调试：编码练习、结构化数据、调试错误、可读代码、异常处理

API 与集成：解释 REST、设计两个系统之间的集成、超时与速率限制、身份验证与授权、诊断失败的请求

AI 应用开发：RAG 与工具调用、工作流与 AI Agent 的对比、评估输出、幻觉与提示词注入、安全的工具执行

系统设计：将需求映射到架构、依赖关系、面向故障的设计、保护敏感数据、权衡取舍

面向客户的沟通：澄清模糊之处、向非技术利益相关者解释、需求变更、坦诚讨论局限性、在时间压力下确定优先级

演练这些问题

  • 你会如何设计一个从公司内部系统检索信息的 AI 助手？
  • 你会如何排查一个在本地正常工作但在生产环境中失败的 API？
  • 你会在什么情况下选择传统工作流而非 AI Agent？
  • 你会如何防止 AI Agent 执行未经授权的业务操作？
  • 你会如何向期望立即得到解决方案的客户解释技术局限性？

可复用的答题方法

澄清需求 → 解释方案 → 讨论权衡 → 处理故障与安全 → 明确验证方式
