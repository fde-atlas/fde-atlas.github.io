FDE 家庭作业：如何搞定它

一些前沿部署工程师的面试流程包含家庭作业，通常是一个贴近真实的数据或集成任务，而不是算法谜题。这是一个展示该职位所需素质的机会：整洁的代码、可靠的判断力和清晰的沟通。以下是应对方法。

把它当作真实的客户工作

家庭作业是对工作的模拟，所以要像 FDE 一样行事。首先明确范围：说明你的假设以及你将构建和不构建的内容的边界，尤其是在题目描述含糊不清的情况下。然后先构建一个整洁、可运行的核心，再进行打磨，一个能运行的小型端到端解决方案胜过一个庞大但半途而废的项目。

像在实战中一样处理那些不体面的现实问题：校验混乱的输入，处理缺失或格式错误的数据，并让任何可能被重复运行的东西具备幂等性。这些细节正是评分者所关注的。

沟通你的决策

一份 README，解释你的假设、你做出的权衡、如果有更多时间你会怎么做，以及如何运行和测试你的代码，往往与代码本身同样重要。它展示了 FDE 所需的沟通能力和判断力。附上测试，哪怕只有几个，也能表明你在乎正确性。

不要过度设计。干净利落地解决问题并解释你的推理，胜过一个聪明但难以读懂的方案。

提交前检查清单

在提交之前，像 FDE 在向客户交付前那样进行同样的审查。

能从干净的克隆中运行

在全新的检出上按照你自己的 README 操作。如果安装步骤出错，评分者的第一印象也会随之崩塌。

边界情况已处理

空输入、格式错误的行、重复项和缺失字段——题目所暗示的那些混乱的现实。

有几个真实的测试

哪怕只有几个覆盖核心逻辑和一个边界情况的测试，也能表明你在乎正确性。

README 物有所值

假设、权衡、如何运行和测试，以及如果有更多时间你会怎么做。简短而诚实胜过冗长而含糊。

常见问题

FDE 家庭作业是什么样的？

通常是一个贴近真实、注重实用的任务——处理数据、构建小型集成或工具——而不是算法谜题。评分标准是整洁且有测试的代码、对混乱输入的合理处理，以及你能否清晰地传达你的假设和权衡。

如何在 FDE 家庭作业中脱颖而出？

一开始就明确范围并说明你的假设，先构建一个干净可用的核心再做打磨，对混乱和缺失的数据做防御性处理，附上测试，并写一个 README 说明你的决策以及如果有更多时间你会怎么做。

FDE 的带回家作业需要附上 README 吗？

需要。一份清晰的 README，说明你的假设、权衡、后续步骤以及如何运行和测试代码，恰恰展示了 FDE 岗位所考察的沟通能力和判断力，它的分量往往不亚于代码本身。

FDE 带回家作业应该花多少时间？

遵守给定的时间限制；如果没有限定，目标是花几个小时做出一个干净、范围明确的成果，而不是耗掉整个周末。评分者更看重一个附带清晰思路的小型端到端解决方案，而不是过度构建的作品，所以如果时间不够，就缩减范围，并在 README 中说明你接下来会做什么。
