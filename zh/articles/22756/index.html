简要总结

FDE 编程环节看起来不像解谜题，更像现场工作的一天：读取一份真实感十足的数据样本，调用一个有分页和限流的 API，正确地聚合结果，并修复别人代码里的 bug。面试官希望你的代码尽早跑起来，能处理那些乏味的边界情况（重复、时区、金额、重试），并且边写边测试。巧妙的算法不如正确性和清晰的结构重要——当追问来临时，这种结构要能方便地扩展。

这个环节考察什么

我们题库中来自 FDE 面试的两道编程题都很实用：调用一个 REST API 并使用其结果，以及校验表单并将行追加到表格中。本页列表中的其他题目也类似，都是来自招聘 FDE 的公司工程面试环节的工作：查询一个端点并合并结果，将日志或 CSV 解析成报告，爬取相互链接的资源，或找出小型服务中的 bug。其中两道题会让你进入一个现成的多文件代码库，而不是空白编辑器。

  • 快速写出能运行的代码，然后逐步改进，而不是在脑子里设计 20 分钟。
  • 仔细阅读数据或 API 契约：字段类型、可空性、分页、错误码、单位和时区。
  • 处理真实数据中的边界情况：重复、乱序记录、格式错误的行、部分失败、金额和日期。
  • 结构：为获取、解析、转换和输出编写小函数，这样追问（“现在加上缓存”“现在让它可断点续传”）就只是小改动。
  • 调试不是你写的代码：复现、隔离、修复，并用测试保护修复结果。

如何应对：阅读、探查、搭骨架、跑通主流程、加固、验证

我们的指导（编辑观点），非候选人报告

  • 阅读契约 在编码前，用注释写下输入的结构和期望的输出：字段名、类型、哪些字段可能缺失，以及 API 在数据末尾的行为。对样本无法确定的问题要提问（金额是字符串还是数字？日期是哪个时区？）。
  • 探查数据 打印三条记录、总数，以及任何状态字段的去重值。寻找空值、重复和混合格式。这里花两分钟，之后能省二十分钟。
  • 搭骨架 为获取、解析、转换和报告写出函数签名，并用一个 main 函数把它们串起来。即使函数体还没写，面试官也能看懂你的计划。
  • 端到端跑通主流程 让最小的输入产生正确的输出，并运行它。第 15 分钟能运行的代码，比第 40 分钟完美的代码更有价值。
  • 加固：添加分页终止条件、针对 429 和 5xx 的指数退避重试（遵循 Retry-After）、超时处理、按键去重、精确的十进制金额、带时区的日期，以及坏数据的处理位置（统计并保留坏行及其原因，而不是崩溃或静默丢弃）。
  • 验证并谈规模：对一个手工计算过的用例进行断言，为你处理的每个边界情况添加一个测试，然后说明数据量扩大 100 倍时会有什么变化：用流式处理代替全部加载、对游标做检查点、并发限制。

实例：从分页的订单 API 计算每个客户的收入

提示词

一个订单 API 返回 JSON 分页数据，每页最多 200 个订单，并带有 next_cursor 字段（最后一页为 null）。当请求过快时返回 HTTP 429 和 Retry-After 头，偶尔返回 503。每个订单包含 id、customer_id、status（paid、partially_refunded、refunded、cancelled）、amount 和 refunded_amount（十进制字符串）、currency、created_at 和 updated_at（ISO 8601，UTC）。给定一张汇率表，计算过去 30 天内创建的订单中每个客户的美元净收入。订单在你翻页时可能发生变化，因此同一订单可能出现两次。

候选人首先说明提示词中留白的关键决策：净收入等于 amount 减去 refunded_amount；已取消和全额退款的订单计为零；当同一订单出现两次时，以 updated_at 较新的那份为准；未知货币是要报告的错误，而不是静默跳过。按 updated_since = 截止时间过滤是安全的，因为窗口内创建的订单不可能在截止时间之前被更新。

import random
import time
from collections import defaultdict
from datetime import datetime, timedelta, timezone
from decimal import Decimal

import requests

ORDERS_URL = "https://api.example.com/v1/orders"
RETRYABLE = {429, 500, 502, 503, 504}


def get_with_retries(session, url, params, max_retries=5):
    """GET with backoff. Retries timeouts, 429 and 5xx; any other 4xx is a bug in our request."""
    for attempt in range(max_retries + 1):
        try:
            resp = session.get(url, params=params, timeout=10)
        except (requests.ConnectionError, requests.Timeout):
            resp = None
        if resp is not None and resp.status_code not in RETRYABLE:
            resp.raise_for_status()
            return resp
        if attempt == max_retries:
            break
        if resp is not None and resp.status_code == 429 and resp.headers.get("Retry-After", "").isdigit():
            wait = int(resp.headers["Retry-After"])
        else:
            wait = min(30, 2 ** attempt) * random.uniform(0.5, 1.0)  # exponential backoff with jitter
        time.sleep(wait)
    status = resp.status_code if resp is not None else "network error"
    raise RuntimeError(f"giving up on {url} after {max_retries} retries ({status})")


def fetch_orders(session, updated_since):
    """Yield every order updated since the given time, following the cursor to the end."""
    params = {"updated_since": updated_since.isoformat(), "limit": 200}
    while True:
        body = get_with_retries(session, ORDERS_URL, params).json()
        yield from body["data"]
        cursor = body.get("next_cursor")
        if not cursor:
            return
        params = {"cursor": cursor, "limit": 200}
def parse_ts(s):
    # fromisoformat only accepts a trailing "Z" from Python 3.11 on.
    return datetime.fromisoformat(s.replace("Z", "+00:00"))


def net_revenue_by_customer(orders, fx_to_usd, now, days=30):
    cutoff = now - timedelta(days=days)

    latest = {}  # order id -> newest copy seen
    for o in orders:
        prev = latest.get(o["id"])
        if prev is None or parse_ts(o["updated_at"]) > parse_ts(prev["updated_at"]):
            latest[o["id"]] = o

    totals = defaultdict(Decimal)
    for o in latest.values():
        created = parse_ts(o["created_at"])
        if not (cutoff <= created < now) or o["status"] in ("cancelled", "refunded"):
            continue
        if o["currency"] not in fx_to_usd:
            raise ValueError(f"no exchange rate for {o['currency']} (order {o['id']})")
        net = Decimal(o["amount"]) - Decimal(o.get("refunded_amount") or "0")
        totals[o["customer_id"]] += net * fx_to_usd[o["currency"]]

    return {c: v.quantize(Decimal("0.01")) for c, v in totals.items()}


def main(session, fx_to_usd):
    now = datetime.now(timezone.utc)
    orders = fetch_orders(session, updated_since=now - timedelta(days=30))
    return net_revenue_by_customer(orders, fx_to_usd, now)
class FakeResp:
    def __init__(self, status, body=None, headers=None):
        self.status_code, self._body, self.headers = status, body, headers or {}

    def json(self):
        return self._body

    def raise_for_status(self):
        if self.status_code >= 400:
            raise requests.HTTPError(self.status_code)


class FakeSession:
    def __init__(self, responses):
        self.responses = list(responses)

    def get(self, url, params, timeout):
        return self.responses.pop(0)


def order(id, cust, amount, updated, status="paid", refunded="0.00", cur="USD"):
    return {"id": id, "customer_id": cust, "status": status, "amount": amount,
            "refunded_amount": refunded, "currency": cur,
            "created_at": "2026-11-01T10:00:00Z", "updated_at": updated}


def test_dedupes_refunds_and_retries(monkeypatch):
    monkeypatch.setattr(time, "sleep", lambda s: None)
    page1 = {"data": [order("o1", "c1", "100.00", "2026-11-01T10:00:00Z"),
                      order("o2", "c2", "50.00", "2026-11-01T10:00:00Z")],
             "next_cursor": "abc"}
    # o1 changed while we paged: it reappears with a partial refund.
    page2 = {"data": [order("o1", "c1", "100.00", "2026-11-02T09:00:00Z",
                            status="partially_refunded", refunded="30.00"),
                      order("o3", "c2", "20.00", "2026-11-01T11:00:00Z", status="refunded", refunded="20.00")],
             "next_cursor": None}
    session = FakeSession([FakeResp(429, headers={"Retry-After": "1"}),
                           FakeResp(200, page1), FakeResp(200, page2)])
    now = datetime(2026, 11, 10, tzinfo=timezone.utc)
    orders = fetch_orders(session, now - timedelta(days=30))
    assert net_revenue_by_customer(orders, {"USD": Decimal("1")}, now) == {
        "c1": Decimal("70.00"), "c2": Decimal("50.00")}

面试官看到的是：抓取是一个生成器，因此无论有多少页，内存占用都保持平稳；重试只覆盖可以安全重试的失败；金额从不接触浮点数；重复订单的情况由事先声明的规则处理，并有测试证明。当被问及规模时，候选人补充道：每抓取一页后持久化最后的游标，这样崩溃后可以恢复而不是重新开始；如果多个 worker 共享一个 API key，应在调用前加一个共享的令牌桶，而不是让每个 worker 各自退避。

常见追问及其考察点

  • “任务在第 900 页中的第 400 页挂掉了。重跑时会发生什么？”
  • 考察可恢复性。每处理一页后对游标（以及部分聚合结果，或从存储的原始页面重新计算）做检查点，并确保重复处理是幂等的，这样重复的页面不会导致重复计数。
  • “你会重试一个创建支付的 POST 请求吗？”
  • 考察幂等性。只有在服务器支持幂等键（idempotency key）时才可以；否则超时后重试可能导致重复扣款。读操作可以安全重试，写操作需要幂等键或先检查再写入。
  • “十个 worker 共享一个 API key，限制为每秒 50 个请求。”
  • 探查协调能力。各 worker 独立退避会导致相互碰撞。使用共享限流器（Redis 中的令牌桶，或由单一抓取器向队列供数），并将其容量设置在限额以下。
  • “如何在不访问真实 API 的情况下测试这段代码？”
  • 探查可测试性设计。注入 HTTP 会话（如上所述），将几条真实响应保存为测试夹具，并添加契约测试，按计划定期对沙箱运行，而不是每次提交都运行。
  • “百分之十的行解析失败，你会怎么处理？”
  • 探查数据质量判断力。不要默默丢弃：统计数量，保留每条失败记录及其原因，报告失败率，并与客户商定一个中止运行的阈值。

常见错误

  • 用浮点数处理金额，最后才四舍五入，导致总额与客户财务团队的计算不一致。
  • 比较无时区与带时区的日期时间，或把 UTC 时间戳当作本地业务日期。
  • 分页循环没有明确的结束条件，或者跳过了最后一页。
  • 捕获所有异常并继续执行，把 bug 变成静默的错误数字。
  • 重试那些不安全、不宜重复执行的请求。
  • 在生成器即可胜任的情况下，却把所有页面加载进列表再处理。
  • 在连一条记录都还没解析出来之前，就先搭建类层次结构。

常见问题

  • FDE 编程面试比标准软件工程编程面试更容易吗？
  • 它是不同，而不是更容易。算法深度的重要性较低，但在混乱数据、API 行为和代码质量方面的正确性标准很高，而且问题更长、更开放。
  • 我应该使用哪种语言？
  • Python 是最常见的选择，因为数据处理和 HTTP 的代码写起来很短。除非公司要求特定语言，否则请使用你最快、最不容易出错的语言。
  • 面试期间我可以查资料吗？
  • 这因公司和环节而异，我们的报告也没有明确说明。请在开始时询问允许什么。即使允许查阅文档或使用助手，也要说明你在查什么以及为什么。
  • 我需要背 LeetCode 题型吗？
  • 要熟练掌握基础知识（哈希表、排序、堆、BFS 和 DFS、区间、滑动窗口），因为它们会出现在实际问题中。为这个职位刷几百道题是对时间的糟糕使用。
