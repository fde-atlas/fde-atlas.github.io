什么是前沿部署工程师？为什么他们如此抢手？

初创公司和成长期公司正在疯狂招聘一个由 Palantir 首创的软件工程职位。本文将深入剖析这一职位，以及为什么 FDE 在 2025 年如此受欢迎

编者按：通讯已从暑假中回归。播客方面，8 月将没有新节目：播客节目将于 9 月回归。在此期间，你可以收听往期播客节目。

今年 AI 初创公司领域一个有趣的趋势，是一个名为“前沿部署工程师”（FDE）的专业软件工程职位的崛起。它甚至被风险投资（VC）公司 a16z 称为“科技行业最热门的工作”。

FDE 的工作内容融合了软件、销售和平台工程，自今年年初前后以来，在 AI 解决方案集成需求的推动下，该职位的招聘量大幅上升。但招聘这一职位的并不只有 AI 初创公司。

今天，我们来深入了解 FDE，内容包括：

  • 什么是前沿部署工程师（FDE）？一种在客户团队和核心产品工程团队之间轮换驻场的软件工程师。这可能是一份颇具挑战的工作！
  • 起源。直到 2016 年，Palantir 拥有的 FDE（该公司称之为“Delta”）比软件工程师还多。没有其他公司比这家神秘的科技公司更能塑造这一职位了。
  • OpenAI 的这一职位。这家 ChatGPT 制造商于今年早些时候设立了该职位，并将其与解决方案架构师这类专业服务型岗位区分开来。
  • Ramp 的 FDE。该职位于 9 个月前设立，Ramp 目前拥有约 15 名 FDE，以小组形式按照四项核心运营原则开展工作。
  • 为什么现在这么火？集成 LLM 和基于 AI 的产品是该职位的完美用例，而 Palantir 的商业成功也与 FDE 密切相关。
  • FDE 与解决方案工程师（SE）和 Agent 工程师（AE）的对比。两者有相似之处，但通常期望 FDE 对核心产品做出更多贡献。
  • FDE 职业发展。如何招聘 FDE、薪酬水平以及潜在的职业晋升路径。

感谢 Colin Jarvis（OpenAI FDE 负责人）、Leo Mehr（Ramp FDE 负责人）和 Anjor Kanekar（曾在 Palantir 担任 FDE 长达 7 年）提供的意见。Anjor 目前可承接 FDE 架构设计或招聘方面的顾问工作——详情请联系他。

1. 什么是前沿部署工程师？

FDE 的招聘广告描述了几个主要特征：

软件工程基础。几乎每一位招聘方都要求扎实的软件工程背景，以及一些实际经验来证明基础功底到位。Ramp 对高级 FDE 职位偏好 5 年以上的经验，但也会录用一些特别优秀的新毕业生担任 FDE。Palantir 录用毕业后仅有约一年工作经验的人，而医疗初创公司 Commure 和工业 AI 初创公司 Matta 都重视从零到一构建并交付项目的真实经验。

与销售团队协作以促成客户成交。许多雇佣 FDE 的初创公司会利用他们来帮助赢得客户。基本上，当客户还不确定能否有效使用某产品时，销售团队会提出派一名 FDE 帮助他们成功完成集成。以下是 Ramp 在一则招聘广告中的表述：

“与我们的销售和市场推广团队紧密协作，促成令人振奋的交易，激活客户，并随着时间推移不断扩大 Ramp 所提供的价值”。

嵌入客户团队。正如 OpenAI 的一则广告所说：“作为 FDE，你将深入客户团队，理解他们的领域，并共同开发解决方案，以应对那些往往界限模糊或不断演变的问题空间中的真实问题”。

这类工作通常需要多次前往客户现场与他们并肩工作，这是相当标准的做法。Palantir 预计 FDE 约 25% 的时间要在客户现场度过，而医疗 AI 公司 Commure 估计这一比例高达 50%。

对于服务特殊客户的企业来说，这可能意味着要在更难进入的工作环境中工作。例如，工业 AI 初创公司 Matta 期望 FDE 能“在工厂车间里规划解决方案”。前 FDE Anjor Kanekar 表示，他在 Palantir 工作时曾待在航空航天制造商 Airbus 的总装生产线上，他的许多 FDE 同事也在类似的非常规环境中工作，包括物理隔离（airgapped）的环境。可不是典型的办公场所！

为核心产品做贡献，并嵌入核心产品工程团队。正如 Ramp 所描述的，FDE 需要：

“推动核心产品工程路线图，并做出重要的优先级和范围决策，决定我们何时构建定制化解决方案、何时加速推进现有的更大项目。Ramp 的团队采用嵌入模式，让 FDE 嵌入核心产品工程团队，在最相关的技术领域积累专业能力”。

帮助客户取得成功。这一角色的核心是在公司产品的基础上进行构建，让客户获得成功。正如机器人初创公司 Gecko Robotics 所表述的：“[FDE] 寻找我们能找到的影响最大的问题，我们花大量时间与客户相处以理解问题的真正本质，我们提出新的[方法]，并且在达成影响力之前绝不放弃”。

有些地方把这个角色更多视为技术顾问。AI Agent 管理平台 Lindy 期望 FDE 帮助客户构建和维护他们的无代码工作流，“同时担任他们的技术顾问”。显然，顾问与既服务客户又参与产品开发的工程师之间的界限可能是模糊的。

每家公司对 FDE 都有自己的定义。这个角色相当新，意味着各工作场所会自行定义对它的期望。有些更强调 FDE 完成销售管道，有些强调协助客户，还有些则专注于为核心产品做贡献。

这个角色似乎承载着许多期望；例如，以下是 Salesforce 对高级 FDE 的期望：

  • 通过亲身实践推动切实成果
  • 构建变革性的 AI 解决方案
  • 工程化定制智能体 AI 解决方案
  • 负责整个数据配置与集成生命周期
  • 主动清除技术障碍
  • 推动 Agentforce 创新
  • 成为值得信赖的战略合作伙伴
  • 进行深入的技术调试和根因分析
  • 主导快速原型设计与迭代
  • 实施并推行最佳实践

这份清单相当长，看起来类似于对经验丰富的软件工程师——通常是高级及以上级别——的隐性期望。我个人很喜欢 Palantir 的定义，它概括了这一切：

“FDE 的职责类似于初创公司 CTO：你将在小团队中工作，并负责高风险项目的端到端执行。”

与 FDE 高度相似的角色可能有不同的称呼。“Agent 工程师”、“解决方案架构师”、“售前工程师”和“技术交付工程师”都与前沿部署工程师的工作非常接近。区别在于 FDE 既与客户合作，也为公司销售的产品做贡献。

以下是我自己对 FDE 通常是什么的心智模型——需要注意的是，在 FDE 不参与产品开发的地方，“平台工程师”这一部分可能不那么被强调：

2. 起源

“前沿部署软件工程师”这一角色由数据挖掘巨头 Palantir 于 2010 年代初创立，最初名为“Delta”。Palantir 成立于 2003 年，为执法机构和军方等政府机构以及私营公司提供服务。它处理的数据通常是敏感且专有的。

直到大约 2016 年，Palantir 的 FDE 数量都多于“普通”软件工程师。那一年，一款名为 Palantir Foundry 的产品发布：这是一个面向商业和民用政府部门构建的集成数据平台。从那时起，更多 FDE 转回软件工程师的工作，负责开发 Foundry，并将他们在一线积累的经验带入这一核心产品。

即使在今天，没有哪家公司雇佣的 FDE 比 Palantir 更多，也没有哪家初创公司或成长期公司对该职位的影响力能与之相比。以下是 Palantir 更详细的解释：

“Delta（前沿部署软件工程师）负责将我们的软件平台部署到客户那里。Delta 隶属于业务发展部门，他们的使命是为客户实现技术成果。作为直接支持某一客户的团队的一员，Delta 专注于以技术驱动的价值创造：部署和定制 Palantir 平台以解决关键业务问题。他们以对客户目标的影响来衡量成功。例如，我们与希望减少装配线上缺陷产品数量的制造商合作。为了改善这一指标，Delta 会使用 Palantir 产品、多种语言、开源工具和行业标准构建工具，并发挥自己的创造力来设计解决方案。你可以把 Dev 的关注点理解为“一个能力，服务多个客户”，而 Delta 的关注点则是“一个客户，运用多种能力”。

FDE 有时会被误认为是顾问，但顾问与 FDE 的区别在于：前者提供一次性的建议，而 FDE 通常与客户长期合作。

如前所述，FDE 也会为核心产品做出贡献。当客户需要的能力缺失时，FDE 可以承担“开发”工作，为 Palantir 的产品添加功能和改进。

在 Palantir 担任 FDE 的日常

两位 Palantir 的 FDE 曾在 2019 年分享过他们典型的一天：

“Dyon（阿布扎比）：“大多数周里，我会花几天时间在客户现场工作，其中一部分时间用于与技术或业务利益相关者开会，其余时间则用于监控、调试、部署或为该客户配置我们的软件。回到办公室后，我会花一些时间编写小的代码改动、审查 pull request，以及研究/规划客户解决方案。剩下的时间则用于通过电子邮件或视频会议与我们的内部支持和产品开发团队沟通，以及与分布在多个远程办公室的直接下属沟通。” G.M.（圣保罗）：“我的‘日常工作’每个月都在变化，这是我这个职位的一个很酷的特点！有些周，我大部分时间都在开发和审查团队的代码，就像典型的软件工程师一样。另一些周，我大部分时间则用于与客户规划项目的未来方向，或者与用户一起确保我们构建的东西满足他们的需求。”

总的来说，Palantir 的 FDE 典型的一周通常是以下几方面的混合：

  • 为客户进行项目工作： 主要关注点
  • 改进 Palantir 的平台/系统： 当 Palantir 的平台妨碍功能构建时，FDE 会做一些事情，比如配置新的数据模型、贡献稳定性改进，或向平台提交修复
  • 跟进内部事务：内部沟通、邮件、会议、站会、与同事会面、共享项目等。

以上内容看起来似乎描述了两种不同的工作（类似顾问的工作/平台工程师的工作）合二为一！这正是这个角色的微妙之处：根据 Palantir 一位 FDE 的说法，学会说“不”是做好这份工作的一部分：

“我通常会问自己‘这个讨论必须开成会议吗？我必须参加吗？’，以此来限制花在会议上的时间。公司里大多数人也是类似的做法，这让我参加的每一场会议最终都能高效利用我的时间。”

为什么 Palantir 雇佣这么多 FDE？

Palantir 与政府机构以及我认为属于“传统”类型的公司有大量合作。我怀疑如果没有 FDE 这样的角色，这些较为传统的企业将难以把 Palantir 的系统集成到自己的系统中。

相比之下，初创公司行动敏捷，雇用的开发者通常乐于尝试，也不介意把解决方案“拼凑”出来。但大型企业往往恰恰相反：把事情办成与其说是技术挑战，不如说是官僚流程问题，而且“不关我事”的心态会阻碍项目推进。

通过派出被充分授权、使命是以能为客户创造价值的方式集成 Palantir 软件的工程师，Palantir 可谓“一石二鸟”：他们对内部官僚体系浑然不觉，因此不必太担心；同时他们派出的是一位抱着“我怎样才能让它跑起来”而非“这为什么行不通”心态的“初创思维”开发者来做集成。与 Palantir 签约的公司在软件集成上的进展，比自己动手要快得多。

3. OpenAI 的 FDE 角色

Colin Jarvis 是 OpenAI 前沿部署工程负责人。他于 2022 年以解决方案架构师的身份加入公司，去年成为解决方案架构负责人。今年年初，Colin 提出了组建前沿部署工程团队的商业方案，以提供更有针对性的服务。该团队最初只有两名 FDE，如今公司已有超过 10 名，分布在：

  • 美国：纽约和旧金山
  • 欧洲：都柏林、伦敦、慕尼黑、巴黎
  • 亚洲：东京和新加坡

OpenAI 仍设有“解决方案架构师”（SA）角色。SA 和 FDE 都在应对同一个挑战：LLM 对客户来说使用起来过于复杂。

FDE 更加亲力亲为，通常比传统意义上的 SA 面对更多的不确定性。SA 更像顾问角色：他们很少在客户的基础设施上编写代码，通常使用匿名化或离线的数据切片来构建最小可行产品（MVP）或概念验证（PoC）。

FDE 的工作方式更加亲力亲为：他们直接在客户的基础设施上编写代码，并使用客户的工具来完成这项工作。FDE 同时也契合 OpenAI 的研究目标，并与最有可能构建出有助于推进 OpenAI 研究方向的解决方案的客户合作。相比传统的云解决方案架构师，FDE 需要在更多的模糊性中开展工作。

FDE 有助于推进产品路线图。 有一个案例中，OpenAI 与一家语音客户合作开展呼叫中心自动化项目，FDE 为语音模型创建了评测。起初，模型的表现不够好，客户不愿承诺部署。

于是，FDE 团队带着数据回到 OpenAI 的研究部门，致力于提升模型在语音用例上的表现，最终使该客户成为首家在生产环境中部署这一先进解决方案的客户。

OpenAI 的 Realtime API 也因这项工作得到了改进。最终，这是一个双赢的局面：客户借助 FDE 更快地获得了更先进的能力，而 OpenAI 则通过真实案例测试了改进效果，并为所有客户改进了产品。

OpenAI 的工作结构

Colin 讲解了他们的 FDE 团队如何看待工作中相互并行的各个维度：

面向客户的 FDE 工作结构

客户项目分为三个阶段：

早期范围界定（阶段 #1）与客户现场共处几天

  • 与用户坐在一起，梳理他们的流程
  • 找出价值最大的领域
  • 使用合成数据进行原型开发
  • 在白板上讨论想法并排定优先级

验证（阶段 #2）。FDE 驻扎到客户现场，回答这个问题：“我们界定出的范围，是否是我们能为客户做的最有价值的事情？”如果是，他们就商定验证标准。制定验证标准通常包括：

  • 结合用户输入和标注构建评测（针对 LLM 应用的质量检查）
  • 扩展标注流程
  • 构建功能并基于评测进行爬坡优化（优化模型，使其在预先定义的质量检查上表现更好）
  • 提交最终报告，展示评测表现与目标的对比

Colin 表示，在交付之前进行验证并不常见，但这样做有充分的理由：

“FDE 在大量的模糊性中工作，客户在范围界定阶段描述的内容往往与实际的数据/系统情况不符。我们倾向于快速行动，先验证是否存在无法逾越的障碍，然后在存在不可克服的约束的情况下，将范围调整到我们能做的最有用的事情上。”

交付（阶段 #3）。驻扎在客户现场，通常每周几天

  • 了解问题的确切细节
  • 从客户那里获取数据
  • 构建解决方案——通常在 OpenAI 办公室进行——然后向客户演示
  • 聚焦于能形成端到端解决方案（或演示）的“最小可行单元”

一个有趣的例子：在美国爱荷华州，一位 FDE 与 John Deere 合作开展了一个项目——这是一家拥有 200 年历史的农业基础设施企业。他们帮助解决了“个性化农户干预”规模化的问题。此前，客户通过人工电话联系农户，向他们提供如何充分利用农业设备的提示和建议。

但客户希望农户能获得个性化洞察，以最大限度地利用其最新的除草技术，该技术减少了喷洒在农作物上的农药用量，从而节省了大量资金。

作为项目的一部分，Colin 和一位 FDE 前往爱荷华州，直接与农户一起工作。

Colin Jarvis 在爱荷华州的一个农场，作为 John Deere 项目的一部分。这可真是名副其实的“实地经验”！

项目的时间非常紧张：John Deere 希望新功能能在下一个种植季之前就绪，届时农作物已完成播种，有效喷洒至关重要。团队在如此紧凑的时间框架内完成了集成，该项目被认为是成功的。

面向内部的 FDE 工作结构

虽然 FDE 的主要工作是参与客户项目，但他们也与 OpenAI 分享知识，并与内部团队合作：

  • 与研究团队定期举行知识分享会，通常每两周一次
  • 每两周与 OpenAI 的产品负责人和产品经理进行一次汇报
  • “FDE 实地笔记” Slack 频道，所有 FDE 都可以在这一内部公开频道中分享见解
  • 每季度举办一次训练营，将整个 FDE 团队聚集在一起。这一点很重要，因为团队成员目前分布在 3 大洲的 8 个城市

FDE 团队是 OpenAI Agents SDK 的重要贡献者。OpenAI 的解决方案架构团队创建了 Swarm 框架，旨在帮助客户更轻松、更快速地集成 OpenAI API。他们是在意识到现有的 agent SDK 学习曲线较高之后，希望在向客户交付 agent 网络时提供更简单的方案，才这样做的。

如今，Swarm 框架已被 OpenAI Agents SDK 取代，解决方案架构团队和 FDE 团队都为其做出贡献。
