AI Agent 权限管理设计｜FDE 实践技巧

原标题：AIエージェントの権限管理設計｜FDE実践術

日本Fde協会 · 2026-09-29 · 约 6 分钟读完

摘要

这篇由日本FDE协会发布的文章面向前沿部署工程师，讲解AI Agent在客户现场执行实际业务动作时的权限管理设计。文章指出，当Agent开始发邮件、更新数据、创建订单时，最先被破坏的是职务分工，而权限设计若被推迟，往往导致“先给管理员权限再说”的过度授权。作者提出三个判断轴：读与写、可逆与不可逆、影响范围大小，并据此决定哪些动作需要人工审批、哪些只需记录日志。文章强调日志必须记录“以谁的名义、基于什么依据执行”，仅有Agent名义的日志无法作为审计证据，最后提醒权限设计意图需文档化以防人员更替后无法解释。

要点

  • Agent执行写操作时职务分工最先崩坏。
  • 权限按读写、可逆性、影响范围三轴划分。
  • 不可逆动作须人工审批并留审计证据。
  • 日志须记录指示者、内容、对象与结果。
  • 权限设计应在导入前完成并文档化。

本文所说的 FDE 指 Forward Deployed Engineer（前沿部署工程师，即深入客户现场、将 AI 和软件结合业务进行实现与运用的技术人员），并非指磁盘加密的 Full Disk Encryption。当 AI Agent 真正开始代行业务时，许多现场最先出现问题的就是权限管理。读完本文，您将能够判断如何划分 AI Agent 的权限管理、哪些操作需要保留审批、日志和审计追踪，并将权限设计项目纳入贵公司的导入计划。正是在导入之前的现在，让我们一起思考吧。

AI Agent 权限管理中最先崩溃的是职责分离

如果 AI 只是在聊天中回答问题，几乎不会涉及权限的话题。然而，当 Agent 开始执行“发送邮件”“更新数据”“创建订单”等操作的那一刻，情况就完全不同了。我们在导入支持现场最先确认的一点是：该 Agent 以谁的权限运行。

“人的替身”会破坏职责分离

业务本来就有将创建者和审批者分开的职责分离机制。但如果把一切都交给 Agent，创建和相当于审批的判断就会由同一个主体掌握，管控会瞬间崩溃。曾有一个制造业客户的现场案例：负责整理采购数据的 Agent 甚至被赋予了更新权限。虽然很方便，但谁批准了该变更没有留下记录，事后盘点时处于无法追踪的状态。

过度权限源于“先全部给上再说”

如果把权限设计往后推，为了加快开发进度，往往会把管理员权限整个交出去。我们也重视以最快速度展示可运行成果的姿态，但权限是例外。Agent 所需要的，只是让该业务成立的最小范围。过度权限会在事故发生时直接扩大受害范围。

划分权限范围的 3 个判断维度

那么应以什么标准来划分权限呢？我们把现场使用的思路整理为 3 点。

是读取，还是写入

第一条界线是区分仅参照信息的操作和改变状态的操作。参照类可以相对宽松地授予，但写入、更新、删除、发送、下单等改变状态的操作要分别独立评估。“能读就能写”的想法正是过度权限的入口。

可撤销，还是不可撤销

其次，要看该操作是否可撤销。像向外部发送邮件、资金转移、对外下单这类一旦执行便无法回退的操作，不应单独交给 Agent，而应以插入人工审批为前提进行设计。在接近金融领域的业务中，这种不可逆操作的剥离是权限设计的核心。

影响范围波及到哪里

第三是影响范围。是在一条记录内完成，还是波及多个部门或外部系统。在像医疗这样所处理信息敏感性高的现场，即使是参照类，也要限定能访问谁、哪些数据，并通过设计堵死超出范围的访问。

操作的性质权限授予的思路审批与日志的处理
仅参照限定对象范围后授予记录访问日志
可撤销的更新以最小范围授予记录变更前后
不可撤销的执行避免单独授予必须有人工审批＋审计追踪

如何保留审批流程与操作日志、审计追踪

划分好权限后，接下来要建立事后能够说明“谁做了什么”的状态。这正是一般工具使用说明中容易遗漏的部分。

审批只针对不可逆操作插入

如果所有操作都插入审批，运营就会停滞。只在不可撤销的执行和影响范围大的变更中引入人工审批，其余自动运行。这条界线正是导入设计的关键所在。审批记录中要留下谁在何时批准了什么，以便日后审计可追踪。

日志要记录到“以谁的代理身份做了什么”

Agent 操作日志中重要的是，不能只记录“更新了”，而要记录借用了哪个用户的权限、基于什么依据执行。曾有一位 SaaS 企业经营者来咨询，他们有日志，但全部以 Agent 名义记录，无法追溯到实际下达指示的人。这样就无法作为审计追踪发挥作用。建议从一开始就采用将指示者、执行内容、对象、结果成套记录的设计。

防止个人依赖的文档化也是设计的一部分

权限设计并非做一次就结束。如果不把“为什么将该权限限定在该范围”记录下来，一旦负责人更换，就没人能说明判断依据。我们认为，将设计意图写入文档、形成可交接的形式，也是权限管理的一部分。整个工作流程的设计步骤请参阅业务工作流与数据联动的设计步骤，所需技能的全貌请参阅FDE 所需技能的全貌｜8 大领域详解。

常见问题

问：AI Agent 权限管理应该在导入前还是导入后设计？ 建议在导入前纳入设计。事后补做的话，过度权限会成为既成事实，之后再收紧会遇到运营方面较大的阻力。

问：是否应该为所有操作插入人工审批？ 不是。只针对不可撤销的执行和影响范围大的变更插入审批，其余自动运行更符合现实。请根据贵公司的管控方针和行业要求进行判断。

问：操作日志要记录什么才能作为审计追踪使用？ 基本原则是将指示者、执行内容、对象、结果成套记录。仅有 Agent 名义的日志无法追踪是谁的指示，难以作为审计追踪发挥作用。
