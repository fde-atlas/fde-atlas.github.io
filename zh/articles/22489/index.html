FDE 在 Factory：面向 Agent 就绪的代码

原标题：FDE chez Factory : le code prêt pour les agents

SFEIR AI · 2026-11-10 · 约 5 分钟读完

摘要

本文分析 Factory 联合创始人兼 CTO Eno Reyes 在 AI Engineer World's Fair 2026 的 21 分钟演讲。他拒绝纯咨询式代码现代化项目，主张前沿部署工程师应推动产品改进，并提出以确定性验证循环的密度衡量代码对 AI Agent 的就绪度。

要点

  • Factory 拒绝纯服务型项目，前沿部署工程师的职责是把大客户的反馈带回产品 Droid。
  • 软件开发被比作工厂：信号进、计划出、自动验证后部署，人类负责建造和维护这条流水线。
  • 代码就绪度取决于确定性验证循环（lint、类型、安全、测试）的密度，密度越高 Agent 可自主工作越久。
  • Droid 只能弥补 30%–40% 的差距，其余需改变开发习惯；Factory 自身代码自主率约 15%–20%。
  • 以 Epcot 为喻：示范代码库应贴近团队日常而非过于超前，才能被效仿。

当客户拿着大型咨询公司的报价单，请 Factory 现代化改造一个代码库时，Eno Reyes 拒绝了（约 3:03 处），即使 Factory 可以用自己的产品完成这项工作。这位 Factory 联合创始人兼 CTO 在 World's Fair 上开启了前沿部署工程专题，并开门见山地解释了这一拒绝：这类项目能带来收入，但 Factory 无法从中为其产品获得任何东西，也不会因此成长。他的部署工程师是产品的先锋：他们带回最大客户的技术管理层和一线工程师的真实想法，Factory 据此调整 Droid。据 Eno Reyes 所说，产品随后必须能在拥有 45,000 名员工、数万个代码库的客户那里几乎自主地落地。

软件工厂：从信号到部署

Eno Reyes 将软件开发描述为一座工厂（约 5:06 处）。信号源源不断地进入：客户对话、缺陷报告、Slack 或 Teams 消息、管理层的决策。人类对这些信号进行分类并制定计划，开发者再将计划转化为代码修改。这些修改通过代码评审、QA、安全分析、SAST、linters 和类型检查，然后进入生产环境，监控又在那里产生新的信号。大多数组织对这一循环的监测做得并不好。Factory 的目标是实现从信号到部署的无人工中断流程，人类负责设计和维护工厂本身。

Eno Reyes 反复强调：“We like to say this is built, not bought”（软件工厂是建造出来的，不是买来的）。Factory 提供构建模块，首先是与模型无关的智能体框架，客户拥有其中的追踪记录和数据，并在集中式治理之下运行。金融、医疗和公共部门的客户可以在无网络连接的情况下运行它；Factory 的一位工程师开玩笑说，甚至可以把它装进潜艇里。

让代码为智能体做好准备

部署工程师的角色在演讲中出现得较晚（约 8:11 处），Eno Reyes 也承认这一点。部署工程师与客户共同构建自主性成熟度模型（大多数企业完全没有），为代码做好面向 AI Agent 的准备，设计工作流，并端到端地讲述投资回报。关于最后一点，Eno Reyes 用一个假设性例子说明：一次经过自动化代码评审、QA 和安全分析的修改，也许能将包含 bug 的风险降低 87%，从而降低缺陷率、提升满意度，最终体现在营收上。

代码准备是最有意思的部分（约 12:14 处）。在 Factory 看来，代码是否为 AI Agent 做好了准备，取决于其确定性验证循环的密度：linter、类型检查、安全分析、端到端测试。这些循环越多，AI Agent 就能在越少人工干预的情况下，在更难的任务上工作更长时间。Eno Reyes 将此与模型训练联系起来——模型需要密集的奖励才能坚持目标。他认为，Droid 单靠自身能弥补 30% 到 40% 的不足；其余部分需要改变习惯，因为开发者很难忍受自动检查的繁琐。他的准则是：凡是能表述为一组检查项的问题，如今都能用 AI 解决。Factory 宣称已完成 3000 万到 5000 万行代码库的自主迁移，但未透露客户名称。

Epcot，或者说不过头的艺术

为了推广这些实践，Eno Reyes 建议打造一个示范性的代码库（约 16:15 处）。他举了 Epcot 的例子：Walt Disney 想要一座作为世界典范的未来之城，结果建成的是一座游乐园，但其他城市仍然借鉴了其中的一些交通理念。一个过于超前的代码库在团队眼中就像游乐园；而足够贴近他们日常工作的代码库，才会让他们产生模仿的意愿。他对 Factory 也同样坦诚：按他自己的衡量标准，其自身代码的自主性约为 15% 到 20%，一个内部法律工具几乎以自主方式维护，还有一个终端模式的测试框架，其某些视觉缺陷（如闪烁）仍无法通过任何自动检查发现。

对 ESN 而言

Factory 把迁移的执行留给别人，并在上游设置了一个前提条件：代码需有测试、linter 和类型检查的覆盖。这两项工作——执行迁移和让代码可验证——正是 ESN 的专长所在。这场演讲为后者提供了一个量化标准：在向代码库投放 AI Agent 之前，先统计其中确定性验证循环的数量。

结论

原创性：4/5。 从信号到部署的闭环、通过验证循环衡量代码就绪度，以及 Epcot 的类比，构成了一个连贯的愿景，而且 Eno Reyes 对拒绝外包服务给出了充分的论证。

信息质量：4/5。 内容技术性强，对 Factory 的局限性坦诚相告，且在其产品之外也有价值。FDE 角色出现得较晚，87% 仅作示例说明，大型迁移也没有提及具体客户。
