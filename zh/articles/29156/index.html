Stakeholder-Mapping

FDE中国社区 · 2026-07-12 · 约 4 分钟读完

摘要

本文是 FDE 中国社区的一个可复用技能包，介绍 AI 项目中的干系人映射方法。核心是用“影响力×态度”矩阵识别业务、IT、合规、一线等角色，制定沟通与升级策略，避免因遗漏 IT/合规或隐形反对者导致项目受阻。文中给出输入输出、执行步骤、阶段门控、与 AIBP 的分工接口，以及政企案例：合规评审前置后提前两周完成。技能包含 checklist、evaluation、prompt 等文件，可导入支持 Agent Skills 的工具。

要点

  • 用影响力与态度矩阵对干系人分类并制定策略。
  • 适用场景包括 Kickoff 前、范围争议、上线推广与续约评估。
  • 常见误区：忽略 IT/合规、漏掉隐形反对者、地图不更新。
  • FDE 主导执行，AIBP 提供 Ground Truth 与验收反馈。
  • 案例中合规评审前置使上线评审提前两周完成。

问题定义

AI 项目涉及业务、IT、数据、合规、一线等多方，缺少干系人地图导致决策慢、推不动。

方法论框架

矩阵：影响力 × 态度（支持/中立/反对）→ 策略（拉拢/说服/隔离/升级）。 关键角色：业务 Owner、AIBP、CIO/IT、安全合规、一线骨干、预算决策者。

常见问题 FAQ

Q1：执行【Stakeholder-Mapping】时如何避免「只映射业务忽略 IT/合规」？

A：按 README 方法论逐步执行，在周度 Demo 展示阶段性交付物；若 PoC 材料不齐，先输出「待验证清单」再推进。

Q2：私有化/信创/等保环境下有哪些额外约束？

A：在 prompt 约束段明确部署形态；涉及数据不出域、国产化组件、审计日志时同步引用 Private-Deployment-Gateway 与 RBAC-Audit。

Q3：与 AIBP 分工边界不清怎么办？

A：回到 AIBP-Collaboration-Playbook 更新 RACI；AIBP 负责 Ground Truth 与业务验收，FDE 负责可交付技术资产。

Q4：PoC 通过后如何衔接到 Beta/生产？

A：输出物中标注下一阶段 Skill（如 RAG-Evaluation→Private-Deployment-Gateway→FDE-Adoption-Growth），并在 checklist 触发上线门禁。
