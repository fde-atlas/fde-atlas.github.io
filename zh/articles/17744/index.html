动手实践

读懂岗位，再为一个真实项目写简报

  • 找一份解决方案工程师的招聘启事和一份 FDE 的招聘启事，分别回答五个问题：这个岗位向工程团队还是销售团队汇报？是在签约前还是签约后加入？你的代码会进入生产环境，还是止步于 POC？上线后谁来值班？薪酬是否和销售业绩挂钩？
  • 挑一个你手头正在做的项目或工单，写一份五段式交接简报：用户是谁、瓶颈在哪里、现在怎么绕过去、他们希望更早做出哪个决策，以及最小可用原型和它的约束条件。
  • 把它改写成一份七行的合作简报，其中“不在范围内”和“交付之后”两行必须写。
  • 连续三个早上，把前一晚以来收到的所有请求写成 P0/P1/P2 分级记录，排序依据是：有没有人被卡住、是谁、谁的决定能让他们继续往下走。

动手实践

拉取、去重并核对一份公开数据集

  • 找一个使用 token 认证的公开 API，用 curl 分别带和不带 token 调用同一个接口；然后在 Postman 里建一个增删改查（CRUD）集合，用 Collection Runner 跑一遍。
  • 用 Python 写一个 pull_all()：显式设置 limit，遇到 429 时重试，并且只在每批数据写入磁盘之后才保存游标。中途强行终止，再重新运行，检查唯一 ID 的数量是否等于写入的行数。
  • 把数据导入本地 PostgreSQL，用四条 SET 语句开启一个分析会话（只读，加上语句超时、锁超时和事务空闲超时），确认写操作会被拒绝。
  • 用 ROW_NUMBER() OVER (PARTITION BY 规范化后的键 ORDER BY updated_at DESC NULLS LAST, id DESC) 去重，再确认源数据中不同键的数量等于筛选 rn = 1 后剩下的行数。
