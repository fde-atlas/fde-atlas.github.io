Celonis FDE 岗位解析：价值工程师与部署工程师

FDE Times · 2026-11-25 · 约 5 分钟读完

摘要

文章对比 Celonis 的两类招聘启事，指出 FDE 头衔实际对应价值工程师，负责客户签约、扩展、采用与续约，需母语级法语或德语；而部署工程师才是动手搭建的角色，指挥 Apollo Agent 生成数据模型与看板，只要求英语。作者提醒求职者细读启事正文与职责动词，避免只看头衔投错岗位，并强调验证 Agent 产出数据的重要性。

要点

  • Celonis 的 FDE 头衔实为价值工程师，负责客户全生命周期。
  • 部署工程师指挥 Apollo Agent 搭建数据模型、KPI 和看板。
  • FDE 岗位要求母语级法语或德语，部署岗只要求英语。
  • 技能分三层：SQL/Python、PQL、ERP 业务流程理解。
  • 建议像读合同一样读招聘启事，核对职责动词。

工程师想象中的 FDE 实操工作在部署工程师岗位上：Agent 搭建看板，只要求英语。

要点速览

  • 巴黎的 Senior FDE 招聘启事把这个岗位称为价值工程师。它和慕尼黑的 FDE 启事都把客户全生命周期交给这个岗位：签约、扩展、采用、续约。
  • 部署工程师启事安排的是动手工作：指挥 Apollo Agent 搭建数据模型、KPI 和看板。它只要求英语。
  • 投递之前先读启事正文里的岗位描述和职责动词，头衔并不能说明实际要做什么。

Celonis 正在巴黎招聘一名“Senior Forward Deployed Engineer”。启事往下读几行，这份工作换了个名字：价值工程师（Value Engineer），即端到端负责客户价值旅程的人。

与此同时，头衔为部署工程师（Deployment Engineer）的启事，描述的才是多数工程师听到 FDE 这几个字母时想到的工作。Lead Deployment Engineer 启事称，这个岗位直接负责在客户处部署 Celonis。Deployment Engineer 启事则把指挥 AI Agent 搭建数据模型和看板的工作交给这个岗位。

这一点很重要，因为在同一家公司里，两个头衔要求两套不同的技能。只看头衔选工作的人，可能投错岗位、准备错面试，一年后才发现工作内容和预期完全不同。

在 Celonis，FDE 头衔挂在负责客户全生命周期的岗位上

巴黎的前线部署工程师（FDE）启事用四个动词概括职责：签约（land）、扩展（expand）、采用（adopt）、续约（renew）。慕尼黑的“Forward Deployed Engineer – CPG/Retail”启事用的是同样四个词。这是客户账户的语言，不是部署项目的语言。

慕尼黑的启事从未提到价值工程师这个说法。但两份启事的动词完全相同，说明它们描述的是同一类岗位，只是巴黎把名字写了出来。

扩展指扩大客户对产品的使用范围，续约指延长合同。职位描述里出现这两个词，就意味着这个岗位要对客户是否留下、是否追加采购负责，远不止让系统跑起来。

Celonis 自己的招聘网站印证了这种理解。一篇介绍价值工程团队的文章说，价值工程师端到端负责每一位 Celonis 客户的完整价值旅程。

同一网站的另一篇文章描述了日常工作：制作演示、商业论证和价值验证项目，把 CEO 的战略目标转化为高影响力的用例。

巴黎的启事在方法上更具体：价值工程师主持业务价值研讨会，用 Celonis 发现并验证流程改进机会。

语言要求把岗位性质说得很清楚。巴黎的启事要求母语级法语，慕尼黑的启事要求母语级德语。慕尼黑还解释了原因：这个岗位要用德语主持研讨会、向高管汇报、与利益相关方合作。

部署工程师做技术工作

Lead Deployment Engineer 启事让这个岗位直接负责客户的部署，包括主持需求调研研讨会。技术方面要求 SQL 和 Python。企业资源计划（ERP）要求写得很细：SAP MM/SD/PP、S/4HANA、APO/IBP，或 Oracle、Kinaxis、o9、Blue Yonder 等同类系统。

发布在 Accel 招聘平台上的 Deployment Engineer 启事，除 SQL 和 Python 外，还要求掌握 Celonis 的流程查询语言（PQL），并具备 ERP 知识。

最能说明问题的是语言要求。Deployment Engineer 启事只要求英语，其他语言是加分项。对于既不会德语也不会法语的工程师，这是两个头衔之间最大的区别。

Agent 搭建看板时，你的工作是检查

Deployment Engineer 启事写道，工程师指挥 Celonis 名为 Apollo 的部署 Agent，搭建数据模型、流程分析、KPI 和看板。如果大部分搭建工作由 Agent 完成，工程师的时间就转向给 Agent 下达任务、阅读它的产出，以及在数字出错时向客户交代。

举一个假设的例子。某客户在 SAP 里有 1,000 条订单行，每张订单分 2 次发货。Agent 没有按订单分组，直接把订单表和发货表连接起来，得到 2,000 行。准时交付 KPI 于是按发货而不是按订单计算，看板看上去却完全合理。

只会给 Agent 写提示词的工程师，会把这个数字带进客户会议。懂数据模型的工程师会在连接前后各数一次行数，发现数字翻倍，然后追问原因。

在真实客户那里，第一步是先核对几个业务人员烂熟于心的数字，比如上个月的订单总数，再去相信任何图表。

同样的流程挖掘底子，对面坐着不同的人

下表把三组启事的要求并排列出，便于看清差异。

主要职责 直接负责客户处的部署 指挥 Apollo 搭建数据模型、KPI、看板 签约、扩展、采用、续约；巴黎启事称该岗位为价值工程师
研讨会 需求调研研讨会 引用文本中未提及 业务价值研讨会；慕尼黑要求向高管汇报
查询语言 SQL、Python PQL、SQL、Python 引用文本中未提及
ERP SAP MM/SD/PP、S/4HANA、APO/IBP 或同类系统 ERP 知识 SAP 类企业软件（慕尼黑）

逐行看，共同点在客户的系统：Lead、Deployment Engineer 和慕尼黑的启事都提到 ERP 或 SAP 类企业软件。

研讨会出现在 Lead 启事和两份 FDE 头衔启事中，区别在于桌子对面坐的是谁。需求调研研讨会服务于搭建方案；价值研讨会和高管汇报服务于说服客户继续投入。

流程挖掘对候选人有什么要求？

综合三组启事，技能要求分为三层。底层是 SQL、Python 和搭建数据模型的能力。中间层是 PQL，这项技能与 Celonis 产品紧密绑定。顶层是理解业务流程在 ERP 中如何运转，从采购、销售到生产计划。

后端工程师通常已经具备底层能力。如果德语或法语达不到母语水平，进入 Celonis 的现实路径是只要求英语的部署工程师岗位；投递前先学 PQL，并深入研究一个 SAP 模块，比如 MM 或 SD。

想冲 FDE 头衔，还需要技术文档教不会的东西：用客户的母语主持价值研讨会、做商业论证的能力。

像读合同一样读招聘启事

第一条建议在任何公司都适用：在启事正文里找岗位描述。Celonis 把“Value Engineer”直接写在巴黎的 FDE 启事里，只看头衔的人会错过它。

其次，数一数职责动词。启事里出现搭建、数据模型、看板，就是部署岗位。出现扩展和续约，就直接问招聘人员这个岗位的成功如何衡量。

申请部署工程师岗位，简历要体现你懂得验证自动化产出。好的一条要点会写清：你在 ERP 数据中发现了什么错误，怎么发现的，以及因为数字正确，客户做出了什么决定。

在 Celonis，FDE 头衔和部署工作分属两份不同的启事。投递前越过头衔看清实际工作，再选择成功标准与你希望被评价的方式相符的岗位。
