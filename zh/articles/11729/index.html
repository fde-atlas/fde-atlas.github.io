摘要

这是一份面向前沿部署工程师的代理协议集成指南（2026年10月版，105页、32章），围绕一次客户购买流程讲解 MCP、A2A、AG-UI、UCP、Agentic Commerce Protocol、AP2、x402 等协议在各边界的职责。核心观点是：每个边界都需要显式契约，应用层必须自行维护操作身份、审批绑定与失败恢复，不能依赖协议自动授权。指南区分发现与信任、接口事件与已提交业务、重试消息与安全业务重试，并通过三个虚构事故（回复丢失、跨租户回调、审批后金额变更）演示恢复方法。配套 Python/SQLite 契约实验含56个测试和8个变异检查，无真实支付或生产部署。

要点

  • 以一次客户购买贯穿讲解各代理协议边界
  • 强调应用需维护操作身份、审批与恢复逻辑
  • MCP 连接工具能力，A2A 连接独立代理，均不自动授权
  • 三个事故案例演示丢失回复与租户错误的恢复

一个 Agent 系统跨越多个边界：模型提议工具调用，宿主调用服务，远程 Agent 拥有任务，而商户或支付提供商拥有外部效果。每个边界都需要明确的契约。

本指南解释这些边界上的协议，并通过一个连贯的架构将它们连接起来。它将发现与信任分离，将接口事件与已提交的工作分离，并将重试的消息与安全的业务重试区分开来。

它们是 AI Agent 系统边界上的契约：模型到工具的调用、对工具和资源的访问、Agent 之间的委托工作、用户界面事件、身份、结账与支付。本指南解释每个协议服务于哪个边界，以及如何在这些边界之间保持权限与可恢复性。

本指南涵盖 MCP、A2A、AG-UI、A2UI、MCP Apps、Agent Client Protocol、UCP、Agentic Commerce Protocol、AP2、x402 和 MPP。它还讲解了 OAuth/OIDC、令牌交换、DPoP、mTLS、工作负载身份、CIBA、PAR、可验证凭据、HTTP 消息签名、OpenTelemetry 和 CloudEvents。WebMCP、ANP、NLWeb、Agent Skills、AGENTS.md、ERC-8004 以及各厂商的支付服务也被置于恰当的语境中，并区分了草案与产品状态同开放协议支持之间的差别。

MCP 将主机或客户端连接到工具、资源和提示等能力。A2A 通过发现、消息、任务和工件连接独立运营的 Agent。两者都不会自动授予代表用户行动的权限。本指南追踪身份、审批和持久业务状态如何跨越这两个边界。

这两个名称都出现在生态系统中。Agentic Commerce Protocol 定义的是商务边界；Agent Client Protocol 连接的是编码 Agent 与编辑器。更早的 Agent Communication Protocol 则是另一个独立项目。本指南使用完整名称和确切版本，以避免将它们混为一谈。

配套材料包含一个 Python/SQLite 契约实验环境，内含 56 个测试、一个回环 HTTP 服务器、一个丢失响应演示、回调与流式练习，以及 8 份工作表。其核心需求仅为 Python 3.10 或更高版本，无需任何软件包、云凭据或模型密钥。另有独立的 Python 3.12 路线，使用固定版本的 SDK 搭建真实的本地 MCP 服务器/客户端，并使用经哈希校验的 MCP 与商务 ACP 官方模式，外加 A2A protobuf 检查。

购买服务提供方与身份均为本地合成测试数据。可选的 MCP 服务器执行的是公开的合成读取。不存在真实的购买、钱包或生产环境 OAuth 流程。部署章节说明了构建客户系统所需的额外身份、基础设施、凭据、支付与运维工作。

2026 年 10 月版使用 86 个主要参考文献和明确的版本边界，包括 7 月的 MCP 和 A2A wire 1.0。精确提取的配套材料通过了 56 项测试，并检测出 8 个故意损坏的控件。可选路径通过了五项本地 MCP 检查和 30 项 schema/选定不变量检查。这些检查仅确立其所述范围，并非在所有对等方或支付提供商之间的完整合规性。
