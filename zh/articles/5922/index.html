摘要

FDEInterviews 整理了 Hippocratic AI 前沿部署工程师岗位的面试准备资料。该公司面向医疗领域构建安全优先的语言模型平台，FDE 需驻场医院系统，负责检索架构、工具调用与 MCP 集成及生产环境可靠性。文中给出岗位要求、薪资参考区间与高频面试题方向，但强调流程细节未经官方确认。

要点

  • Hippocratic AI 的 FDE 需驻场医疗系统，端到端负责对话 Agent 部署。
  • 岗位要求 3-5 年 Python 经验，熟悉 RAG、工具调用、LLM-as-judge 等模式。
  • 患者安全与 HIPAA 合规是面试重点考察方向。
  • 该公司未公布可验证薪资区间，印度远程合约参考 55-90 LPA（中级）。
  • 面试流程无公开细节，需以招聘方信息为准。

Hippocratic AI 构建一个仅面向医疗、以安全为核心的大语言模型平台，并将面向患者的 Agent 授权给医疗系统使用。前沿部署工程师端到端地负责这些部署的技术侧工作：设计检索架构、设计工具调用与 MCP 集成模式，并确保对话式 Agent 在多个医院系统的生产环境中保持可靠。在这个领域，安全导向绝非点缀，它既塑造了产品，也决定了面试可能考察的内容。

检索与 Agent

基础登录检索增强生成（RAG）RAG 通过在查询时检索相关段落并将其放入提示词中，使语言模型基于你自己的数据作答，从而让模型依据真实来源而非记忆回答。它几乎是所有企业级 FDE 部署的默认模式，因此几乎每个循环都会考察它。

基础登录向量数据库向量数据库将嵌入向量与元数据一同存储，并使用近似索引快速回答最近邻查询。真正的面试问题不是它们如何工作，而是你何时真正需要一个向量数据库，而不是一个库或使用 pgvector 的普通 Postgres。

AI 安全、隐私与治理

LLM 与生成式 AI 的基础

基础分词与 Token语言模型不读取字符或单词。它读取的是 token：由分词器产生的子词片段，每个片段被映射为一个模型嵌入的整数。Token 是上下文窗口和计费的单位，文本被切分成 token 的方式解释了大量模型怪癖，这就是为什么几乎每个学习循环都从这里开始。

基础上下文窗口上下文窗口是语言模型一次能够关注的固定 token 数量，输入和输出共享同一预算。理解它是区分以下两类工程师的关键：一类能够合理规划提示词大小、控制成本和延迟，并决定何时使用 RAG；另一类只是把所有内容粘贴进去然后祈祷。

基础嵌入与向量表示嵌入将一段文本转换为一组数字，其位置使得含义相近的文本在空间中彼此靠近，这让你可以按含义而非关键词进行搜索。嵌入是 RAG、语义搜索、聚类和去重背后的引擎，因此 FDE 学习循环期望你能解释余弦相似度，以及那些悄悄破坏向量索引的陷阱。

面向客户的技艺

基础需求发现需求发现是找出隐藏在客户明确诉求背后的真实问题的工作。客户交给你的请求（“给我们做一个聊天机器人”）几乎从来不是真正的需求；能够挖掘出谁在使用它、成功是什么样子、实际存在哪些数据、以及为什么截止日期是截止日期的 FDE，才能交付出人们真正使用的东西。

基础界定模糊问题界定一个开放式命题（“某城市希望缩短 911 响应时间”）是一种结构化操作，而非灵光一现：澄清输入与约束，大声说出你的假设，切分出最小可用的 MVP，明确你在准确性/成本/延迟之间所做的取舍，并规划失败时该怎么办。直接跳进模型或架构设计，是候选人在模拟面试轮中被淘汰的最常见原因。

基础向非工程师解释取舍高管并不关心你选择了 RAG 还是微调；他们关心的是成本多少、何时上线、以及可能出什么错。翻译技术取舍意味着把准确性、成本和延迟转化为业务真正在做的决策，用他们的语言把每个选项框定为带有后果的选择，并回答他们最终都会问的问题：为什么 AI 每次给出的答案都不一样，以及为什么这不是 bug。
