Warp CEO Zach Lloyd 谈为何软件工厂是编程的下一个阶段

原标题：Warp CEO Zach Lloyd on why software factories are the next phase of coding

Latent Space · 2026-07-01 · 约 8 分钟读完

摘要

Latent Space 采访 Warp CEO Zach Lloyd，谈其从终端产品转向软件工厂平台 Oz 的战略：自动化软件开发的完整循环，包括分诊、实现、评审、验证与监控。

要点

  • Warp 从 Rust 终端演进为集成 AI Agent 的软件工厂平台，并已开源核心 CLI。
  • 新平台 Oz 旨在自动化分诊、实现、评审、验证、发布和监控的完整开发循环。
  • Lloyd 认为未来重点是元工程：构建能构建产品的系统，而非手写代码。
  • 前沿部署工程师在软件工厂落地中承担改造企业工作流的转型项目。
  • 他预测一年内每个重要软件项目都会有类似工厂的自动化引擎持续驱动。

Warp 创始人 Zach Lloyd 在 AI Engineer World's Fair 展厅。

我报道 Warp 已经有几年了，看着它从一个命令行界面工具快速演变为软件工厂平台，一直很着迷。这家公司成立于 ChatGPT 出现之前的 2021 年年中，最初是一个基于 Rust 的终端。后来 AI 浪潮来临，它转型为集成了编码 Agent 的终端。

但近年来 CLI 工具之间的竞争急剧加剧，包括来自 Claude Code、Codex CLI 和 Gemini CLI——这三款产品背后都有大型科技公司支持。这很可能促使 Warp 决定在今年 4 月将其核心 CLI 工具开源。

我自己就是 Warp 的用户，发现它比我 Mac 原生的 CLI 复杂精细得多。但我也很欣赏这家公司顺应时代的能力——几年前我第一次采访 CEO Zach Lloyd 时就注意到了这一特质。所以我很想在本周的 AI Engineer World's Fair 上与他聊聊，他在那里发表了一场关于软件工厂的主题演讲，这个新词指的是编排一个团队（咳咳，一个工厂）的 Agent。

Warp 推出了一个名为 Oz 的新 Agent 编排平台。这是该公司对 Lloyd 所认为的行业转型的回应：从工程师与 Agent 交互式协作，转向持续进行分诊、实现、审查、验证和监控软件变更的自动化系统。Oz 旨在跨本地环境和隔离的云沙箱连接多个模型和编码工具链，同时融入开发者已经在使用的工具中。

我在 Lloyd 舞台演讲结束后不久与他交谈，演讲可以在 YouTube 上观看——它是了解软件工厂的一个很好的入门材料。在我们的一对一讨论中，我们谈到了 Warp 转向软件工厂的原因、Lloyd 是如何想出这个术语的（似乎与类似公司——如 Factory——是独立想出的），以及为什么他预计大多数重要的软件项目将在未来一年内以某种形式的自动化工厂运作。

从单个 Agent 到自动化开发循环

Latent Space: 你第一次接触到“软件工厂”这个术语是什么时候？这个概念有什么吸引你的地方？

Zach Lloyd: 我不记得具体是什么时候开始用这个概念来思考的，但应该是在过去六个月内，当时软件开发自动化的能力变得更加完善。

我们从更多一次性的自动化开始：在云端运行一个 Agent。很多平台都是从这个阶段起步的。然后演变为：在云端定时运行一个 Agent。

下一个问题是，最有价值的自动化循环是什么？答案基本上就是软件工程的主循环：分诊、规格说明、实现、审查、验证、发布和监控。

我们大约在一年前开始朝着这个云自动化愿景迈进，那时我们还没有开始构建 Oz。在过去几个月里，行业也开始围绕“工厂”这个术语凝聚共识。本次大会就有一个完整的软件工厂专题。

这正是我们产品所围绕的方向。在 Oz 的下一个版本中，你将可以搭建你的工厂、查看它的样子并管理工厂车间。

但我并不太在意这个术语能否流行。本质的转变是从交互式开发转向自动化开发。“工厂”是一个有用的比喻。

围绕现有工作流构建工厂

Latent Space： 在你的演讲中，你展示了一个包含多款你们自家产品的软件工厂技术栈。Warp 的计划是提供构成这个技术栈的工具吗？

Lloyd： 是的。当你进入 Oz——我们的云端 Agent 平台时，会被引导完成工厂的搭建流程。

你可以选择你的代码仓库、想要自动化的软件生命周期环节，以及应该让人类介入的节点。不同的组织和代码库会有不同的偏好。你要完全自动化代码审查吗？还是让人类审查某些高风险的变更？

然后系统就会开始创建这个闭环。它可以从 Jira 或 Linear 拉取工单，让人们通过 Slack 或 Teams 提交工单，并允许开发者在 GitHub 上重新指派一个 Agent。

从产品角度来看，有趣的是工厂的大部分并不一定是一个全新的界面，而是对人们现有工作流的集成。至少我们是这么构思的。

Warp 为何要超越终端

Latent Space： 当我第一次写关于 Warp 的文章时，它还在打造一款现代终端。现在代码依然重要，但越来越多地由 Agent 来产出。看起来 Warp 已经相应地拓宽了它的产品愿景……

Lloyd： 完全正确。可以这样理解：自公司创立以来，我们的使命一直没有变，始终是帮助开发者和公司更快地交付更好的软件。

产品则发生了巨大的演变。它最初是现代版终端，那是在当前这波 AI 浪潮之前。下一阶段是内置 Agent 的终端，我们仍在持续投入，并且现在已经开源。

但世界在不断变化。底层 AI 进步得如此之快，以至于我对未来的看法就是我在演讲中所描述的：交互部分将变得不那么重要。

作为一家公司，你会希望有一个集中的地方来构建软件，并衡量这个过程的效率。我不怕改变产品的方向。随着底层技术越来越好，不适应的公司将会被甩在后面。

工厂工程作为一门新学科

Latent Space: “工厂”这个词可能会让一些开发者感到反感，因为它带有机械化和重复劳动的意味。关于这次转型，你从 AI 工程师那里收到了什么反馈？

Lloyd: 这个概念在经济买方——也就是管理工程团队的人——那里引起了强烈共鸣。

对于个人工程师来说，它可能听起来机械而缺乏创造性。他们可能会想：“我喜欢写代码，为什么我要在工厂里工作？”

我在演讲中试图传达的一点是，这将成为一门新的工程学科。我认为，如果你把这份工作视为元工程——构建那个构建产品的系统——它可能会非常有趣。

它运用了许多相同的解决问题的技能。你是在追问为什么一个 AI Agent 能把某个任务做好，却把另一个做砸。你应该怎样调整它的反馈？它需要什么上下文？工作流程应该如何改变？

但无论好坏，这些系统的强大能力以及它们加速软件开发的能力是如此之大，以至于再靠手工编写所有代码，很快就会变得不合时宜。

前沿部署工程师的用武之地

Latent Space: 大会上的另一个趋势是前沿部署工程，它通常融合了产品管理、咨询和传统工程的元素。这如何融入软件工厂模式？

Lloyd: 搭建一个软件工厂可能涉及与大量现有系统的集成，具体取决于公司的情况。

当工厂能够从这些系统中获取上下文，并融入整个组织的工作流程时，它的运作效率最高。在这个领域，很多前沿部署工程工作实际上是一个转型项目。

它需要真正的工程能力，需要有人懂得如何配置和部署这类系统。我们做了一部分这样的工作，我们的一些竞争对手也在做。

我不知道最终会是什么样子。Warp 更多地把它当作一个平台业务，而不是服务业务。但如今，把聪明人派进公司、用这些产品改造其工作流程，确实是一门生意。

Warp 作为 Oz 的试验场

Latent Space: 我用 Warp 作为我的终端，包括完成一些编码任务。在软件工厂时代，原来的 Warp CLI 产品会怎样？

Lloyd: 当我们把 Warp 开源时，我们把代码库交由 Oz 控制。我们围绕这个开源项目，用我们自己的工厂平台搭建了一个软件工厂。

我们仍在尽力改进 Warp。我们与社区一起做，也大量借助 AI Agent 来做。从这个意义上说，Warp 是工厂概念的试验场。

但它也是一个被近百万开发者使用的产品，其中许多人把它当作主要的开发环境。我们自己也在频繁使用它，而且公司内部仍有工程师专门负责改进它。我们只是以工厂化的思维方式来开展这项工作。

渐进式自动化，而非一夜之间的取代

Latent Space: 在软件工厂的采用方面，你预计未来一年会是什么样子？

Lloyd: 这不会一蹴而就。工程师们不会某天早上醒来，发现软件工厂已经取代了他们的工作。

公司会从特定的用例入手，比如某些类型的问题或风险较低的代码仓库。在这些地方，他们可能可以接受不必由人工逐行审查代码。

他们会观察它的表现。接下来，工程上的挑战就变成：与其只自动合并 20% 的拉取请求，能否提升到 30%、40%、50% 甚至 60%？

仍会有一部分工作由人来完成，因为那些工作太难、太模糊，或者依赖于从零开始的创新思维。

但我认为这种转变会在未来一年内发生。我的预测是，每一个重要的软件项目都会拥有某种代码引擎——某种类似工厂的东西——持续推动它向前发展。

它会变得像 GitHub 或 CI/CD 一样：成为严肃软件项目运作方式的标准组成部分。如果这没有发生，我会感到意外。

从自动化那些烦人的部分开始

Latent Space: 这场大会有成千上万的 AI 工程师。他们应该做些什么来为这一转变做好准备？

Lloyd: 不要只直接构建产品，试着朝着工厂的方向构建一些自动化，看看感觉如何。

假设你想让一个 AI Agent 自动处理新进的用户问题。要实现这一点需要做些什么？是什么阻碍了你采用它？

也许代码审查是瓶颈。也许 AI Agent 在做修改，但你无法清楚地看到它做了什么。只有尝试构建这个闭环，你才会发现这些问题。

摆脱凡事都手工构建的思维模式。找出你工作中一个烦人的部分，尝试用工厂化的方法创建一个为你处理它的闭环。
