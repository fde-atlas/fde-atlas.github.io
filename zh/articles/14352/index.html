带回家作业演示视频：FDE 候选人脚本

原标题：Take-home walkthrough video: a script for FDE candidates

FDE Interview Prep · 2026-09-25 · 约 15 分钟读完

摘要

这篇文章为 FDE 候选人提供带回家作业演示视频的逐镜头脚本：视频应展示问题理解、端到端演示、一个关键决策、一个权衡、评测结果（含失败案例）和后续计划。作者对比了 Coframe、Palantir、Alchemyst 等公司的视频要求，给出决策与权衡的表述模板、配套 README 结构，并列出常见录制错误，如超时、泄露密钥、链接失效等。

要点

  • 视频核心是展示判断力，而非罗列功能或浏览文件。
  • 六段脚本：问题、演示、决策、权衡、评测、后续计划。
  • 评测镜头应展示至少一个失败案例及其原因。
  • README 中“有意省略”清单可把短板转化为主动决策。
  • 常见错误包括超时、泄露密钥和链接未登出验证。

你完成了构建，测试全部通过，任务说明的最后一行要求录制一段演示视频，于是你盯着屏幕录制软件，不知道该说什么。带回家的作业演示视频是一段简短的屏幕录制，展示问题、现场运行核心路径并解释背后的决策；时长要控制在任务说明规定的范围内，把时间花在展示判断力上，而不是带你浏览文件。也就是说：一个决策、一个权衡、你如何验证它有效、以及你接下来会做什么。本文是 FDE 面试指南的一部分，为你提供逐镜头脚本、难点部分的准确措辞、README 模板，以及会掩盖优秀成果的录制错误。

视频必须证明什么

仓库展示了你构建了什么。而视频则是评审者以你自己选择的方式、用你自己的声音听到你的推理过程。请把它做成让一个从未读过你一行代码的人也能看懂。

Sierra 公布了它在现场面试中如何评审构建成果：构建完成后，候选人演示作品，然后面试官讨论产品流程和各项选择，并审查代码以了解其技术判断力。来源 12The AI-native interview发布者Sierra来源类型公司博客 Sierra 的同一篇文章还提到，评审也涵盖通往生产的路径以及候选人在过程中如何使用 AI。来源 12The AI-native interview发布者Sierra来源类型公司博客 一位候选人在 2026 年 8 月报告了一份 Tavily FDE 任务说明，其中直白地表达了同样的观点：“我们宁愿看到一件小事做得好，也不愿看到一件大事做得潦草。”来源 13Tavily - FDE - Take Home Assignment发布者azamkhan99 (GitHub)来源类型候选人的 take-home 仓库

所以你的视频有四项任务：

  • 你理解了问题。 用客户自己的语言阐述他们的问题，而不是照着任务说明的第一行念出来。
  • 它能端到端运行。 输入一个真实的输入，实时输出用户会看到的结果。
  • 你的决策是有意为之。 讲一个选择、你否决的替代方案，以及原因。
  • 你知道它在哪里会出问题。 你如何测试它、什么失败了，以及你接下来会怎么做。

一段在几分钟内把这四点讲清楚的视频，胜过对更大规模构建的更长漫游式讲解。

脚本，逐镜头分解

这是我们的脚本，不是任何公司都会发布的格式。它假设任务简报有一个

5:00

时长上限；请按你的实际情况调整时间。

镜头展示内容时长
问题谁受困扰，以及你构建了什么0:30
演示一个真实输入，端到端跑通1:30
一个决策其背后的代码或图表0:45
一个权衡你放弃了什么，以及何时重新审视0:45
评测测试输出，包括一个失败案例0:45
下一步上生产还需要什么，按顺序说明0:45

为了让它更具体，我们拿一个虚构的简报来举例：将诊所的预约电子表格与排班 API 同步，并标记重复预约。

问题。 从 README 的顶部开始，而不是你的编辑器。用两句话说明谁有这个问题、它带来什么代价，然后说明你构建了什么。“前台把预约记录在电子表格里，而预订系统在 API 里，两者会不同步，导致患者被重复预约。我构建了一个每隔几分钟运行一次的同步程序，在患者到场之前标记冲突。”要练习口头描述客户的问题，可以运行免费的 AI 练习案例。

演示。 这是最长的镜头，而且只展示核心路径。从工具已安装并运行的状态开始，然后在表格中编辑一行，运行同步，并展示冲突标记出现。这就是行走骨架课程所教授的精简端到端版本的实际运行展示。跳过登录界面、设置页面以及用户在第一天不会接触的所有功能。

一个决策。 挑选评审者最可能质疑的选择，并打开其背后的那一个文件或函数。不要滚动页面。高亮关键的代码行，并对着它们讲解。

一个权衡。 说出你为了在时间限制内完成而有意放弃的东西。下一节有具体的措辞。

评测。 展示你如何知道它有效：一次测试运行、一个带分数的小型标注数据集，或一张前后对比表。至少展示一个失败案例，并说明原因。“我在 40 行已知答案的数据上运行，得到了 37 个正确。三个失败案例都是合并单元格，解析器把它们读成了空值。”

下一步。 说明这个项目与生产环境之间还差什么，按你打算执行的顺序，并到此结束。“在真实诊所使用之前：第一，API 宕机时的重试和告警；第二，每个标记的审计日志；第三，用变更通知替代轮询。”

如果简报问到 AI 工具，在这里加一句话：用了哪些工具、用来做什么、你手工核查了什么。“我用一个编程工具搭建了 API 客户端和最初的测试。匹配逻辑是我自己写的，并且对照 40 行标注数据核查了每一个冲突标记。”

写好脚本，然后说出来，而不是念出来

把六个镜头作为要点列表放在录制窗口旁边。照着完整的句子念听起来很生硬；根据要点来讲则像一位工程师在解释自己的工作。

决策与权衡的确切措辞

判断力体现在这两个镜头中。为每个镜头使用固定的结构。

决策。 说出两个选项，给出与该客户相关联的理由，并说明另一个选项在什么情况下会胜出。

“把预约记录匹配到就诊时间，我有两种方法：按患者姓名和时间匹配，或者按前台已经录入到 C 列的预约 ID 匹配。我用了预约 ID，因为姓名容易拼错、时间会被修改，用它们匹配会产生虚假冲突。如果诊所不再录入 ID，我会退回到姓名加时间的方式并附上置信度评分，把低置信度的匹配转给人工处理。”

权衡。 说明你放弃了什么、代价是什么、为什么目前可以接受，以及什么信号意味着该修复了。

“为了在时间限制内完成，同步功能采用轮询表格的方式，而不是监听变更。这意味着一个冲突可能在整个轮询间隔内都未被标记。对于提前一天预约的诊所来说，这是可以接受的。如果他们开始支持当天预约，我会切换到变更通知，这也是我下一步计划清单上的第一项。”

三个应该删掉的短语，以及应该说什么：

不要说应该说
“这是最佳实践”它适合这个客户的原因
“我没时间了”“我选择不做，因为……”
“这是最优方案”“在……之前这是最优的”

如果评审人把你列入候选名单，要预期这两个同样的时刻会以提问的形式再次出现。先用带回家作业中你会改进什么这道免费问题练习，再练习像面对客户的架构师那样为一个设计选择辩护。

随附的 README

视频和 README 应该讲述同一个故事。README 要简短，并把决策放在靠前的位置，也就是评审人最先看的地方。

# Appointment sync

## The problem
Two sentences, in the customer's words

## Watch first
Video: <link> (test it signed out)

## Run it
Two or three commands; sample data

## Built, and left out
- Built: the core path.
- Left out: auth, retries. Why.

## Decisions
- Booking ID, not name: reason.

## How I checked it
Test command, score, known misses

## Next steps
In the order I would do them.

## AI use
Tools, what for, what I checked

“有意省略”清单的作用最大。它把评审人可能记在你头上的一个缺口，变成你主动做出的一个决策。面向客户写作那一课讲了执行摘要中同样的习惯：先给出读者做决策所需的信息，再给细节。

关于 AI 部分：各家的要求不同，所以要仔细读你的题目要求。Coframe 的题目要求你列出你使用的每一个 AI 工具以及它如何影响了结果。Source 1Coframe Forward Deploy — Take-HomePublisherCoframe (GitHub)Source typecompany website ELITH 要求提交一份单独的《AI 使用备忘录》。Source 6ELITH LOCK: FDE Challenge 2026PublisherELITH (elith-co-jp on GitHub)Source typecompany website 一位候选人在 2026 年 8 月提到，Tavily 的 FDE 题目要求提供工作过程的记录，例如编码 Agent 的聊天记录或会话日志。Source 13Tavily - FDE - Take Home AssignmentPublisherazamkhan99 (GitHub)Source typecandidate’s take-home repository 当题目没有说明时，带回家作业能否使用 AI这篇文章讲了如何判断以及如何披露。

十分钟内完成录制环境搭建

你不需要专门的软件。除非任务说明中指定了某个平台或工具，否则使用你电脑上已有的即可。

  • 在 Mac 上， 按 Shift-Command-5 打开屏幕录制控制，如 Apple 的 Mac 屏幕录制指南 所述。选择录制选定区域，以便只捕获你的窗口。
  • 在 Windows 11 上， 截图工具可以录制视频：按 Windows 徽标键 + Shift + R，参见 Microsoft 的截图工具指南。
  • 分辨率。 以你正常的屏幕分辨率录制，只共享一个窗口，把文字调大而不是调大录制画面。
  • 测试片段。 录制约 20 秒你讲解第一个镜头的视频，然后在手机上回放。如果听不清自己的声音或看不清终端，先解决这个问题再正式录制。
  • 上传。 使用任务说明中指定的托管平台，然后测试链接，如下文最后一个错误所述。

录制错误及其解决方法

没有留出录制时间。 视频只能用剩下的几分钟来完成，效果一目了然。即使是三小时的任务也可以为此预留时间。GitHub 账号 brianbrainforge-wq 发布的一个任务（其与 Brainforge 的关联由账号名推断）为演示准备预留了 15 分钟，为局限性预留了 10 分钟。来源 14AI FDE Challenge发布者brianbrainforge-wq (GitHub 账号)来源类型公司网站来源 15Shared challenge brief发布者brianbrainforge-wq (GitHub 账号)来源类型公司网站 解决方法：从一开始就把演示准备和录制纳入你的计划，而不是在完成最后一个功能之后。

以环境搭建开场。 安装依赖和讲解环境变量会占用评审者注意力最集中的那几分钟。解决方法：从工具已经运行的状态开始，把环境搭建放在 README 中。

浏览文件。 滚动每个文件夹展示不了仓库之外的任何东西。解决方法：只打开一个文件，用于决策镜头。

只演示正常路径。 只展示正常路径的演示会让评审者猜测它在哪里会出错，而他们一定会去找。解决方法：在评测镜头中展示一个会失败的输入，并说明原因。

屏幕不可读。 小字体和宽屏显示器在浏览器标签页里会变成一片模糊。解决方法：录制一个窗口，把编辑器和终端放大到远超你平时的大小，并隐藏侧边栏。

泄露机密。 一个打开的

.env

文件、终端历史中的 API 密钥或带有同事消息的通知，都会出现在发送后无法再编辑的视频里。解决方法：开启勿扰模式，关闭其他所有内容，并在发送前完整观看一遍录制。如果屏幕上出现了密钥，轮换它并重新录制；模糊一帧是不够的。

超时。 超出时长限制就违反了任务说明中唯一一条明确的规则，而超出的部分可能永远不会被观看。解决方法：为试录计时，先删减演示内容，而不是删减决策或评测部分。

拍二十遍。 追求完美的一条录像会吃掉你本该用来检查构建成果的时间。解决方法：分段录制，剪掉片段之间的空白时间，接受小失误。不要把失败的部分从演示中剪掉。

打不开的链接。 Palantir 的部署策略师 Build to Apply 招聘要求以未公开的 YouTube 链接提交视频。来源 3部署策略师，Build to Apply - 美国政府发布方Palantir Technologies (Lever)来源类型公司招聘信息 解决方法：无论简报指定哪个托管平台，提交前先在隐私窗口中、以未登录状态打开你的链接。

发送视频之前

  • 时长在简报规定的范围内
  • 第一个镜头点明客户的问题
  • 演示从一个已运行的工具开始，并展示核心路径
  • 一个决策和一个权衡，各自附上备选方案
  • 至少展示并解释一处失误
  • 按顺序说明后续步骤，若简报有要求则说明 AI 的使用
  • 屏幕上没有机密信息、通知或个人标签页
  • 未登录状态下链接可以打开

当提交之后进入现场演示环节

对某些简报来说，视频并不是终点。一位候选人在 2026 年 9 月创建的仓库中报告，某份简报要求在约 3 分钟的视频之后，在面试中展示解决方案并回答技术问题。来源 9FDE 家庭作业（PDF）发布方peerfichman (GitHub)来源类型候选人的家庭作业仓库 其他流程则跳过视频，直接进入现场评审：一个名为 AzurePartners 的 GitHub 账号发布了一份 FDE 家庭作业，入围候选人将获得 45 分钟的时间来讲解他们构建的内容并进行现场扩展 来源 16家庭作业：规划 Agent发布方AzurePartners (GitHub 账号)来源类型公司网站，而 Sierra 的现场面试则要求候选人演示构建成果，然后就产品选择进行辩论并评审代码。来源 12AI 原生面试发布方Sierra来源类型公司博客

把视频，或者你的前五分钟，当作这场对话的开场陈述：

  • 保留脚本。 你的现场讲解可以沿用同样的六个镜头，在决策和权衡之后留出更多提问空间。
  • 了解你交付的每一行代码。 如果某个 AI 工具写了一个函数，反复阅读直到你能解释它并当场修改它。现场扩展往往会落在你最不熟悉的那部分代码上。
  • 准备好扩展点。 选出两个可以接入新需求的位置，并明确每个位置你会先打开哪个文件。
  • 边改代码边讲解。 在动手输入之前，先说出你打算尝试什么以及为什么。讲解、白板与计时课程会在计时条件下反复训练这一点。

常见问题

带回家作业的讲解视频应该多长？

请遵循任务说明，因为各家的要求不同。Palantir 的 Deployment Strategist Build to Apply 职位要求提供 5 分钟以内的演示视频，其他说明则设定了更短或更长的时限。如果说明中没有给出时长，就保持简短，涵盖问题、演示、一个决策以及你接下来会做什么。来源 2Deployment Strategist, Build to Apply - US Government (Washington, D.C.) - Palantir on Lever发布方Palantir Technologies (Lever)来源类型公司招聘信息来源 3Deployment Strategist, Build to Apply - US Government发布方Palantir Technologies (Lever)来源类型公司招聘信息

候选人反馈的 FDE 带回家作业视频时长是多少？

一位候选人于 2026 年 4 月反馈，其 FDE 带回家作业要求提供 5 到 8 分钟的讲解。另一位候选人于 2026 年 9 月反馈，其任务说明要求提供约 3 分钟的视频，随后在面试中进行演示。以你自己的说明为准。来源 8Forward Deployed Engineer — Take-Home Assignment (PDF)发布方JoshOlam (GitHub)来源类型候选人的带回家作业仓库来源 9FDE Home Assignment (PDF)发布方peerfichman (GitHub)来源类型候选人的带回家作业仓库

我应该在讲解视频中说明自己使用了哪些 AI 工具吗？

如果任务说明有要求，就应该说明。Coframe 的公开 FDE 带回家作业要求候选人列出他们使用的每一个 AI 工具，以及它如何影响了结果。如果说明中没有提及，先查看公司公布的 AI 使用规则，然后简要说明你使用了什么，以及哪些是你自己核实的。来源 1Coframe Forward Deploy — Take-Home发布方Coframe (GitHub)来源类型公司网站

我应该在带回家作业视频中展示代码吗？

简短即可。展示你主要决策背后的那一段代码，而不是把每个文件都滚动一遍。评审者可以阅读代码仓库；视频是为了展示他们从仓库中看不到的思考过程。

需要露脸吗？

只有要求中明确要求时才需要。如果要加，请保持小尺寸并放在角落里，确保不会遮挡终端、输出或你正在讲解的代码。你的声音和清晰可读的屏幕更重要。

可以剪辑视频吗，还是必须一镜到底？

除非要求中另有说明，剪掉无效时间（如安装、长时间等待和失败的开头）是可以的。不要为了美化构建效果而把演示中的失败剪掉；要展示它，并说明原因。
