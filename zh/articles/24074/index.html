TypeScript是Microsoft开发的JavaScript超集语言。它在JavaScript的基础上增加了静态类型和基于类的面向对象特性，旨在让大规模应用开发更加安全、高效。

单靠TypeScript本身，并不具备文件依赖管理、UI组件复用、HTTP请求抽象等实际应用开发所需的众多功能。于是框架应运而生。框架可以定义为“将应用的骨架结构、规则以及便利的功能集合打包在一起的东西”。

大多数支持TypeScript的框架都属于以下分类之一。

分类主要作用代表示例
前端框架浏览器UI、状态管理、路由React、Angular、Vue.js
后端框架服务端API、数据库对接、认证NestJS、Express、Hono
全栈框架整合前端＋后端＋SSR/SSGNext.js、Nuxt.js、SvelteKit

将TypeScript与框架结合使用，可以实现从前端到后端一致的类型安全开发。过去用JavaScript编写时频繁出现的“运行时才发现的Bug”，如今大部分都能在编译阶段被检测出来。

相关文章：想详细了解TypeScript的基本概念及引入优势的读者，也请一并阅读【面向初学者】什么是TypeScript？详解其特点与引入优势。

① 通过类型安全实现Bug的早期检测

TypeScript最大的优势在于基于类型的静态分析。例如，在React中预先定义传递给组件的props类型后，一旦传入错误类型的值，IDE就会显示错误。Angular默认采用TypeScript，服务的DI以及模板绑定也会进行类型检查。

// React的props类型定义示例

type UserCardProps = {

  name: string;

  age: number;

  isAdmin?: boolean;

};

const UserCard = ({ name, age, isAdmin = false }: UserCardProps) => {

  return <div>{name} ({age}){isAdmin && " [管理者]"}</div>;

};

有了这样明确的类型定义，团队中任何人阅读代码时，都能一眼看出“该向这个组件传递什么”。

② 与IDE、编辑器的强大联动

VS Code与TypeScript的兼容性极高，补全、跳转、重构都能基于类型信息高精度运行。由于框架侧也提供类型定义文件（.d.ts），包括框架特有的API在内，都能享受代码补全的便利。

③ 适合大规模团队开发和长期维护

由于存在基于类型的接口契约，多人并行开发时不容易出现API规格的偏差。此外，即使数年后重新阅读代码，类型信息也能充当“文档”，大幅降低维护成本。

在选择框架之前，首先需要明确“要做什么”。

前端框架（客户端） 用于构建在浏览器上运行的UI的框架。负责状态管理、组件设计、路由等。代表示例为React、Angular、Vue.js。

后端框架（服务端） 用于在Node.js上构建HTTP服务器、REST API、GraphQL API的框架。负责数据库连接、认证、校验等。代表示例为NestJS、Express、Hono。

全栈框架 同时涵盖前端和后端的框架。还集成了SSR（服务端渲染）和SSG（静态站点生成）等功能。代表示例为Next.js、Nuxt.js、SvelteKit。

为了避免框架选型失败，建议从以下5个维度进行评估。

  • 与TypeScript的兼容性：是一等公民支持TypeScript，还是事后追加支持，开发体验会有很大差异
  • 学习成本：需要考虑团队的技能水平和上手所需的时间
  • 生态系统的完善程度：库、插件和社区的规模直接决定解决问题的速度
  • 性能：渲染方式（CSR/SSR/SSG）和虚拟 DOM 的实现会影响用户体验
  • 适合的项目规模：是从小规模起步，还是大型企业级项目，最优解会有所不同

从这张表中可以读出的一个重要要点是，Angular 和 NestJS 是 TypeScript 原生的。这些框架在设计时就以 TypeScript 为前提，因此可以最大限度地享受类型带来的好处。另一方面，React 和 Vue.js 虽然基于 JavaScript，但类型定义文件已经相当完善，在实际使用中几乎没有不便之处。

概述与特点

React 是 Meta（原 Facebook）开发的 UI 库。严格来说，它被归类为“库”而非“框架”，但通过与周边库（React Router、Zustand、React Query 等）组合使用，可以获得与框架相当的开发体验。

React 最大的特点是基于组件的 UI 构建。将 UI 定义为可复用的部件（组件），再通过组合这些组件来构成整个应用。

与 TypeScript 的结合方式

React 通过 @types/react 包提供类型定义。组件的类型定义主要使用以下几种模式。

// 使用 FC（Function Component）类型的方法

import React, { FC, useState } from 'react';

type CounterProps = {

  initialCount: number;

  label: string;

};

const Counter: FC<CounterProps> = ({ initialCount, label }) => {

  const [count, setCount] = useState<number>(initialCount);

  return (

    <div>

      <p>{label}: {count}</p>

      <button onClick={() => setCount(c => c + 1)}>増加</button>

    </div>

  );

};

useStateのジェネリクス<number>により、countの型がnumberに固定されます。誤ってstring型の値をセットしようとするとコンパイルエラーになります。

自定义 Hook + TypeScript

React 的优势之一是自定义 Hook。与 TypeScript 结合使用时，可以为可复用的逻辑加上类型保证。

// 用于数据获取的自定义 Hook

type FetchState<T> = {

  data: T | null;

  loading: boolean;

  error: string | null;

};

function useFetch<T>(url: string): FetchState<T> {

  const [state, setState] = useState<FetchState<T>>({

    data: null,

    loading: true,

    error: null,

  });

  useEffect(() => {

    fetch(url)

      .then(res => res.json())

      .then((data: T) => setState({ data, loading: false, error: null }))

      .catch(err => setState({ data: null, loading: false, error: err.message }));

  }, [url]);

  return state;

}

  • 中～大规模的 SPA（单页应用）
  • 团队成员技能水平参差不齐的情况
  • 希望充分利用丰富的 OSS 库的情况
  • 考虑向移动应用（React Native）横向扩展的情况

注意事项

状态管理、路由、表单校验等都需要自己选择和集成。“自由度高”反过来说就是“设计的责任在开发者身上”。如果团队没有事先确定统一的设计方针，代码库就容易变得杂乱。

Angular 是由 Google 开发和维护的前端框架。它原生采用 TypeScript，DI（依赖注入）、路由、表单校验、HTTP 客户端全部包含在框架本体中。

Angular 有一套被称为“Angular Way”的独特设计理念，组件、服务、模块、指令、管道等各角色的划分被明确定义。因此，即使在人数较多的团队中，也容易保持代码库的一致性。

Angular 的特点是大量使用装饰器的设计。

// 服务的示例

import { Injectable } from '@angular/core';

import { HttpClient } from '@angular/common/http';

import { Observable } from 'rxjs';

type User = {

  id: number;

  name: string;

  email: string;

};

@Injectable({

  providedIn: 'root'

})

export class UserService {

  private apiUrl = 'https://api.example.com/users';

  constructor(private http: HttpClient) {}

  getUsers(): Observable<User[]> {

    return this.http.get<User[]>(this.apiUrl);

  }

  getUserById(id: number): Observable<User> {

    return this.http.get<User>(`${this.apiUrl}/${id}`);

  }

}

通过 @Injectable 装饰器，该服务会被注册到 Angular 的 DI 容器中。通过在 HttpClient 的 get 方法上用泛型指定类型，可以保证响应的类型。

校验逻辑集中在组件类中，与模板的协作也可以做到类型安全。

  • 金融、医疗、行政等需要严格设计规范的企业级系统
  • 10 人以上大规模团队的开发
  • 以长期维护为前提的系统（5 年以上的运营）
  • 熟悉 Java、C# 等静态类型语言的开发者较多的团队

Angular 特有的概念（模块、装饰器、基于 RxJS 的响应式编程）学习成本较高，对于小规模项目来说可能过于笨重。尤其是 RxJS 的 Observable 模式对 JavaScript/TypeScript 初学者来说难度较高，因此需要谨慎评估团队的技能水平。

Vue.js 是 Evan You 作为个人项目启动、目前由社区主导开发的前端框架。它以“渐进式框架”为理念，既可以只用一行 script 标签嵌入现有的 HTML 页面，也可以用于构建完整的 SPA，支持渐进式引入。

从 Vue 3（2020 年发布）开始，TypeScript 支持大幅增强，与 Composition API 结合后可以获得接近 React 的类型安全开发体验。

TypeScriptとの組み合わせ方（Composition API + <script setup>）

<script setup lang="ts">

import { ref, computed, onMounted } from 'vue';

type Product = {

  id: number;

  name: string;

  price: number;

  stock: number;

};

const products = ref<Product[]>([]);

const searchQuery = ref<string>('');

const filteredProducts = computed(() =>

  products.value.filter(p =>

    p.name.toLowerCase().includes(searchQuery.value.toLowerCase())

  )

);

const totalValue = computed(() =>

  products.value.reduce((sum, p) => sum + p.price * p.stock, 0)

);

onMounted(async () => {

  const res = await fetch('/api/products');

  products.value = await res.json() as Product[];

});

</script>

<template>

  <input v-model="searchQuery" placeholder="商品を検索..." />

  <p>在庫総額: ¥{{ totalValue.toLocaleString() }}</p>

  <ul>

    <li v-for="product in filteredProducts" :key="product.id">

      {{ product.name }} - ¥{{ product.price }}

    </li>

  </ul>

</template>

<script setup lang=”ts”>を使うことで、TypeScriptとComposition APIが自然に統合されます。ref<Product[]>([])のようにジェネリクスで型を指定でき、テンプレート内の変数にも型チェックが効きます。

Pinia（Vue 3 推荐的状态管理库）与 TypeScript

import { defineStore } from 'pinia';

type CartItem = {

  productId: number;

  quantity: number;

  price: number;

};

export const useCartStore = defineStore('cart', {

  state: (): { items: CartItem[] } => ({

    items: []

  }),

  getters: {

    totalPrice: (state): number =>

      state.items.reduce((sum, item) => sum + item.price * item.quantity, 0),

    itemCount: (state): number =>

      state.items.reduce((sum, item) => sum + item.quantity, 0)

  },

  actions: {

    addItem(item: CartItem): void {

      const existing = this.items.find(i => i.productId === item.productId);

      if (existing) {

        existing.quantity += item.quantity;

      } else {

        this.items.push(item);

      }

    },

    removeItem(productId: number): void {

      this.items = this.items.filter(i => i.productId !== productId);

    }

  }

});

Pinia 作为 Vuex 的后继者被官方推荐，与 TypeScript 的兼容性非常高，可以实现具备类型推断的状态管理。

  • 有 JavaScript 经验但首次接触 TypeScript 的团队
  • 从现有 jQuery 或 Vanilla JS 的重构迁移
  • 以内容为主的网站・中等规模 SPA
  • 设计师或后端工程师兼任部分前端工作的团队

Vue 3 相比 Vue 2 有大幅变更，Composition API 与 Options API 两种风格并存，因此需要注意代码库的统一。此外，虽然日语社区资源丰富，但在英语圈中其采用案例不如 React、Angular 多，因此在海外项目中往往不太容易被列为候选。

Next.js 是 Vercel 开发的基于 React 的全栈框架。它突破了 React“仅客户端渲染（CSR）”的限制，可以通过统一的 API 使用 SSR（服务器端渲染）、SSG（静态站点生成）、ISR（增量静态再生成）。

从 2023 年发布的 App Router（Next.js 13 及以后）开始，利用 React Server Components 的新设计模式已成为主流。

渲染方式的选择（TypeScript）

// app/products/page.tsx（Server Component：SSG）

type Product = {

  id: number;

  name: string;

  price: number;

};

// デフォルトでServer Component（サーバーで実行される）

export default async function ProductsPage() {

  // このfetchはビルド時に実行（SSG）

  const products: Product[] = await fetch('https://api.example.com/products', {

    cache: 'force-cache' // SSG

    // cache: 'no-store'   // SSR（毎回取得）

    // next: { revalidate: 60 } // ISR（60秒ごとに再生成）

  }).then(res => res.json());

  return (

    <ul>

      {products.map(product => (

        <li key={product.id}>{product.name} - ¥{product.price}</li>

      ))}

    </ul>

  );

}

Server ActionsによるフルスタックAPI（Next.js 14以降）

// app/actions/createOrder.ts

'use server';

import { z } from 'zod';

const OrderSchema = z.object({

  productId: z.number(),

  quantity: z.number().min(1),

  address: z.string().min(1),

});

type OrderInput = z.infer<typeof OrderSchema>;

export async function createOrder(input: OrderInput) {

  const validated = OrderSchema.safeParse(input);

  if (!validated.success) {

    return { success: false, error: validated.error.flatten() };

  }

  // DBへの保存処理...

  return { success: true };

}

使用 Server Actions，无需将 API 路由写在单独的文件中，即可从组件直接调用服务器端处理。结合 zod 进行验证，可以实现类型安全的全栈开发。

  • 重视 SEO 的电商网站・媒体网站・企业官网
  • 重视性能（LCP、TTFB 等 Core Web Vitals）的服务
  • 希望将 React 技能直接延伸到全栈 API 的团队
  • 创业公司的 MVP 开发（前端与 API 在同一个仓库中管理）

App Router 相比 Pages Router 变化很大，从现有 Pages Router 项目迁移需要成本。此外，如果 Server Components 的渲染边界（’use client’ 的位置）设计不当，可能会出现性能问题，因此理解其架构至关重要。

NestJS 是 TypeScript 原生的 Node.js 后端框架。它将 Angular 的设计思想（装饰器、DI、模块）移植到了服务器端，Angular 经验者可以平滑迁移。内部使用 Express 或 Fastify，可根据需要进行切换。

其特点是单体且可扩展的设计，支持 REST API、GraphQL、WebSocket、微服务等多种通信方式。

}

// users.controller.ts

import { Controller, Get, Post, Body, Param, Delete, ParseIntPipe } from '@nestjs/common';

import { UsersService } from './users.service';

import { CreateUserDto } from './dto/create-user.dto';

@Controller('users')

export class UsersController {

  constructor(private readonly usersService: UsersService) {}

  @Get()

  findAll(): Promise<User[]> {

    return this.usersService.findAll();

  }

  @Get(':id')

  findOne(@Param('id', ParseIntPipe) id: number): Promise<User> {

    return this.usersService.findOne(id);

  }

  @Post()

  create(@Body() createUserDto: CreateUserDto): Promise<User> {

    return this.usersService.create(createUserDto);

  }

  @Delete(':id')

  remove(@Param('id', ParseIntPipe) id: number): Promise<void> {

    return this.usersService.remove(id);

  }

}

结合 class-validator，可以自动对请求体进行验证。ParseIntPipe 负责对 URL 参数进行类型转换和验证，因此当传入非法的 ID（如字符串）时会自动返回 400 错误。

使用 Guard 实现类型安全的认证与授权

// jwt-auth.guard.ts

import { Injectable, CanActivate, ExecutionContext } from '@nestjs/common';

import { JwtService } from '@nestjs/jwt';

import { Request } from 'express';

type JwtPayload = {

  sub: number;

  email: string;

  role: 'admin' | 'user';

};

@Injectable()

export class JwtAuthGuard implements CanActivate {

  constructor(private jwtService: JwtService) {}

  canActivate(context: ExecutionContext): boolean {

    const request = context.switchToHttp().getRequest<Request>();

    const token = this.extractTokenFromHeader(request);

    if (!token) return false;

    try {

      const payload = this.jwtService.verify<JwtPayload>(token);

      request['user'] = payload;

      return true;

    } catch {

      return false;

    }

  }

  private extractTokenFromHeader(request: Request): string | undefined {

    const [type, token] = request.headers.authorization?.split(' ') ?? [];

    return type === 'Bearer' ? token : undefined;

  }

}

通过实现 CanActivate 接口，可以保证实现符合 NestJS 守卫的类型约束。将 JWT 载荷也定义为 JwtPayload 类型，即可类型安全地引用 payload.sub 和 payload.role。

TypeScript 是与生成式 AI 工具（GitHub Copilot、Cursor、Claude）兼容性特别高的语言。原因在于“类型信息可以作为 AI 的上下文发挥作用”。

在 JavaScript 这样的动态类型语言中，AI 需要推测变量可能持有何种值。而在 TypeScript 中，类型定义、接口、泛型可以作为“代码的规格说明书”发挥作用，因此 AI 能够进行更准确的代码补全和重构建议。

类型定义提升 AI 补全精度的具体示例

// 没有类型定义的情况（AI 难以判断应该补全什么）

const processOrder = (order) => {

  // AIの補完：order.???（何のプロパティかわからない）

};

// 型定義がある場合（AIは正確な補完ができる）

type Order = {

  id: string;

  items: OrderItem[];

  totalAmount: number;

  status: 'pending' | 'processing' | 'shipped' | 'delivered';

  customer: Customer;

};

const processOrder = (order: Order) => {

  // AIの補完：order.status, order.items, order.customer など正確に補完される

};

通过认真定义类型，AI 工具的代码生成质量会显著提升。

React × Cursor：加速组件生成

Cursor 是能够将整个代码库作为上下文读取的 AI 编辑器。让它在参考现有组件类型定义的同时生成新组件，可以快速生成符合项目设计方针的代码。
