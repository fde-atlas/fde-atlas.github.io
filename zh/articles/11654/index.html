TextGrad (2024) 解读：面向 FDE

原标题：TextGrad (2024) Explained for FDEs

FDE Interviews · 2026-10-17 · 约 4 分钟读完

摘要

本文解读斯坦福团队的 TextGrad 论文：用 LLM 生成的文字批评充当不可微系统的“梯度”，通过反向传播式的反馈链优化提示词、代码、分子等对象。框架模仿 PyTorch API，在 LeetCode Hard、GPQA、GSM8K 等基准上带来提升，并讨论了成本、公平基线与验证把关等部署要点。

要点

  • TextGrad 用 LLM 文字反馈模拟反向传播，优化不可微的复合 AI 系统。
  • API 复刻 PyTorch：Variable、backward、step，每条边每次迭代多一次 LLM 调用。
  • GPT-4o 的 LeetCode Hard 完成率从 26% 升至 36%，GPQA 从 51% 升至 55%。
  • FDE 关键启示是逐边归因：把一次失败输出转化为对具体环节的反馈。
  • 需注意成本倍增、计算量对齐基线缺失，以及用验证集把关每次更新。

一分钟读懂这篇论文

神经网络之所以变得容易训练，是因为自动微分让反向传播开箱即用：定义计算图，调用

backward()

，然后运行优化器。斯坦福大学的 Mert Yuksekgonul、James Zou 及其同事提出了一个问题：对于由 LLM 调用和工具构建、完全不可微的系统，与之对应的等价物是什么？他们的答案是 TextGrad，它使用由 LLM 撰写的“梯度”式批评意见。

以最简单的系统为例：一个提示词生成一个预测，再由一个评估 LLM 对该预测进行评判。在反向传播过程中，LLM 读取评估结果并为预测撰写反馈（“这里可以通过……来改进”）。然后，在给定提示词、预测和该反馈的情况下，它再为提示词撰写反馈。文本梯度下降要求 LLM 根据反馈重写提示词。在更大的图中，同样的过程逐条边进行：每个变量从它被使用的所有地方收集批评意见，每条边每次迭代需要额外一次 LLM 调用。

该框架复制了 PyTorch 的结构：

tg.Variable

使用

requires_grad

，一个损失函数，

loss.backward()

,

optimizer.step()

，通过

tg.sum

进行小批量处理，外加动量的类比（优化器能看到早期版本）和约束（用英文书写的格式规则）。目标可以是一个

LLM judge

、单元测试结果或模拟器的输出。

论文将其应用于两类问题。实例优化改进单个产物：LeetCode Hard 题目的代码、GPQA 和 MMLU 问题的答案、通过分子对接和类药性评分的小分子，以及五位前列腺癌患者的放射治疗计划。提示词优化改进某个任务的一个提示词：针对 Object Counting、Word Sorting 和 GSM8K 的 GPT-3.5 Turbo 提示词，反馈由 GPT-4o 撰写。

研究笔记：问题、方法与结果

经 TextGrad 优化后，GPT-4o 在 LeetCode Hard 上的完成率为 52%，相比之下 Reflexion 为 31%，零样本为 26%（5 个随机种子）

使用 GPT-4o 的 GPQA 准确率，经过三轮优化并对四个答案进行多数投票

GPT-3.5 Turbo 经过 12 次提示词更新（每批 3 个样本）后的 GSM8K 准确率，与 DSPy 的 8-shot 提示词相当

复合 AI 系统将 LLM 调用、工具和模拟器串联起来，它们都不可微。这些系统过去靠人工逐个提示词进行调整，没有通用的方法来说明哪个组件应该改变以及如何改变。

将系统表示为变量（提示词、代码、答案、分子）构成的图。一个 LLM 对输出撰写自然语言反馈，然后基于下游反馈对每个上游变量撰写反馈，再由一个优化器 LLM 重写每个变量。API 仿照 PyTorch 设计。

GPT-4o 在 LeetCode Hard 上的完成率从 26% 提升到 36%，GPQA 准确率从 51% 提升到 55%，而用 GPT-4o 反馈调优的 GPT-3.5 提示词达到或超过了 DSPy 的 few-shot 提示词。分子和放射治疗的结果是计算机模拟的概念验证。

为什么这对 FDE 很重要

有用的思想是信用分配。当客户的四步流水线给出糟糕的答案时，问题在于应该修改哪一步。TextGrad 的反向传播让 LLM 在每条边上提问，这是一种结构化的方式，把一次失败的输出转化为对检索提示词、起草提示词或格式化步骤的反馈。

用更强的模型来调优更便宜的模型。 提示词实验使用 GPT-4o 为 GPT-3.5 Turbo 的提示词撰写反馈。为强模型的批评付费一次，然后由便宜模型提供服务，这是一种合理的成本模式。

数一数调用次数。 每次迭代在每条边上增加一次批评调用，每个变量增加一次更新调用，再加上评估器。在长流水线上，这是前向传播成本的数倍。

要求算力匹配的基线。 对答案进行三次精炼并在四个版本上投票，花费的是四个答案的算力。公平的比较是四个独立答案的投票。论文没有报告这一比较，我们下面的模拟会说明为什么这很重要。

用留出数据对每次更新设置门槛。 在提示词实验中，TextGrad 只有在验证准确率提升时才保留新提示词。没有这个门槛，LLM 自信满满的批评可能让事情变得更糟。
