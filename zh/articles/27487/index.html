今日判断

今天最值得注意的不是 Agent 又多了一个功能，而是国内开始补齐"能行动之后，谁授权、谁付款、谁担责、怎样追溯"的交易基础设施：蚂蚁发布面向 Agent 商业活动的 APASS，把智能体身份、授权、风控和交易存证连成一条链。

同一天，两条"人"的信号形成呼应：北京石景山的"头号星系"OPC 社区展示了垂直生态的组织样本；Palantir 前 FDE 负责人则发文点破行业本质——FDE 若只解决单个客户的最后一公里而不回写产品，就仍是换了名字的咨询公司。

重点信号

蚂蚁发布 APASS：Agent 身份、授权、风控和交易存证连成责任链

  • 来源：支付宝 APASS 官方产品页；中国证券报
  • 蚂蚁集团在外滩大会发布面向 Agent 商业活动的 APASS（智能体可信身份基础设施）：建立静态身份、运行时身份和责任主体身份三层模型，持续核验环境、实例、代码组件、商业授权与行为权限，并把交易前授权、交易中风控和交易后存证串联。现场披露已接入超过 100 万个 Agent、覆盖 442 家服务供给方。
  • 为什么重要：当 Agent 能调用服务和支付，交付对象就从"一个会回答的应用"升级为"有身份、有权限、有预算、有履约证据的业务参与者"。FDE 的任务清单必须相应扩展：主体绑定、授权范围、额度、异常升级、日志、签收和争议处理。完整的 Agent 交易责任链有九段：委托人 → Agent 身份 → 责任主体 → 授权与额度 → 服务确认 → 支付 → 履约 → 业务验收与凭证回传 → 争议/追责/回滚——任何一段只有技术调用而没有主体、证据和负责人，都不算可生产的商业闭环。注意：接入数和激活数为会议累计口径，不等于生产活跃或成功交易。

北京石景山「头号星系」OPC 社区：垂直生态的组织样本

  • 来源：人民网北京频道 ｜ 原文链接
  • 石景山"头号星系"OPC（一人公司）社区在服贸会按"工具赋能—资产运营—前沿成果—沉浸体验—个体创作"组织展示，近 30 家企业带来 60 余个展项；社区称已入驻近 40 家企业，聚焦"AI + 科幻"垂直方向，以 IP 源头、AI 生产工具和创作者基地构成闭环。
  • 为什么重要：这是国内 OPC（超级个体/一人公司）生态的一个可观察样本——它的启示不在规模而在垂直化选择：不泛化罗列全部 AI 资源，而是聚焦一个方向做深闭环。评估这类社区用七级漏斗：入驻 → 活跃 → 真实需求 → 成交 → 交付 → 验收结算 → 复购。入驻企业数与展项数证明供给聚合，后四项才证明商业闭环。注意：活跃企业、订单和收入均未披露。

Palantir 前 FDE 负责人：只解决最后一公里，你仍然是咨询公司

  • 来源：Latent Space ｜ 原文链接
  • Palantir 前 FDE、Project Frontline 前负责人 Vinoo Ganesh 撰文分享 FDE 最佳实践（该轮岗项目约有 250 人参加）。核心主张：FDE 应作为产品团队的延伸，进入客户现场收集真实业务的"名词与动词"（业务对象与动作语义），并把最后一公里的洞察回写成所有后续客户都能获得的通用能力。
  • 为什么重要：这句话刺中了行业软肋——FDE 与咨询的分水岭不在驻场，而在回写。可复制性的衡量标准是第二个客户的交付周期、复用比例和质量变化，不是项目数量。现场洞察回写飞轮：观察真实用户 → 收集业务名词/动词 → 对齐数据语义与责任 → 完成最小交付 → 客户验证 → 回写通用产品/模板 → 在下一客户复用并测周期。现场交付获取的是高价值上下文，只有回写与复用，项目收入才能沉淀为产品资产。

对 FDE 从业者的启发

  • 给交易型 Agent 项目建"责任对象表"：需求方、承接方、Agent、责任主体、授权范围、预算额度、履约证据、验收人、争议处理、退款回滚——十项逐一落到人。
  • 停止用人月作为核心产品语言：报价底稿保留人力成本，客户方案改为"付费诊断包 → 单场景交付包 → 运营支持包 → 复用/分成机制"，各自写清交付物与验收——按人天扩张会被交付人数和验收争议锁死。
  • 每个项目做"名词—动词—责任"采集：名词对应业务对象与数据语义，动词对应动作、权限与状态变化，责任对应确认、异常和签字。项目结束必须回写通用资产——这是从咨询升级为产品公司的唯一路径。
