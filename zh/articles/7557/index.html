什么是图工程？一个通俗易懂的定义

原标题：What Is Graph Engineering? A Plain-English Definition

AY Automate · 2026 · 约 7 分钟读完

摘要

AY Automate 撰文解释“图工程”这一概念：将 AI Agent 系统组织为节点、边和共享状态构成的图，并叠加可自我修复的循环。作者说明该术语来自 aibuilderclub 的指南，LangGraph、AutoGen 等早已实践此模式，AY 只是借用了这套词汇来描述其内部已在生产环境运行的多 Agent 构建系统。文章还给出循环与图的选择标准、成本权衡及三种常见生产故障。

要点

  • 图工程指由节点、边和共享状态组成的 Agent 系统，叠加可重试的循环。
  • 术语源自 aibuilderclub 的升级阶梯框架：提示、上下文、工具层、循环、图。
  • LangGraph、AutoGen GraphFlow、Google ADK 和 A2A 协议早于该术语实践了图模式。
  • 仅当任务需要多角色交接、分支或并行时才值得用图，否则循环更省成本。
  • 生产中三大故障：状态漂移、节点越界写入、以及未改变输入的假自愈。

声明出处

“图工程”这个词不是我们创造的。

下面的升级阶梯框架——提示词、上下文、工具框架、循环、图——来自 aibuilderclub 的图工程指南，作为 2026 年 7 月关于 Agent 工程下一步走向的讨论的一部分发布。那篇文章也诚实地列出了它自己的先行工作：LangGraph、AutoGen 的 GraphFlow、Google 的 ADK 以及 A2A 协议，都远在这个短语出现之前就把 Agent 工作建模为图。

我们在这个页面带来的不是这个术语，而是一个框架：早在这套词汇出现之前，它就已经在生产环境中内部运行图加循环的组合——AY 多智能体构建系统，它在范围受限的 Agent 节点之间规划、锁定、构建、审查和合并任务。我们使用 aibuilderclub 的词汇，是因为它最清晰地描述了我们内部早已有名字的一种形态，而且这个名字比我们的更好。

节点、边和共享状态

图由三部分组成。节点各自只做一件事。边在它们之间路由工作：直连、条件、扇出、扇入或回环。共享状态是每个节点都读写的唯一对象，而不是每个节点各自维护自己的记忆。

节点

一个专门的 Agent 或一个确定性步骤，只承担恰好一项工作。

边

节点之间的路由：直连、条件、扇出、扇入或回环。

共享状态

在图中流转的唯一对象：需求简报、来源、草稿、评分、结论。

循环还是图？

图并不天然更好。它消耗更多 token，也带来更多出错面。只有当信号确实存在时才使用图。

State is a single running buffer, not shared structured data
Parts of the task are independent and can run in parallel

图结构的真实成本

更多节点读取同一状态，且审查阶段会重新读取输出，因此图结构比单一循环消耗更多 token。并行扇出用部分额外成本换取更低的延迟。

仅为示意，并非基准测试。图结构比单一循环消耗更多 token，因为更多 agent 读取同一共享状态，且审查阶段会重新读取输出。并行扇出花费更多 token 来换回延迟：独立节点同时运行，而不是依次执行。

生产环境中的图结构实际如何出错

并非假设。这三种故障模式正是 AY 框架的锁定与审查协议所要捕捉的。

状态漂移

两个节点写入同一字段，却对该字段的结构有不同假设。AY 强制使用一个共享的追踪层（BOARD.md、HANDOFFS.md），而不是让每个 agent 自行发明自己的状态格式。

节点隔离失效

一个被限定在某个目录内的 worker 越出该目录，与另一个 worker 的修改发生冲突。锁定文件协议（每个任务一个锁，写入前先提交）正是为了在合并前捕捉这种情况而存在的。

假装恢复，而非真正恢复

回退循环用相同的输入重试同一个失败的步骤，并称之为自愈。真正的恢复会改变某些东西：提示词、上下文或计划，并在 HANDOFFS.md 中记录原因，以便下次运行不再重复。

常见问题

图工程相关问题

什么是图工程？+

图工程是将 AI 系统作为一组由边连接的专用 Agent 节点来运行，并在节点之间传递一个共享的状态对象。它比循环工程高一层：循环是一个 Agent 不断重复直到通过某项检查，而图是多个 Agent 沿着路由路径（包括分支和回环）相互交接工作。

谁创造了“图工程”这个术语？+

升级阶梯框架（提示、上下文、工具层、循环、图）来自 aibuilderclub 的《图工程指南》，发表于 2026 年 7 月的一次讨论中。AY Automate 并非该术语的创造者。本页面使用该术语来描述我们已在生产环境中运行的框架——AY 多 Agent 构建系统，并注明这一词汇的来源。

图难道不只是 LangGraph、AutoGen 或换了新包装的工作流引擎吗？+

大体上是的，aibuilderclub 的指南也直接说明了这一点。在“图工程”这一术语出现之前，LangGraph、AutoGen 的 GraphFlow、Google 的 ADK 以及 A2A 协议就已经将 Agent 工作建模为图。较新的部分是为这一实践命名，并为团队提供一套词汇（节点、边、共享状态），以便判断图何时值得比循环付出额外的复杂度。

我需要图，还是循环就够了？+

如果一个 Agent 针对单一检查进行重试就能完成工作，那么循环就够了，图只会增加成本而不增加价值。当两个或更多专用角色需要交接工作、任务存在分支，或部分工作可以并行运行时，才考虑使用图。本页面的决策表列出了具体的判断信号。

AY 框架如何结合循环和图？+

AY 框架是一个由作用域受限的 Agent（规划器、工作节点、审查者）组成的图，通过一个构建循环连接：观察、锁定、规划、构建、自审、测试、学习、解锁。共享状态保存在普通的跟踪文件（BOARD.md、HANDOFFS.md、任务锁）中，而不是数据库中；当对抗性审查发现问题并将任务退回给工作节点时，就会发生循环回退，此时任务尚未合并。

在生产环境中运行 Agent 图时，真正会出问题的是什么？+

主要有三点：一是状态漂移，即各节点对共享数据结构的理解不一致；二是节点隔离失效，即某个受限 Agent 越界写入了不属于它的范围；三是虚假自愈，即循环回退只是对同一个失败的输入不断重试，却没有做任何改变。以下生产环境故障模式部分涵盖了这三点，并给出了 AY 实际采用的应对措施。
