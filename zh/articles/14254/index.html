前沿部署工程师的带回家作业：提示词与范围界定

原标题：Forward deployed engineer take-home: prompts and scoping

FDE Interview Prep · 2026-09-25 · 约 17 分钟读完

摘要

文章分析了多家公司公开及候选人复述的 FDE 带回家作业题目，指出这类作业通常不只是写代码：除小型可运行的构建外，还常要求写给客户的邮件、AI 使用记录和答辩式讲解。作者建议先读提交要求，按比例分配时间，先搭最简端到端骨架，再按风险排序，并用 cut list 说明主动放弃的内容。

要点

  • FDE 作业通常要求代码、客户邮件、AI 使用记录和讲解四类交付物。
  • Tangible 给 2 小时：服务约 60–75 分钟，邮件 20–30 分钟，AI 说明约 5 分钟。
  • 多家公司明确偏好小而完整的方案，而非雄心勃勃的半成品。
  • AzurePartners 等要求用 DECISIONS.md 记录主动放弃的内容及原因。
  • 遇到模糊处应提问或写下假设，默默猜测不被接受。

招聘人员的邮件说下一步是带回家作业，任务简述一屏就能看完：在几个小时内为一家虚构客户构建有用的东西。你可能已经在挑选框架了，这意味着你准备把整个时间都花在写代码上。在我们读过的带回家作业简述中，除了代码之外，通常还要求三样东西：写给客户的文字说明、你如何使用 AI 的记录，以及一段你为自己构建的东西进行答辩的演示讲解。并非每份简述都要求全部三项，所以在阅读题目之前，先看清你的简述要求提交什么。对于招聘流程中的其他环节，请从前沿部署工程师面试指南开始。

Tangible 的简报给出了格式：你使用了哪些工具、用它们做了什么，以及一个你推翻或纠正 AI 结果的例子。来源 1Take-Home Assignment: Client Positions Feed Onboarding发布方Tangible（GitHub 上的 tangiblemarkets）来源类型公司网站以下是一个符合该格式的示例说明，针对一个虚构的简报：

规划你的时间盒：裁剪清单和占位清单

剪裁清单并非我们的发明。AzurePartners 的简报中 DECISIONS.md 的第一个问题是“你刻意没有做什么，为什么？”，而一位候选人报告的 Concourse 简报则要求提供剪裁清单：“你决定不做什么，为什么。”来源 5Take-home: the planning agent发布方AzurePartners（GitHub 账号）来源类型公司网站来源 12Forward Deployed Engineer: Take-Home (PDF)发布方cgillespie529-gif（GitHub）来源类型候选人的 take-home 仓库来源 13vibe-coding（仓库描述）发布方cgillespie529-gif（GitHub）来源类型候选人的 take-home 仓库时间分配和桩模块清单则是我们提出的。

在打开编辑器之前先切分时间。 Tangible 的简报已经为你做好了切分：服务部分约 60 到 75 分钟，邮件部分 20 到 30 分钟，AI 说明约 5 分钟，总共在 2 小时之内。来源 1Take-Home Assignment: Client Positions Feed Onboarding发布方Tangible（tangiblemarkets on GitHub）来源类型公司网站如果你的简报没有给出时间分配，就先为写作和讲解预留时间，把剩下的留给构建。以下是一个针对虚构简报的计划。它遵循 Tangible 的比例，而非 Tangible 的具体数字：

Brief: 4 hours. Build, email, README.
0:00 read brief, write README heads
0:15 skeleton: input to output
1:15 riskiest part (messy rows)
2:30 stop building, commit
2:45 client email
3:15 README: cut, stub, AI, time
3:45 clean clone, say walkthrough

构建最精简的端到端路径。 输入进、输出出，中间可以很粗糙。一个能跑通的行走骨架胜过三个互不连通的精美模块。

按风险排序其余部分。 先构建最可能出问题的部分：混乱的输入、不稳定的 API、含义模糊的字段。Namastex 的评测清单会问当报价 API 失败时 Agent 会怎么做，并称这是“最能区分高下的地方”（由葡萄牙语翻译而来）。来源 4Desafio Técnico — FDE / AI Engineer (Namastex)发布方Namastex（GitHub）来源类型公司网站按风险排序在一个更大的项目上展示了这一方法。

要么提问，要么做出决定并写下来。 Tangible 告诉候选人可以“像对待 Dana 那样”发邮件提问，Dana 是其虚构的集成负责人；Ethyca 也邀请你主动联系并提问。来源 1Take-Home Assignment: Client Positions Feed Onboarding发布方Tangible（tangiblemarkets on GitHub）来源类型公司网站来源 2Ethyca Technical Challenge -- Forward Deployed Privacy Engineer (FDPE)发布方Ethyca（GitHub）来源类型公司网站AzurePartners 的简报则表示，你也可以自行做出判断并写下来，但“默默猜测而不说明”是不行的。来源 5Take-home: the planning agent发布方AzurePartners（GitHub 账号）来源类型公司网站一位候选人报告的 Concourse 简报说，如果你在流程事务上受阻可以提问，而“关于数据的判断则由你自己做出”。来源 12Forward Deployed Engineer: Take-Home (PDF)发布方cgillespie529-gif（GitHub）来源类型候选人的 take-home 仓库来源 13vibe-coding（仓库描述）发布方cgillespie529-gif（GitHub）来源类型候选人的 take-home 仓库

一个值得发送的问题应当简短，说明你的默认处理方式，并且能用一行话回答：

Priya 你好，就诊导出中有两行的就诊 ID 相同，但列出的诊所不同。我把后出现的一行当作更正，并在报告中把两行都标记出来。如果你的导出逻辑与此相反，请告诉我。

如果没有回复，就保留你的默认处理，并把它写进 README 的“假设”一栏。

随手维护两个清单。它们是不同的东西，评审者需要能区分它们。

  • 裁剪清单记录本次提交中不包含的内容，每项附一句原因。“无身份验证：需求说明只涉及一个内部用户，且评审者在本地运行。”
  • 桩清单记录那些只有形式但行为是伪造的内容。代码路径是真实的；末尾的调用不是。

桩应当自我声明。下面是一个虚构需求中的示例：诊所的就诊导出需要接入一个你没有凭据的排班系统：

def push_visit(visit: dict) -> dict:
    """Stub: no scheduler credentials.
    See README, 'Stub list'."""
    vid = visit["id"]
    print(f"[stub] push {vid}")
    return {"id": vid,
            "status": "stubbed"}

它会打印

[stub] push V-1042

并返回一个标记为

stubbed

的记录，这样就不会有人把它误认为真实的集成。桩清单条目要说明真实版本需要什么：重试机制，以及一个

idempotency key

，确保重新运行时不会重复预订同一次就诊。

用计时器而非感觉来决定何时停止构建

设一个闹钟，提醒你必须切换到写作的时刻。闹钟响起时，提交能运行的代码，哪怕是半个功能，然后把其余部分移入裁剪清单。一份关于未完成功能的完整说明，比一个没有说明的完整功能是更好的交付物。

用写作代替构建的内容

你裁剪的每件事都变成一句话，而 README 承载了其中大部分：

家庭作业式任务的 README 标题

  • 它做什么，用一句客户能理解的话说明
  • 如何运行，用在一台干净机器上可用的命令说明
  • 我构建了什么，以及为什么先做这一部分
  • 假设：我在没有得到答复的情况下做出的决定
  • 裁剪清单：我略去了什么，以及原因
  • 桩清单：什么被伪造了，真实版本需要什么
  • 如果再多一天：接下来的三件事，按顺序排列
  • 我如何使用 AI（如果需求允许）
  • 花费的时间，如实说明

给客户的说明更简短、更直白。虚构诊所需求的一个骨架：

Priya 你好，就诊导出现在每次运行时都会加载到暂存表中，重新运行不会产生重复数据。在上线之前有两件事需要你决定。第一，有些行没有诊所代码；我没有猜测，而是把它们放在了待审核清单中。你的团队能告诉我它们属于哪家诊所吗？第二，我还没有连接排班系统，因为我没有凭据。一旦有了凭据，这只是一个小改动，我会先发送一次测试运行供你检查，然后才会移动任何真实就诊数据。

它说明了什么能用、什么被阻塞、由谁决定。

对于你最需要的那句话，借用这个句式：“我没有构建 X。在有限的时间里，我选择了 Y，因为 Z。构建 X 需要这些。”

为演示讲解和现场扩展做准备

Coframe 列出的视频应涵盖的内容，是任何演示讲解的绝佳默认大纲：一个演示、解决方案及你使用的 AI 工具、边界情况，以及要在生产环境运行还需要什么。来源 3Coframe Forward Deploy — Take-Home发布方Coframe (GitHub)来源类型公司网站 录制演示讲解视频介绍了节奏把控和屏幕上应展示的内容。

准备好回答演示讲解中反复出现的三个问题：

  • “为什么先做这一块？” 指出你消除的风险。“输入是最不确定的部分，所以我确保在构建任何东西之前能加载每一行数据。”
  • “在生产环境中什么会最先出问题？” 说出一件具体的事。“对调度器的重试，因为桩实现把它们隐藏了。我会加一个死信表并对它设置告警。”如果你不熟悉“死信”（dead-letter），死信队列条目用一段话解释了它。
  • “如果再多一天，你会改什么？” 从你的 README 中找答案。用我们题库中的这个问题练习一下，它还会问你刻意省略了什么。

如果你的任务简报包含现场扩展环节，比如 AzurePartners 的简报，就为它留好接口。来源 5Take-home: the planning agent发布方AzurePartners (GitHub 账号)来源类型公司网站 保持从输入到输出的路径由小而命名清晰的函数组成，这样新增一个字段只需改动一处。在面试通话之前，端到端地演练一次扩展：新增一个字段、把它传递下去，并在输出中展示它。

代价最大的错误

  • 构建了整个任务却什么都没写。 解决方法：在写代码之前先起草 README 的标题和客户说明的第一行，最后再填充内容。
  • 超出时间限制还隐瞒不报。 AzurePartners 的简报说“请不要超过四个小时”。来源 5Take-home: the planning agent发布方AzurePartners (GitHub 账号)来源类型公司网站 解决方法：到点就停，并在 README 中说明你的用时。
  • 把可见的测试当作目标。 AzurePartners 的简报说“可见的测试是底线，而不是上限”。来源 5Take-home: the planning agent发布方AzurePartners (GitHub 账号)来源类型公司网站 解决方法：测试简报所暗示的边界情况，而不仅仅是它展示的那些。
  • 猜测 AI 使用规则。 Namastex 期望使用 AI 编程工具，而 Anthropic 要求候选人在没有特别说明的情况下不使用 Claude 完成带回家的任务。来源 4Desafio Técnico — FDE / AI Engineer (Namastex)发布方Namastex (GitHub)来源类型公司网站来源 15Guidance on Candidates' AI Usage发布方Anthropic来源类型公司网站 解决方法：在你的简报中找到相关句子，如果没有就询问招聘人员。按公司和阶段划分的 AI 规则课程列出了已公布的规则。
  • 沉默的占位实现与沉默的猜测。 一个看起来像真的假实现会被当成 bug 或虚张声势，一个没人写下来的假设也是如此。解决方法：在代码中标注每个占位实现，并在 README 中列出所有占位实现和假设。

如果你的带回家作业来自 AI 实验室，同样的流程也适用；OpenAI 的 FDE 带回家作业结合 OpenAI 发布的内容和候选人的反馈展示了这一点。

提交之前

交付当晚

  • 从干净的克隆仓库开始，使用 README 中的命令即可运行
  • 取舍清单和占位实现清单都已写好，每一项都附有理由
  • 你在没有得到答案的情况下做出的每个假设都已写下来
  • 给客户的说明中写明了哪些可用、哪些被阻塞以及由谁决定
  • 你的 AI 使用情况符合任务说明中的规则，包括你所做的例外处理
  • 你已经从头到尾完整地口头演练过一次

一位候选人报告的 Kong 任务说明以一场启动电话会议开场，面试官扮演客户。来源 8Kong PS / 前沿部署工程师 — 带回家作业发布者alexscottan (GitHub)来源类型候选人的带回家作业仓库 这个免费案例就是那通电话：一个有建筑许可问题的 AI 客户、10 分钟的计时，以及一个引用你说过的内容的评分。在带回家作业到来之前，先运行这个免费案例，并练习你在构建过程中需要提出的问题。

人们常问的问题

前沿部署工程师的带回家作业要求什么？

在我们读到的任务说明中，要求的不只是代码。Tangible 公开的 FDE 带回家作业要求一个数据接入服务、一封发给客户集成负责人的跟进邮件以及一份 AI 使用说明，而 Coframe 的则要求代码外加一段录制的视频演示。来源 1带回家作业：客户职位数据接入发布者Tangible (tangiblemarkets on GitHub)来源类型公司网站来源 3Coframe Forward Deploy — 带回家作业发布者Coframe (GitHub)来源类型公司网站

FDE 带回家作业应该花多长时间？

遵守任务说明中规定的时间，并说明你舍弃了什么。规定的时限各不相同：Coframe 公开的带回家作业给出 2 小时，而 Ethyca 的说明其挑战应耗时 3 到 4 小时。来源 2Ethyca 技术挑战 -- 前沿部署隐私工程师 (FDPE)发布者Ethyca (GitHub)来源类型公司网站来源 3Coframe Forward Deploy — 带回家作业发布者Coframe (GitHub)来源类型公司网站

在 FDE 带回家作业期间我可以提问吗？

有些简报明确欢迎提问。Tangible 公布的 FDE 家庭作业说明在作业期间可以通过邮件提问，而 AzurePartners 的说明则表示，如果内容有歧义可以发邮件询问，或者自行做出判断并记录下来。来源 1家庭作业：客户职位数据接入发布方Tangible（GitHub 上的 tangiblemarkets）来源类型公司网站来源 5家庭作业：规划 Agent发布方AzurePartners（GitHub 账号）来源类型公司网站

我可以在 FDE 家庭作业中使用 AI 工具吗？

遵循简报要求。Namastex 公布的 FDE 家庭作业预期使用 AI 编程工具，并要求将你的 AI 对话记录放在 ai-logs 文件夹中提交；而 Anthropic 则要求候选人在没有特别说明的情况下，不使用 Claude 完成家庭作业。来源 4技术挑战 — FDE / AI 工程师（Namastex）发布方Namastex（GitHub）来源类型公司网站来源 15关于候选人使用 AI 的指引发布方Anthropic来源类型公司网站
