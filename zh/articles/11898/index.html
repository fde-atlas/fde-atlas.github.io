气隙与受监管环境部署：在没有互联网的地方交付 AI

原标题：Air-Gapped & Regulated Deployment: Shipping AI Where There Is No Internet

Vibe Engines · 2026-07-31 · 约 14 分钟读完

摘要

本文讲解在无互联网、受监管环境中部署 AI 系统的完整方法论，涵盖从客户云租户到真正物理隔离的五种隔离程度区分、FedRAMP 与 DoD 影响等级等合规概念、模型权重跨边界传输的八步流程，以及更新、评测与调试在受限环境下的替代方案。

要点

  • “隔离”实为五种模式，需在需求阶段问清机器能否访问公网。
  • 合规框架本质都问三件事：谁能访问数据、能否审计、控制是否有效。
  • 模型权重传输需八步流程，含校验、扫描与登记，耗时数天到数周。
  • 配置应作为数据由操作员修改，调优周期可从84天缩至20天。
  • 离线自测、回滚包与边界内评测集是受限环境的关键设计。

一些价值最高的前沿部署工作发生在你的常规工具完全无法触及的环境中：没有软件包仓库，没有模型 API，日志不能离开大楼，部署窗口每两周才开放一次。Anthropic 的联邦 FDE 职位直接点名了气隙隔离和影响级部署。29 这就是这项工作的真实内容，也是为什么能胜任的工程师如此稀缺。

光谱分析，因为“气隙隔离”常被泛泛而谈

客户说“气隙隔离”时可能指五种不同的情况，而其中的差异决定了你的整个架构。在需求发现阶段用一个具体的问题确认你处于哪一种：这个环境中的机器能否访问公网 IP 地址？如果能，通过什么方式？

模式实际情况代价
他们的云租户完整互联网，他们的账户，他们的管控架构上几乎没有任何额外代价。这就是常规工作。
私有 VPC，无公网入口通常允许出站流量，入站被封锁堡垒机访问、PrivateLink 端点、一次 VPN 沟通。
无出站 VPC任何东西都无法访问互联网，包括你的软件包安装镜像仓库、内嵌依赖、无外部模型 API。一次真正的架构重构。
本地部署，物理断网他们的数据中心，更新通过经批准的传输流程送达以上全部，再加上他们的硬件、他们的操作系统基线、他们的变更委员会。
真正的气隙隔离物理隔离的网络；数据通过正式审查后经可移动介质传输每次变更都有数周的延迟。你的调试循环才是瓶颈，而不是你的代码。

“当你们今天在这个环境中向现有系统部署一次更新时，请带我走一遍会发生什么、需要多长时间。”去问一线操作人员，而不是架构师。答案——每两周一次的窗口、一次签名的介质传输、为期两周的安全扫描——才是你真实的迭代速度，你给出的每一个估算都应建立在这个基础上，而不是建立在你能多快写出代码上。

面向工程师的合规术语

你不需要成为合规专家。但你需要知道这些术语限制了什么。

FedRAMP——美国联邦云服务授权

一个针对销售给美国联邦机构云服务的授权计划，设有 Low、Moderate 和 High 基线，对应数据泄露的影响程度。对工程师的实际影响是：服务必须运行在授权边界之内，边界内的每个组件都要登记造册，变更需经过文档化的流程。你新增的一个依赖是一次边界变更，而不是一次 pull request。

美国国防部数据的并行分级。IL2 为公开/非关键。IL4 为受控非密信息。IL5 要求再次提高，通常需要专用基础设施和美国公民访问控制。IL6 涵盖最高至 SECRET 的机密信息，并完全运行在独立的网络上。联邦 FDE 职位会直接引用这些级别。29 其工程后果是一个阶梯：随着级别升高，共享基础设施、远程访问和出站遥测会依次消失。

SOC 2 Type II — 对一段时间内控制措施的审计报告；大多数企业买家首先要求的就是它。ISO 27001 — 国际管理体系标准，在美国以外很常见。HIPAA — 美国健康数据，附带一份将实际责任分配给你的商业伙伴协议。GDPR 与数据驻留 — 数据在物理上可以存放的位置，这会悄悄排除掉许多架构方案。CMMC — 国防供应链对同样理念的认证。

所有这些框架都用不同的词汇问同样三个问题：谁能访问数据、你能否证明发生了什么，以及你能否展示控制措施长期有效。身份、审计日志和证据 — 即企业身份的主题。把这三件事做好，大部分问卷就能自答；做晚了，每个框架都会让你单独付出代价。

将模型权重送入隔离网络

人们低估的一步，因为在其他所有场景中它都只是一次下载。

一个实用规模的开源权重模型有数十到数百 GB。将其通过获批边界传输是一项附带安全审查的后勤工作，而且通常是首次交付中最耗时的环节。

1. 许可确认权重可在该环境、该级别下使用

2. 获取在你控制的干净暂存环境中下载一次

3. 校验对照发布方核对校验和 — 并记录下来；你会被问到的

4. 扫描对权重进行恶意软件 + 供应链扫描，

容器镜像和依赖

5. 打包一个制品：权重 + 运行时 + 配置 + 清单 + 哈希

6. 传输经批准的介质或单向数据二极管，附带签名的清单

7. 重新校验再次核对校验和

在边界内，在任何东西运行之前

8. 登记该制品作为受控组件进入他们的资产清单

# 在真实项目中，仅第 6 步的耗时：数天到数周

一次性正确打包

  • 所有内容放在一个签名的制品中 — 权重、运行时、模型配置、分词器、依赖项。
  • 一份列出每个文件及其哈希和许可的清单。
  • 一个对他们的变更委员会有意义的版本字符串，而不是 git SHA。
  • 假定没有镜像仓库、没有 DNS、且操作员从未见过你的离线安装说明。
  • 一个回滚产物，随更新同时传输。本周不会有第二次传输。

用惨痛教训换来的发现

  • 一个在运行时才拉取基础层的容器镜像。在那里面，什么都不会拉取任何东西。
  • 一个需要从源码编译的 Python 包，而所需的工具链没人安装过。
  • 一个在启动时会联网进行许可证检查的模型运行时。
  • 硬件不匹配：不同的 GPU 代次、不同的驱动、不同的量化支持。
  • 忘记带上分词器，或者发布的配置引用了 HuggingFace 路径。

在任何传输之前，先在一台物理断网的机器上安装你的软件包。这只需要一个下午，却能捕获上述几乎所有的失败。否则，你就要在一个无法下载任何东西、无法带笔记本电脑进入、并且要等到下一个窗口才能重试的设施里，才发现缺失的基础层。

没有更新通道的更新

持续交付带来的所有便利都消失了。取而代之的是一个更慢的循环，必须让它变得可靠，因为你尝试的机会很少，而且每一次代价都很高。

按他们的节奏批量交付，而不是你的

如果窗口是每两周一次，那你的发布节奏就是每两周一次。把变更打包在一起，把整个包作为一个单元来测试，不要再以单个提交来思考。错过窗口的变更只能等待，所以每个包的范围应该限定在你有把握的内容，而不是刚好做完的内容。

把配置做成一条独立、更快的路径

提示词、阈值、路由规则和功能开关应该是授权操作员可以在环境中修改的数据——而不是需要完整传输的代码。这一个设计决策，决定了你调优系统需要一天还是一个月，而且事后改造远比一开始就构建要困难得多。

随产品一起交付诊断工具

你将无法附加调试器，而且往往看不到日志。构建一个自检命令，遍历每一个依赖项并打印一份可读的报告；再准备一个脱敏安全的诊断包，操作员可以生成并通过批准的渠道传给你。要刻意设计这个包里放什么——它是你唯一的窗口。

把回滚做成一等产物

有版本号、随更新一起传输、经过测试。在联网环境中，回滚只是一条部署命令；而在这里，它是一个物理过程，如果回滚包不在边界之内，它就等于不存在。

为无法向你提问的操作员编写文档

这些环境中的运行手册，是由完全无法打电话求助的人来阅读的。每一步都必须是确定性的，每个预期输出都要展示出来，每个失败分支都要命名。这是在最严苛约束下的赋能。

评测。所有人都依赖的闭环——观察生产环境、收集失败案例、持续改进——前提是你能看到生产环境。而你看不到。替代方案是一套存放在边界之内的黄金数据集，由他们的运维人员针对每次发布运行，只有汇总分数通过审批渠道传出来。要在项目一开始就设计好；事后把评测框架改造进一个隔离环境，远比从头搭建困难得多。评测框架本身参见客户项目评测。

在约束条件下工作

环境塑造的是日常，而不仅仅是架构。

真正不同的地方

  • 你可能不能把手机或笔记本电脑带进设施。你的笔记只能用纸。
  • 你不能在解决问题的过程中上网搜索。把文档带进去。
  • 访问许可可能需要数月，而且完全决定工作能否开展。
  • 你可能无法与自己的同事讨论问题的具体细节。
  • 与持有许可的运维人员结对，往往取代了与工程师结对。

让工作可持续的习惯

  • 准备一个离线工具包：文档、依赖镜像、参考实现、一个可用的本地模型。
  • 在每次会话之前写下假设——你只有一次实验机会，而不是二十次。
  • 让系统自己解释自己，因为你无法从外部检查它。
  • 在边界之外过度沟通，让看不到工作的人依然信任它。
  • 保持决策日志。六个月后没人会记得为什么某个阈值是 0.7。

这份工作报酬丰厚且确实稀缺，但它有一些招聘谈话往往略过的真实代价：许可流程会限制出行和个人生活，工作成果无法放进作品集或在面试中描述，现场驻场要求不可协商，技能深厚但面窄。它非常适合某些人。请在看清利弊权衡后再做决定——前沿部署工程值得做吗更全面地讨论了这个问题。

两个数字决定首次交付：需要跨过边界多少字节，以及调优需要跨边界多少次。仅计权重，按 1 GB = 10⁹ 字节。调优计划仅为示意。

步骤问题计算答案
170B 参数模型，16 位700 亿 × 2 字节140 GB
2同一模型，4 位700 亿 × 0.5 字节35 GB，前提是他们的运行时和 GPU 支持
38B 模型，16 位80 亿 × 2 字节16 GB
4一次跨边界传输中包含更新加回滚（70B，16 位）2 × 140 GB280 GB，不含运行时和镜像
5六轮调优，每轮一次代码传输，每两周一个窗口6 × 14 天84 天，约四分之一

第 5 行和第 6 行用数字展示了本页“将配置作为独立路径”的建议：同样的调优需要 84 天或 20 天。第 1 到 4 行解释了为什么较小的模型往往是这里的正确选择。扫描时间、媒体大小和 GPU 内存都随字节数增长，而且 GPU 除了权重之外还需要内存来存放 KV 缓存。

这在生产环境和面试中的体现

  • 国防和联邦工作频谱的远端：IL5 和 IL6 工作负载、现场工作、有安全许可的操作员和纸质记录。这是本页联邦 FDE 参考所描述的情形。
  • 受监管的商业工作银行、保险公司和医疗系统更常处于频谱中部：一个无出站流量的 VPC 或带变更委员会的本地集群。你计划调用的模型 API 通常第一个被排除。
  • 因环境而断网工厂、船只和偏远站点因物理原因而非政策缺乏网络连接。同样的习惯适用：一个制品、一次自测、配置即数据，以及已就位的回滚方案。
  • 面试版本“为一个网络无法访问任何外部 API 的客户设计一个助手。”先问他们在频谱上处于哪种模式。然后涵盖模型大小与其 GPU 的匹配、制品及其哈希、配置路径、边界内的黄金集，以及诊断包。

自我检查

客户说网络是物理隔离的，但那边的一台服务器可以运行 pip install。你实际上处于哪种模式？

这不是真正的物理隔离。既然有东西能访问包索引，就说明存在出站流量，可能是通过代理。问一下页面上的问题：机器能否访问公网 IP，通过什么方式？答案会把你从长达数周的介质流程转向 VPN 和终端的讨论。

在边界内，服务在启动时获取其分词器（tokeniser）时失败了。什么手段本可以提前发现这个问题？

在传输之前，把制品安装到一台物理禁用网络的机器上。指向 HuggingFace 路径的配置，或缺失的分词器，会在几分钟内在那里失败，而不是浪费整个部署窗口。

运营人员想把置信度阈值从 0.7 提高到 0.8。这是代码发布还是配置变更？

是配置变更，而这正是构建这条路径的意义所在。但它仍然会改变行为，所以应该在边界内运行黄金数据集，并写入审计日志，记录谁做了变更以及为什么。

只有聚合分数会离开边界，而发布后分数下降了。如何找出原因？

提前为此做好设计。按黄金数据集的类别分别报告分数，这样分数下降就能指向某一类案例。向运营人员索要可安全脱敏的诊断包。如果原因不能很快查明，就回滚，因为回滚制品已经在边界内了。

快速问答

在 AI 部署中，“物理隔离”（air-gapped）到底是什么意思？

这个词被宽泛地用来指五种不同的模式：完全联网的云端租户；无公网入站但有出站流量的私有 VPC；无出站流量的 VPC，包括包安装在内任何东西都无法访问互联网；本地部署且断网，更新通过经批准的传输流程送达；以及真正的物理隔离，即网络物理分离，数据通过可移动介质传递。在需求调研阶段就要弄清楚是哪一种，方法是询问是否有任何机器能访问公网 IP 地址。

FedRAMP 和 DoD 影响级别是什么？

FedRAMP 是美国联邦政府的云服务授权计划，设有低（Low）、中（Moderate）、高（High）三个基线，反映数据泄露的影响程度。DoD 影响级别（Impact Levels）是针对国防数据的并行分级：IL2 适用于公开和非关键数据，IL4 适用于受控非密信息（CUI），IL5 通常要求专用基础设施和美国公民访问控制，IL6 适用于最高至 SECRET 级的机密数据并部署在独立网络上。随着级别升高，共享基础设施、远程访问和出站遥测会依次消失。

模型权重如何进入物理隔离环境？

确认该环境的许可要求，在干净的中转区一次性下载，对照发布方校验校验和并记录，扫描权重和镜像，将所有内容连同清单打包成一个签名的制品，通过经批准的介质或单向传输设备传送，在边界内任何程序运行之前重新校验校验和，并将该制品登记到他们的资产清单中。仅传输环节通常就需要数天到数周。务必同时传输一个经过测试的回滚制品。

当没有更新通道时，你如何交付更新？

将发布批次对齐到客户的变更窗口，而不是你自己的节奏；并将配置——提示词、阈值、路由规则、功能开关——作为一条独立的更快路径，由经授权的操作员就地修改，无需完整传输。交付一个自检命令和一个可安全脱敏的诊断包，将回滚视为与更新一同传输的一等制品，并为无法向你提问的操作员编写运行手册。

在断网环境的 AI 部署中，什么最先出问题？

评测。观察生产环境、收集失败案例并持续改进的常规闭环，前提是你能看到生产环境——而你看不到。替代方案是一套存放在边界内的黄金测试集，由客户的操作员针对每次发布运行，只有汇总分数通过经批准的通道返回。要在项目一开始就设计好——事后将评测框架改造进断网环境，比从头构建要困难得多。
