Google LLM 与 GenAI 基础轮次背后的概念

这些问题所假设的词汇和思维模型。基础部分免费学习；更深层的、决定面试成败的概念属于付费内容。

基础Token 化与 Token语言模型不读取字符或单词。它读取 token：由分词器产生的子词片段，每个 token 被映射为模型嵌入的一个整数。Token 是上下文窗口和计费的单位，而文本如何切分成 token 解释了大量看似奇怪的模型行为，这也是为什么几乎每个面试流程都从这里开始。

基础上下文窗口上下文窗口是语言模型一次能够关注的固定 token 数量，输入和输出共享同一预算。理解它，正是能够合理规划提示词大小、控制成本与延迟、并判断何时该使用 RAG 的工程师，与那些只是把所有内容一股脑粘贴进去然后祈祷的工程师之间的分水岭。

基础嵌入与向量表示嵌入将一段文本转换为一组数字，其位置使得含义相近的文本在空间中彼此靠近，从而让你可以按语义而非关键词进行搜索。嵌入是 RAG、语义搜索、聚类和去重背后的引擎，因此 FDE 面试流程期望你能解释余弦相似度，以及那些会悄悄破坏向量索引的陷阱。

基础Transformer 的直观理解Transformer 是所有现代大语言模型背后的架构，建立在自注意力机制之上，让每个 token 可以并行地关注其他所有 token。FDE 面试流程不要求数学推导；他们希望你用高管或同事都能听懂的通俗语言，解释为什么注意力机制胜过 RNN、decoder-only 意味着什么，以及为什么长上下文代价高昂。

基础Temperature、Top-p 与采样在每一步，模型都会为每个可能的下一个 token 输出一个概率分布，而 temperature、top-p 和 top-k 等采样设置决定了如何将这个分布转化为实际的选择。FDE 面试循环会测试这一点，因为它控制着确定性与创造性之间的旋钮：知道何时为信息抽取设置低值、为头脑风暴设置高值，以及为什么同一个提示词给出不同答案是预期行为而非 bug。

Google 的前沿部署工程师面试循环会考察 LLM 与 GenAI 基础问题，例如“请描述 LLM 生成响应时实际发生了什么”、“请端到端讲解 Transformer 架构，不涉及复杂数学”、“什么是上下文窗口，它在生产环境中的实际限制是什么？”。Token、上下文窗口、提示词 vs RAG vs 微调、幻觉、评测、成本与延迟：这是每个 AI 原生 FDE 面试循环首先考察的概念核心。完整题集按由易到难排序并附专家答案，见下文。

是的，而且是大规模的。Google Cloud 运营着一个大型、多层级的前沿部署工程师项目，同时还有客户工程师和应用 AI 岗位，将工程师派驻到企业客户中，在 Vertex AI 和 Gemini Enterprise 上交付 Agent 解决方案。它是 2026 年最大的 FDE 招聘方之一。

预期会有实操编码、GenAI 和 Agent 系统设计，以及与岗位相关的环节，考察如何将 Gemini 或 Vertex AI 解决方案从概念验证推进到生产环境，此外还有面向客户的判断力考察。面试官会探究你如何界定模糊的企业问题并可靠地构建解决方案。
