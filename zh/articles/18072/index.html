FDE 安全问卷怎么填：SOC 2 与 ISO 27001

FDE Times · 2026-10-09 · 约 6 分钟读完

摘要

这篇指南面向前沿部署工程师，讲解如何高效填写客户安全问卷。文章区分了 SOC 2 报告与 ISO 27001 证书的不同证明作用，建议先发送 SOC 2 Type II 报告再填表，据合规咨询公司 Agency 估算，一份有效的 Type II 报告可直接回答 CAIQ 约 260 题中的 60-70%，只剩 78 到 104 题需新写。作者给出答案模板（含回答、证据、范围、负责人等字段），强调按主题而非框架组织答案库，并提醒过时答案库比没有更危险。文末列出常见错误，如误发 Type 1 报告、忽略证书范围等。

要点

  • SOC 2 是 CPA 出具的报告，ISO 27001 是写明 ISMS 范围的证书，两者证明内容不同。
  • SOC 2 Type II 报告可回答约 60-70% 的 CAIQ 问题，260 题中仅剩约 78-104 题需新写。
  • 每条答案应标注证据、适用范围和负责人，写清范围的“部分”比含糊的“是”更可信。
  • 答案库按访问管理、加密等主题组织，而非按问卷框架，且每条需负责人和复核日期。
  • 常见错误包括误发 Type 1 报告、未核对 ISO 27001 证书范围、答“是”却不附证据。

据一家咨询公司估算，先发 SOC 2 报告，260 题的 CAIQ 只剩约 78 到 104 题要自己写。

要点速览

  • SOC 2 是一份报告，由注册会计师（CPA）就组织是否言行一致给出意见；ISO 27001 是一张证书，写明 ISMS 的覆盖范围。两者证明的内容不同。
  • 动手填表之前先把报告发出去：一家合规咨询公司估计，SOC 2 Type II 可直接回答约 60-70% 的 CAIQ 问题。
  • 答案库按主题组织，并指定负责人和复核日期。过时的答案库比没有答案库风险更大。

驻场第一周，一行代码还没跑，邮件先到了：一张列着几百道安全问题的表格，外加一句话，填完才给你开权限。如果客户是金融机构，这张表可能是 SIG Core，一份超过 800 道题的问卷。

为企业提供前线部署工程师（FDE）人力的公司 Appsierra 观察到，开通权限、安全评审和等待客户审批，耗时往往比找到工程师本身还长。不过，这是一家出售该服务的公司的说法。

好消息是，这是一项可以学会的技能。FDE 的工作不是重写公司的安全策略，而是在合适的时间，把范围正确的证据摆到客户面前，让对方安全团队有足够的理由点头。

SOC 2 和 ISO 27001 证明的东西不同

要用好证据，先得知道每种证据证明什么。审计机构 Schellman 表示，SOC 2 的产出是一份报告，由注册会计师（CPA）就组织是否真正做到了它所声称的事情给出意见。

美国注册会计师协会（AICPA）表示，SOC 报告为使用者提供信息，帮助其评估和应对外包服务的风险。其 SOC 2 材料围绕五个类别展开：安全性、可用性、处理完整性、保密性和隐私。

SOC 2 报告分两种类型。据 Schellman 介绍，Type 1 评估的是某一个时间点，Type 2 覆盖一段时间，通常为 12 个月。因此 Type 2 的说服力更强：控制措施是在整段时间内接受检验，而不是只看某一天。

ISO 27001 则不同。Schellman 表示，它的产出是一张证书，写明信息安全管理体系（ISMS）的范围，包括覆盖的部门和地点，认证周期为三年，每年复审。

每个客户的要求都不一样，所以要尽早问清对方安全团队需要哪类证据。

SOC 2ISO 27001
发给客户的是什么一份附有 CPA 意见的报告一张证书
回答的问题组织是否做到了它承诺的事？信息安全管理体系是否通过认证？
发送前要核对什么是 Type 1 还是 Type 2，是否仍在有效期内ISMS 范围是否覆盖你即将部署的系统

先发报告，再填表格

别打开文件就从第 1 行开始填。安全合规咨询公司 Agency 建议先发 SOC 2 报告，因为买方有时会接受用它代替整份问卷。这家公司有商业利益在其中，所以把这当作一种可能，而不是保证。

同一来源称，云安全联盟（Cloud Security Alliance）的 CAIQ 约有 260 道题，分属 17 个领域。它还估计，一份有效期内的 SOC 2 Type II 报告可直接回答约 60-70% 的 CAIQ 问题。

按这个估算算一下：260 的 60% 是 156 题，70% 是 182 题。剩下需要自己写的大约是 78 到 104 题，而不是 260 题。

你手上的实际数字可能不同，但思路成立：一份长问卷，其实是“已有证据的部分”加上“仍是空白的部分”。第一步就是把两者分开。

一个完整的例子

假设你是一名 FDE，正在为一家银行部署一个读取信贷档案的 Agent。客户发来了 CAIQ。

回答任何问题之前，先向自家安全团队问三件事：最新的 SOC 2 报告是 Type 1 还是 Type 2？ISO 27001 证书上的 ISMS 范围怎么写？公司是否已有填好的 CAIQ？

第二个问题是 FDE 最该盯紧的。如果你的 Agent 运行在银行的云环境里，或者依赖证书上没有列出的部门或地点，那么证书的范围就覆盖不到你即将做的工作。不加说明就把证书发过去，日后可能被视为虚假陈述。

接下来，给表格里的每一行打上三个标签之一：“报告已覆盖”（注明引用报告的哪一节）、“答案库已有”、“需要新写”。最后一组的每个答案都套用固定模板：

问题：[客户的原题，一字不改]
回答：是 / 否 / 部分
说明：[1-2 句，不写营销话术]
证据：[SOC 2 报告章节、策略名称、配置截图]
范围：[适用于哪个系统/环境]
负责人：[由谁确认这条答案]
最后更新：[日期]

“范围”和“负责人”这两栏，正是 FDE 发挥作用的地方。你了解真实的部署架构，安全团队了解策略。一个写清范围的“部分”，远比一个含糊的“是”更可信。

以上面的银行项目为例，假设信贷档案存放在银行的云上，一条填好的答案可能是这样：

问题：客户数据是否进行静态加密？
回答：部分
说明：公司环境中的数据已做静态加密。信贷档案存放在银行的云上，遵循银行的加密配置。
证据：最新 SOC 2 Type 2 报告的加密章节；项目存储配置截图
范围：公司环境；不含银行的云
负责人：安全负责人确认，项目 FDE 起草
最后更新：[最近一次复核日期]

客户安全团队一看就知道：哪部分归你们公司负责，哪部分归他们自己，以及该翻报告的哪一页去核实。他们不需要再发一封邮件来问。

按主题建答案库，以及旧答案库的代价

做过几份问卷后你会发现，同一个点会被换着法子问：CAIQ 一种问法，SIG 一种问法，银行自己的模板又是第三种。

因此，答案库应按主题组织，比如访问管理、加密、日志、事件响应，而不是按框架。这样，一条关于访问管理的答案可以同时用在三种问卷上。

但答案库也有隐患。同一来源提醒，过时的答案库比没有答案库风险更大。

设想你粘贴了一条在公司更换基础设施供应商之前写的答案，客户据此签了合同。从那一刻起，这条错误答案就成了躺在客户档案里的一项承诺；真相暴露时，你们公司可能被认为违背了对客户的承诺。

所以答案库里的每一条都需要负责人和复核日期。

在客户开口之前先行一步

Drata 指出，问卷对本就人手紧张的安全团队是一种负担。因此有些公司会主动把填好的标准问卷发给重要的潜在客户，先回答那些常见问题。

据 Drata 介绍，主动分享这些文件既能节省时间，又能通过展示透明度建立信任。

如果公司还什么都没有，CSA STAR Level 1 是一个低成本的起点：它是基于 CAIQ v4 的自评估，免费，并公布在云安全联盟的注册库上。

把报告、证书、填好的 CAIQ 和项目的数据流图打包成一份材料，在项目启动会上发出去。

会被打回来的错误

第一个错误：客户需要看到控制措施长期有效，你却发了 Type 1。第二个错误：发 ISO 27001 证书前没对照真实系统核对范围。第三个错误：回答“是”却不附证据，迫使客户追问，又多一轮邮件往来。

还有一个要避免的错误：FDE 为了省时间独自作答。你了解系统，但安全承诺是整个公司的承诺。拿不准的地方，写“部分”并注明范围，再交给有权限的人确认。

如果你想转做 FDE，这项技能值得写进简历，因为安全评审花的时间可能比找到合适的人还长。看岗位描述时，留意“security review”“vendor assessment”或“SOC 2”这类字眼。

简历上要写具体成果，比如你如何对一份问卷做分类、把评审周期缩短了多少，而不是只写“熟悉安全”。

下次收件箱里再出现一张长表格，别从第一行开始。先弄清已有哪些证据、范围覆盖到哪里，再处理剩下的空白。
