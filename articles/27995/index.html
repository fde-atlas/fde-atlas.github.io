Enterprise AI truly entering production is not about removing humans entirely, but about building "machine auto-approval, second-tool verification, human confirmation" into a quantifiable tiered pipeline — 2026-08-07

Original title: 企业 AI 真正进入生产，不是把人工全部拿掉，而是把「机器自动通过、第二工具复核、人工确认」做成可量化的分层流水线 — 2026-08-07

Today's Verdict

A tool question often mis-framed as "is the accuracy rate high" becomes a production system problem in real enterprise settings: a receipt OCR project at a chain restaurant enterprise ran full evals on 22,863 recognition items extracted from 344 images — 19,022 items qualified as machine auto-pass candidates (83.20%), while 3,841 items required human review (16.80%).

The key is not claiming 83% automation, but establishing a three-stage acceptance process at the same time: main engine full processing → second tool cross-checking → human confirmation of high-risk conflicts. This is exactly the on-site value of an FDE: first establish a same-standard baseline, then select the main engine, use a second tool to handle risky items, and finally write the human-takeover boundary into the process.

Key Signals

Enterprise OCR full evals: three-stage production acceptance of 22,863 recognition items

  • Source: FDE on-site enterprise practice
  • A receipt recognition project at a chain restaurant enterprise completed full evals: 344 images were broken down into 22,863 recognition items. The main tool (RapidOCR) judged 15,187 items as clear, and 7,676 items went to the second tool (PaddleOCR) for review; the two tools agreed on 3,835 items, disagreed on 3,714 items, and the second tool produced no output for 127 items. In the end, 19,022 items were machine auto-pass candidates (83.20%), and 3,841 items were kept for human review (16.80%). Accuracy on samples with existing human ground truth was 276/291, i.e., 94.85%.
  • Why it matters: Enterprise AI cannot report just one "accuracy rate." This case shows the six metrics an FDE should record simultaneously: processing coverage, field accuracy, auto-pass rate, dual-tool conflict rate, human review rate, and per-item review time. 83.20% is a screening pass rate, not the true accuracy rate over the full set — confusing these two numbers is the most common acceptance trap in enterprise AI projects.

Qwen adds thinking research, scheduled tasks, and office assistant entry points

  • Source: Qwen App official | Original link
  • Qwen was updated on August 7, adding capabilities such as thinking research, scheduled tasks, office assistant, and voice calls, and supporting Qwen3.8-MAX. Office agents are moving from one-off Q&A toward persistent tasks and dedicated workstations.
  • Why it matters: New entry points lower the barrier to use, but enterprise deployment still needs identity management, data scope, task trigger rules, failure alerts, and human-takeover mechanisms. Product entry updates do not equal enterprise customer adoption.

Agent Plugins 1.0.0: a unified packaging standard for Skills, tools, and agent plugins

  • Source: Google Developers Blog | Original link
  • Agent Plugins 1.0.0 was released on August 6, with participants including Google, Amazon, Microsoft, and others, aiming to describe and distribute the Skills, tools, and related resources agents need via a unified plugin package.
  • Why it matters: This means an FDE's replicable deliverables are no longer just prompt files, but standardized plugin packages with versions, dependencies, permissions, and test instructions. Project experience that cannot be packaged, versioned, and regression-tested cannot be replicated across customers. This is an infrastructure signal of FDE upgrading from "individual craft" to "engineering delivery."

Implications for FDE practitioners

  • Enterprise OCR acceptance must list six metrics separately: coverage, field accuracy, auto-pass rate, dual-tool conflict rate, human review rate, and per-item review time. Reporting only one "accuracy rate" is irresponsible to the customer.
  • Human review is not an automation failure: The 16.80% human review is an explicit safety cost of high-risk processes. Amounts, long digit strings, and handwritten fields cannot be auto-approved based on model confidence.
  • Package project experience into versionable assets: Tool combinations, threshold configurations, field risk levels, review rules, and test samples — these should be packaged into FDE plugins reusable across customers, not scattered in chat logs.
