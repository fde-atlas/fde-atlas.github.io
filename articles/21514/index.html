Summary

A LayerX talk by Masanori Onda, Lead FDE of the Ai Workforce business, on how the company runs its forward deployed engineering practice. FDEs deeply study each customer's domain—reading practical manuals, documents, and regulations—then build AI Workflows on the Ai Workforce platform, reusing existing features to avoid reinventing wheels per client. FDEs also commit code to the product itself, following the same process as the platform team. Workflow construction, once done manually in about two weeks, is now automated with Coding Agents: they generate initial workflows from exemplars, absorb exception cases into a continuous improvement loop, and are constrained by declarative harnesses that check domain requirements. Remaining challenges include avoiding local optima, huge token consumption in long-running agents, test bloat, and the difficulty of defining good harnesses, with hard-to-rule cases falling back to LLM-as-a-Judge at added cost.

Key points

  • FDEs must understand customer domain, stakeholders, and regulations before delivering value.
  • They reuse Ai Workforce features to avoid reinventing wheels per customer.
  • FDEs also develop missing product features, using the same process as the platform team.
  • Coding Agents now build and iteratively improve workflows from exemplars and real cases.
  • Open issues: local optima, token costs, harness design, and LLM-as-a-Judge overhead.
