Private-Deployment-Gateway

Original title: Private-Deployment-Gateway

FDE中国社区 · 2026-07-12 · 4 min read

Summary

This article documents Private-Deployment-Gateway, a skill package (v1.1, maturity: usable) from the FDE China community for delivering AI systems in environments where public cloud is not an option: government and enterprise private deployment, domestic (xinchuang) hardware requirements, data that cannot leave the customer's domain, and moving PoCs to production. It proposes a three-layer path: quick validation with out-of-the-box tools like Dify or MaxKB, small-scale customization, then an engineering scaffold built on FastAPI with a gateway and monitoring. An AI Gateway handles unified authentication, model routing, auditing, rate limiting, and content safety. The package defines stage gates (production requires evaluation.md metrics of at least 80%), role interfaces between FDE, AIBP, business owners, and IT/security, and deliverables such as architecture diagrams, gateway configs, launch checklists, and runbooks. It warns against common mistakes like putting PoC tools directly into production or skipping gateway auditing.

Key points

  • Targets private deployment, domestic hardware (xinchuang), data-sovereignty, and PoC-to-production scenarios.
  • Three-layer path: Dify/MaxKB validation, light customization, then FastAPI-based engineering scaffold.
  • AI Gateway centralizes authentication, model routing, audit, rate limiting, and content safety.
  • Production gate requires evaluation.md metrics of at least 80%.
  • Deliverables include architecture diagrams, gateway configs, checklists, and runbooks.

FAQ

Q1: When executing [Private-Deployment-Gateway], how do you avoid "putting PoC tools directly into production"?

A: Follow the README methodology step by step and showcase interim deliverables in the weekly Demo; if PoC materials are incomplete, first produce a "pending validation list" before proceeding.

Q2: What additional constraints apply in private deployment/Xinchuang/MLPS environments?

A: Clearly specify the deployment model in the prompt constraints section; when data must remain on-premises, domestic components, or audit logs are involved, reference Private-Deployment-Gateway and RBAC-Audit accordingly.

Q3: What if the division of responsibilities with AIBP is unclear?

A: Return to the AIBP-Collaboration-Playbook to update the RACI; AIBP is responsible for Ground Truth and business acceptance, while the FDE is responsible for deliverable technical assets.

Q4: How to transition from a passed PoC to Beta/production?

A: Mark the next-stage Skill in the deliverables (e.g., RAG-Evaluation→Private-Deployment-Gateway→FDE-Adoption-Growth), and trigger the launch gate via the checklist.
