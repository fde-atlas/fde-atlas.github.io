Agent Engineer vs AI Engineer vs ML Engineer

Zarif Automates · 2026-09-26 · 8 min read

Summary

Drawing on live job postings opened September 26, 2026, this article separates three frequently confused roles. An ML engineer is judged on models trained on company data; an AI engineer on product features built on foundation models; an agent engineer on what happens when a model takes actions—tools, guardrails, evals, and recovery. Comparing postings from Ramp, WRITER, Sierra, Anthropic, Scale AI, and others, it shows how titles blur (AI engineers building agents, agent roles that are really platform or customer-facing work) and offers a signal table—verbs, skills, data, failure modes, team names—for reading postings. It also lists posted salary ranges and maps entry paths from backend, full-stack, and data science backgrounds.

Key points

  • ML engineer owns the model; AI engineer owns shipped features; agent engineer owns model actions.
  • Agent roles split into product-facing and platform work, like Sierra Agent Runtime and Anthropic Claude Managed Agents.
  • Ramp's paired postings show the clearest contrast: foundation-model features versus in-house fraud models.
  • Titles are unreliable; judge postings by verbs, skills, data types, and failure modes.
  • Posted ranges include Anthropic Staff+ at $405K–$485K; Ramp's two roles are the fairest comparison.

What agent, AI and ML engineers each own, and how to tell which job a posting really describes, read from live postings in September 2026.

Ramp posts an Applied AI Engineer job and a Machine Learning Engineer job. Both ship to production. Both want backend skills. Both mention AI.

They're different jobs. One builds product features on top of big general-purpose models someone else trained. The other builds a model from the company's own data to catch fraud.

Add "Agent Engineer" to the mix and it gets blurrier. Here's the simplest way to keep them apart. An ML engineer is judged on the model. An AI engineer is judged on the product feature built around a model. An agent engineer is judged on what happens when the model is allowed to take actions. Reading a posting for which of those it cares about tells you more than the title does.

The postings compared here were opened on September 26, 2026. Roles close and ranges change, so open the link before relying on any detail.

Agent engineer: owns what the model is allowed to do

Agent engineering postings talk about actions, tools and testing more than about models. The work comes in two kinds: building agents for a product or a customer, and building the platform other agents run on.

On the product side, Harvey's Senior Software Engineer, Agents asks the engineer to "design environments and actions for agentic professional work, make model selection decisions, manage context windows, create optimal tools, and develop evals." Sierra's Software Engineer, Agent is responsible for "building, tuning, and evolving AI agents in production environments." Scale AI's Frontier Agents Engineer (Applied AI) names "agent guardrails, fallback strategies, tracing, monitoring, and evaluation pipelines."

On the platform side, Sierra's Software Engineer, Agent Runtime sits in platform engineering and works on "the orchestration engine, runtime, and primitives that define how agents reason, take actions, and interact with users and systems." Anthropic's Staff+ Software Engineer, Claude Managed Agents designs "durable session and event storage, sandbox orchestration, streaming, scheduling, and multi-tenant isolation." That's large-scale systems work, and the posting asks for at least eight years of it.

What these postings share is a worry about what goes wrong after the model decides. WRITER's Software engineer, agents puts it plainly: "Ensure reliability, monitoring, and observability for all agent components."

Anthropic's own guide, Building effective agents, draws the line this way. In a workflow, code decides each step. In an agent, the model directs its own steps and picks its own tools. An agent engineer decides where that line sits and makes the result safe to run.

The agent engineer career guide breaks the work into parts, with a portfolio project to practice on.

AI engineer: ships features built on foundation models

AI engineer postings are broader. The engineer plugs models into a product and ships the result. Agents are one possible result among several.

Ramp's Applied AI Engineer asks the engineer to "ship full-stack AI projects end to end" and wants "a track record of working on full-stack AI projects, particularly those involving production use cases of LLMs." The same posting also covers "components for AI infrastructure, supporting production-level inference and fine-tuning" and internal tools for other engineers. The weight is on range and shipping.

WRITER's AI engineer reports to the head of AI engineering and will "drive the development of intelligent agents and AI-powered features." It also asks for PyTorch, TensorFlow or JAX and "MLOps tools for managing the AI lifecycle." That's the overlap in one posting: agents are part of the job, and so is model tooling that an agent engineer posting rarely mentions.

The practical difference from an agent engineer is how deep you go on one question. An AI engineer is judged on whether the feature works for users. An agent engineer is judged on whether the actions the model takes are correct, allowed, and possible to recover from when something breaks.

The AI engineer career guide covers the broader role, with a project on finding documents and testing answers.

ML engineer: owns the model

ML engineer postings start from data. The engineer trains, tests and deploys models for one specific problem, and the model itself is the product.

Ramp's Machine Learning Engineer sits in the data department and works with fraud engineering. The posting asks the engineer to "prototype and productionize machine learning models and rules-based systems to protect Ramp and its users from fraud." It wants "strong python experience (numpy, pandas, sklearn, pytorch etc.)" and "prior experience deploying Machine Learning models to production."

Put that next to Ramp's Applied AI Engineer posting. Both ship to production, and both need backend skills. The ML engineer works with statistics, feature data and a model the company owns. The applied AI engineer works with foundation models someone else trained. Neither posting mentions what an agent is allowed to change or how approvals work.

Where the titles blur

Three patterns come up often enough to watch for.

  • The AI engineer who builds agents. WRITER's AI engineer posting includes "intelligent agents" in its scope. If most of the bullets are about tools, actions and testing, prepare for an agent engineering interview.
  • The agent engineer who's really a platform engineer. Anthropic's Claude Managed Agents and Sierra's Agent Runtime postings are platform jobs. Knowing agents matters, but the interview will test storage, keeping customers separated, and what breaks at scale.
  • The agent engineer who works with customers. Decagon's Senior Software Engineer, Agent Product will "integrate them at scale with large enterprise-grade customers." That leans toward forward deployed engineering, which the FDE vs solutions architect comparison covers.

The exact title "Agent Engineer" is still rare. On the job boards checked for this piece, Scale AI's Frontier Agents Engineer and Elastic's Agentic AI Engineer came closest. Most employers post "Software Engineer" with an agents team name attached.

How to tell which one a posting really is

Read for these signals before you trust the title. Most postings mix a little of each, so count which column wins.

Named skillsTool calling, context management, eval harnesses, tracingLLM APIs, full-stack frameworks, cloud platformsStatistics, sklearn, PyTorch, feature engineering
Data it works withTraces, tool results, task outcomesPrompts, documents, user feedbackLabeled datasets, features, model metrics
Failure it worries aboutA wrong or unauthorized action, a stuck loopA bad answer or a slow featureDrift, false positives, a model that stops generalizing
Team nameAgents, agent platform, agent runtimeApplied AI, AI productData, ML platform, a domain team like fraud

If the posting still leaves it open, ask on the first call:

  • Does the model in this product take actions that change records, or does it only return text?
  • Who owns the test set, and how do you measure agent quality today?
  • Does the team train or fine-tune models, or only use hosted ones?
  • What broke in production last quarter, and who fixed it?

Which one fits your background

If you come from backend or large-scale systems work, agent engineering is the closest step, especially the platform side. The gap is testing: learning to measure a task whose output changes from run to run.

If you come from product or full-stack engineering, AI engineering is the natural way in, and agent work is a specialty inside it. Start with one feature, then add one tool the model can call.

If you come from data science or statistics, ML engineering uses what you already have. Moving to agent work means learning to run a service: logins and permissions, retries, and writes that are safe to repeat.
