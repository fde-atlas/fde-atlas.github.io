PII Handling and Redaction

FDE Interviews · 2026-06-14 · 1 min read

Summary

This lesson from FDE Interviews covers handling personally identifiable information in AI systems. PII enters through three channels: prompts sent to model APIs, debugging logs, and stored evaluation traces. The recommended approach is to detect and redact personal data before it crosses any of these boundaries, then minimize, encrypt, access-control, and expire whatever must be retained. It flags logging raw prompts as the most common compliance failure in regulated industries. Related practice questions compare detection methods (regex, entropy, NER, external APIs), cover redaction design across four LLM pipeline entry points, gateway-versus-application-layer trade-offs, GDPR implications per API call, and customer scenarios like CISO security questions.

Key points

  • PII enters AI systems via prompts, logs, and eval traces
  • Redact before data crosses any boundary
  • Retained data needs minimization, encryption, access control, expiry
  • Logging raw prompts is the top compliance failure in regulated industries
  • Practice covers detection methods, pipeline entry points, and GDPR

Personal data leaks into AI systems through three doors: the prompt you send a model API, the logs you keep for debugging, and the traces you store for evaluation. Handling it means detecting and redacting personal data before it crosses any of those boundaries, then minimizing, encrypting, access-controlling, and expiring whatever you must keep. In regulated industries, logging a raw prompt is the single most common compliance failure.
