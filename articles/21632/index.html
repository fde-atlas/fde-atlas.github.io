Summary

Japanese firm DeFactory offers a "security FDE" service that goes beyond detection: instead of selling scanners, its engineers embed in client teams and turn existing diagnostic reports and scan results into prioritized, implemented fixes. A sample funnel narrows 3,000 scan findings to 50 triaged items and delivers 30 tested pull requests. Coverage spans three areas—vulnerabilities, supply chain (dependency upgrades, SBOM generation, lockfile pinning, secret rotation), and generative AI governance (RAG access control, AI asset registers, agent permission design). AI drafts fixes, but humans review everything and clients retain final approval. An initial trial runs 2–4 weeks, with spot engagements accepted and pricing quoted by scope.

Key points

  • No tool sales; builds on clients' existing scanners and diagnostic reports.
  • Example funnel: 3,000 findings triaged to 50, yielding 30 tested PRs.
  • Covers vulnerabilities, supply chain, and generative AI governance.
  • AI drafts fixes; human review mandatory, client approves releases.
  • 2–4 week trial entry, spot engagements and custom quotes available.

VALUE

We step into your team and take on the work that tends to stall after findings are reported. We deliver the following six values.

Deciding | | | | |

Diagnostic firm reports, results from multiple scanners, and AI diagnostic findings are consolidated into a single priority list, with "what to fix this month" and "why not to fix" clearly documented.

  • Consolidating findings from different sources into a single list
  • Filtering by exploitation history, external exposure, asset criticality, and whether the affected code is actually used (reachability)
  • Recording items that can't be fixed immediately with reasons and deadlines

Fixing | | | | |

Remediation progresses with tests and impact verification. The fear of "breaking things by fixing" decreases, and stalled work starts moving.

  • AI-generated drafts reviewed by humans before implementation
  • Adding regression tests
  • Mapping impact scope and preparing rollback procedures

Deploying

We work alongside you through review requests, change approvals, and release scheduling. Deployment decisions and approvals remain with your company.

  • Organizing changes into review-friendly form
  • Preparing change requests
  • Coordinating release plans

Verifying continuously | | | | |

Post-fix re-verification and mechanisms that stop similar findings at the source keep your systems in a fixed state.

  • Re-scanning and regression checks
  • Integration into CI/CD
  • Consolidation into shared components for batch remediation of similar findings

Explaining

With remediation history and SBOMs in place, you can answer partner checklists and audit inquiries with facts.

  • Organizing remediation history
  • Creating SBOMs and handling submissions
  • Building the basis for checklist responses

Generative AI | | | | |

We establish the infrastructure and rules for safe generative AI use, all the way through post-diagnostic implementation.

  • Access control for internal RAG and a closed internal AI platform
  • Usage log auditing and AI asset inventory
  • Usage policies and approval workflows

WHY DEFACTORY

HOW WE WORK

Vulnerability and attack surface management, and application/supply chain work, proceed as follows.

STEP 1

Finding | | | | |

We take in your existing scan results and diagnostic reports, normalize the formats, and consolidate them into a single list.

STEP 2

Narrow down

STEP 3

Fixing | | | | |

STEP 4

Iterate

Even when new issues arise, we leave behind a process and workflow that lets you handle them the same way.

SAFETY

Source code and diagnostic results are confidential information. Before starting work, we clarify the scope of handling in the contract.

Operational policies

Access rights are limited to the minimum necessary for the work.

We keep records (logs) of the work in a form your company can review.

When processing code or diagnostic results with an LLM, we obtain your company's consent in advance. We use services configured not to use data for training, and where necessary, work in a closed environment.

All fixes generated by AI are always reviewed by a human.

Confidentiality, scope of responsibility, and acceptance criteria are agreed upon before the contract.

Scope of work

Fixes come with re-verification results attached as deliverables. However, we do not guarantee protection against all attacks.
