Today's Judgment

Today's core story is not the model leaderboards, but a clear dividing line: the model layer is rapidly getting cheaper and faster, while the truly scarce assets on the enterprise side are becoming business test sets, permission governance, and failure replays.

A chain enterprise's HR knowledge base completed a question-by-question review of 1,000 real pages—evals no longer just check "does the answer look right," but verify the text, tables, images, and download buttons on the page; on the same day, DeepSeek V4 Pro officially launched with native Responses API support, and Google released Gemini 3.7 Flash at half the price. The long-term value of an FDE lies not in picking a model for the client once, but in preserving the same business test set, risk boundaries, and outcome metrics over the long term—models can be swapped, but the test set must not be lost.

Key Signals

Enterprise knowledge base acceptance upgraded: question-by-question review of 1,000 real pages, parameter comparison enters a verifiable stage

  • Source: FDE on-site enterprise practice
  • The HR knowledge base testing of a chain restaurant group entered its second round: two independent test subjects used the same batch of 500 questions, verifying a total of 1,000 actual answers, with 0 page read failures. The review method was upgraded from "keyword matching" to question-by-question verification of text, lists, tables, images, download buttons, and file links. In this round, test subject A averaged 9.77 points and B averaged 9.60 points, a difference of only 0.16 points.
  • Why it matters: This demonstrates the key leap in enterprise knowledge base acceptance—from "does the answer look right" to "is the page complete, can the user get things done, and can failures be pinpointed." Same-question inputs, independent subjects, page-by-page evidence, and version records matter more than a single high score. But be clear-eyed: the average score is an internal scoring standard and cannot replace error classification, real employee adoption rates, human handoff rates, and hours saved. The five-layer evidence chain for an enterprise knowledge base is: same-question inputs → complete pages → task outcomes → failure classification → real adoption—the first two layers prove the system is testable, while the last two prove production value.

DeepSeek V4 Pro officially launches: Agent foundation with native Responses API and Codex support

  • Source: DeepSeek official | Original link
  • DeepSeek officially launched V4 Pro on August 13, with the App, web, and API updated simultaneously; the API natively supports the OpenAI Responses API format and is adapted for Codex, supporting three reasoning effort levels: low/high/max. Officially announced scores: Terminal Bench 2.1 at 87.9 and Toolathlon-Verified at 74.1; the new off-peak pricing takes effect on August 17.
  • Why it matters: Standard interfaces greatly reduce the cost of switching models—enterprises should decouple model names from process rules so the foundation layer is replaceable. But interface compatibility cannot replace business regression testing: before switching models, you must compare quality, latency, tool call success rates, human takeover rates, and total cost using the same task set.

Google Gemini 3.7 Flash released: price halved, premium on general-purpose models continues to compress

  • Source: Google DeepMind | Original link
  • Google DeepMind released Gemini 3.7 Flash on August 13, positioned as a coding and agentic work model; priced at $0.75 per million input tokens and $3.75 for output, half the previous Flash generation.
  • Why it matters: DeepSeek strengthens Agent interfaces and off-peak pricing, while Google cuts prices directly—two signals on the same day show that the decision unit for enterprise model selection should shift from "token unit price" to "cost per qualified task": model price → first-pass success rate → failure reruns → tool calls → human review → final cost per qualified task. Token unit price is only a cost line item; a cheap model that fails on the first try may cost more overall.

Implications for FDE Practitioners

  • Test sets are a longer-lived asset than models: Models are updated and repriced monthly, but an enterprise's business test sets, scoring templates, and failure sample libraries can be reused across models. The most valuable part of an FDE's delivery is not "which model was integrated," but this verifiable acceptance system.
  • Acceptance checks pages, not just text: Enterprise knowledge base answers often contain tables, images, and download links—if any element is missing, employees cannot get things done. Page-by-page verification should become the standard practice.
  • After the overall average score, track four numbers: Top error types, count of severe errors, divergent questions between the two test subjects, and real employee task success rates. An average score of 9.77 is not grounds for launch—the error distribution is.
  • New models uniformly go through "same-task replacement testing": Record quality, tool call success rate, latency, price, failure reruns, and human review costs simultaneously, and make decisions based on cost per qualified task.
