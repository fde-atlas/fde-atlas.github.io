AI Forward Deployed Engineer Skills: RAG, Evals & Prompts

FDE India · 2026-11-13 · 10 min read

An AI forward deployed engineer in India is expected to build working LLM systems for customers, not just call an API. Across eight India FDE listings from 2026, every one asks for AI agents or tool calling, seven name RAG, six ask for prompt design, and five ask you to run evals. Fine-tuning, the skill many people study first, shows up in only two.

This guide explains each of those skills the way the listings use them, what “good enough” looks like for an interview, and one mini-project for each that you can finish in a weekend or two.

Four are marked closed (Sarvam AI’s FDE role, Nanonets, evnek and Google Cloud’s GenAI FDE role), and both RevRag AI roles say applications are opening soon. We include closed roles because they show how well-known AI employers define the job. A skill counts only if the listing names it.

Skill 1: Building agents that call tools

All eight listings ask for agents, agentic workflows or tool calling in some form. Prodigal wants FDEs to build LLM-powered AI agents, including voice agents. Nanonets asks for agentic workflows and agent orchestration. RevRag AI’s FDE role names tool calling, system prompts and structured outputs together.

Most listings don’t name a framework. The ones that do:

  • Sarvam AI (FDE): LangGraph, LlamaIndex, Google ADK and MCP servers.
  • Google Cloud (GenAI FDE): LangGraph, CrewAI and MCP servers, plus orchestrating model calls with external tools.
  • RevRag AI (both roles): LiveKit Agents and Pipecat as bonus skills, because its agents talk to customers by voice.

LangChain, often treated as the default, was not named in any of the eight. The lesson: learn how tool calling works underneath (a model returns a structured call, your code runs it, the result goes back into context), then pick one framework. Employers care that you can debug the loop, not which library you used.

What good looks like: you can explain why an agent called the wrong tool, and fix it with a better tool description, a schema change or a guard in code.

Mini-project: an agent that answers “where is my order?” by calling two real or mocked APIs (an orders API and a shipping API), returns structured JSON, and refuses politely when the order ID is missing. Expose one of the tools as an MCP server to match the Sarvam AI and Google asks.

Skill 2: RAG that works on messy customer data

Seven of eight listings name RAG. Prodigal and Nanonets both ask for RAG pipelines; evnek’s listing pairs RAG with AI agents as the core of the role; Google Cloud’s GenAI role names retrieval-augmented generation directly. Sarvam AI’s software engineer role is the one that doesn’t say “RAG”, but it asks for vector databases and semantic search, which is the same building block.

For an FDE, RAG is rarely a clean demo. The customer’s documents are PDFs, scanned forms, wikis and tickets, often in more than one language. Your job is to get good answers out of that.

What good looks like: you know where RAG usually fails (bad chunking, missing metadata filters, retrieval returning the wrong section) and you can show how you measured retrieval quality separately from answer quality.

Mini-project: a question-answering assistant over 50–100 real public documents, such as RBI circulars or your state’s government orders. Store embeddings in any vector store, add a metadata filter (date or department), and return the source passage with every answer.

Skill 3: Prompt design for production, not chat

Six listings ask for prompt engineering or prompt design. RevRag AI is the most specific, asking for practical prompt engineering for LLM agents covering system prompts, tool use and structured outputs, plus conversation design. Prodigal asks FDEs to design and optimise prompts; Sarvam AI’s software engineer role asks you to learn and apply prompt engineering techniques. Sarvam AI’s FDE role uses a different phrase, “context engineering”, for the same idea: deciding exactly what the model sees.

What good looks like: prompts kept in version control, tested against a fixed set of inputs before every change, and outputs forced into a schema your code can parse.

Mini-project: take your RAG assistant and write three versions of its system prompt. Run all three against the same 30 questions and keep a table of which version won and why. That table feeds straight into Skill 4.

Skill 4: Evals, the skill that separates FDEs from demo builders

Five of eight listings ask for evaluations. Google Cloud’s GenAI FDE role asks you to build evaluation pipelines. Sarvam AI’s FDE role asked engineers to set up evals and to bring an evals mindset. Prodigal asks for evaluation frameworks. RevRag AI’s senior role asks for evaluation-driven iteration and judges success by measurable accuracy, latency and conversion gains.

Evals are how a customer is convinced to switch an AI system on. An FDE who can say “accuracy on our 200-question test set went from 71% to 88%, and here is what changed” is far more useful than one who says “it looks better now”. We covered how evals show up as a job responsibility in our guide to FDE KRAs at AI startups.

What good looks like: a fixed test set, a clear metric per task (exact match, a rubric scored by a model, or human grading for a sample), and a habit of running it before every release.

Mini-project: write 50 question–answer pairs for your RAG assistant, including 10 questions it should refuse. Score every prompt or retrieval change against them and plot the score over time.

Skill 5: Monitoring, guardrails and voice

Five listings ask for production monitoring, observability or guardrails. Google Cloud’s GenAI role names observability frameworks and granular tracing; evnek asks for model observability; Prodigal includes monitoring deployed agents; RevRag AI asks FDEs to configure tools and guardrails. This is the part of the job that starts after go-live.

Voice AI also appears in five listings: both RevRag AI roles, Prodigal, and both Sarvam AI roles. If you are aiming at Indian AI startups selling to banks, lenders or customer-support teams, a voice agent project is a strong signal. Read Sarvam AI’s company page for more on how it hires.

Mini-project: add logging to your agent (every prompt, tool call, latency and cost), a simple dashboard, and one guardrail, such as blocking answers that mention an account number.

Fine-tuning and Python: where they fit

Only two listings mention fine-tuning: Google Cloud’s GenAI role, and RevRag AI’s senior role, which lists LoRA or QLoRA fine-tuning as a bonus. Most FDE work is getting existing models to perform on a customer’s data, so learn fine-tuning after the other five skills, not before.

Python is a different story. Six of eight listings name it: Prodigal wants strong Python and SQL, Sarvam AI asks for Python in both roles, Google asks for three years of Python with ML packages, and RevRag AI asks for strong Python fundamentals. The LLM skills above sit on top of normal software engineering. Our broader guide to the six skill areas Indian employers want from FDEs covers the non-AI side.

How much experience these roles expect

Lowest number of years stated in each listing. Google’s figure is years of Python and ML packages. Listings read November 2026.

The entry point is lower than many assume. Sarvam AI’s software engineer role asks for 1–3 years, and RevRag AI, Prodigal and Nanonets all start at about 2 years. Senior roles at RevRag AI and Sarvam AI start at 4 years, and evnek asks for 5–10.

A 6-week plan to build these skills

  • Week 1 – Tool calling from scratch. Build the order-status agent with a raw model API and no framework, so you understand the loop. Then rebuild it in LangGraph or another framework the listings name.
  • Week 2 – RAG over real documents. Build the document assistant with metadata filters and source citations.
  • Week 3 – Evals. Write the 50-question test set, add refusal cases and record a baseline score.
  • Week 4 – Prompt iteration. Run three prompt versions and two chunking strategies against your evals. Keep the results table.
  • Week 5 – Production basics. Add logging, cost and latency tracking, one guardrail, and deploy it somewhere a recruiter can try it.
  • Week 6 – Tell the story. Write a one-page case study per project: the customer problem, what you built, the metric and how it moved. Use it in interviews; our FDE interview process guide shows where it fits.

Frequently asked questions

What AI skills does a forward deployed engineer need in India?

In eight India FDE listings from 2026, the most common asks were building AI agents with tool calling (all eight), RAG (seven), prompt design (six), Python (six) and evals (five). Production monitoring or guardrails and voice AI also appeared in five listings each.

Do FDEs need to know fine-tuning?

Rarely. Only two of the eight listings reviewed mention it: Google Cloud's GenAI FDE role, and RevRag AI's senior FDE role, which lists LoRA or QLoRA fine-tuning as a bonus. RAG, prompt design and evals come up far more often.

Which agent frameworks do India FDE listings name?

Most listings name none. Sarvam AI's FDE role named LangGraph, LlamaIndex, Google ADK and MCP servers; Google Cloud's GenAI FDE role named LangGraph, CrewAI and MCP servers; RevRag AI lists LiveKit Agents and Pipecat as bonus skills for voice agents. LangChain was not named in any of the eight.

How do I show LLM skills for an FDE job without work experience in AI?

Build small, deployed projects that mirror the listings: a RAG assistant over real documents with an eval set, an agent that calls two or three real APIs, and a monitoring dashboard for it. Write down the metric you chose and how it changed.
