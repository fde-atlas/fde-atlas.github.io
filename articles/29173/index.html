API-Design-Review

Original title: API-Design-Review

FDE中国社区 · 2026-07-12 · 4 min read

Summary

This is a reusable skill package from the FDE China community on API design review for enterprise system integration. It argues that poor API design causes permission vulnerabilities, failed integration testing, and missing audit trails. The review framework covers eight dimensions: contract clarity, idempotency, error codes, pagination, authentication, audit logging, rate limiting, and versioning, with extra FDE focus on agent call stability, timeout retries, and manual fallback. The package defines execution steps, stage gates from PoC preparation to retrospective assetization, and collaboration interfaces among FDE, AIBP, business owners, and IT/security. Four scenarios are covered: agent-to-CRM/ERP integration, Feishu/ticket integration, MCP tool design, and PoC-to-MVP transitions. An illustrative case reports a three-day integration with zero P0 incidents after applying the methodology.

Key points

  • Eight-dimension review framework covering auth, idempotency, error codes, and audit logs.
  • FDE focus: agent call stability, timeout retries, manual fallback.
  • Stage gates from PoC to production with evaluation thresholds.
  • Defined roles and handoffs for FDE, AIBP, business owner, IT/security.
  • Four scenarios: CRM/ERP, Feishu, MCP tools, PoC-to-MVP.

FAQ

Q1: How to avoid "ignoring authentication" when executing [API-Design-Review]?

A: Follow the README methodology step by step and showcase interim deliverables in the weekly Demo; if PoC materials are incomplete, first produce a "to-be-verified list" before proceeding.

Q2: What additional constraints apply in private deployment/Xinchuang/MLPS environments?

A: Specify the deployment model in the prompt constraints section; when data residency, domestic components, or audit logs are involved, reference Private-Deployment-Gateway and RBAC-Audit accordingly.

Q3: What if the division of responsibilities with AIBP is unclear?

A: Return to the AIBP-Collaboration-Playbook to update the RACI; AIBP owns Ground Truth and business acceptance, while FDE owns deliverable technical assets.

Q4: How to transition from a passed PoC to Beta/production?

A: The deliverable annotates the next-stage Skill (e.g., RAG-Evaluation→Private-Deployment-Gateway→FDE-Adoption-Growth), and the checklist triggers the launch gate.
