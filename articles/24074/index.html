TypeScript is a superset of JavaScript developed by Microsoft. By adding static typing and class-based object-oriented programming to JavaScript, it is designed to enable safer and more efficient large-scale application development.

TypeScript alone lacks many features needed for actual application development, such as managing file dependencies, reusing UI components, and abstracting HTTP requests. That's where frameworks come in. A framework can be defined as "a collection of structures, rules, and convenient features that form the skeleton of an application."

Most TypeScript-compatible frameworks fall into one of the following categories.

CategoryMain roleRepresentative examples
Frontend frameworksBrowser UI, state management, routingReact, Angular, Vue.js
Backend frameworksServer-side APIs, database integration, authenticationNestJS, Express, Hono
Full-stack frameworksIntegrating frontend + backend + SSR/SSGNext.js, Nuxt.js, SvelteKit

Combining TypeScript with frameworks enables consistent, type-safe development from frontend to backend. Most of the "bugs noticed only at runtime" that were frequent when writing JavaScript are now detected at compile time.

Related article: If you want to learn more about TypeScript's basic concepts and the benefits of adopting it, also check out What Is TypeScript? A Beginner's Guide to Its Features and Benefits.

1. Early bug detection through type safety

TypeScript's greatest strength is static analysis through types. For example, if you define the types of props passed to a React component, the IDE displays an error the moment you pass a value of the wrong type. Angular adopts TypeScript by default, and type checking also works for service DI and template bindings.

// Example of React props type definition

type UserCardProps = {

  name: string;

  age: number;

  isAdmin?: boolean;

};

const UserCard = ({ name, age, isAdmin = false }: UserCardProps) => {

  return <div>{name} ({age}){isAdmin && " [管理者]"}</div>;

};

With explicit type definitions like this, anyone on the team can tell at a glance "what should be passed to this component."

2. Powerful integration with IDEs and editors

VS Code has excellent compatibility with TypeScript, with completion, navigation, and refactoring working with high precision based on type information. Since frameworks also provide type definition files (.d.ts), you can benefit from code completion including framework-specific APIs.

3. Strong for large team development and long-term maintenance

Because type-based interface contracts exist, API specification mismatches are less likely to occur when multiple people develop in parallel. Also, when reading code years later, type information functions as "documentation," greatly reducing maintenance costs.

Before selecting a framework, you first need to clarify "what you want to build."

Frontend frameworks (client-side) Frameworks for building UIs that run in the browser. They handle state management, component design, routing, and more. Representative examples are React, Angular, and Vue.js.

Backend frameworks (server-side) Frameworks for building HTTP servers, REST APIs, and GraphQL APIs on Node.js. They handle database connections, authentication, validation, and more. Representative examples are NestJS, Express, and Hono.

Full-stack frameworks Frameworks that encompass both frontend and backend. They also integrate features such as SSR (server-side rendering) and SSG (static site generation). Representative examples are Next.js, Nuxt.js, and SvelteKit.

To avoid failure in framework selection, we recommend evaluating along the following 5 axes.

  • Compatibility with TypeScript: The development experience differs greatly depending on whether TypeScript is supported as a first-class citizen or as an afterthought
  • Learning cost: Consider your team's skill level and the time required for onboarding
  • Ecosystem maturity: The size of the library, plugin, and community ecosystem directly affects problem-solving speed
  • Performance: Rendering methods (CSR/SSR/SSG) and virtual DOM implementations affect UX
  • Suitable project scale: The optimal choice differs depending on whether you're starting small or building a large enterprise application

An important takeaway from this table is that Angular and NestJS are TypeScript native. Because these frameworks are designed with TypeScript in mind, you can take full advantage of its type system. On the other hand, React and Vue.js are JavaScript-based, but their type definition files are well maintained, so there is virtually no practical inconvenience.

Overview and characteristics

React is a UI library developed by Meta (formerly Facebook). Strictly speaking, it is classified as a "library" rather than a "framework," but by combining it with surrounding libraries (React Router, Zustand, React Query, etc.), you get a development experience comparable to a full framework.

React's greatest feature is component-based UI building. You define the UI as reusable parts (components) and combine them to build the entire application.

How to combine it with TypeScript

In React, type definitions are provided via the @types/react package. For component type definitions, the following patterns are mainly used.

// Using the FC (Function Component) type

import React, { FC, useState } from 'react';

type CounterProps = {

  initialCount: number;

  label: string;

};

const Counter: FC<CounterProps> = ({ initialCount, label }) => {

  const [count, setCount] = useState<number>(initialCount);

  return (

    <div>

      <p>{label}: {count}</p>

      <button onClick={() => setCount(c => c + 1)}>増加</button>

    </div>

  );

};

useStateのジェネリクス<number>により、countの型がnumberに固定されます。誤ってstring型の値をセットしようとするとコンパイルエラーになります。

Custom hooks + TypeScript

One of React's strengths is custom hooks. Combined with TypeScript, you can add type guarantees to reusable logic.

// Custom hook for data fetching

type FetchState<T> = {

  data: T | null;

  loading: boolean;

  error: string | null;

};

function useFetch<T>(url: string): FetchState<T> {

  const [state, setState] = useState<FetchState<T>>({

    data: null,

    loading: true,

    error: null,

  });

  useEffect(() => {

    fetch(url)

      .then(res => res.json())

      .then((data: T) => setState({ data, loading: false, error: null }))

      .catch(err => setState({ data: null, loading: false, error: err.message }));

  }, [url]);

  return state;

}

Suitable projects

  • Medium to large SPAs (single-page applications)
  • When team members have diverse skill levels
  • When you want to leverage a rich ecosystem of OSS libraries
  • When considering expansion to mobile apps (React Native)

Points to note

State management, routing, form validation, and so on must be chosen and integrated yourself. "High flexibility" also means "the responsibility for design lies with the developer." Unless the team agrees on consistent design principles, the codebase can easily become disorganized.

Angular is a frontend framework developed and maintained by Google. It natively adopts TypeScript, and DI (dependency injection), routing, form validation, and HTTP client functionality are all included in the framework itself.

It has a unique design philosophy called the "Angular Way," with clearly defined roles such as components, services, modules, directives, and pipes. This makes it easier to maintain a consistent codebase even with large teams.

Angular is characterized by heavy use of decorators.

// Service example

import { Injectable } from '@angular/core';

import { HttpClient } from '@angular/common/http';

import { Observable } from 'rxjs';

type User = {

  id: number;

  name: string;

  email: string;

};

@Injectable({

  providedIn: 'root'

})

export class UserService {

  private apiUrl = 'https://api.example.com/users';

  constructor(private http: HttpClient) {}

  getUsers(): Observable<User[]> {

    return this.http.get<User[]>(this.apiUrl);

  }

  getUserById(id: number): Observable<User> {

    return this.http.get<User>(`${this.apiUrl}/${id}`);

  }

}

The @Injectable decorator registers this service with Angular's DI container. Specifying the type via generics on HttpClient's get method guarantees the response type.

Angular form validation (ReactiveFormsModule)

import { Component, OnInit } from '@angular/core';

import { FormBuilder, FormGroup, Validators } from '@angular/forms';

@Component({

  selector: 'app-login',

  template: `

    <form [formGroup]="loginForm" (ngSubmit)="onSubmit()">

      <input formControlName="email" type="email" />

      <span *ngIf="loginForm.get('email')?.errors?.['required']">メールは必須です</span>

      <button type="submit" [disabled]="loginForm.invalid">ログイン</button>

    </form>

  `

})

export class LoginComponent implements OnInit {

  loginForm!: FormGroup;

  constructor(private fb: FormBuilder) {}

  ngOnInit(): void {

    this.loginForm = this.fb.group({

      email: ['', [Validators.required, Validators.email]],

      password: ['', [Validators.required, Validators.minLength(8)]]

    });

  }

  onSubmit(): void {

    if (this.loginForm.valid) {

      console.log(this.loginForm.value);

    }

  }

}

Validation logic is centralized in the component class, and integration with templates is also type-safe.

  • Enterprise systems requiring strict design standards, such as finance, healthcare, and government
  • Development with large teams of 10 or more members
  • Systems designed for long-term maintenance (5+ years of operation)
  • Teams with many developers accustomed to statically typed languages like Java or C#

The learning cost of Angular-specific concepts (modules, decorators, and reactive programming with RxJS) is high, which can be excessive for small projects. In particular, RxJS's Observable pattern is difficult for JavaScript/TypeScript beginners, so you need to carefully assess your team's skill level.

Vue.js is a frontend framework that Evan You started as a personal project and is now developed community-driven. It bills itself as a "progressive framework," allowing gradual adoption—from simply adding it to an existing HTML page with a single script tag, to building a full-scale SPA.

Since Vue 3 (released in 2020), TypeScript support has been significantly enhanced, and combined with the Composition API, it provides a type-safe development experience close to React.

TypeScriptとの組み合わせ方（Composition API + <script setup>）

<script setup lang="ts">

import { ref, computed, onMounted } from 'vue';

type Product = {

  id: number;

  name: string;

  price: number;

  stock: number;

};

const products = ref<Product[]>([]);

const searchQuery = ref<string>('');

const filteredProducts = computed(() =>

  products.value.filter(p =>

    p.name.toLowerCase().includes(searchQuery.value.toLowerCase())

  )

);

const totalValue = computed(() =>

  products.value.reduce((sum, p) => sum + p.price * p.stock, 0)

);

onMounted(async () => {

  const res = await fetch('/api/products');

  products.value = await res.json() as Product[];

});

</script>

<template>

  <input v-model="searchQuery" placeholder="商品を検索..." />

  <p>在庫総額: ¥{{ totalValue.toLocaleString() }}</p>

  <ul>

    <li v-for="product in filteredProducts" :key="product.id">

      {{ product.name }} - ¥{{ product.price }}

    </li>

  </ul>

</template>

<script setup lang=”ts”>を使うことで、TypeScriptとComposition APIが自然に統合されます。ref<Product[]>([])のようにジェネリクスで型を指定でき、テンプレート内の変数にも型チェックが効きます。

Pinia (Vue 3's recommended state management library) and TypeScript

import { defineStore } from 'pinia';

type CartItem = {

  productId: number;

  quantity: number;

  price: number;

};

export const useCartStore = defineStore('cart', {

  state: (): { items: CartItem[] } => ({

    items: []

  }),

  getters: {

    totalPrice: (state): number =>

      state.items.reduce((sum, item) => sum + item.price * item.quantity, 0),

    itemCount: (state): number =>

      state.items.reduce((sum, item) => sum + item.quantity, 0)

  },

  actions: {

    addItem(item: CartItem): void {

      const existing = this.items.find(i => i.productId === item.productId);

      if (existing) {

        existing.quantity += item.quantity;

      } else {

        this.items.push(item);

      }

    },

    removeItem(productId: number): void {

      this.items = this.items.filter(i => i.productId !== productId);

    }

  }

});

Pinia is recommended as the successor to Vuex, works very well with TypeScript, and enables state management with full type inference.

  • Teams with JavaScript experience but new to TypeScript
  • Replacing existing jQuery or Vanilla JS codebases
  • Content-focused websites and mid-sized SPAs
  • Teams where designers or backend engineers also handle some frontend work

Vue 3 introduced major changes from Vue 2, and the coexistence of two styles, the Composition API and the Options API, means you need to be careful about keeping the codebase consistent. Also, while Japanese community resources are abundant, adoption in the English-speaking world is not as widespread as React or Angular, so it may rarely come up as an option for overseas projects.

Next.js is a React-based full-stack framework developed by Vercel. It goes beyond React's limitation of "client-side rendering (CSR) only," allowing you to handle SSR (Server-Side Rendering), SSG (Static Site Generation), and ISR (Incremental Static Regeneration) through a unified API.

Since the App Router (Next.js 13 and later) released in 2023, new design patterns leveraging React's Server Components have become mainstream.

Choosing a rendering approach (TypeScript)

// app/products/page.tsx（Server Component：SSG）

type Product = {

  id: number;

  name: string;

  price: number;

};

// デフォルトでServer Component（サーバーで実行される）

export default async function ProductsPage() {

  // このfetchはビルド時に実行（SSG）

  const products: Product[] = await fetch('https://api.example.com/products', {

    cache: 'force-cache' // SSG

    // cache: 'no-store'   // SSR（毎回取得）

    // next: { revalidate: 60 } // ISR（60秒ごとに再生成）

  }).then(res => res.json());

  return (

    <ul>

      {products.map(product => (

        <li key={product.id}>{product.name} - ¥{product.price}</li>

      ))}

    </ul>

  );

}

// app/products/[id]/page.tsx（動的ルーティング）

type PageProps = {

  params: { id: string };

};

export default async function ProductDetailPage({ params }: PageProps) {

  const product: Product = await fetch(

    `https://api.example.com/products/${params.id}`

Server ActionsによるフルスタックAPI（Next.js 14以降）

// app/actions/createOrder.ts

'use server';

import { z } from 'zod';

const OrderSchema = z.object({

  productId: z.number(),

  quantity: z.number().min(1),

  address: z.string().min(1),

});

type OrderInput = z.infer<typeof OrderSchema>;

export async function createOrder(input: OrderInput) {

  const validated = OrderSchema.safeParse(input);

  if (!validated.success) {

    return { success: false, error: validated.error.flatten() };

  }

  // DBへの保存処理...

  return { success: true };

}

Using Server Actions, you can call server-side processing directly from components without writing API routes in separate files. Combined with validation via zod, this enables type-safe full-stack development.

  • E-commerce sites, media sites, and corporate sites where SEO is important
  • Services that prioritize performance (Core Web Vitals such as LCP and TTFB)
  • Teams that want to leverage their React skills all the way to full-stack APIs
  • Startup MVP development (managing frontend and API in a single repository)

The App Router differs significantly from the Pages Router, and migrating existing Pages Router projects comes at a cost. Also, mistakes in designing the rendering boundaries of Server Components (the placement of 'use client') can cause performance issues, so a solid understanding of the architecture is essential.

NestJS is a TypeScript-native Node.js backend framework. It ports Angular's design philosophy (decorators, DI, modules) to the server side, allowing Angular-experienced developers to transition smoothly. Internally it uses Express or Fastify, and you can switch between them as needed.

Its key feature is a monolithic yet extensible design that supports diverse communication methods such as REST APIs, GraphQL, WebSockets, and microservices.

Example implementation of a basic CRUD API

// user.entity.ts

export class User {

  id: number;

  name: string;

  email: string;

  createdAt: Date;

}

// create-user.dto.ts

import { IsEmail, IsString, MinLength } from 'class-validator';

export class CreateUserDto {

  @IsString()

  name: string;

  @IsEmail()

  email: string;

  @IsString()

  @MinLength(8)

  password: string;

}

// users.controller.ts

import { Controller, Get, Post, Body, Param, Delete, ParseIntPipe } from '@nestjs/common';

import { UsersService } from './users.service';

import { CreateUserDto } from './dto/create-user.dto';

@Controller('users')

export class UsersController {

  constructor(private readonly usersService: UsersService) {}

  @Get()

  findAll(): Promise<User[]> {

    return this.usersService.findAll();

  }

  @Get(':id')

  findOne(@Param('id', ParseIntPipe) id: number): Promise<User> {

    return this.usersService.findOne(id);

  }

  @Post()

  create(@Body() createUserDto: CreateUserDto): Promise<User> {

    return this.usersService.create(createUserDto);

  }

  @Delete(':id')

  remove(@Param('id', ParseIntPipe) id: number): Promise<void> {

    return this.usersService.remove(id);

  }

}

Combined with class-validator, request body validation is performed automatically. ParseIntPipe handles type conversion and validation of URL parameters, so if an invalid ID (such as a string) is passed, it automatically returns a 400 error.

Type-safe implementation of authentication and authorization with Guards

// jwt-auth.guard.ts

import { Injectable, CanActivate, ExecutionContext } from '@nestjs/common';

import { JwtService } from '@nestjs/jwt';

import { Request } from 'express';

type JwtPayload = {

  sub: number;

  email: string;

  role: 'admin' | 'user';

};

@Injectable()

export class JwtAuthGuard implements CanActivate {

  constructor(private jwtService: JwtService) {}

  canActivate(context: ExecutionContext): boolean {

    const request = context.switchToHttp().getRequest<Request>();

    const token = this.extractTokenFromHeader(request);

    if (!token) return false;

    try {

      const payload = this.jwtService.verify<JwtPayload>(token);

      request['user'] = payload;

      return true;

    } catch {

      return false;

    }

  }

  private extractTokenFromHeader(request: Request): string | undefined {

    const [type, token] = request.headers.authorization?.split(' ') ?? [];

    return type === 'Bearer' ? token : undefined;

  }

}

Implementing the CanActivate interface guarantees an implementation that conforms to NestJS's guard type constraints. By also defining the JWT payload with a JwtPayload type, you can reference payload.sub and payload.role in a type-safe manner.

  • Building medium to large-scale REST APIs and GraphQL APIs
  • Systems adopting a microservices architecture
  • When backend and frontend (Angular, React) are developed by the same team
  • When you want to enforce TypeScript's type safety on the server side as well

TypeScript is a language that works particularly well with generative AI tools (GitHub Copilot, Cursor, Claude). The reason is that "type information functions as context for the AI."

In dynamically typed languages like JavaScript, the AI has to infer what values a variable might hold. In TypeScript, on the other hand, type definitions, interfaces, and generics act as a "specification for the code," enabling the AI to provide more accurate code completion and refactoring suggestions.

A concrete example of type definitions improving AI completion accuracy

// Without type definitions (the AI has difficulty deciding what to complete)

const processOrder = (order) => {

  // AIの補完：order.???（何のプロパティかわからない）

};

// 型定義がある場合（AIは正確な補完ができる）

type Order = {

  id: string;

  items: OrderItem[];

  totalAmount: number;

  status: 'pending' | 'processing' | 'shipped' | 'delivered';

  customer: Customer;

};

const processOrder = (order: Order) => {

  // AIの補完：order.status, order.items, order.customer など正確に補完される

};

Defining types carefully dramatically improves the quality of AI tool code generation.

React × Cursor: Speeding up component generation

Cursor is an AI editor that can read the entire codebase as context. By having it reference the type definitions of existing components while generating new ones, you can quickly generate code that fits your project's design principles.

Practical examples:

  • Reference the existing UserCard.tsx and instruct: "Create ProductCard.tsx using the same design pattern"
  • Provide the API response type definitions and instruct: "Write a React Query hook that matches this type"
  • Reference the test files and instruct: "Create useCart.test.ts using the same test pattern"
