16 Domestic Models, Data Classification, Privacy Interception, and AIGC Auditing

Original title: 16 国产模型、数据分级、隐私拦截与 AIGC 审计

FDE中国社区 · 2026 · 3 min read

Summary

This article argues that swapping to domestic Chinese models (DeepSeek, Qwen, GLM, etc.) does not by itself make an enterprise AI system compliant. FDEs must build a full governance chain: data classification with pre-Prompt masking, privacy interception across five stages (input, retrieval, tools, output, logs), AIGC audits, an Agent Registry with L0–L4 autonomy levels requiring human review for high-risk actions, circuit breakers, and policy-as-code. It also provides an industry compliance matrix, a launch gate checklist, and a cross-functional sign-off table covering business, IT, security, data, and FDE roles.

Key points

  • Domestic models alone don't satisfy security review; governance chain is required.
  • Data is classified into four levels; masking must precede model calls.
  • Privacy interception spans input, retrieval, tools, output, and logs.
  • Agents get L0–L4 autonomy tiers with human review and rollback for high risk.
  • Launch gates require sign-off from five roles, not just the FDE.

Chapter Objectives

Understand the domestication, privatization, and compliance requirements in Chinese enterprise AI projects, and design data classification, desensitization, privacy interception, AIGC auditing, and launch gates.

Opening Case: Why "Switching to a Domestic Model" Does Not Equal Compliance

A government and enterprise customer required that the AI system must use a domestic model. The team switched the model API to a domestic vendor and assumed the compliance problem was solved. But the security review kept pressing: Are sensitive fields desensitized before entering the model? Are retrieval results filtered by classification level? Do the logs store the full Prompt? Is there AIGC auditing for generated content? Do high-risk tools have human review and rollback?

A domestic model is only part of the compliance solution, not all of it. What the FDE must design is a complete governance chain: data classification, permission filtering, model routing, privacy interception, audit logs, Agent autonomy levels, and launch gates.

Model Adaptation

Common models in enterprise projects include DeepSeek, Tongyi Qianwen, Zhipu GLM, Kimi, Doubao, Hunyuan, and Wenxin. The FDE should design a model adaptation layer to avoid business code being bound to a single model API.

The adaptation layer should unify:

  • Input and output formats.
  • Error codes.
  • Timeouts and retries.
  • Streaming responses.
  • Structured output.
  • Model version records.

Data Classification

LevelExamplesPolicy
PublicWebsite materials, public policiesCan enter public cloud models
InternalInternal policies, process documentsRestrict access scope
SensitiveCustomer information, orders, financial detailsDesensitization, auditing, permission filtering
CoreTrade secrets, classified documentsPrivatization, approval, strict audit trails

Desensitization should happen before the Prompt is sent to the model, not just in the logs.

Privacy Interception

Five points need to be covered:

  • Input side: user input and uploaded files.
  • Retrieval side: content returned by the knowledge base.
  • Tool side: tool parameters and returned results.
  • Output side: the model's final answer.
  • Log side: record hashes, digests, and risk flags.

AIGC Auditing

Outputs should be checked for:

  • Factual errors.
  • Non-compliant content.
  • Sensitive information.
  • Copyright risks.
  • Discrimination and bias.
  • Improper commitments.

Important business outputs must be traceable to their data sources and generation chain.

Agent Registry and Tiered Autonomy

Agent Registry

The infrastructure for enterprise-level Agent governance, registering:

  • Agent name, version, owner, and status.
  • Bound tool whitelists and knowledge base scope.
  • Associated eval sets and launch approval records.

L0–L4 Autonomy Levels

LevelDescriptionHuman Review Requirement
L0Read-only Q&A, no toolsSampled review
L1Advisory output, no executionHuman review in critical scenarios
L2Low-risk tools (query-type)Human review triggered by anomalies
L3Medium-risk tools (creating drafts)Human review before release
L4High-risk execution (funds, external commitments)Gradual rollout + strong auditing

Circuit Breaker

When the consecutive failure rate, latency, or cost exceeds a threshold, automatically degrade to read-only mode, escalate to a human, or switch to a backup model, to prevent the Agent from continuing to execute in an abnormal state.

Policy-as-code

Write data classification, tool permissions, and approval rules as versionable policies (OPA, custom rule engines, etc.), enforced uniformly at the gateway, tool layer, and Agent orchestration layer.

Industry Compliance Matrix

IndustryAdditional Concerns

The Minimal Closed Loop of Governance Design

数据分级 → 输入拦截 → 权限检索 → 模型/工具调用 → 输出审计 → 人审/回滚 → 日志留痕

If any link in this chain is missing, the system will be blocked during the security review. Especially in tool-calling scenarios, compliance happens not only at model input and output, but also in tool parameters, tool returns, and execution results.

Launch Gate

  • Data sources have been confirmed.
  • Sensitive data has been classified and desensitized.
  • User identity, knowledge base permissions, and tool permissions have been confirmed.
  • The Golden Dataset has passed the minimum threshold.
  • High-risk actions have human review, approval, idempotency, and rollback in place.
  • Model, Prompt, knowledge base, tool, and code versions have been pinned.
  • Logging, Trace, cost, latency, alerting, and auditing have been enabled.

Launch Review Role Table

RoleFocusSignature or Confirmation Required
Business ownerScenario value, trial scope, responsibility boundariesYes
IT / OperationsDeployment, logs, backups, alertingYes
Security / ComplianceData classification, auditing, model routingYes
Data ownerData sources, permissions, updatesYes
FDEArchitecture, evals, tool governance, rollbackYes

The launch gate is not a checklist for the FDE alone, but a cross-functional responsibility confirmation table.

Hands-on Tasks

For your PoC, complete:

  • A data classification table.
  • Desensitization rules.
  • Input/output interception rules.
  • Audit log fields.
  • A launch gate checklist.

Deliverables

  • A data classification plan.
  • A privacy interception policy.
  • An AIGC auditing process.
  • A launch review form.

Common Pitfalls

  • Only switching to a domestic model without redoing the evals.
  • Logs storing full sensitive Prompts.
  • High-risk outputs without human review.
  • Launch gates that only cover technical items, not business responsibilities.

Checklist

  • Do you know which data cannot enter public cloud models?
  • Do you perform permission checks before retrieval and tool calls?
  • Can you answer "who processed what data with which model and when"?
  • Do you have a rollback and human takeover plan?
