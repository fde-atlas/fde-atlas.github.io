A Guide to Cresta's Senior FDE Job Requirements and Interview Preparation

Original title: Cresta 高级 FDE 招聘要求解读与面试准备

Summary

Open Cresta's Senior Forward Deployed Engineer (FDE, AI agent) job posting, published October 13, 2026 for remote candidates in Australia, and you'll see a familiar list: Python, Golang, cloud, DevOps, LLMs, project management.

At a glance, it looks like any other engineering job posting. Read closely, and every line maps to a concrete task to be done on customer systems—even though this is a remote role.

The skills to learn here go beyond Cresta: it's about how to read an FDE job posting—translate each requirement into the work behind it, then produce a small piece of evidence for each task. Candidates who do this are more likely to pass the resume screen, and by the time they reach the technical assessment, they've already built a version of the work with their own hands.

The verbs in the posting say more than the nouns

The first sentence of the responsibilities section contains four verbs: develop, configure, deploy, and optimize AI agents on Cresta's platform and tools. That sequence is the lifecycle of a customer project. It's not building a product from scratch—it's taking an existing platform and making it run for one specific customer.

To understand what "making it run" means, you first need to look at the product. Cresta describes itself as a unified platform for enterprise scale, serving both human agents and AI agents.

An analysis updated by eesel AI in May 2026 notes that Cresta's AI agent supports voice, chat, and SMS, connecting to other systems through API-based function calling and MCP support.

An earlier detail matters even more. Back in 2021, Cresta's blog stated that the product was designed to integrate and work alongside the call center software customers already use. So the FDE here almost always works inside someone else's system, where the data, constraints, and processes are not under their control.

The posting requires at least 3 years of full-time experience in software development, consulting, or AI/ML engineering. All three paths are treated equally, so a backend engineer who hasn't done AI still has a chance—provided they can prove the Python and Golang line, and the cloud and DevOps line.

Example: the agent looks up a bill while the customer is still on the call

Suppose a telecom carrier wants its AI agent to answer "How much is my bill this month?" on the voice channel. The data lives in the carrier's billing system, not in Cresta. Your task is to write a tool the agent can call via function calling.

import requests

BILLING_URL = "https://billing.example-telco.internal"

TOOL_SPEC = {
    "name": "get_open_invoice",
    "description": "获取已验证手机号的客户的未付账单",
    "parameters": {
        "type": "object",
        "properties": {"phone": {"type": "string"}},
        "required": ["phone"],
    },
}

def get_open_invoice(phone: str) -> dict:
    try:
        r = requests.get(
            f"{BILLING_URL}/invoices",
            params={"phone": phone, "status": "open"},
            timeout=2.5,  # 通话中，长时间沉默就等于失败
        )
        r.raise_for_status()
    except requests.RequestException:
        # 客户系统出错：不要猜，转接人工
        return {"ok": False, "action": "handoff_to_human"}

    items = r.json().get("items", [])
    if not items:
        return {"ok": True, "invoice": None}
    inv = items[0]
    return {"ok": True, "amount": inv["amount"], "due": inv["due_date"]}

The API call itself is only a few lines. The value lies in the three decisions around it—and that's exactly what the interviewer wants to hear you explain.

The first decision is the timeout. Waiting five seconds in a chat channel is acceptable; five seconds of silence on a call, and the customer will think the line dropped. The 2.5 seconds here is just an illustrative assumption—in a real project, you'd measure the customer's API latency first before setting it.

The second decision is returning

handoff_to_human

rather than letting the model improvise. An agent that answers anyway when it can't get the data is fabricating billing amounts. Since the platform serves both human agents and AI agents, transferring the call to a human is the natural fallback.

The third decision is distinguishing "no bill exists" from "an error occurred." The responses to the customer are completely different in each case, and the prompt must teach the agent to say the right thing in each situation.

From example to application: do it in this order

First, implement the tool above against a mock API you write yourself, then add ten test questions, including nonexistent numbers and an API that hangs without responding. Record how many questions the agent answers correctly before and after tuning the prompt. That's your evidence for the LLM and prompt engineering line, which the posting explicitly lists as preferred.

Then rewrite the mock billing service in Go. The posting requires both Python and Golang, and a repository implementing the same service in two languages responds to that line directly. Containerize it, add a CI pipeline that runs tests, and wire in a latency metric: those three things fully cover the cloud and DevOps line.

Finally, write a one-page hypothetical deployment plan for this carrier: what the milestones are, which of the customer's teams need to grant API access, and which risks could cause delays. The posting requires the FDE to set milestones, plan deployments, and coordinate with internal teams to deliver on schedule—this plan is direct evidence for that line.

The CoderPad stage and common mistakes

According to the posting, candidates who pass the resume screen must complete a technical assessment on their own on CoderPad. The resume is the first gate, so it should describe work you've done, not list technologies.

A simple template: "Integrated an agent with customer system X via API Y, reducing Z," where Z is a number you actually measured.

The first mistake is writing "LLMs, RAG, agents" in the skills section without a test set to back it up. The second is assuming the FDE replaces the customer's systems, when Cresta itself says the product was designed to work alongside existing call center software. The third is assuming AI only needs Python and skipping Go.

Another Cresta posting shows the next step on this path: a Forward Deployed Engineering Manager role, published in January 2026 for remote candidates in the US, requiring at least 2 years of experience managing, mentoring, and developing engineering teams, plus willingness to travel 10-25% of the time to visit customers and attend events.

The planning and coordination skills you practice today are the foundation for taking that step.

People who know how to read job postings don't count how many keywords they match. They ask: have I done this work for anyone? If not, build a small version of it this weekend.
