The term "Agentic Coding" has been rapidly gaining presence in software development since 2025. Following the first wave driven by the spread of "code completion" AI assistants like GitHub Copilot and Cursor, the core of the second wave is a development style in which "AI agents" autonomously plan, execute, and verify tasks.

Autonomous coding agents such as Devin, Claude Code, SWE-agent, OpenAI Codex agents, Cline, and AutoCoder have been released in rapid succession, and many companies have already integrated them into their production development workflows. Drawing on my experience supporting AI adoption at multiple development organizations as a technical advisor, this article provides a thorough explanation of the definition of agentic coding, its core technologies, the realities of on-the-ground implementation, and career strategies for engineers to survive this era, including how to go independent as a freelancer.

Conclusion: Agentic coding refers to a development style in which AI agents "understand tasks, formulate plans, and autonomously repeat file editing, command execution, testing, and verification." While conventional code-completion AI assistants existed to "assist humans," the decisive difference of agentic coding is that it functions as "an autonomous developer collaborating with humans."

Agentic coding rapidly emerged as a distinctly new-generation development style after 2025, clearly differentiated from 2023–2024, when "conversational/completion" AI like ChatGPT and GitHub Copilot were mainstream. This section organizes its essence and evolutionary trajectory.

The decisive paradigm shift occurred between Generation 2 and Generation 3. Until now, "humans were the primary actors writing code," but in the world of agentic coding, "humans become the primary actors of instruction and approval," with AI taking on a substantial portion of the actual work of writing code.

This shift is not merely the evolution of a "productivity tool," but a change that demands the redesign of the entire software development workflow. Technology selection, requirements definition, design reviews, code reviews, test strategies, and operational design are all being restructured around the assumption of AI agents.

Conclusion: Agentic coding works by integrating the LLM's "reasoning ability," "planning ability," and "tool use ability" into a mechanism that autonomously runs problem-solving loops. The three core technologies are the ReAct (Reasoning + Acting) framework, tool-calling APIs, and RAG (Retrieval-Augmented Generation).

To understand why agentic coding has reached a practical level, it is important to know the technical mechanisms behind it. This section organizes the core technologies.

At the heart of agentic coding is the ReAct framework, which alternates between "Reasoning" and "Acting." Proposed by Google researchers in 2022, it has become established as the fundamental pattern for modern AI agents.

The basic structure of the autonomous loop driven by the ReAct framework is as follows.

  • Thought: Reasoning in natural language about "what should be done next"
  • Action: Selecting and executing a tool (file reading, command execution, browser access, etc.)
  • Observation: Obtaining execution results and updating the state
  • Re-thinking: Replanning the next action based on the observation results
  • Completion check: Determining whether the goal has been reached; if not, looping again

Through this loop, agents can autonomously repeat "failure → fix → retry." The essence of agentic coding is that AI can now perform on its own the trial and error that humans do in programming work: "just try running it, look at the errors, and fix them."

In addition to ReAct, modern implementations also combine the following derivative frameworks.

  • Plan-and-Execute: Create an overall plan first, then execute it step by step (effective for complex tasks)
  • Tree of Thoughts: Branch out multiple solution approaches and explore them in parallel
  • Reflection: Self-review one's own output and improve it
  • Multi-Agent: Multiple agents collaborate with divided roles (tester, implementer, reviewer, etc.)

The biggest point that distinguishes agentic coding from traditional AI assistants is its "Tool Use / Function Calling" capability. With LLMs now able to call external tools, an "acting AI" that goes beyond text output has become a reality.

In particular, MCP (Model Context Protocol), which has spread rapidly since late 2024, is a key protocol that dramatically expanded the agentic coding ecosystem. Through MCP servers, agents can now access Slack, Notion, GitHub, Jira, databases, internal systems, and more in a standardized way, making autonomous workflows that span not just development work but the entire cycle from "task management → implementation → deployment → internal notifications" a practical reality.

For agentic coding to work on large-scale codebases, the LLM's context window alone is far from sufficient. That is where RAG (Retrieval-Augmented Generation) comes in as retrieval augmentation.

A typical RAG configuration for agents to understand codebase context is as follows.

  • Codebase indexing: Vectorize the entire project and store it in a vector DB (Pinecone, Weaviate, Qdrant, etc.)
  • Combining structural search: Use AST (Abstract Syntax Tree) analysis to structurally grasp classes, functions, and call relationships
  • Document RAG: Add READMEs, API docs, ADRs, and design documents to the search targets
  • Ticket/knowledge RAG: Reference past tickets and meeting notes accumulated in Jira and Notion
  • Dynamic retrieval: "Just-in-Time" retrieval where the agent loads only the relevant files as needed

RAG accuracy directly determines the accuracy of agentic coding. "Vector search alone" or "keyword search alone" has its limits, and hybrid search combining both, along with advanced retrieval design incorporating structural code analysis, has become a key differentiator in modern agent implementations.

Conclusion: When introducing agentic coding into development teams, the keys to success are three points: integration into CI/CD workflows, context management, and quality/security governance. Most failures stem from flawed process design, such as "adopted but unused" or "quality cannot be guaranteed."

If you settle for tool selection alone, the true value of agentic coding will not be realized. This section explains practical steps for real-world development teams and how to address common issues.

When integrating agentic coding seriously into the development flow, consistency with existing CI/CD pipelines is critically important. Below are representative integration patterns.

Best practices for adoption are as follows.

  • Narrowing down target tasks: Don't apply it to all work at once; start with areas where results are easy to see (bug fixes, test generation, etc.)
  • Installing guardrails: Codify rules such as prohibiting direct deployment to production and requiring PR-based, human-reviewed changes
  • Cost management: Visualize API usage and set monthly budget limits
  • Defining quality metrics: Measure bug density, review time, and lead time before and after agent intervention
  • Gradual expansion of permissions: Once results appear, expand permissions to more autonomous tasks
  • Sharing failure cases: Foster a culture of sharing agent operation know-how and failures within the team

Agentic coding is powerful, but specific failure patterns occur frequently in practice. Below are representative failures and how to address them.

Failure patternSymptomsCountermeasures
Context collapseAI loses context mid-task and diverges into contradictory implementationsBreak tasks into smaller pieces and periodically reset context
Infinite loopsFixing an error → a new error occurs → endless fixing continuesLimit maximum retry attempts and set escalation rules
Hallucination (fictional APIs)Calls non-existent library functions or API endpointsHave it reference the actual codebase via RAG and detect issues with linters/type checkers
Over-modification"Incidentally" changes unrelated filesSet limits on the number of changed files and thoroughly review diffs
Neglecting testsCode appears to work but edge cases are not consideredExplicitly state test coverage requirements and introduce property-based testing
Security vulnerabilitiesGenerates code containing authentication bypasses, SQL injection, etc.Make static analysis (Snyk, Semgrep, etc.) mandatory and add a dedicated review phase
Dependency bloatAdds large numbers of unnecessary packagesRequire review when adding dependencies and run supply chain security scans
Documentation driftCode is updated but documentation is notInclude documentation updates in the agent task's Definition of Done

These failures are amplified not only by technical constraints but also by flawed operational rules. Professional tech leads focus on designing appropriate guardrails based on an understanding of what agents can and cannot do.

The most important aspect of putting agentic coding into production is designing quality and security governance. Below are representative countermeasures.

  • Mandatory static analysis: Make static analysis tools such as ESLint, SonarQube, Semgrep, and CodeQL required CI checks
  • Dependency vulnerability scanning: Continuously monitor supply chain security with tools like Dependabot, Snyk, and Trivy
  • Secret scanning: Introduce tools like Gitleaks to prevent API keys, passwords, and other secrets from being accidentally committed
  • Code coverage requirements: Require a certain level of test coverage even for code written by agents
  • Approval workflows: Require human approval for production deployments and prohibit agents from merging on their own
  • Audit logs: Record who, when, with which agent, and what was changed
  • Multi-agent review: Have agents other than the implementing agent act as reviewers
  • Architecture Decision Records (ADR): Involve humans, not just agents, in important design decisions

Particularly emphasized in recent years is the mechanism of "cross-agent checks." In this design, "the agent that writes code," "the agent that writes tests," and "the agent that reviews security" divide roles and verify each other's work. This suppresses the runaway behavior of a single agent and greatly improves quality stability.

For security and governance perspectives, the SRE engineer skills and freelance independence article is also a useful reference. Availability, observability, and security remain important themes even in the age of agentic coding.

One of the areas where agentic coding is most effective is legacy code refactoring and migration projects. Below is a summary of typical use cases.

  • Language migration: Bulk conversion from Java to Kotlin, Python 2 to 3, or JavaScript to TypeScript
  • Framework migration: Cross-generation upgrades such as Angular.js to React or Rails 5 to Rails 7
  • API replacement: Bulk replacement of deprecated APIs with their successors
  • Test code addition: Bulk generation of tests for legacy code with almost zero test coverage
  • Documentation generation: Automated documentation for codebases with no documentation at all
  • Microservice decomposition: Gradual extraction of functionality from a monolith into individual services

While these tasks would take humans months to years of manual work, agentic coding can sometimes shorten them to weeks or months.

However, the role of the "human architect" remains critically important here as well. Agents are good at local transformations, but architectural decisions such as "how should the system be divided as a whole" and "in what order should the work proceed" must be made by humans.

What becomes decisively important in the age of agentic coding are "upstream process skills" and "prompt engineering skills."

Breakdown of upstream process skills

  • Requirements definition: Ability to translate business problems into technical requirements
  • System design: Ability to divide functionality into modules and organize dependencies
  • Architecture design: Design that accounts for non-functional requirements (performance, availability, security)
  • Data design: Ability to design high-quality ER diagrams and data flows
  • API design: Ability to design APIs with appropriate granularity, naming, and error handling
  • Test strategy: Ability to design what to test, at what level, and at what granularity

Breakdown of prompt engineering skills

  • Task decomposition: Ability to break large goals down into small, executable tasks
  • Context design: Ability to organize the information given to agents with neither excess nor deficiency
  • Articulating constraints: Ability to clearly communicate prohibitions, requirements, and priorities
  • Designing for verifiability: Ability to frame agent deliverables in a form that can be objectively verified
  • Agent selection: Ability to choose the appropriate agent or model for each task
  • Learning from failure: Ability to improve prompts when agents fail

These skills were traditionally considered something "acquired through long experience from junior to senior levels," but in the agentic era, they have shifted to become "areas that even engineers in their second or third year should actively pursue."

One caveat: agentic usage can inflate API costs to 10–30 times those of conversational usage. This is because a single task involves multiple LLM calls and tool calls, so operation design with cost management in mind is essential.

Practical tips for cost management include the following.

  • Narrow down tasks: Focus deployment on areas with high impact
  • Use models appropriately: Small models for lightweight tasks, high-performance models for complex tasks
  • Leverage caching: Make thorough use of prompt caching and context caching
  • Limit retries: Set maximum loop counts and maximum execution times for agents
  • Cost monitoring dashboard: Visualize API costs daily and weekly

A: Fully on-premises operation is possible, but there is a trade-off between performance and operational burden.

Here is an overview of the main options for on-premises operation.

  • OSS agent frameworks: Agents that can be deployed in-house, such as SWE-agent, OpenDevin-based systems, and custom Cline derivatives
  • Local LLMs: Running Llama 3, Qwen, DeepSeek, Mistral, etc. on your own GPU infrastructure
  • Via private cloud: Using LLMs within your own VPC through AWS Bedrock, Azure OpenAI Service, Google Vertex AI, etc.
  • Hybrid configuration: On-premises for sensitive data, cloud for general tasks

However, fully on-premises operation comes with the following challenges.

  • Model performance gap: Open models lag behind frontier models such as GPT-5 and Claude in agentic capabilities
  • Infrastructure costs: Procuring and operating high-performance GPU clusters is expensive
  • Maintenance burden: Model updates, security patches, and performance tuning must be handled in-house
  • Ecosystem: Limited options for MCP-compatible tools, extensions, etc.

As a realistic compromise, the configuration of "using frontier models via private clouds such as AWS Bedrock or Azure OpenAI Service while keeping data within the company's VPC" is widely adopted as an option that balances security and performance.

A: Copyright and liability must be defined by the terms of service of the tools used and by corporate governance rules.

Here is an overview of the key issues.

Copyright issues

  • Copyright of generated output: Many tools stipulate that "rights to generated output belong to the user," but this varies by tool, so reviewing the terms of service is essential
  • Contribution to training data: Choosing options (opt-out) that prevent your company's code from being used as training data
  • OSS licenses: License compliance when agents incorporate OSS code (e.g., GPL contamination)

Liability issues

  • Bugs and defects: Even for failures caused by agent-generated code, final responsibility generally rests with "the party that reviewed and approved it"
  • Security vulnerabilities: Responsibility for handling injected vulnerabilities likewise rests with the operating organization
  • Contractual warranties: When freelancers deliver agent-generated code to clients, clarify the scope of quality guarantees in the contract
  • Audit logs: Record who used which agent, when, and what was generated, to ensure traceability

As practical measures, the following governance improvements are recommended.

  • Establish an agent usage policy: Clearly document permitted tools and prohibited uses
  • Approval workflow: Make human review mandatory before agent-generated code is deployed to production
  • Auditing and traceability: Record all generation and changes
  • Education and training: Provide basic AI governance training to all engineers
  • Collaboration with legal: Review contracts and terms of service in cooperation with the legal department
