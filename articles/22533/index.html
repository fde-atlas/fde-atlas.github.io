How to Scope a Forward Deployed Engineering Engagement

FWD Deployment · 2026-11-06 · 9 min read

Summary

This guide explains how to scope a forward deployed engineering engagement for retail inventory automation. Drawing on the Federal Acquisition Regulation, it lists six elements a statement of work should contain: work, location, period of performance, deliverable schedule, performance standards and special requirements. It proposes four phases—Discovery, WMS/ERP Integration, Field Deployment and Handoff—each with dates, deliverables and acceptance tests. It stresses writing connector ownership, license-back, reuse, escrow and core-platform terms into the contract, and lists CISA-based security prerequisites like least privilege, MFA and logging before kickoff. On pricing, it distinguishes time-and-materials from fixed-price and suggests T&M for Discovery. The author notes it is general information, not legal advice.

Key points

  • A statement of work should name six elements: work, location, period of performance, deliverable schedule, performance standards, special requirements.
  • Split the engagement into Discovery, WMS/ERP Integration, Field Deployment and Handoff, each with dates and acceptance tests.
  • Connector ownership, license-back, reuse, escrow and core-platform restrictions must be explicit contract terms.
  • Before kickoff, set least-privilege access, MFA, logging, failed-login alerts and an incident response plan.
  • Price Discovery on time-and-materials and seek fixed pricing for later phases once scope is defined.

Scope a retail inventory engagement by writing a statement of work that names six things: the work, the work location, the period of performance, the deliverable schedule, performance standards, and special requirements. Then divide the work into four phases (Discovery, WMS/ERP Integration, Field Deployment, Handoff), each with its own dates and acceptance test. How long each phase runs depends on your site count, your number of system interfaces, and your robotics vendor's install schedule, so set the dates from your own plan.

This is general information, not legal advice, so have your counsel read the final contract language.

What must a statement of work for an FDE engagement contain?

The Federal Acquisition Regulation (8.405-2) says a statement of work must describe the work to be performed, work location, period of performance, deliverable schedule, applicable performance standards, and special requirements such as security clearances, travel, or specialized knowledge. The FAR Subpart 8.4 makes the same list. These are federal rules, but the list works as a checklist for a private retail contract.

Apply each element to a retail inventory project like this:

  • Work to be performed: name the systems, interfaces and workflows, such as the WMS-to-robot-controller connection or an ERP inventory sync.
  • Work location: list each distribution center, store or lab, and say what is done remotely.
  • Period of performance: give a start date, an end date, and dates for each phase.
  • Deliverable schedule: tie every deliverable to a date and a named reviewer on your side.
  • Performance standards: define how you will measure acceptance (see the metrics section below).
  • Special requirements: cover travel to sites, background checks, and specialized knowledge of your WMS or robotics platform.

Federal Part 16 guidance adds that the SOW should be written so the tasks to be performed or supplies to be delivered are clearly specified. If a task can be read two ways, rewrite it before you sign.

What phases should the contract include?

Use four phases: Discovery, WMS/ERP Integration, Field Deployment and Handoff. This split is a drafting suggestion for organizing the SOW, not a required template. Each phase should carry the same six elements from the list above.

Phase What the SOW should name Example acceptance test
Discovery Systems inventory, process maps, data access granted, baseline metrics, written scope for later phases Baseline report signed by operations and IT
WMS/ERP Integration Each interface, message types, error handling, test environment, connector code deliverables Integration messages pass a defined test set in a non-production environment
Field Deployment Sites in order, on-site staffing, travel, cutover plan, rollback plan, safety review Each site meets the performance standards you set
Handoff Runbooks, documentation, training, access removal, IP deliverables Your team operates the system without the vendor for an agreed period

Make Discovery produce a deliverable that rewrites the later phases. If Discovery shows that your WMS has three more interfaces than you thought, the SOW should let you adjust the integration scope in writing instead of arguing about it later.

How long should each phase take?

Put a start date and an end date on every phase in the period of performance. Let these inputs set the length:

  • The number of sites and the order you will roll them out.
  • The number of WMS and ERP interfaces, and whether a test environment exists.
  • The robotics vendor's delivery and install schedule.
  • How fast your team can grant access and review deliverables.

Ask the firm to show a dated plan that ties each phase to these inputs. If a proposal gives one total duration with no phase dates, ask for the breakdown before you sign.

Who owns the custom connectors?

Decide this in the contract text. Do not leave it to assumption. Custom API connectors that link your WMS or ERP to a robotic system are a different asset from the vendor's core platform, and the SOW should treat them separately. Cover each of these points:

  • Connector ownership: state who owns the custom connector code and the integration configurations written for your systems.
  • License-back rights: if the firm owns the connectors, state that you hold a license to use, modify and maintain them. If you own them, state what the firm may keep.
  • Reuse rights: say whether the firm may reuse the connector logic, or parts of it, on other clients' projects, and what must stay confidential.
  • Escrow: if the firm keeps ownership, consider requiring source code escrow so you can maintain the connectors if the relationship ends.
  • Core-platform restrictions: state that the vendor's core platform code stays the vendor's, and that your connector work must not require you to take over or modify that code.
  • Your data and schemas: state that your data, mappings and business rules remain yours.

The right answer on each point depends on the deal: how custom the connectors are, how much of your own logic they hold, and whether you plan to move to another vendor later. Your attorney should review this clause.

What data access prerequisites must be in place before kickoff?

List these in the SOW as customer responsibilities with dates, because slow access is a common cause of schedule slips. The checklist below draws on CISA guidance. For a deeper treatment of the access model, see our guide on how to securely grant forward deployed engineers access to logistics systems.

  • Least privilege: CISA recommends limiting employee access to only the resources needed for assigned tasks. Apply the same rule to contractors: give each engineer access only to the WMS, ERP and test systems their phase requires.
  • MFA: CISA recommends multifactor authentication for VPN connections, external-facing services and privileged accounts. It also recommends phishing-resistant MFA for critical services.
  • Logging: CISA recommends that applications and systems generate sufficient logging information, and it names system, network, application and cloud logs as sources for centralized collection and retention. Confirm that the engineers' activity in your WMS and ERP shows up in those logs.
  • Failed-login alerts: CISA's Cross-Sector Cybersecurity Performance Goals recommend logging unsuccessful logins and sending them to the security team or logging system. It gives five failed attempts in two minutes as an example alert threshold.
  • Incident response plan: CISA defines this as documented procedures for detecting and responding to cyber incidents. Name who calls whom if an engineer's account is compromised.
  • AI-system inventory: if the firm will build AI agents or models into your fulfillment flow, the NIST AI RMF Playbook recommends policies for maintaining an AI-system inventory and assigning responsibility for it. Name that owner in the SOW.

Add a Discovery-phase exit condition: the work does not move to integration until these items are confirmed in writing.

How do you define success metrics and SLAs?

Define them in the SOW from your own baseline, then confirm them with acceptance tests. Measure your current performance during Discovery, so that every target compares against a number you recorded. Candidate metrics include:

  • Inventory accuracy
  • Order-cycle time
  • Robot availability
  • Pick or move throughput
  • Exception rate
  • Safety incidents
  • Integration-message success rate
  • Incident-response times

The NIST AI RMF Playbook identifies system downtime and incident-response time as examples of security tests and metrics to track. For each metric you choose, write down the measurement method, the data source, the target, and who signs off. A target with no measurement method is not enforceable.

How should you price the engagement?

Know the two basic mechanics first. FAR Part 16 describes time-and-materials as specified fixed hourly labor rates plus actual material costs, and says it is not a fixed-price contract. Subpart 16.2 treats fixed-price contracting as distinct from time-and-materials and labor-hour contracting.

Time-and-materials or labor-hour pricing is appropriate when the extent or duration of the work and its costs cannot be estimated accurately at contracting time, per FAR Subpart 8.4. Federal guidance in 8.405-3 recommends firm-fixed-price orders when practicable.

One structure to consider: price Discovery on time-and-materials, because its outcome sets the scope, and ask for fixed pricing on later phases once the interfaces and sites are defined. Whether a firm will agree depends on the firm and the deal. Public price ranges are not something we can give you as of November 2026, so ask each firm for a written quote against your SOW. For a look at how these models compare in another industry, see FDE pricing models for insurers.

Which engagement model fits: embedded team, project delivery or technical leadership?

Match the model to how well you can define the work. Dplyz, for example, places senior engineers inside a business to connect its data, build products and run AI agents and workflows in production, and it offers three ways to work: an embedded team, project delivery or technical leadership. It does not publish a price list, so expect to request a quote.

A pre-signature checklist

  • All six SOW elements are filled in for every phase.
  • Each phase has dates, deliverables and a named acceptance reviewer.
  • Baseline metrics and measurement methods are written down.
  • Connector ownership, license-back, reuse, escrow and core-platform terms are explicit.
  • Access, MFA, logging and incident response prerequisites have owners and dates.
  • The pricing model for each phase is stated, with the reason for it.

Common questions

What are the standard phases in a statement of work for retail forward deployed engineers?

We suggest four: Discovery, WMS/ERP Integration, Field Deployment and Handoff. This is a drafting structure, not a required template. Each phase should name the work, location, period of performance, deliverable schedule, performance standards and special requirements.

Who owns the intellectual property for custom WMS integrations built by an FDE team?

The contract decides, so write it explicitly. Cover connector ownership, license-back rights, reuse rights, escrow, and restrictions on the vendor's core-platform code, and have your attorney review the clause.

What data access and security prerequisites must be met before an FDE retail deployment begins?

Based on CISA guidance, set least-privilege access, MFA on VPN, external-facing services and privileged accounts, centralized logging, failed-login alerts, and a documented incident response plan. If AI systems are involved, assign an owner for an AI-system inventory, as the NIST AI RMF Playbook recommends.

How do you define success metrics and SLAs for robotic mobile fulfillment system deployments?

Record your baseline in Discovery, then set targets and acceptance tests in the SOW. Candidate metrics include inventory accuracy, order-cycle time, robot availability, throughput, exception rate, safety incidents, integration-message success rate and incident-response times.

How are forward deployed engineering contracts typically priced for retail logistics projects?

We have no public price ranges to cite. The mechanics are time-and-materials, which uses fixed hourly labor rates plus actual material costs, and fixed-price, which is a distinct structure. Time-and-materials fits work you cannot yet estimate accurately.
