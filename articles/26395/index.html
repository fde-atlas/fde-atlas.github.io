Original title: 企业 AI 开始进入

Today's Take

If enterprise AI spent the past few days moving through "endpoint management," "process assembly," and "acceptance and self-optimization," today's most notable new development is this: enterprise AI is converging from "platform capabilities" into industry-specific delivery packages embedded in customer environments.

Taken together, today's signals show four highly consistent shifts:

1. No longer just selling models, but selling entire result chains within industry workflows.

2. No longer just talking about integration, but building data foundations, content permissions, approvals, and human-in-the-loop into runnable systems.

3. No longer serving only top-tier mega-customers; even the mid-market is seeing standardized "FDE + industry solution package" playbooks.

4. No longer confined to the digital world; AI has entered heavier business settings like chip verification, manufacturing, banking operations, and core marketing workflows.

Put together:

  • The value of the FDE is upgrading from "helping enterprises connect to AI" to installing enterprise AI into customers' business operations and making it deliver results.
  • The next stage of high-ticket projects will look more like full-package delivery: "industry work packages + data governance + content governance + on-site co-creation."

Key Signals

Databricks × Acxiom pulls enterprise AI's focus back to the data foundation, delivering 80%-90% speed gains

  • Source: Databricks Blog ｜ Original link
  • On July 10, 2026, Databricks published the Acxiom case study, with the core thesis: The agentic marketing stack starts with the data layer.
  • Acxiom is chaining identity resolution, audience planning, media buying, campaign activation, and performance analysis into an end-to-end agentic marketing value chain.
  • After migration, multiple workload types ran 80%-90% faster. Tasks that used to take 50+ or even 90+ hours now take 2-3 hours.
  • The delivery model upgraded from traditional SFTP file transfers to embedding data capabilities agentically into the customer's own environment.
  • Why it matters: The main battleground for enterprise AI isn't "deploy an Agent first, then figure out how to use it"—it's preparing the customer's data foundation, process foundation, and runtime environment first. The teams that can sustainably capture budget long-term are those that consolidate previously scattered people, data, approvals, and execution into a single business chain.

Anthropic × UST brings Claude into physical AI, with FDEs entering chip, manufacturing, and banking sites

  • Source: Anthropic Case Study ｜ Original link
  • On July 9, 2026, Anthropic published "UST is bringing Claude to physical AI."
  • UST plans to train 20,000 engineers, architects, consultants, and FDEs globally.
  • In the hardware and silicon verification platform iDEC, verification cycles have been cut by 50%-70%, with the standard 4-day cycle compressed to 48 hours. Claude Code is used to directly read chip pinouts and hardware schematics, then write and run regression tests.
  • Deployment extends across three platform types: healthcare, telecom, and banking. On the banking side, AI agents are explicitly embedded into case handling, servicing automation, knowledge retrieval, and workflow assistance.
  • The report explicitly names forward-deployed engineers, who sit alongside client teams.
  • Why it matters: The FDE battlefield has advanced from knowledge Q&A and software assistants into heavier core lines like engineering verification, physical equipment, network operations, and banking processes. High-value FDEs of the future will look more like embedded engineering teams capable of entering customers' production systems, engineering systems, and compliance processes.

Box turns the MCP server into an enterprise content permissions bridge—the content layer formally enters the enterprise Agent mainstream

  • Source: Box Blog ｜ Original link
  • On July 9, 2026, Box announced that the Box MCP server and Slackbot MCP client are now generally available, while previewing an expansion to Salesforce Agentforce.
  • Box defines the MCP server as a secure bridge, letting Slackbot access enterprise content without leaving the collaboration context. All actions run on existing permissions, without creating a separate permission system.
  • Box for Agentforce already has 41 prebuilt agent actions, handling workflow, document, and security metadata.
  • Why it matters: Once enterprise Agents truly enter core workflows, the most valuable asset isn't a single model—it's the layer of "collaboration entry point + content permissions + metadata actions + audit trails." Going forward, many customers will pay for an enterprise content operations layer that can securely move context and actions across Slack, CRM, and document systems.

Google Cloud × Accenture packages FDEs for the mid-market, moving FDEs from top-tier customization to standardized services

  • Source: ITPro industry coverage ｜ Original link
  • On July 8, 2026, ITPro reported that Google Cloud and Accenture launched six categories of industry-specific agentic AI solutions for the mid-market, covering intelligence and growth, customer experience, cybersecurity, business operations, industry solutions, and workforce enablement.
  • On Accenture's side, forward deployed engineers (FDEs) explicitly provide guidance and technical support.
  • Research data: roughly 73% of mid-market enterprises have already deployed AI, but about 90% of projects remain stuck at the pilot stage.
  • Why it matters: FDEs are no longer a heavy-delivery model reserved for a few mega-customers; they are moving toward standardized services of "industry packages + platform packages + FDE support." This shows FDE is becoming a genuinely scalable service business.

Box evals GPT-5.6 on real industry tasks—enterprise model acceptance shifts from generic leaderboards to business-based testing

  • Source: Box AI Research ｜ Original link
  • On July 9, 2026, Box evals GPT-5.6 on the Box Complex Work Eval, spanning 12 industries, with tasks based on real documents, including reading source documents, reconciling numbers, due diligence, and expert output review.
  • GPT-5.6 Sol is only about 1% higher than GPT-5.5 overall, but it opens up a bigger gap on high-value, data-heavy hard tasks. On data analysis tasks, Sol scores 64% versus GPT-5.5's 57%.
  • Industry score comparison: finance 76% vs 71%, public sector 74% vs 63%, retail 72% vs 66%.
  • Why it matters: Model comparison is shifting from "who is smarter" back to "who is more stable, faster, and more cost-effective on my industry's tasks." Business owners increasingly don't want to hear about leaderboards; they want to know which model fits which role on specific industry tasks.

Implications for FDE practitioners

  • Data foundation before AI agent deployment: The Acxiom case proves that if you don't fix the foundation first, AI agents can only produce fragmented answers from fragmented data. When discussing solutions with clients, package "foundation modernization" as a separate upfront diagnostic rather than assuming the client already has it in place.
  • The FDE role can carry more weight: The UST case shows that FDEs don't have to live only in knowledge work. Long-chain, high-risk scenarios like chip verification, equipment data, and bank case handling are where FDEs can best prove themselves as the true main combat force of enterprise AI.
  • The content permission layer is a new high-value delivery area: Knowledge base projects shouldn't just sell retrieval; they should sell "content permissions + metadata actions + approval chains." The Box MCP server model is worth studying and borrowing from.
  • Pay attention to the "industry solution package" model: The Google Cloud × Accenture move shows that FDE services can be repackaged into a standardized product of "scenario packages + on-site advancement + outcome acceptance," lowering the barrier to closing deals.
  • Build industry-specific task evals: When designing solutions for clients, stop comparing generic leaderboards; instead, run evals on the specific tasks of the client's industry so that model selection is grounded in evidence.
