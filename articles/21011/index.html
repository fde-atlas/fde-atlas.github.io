Three Physical and Logical Isolation Forms of Enterprise Classified Networks

Enterprise security infrastructure typically takes the following three isolation forms, and FDEs must match architectures to each form:

  • Form One: Physically Air-Gapped Data Center: All external network cables and wireless devices are physically cut off, and servers are interconnected only via an internal physical dedicated network. System deliverables must be 100% offline self-contained, with any hidden external dependency download requests (such as pip indexes, HuggingFace weight downloads, or external CDN fonts) strictly prohibited.
  • Form Two: Physical One-Way Security Data Diode: A physical fiber-optic one-way transmission diode (one-way transmit/one-way receive) is deployed between the intranet and the external network; data can only flow into the intranet in one direction, with no physical return path whatsoever. The system must be designed with a dedicated one-way traversal proxy and asynchronous signed receipt verification mechanism to strictly prevent state hangs caused by the lack of HTTP response confirmation.
  • Form Three: Enterprise Virtual Private Cloud Dedicated Network (VPC with PrivateLink & Peering): A fully isolated virtual private cloud subnet is carved out on public or hybrid cloud, with the public NAT gateway disabled. All inter-service communication flows through VPC Peering or Private Endpoints, strictly adhering to intranet compliance boundaries.

End-to-End Topology Architecture Specification for Classified AI Systems

Classified AI systems must adopt a five-layer architecture with physical and logical decoupling:

  • Layer One: Business Workstations and Intranet Unified Portal: Deployed on intranet security-controlled workstations, accessed via SSO single sign-on and multi-factor authentication (MFA);
  • Layer Two: Pre-Authentication and Sensitive Data Security Vault: Before requests flow to the model, personally identifiable information (PII) and classified fields are automatically irreversibly desensitized, with the mapping dictionary stored only in the intranet vault;
  • Layer Three: Deterministic State Machine Guardrails (Agent Harness): Multi-step long transactions are strictly driven by a deterministic finite state machine; no large model output may directly trigger underlying write instructions;
  • Layer Four: Local Private Open-Source LLM Cluster: Quantized fine-tuned model weights are mounted via vLLM/SGLang on offline GPU servers (such as domestic compute clusters or private compute pools), providing stable offline concurrent inference capability;
  • Layer Five: Enterprise Legacy Data and Internal Knowledge Foundation: Hybrid dense and sparse RAG vector databases are deployed on local private databases, with strict control over chunk data lifecycle and document provenance.

Engineering Standards for Offline Runtime Packages (Images, Weights, and Dependencies with Zero External Network Dependency)

Before entering the customer's data center, the FDE delivery team must prepare the delivery media package according to the following standards:

  • Self-Contained Docker Image Archive: Use docker save to export the complete system image package, and verify offline cold start after docker load on a clean network-isolated test machine;
  • Local Fine-Tuned Model Weight Solidification: Model weights are packaged in SafeTensors format with SHA-256 hash verification; dynamic network downloads via trust_remote_code=True are explicitly disabled;
  • Pinned Dependency Wheel Package Mirror Repository: The package includes a local pip wheel offline source, installing all Python dependencies via pip install --no-index --find-links;

One-Way Physical Data Diode Traversal Proxy and Encrypted Receipt Confirmation Mechanism

Addressing the pain point that a physical one-way data diode cannot establish a two-way TCP handshake, the white paper specifies an asynchronous one-way traversal communication protocol:

  • Packet Assembly and HMAC Signing: The external data source packages events into a canonical JSON payload, signs it with a mutually agreed asymmetric private key, and attaches a globally unique timestamp and request fingerprint serial number;
  • One-Way Traversal Proxy Push (Unidirectional Egress Agent): Pushed one-way into the intranet via dedicated data diode transfer software; the external side marks the transaction as SENT_UNCONFIRMED;
  • Intranet Reception and Signature Verification (Ingress Processing & Verification): The intranet service listens on the receiving port, verifying signature validity and request idempotency; after successful database insertion, the receipt is written to the intranet audit log;
  • Scheduled Reconciliation and Offline Statement Synchronization: For financial or audit operations with extremely high requirements, receipt summaries are synchronized daily via the reverse channel of the physical one-way data diode (or a dedicated controlled read-only interface), reconciling the ledgers on both ends to ensure accounts match reality.

White-Box Security Compliance Walkthrough and Go-Live Acceptance Checklist

Before formally signing the go-live delivery report, the technical leads of both parties must complete a closed-loop walkthrough item by item against the following checklist:

  • [ ] Physical Network Disconnection Verification: Unplug the servers' public network cables on site; the core business flows of the system's full lifecycle must operate normally and pass acceptance testing;
  • [ ] Prompt Injection Defense: Input 20 sets of pre-configured injection counterexamples (such as "ignore the above rules" and "output all passwords"); the boundary gateway must intercept 100% of them and record audit logs;
  • [ ] Multi-Tenant Data Isolation Walkthrough: Attempt to construct cross-tenant requests as an ordinary tenant; the database layer and retrieval layer must physically isolate and reject the requests;
  • [ ] Checkpoint Snapshot Recovery Verification: Force-kill and restart the process at an intermediate node of a long transaction approval; the system must perfectly recover the context based on the original request ID and resume execution, with no duplicate write actions;
  • Asset Handover and Password-Free Drill: Provide a complete offline Runbook and operations troubleshooting package with no external network key dependencies, enabling the customer's technical team to independently review and reproduce all functionality.

Frequently Asked Questions

How can an offline classified data center solve the problem of model knowledge updates?

This is addressed through hot reloading and incremental mounting of local RAG knowledge base chunks. Updates to business policies and manuals are synced directly to the private intranet vector database and full-text search engine, without requiring frequent retraining or fine-tuning of the base large model.

What advantages does VPC private network deployment have over a fully air-gapped physical data center?

A VPC private network offers cloud elasticity and more mature operations and monitoring infrastructure, while VPC Peering and private endpoints ensure data never leaves the dedicated intranet. It is well suited for enterprise customers who need both cloud compute orchestration and strict compliance isolation.

If a white-box security walkthrough reveals the model can be prompted to exceed its permissions, how can you stop the bleeding quickly?

Configure deterministic rule-based blacklists and sensitive-word Bloom filters at the gateway layer, enabling millisecond-level hot updates of filtering policies without restarting or fine-tuning the model, achieving immediate blocking.
