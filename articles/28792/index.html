How to Build an AI Evals Framework: An FDE's Deep Dive into the Open-Source Eval Harness

The companion repository for *Forward Deployed AI Engineering* demonstrates how to decide whether an AI pilot is ready for production.

Key Takeaways

  • The ghanemzadeh/ai-fde repository is the companion repo for the book *Forward Deployed AI Engineering*, containing templates, prompts, an evals framework, and illustrations.
  • The evals framework is written in Python, has 36 tests, and runs offline; a trial run scores six fictional contract memos and flags the ones that fail.
  • The evals framework code is MIT-licensed; the templates, prompts, and illustrations are copyrighted and may be adapted, but not republished as a whole collection.

Six contract review memos, all fictional, are scored one by one against a rubric. At the end of the run, the tool reports which memos failed and why. That is the trial run in the ghanemzadeh/ai-fde repository. The repo is the companion to the book *Forward Deployed AI Engineering*, and the trial run requires no API key.

The repository contains the book's templates, prompts, evals framework, illustrations, and reference material. The book is divided into five parts and twenty chapters, with twelve templates. The README is blunt about its purpose: everything in it is meant to be copied and adapted.

For a Forward Deployed Engineer (FDE), the first thing to open should be the evals framework. Gyde believes the core of this role lies in the distance between an AI pilot and AI in production. HatchWorks sees the FDE as owning the entire closed loop: starting from the question "what should be done," all the way to the system going live with real users.

In the middle of that loop is a question the customer will eventually ask: how do you know the output is good enough? A pilot that cannot answer with concrete numbers usually stays a pilot forever.

Four Components, Each Catching a Different Class of Problem

The evals framework is a Python project with 36 tests. It consists of four parts: deterministic checks, a model acting as a judge, a calibration step that aligns the judge's scores with human raters, and a dashboard. The easiest way to understand it is as a stack of filters layered on top of each other.

Deterministic checks are cheap and conclusive: is a required section missing, is the format correct? Model review handles what regex cannot catch, such as whether the reasoning is actually grounded in contract clauses.

Calibration is the component most often skipped. A model judge is still a model; it may be too lenient, or carry biases no one anticipated.

Suppose the customer's lawyers rescore all six memos, and only four match the model judge. Those two disagreements point to where the rubric or the judge prompt needs revision, and they surface before anyone shows the dashboard to the board.

The evals framework runs offline, so you can understand the entire scoring pipeline without spending a cent on API fees. It is a better introduction to evals than slides: run it first, see which memo fails, then trace back to the code that failed it.

What Can You Reuse with Confidence?

The licensing is split in two. The evals framework code is MIT-licensed and can be used in client projects. The templates, prompts, and illustrations are copyrighted: you may adapt them for your own work, but you cannot republish them as a collection. When building a portfolio, publish your own modified version of the evals framework rather than a copy of the template set.

The templates are worth reading alongside the code, because an FDE's work goes beyond engineering. HatchWorks describes the FDE as a role that combines consultant, product manager, and senior engineer, and as the single accountable owner.

For developers who want to move into an FDE role, there is a ready-made exercise at hand: fork the evals framework, replace the six contract memos with outputs from a domain you know well, write your own deterministic checks, then manually score a small sample to calibrate the model judge.

On a resume, a line like "built an evals framework, calibrated the model judge against human raters, and reported agreement rates" carries more weight than any claim of "LLM experience." When reading job postings, watch for companies that mention evals or measuring output quality: such companies are likely to value this skill directly.

When a customer asks how you know the system answers correctly, don't answer by feel. The most convincing answer is a run that precisely pinpoints where the problems are.
