How to Migrate Gemini 3.8 Flash to Gemini 4 Hydrogen: Sampling, Caching and Thinking Changes

Traversaal.ai · 2026-11-16 · 7 min read

Summary

Traversaal.ai walks through migrating from Gemini 3.8 Flash to Gemini 4 Hydrogen, released November 12, 2026 at $1.50 per million input tokens and $7.50 per million output tokens. Four changes are needed: remove temperature, top_p and top_k (out-of-range values can return 400 errors on AI Studio); drop explicit cached_content in favor of implicit caching on prompts of 4,096+ tokens; replace the minimal thinking level, since Hydrogen defaults to high and bills thinking tokens; and pin the model in agent_config, because the Antigravity agent in Gemini Managed Agents now defaults to Hydrogen. The author recommends staging the migration one setting group at a time, comparing token counts against identical prompts on 3.8 Flash, and verifying function-declaration billing details, which Google's guide states inconsistently.

Key points

  • Sampling parameters must be deleted; out-of-range values may trigger 400 errors.
  • Explicit caching is unsupported; implicit caching applies only to prompts of 4,096+ tokens.
  • Thinking defaults to high instead of medium, and thinking tokens are billed as output.
  • Teams using the Antigravity agent without agent_config will switch models automatically.
  • Migrate incrementally on staging, logging token usage per thinking level and alerting on 400s.

What actually breaks when you swap the model ID?

Four things change at once: sampling parameters, explicit caching, thinking levels and billing. The first three produce errors or silent behavior shifts in code that worked on Gemini 3.8 Flash. The fourth shows up later, on the invoice.

Google launched Hydrogen on November 12, 2026 and lists it at $1.50 per million input tokens and $7.50 per million output tokens, flat across its 1 million-token context window. The AI Studio changelog entry for the same date says Hydrogen is now the default model for the Antigravity agent in Gemini Managed Agents. The Antigravity agent documentation adds that if you omit

agent_config

, the agent defaults to

gemini-4-hydrogen

.

Teams that never pinned a model should set

agent_config

explicitly to control when the switch happens.

Do temperature, top_p and top_k still work on Gemini 4 Hydrogen?

No. Google's guides say to remove them. The AI Studio guide says the server ignores in-range custom values if sent, while out-of-range values return a 400 validation error. The Vertex guide, covered below, says custom values are ignored.

The Vertex AI version of the Hydrogen developer guide words this differently: it says the backend ignores custom sampling values and does not mention a 400 for them. It also lists extra hard failures. Passing

frequency_penalty

,

presence_penalty

or a

candidate_count

greater than 1 returns an HTTP 400 error there, and prefilled model turns in chat history are not supported. I could not confirm that the AI Studio and Vertex surfaces behave identically for out-of-range sampling values, so test the surface you actually call.

What replaces explicit caching on Hydrogen?

Implicit caching replaces it, and you cannot create explicit caches at all. Google states that Hydrogen does not support explicit caching through

cachedContents

or

caches.create

, and tells you to remove

cached_content

fields from requests.

Implicit caching runs by default on prompts of at least 4,096 tokens. The Vertex guide describes it as applying to shared prompt prefixes of 4,096 tokens or more. The practical rule is to put static content first: system instructions, tool descriptions and reference documents at the top, the user's changing question at the bottom. Prompts under 4,096 tokens get no implicit caching, so a 2,000-token instruction block you cached explicitly before no longer qualifies. The AI Studio guide says implicit caching discounts cached input by 95%, to $0.075 per million tokens.

Why does thinking default to high, and what does it cost?

Hydrogen defaults to 

high

thinking where Gemini 3.8 Flash defaulted to

medium

, and Google bills the extra tokens.

The AI Studio guide says Hydrogen defaults to

high

rather than

medium

, adds

xhigh

, and rejects

minimal

with an error. The Vertex guide states that

thinking_budget

and

thinking_level="MINIMAL"

return an HTTP 400 error.

Google's AI Studio migration guide lists billing for thinking tokens and function declarations. The page words the function-declaration part two ways: one place ties it to grounding, while the migration checklist omits the "when using grounding" qualifier. Teams should confirm on their own bill. Output pricing includes thinking tokens at $7.50 per million.

Here is the arithmetic on that listed price. A request that produces 10,000 thinking tokens adds $0.075 in output charges. Across 100,000 requests, that is $7,500. This is an illustration of the price list, not a measurement of Hydrogen, because I found no published figure for how many extra thinking tokens

high

produces compared with

medium

.

Google's launch post reports that Hydrogen finishes tasks 2.5 times faster than Gemini 3.8 Flash at its high default setting. That is a vendor claim, so run your own evals before assuming the speed offsets the token bill.

The practical fix is to set 

thinking_level

explicitly on every call. Use

LOW

or

MEDIUM

for classification, extraction and routing.

Reserve

HIGH

and

XHIGH

for the steps where quality gains justify the spend. Google's

migration page

says to replace

thinking_budget

with a

thinking_level

in the same pass.

Frequently Asked Questions

Will my Gemini 3.8 Flash code run unchanged on Gemini 4 Hydrogen?

Probably not. On AI Studio, out-of-range sampling values return a 400 error, 

cached_content

is unsupported, and the

minimal

thinking level returns an error. Code that sets none of these will run, but it will use the

high

thinking default and its higher token usage.

Is explicit context caching available on Gemini 4 Hydrogen?

Google's migration guide says Hydrogen does not support explicit caching. Implicit caching covers prompts of at least 4,096 tokens. Plan around implicit caching.

Does Hydrogen bill for function declarations?

Google's migration guide lists billing for thinking tokens and function declarations, but the page is not consistent. One place ties function-declaration billing to grounding, while the migration checklist omits that qualifier. Confirm on your own bill, and measure token counts per request before and after the move.

Which thinking level should I choose?

Set it explicitly. Hydrogen supports

LOW

,

MEDIUM

,

HIGH

and

XHIGH

, with

HIGH

as the default. Start with

MEDIUM

to match what Gemini 3.8 Flash did by default, then raise it only for steps where evals show a quality gain.

Conclusion

Treat this as a configuration migration with a cost review attached. Remove the sampling parameters, delete explicit caching, set

thinking_level

on every call and pin the model where you manage agents. Do those four things on staging before the change reaches production, and compare token counts against Gemini 3.8 Flash on identical prompts.
