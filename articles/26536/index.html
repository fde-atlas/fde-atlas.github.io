How to Study Andrew Ng's Agentic AI Course: FDEs Should Focus on Evals

Original title: 吴恩达 Agentic AI 课程怎么学：FDE 重点看评测

FDE Times · 2026-10-08 · 4 min read

Summary

This article reviews Andrew Ng's Agentic AI course on DeepLearning.AI and argues that for aspiring FDEs, Module 4—covering evals, error analysis, latency and cost—is more valuable than the four celebrated design patterns. The course has 5 modules (Coursera estimates 2 weeks at 10 hours per week) and requires intermediate Python plus basic LLM API familiarity. Every pattern is implemented from scratch in Python without frameworks, which helps FDEs debug any stack on site. Using a hypothetical banking chatbot error table, the author shows why errors should be attributed to components before choosing fixes, and recommends turning the customer service experiment into a GitHub project with an error analysis table for job applications.

Key points

  • Taught by Andrew Ng, intermediate level, 5 modules, roughly 2 weeks of work.
  • Four patterns—reflection, tool use, planning, multi-agent—all built from scratch in Python.
  • Module 4's evals, error analysis, latency and cost content maps closest to FDE work.
  • GPT-3.5 with an agent loop hit 95.1% on HumanEval, beating GPT-4's 67.0% zero-shot.
  • Recommendation: attribute errors before fixing, and publish a GitHub project with an error analysis table.

Key Takeaways

  • The "Agentic AI" course is taught by Andrew Ng on DeepLearning.AI, is intermediate level, and consists of 5 modules. Coursera estimates it takes 2 weeks at 10 hours per week.
  • Each pattern is implemented from scratch in Python, with no reliance on any framework.
  • If you want to become an FDE, Module 4 is the most worth studying closely, covering evals, error analysis, latency, and cost.

On the HumanEval benchmark, GPT-4 scored 67.0% zero-shot. The weaker GPT-3.5, wrapped in an agent loop, reached 95.1%. Andrew Ng cited these figures in The Batch on March 20, 2024, showing that how you organize work around a model may matter as much as the model itself.

That article proposed four design patterns, and they now have a dedicated course: Agentic AI on DeepLearning.AI. The course's full name lists all four: reflection, tool use, planning, and multi-agent workflows. Most learners will sign up for them.

But if your goal is a Forward Deployed Engineer (FDE) role, the most valuable part of this course is not in the title.

Who teaches it, and who is it for?

Andrew Ng is the founder of DeepLearning.AI and co-founder of Coursera. He teaches this course personally, and it is intermediate level. The official page does not give a launch date, only noting it was last updated on August 31, 2026; Coursera also shows the course was updated in September 2026.

There are two prerequisites: intermediate Python, to understand the implementation code, and a basic understanding of LLMs and their API calls. Coursera divides the course into 5 modules, estimated to take 2 weeks at 10 hours per week.

If you have two to eight years of experience and have called LLM APIs, the fundamentals will pose no difficulty.

The course defines agentic AI as: a new way of building software in which LLMs carry out some or all of the steps in complex tasks. The word "some" is key. Not every system needs a fully autonomous agent, and the course saves highly autonomous patterns for the final module.

Four patterns, ordered by autonomy

Across the 5 modules, the four patterns and the evals content are spread across Modules 2 through 5. Module 2 covers reflection, which Andrew Ng defines as: an LLM examines its own output to find ways to improve it. Module 3 covers tool use, including MCP and code execution.

Module 5 groups the remaining two patterns under "Patterns for Highly Autonomous Agents": first, planning, where an LLM devises and executes multi-step plans to achieve a goal; second, multi-agent systems.

Each pattern comes with a hands-on lab. The Customer Service Agent lab corresponds to planning, the Market Research Team lab corresponds to multi-agent systems, and there is a lesson on communication patterns between agents.

If you want to become an FDE, the customer service lab deserves the most effort. This agent has clearly defined inputs and outputs, making it easy to evaluate using the methods from Module 4.

What makes this course distinctive is its teaching approach: every pattern is implemented from scratch in Python, without any framework. This is a real advantage for FDEs. At customer sites, you rarely get to choose your tech stack; when a framework breaks, only someone who understands the underlying loop can debug it.

Why Module 4 is where the valuable skills are

Module 4 sits between tool use and the highly autonomous patterns, and its content is quite different from the rest of the course. It covers evals, error analysis, component-level evaluation, and measuring latency and cost. One lesson is about analyzing errors first, then deciding what to prioritize next.

This is the part closest to FDE work. Suppose you deployed a customer service agent for a bank, and it answers 15% of questions incorrectly. Knowing one more pattern won't help much here.

You need to know: whether the errors come from retrieval, tool calls, or planning; which fix yields the biggest gains; and how each fix affects latency and cost. The simplest approach is to sample a batch of failed runs and assign each one to the component that caused the failure.

The table below is a hypothetical example covering 20 failed runs of this bank agent.

ComponentExample error (hypothetical)Count / 20
RetrievalFetched last year's fee schedule9
Tool callPassed a malformed account number to the query API7
PlanningSkipped identity verification before answering4

Based on this table, you should fix retrieval first, since it accounts for nearly half the errors. Adding a reflection loop to the entire agent might seem more appealing, but it would also add latency and cost to steps that were already working fine.

Andrew Ng's 95.1% figure should be understood the same way. An agent loop can let a weak model outperform a strong one, but only if you can measure will you know whether the loop actually helps. Without evals, it is hard to tell whether reflection or planning actually benefits your system.

In what order should you learn?

Before enrolling, first read that 2024 article on The Batch to understand what problems the four patterns were originally meant to solve. Then follow the course's own order: learn reflection and tool use first, then the highly autonomous patterns. The further along you go, the more steps the agent has, and the more steps it has, the harder it is to debug.

Give Module 4 more time than Coursera's estimate, and apply its methods to the agents you built in Modules 2 and 3.

When putting this course on your resume, don't just list the certificate. Turn the customer service agent lab into a GitHub project, with an error analysis table like the one above: how many runs, which component caused each error, what you fixed first, and why.

Writing the code from scratch the way the course teaches also demonstrates to employers that you can apply these patterns to any tech stack.

When reading FDE job descriptions, watch for phrases like "evaluation," "error analysis," or "latency and cost." A project with an error analysis table matches these requirements exactly.

The four patterns will keep changing with every generation of models. The habit of measuring first, then fixing, will remain useful no matter which model tops the next benchmark.
