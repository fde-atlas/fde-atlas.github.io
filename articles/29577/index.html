Google's 5-Day AI Agent Course: FDE Study Guide

Original title: 谷歌 5 天 AI Agent 课程 FDE 学习指南

Key Takeaways

  • The course is free and self-paced, with one whitepaper and two codelabs per day, based on Gemini and ADK.
  • The most worth studying in depth are tools and MCP, context engineering, and evals (Days 2 through 4).
  • ADK supports most models and can run on your own infrastructure—don't let your skills work only with Gemini.

According to Google's summary article, this agent course co-hosted by Google and Kaggle attracted over 1.5 million learners during its November 2025 live period, with more than 11,000 submissions for the capstone project. With that many people having taken it, the course certificate can no longer make you stand out.

So for those working as or aspiring to be a Forward Deployed Engineer (FDE), the question is no longer whether to take it: the course is free to everyone in the form of a Kaggle Learn Guide. The better question is which parts to study closely so you can use them at a client site next week, and which parts can be skimmed.

Five Days, One Whitepaper and Two Codelabs Per Day

The course's official name is "5-Day AI Agents Intensive Course with Google." According to KDnuggets, each day includes one technical whitepaper and two hands-on codelabs, based on Gemini and Google's Agent Development Kit (ADK). Those with full-time jobs can set their own pace: read the whitepaper first, then do the codelabs later.

The Kaggle Learn Guide page renders content with JavaScript, so the syllabus below is based on KDnuggets' summary rather than the Kaggle page itself. This study plan is built on that outline; when you start learning, verify against the Kaggle page.

According to KDnuggets, Day 1 introduces agents and their architecture; Day 2 covers tools and MCP; Day 3 covers context engineering, sessions, and memory; Day 4 covers agent quality: logging, tracing, metrics, and evals; Day 5 covers how to take agents from prototype to production, involving A2A and managed runtimes.

In June 2026, the course launched a new cohort themed around vibe coding. According to Pulse 2.0, enrollment exceeded 353,000, with content focused on designing, securing, and deploying production-grade agents on the cloud.

Gemini Is Just the Starting Point; ADK Is the Reusable Part

A common mistake is assuming you're learning "Gemini-based agents." According to the official page, ADK is an open-source framework for building, debugging, and deploying agents. The same page also states that ADK can work with almost any generative AI model.

This matters for FDEs because you don't get to choose the client's tech stack. A bank may already have a contract with another model provider, or may not allow data to leave its own infrastructure. ADK can be packaged into containers and run on private infrastructure, so what you learn in the codelabs still applies there.

When doing the codelabs, treat Gemini as the default configuration, not a requirement. After finishing each day, try swapping in a different model. Where things break after the swap is exactly where things will break when deploying at a client.

Three Points Worth Remembering

Tools are the main work (Day 2). An agent at a client is only useful when connected to existing systems, such as a CRM, order database, or ticketing system. So study tool definitions and MCP closely. The first thing to do at a client site is list the systems the agent needs to read from or write to, then write each one as a tool with clearly defined inputs.

Context needs to be designed (Day 3). Imagine an agent assisting customer service staff. The transcript of an ongoing call belongs to the session; the fact that this customer has already complained twice this quarter belongs to long-term memory. Stuffing both into the prompt raises costs and muddles the answers. So work with the client to determine what needs to be remembered and for how long.

Evals are what you deliver to the client (Day 4). This is the day most worth studying in depth. Suppose you get 50 real questions from a client and the agent answers 40 correctly—80%. On its own, that number says very little. Only by reading the traces of those 10 wrong answers do you know whether the failure was a mis-called tool, missing context, or the model itself—and each type of failure requires a different fix.

Which Parts Can Be Skimmed?

If you've built agents before, a quick read of Day 1 is enough. For Day 5, grasp the concepts of A2A, but if the client doesn't use Google Cloud, don't invest too much in managed runtimes. Spend that time instead practicing packaging agents into containers.

The vibe coding cohort is good for quickly assembling a demo for your first meeting with a client. But quickly generated code is no substitute for the Day 4 eval set. The demo wins you the contract; the evals keep the client using the product.

Turn the Capstone Project into a Portfolio Project

Study order: start with Days 2 and 3, spend the most time on Day 4, then study Day 5 based on the infrastructure you want to prove you can handle. Read Day 1 as needed.

As for the capstone project, don't just submit it and move on. Redo it with a non-Gemini model, run it in a container, and put the eval set and a few traces of fixed failures into the repository.

On your resume, state the number of questions in the eval set, the accuracy before and after fixes, and where the agent runs. These few lines show work you've actually done, which the course name cannot.

Before you, there have already been more than 11,000 capstone project submissions. For your project to get noticed, it needs to showcase an agent running on non-Google infrastructure, using a non-Gemini model, with measured results.
