How to Learn the Claude API Free Course: FDE Learning Path

Original title: Claude API 免费课程怎么学：FDE 学习顺序

Key Takeaways

  • The course is free, requires only basic Python and JSON, and includes dedicated modules on evals, tool use, RAG, MCP, and Agents.
  • The MCP and Agent modules correspond exactly to the deliverables Anthropic's FDE job posting requires engineers to deliver to customers.
  • The course doesn't teach how to work on-site at customers, nor how to distill deployment patterns—that part you can only practice on your own.

Anthropic's Applied AI team posted a Forward Deployed Engineer (FDE) job listing on April 28, 2026, requiring candidates to deliver very specific things to customers: MCP servers, sub-agents, and agent skills. And Anthropic's own free course happens to include dedicated modules on MCP and Agent workflows. There's considerable overlap between the course syllabus and the job description.

However, the same job posting also requires FDEs to spend 25% to 50% of their time on-site with customers, building products alongside them. No video can teach that part.

If you're a developer considering a move to FDE, this course is worth your time. Just be clear about which half of the job it covers, and which half you'll have to learn on your own.

Who Is This Course For?

"Building with the Claude API" is produced by Anthropic, hosted on Skilljar, and is part of Anthropic Academy, with free enrollment. Anthropic Academy describes itself as where Anthropic's education team publishes free courses and guides. The course page describes it as a video course teaching developers how to integrate Claude into applications via the Anthropic API.

The barrier to entry is low: basic Python and JSON are enough, no LLM experience required. Notably, the target audience explicitly includes software engineers transitioning into AI application development—which is almost exactly the profile of someone looking to become an FDE.

The course page doesn't list a duration, and you can set your own pace—for example, one module per week plus a small exercise.

Which Modules to Learn First?

Start with the Prompt evaluation module, which comes before RAG and Agents. It teaches you to build test datasets and then score results using both models and code. On-site at a customer, this is what lets you prove a system works with numbers instead of feelings.

Imagine a customer is an insurance company that wants to use Claude to extract information from claims files. You write 20 sample files and use code to check whether the output is valid JSON and whether all required fields are present.

What code can't judge, hand off to the model to score—for example, whether a summary fabricates details. If 17 of the 20 files pass in both rounds, you have a number you can bring into a customer meeting, and the remaining 3 tell you what to fix next.

After evals, learn Tool use. This module covers everything from schemas to multi-turn conversations with multiple tools, and also includes a text editor tool and a web search tool. If you're short on time, you can skim these two built-in tools quickly.

Spend your time on writing schemas and handling multi-tool, multi-turn conversations, because every tool-based system you build for customers will depend on these two skills.

Next is RAG and Agentic Search: chunking, embeddings, BM25, and multi-index pipelines. Almost every customer has a pile of internal documents they want to query directly. Combining BM25 with embeddings lets you hit both exact product codes and questions phrased in all sorts of ways.

Three Ideas Worth Remembering

First, evals need two layers of scoring. What can be measured mechanically goes to code; the rest goes to the model. Missing either layer means you're fooling yourself.

Second, from the Agents and workflows module. It covers parallelization, chaining, and routing, plus a section specifically comparing workflows with agents. Choose the simplest structure that solves the problem. A document review process with fixed steps only needs chaining. Only when the steps can't be predicted in advance do you need an agent that can make autonomous decisions.

Third is MCP. This module covers clients, servers, tools, resources, and prompts—and MCP servers are explicitly listed in Anthropic's job posting as one of the deliverables FDEs must provide to customers. So learn MCP as a way of packaging deliverables, not as a protocol you learn just to say "I know it."

The Half the Course Doesn't Teach

Gergely Orosz of The Pragmatic Engineer defines an FDE as an engineer who rotates between customer teams and core product teams. The role originated at Palantir in the early 2010s. Google's FDE job posting describes someone who builds directly inside customer teams, connecting cutting-edge AI products to the realities of production environments.

Anthropic's job posting likewise requires working inside customer systems and identifying and codifying recurring deployment patterns. No module teaches you how to read an unfamiliar codebase in two days, and no module teaches you how to turn a third deployment into a reusable template for the product team.

You can fill this gap with personal projects. Pick a hypothetical scenario, say the customer service department of a retail chain. Build an MCP server that wraps its mock API, write a set of evals, then write a one-page document describing patterns the next deployment could reuse.

Put exactly these on your resume: deliverables, eval numbers, and distilled patterns. When reading job descriptions, watch for phrases like "customer systems" or "deployment patterns" to judge which half of you the company needs.

The course can help you write the code customers need. Whether customers invite you back depends on the other half of the job.
