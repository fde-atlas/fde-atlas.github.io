Choose a first FDE portfolio project with a bounded client problem

NeuraPath Academy · 2026-09-20 · 1 min read

Summary

This NeuraPath Academy article advises aspiring forward deployed engineers on picking a first portfolio project. The core argument: choose a problem small enough to evaluate end to end, since broad projects like an autonomous CRM agent introduce permission and integration risks before core decisions can be shown. A delivery lab scores fictional options on owned data, bounded writes, testability, demo value and access risk. Good candidates include document review, cited knowledge retrieval or read-only operational summaries. The author warns against claiming real clients or production savings without evidence, and says a complete small system with normal, unsupported and failure paths, test data, architecture and cost decisions, a threat model and a runbook demonstrates more engineering than scattered features.

Key points

  • First projects must be end-to-end evaluable.
  • Five criteria score candidate projects.
  • Avoid broad autonomous agents early on.
  • Never claim unevidenced clients or savings.
  • Complete small systems beat disconnected features.

The best first project is small enough to evaluate end to end. A broad autonomous CRM agent creates permissions and integration risk before the learner can demonstrate the core decision.

Score two fictional options

The delivery lab weights owned data, bounded writes, testability, demo value and access risk.

from delivery_cases import project_choice_case

result = project_choice_case()
assert result["selected"] == "invoice-review"
assert result["scores"]["invoice-review"] > result["scores"]["live-crm-autonomy"]
assert result["fictional_client"] is True
assert result["external_access"] is False

Choose a task with a clear current process, synthetic/rights-cleared data, measurable acceptance, useful exception path and reversible proposal. Good examples include document review, cited knowledge retrieval or read-only operational summaries.

Avoid claims of a real client, production savings or deployment unless evidenced. Build normal, unsupported and failure paths; include test data, architecture decision, cost model, threat model and runbook. A smaller complete system demonstrates more engineering than disconnected features.

Exercise

Score three project ideas with your own weights. Select one, write the non-goals and identify the critical regression that must block the demo.
