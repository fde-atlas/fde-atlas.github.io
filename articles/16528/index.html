Preface

What the job is

A Forward Deployed Engineer takes software from a promising demo to a system that real users depend on, inside a customer’s data, workflows, and constraints. A Special Projects Engineer owns an unclear, high-stakes problem from start to finish, often across team boundaries.

Both roles need the same craft: engineering that holds up in production, enough domain knowledge to challenge the original request, and evidence that the work changed an outcome. Titles vary by company, and neither role is a seniority level.

How to use this book

Read the chapters in order with one real project beside you: a bounded, permitted workflow with real users. If you lack user access, use public or synthetic data and label the result as a simulation. Each chapter ends with a test for when you are done. Plan for five to eight focused hours a week.

How others teach this

Training programs pair technical work with customer work. The FDE Academy method runs parallel technical and consulting tracks with a reviewed portfolio; it is a provider’s description of itself, and this guide is unaffiliated with it. Plank describes a training-and-embedded-team model; its handoff lesson appears in chapter 11.

The engagement, phase by phase

  • Discover. Start with a person, a recurring task, and an observable problem. Watch how work happens today. Part I
  • Frame. Convert an ambiguous ambition into a small decision you can test. Part II
  • Build. Connect the interface, data, business logic, and feedback in one usable slice. Part III
  • Deploy. A release needs users, monitoring, support, and a way to recover. Part IV
  • Measure. Connect use and quality to the user’s outcome, including the cost of review and support. Part V
  • Scale. Turn repeated needs into reusable capabilities, while retaining an accountable operator. Part VI
