How to migrate to AgentCore after the Bedrock Agents course is taken offline

Original title: Bedrock Agents 课程下线后如何迁移 AgentCore

FDE Times · 2026-11-23 · 4 min read

Summary

DeepLearning.AI's Bedrock agents course has been retired, and AWS has stopped accepting new Bedrock Agents customers, renaming the service Agents Classic. Existing deployments keep running, so FDEs will still encounter this architecture at customer sites. The article suggests rereading the course as a map of legacy systems: its build approach is obsolete, and new projects should use AgentCore with the Strands Agents SDK, plus Observability, Identity, Policy, and Evaluations. Three ideas still hold: tools are contracts between agents and customer systems (requiring schema locking and regression testing during migration), arithmetic belongs in verifiable code rather than the model, and responsible AI is an engineering layer with real configuration. The piece ends with learning-order advice and job-interview tips.

Key points

  • Bedrock Agents is now Agents Classic; existing customers can keep running their agents.
  • New projects should use AgentCore and Strands Agents SDK, adding Policy, Observability, Identity, and Evaluations.
  • Migration requires locking tool schemas and running regression tests before retiring old action groups.
  • Three lasting ideas: tools as contracts, no model arithmetic, responsible AI as configured engineering.
  • Ask in interviews whether clients use Agents Classic or AgentCore to gauge the job type.

Read it as a map of legacy systems: three ideas from the course still hold after moving to AgentCore.

Key Takeaways

  • DeepLearning.AI has taken the course offline, and AWS has stopped accepting new registrations for Bedrock Agents; the service has been renamed Agents Classic
  • Customers already using Agents Classic can keep running it, so Forward Deployed Engineers (FDEs) still need to understand the architecture the course teaches
  • New projects should be built on AgentCore and the Strands Agents SDK, supplemented with learning on Observability, Identity, Policy, and Evaluations

The course page for Serverless Agentic Workflows with Amazon Bedrock on DeepLearning.AI was updated on June 4, 2026, and now opens with a single line: this course has been retired. AWS documentation likewise states that Amazon Bedrock Agents, the course's core service, no longer accepts new registrations and has been renamed Agents Classic.

At first glance, that would be the end of the story. But AWS has also made clear that existing Bedrock Agents users can continue using the service.

For Forward Deployed Engineers (FDEs), this is exactly the key point. Systems built on Bedrock Agents are likely still running in production. When you are deployed to an AWS customer who deployed agents some time ago, what you encounter will very likely be the very concepts this course teaches.

So the course is best reread as a map of legacy systems, paired with a cross-reference table leading to the current platform. Below, we sort out what to keep and what to discard.

A Short Course Taught by AWS

The instructor is Mike Chambers from AWS. The course is positioned as intermediate level, runs about 1 hour 34 minutes, and includes 8 videos and 5 code examples. The only prerequisite is basic Python, and it targets people who want to build agentic applications for work or personal projects.

The course goal is stated plainly: use serverless technology to take a "responsible" agentic application to production. The underlying problem it addresses is handling tasks that are hard to predict in advance with agentic workflows, because those tasks depend on user input, such as calling an API.

A hands-on walkthrough published by Classmethod on December 8, 2024, laid out the specific path; according to that article, the course is free. Learners first build an agent on Bedrock Agents, connect it to AWS Lambda functions, use a Knowledge Base to answer FAQs (that is, AWS-managed RAG), attach Guardrails, and then add computation logic with Code Interpreter.

What Is Already Outdated?

The way the course builds agents rests on the fully managed Bedrock Agents model: each agent needs at least one action group, plus a knowledge base and trace.

For new users, AWS points to Amazon Bedrock AgentCore, where agents are defined in code using the Strands Agents SDK. According to AWS documentation, AgentCore works with any framework and any model, and consists of multiple modular services, each of which can be used independently.

If a customer is just starting out, do not build the agent step by step following the course. You will run straight into a registration gate that is closed to new users.

The course also omits several pieces that real production work requires. AgentCore ships with Observability, Identity, Policy, and Evaluations. AWS specifically describes Policy as a deterministic control layer that lets agents hold business boundaries and rules without slowing execution. This part you need to learn on your own.

Three Ideas Still Worth Keeping

First, tools are the contract between the agent and the customer's systems. In the course, that contract is an action group pointing to a Lambda function. On AgentCore, Gateway converts APIs, Lambda functions, and existing services into MCP-compatible tools, so the course's content on connecting an agent to a CRM still teaches the right idea.

Suppose a retail customer runs a customer service agent on Agents Classic, where one action group queries orders through Lambda. When migrating to AgentCore, Gateway can wrap that Lambda function as an MCP tool. The real effort lies in the two steps before shutting down the old path.

The first step is locking down the schema. For example,

look_up_order

the tool takes a required string

order_id

and a field used to verify order ownership

email

, and returns only three fields:

status

、

estimated_delivery_date

, and

total_amount

. Any field the old agent implicitly accepted, such as a phone number, must either be documented or deliberately removed.

The second step is regression testing. Take real questions the old agent received, run both the old action group and the new tool on them, and check that the tools called, the arguments passed in, and the results returned are exactly identical. Only after they match should you shut down the old action group.

The second idea: don't let the model do arithmetic. The course delegates computation to Code Interpreter. When an agent quotes prices, calculates refunds, or sums up inventory, the numbers should go through code that actually executes and can be audited, because customers will inevitably ask where the number came from.

The third idea: "responsible" is an engineering layer with real configuration. The course places Guardrails directly on the road to production; on AgentCore, Policy and Evaluations serve the same role: keeping agents within boundaries.

This is only a conceptual correspondence, and does not mean Policy replaces Guardrails. When a customer asks whether the agent will produce non-compliant answers, what you need to produce is a configuration and a set of evals, not a promise.

Who Should Learn It, and in What Order?

If you are about to take over a customer already running Bedrock Agents, before opening their AWS account, first master action groups, knowledge bases, traces, and guardrails. Then read the AgentCore documentation: start with Gateway, since it connects directly to the Lambda parts you already know, then move on to Policy, Observability, Identity, and Evaluations. Save the Strands Agents SDK for last, until you are ready to write agents in code.

If the customer is entirely new to AWS, go straight to AgentCore and Strands. In that case, the course serves only as background, helping you understand why the old system looks the way it does.

On the career side, if a job posting mentions Amazon Bedrock, you can ask in the interview: are their customers on Agents Classic or AgentCore? The answer will tell you whether the job is maintenance, migration, or building from scratch.

On a resume, a line like "migrated Bedrock Agents' action groups to MCP tools via AgentCore Gateway, with regression tests" is far more convincing than a certificate for a course that has already been retired.

The course has been shut down, while agents built on Bedrock Agents are still allowed to keep running. When they need to "move house," the person who gets the call will be the one who understands both generations of the platform.
