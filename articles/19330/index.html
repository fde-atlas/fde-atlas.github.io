What Is AI-Driven Development? Enterprise Adoption and Operational Design of Coding Agents

Original title: AI駆動開発とは？コーディングエージェントの企業導入と運用設計

FDX株式会社 · 2026-11-13 · 20 min read

Summary

This long-form guide from FDX explains "AI-driven development," a Japanese term for having coding agents like Claude Code, Codex, and GitHub Copilot handle investigation, editing, command execution, and testing, while humans own specifications, review, and merging. It distinguishes the term from spec-driven development (GitHub Spec Kit, AWS Kiro) and vibe coding, catalogs governance features of major tools, and reviews mixed productivity evidence: METR's 2025 study found a 19% slowdown that participants perceived as 20% faster, while DORA argues AI amplifies existing team strengths and weaknesses. The article closes with five design decisions for enterprise adoption and a phased rollout plan.

Key points

  • AI-driven development has no official definition; agents do implementation, humans keep spec, review, and merge decisions.
  • METR's 2025 experiment: AI work took 19% longer, yet developers felt 20% faster.
  • Major tools offer sandboxes, approval tiers, and admin settings users cannot override.
  • Key risks: prompt injection, hallucinated packages, secret exposure, review bottlenecks; OWASP lists ten agentic risks.
  • Adoption hinges on five designs: scope, permissions, repo instruction files, verification gates, and measurement.

Ways of having AI help with development have expanded from "completion," which suggests the continuation of code, to "agents," which take on entire tasks. When given instructions, coding agents read code, edit files, run commands and tests, and return the changes as a batch. This approach, where agents handle implementation and testing while humans own the specifications and decisions, is called "AI-driven development" in Japan.

However, using AI does not necessarily make development faster. In a 2025 comparative experiment with experienced developers, work using AI took 19% longer. Yet the participants felt they were 20% faster. Whether adoption succeeds depends less on tool performance than on the design of what to delegate and how to verify it.

  • AI-driven development is an approach where coding agents handle implementation, testing, and fixes, while humans retain decisions on specifications, reviews, and merges. No official definition has yet been established.
  • Similar terms include spec-driven development and vibe coding. The former is a method of writing specifications first and having AI implement them; the latter is playful development that accepts generated code without reading it, and is unsuitable for business use.
  • Major tools include governance features such as sandboxes, approval stages, and administrator settings that users cannot override. Whether to use them is decided by the adopting company.
  • For corporate adoption, it is easier to proceed if you first decide on five points: the scope of delegation, permissions and execution environments, repository instructions, verification gates, and measurement and training.

This article was written based on each company's official documentation and primary sources from research institutions, verified as of November 5, 2026.

Who this article is for

The primary readers are CTOs and development managers deciding whether to introduce coding agents such as Claude Code, Codex, or GitHub Copilot to their development teams. It is also aimed at information systems departments and security officers who need to establish internal rules when engineers on the ground start using agents individually. HR and training staff who want to incorporate AI-driven development into engineer development plans should start reading from "Measure and Grow," one of the five design points.

What is AI-driven development? (3 key points)

  • An approach to development where coding agents are entrusted with code investigation, editing, command execution, and testing as a whole
  • Humans communicate "what to build" through specifications and acceptance criteria, then review the resulting changes and decide whether to merge them
  • Because entire tasks can be delegated, quality and safety collapse if you do not decide how to verify the work in advance

Three stages of AI development support

AI that supports development can be divided into three stages by the size of the unit delegated to it.

StageUnit delegated to AIUnit verified by humansTypical use
CompletionA few lines to a functionEach suggestionSuggesting the continuation of code being written
DialogueAnswers to questions, file-level fixesEach answerAsking about the cause of an error, having a function rewritten
AgentTasks (investigation, editing, command execution, testing)Pull requests (batches of changes)Requesting a bug fix and receiving changes with passing tests

AWS prescriptive guidance describes coding agents as systems that can reason about programming problems, generate and modify code, and interact with the development environment. Unlike completion tools, they differ in that they interpret objectives, gather context from the environment, and propose and execute actions.

Agents come in two types: those that run on a developer's PC and those that run in the cloud and return pull requests. The former, like Claude Code or Codex CLI, run in a terminal or editor, allowing developers to proceed while checking results on the spot. The latter, like the GitHub Copilot cloud agent, work in an isolated environment when assigned an Issue and return results as a pull request.

Differences from spec-driven development and vibe coding

Around AI-driven development, there are several similar terms. "AI-driven development" has no official definition from standards bodies or governments, and its scope varies by user. To align the basis of comparison, this article distinguishes them as follows.

TermContentOriginPositioning in business
AI-driven developmentAn umbrella term for development approaches where agents handle implementation and humans own specifications and decisionsA term widely used in Japan. No single established definitionThe subject of this article
Spec-driven development (SDD)A method of writing what to build and why in a specification, then deriving plans, tasks, and code from itAdopted by GitHub's Spec Kit, AWS's Kiro, and othersOne of the approaches within AI-driven development. Suitable for business use because specifications remain
AI-DLCA development lifecycle where AI handles planning and execution while humans make key decisionsA methodology published by AWS in July 2025Useful as a reference vendor methodology
Vibe codingDevelopment where generated code is accepted without reading it and errors are simply pasted to AIA February 2025 post by Andrej KarpathyThe author himself limited it to throwaway weekend projects. Unsuitable for business development

GitHub's Spec Kit describes spec-driven development as a method of defining what to build and why, and transforming specifications into plans, tasks, and working code. AWS's Kiro creates three files—requirements (requirements.md), design (design.md), and tasks (tasks.md)—before starting implementation.

The term "vibe coding" is sometimes used to mean AI-based development in general. The original post described a playful approach of accepting diffs without reading them, which is a different matter from business quality standards.

Major Coding Agents and Their Governance Features

When deploying in enterprises, what matters is not generation performance but what administrators can restrict. Here is a summary of the governance features of major tools. Since product names and features change frequently, verify them in official documentation at the time of adoption.

ToolWhere it runsMain governance features
Claude Code (Anthropic)Terminal and editor. Also cloud executionPermission modes, deny/ask/allow rules, managed settings, hooks to insert processing before and after operations, sandboxing
Codex (OpenAI)Terminal, editor, and cloudThree sandbox levels (read-only, write to working folder, unrestricted), approval policies, no network access by default, managed settings
GitHub Copilot cloud agentIsolated environment on GitHubCan only be launched by users with write access, can write only to a single branch, cannot approve or merge, human approval required for workflow runs by default, firewall
Kiro (AWS)Editor and terminalSpec-driven development features, organization-wide MCP allowlists (for users authenticated via IAM Identity Center or API keys)

In Claude Code, rules are evaluated in the order of deny, ask, and allow, with the first match determining the outcome. Modes that run without confirmation or automatic modes can be prohibited via managed settings, and cannot be overridden by user settings. The official documentation explicitly states that instructions written in CLAUDE.md and similar files only guide Claude's behavior and do not change the scope of permissions.

Codex recommends, for folders under Git management, a configuration combining write access to the working folder with approval when needed, and does not connect to the network by default. GitHub Copilot cloud agent can neither approve nor merge the pull requests it works on, and the requester also cannot approve that pull request.

Product restructuring continues as well. GitHub renamed its agent from coding agent to cloud agent. AWS announced on April 30, 2026 that it will end support for the Amazon Q Developer IDE plugin and paid plans on April 30, 2027, and is directing users to Kiro as the migration destination.

In addition, the way instruction files are written across these tools is converging on a common format called AGENTS.md. AGENTS.md was created by OpenAI and donated in December 2025 to the Agentic AI Foundation under the Linux Foundation. According to the official website, it is used in more than 60,000 open source projects, and is supported by Codex, GitHub Copilot, Gemini CLI, Cursor, and others.

Productivity Research Results Are Divided

The effects of AI-driven development vary depending on how they are measured. When making adoption decisions, perceived figures and measured figures need to be read separately.

StudySubjectsMain findings
METR (July 2025)16 experienced open source developers, 246 issuesUsing AI made work time 19% longer. Prior expectation was a 24% reduction, and perceived reduction after completion was also 20%
METR (February 2026 follow-up)57 people, over 800 tasksEstimated reductions in work time were obtained (18% for original participants, 4% for new participants). However, because the number of developers declining to participate increased significantly, METR itself states this is not a reliable result reflecting current effects
DORA (Google, September 2025)About 5,000 technology professionals90% use AI at work, and over 80% believe their productivity has increased. 30% trust AI-generated code little or not at all
Stack Overflow Developer Survey (2025)Developers84% use or plan to use AI. 46% do not trust its accuracy, exceeding the 33% who do. 66% are frustrated with output that is "almost right but not quite"

METR's 2025 experiment used tools available at the time, and METR itself notes on its page that the results have become outdated. Even so, the fact that self-perception and actual measurement diverged in opposite directions remains a useful reference when considering how to evaluate adoption.

DORA's 2025 report concluded that AI does not fix teams but amplifies existing strengths and weaknesses. It also lists seven capabilities for realizing AI's benefits: a clearly communicated AI policy, a healthy data foundation, AI-accessible internal data, strong version control, working in small increments, a user-centric approach, and a high-quality internal platform. Introducing agents into teams with weak testing and review mechanisms also amplifies those weaknesses.

Common Problems When Using in Enterprises

Coding agents can read files, execute commands, and communicate externally. Since humans do not verify each item individually, the impact of problems tends to spread more widely.

ProblemWhat happensReported in primary sources
Instruction hijacking (prompt injection)Agents follow instructions written in issues, READMEs, or dependency packagesInvariant Labs reported in May 2025 that by having an agent read a malicious issue in a public repository, it could be made to exfiltrate private repository information into a public pull request
Non-existent packagesAI writes package names that don't actually exist, and attackers publish malicious packages under the same namesA 2025 USENIX Security paper generated 576,000 code samples across 16 models and reported that, of the packages referenced by the code, the proportion that didn't exist averaged over 5.2% for commercial models and over 21.7% for open-source models
Secret exfiltrationAn agent reads .env or key files, which then end up in logs or outbound communicationsThe official Claude Code documentation shows example rules for denying reads of .env and similar files
Review bottlenecksThe volume of changes grows, reviews can't keep up, and some changes get merged without being readDORA points out that AI also amplifies existing weaknesses
Use under personal contractsHandling company code with personal accounts the company doesn't know aboutAnthropic states that under commercial terms such as Team, Enterprise, and API, code and prompts are not used for training. On consumer plans, handling depends on the user's choices

In December 2025, OWASP published the "Top 10 for Agentic Applications," summarizing risks specific to agentic AI in 10 items. Goal hijacking, tool misuse, privilege abuse, unintended code execution, and more are listed, and they apply directly to coding agents as well. In Japan, the AI Safety Institute (AISI) updated its evaluation perspectives in Version 1.20 of the "Evaluation Perspectives Guide for AI Safety" (July 2026), taking the spread of AI agents into account.

Five design decisions for enterprise adoption

From here on, we present five design decisions to make before using coding agents in an enterprise, as examples from the editorial team.

1. Decide the scope to delegate

First, decide which work in which repositories to delegate to agents. Opening it up to the whole company at once makes it hard to narrow down causes when problems occur.

CategoryExample workHandling
Easy to delegateAdding tests, fixing small bugs, updating documentation, resolving type and lint errorsInclude in the pilot
ConditionalAdding features, refactoring, updating librariesDelegate only after writing specs and acceptance criteria
Not for nowAuthentication, payments, handling of personal information, production configurationHumans write it; agents are used only for investigation and explanation

2. Decide permissions and execution environment

Next, decide the environment the agent runs in and the range of operations it can perform without confirmation. For types that run on a developer's PC, use sandboxing and network restrictions, and

.env

deny reads of .env and key files. Claude Code and Codex have settings that administrators distribute and users cannot override; prohibiting modes that run without confirmation is also done here.

For cloud-based types, verify the credentials the agent can use and its communication destinations. The GitHub Copilot cloud agent restricts internet connections via a firewall and limits writable branches to one. To do the same in an in-house environment, give agent accounts only minimal permissions.

3. Put instruction files in the repository

Agents read instruction files placed in the repository and work accordingly. Writing build and test commands, code conventions, and directories that must not be touched in AGENTS.md or CLAUDE.md makes the resulting changes consistent. Codex reads AGENTS.md files in order from the repository root down to the working folder, prioritizing those in deeper levels.

However, instruction files have no enforcing power. The official Claude Code documentation asks that operations you want to reliably block be stopped with permission rules or hooks that insert processing before operations. "Do not connect to the production database" should not only be written in the instructions but also blocked by configuration.

4. Have verification gates

Verify agent changes as much as or more than human-written changes. Always run tests, type checks, lint, and security checks in CI, and for changes that add dependency packages, verify that the package actually exists and is trustworthy.

Humans own review and merging. The GitHub Copilot cloud agent is designed so that the agent cannot merge on its own, and the requester cannot approve either. With in-house rules too, having someone other than the requester review and merge reduces changes that pass without being read.

5. Measure and grow

Measure effects with development metrics, not by feel. As METR's experiment showed, a person's perception can diverge in the opposite direction from actual measurements. Compare lead time for changes, time spent on reviews, and the number of reworks and incidents after merging, before and after adoption.

Differences in usage also matter greatly. If how specs are written, how work is divided into delegable units, and what to look for in reviews are not aligned, results vary widely between people even with the same tool. Align basic usage through training, and share successful instruction files and settings across the team.

How to roll out adoption

Here is an example rollout based on the five design decisions. The durations are rough guidelines assuming a company with a few development teams.

PhaseDuration guidelineWhat to do
1. Decide policy and scope2 weeksDecide which tools to use and the contract (commercial plan), the scope to delegate, and prohibited operations. Survey the actual state of personal use in the field
2. Pilot4-6 weeksStart with 1-2 teams, beginning with easy-to-delegate work. Create templates for instruction files and settings, and measure pre-adoption metrics

Frequently Asked Questions (FAQ)

Q1. What is AI-driven development?

A. It is a development approach in which coding agents are entrusted with code investigation, editing, command execution, and testing as a whole, while humans retain decisions on specifications, review, and merging. There is no official definition by standards bodies or governments; it is a term widely used in Japan. AWS refers to a similar approach as AI-DLC, and GitHub and AWS describe similar practices under the name spec-driven development.

Q2. How does it differ from spec-driven development?

A. Spec-driven development is one approach within AI-driven development. You write what to build and why in a specification, then derive plans, tasks, and code from it. Because the specification remains as a file, review and handover are easier, making it well suited to business development.

Q3. Can vibe coding be used for business?

A. It is not suited to business development. Vibe coding is a term coined by Andrej Karpathy in February 2025, referring to accepting generated code without reading it. He himself limited it to throwaway weekend projects. For business, write specifications and review changes before merging them.

Q4. Does AI-driven development actually make development faster?

A. It depends on conditions. In METR's 2025 experiment, experienced developers' work time was 19% longer when using AI, while they felt they were 20% faster. DORA's 2025 report concludes that AI amplifies both a team's strengths and weaknesses. Establish testing and review mechanisms, and measure effects by lead time and rework rather than by perception.

Q5. What are the security considerations for coding agents?

A. Because agents can read files, execute commands, and communicate externally, watch out for prompt hijacking, secret exfiltration, and ingestion of nonexistent packages. Use sandboxes and network restrictions,

.env

deny reads to paths such as these, and have humans verify any addition of dependency packages. Contract under your company's commercial plan, and never let personal accounts handle in-house code.

Q6. What is AGENTS.md?

A. It is a common instruction file format for telling coding agents about build and test commands and coding conventions. It was created by OpenAI and donated in December 2025 to the Agentic AI Foundation under the Linux Foundation. Codex, GitHub Copilot, Gemini CLI, Cursor, and others support it. Since instruction files are not enforceable, block operations you want to reliably prevent through each tool's permission settings.
