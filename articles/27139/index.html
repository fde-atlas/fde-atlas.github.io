Technology Stack Panorama · OpenFDE

Original title: 技术栈全景 · OpenFDE

OpenFDE · 前沿部署工程师社区 · 2026-10-16 · 2 min read

Summary

This OpenFDE community article maps the FDE tech stack across five layers: full-stack development, RAG, agents/workflows, evals and observability, and cloud/security infrastructure. It argues FDEs need not master every tool but should know each area's essentials and reusable open-source projects, listing concrete examples like LlamaIndex, LangGraph, Ragas, Langfuse, and Terraform. Job postings from Google and OpenAI are cited to show these skills are genuinely required. The core claim: the best FDE is not the strongest at any single point but the one who can connect all five layers into a production system that runs at customer sites.

Key points

  • The FDE stack spans five layers: full-stack, RAG, agents, evals, infrastructure.
  • Permission-aware retrieval is a hard requirement for enterprise RAG deployments.
  • Google's FDE role requires production-grade agentic workflows and MCP servers.
  • LLM-as-judge cannot replace golden datasets and human review of failure paths.
  • OpenAI's government FDE role demands Azure, Kubernetes, and Terraform experience.

An FDE doesn't need to master every tool, but needs a complete "map of the arsenal": knowing, across the five domains of full-stack, RAG, agents, evals, and infrastructure, which essential points must be mastered in each, and which open-source projects can be used directly as skeletons. Below we go through the five domains one by one, naming a batch of real, representative projects.

Don't try to learn everything at once. First use the competency model to identify your weak dimensions, then pick one project in the corresponding domain and build it hands-on—an FDE's tech stack is learned by "using," not by "reading."

1 · Programming and Full-Stack

An FDE's foundation is the ability to independently deliver a full-stack system: frontend, backend, data, and deployment all in one, because at the client site there is often no existing team to fill in any missing piece. You need to master:

  • Languages and frameworks: Python, TypeScript, React / Next.js, FastAPI / Flask / Node.js
  • Data and communication: PostgreSQL, Redis, REST / GraphQL, Webhooks
  • Delivery: Docker, GitHub Actions / CI/CD

2 · LLM / RAG

This is the main battleground for enterprise knowledge projects. The difficulty is not "dumping documents into a vector store," but permission filtering, data freshness, citation traceability, and answer trustworthiness. You need to master embedding model selection, chunking strategies, metadata filtering, hybrid search, reranking, query rewriting, citation grounding, permission-aware retrieval, RAG evals, and hallucination analysis—among these, permission-aware retrieval is almost a hard requirement for enterprise deployment: for the same question, different roles must see different answers.

  • Orchestration frameworks: LlamaIndex↗ LangChain↗
  • Vector databases: Chroma↗ Qdrant↗ Weaviate↗ Milvus↗ pgvector↗

3 · Agent / Workflow

Moving from "Q&A" to "executable" is far harder than building an ordinary chatbot. You need to master tool calling, MCP servers, agent state, ReAct, planner / executor, human-in-the-loop, multi-agent collaboration, workflow graphs, retry / fallback, sandbox execution, action approval, and trace inspection. Google's FDE role directly lists production-grade agentic workflows, MCP servers, state management, and tracing as core requirements. Google Careers↗

  • Agent frameworks: LangGraph↗ AutoGen↗, CrewAI, Google ADK
  • Protocols and orchestration: MCP servers↗ Temporal↗

4 · Evals / Observability

LLM systems are non-deterministic; without evals and observability they cannot go to production—this is the biggest difference between an AI FDE and traditional software delivery. You need to master golden datasets, offline / online evals, human review, the limitations of LLM-as-judge, regression tests, prompt / version tracking, cost dashboards, latency tracing, tool call traces, error taxonomies, and user feedback loops. Be especially wary of LLM-as-judge—it can accelerate evals, but it cannot replace golden sets and human review targeted at failure paths.

  • Evals: Ragas↗ DeepEval↗ promptfoo↗
  • Tracing and observability: Langfuse↗ Phoenix↗

5 · Cloud / Infra / Security

This determines whether an AI system can enter regulated or high-security environments. You need to master AWS / Azure / GCP fundamentals, VPCs / private networks, Kubernetes and Terraform basics, secrets management, logging / monitoring, SSO / SAML / OAuth, RBAC / ABAC, audit logs, data residency, compliance fundamentals, and on-prem / hybrid deployment. OpenAI's government FDE role directly requires Azure, AWS, Kubernetes, and Terraform experience. OpenAI Careers↗

  • Infrastructure: Kubernetes↗ Terraform↗ OpenTelemetry Collector↗
  • Identity and secrets: Keycloak↗ Vault↗

An FDE's differentiation lies not in "how many tools you can use," but in being able to connect these five layers—full-stack, RAG, agents, evals, and infra—into a production system that runs at the client site, is measurable, and is reusable. The person strongest at any single point is not necessarily the best FDE; the one who can connect the entire chain is.

Turning this map into muscle memory requires a progressive practice path—see the learning roadmap; to dig into each project's official documentation and more first-hand resources, see the FDE signals library.
