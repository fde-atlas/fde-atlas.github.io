FDE vs AI Consultant: Which Path to Train For

Key takeaways

  • A forward deployed engineer ships code that runs in a customer's systems, and is judged on the running system.
  • Strategy-led AI roles centre on options, recommendations and explanation, with less time in the codebase.
  • Five questions about where you want your output to live will show which path to train for.
  • Python, APIs, SQL and Git come first on either path, so the early steps overlap.

Engineers in AI often ask a version of this question: should I train to be a forward deployed engineer (FDE), or is an AI consultant role the better target? The titles sound close, but the daily work is different, so the training should be different too.

The short answer: a forward deployed engineer ships code that runs inside a customer's systems. A strategy-led AI role spends more time on options, recommendations and explaining trade-offs to leaders, and less time in the codebase. Both need a working understanding of models. Only the FDE path asks you to build the thing and own the result.

What a forward deployed engineer does

An FDE works close to one customer problem. The work usually follows four steps: learn the workflow from the people who do it, connect a model to the real data, build the tool, and leave a system that someone else can run. You are judged on the running system, not on a slide that describes it.

That is why the FDE path starts with software basics, then adds model APIs, retrieval, evals, agents, data access and handover. The learning path sets out that order.

What a strategy-led AI role covers

Strategy-led AI roles focus on where AI could help a business, how the options compare, what a plan costs and what could go wrong. These roles need domain knowledge, clear writing and a good sense of risk. They rarely need you to debug a failing pipeline at night.

If you enjoy the build, the FDE path fits. If you enjoy shaping the decision before anything is built, a different path may suit you better, and it needs different training.

Five questions to decide

  • When the output is wrong, do you want to open the logs and fix the pipeline yourself?
  • Do you want your main output to be code that runs, or a document that guides a decision?
  • Would you rather stay with one customer's data for weeks, or move across several short projects?
  • Are Python, HTTP APIs, SQL and Git already comfortable for you?
  • Do you want to stay close to the system after launch, to see whether it still works?

If most answers point to building, train for the FDE path. If most point to the decision and the explanation, look for a strategy path instead.

What to do first

Whichever path you pick, the first steps overlap. Build one small retrieval tool over real documents, then write an eval script that scores it. Those two projects show quickly whether you enjoy the build, and they give you something concrete to talk about.

Frequently asked questions

Try it first: turn on practice mode to hide the answers, think through each question, then reveal.

Is forward deployed engineering the same as a strategy-led AI role?

What a good answer covers

No. An FDE builds and owns working systems at a customer, while a strategy-led role mostly shapes decisions and recommendations.

Do I need to be a strong programmer before I train for the FDE path?

What a good answer covers

Yes, you need Python, HTTP APIs, SQL and Git before the model-specific work. The cohort assumes working software skills, not a from-scratch coding course.

How do I know which path suits me?

What a good answer covers

Build a small retrieval tool and an eval script, then notice which part you want to repeat. If you want to keep improving the system after it ships, the FDE path fits.
