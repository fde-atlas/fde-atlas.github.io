SkillsBench (2026) Explained for FDEs

FDE Interviews · 2026-10-17 · 4 min read

Summary

SkillsBench, led by BenchFlow, is the first rigorous measurement of whether Agent Skills actually help. From 400 community submissions, 87 real tasks with deterministic tests survived review. Each ran three times with and without expert-written Skills across 18 model-harness combinations. Average pass rate rose from 33.9% to 50.5%, with gains in every setup. Benefits were largest in domains models know least, like natural science and media production. Compact Skills (one to three per task) beat comprehensive documentation, which added almost nothing, and agents writing their own Skills lowered scores by 8-12 points.

Key points

  • 87 curated real tasks, each tested with and without Skills across 18 model-harness setups
  • Mean pass rate rose from 33.9% to 50.5%; every setup improved (+4.1 to +25.7 points)
  • Gains were largest in specialized domains like natural science (+28.8) and media production (+24.1)
  • One to three compact Skills per task worked best; exhaustive documentation gained only 0.7 points
  • Self-written agent Skills hurt performance by 8-12 points; harness choice also mattered

The paper in one minute

An Agent Skill is a folder an agent can discover and load while it works: a required

SKILL.md

file of instructions, plus optional scripts, templates and reference files. Anthropic introduced the format, and harnesses such as Claude Code, Codex CLI, Gemini CLI and OpenHands support it. A Skill sits between a prompt and a tool. It carries procedure ("how we do X here") and can ship executable code, without changing the model. By the authors' snapshot, community collections held about 2 million distinct Skills. Nobody had measured whether they help.

SkillsBench, a large community effort led by BenchFlow, measures it with paired runs. The authors gathered 400 task submissions from 142 contributors and kept 87 after automated checks and human review. Each task is real work in a container, such as security analysis, scientific signal processing, media conversion, finance or software engineering, with a human-written instruction, a reference solution and a deterministic test suite. Each comes with Skills written by domain experts independently of the task, carrying general expertise for that kind of problem, never the answer. The instruction never mentions the Skills; the agent has to find them.

Each task ran three times without Skills and three times with them, under 18 combinations of model and harness. Curated Skills raised the average pass rate from 33.9% to 50.5%. Every setup improved, from +4.1 to +25.7 points. Gains were biggest in domains models know least, such as natural science (+28.8) and media production (+24.1), and smallest in mathematics (+9.7) and software engineering (+11.6). One to three Skills per task worked better than four or more, and compact Skills beat comprehensive documentation, which added almost nothing. When agents wrote their own Skills before solving, results got worse.

Research notes: the problem, approach and results

average pass-rate gain from curated Skills across 18 model–harness setups

gain from comprehensive, exhaustive Skill documentation, against +19 to +21.5 for compact or standard Skills

change when agents wrote their own Skills first and then used them

Agent Skills spread fast, with millions published in community collections, but nobody had measured whether adding a Skill actually helps an agent, by how much, or when it hurts.

Run 87 real tasks with deterministic tests twice under each of 18 model and harness setups, once without Skills and once with expert-written Skills, and compare the paired results.

Mean pass rate rose from 33.9% to 50.5%. Gains ranged from +4.1 to +25.7 points by setup, were largest in specialized domains, and favored one to three focused Skills over long ones.

Why it matters to an FDE

Skills are a practical way to put a customer's procedures into an agent without fine-tuning: how they format reports, which internal API to call in what order, the quirks of their data. This paper is the first measurement of what works.

Write procedures, not manuals. The winning Skills were short and specific: executable scripts with sensible defaults, the authoritative data source and its parsing quirks, exact output-format constraints, invariants the answer must satisfy. Comprehensive documentation gained 0.7 points against about 19 to 21 for focused Skills. Put in what the agent cannot work out for itself and leave out the rest.

Fewer Skills per task. Tasks with four or more Skills gained about half as much as those with one to three. Bundling every Skill a team has written into every agent dilutes the guidance and can conflict.

Test every Skill with and without. Thirteen of 87 tasks did worse with Skills on average, typically because a Skill prescribed a heavy pipeline that displaced the agent's simpler default approach. Run the customer's tasks both ways before shipping a Skill library.

The harness matters. The same model gained different amounts in different harnesses: Claude Opus 4.7 reached 61.2% in Claude Code and 53.1% in OpenHands. Evaluate Skills in the harness the customer will actually run.

Do not let the agent write its own. Skills an agent generated for itself lowered scores by 8 to 12 points. A human expert's procedure is the asset.
