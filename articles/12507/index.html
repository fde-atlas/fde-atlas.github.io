Multi-Tenancy and Data Isolation

FDE Interviews · 2026-06-14 · 1 min read

Summary

This piece explains multi-tenancy: serving many customers from shared infrastructure while ensuring no tenant can access another's data. Isolation strategies span a spectrum from row-level filtering to fully separate databases, trading cost against blast radius. The central argument for AI systems is that tenant scope must be enforced below the model—in code that filters queries and scopes credentials—never through prompt instructions, since a single prompt-injected document can defeat prompt-level isolation.

Key points

  • Multi-tenancy means shared infrastructure with guaranteed data isolation between tenants
  • Isolation ranges from row-level filtering to separate databases, balancing cost and blast radius
  • Tenant scope must be enforced in code below the model, not in prompts
  • A single prompt-injected document can break prompt-level isolation
  • Query filtering and credential scoping are the key enforcement mechanisms

Multi-tenancy is serving many customers from shared infrastructure while guaranteeing no tenant can ever see another's data. The isolation strategies run a spectrum from row-level filtering to fully separate databases, trading cost against blast radius. The non-negotiable rule for AI systems: tenant scope is enforced below the model, in code that filters queries and scopes credentials, never by instructing the model in a prompt. A single prompt-injected document is enough to break prompt-level isolation.
