What System Design Questions Are Asked in the Google FDE Interview?

Design Gurus · 2026-11-20 · 4 min read

Summary

This article breaks down the system design round of Google's FDE interview, where candidates design an AI system—usually an agent or a retrieval system—for a single enterprise customer. The difficulty lies less in traffic and scale than in safely integrating with customer systems, proving correctness, and meeting cost and latency budgets. It categorizes reported question types (agentic workflows, RAG over private data, agent reliability, data foundations, production readiness), lists what interviewers expect for each, and offers a six-step framework plus preparation resources.

Key points

  • Typical questions: enterprise workflow agents, RAG over private documents, agent reliability, data foundations.
  • Interviewers expect tool permissions, human approval for writes, step budgets, and loop detection.
  • Google job postings name ADK, LangGraph, MCP, and RAG chunking optimization as desired skills.
  • Production readiness covers evaluation sets, tracing with shared ids, cost per request, and latency.
  • The proposed framework: clarify goals, list integrations, build minimal read-only version, add guards, prove it works, plan growth.

The Google FDE system design round asks you to design an AI system for one enterprise customer, usually an agent or a retrieval system over the customer's private data. Reported questions ask you to design an agentic system for a specific enterprise workflow. Follow-ups ask how you would scale the agent, how you would keep it safe, and how you would handle an agent stuck in an infinite loop. Unlike a classic system design interview, the hard part is rarely traffic. It is connecting the model to the customer's existing systems safely, proving the system is correct, and keeping cost and latency inside a budget.

Agentic Workflow Questions

An agent is a program in which a model chooses which tool to call next, reads the result, and repeats until the task is done. A typical question asks for an agent that handles a business process, such as resolving shipment billing disputes for a freight company. Interviewers expect you to name each tool, such as a billing API or a shipment database, and say what the agent may read and what it may change. Any action that moves money or changes a customer record should require human approval.

Google's own postings ask for experience with multi-agent frameworks such as Google's Agent Development Kit (ADK) and LangGraph. They also ask for the Model Context Protocol (MCP), a standard way to expose a tool to a model, together with OAuth sign-in for those tools. Mention these by name where they fit, but do not let the framework replace the design.

Retrieval Questions

Retrieval-augmented generation (RAG) means the system first searches the customer's documents and then gives the matching passages to the model. A common question is a question-answering system over thousands of internal documents. Expect follow-ups on how you split documents into passages, how you stop a user from seeing a document they lack permission for, and how you check that answers quote real sources. One Applied AI posting asks directly for experience "optimizing retrieval-augmented Generation (RAG) chunking to prevent hallucinations."

Reliability and Safety Questions

Candidates report follow-ups on agents that never stop. Give concrete limits: a maximum of, for example, 15 tool calls per task, detection of the same tool called with the same input three times, and a time limit for the whole task. When a limit is reached, the agent should stop and hand the case to a person with a summary of what it tried. For safety, explain input filtering, output checks, and least-privilege access, which means each tool gets only the permissions it needs.

Data Foundation Questions

Data Cloud FDE roles add questions about the data that agents depend on. The postings mention lakehouse design, metadata, access controls "that let custom agents act on trusted data," and de-identifying sensitive data such as payment card and health records. Expect a question like "This customer wants an agent to answer questions over BigQuery tables. What do you build first?" A strong answer starts with table descriptions, access rules, and a test set of real questions before any agent code.

Production Readiness Questions

Google postings repeatedly mention "LLM-native metrics" such as tokens per second and cost per request, plus evaluation pipelines and tracing. Be ready to say how you measure answer quality on a fixed set of test questions. Explain how you trace one user request across several services with a shared id. Then say how you would cut cost by half, for example with a smaller model for simple steps or with caching of repeated context.

A Structure for Any Question

  • Clarify the customer goal. Who uses the system, what decision it supports, and what result the customer measures.
  • List the integrations. Every system the agent reads from or writes to, and who owns it.
  • Design the smallest useful version. One workflow, read-only first, with human approval for every write.
  • Add guards. Step budgets, permissions, input and output checks.
  • Prove it works. An evaluation set, tracing, and a target for cost and latency.
  • Explain how it grows. More workflows, more users, and what fails first.
