1. Introduction: Microsoft Azure AI services and naming in 2026

Microsoft Azure provides a broad set of AI services for building intelligent applications, generative AI solutions, enterprise copilots, AI agents, document-processing systems, speech applications and computer-vision solutions. Organisations use them to automate operations, improve customer experience, process large volumes of documents, analyse images and understand natural language.

Take a bank that wants to automate customer support and loan processing. It might need:

  • Azure OpenAI (through Microsoft Foundry) for conversational AI.
  • Microsoft Foundry for model access, agent development and evaluation.
  • Azure AI Search for enterprise RAG retrieval.
  • Azure Document Intelligence to extract information from loan documents.
  • Azure Language for entity extraction and PII detection.
  • Azure Speech for voice-based support.
  • Azure Vision for image analysis.
  • Azure AI Content Safety to detect harmful content and prompt attacks.
  • Azure Machine Learning for custom models such as credit-risk scoring.
  • Microsoft Entra ID for authentication and authorisation.

Combined, these form an end-to-end enterprise AI platform.

Naming: what interviewers expect you to know

Microsoft's AI branding has changed several times — Cognitive Services became Azure AI services, Azure AI Studio became Azure AI Foundry, and that is now Microsoft Foundry. The prebuilt services (Speech, Translator, Language, Vision, Document Intelligence, Content Understanding, Content Safety and others) are now documented as Foundry Tools. You will still hear "Azure OpenAI", "Azure AI Search" and "Cognitive Services" in interviews and in older projects, so recognise all of them.

Microsoft lists the following as retired — still running for some existing applications, but not to be used for new ones: Anomaly Detector, Content Moderator, Language Understanding (LUIS), Metrics Advisor, Personalizer and QnA Maker. Their replacements are conversational language understanding (CLU) and custom question answering in Azure Language, and Azure AI Content Safety. Speaker Recognition in the Speech service has also been retired. Mentioning these in an interview shows you work with current Azure, not 2022 tutorials. (Microsoft Learn: What are Foundry Tools?)

3. Microsoft Foundry and Azure AI platform interview questions

Q1. What is Microsoft Foundry?

Microsoft Foundry is Microsoft's platform for building, deploying and managing AI applications and agents. It brings together a model catalog, model deployments, Foundry Agent Service, tools, evaluations, guardrails, tracing and governance under one resource and project structure. It was previously called Azure AI Foundry, and before that Azure AI Studio.

Q2. What is the difference between Microsoft Foundry and Azure OpenAI?

Foundry is the broader platform: models from many providers, agents, tools, evaluation, safety and observability. Azure OpenAI is one family of models inside it — OpenAI models hosted and sold by Microsoft on Azure infrastructure, with Azure identity, networking and data-handling commitments. A strong answer: "Azure OpenAI is a model offering; Foundry is where I deploy it, build the agent around it, evaluate it and monitor it."

Q3. What is a Foundry project?

A project is the workspace inside a Foundry resource where a team organises its model deployments, agents, connections, datasets, evaluations and traces. Access is controlled with Azure RBAC, so different teams can have separate projects under the same resource.

Q4. What are Foundry Tools?

Foundry Tools are Microsoft's prebuilt and customisable AI services, exposed through REST APIs and SDKs. The current list includes:

  • Speech
  • Translator
  • Language
  • Content Understanding
  • Document Intelligence
  • Vision and Custom Vision
  • Azure AI Search
  • Content Safety
  • Immersive Reader

Use them when a task is well defined (OCR, transcription, translation, PII detection) and a purpose-built model is cheaper, faster and more predictable than a general LLM.

Q5. What is a foundation model?

A large model trained on broad data that can be adapted to many tasks through prompting, retrieval or fine-tuning. Examples include language models, vision-language models and embedding models.

Q6. What is the model catalog?

The Foundry model catalog lists the models you can deploy — models sold directly by Azure (including Azure OpenAI) and models from partners and the community. Before choosing one, check deployment options, regional availability, quota, licensing and whether it supports the features you need (tools, structured output, vision, agents).

Q7. What is model deployment?

A deployment makes a chosen model version available at an endpoint with a configured deployment type and capacity. Your application calls the deployment, not the raw model. See our Azure for AI engineers guide for deployment types and quotas.

Q8. What is inference?

Inference is using a trained model to produce an output for new input — for example, a user asks the chatbot a question and the deployed model generates the answer. Most of an AI application's running cost is inference.

Q9. What is model evaluation?

Measuring output quality against defined criteria. Common dimensions are relevance, groundedness, accuracy, fluency, safety, latency and cost. Foundry provides built-in evaluators (including LLM-as-judge evaluators) that you can run on a test dataset and in CI/CD. More in our RAG evaluation metrics guide.

Q10. What is responsible AI?

Building and operating AI with safeguards for fairness, reliability and safety, privacy and security, inclusiveness, transparency and accountability — Microsoft's six responsible AI principles. In practice that means content filters, evaluations, human review for high-impact decisions, logging and documentation.

Q11. What is the difference between prebuilt AI services and custom machine learning?

Prebuilt services give ready-to-use capabilities through an API. Custom ML means training or adapting models for a specific business problem.

  • Extracting invoice fields: Document Intelligence (prebuilt invoice model).
  • Predicting equipment failure from historical sensor data: custom ML in Azure Machine Learning.

Q12. When should you use Microsoft Foundry instead of building everything from scratch?

When its managed models, agents, evaluation, identity, guardrails and tracing cover your requirements — that removes a lot of undifferentiated platform work. You still write custom code for business logic, integrations and specialised workflows, and you may host your own agent code as a Foundry hosted agent.

4. Azure OpenAI interview questions and answers

Q13. What is Azure OpenAI?

Azure OpenAI gives access to OpenAI models through Azure, with Microsoft Entra authentication, private networking, regional deployment choices and Azure's data-privacy commitments (prompts and outputs are not used to train the models). It is used for chat, summarisation, classification, extraction, code generation and agents.

Q14. What are the main use cases of Azure OpenAI?

  • Customer-support chatbots
  • Enterprise knowledge assistants (RAG)
  • Document and call summarisation
  • Email and report drafting
  • Code generation
  • Contract analysis
  • Text classification and routing
  • Natural-language querying of data
  • AI agents that call business tools

Q15. What is a deployment in Azure OpenAI?

A named instance of a specific model version with a deployment type (for example Global Standard, Data Zone, regional Standard, Provisioned or Batch) and a capacity quota. Your code calls the deployment name.

Q16. What is the difference between a model and a deployment?

The model is the underlying AI model and version. The deployment is your configured, callable instance of it, with its own name, type, capacity and content-filter configuration. You can have several deployments of the same model — for example one per environment.

Q17. What is a system prompt?

Instructions that set the model's role, behaviour and boundaries:

You are a banking customer-support assistant.
Answer only using approved banking information provided in the context.
Do not invent interest rates or fees.
Do not reveal confidential customer information.
If the information is unavailable, say so and offer to connect the customer to an agent.

A system prompt guides behaviour; it is not a security control on its own.

Q18. What is temperature?

A setting that controls output randomness. Lower values give more predictable output (good for extraction and classification); higher values give more variation (good for brainstorming). Some reasoning models do not support it, so check the model's parameters.

Q19. What is max output tokens?

The upper limit on tokens the model may generate for a request, within the model's own limit. It controls cost and latency and prevents runaway responses.

Q20. What is tokenisation?

Breaking text into tokens — words, sub-words or characters — that the model processes. Pricing, rate limits and context windows are all measured in tokens.

Q21. What is a context window?

The maximum number of tokens (input plus output) a model can handle in one request. Long chat histories and large retrieved contexts must fit inside it, which is one reason RAG retrieves only the most relevant chunks.

Q22. What is function calling?

The model returns a structured request to call a function you defined, with JSON arguments. Your application decides whether to run it.

Example: a customer asks "What is my account balance?" The model asks for

get_account_balance

. Your application must authenticate the user, check they own the account, call the backend and return the result — the model never touches the database directly.

Q23. What is structured output?

Constraining the response to a JSON schema, where the model supports it:

{
  "customer_intent": "loan_application",
  "loan_type": "home_loan",
  "priority": "medium"
}

It makes model output safe to parse in code. Still validate the values.

Q24. What is streaming?

Sending generated tokens to the client as they are produced (server-sent events) instead of waiting for the full response. It cuts perceived latency in chat interfaces, although total generation time is the same.

Q25. What is fine-tuning?

Training a supported model further on your own examples to change its behaviour — output format, tone, domain style or a narrow task. It does not keep a model up to date with changing facts; that is what RAG is for.

Q26. What is the difference between RAG and fine-tuning?

RAGFine-tuning
Retrieves external information at query timeChanges model behaviour through training
Best for changing company documentsBest for specialised task behaviour or format
Can cite sourcesDoes not provide source references
Knowledge stays outside the modelTraining updates model weights
Update by re-indexing documentsUpdate by running another training job

Details in RAG vs fine-tuning.

Q27. How do you secure Azure OpenAI?

  • Microsoft Entra ID authentication instead of API keys (disable key auth where possible)
  • Azure RBAC with least privilege
  • Managed identities for applications
  • Private endpoints and disabled public network access
  • Key Vault for any remaining secrets
  • Content filters and guardrails
  • Diagnostic logging and monitoring
  • Data classification and retention policies

Q28. What is a managed identity?

An identity that Azure creates and manages for a resource, so the resource can get Entra tokens without stored credentials. For example, an Azure Function with a managed identity can call Azure OpenAI, Azure AI Search and Key Vault once it is granted the right roles — no keys in code or configuration.

5. Azure AI Search interview questions and answers

Q29. What is Azure AI Search?

A managed search service for indexing and querying content. It supports full-text (keyword) search, vector search, hybrid search, semantic ranking, filters, facets and agentic retrieval, and it is the most common retrieval layer for RAG on Azure.

Q30. Why do we use Azure AI Search in RAG?

It stores document chunks with their text, vectors and metadata, and returns the most relevant chunks for a question. Those chunks are passed to the LLM so it can answer from your data and cite sources. See what is RAG.

Q31. What is a search index?

A schema of fields plus the documents stored in it:

{
  "id": "policy-101",
  "title": "Home Loan Policy",
  "content": "Eligibility requirements...",
  "country": "UK",
  "department": "loans"
}

Each field has attributes such as searchable, filterable, sortable, facetable and retrievable.

Q32. What is a vector field?

A field that stores an embedding (an array of floats) with a fixed number of dimensions that must match the embedding model, plus a vector search profile that defines the algorithm (HNSW or exhaustive KNN).

Q33. What is vector search?

Converting the query into an embedding and finding the indexed vectors closest to it, so results match by meaning rather than exact words.

Q34. What is hybrid search?

Running keyword and vector queries in one request and merging the results with Reciprocal Rank Fusion (RRF). It handles both meaning and exact terms.

Example: "Find policy HL-2026-101 for UK home loan eligibility" — vector search understands "home loan eligibility", keyword search matches the exact code "HL-2026-101". More in hybrid search and reranking.

Q35. What is semantic ranking?

A second-stage reranker that uses Microsoft language models to reorder the top results (up to 50) by how well they answer the query. It can also return captions and answers. It improves ordering; it does not retrieve new documents.

Q36. What is a semantic configuration?

The index setting that tells the semantic ranker which fields to use — a title field, content fields and keyword fields — in priority order.

Q37. What is an embedding model in Azure AI Search?

The model that turns text (or images) into vectors, such as an Azure OpenAI text-embedding model. With integrated vectorisation, Azure AI Search calls the embedding model itself during indexing and at query time.

Q38. What is the difference between vector search and semantic ranking?

Vector search retrieves results by embedding similarity. Semantic ranking reorders an existing result set using a language model. They are complementary — a common production setup is hybrid search plus semantic ranking.

Q39. What is chunking in Azure RAG?

Splitting documents into smaller passages before embedding, so each chunk is focused enough to retrieve precisely and small enough to fit in the prompt. In Azure AI Search you can use the Text Split skill or Document Layout skill, or chunk in your own pipeline. See RAG chunking strategies.

Q40. How do you select the right chunk size?

Evaluate it against your own data and queries:

  • Document structure (headings, tables, clauses)
  • Average section length
  • Typical query patterns
  • Retrieval precision and recall on a test set
  • How much context the answer needs
  • Token cost and latency

There is no universally optimal chunk size; test two or three options and measure.

Q41. What is metadata filtering?

Restricting results using filterable fields, written as OData filters:

country eq 'USA' and department eq 'credit_cards' and document_type eq 'policy'

It keeps answers relevant to the right region, product or document type.

Q42. What is an indexer?

A crawler that pulls data from a supported source (Blob Storage, ADLS Gen2, Azure SQL, Cosmos DB, SharePoint and others) into an index on a schedule, with change detection. You can also push documents directly with the SDK.

Q43. What is a skillset?

A pipeline of AI enrichment steps an indexer runs during indexing — OCR, text splitting, entity recognition, language detection, embedding generation or a custom Web API skill.

Q44. What is OCR?

Optical Character Recognition: extracting machine-readable text from images and scanned documents.

Q45. What is a knowledge source in Azure AI Search?

In agentic retrieval, a knowledge source is a reusable definition of where content comes from — an existing search index or a supported remote source — which a knowledge base queries.

Q46. What is agentic retrieval?

A multi-query retrieval approach for complex questions. Azure AI Search uses an LLM to plan the query, break it into focused subqueries, run them in parallel against knowledge sources, rerank the results and return grounding data (optionally with a synthesised answer). Some parts are in preview, so check current status before production use. (Microsoft Learn: agentic retrieval)

Q47. How do you improve Azure AI Search retrieval accuracy?

  • Improve document parsing (tables, headers, scanned pages)
  • Tune chunk size and overlap
  • Choose a suitable embedding model
  • Add useful metadata and filters
  • Use hybrid search
  • Enable semantic ranking
  • Tune k and the number of chunks sent to the model
  • Test with real user questions and keep an evaluation set

Q48. How do you secure Azure AI Search?

  • Entra ID authentication and RBAC (disable API keys where possible)
  • Managed identities for indexers and applications
  • Private endpoints and network restrictions
  • Document-level security: store allowed users/groups on each chunk and filter on the caller's verified identity, or use the built-in document-level access features where supported

Never let the model or the user choose the security filter. The application must build it from the authenticated identity.

6. Azure Document Intelligence interview questions

Q49. What is Azure Document Intelligence?

A Foundry Tool (formerly Form Recognizer) that extracts text, layout, tables, key-value pairs and specific fields from documents, so document-heavy processes can be automated. Read more about document parsing for RAG.

Q50. What are the main use cases?

  • Invoice processing
  • Receipt extraction
  • Bank statement processing
  • Identity document extraction
  • Contract processing
  • Purchase order extraction
  • Tax form processing
  • Insurance claim processing

Q51. What is the Read model and the Layout model?

The Read model extracts printed and handwritten text. The Layout model adds structure — tables, paragraphs, headings, selection marks — and can output Markdown, which is very useful as input for RAG chunking.

Q52. What is a prebuilt model?

A model trained for a common document type. The invoice model extracts fields such as invoice number, vendor name, invoice date, total, tax and line items. Other prebuilt models cover receipts, ID documents, bank statements, pay stubs, tax forms and more.

Q53. What is a custom extraction model?

A model you train on your own labelled samples to extract business-specific fields from your layouts — for example a bank's internal loan application form. Custom template models suit fixed layouts; custom neural models handle more variation.

Q54. What is the difference between a prebuilt and a custom model?

Prebuilt modelCustom model
For common document typesFor specialised documents
Works immediatelyNeeds labelled training samples
Standard fieldsBusiness-specific fields
Less preparationMore preparation and evaluation

Q55. What is field confidence?

A score for each extracted field showing how confident the model is. Applications set thresholds per field — for example, auto-approve a total above 0.95 confidence, send anything lower to human review.

Q56. How do you process 100,000 invoices?

Build an event-driven, queue-based pipeline:

Invoice upload
   -> Azure Blob Storage
   -> Event Grid
   -> Azure Service Bus queue
   -> Azure Functions / Container Apps workers
   -> Document Intelligence (prebuilt invoice model)
   -> Field validation rules
   -> Human review if confidence is low
   -> SQL database / ERP
   -> Monitoring and audit trail

Add idempotency keys, retries with backoff, dead-letter handling, duplicate-invoice detection, document versioning, confidence thresholds, encrypted storage and throughput metrics. Respect the service's request-rate limits by controlling worker concurrency.

Q57. How would you integrate Document Intelligence with Azure OpenAI?

Document Intelligence extracts the text and structure; the LLM then summarises, classifies or answers questions about it. For example, extract a contract, then generate a summary of obligations and renewal dates. Validate LLM output before it drives business decisions.

Q58. How would you integrate Document Intelligence with RAG?

  • Read documents from Blob Storage.
  • Extract text and structure with the Layout model (Markdown output).
  • Clean and normalise the content.
  • Chunk by headings and sections.
  • Generate embeddings.
  • Index chunks with metadata in Azure AI Search.
  • Retrieve relevant chunks at query time.
  • Generate grounded answers with citations.

7. Azure Speech interview questions

Q59. What is Azure Speech?

A Foundry Tool for speech to text, text to speech, speech translation, language identification, pronunciation assessment, text-to-speech avatars and Voice Live (real-time voice conversations with agents).

Q60. What is speech to text?

Converting spoken audio into text. Options include real-time transcription for streaming audio, fast transcription for recorded files and batch transcription for large volumes. Example: transcribing a customer's call about a failed transaction for analysis.

Q61. What is text to speech?

Converting text into natural-sounding speech using neural voices, controlled with SSML (pitch, rate, pronunciation). Custom voice lets a brand create its own voice, under Microsoft's limited-access rules.

Q62. What is speech translation?

Translating spoken audio into text or speech in another language in real time — useful for multilingual support and meetings.

Q63. What is speaker diarization, and what happened to Speaker Recognition?

Diarization labels who spoke when in a transcript (Speaker 1, Speaker 2), which is what most call-centre analytics need. Speaker Recognition (identifying or verifying a person by voice) has been retired by Microsoft, so do not design new solutions around it — use proper identity verification for authentication instead.

Q64. What is real-time speech processing?

Processing audio as it streams, returning interim and final results so the application can respond while the user is still speaking.

Q65. What is the difference between speech recognition and speech synthesis?

Recognition converts audio to text. Synthesis converts text to audio.

Q66. Explain a real-time call-centre AI architecture.

Customer phone call
   -> Telephony (Azure Communication Services / Teams Phone / Twilio)
   -> Azure Speech: speech to text
   -> LLM or agent: intent, retrieval, tool calls
   -> Azure Speech: text to speech
   -> Customer

Alternatively, Voice Live or a voice-based Foundry prompt agent can run the audio loop for you. Add human-agent handoff, call-recording consent, PII redaction in transcripts, latency monitoring and quality evaluation.

Q67. How would you build a multilingual voice assistant?

Combine language identification, speech to text, an LLM (answering in the user's language or via Translator) and text to speech with a voice for each language. Test language and accent support, latency, pronunciation and customer experience in each target market — Indian English, Hindi and Telugu behave differently.

8. Azure Vision interview questions

Q68. What is Azure Vision?

A Foundry Tool for analysing images and video — image analysis, captioning, tagging, object detection, OCR and people detection. Face capabilities are a separate, limited-access service.

Q69. What are the main use cases?

  • Image analysis and tagging
  • Image captioning and alt text
  • Object detection
  • OCR on photos and labels
  • Visual inspection
  • Product catalogue image analysis
  • Accessibility applications

Q70. What is image classification?

Assigning a label to a whole image — for example "acceptable" or "defective" for a product photo. Custom Vision lets you train a classifier on your own images.

Q71. What is object detection?

Finding individual objects in an image and returning their bounding boxes — for example boxes, forklifts and pallets in warehouse camera images.

Q72. What is OCR in computer vision?

Extracting text from images, such as a serial number on a product label or a vehicle number plate.

Q73. What is the difference between object detection and image classification?

Classification says what the image contains overall. Detection finds each object and where it is.

Q74. Explain a manufacturing quality inspection use case.

Cameras capture product images on the line. A custom vision model (Custom Vision or a model trained in Azure Machine Learning) flags likely defects. The system records the result, raises an alert and sends uncertain cases to a human inspector. Low latency at the edge often matters, so models may run on edge devices.

Q75. What is a vision-language model?

A model that takes images and text as input and answers in text — for example GPT-4o-class models in Foundry. It supports image question answering, chart reading and visual document understanding, but needs evaluation for accuracy on your images.

9. Azure Language and Translator interview questions

Q76. What is Azure Language?

A Foundry Tool for NLP: sentiment analysis, opinion mining, named entity recognition, PII detection, key phrase extraction, language detection, summarisation, custom text classification, conversational language understanding and custom question answering.

Q77. What is sentiment analysis?

Classifying text as positive, negative, neutral or mixed — for example finding dissatisfied customers in bank feedback. Opinion mining goes further and links sentiment to specific aspects ("the app is fast but the charges are high").

Q78. What is named entity recognition?

Identifying entities such as people, organisations, locations, dates and monetary amounts in text.

Q79. What is key phrase extraction?

Pulling out the main terms and phrases from a document.

Q80. What is language detection?

Identifying which language a text is written in.

Q81. What is PII detection?

Finding and optionally redacting personal data — names, addresses, phone numbers, email addresses, account numbers and other supported categories — in text and conversation transcripts.

Q82. What is custom text classification?

Training a model to sort text into your own categories. A support application might classify messages as account issue, loan enquiry, card dispute, payment failure or fraud report.

Q83. What is conversational language understanding (CLU)?

The Azure Language feature that identifies intents and entities in user utterances. It replaces the retired LUIS. Custom question answering likewise replaces the retired QnA Maker. Many teams now use an LLM for intent detection, but CLU is still useful when you need fast, cheap and deterministic intent routing.

Q84. What is Azure Translator?

Machine translation for text and whole documents across more than 100 languages, with custom translation models for domain terminology. It is used in multilingual support and document translation.

Q85. How would you build a customer feedback analytics solution?

  • Collect feedback from surveys, emails and app reviews.
  • Clean and normalise text.
  • Detect language.
  • Translate where required.
  • Run sentiment and opinion mining.
  • Extract key phrases and entities.
  • Classify into feedback categories.
  • Redact PII before storage.
  • Store results and build Power BI dashboards.
  • Use an LLM to summarise weekly trends.

10. Azure Content Safety and AI security interview questions

Q86. What is Azure AI Content Safety?

A Foundry Tool that detects harmful content (hate, sexual, violence, self-harm) in text and images with severity levels, plus Prompt Shields for prompt-injection attacks, groundedness detection for answers not supported by sources, and protected material detection. In Foundry, the same protections appear as content filters and guardrails on model deployments and agents.

Q87. Why do we need Content Safety in a chatbot?

Users may send harmful or manipulative prompts, and the model may produce unsafe output. Content Safety lets you block, filter or escalate both inputs and outputs, with thresholds tuned to the application.

Q88. What is prompt injection?

An attack where malicious instructions arrive through user input (direct) or through retrieved documents, emails or web pages (indirect) to change the model's behaviour.

Q89. How do you prevent prompt injection in RAG?

  • Treat retrieved content as untrusted data
  • Separate system instructions from retrieved context (delimit it clearly)
  • Use Prompt Shields for user and document attacks
  • Give tools the minimum permissions
  • Validate inputs and outputs
  • Enforce authorisation outside the model
  • Red-team with adversarial prompts

See our agentic AI interview questions for more attack patterns.

Q90. What is a jailbreak attack?

An attempt to bypass a model's safety rules — role-play tricks, encoded instructions or "ignore previous instructions". Prompt Shields detect common patterns; layered controls handle the rest.

Q91. How do you protect PII in an Azure AI application?

  • Detect and redact PII with Azure Language
  • Encrypt data at rest and in transit
  • Use managed identities and least privilege
  • Avoid logging raw prompts and responses that contain personal data
  • Set data retention limits
  • Validate outputs so the model cannot leak other users' data

Q92. What is Azure Key Vault?

A service for storing and managing secrets, keys and certificates. Applications read permitted secrets through a managed identity instead of keeping credentials in code.

Q93. What is Azure RBAC?

Role-based access control: assigning roles (such as Cognitive Services OpenAI User or Search Index Data Reader) to users, groups, service principals and managed identities at a scope, to enforce least privilege.

Q94. What is a private endpoint?

A network interface with a private IP address in your virtual network that connects privately to an Azure service, so traffic stays off the public internet. Pair it with disabling public network access.

Q95. How do you secure an enterprise RAG application?

  • Entra ID authentication for users

12. Microsoft Foundry Agent Service and agentic AI interview questions

Foundry Agent Service is a managed platform for building, deploying and scaling agents. It currently offers three agent types — prompt agents, voice-based prompt agents and hosted agents — and you can also call the Responses API directly from an agent you run elsewhere. (Microsoft Learn: Foundry Agent Service)

Q106. What is an AI agent?

An application that uses a model to decide the next step for a goal and calls tools or services to complete it, looping until the task is done or it needs a human.

Q107. What is Microsoft Foundry Agent Service?

A managed runtime for agents in Foundry. It handles conversations, tool calls, versioning, publishing (including to Microsoft Teams and Copilot), Entra agent identity, RBAC, content filters, tracing and evaluation.

Q108. What is the difference between prompt agents, voice-based prompt agents and hosted agents?

Prompt agentVoice-based prompt agentHosted agent
Defined by instructions, model and toolsPrompt agent with real-time audio via Voice LiveYour own code (Agent Framework, LangGraph, OpenAI Agents SDK, custom) in a container
No runtime code to maintainNo voice orchestration to hostYou maintain the agent logic

Q109. What is tool calling in an AI agent?

The agent requests an action through a defined tool: search documents, get order status, create a ticket, query a database or generate a report. Foundry offers built-in tools (file search, web search, code interpreter, memory) and custom tools through functions, OpenAPI specs and MCP servers. A toolbox groups tools behind one managed endpoint so many agents can share them. The application or tool must still check permissions before acting.

Q110. What is MCP?

The Model Context Protocol: an open standard for connecting AI applications to tools and context servers. Foundry agents can use remote MCP servers. See what is MCP and our MCP interview questions.

Q111. What is a multi-agent architecture?

Several specialised agents — research, document processing, compliance, customer support, reporting — with a coordinator that delegates and combines results. Use it only when one agent with good tools is not enough; every extra agent adds latency, cost and failure points.

Q112. What is agent orchestration?

Coordinating agent steps, tool calls, state, retries and handoffs. Microsoft Agent Framework and LangGraph are common orchestration frameworks.

Q113. What is the difference between a chatbot and an AI agent?

A chatbot mainly answers. An agent also takes actions with tools, within defined permissions.

Q114. How do you secure an AI agent?

  • Give each agent its own Entra identity
  • Enforce tool-level authorisation
  • Validate tool arguments
  • Keep permissions minimal
  • Protect secrets in Key Vault
  • Log every tool call
  • Require human approval for sensitive actions
  • Test prompt injection and misuse

Q115. What is agent observability?

Tracing and monitoring model calls, tool calls, decisions, latency, errors, token usage and evaluation scores — in Foundry through tracing with Application Insights and OpenTelemetry.

14. Scenario-based Microsoft Azure AI interview questions

Q116. Your Azure OpenAI chatbot gives incorrect answers from company documents. How do you troubleshoot?

Work through the RAG pipeline from the start, because most "model" problems are retrieval problems:

  • Check the source document is correct and current.
  • Check extraction (tables, scanned pages).
  • Inspect the chunks.
  • Check the embedding model is the same at index and query time.
  • Run the query directly against Azure AI Search and inspect the results.
  • Check metadata filters.
  • Try hybrid search and semantic ranking.
  • Review the prompt.
  • Compare the answer against the retrieved evidence (groundedness).
  • Add the case to a regression test set.

Q117. Your Azure AI Search application has high latency. What do you do?

Measure each stage — query embedding, search, semantic ranking, prompt construction, LLM generation and network hops — using tracing. Then fix the slowest stage: smaller context, a faster model, streaming, caching frequent answers, or co-locating services in one region. Don't change everything at once.

Q118. Document Intelligence extraction is wrong for certain invoices. How do you fix it?

Compare the original document with the output. Decide whether the cause is image quality, an unusual layout, field mapping or the wrong model. Try the Layout model or a custom model trained on those vendors' samples, and add validation rules and human review for low-confidence fields.

Q119. A user can see another department's confidential documents. How do you resolve it?

Treat it as a security incident. Check how identity flows from login to the search query, whether the security filter is built from the verified token (not from user input), whether every chunk carries correct access metadata and whether the index has stale permissions. Fix it, re-index affected documents and add security regression tests.

Q120. Your AI application gets 50,000 requests a day. How do you scale it?

50,000 a day is under one request per second on average, but traffic peaks — size for the busiest hour. Look at:

  • Peak request rate and token volume
  • Model deployment quota (tokens per minute) and deployment type
  • Search service replicas and partitions
  • Application concurrency
  • Queues for asynchronous work
  • Caching
  • Rate limits, retries with backoff and timeouts
  • Multi-region or spillover for resilience
  • Monitoring and cost per request

Q121. How would you design a document-processing platform for 500,000 PDFs?

Event-driven and queue-based: Blob Storage, Event Grid, Service Bus and autoscaling workers (Container Apps or Functions) calling Document Intelligence within its rate limits, with validation, an output database, dead-letter queues and dashboards for throughput and failures. For a one-time backlog, run batch jobs with controlled concurrency.

Q122. How do you reduce hallucinations in an Azure OpenAI application?

RAG over approved sources, clear grounding instructions, retrieval evaluation, citation checks, groundedness detection, answer validation and a safe "I don't have that information" fallback. Prompting alone does not eliminate hallucinations.

Q123. How would you migrate a traditional chatbot to an AI agent?

Identify the tasks that need actions, define tools and schemas, connect to approved backend APIs, implement identity and permissions, add approval steps for sensitive actions and evaluate the agent on realistic scenarios before replacing the old bot. Keep the old intents as a fallback during rollout.

Q124. How do you choose between Azure OpenAI and Azure Machine Learning?

Azure OpenAI for generative tasks — conversation, summarisation, extraction, language generation. Azure Machine Learning for custom training, classical ML on tabular data, specialised prediction and full ML lifecycle management. Many solutions use both.

Q125. How do you choose between Azure AI Search and a SQL database?

Azure AI Search for search and retrieval — text, vector and hybrid. SQL for transactions, relational queries and consistency. An enterprise solution often needs both: SQL for orders, Search for documents. (PostgreSQL with pgvector or Cosmos DB vector search can be enough for smaller RAG workloads — see pgvector RAG tutorial.)

Q126. How would you deploy a production Azure AI application?

  • Infrastructure as code (Terraform or Bicep)
  • Azure DevOps or GitHub Actions pipelines
  • Managed identities and Key Vault
  • Private networking where required
  • Container hosting (Container Apps, App Service or AKS)
  • Automated tests plus evaluation gates
  • Versioned prompts and model deployments
  • Monitoring with Application Insights
  • Security review
  • Rollback plan

Q127. How do you evaluate an AI agent before production?

Build an evaluation dataset of normal, edge-case and adversarial scenarios. Measure task completion, tool selection, tool-argument correctness, answer quality, groundedness, safety and latency. Prove the agent cannot perform unauthorised actions, and run the suite on every change.

Q128. When would you use Azure Content Understanding instead of Document Intelligence?

Content Understanding extracts structured output from documents, images, audio and video using generative models with a schema you define, and suits mixed media such as claim packs with photos and call recordings. Document Intelligence is the mature choice for high-volume document OCR, layout and prebuilt field extraction where predictable cost and output matter. Benchmark both on your own samples.

Q129. A customer still runs LUIS and QnA Maker bots. What do you recommend?

Both services are retired. Migrate intents to conversational language understanding (or to LLM-based intent detection with structured output), and move the knowledge base to custom question answering or a RAG assistant on Azure AI Search with Azure OpenAI. Plan a parallel-run period, compare accuracy on real conversation logs and switch traffic gradually.

Q130. Your RAG assistant answers confidently even when the documents don't support the answer. How do you catch this in production?

Add groundedness checks: an evaluator or Content Safety groundedness detection compares the answer with the retrieved sources. Ungrounded answers are blocked or replaced with a fallback, logged and reviewed. Track the groundedness rate on a dashboard and add failing cases to the regression set.

token_provider = get_bearer_token_provider(

# Azure OpenAI v1 API: the standard OpenAI client, no monthly api-version parameter
aoai = OpenAI(

Step 6: Hybrid retrieval with a security filter

from azure.search.documents import SearchClient
from azure.search.documents.models import VectorizedQuery

search = SearchClient(
    endpoint="https://YOUR-SEARCH.search.windows.net",
    index_name="enterprise-knowledge-index",
    credential=DefaultAzureCredential(),
)

def retrieve(question: str, user_groups: list[str]) -> list[dict]:
    groups = ",".join(user_groups)  # from the verified Entra token, never from user input
    results = search.search(
        search_text=question,
        vector_queries=[VectorizedQuery(vector=embed(question), k_nearest_neighbors=50, fields="contentVector")],
        filter=f"allowed_groups/any(g: search.in(g, '{groups}', ','))",
        query_type="semantic",
        semantic_configuration_name="default",
        select=["title", "content", "source"],
        top=5,
    )
    return [{"title": r["title"], "content": r["content"], "source": r["source"]} for r in results]

Step 8: FastAPI endpoint

from fastapi import FastAPI, HTTPException, Depends
from pydantic import BaseModel

app = FastAPI()

class Ask(BaseModel):
    question: str

@app.post("/ask")
def ask(req: Ask, user=Depends(verify_entra_token)):   # validates the bearer token, returns groups
    if not req.question.strip():
        raise HTTPException(400, "Question cannot be empty")
    docs = retrieve(req.question, user.groups)
    if not docs:
        return {"answer": "I couldn't find this in the documents you can access.", "sources": []}
    context = "\n\n".join(f"[{i+1}] ({d['source']}) {d['content']}" for i, d in enumerate(docs))
    resp = aoai.chat.completions.create(
        model="YOUR-CHAT-DEPLOYMENT",
        temperature=0,
        messages=[{"role": "system", "content": SYSTEM_PROMPT.format(context=context)},
                  {"role": "user", "content": req.question}],
    )
    return {"answer": resp.choices[0].message.content, "sources": [d["source"] for d in docs]}
verify_entra_token

is your dependency that validates the Entra ID access token (issuer, audience, signature) and reads group claims.

17. Common interview mistakes to avoid

  • Saying Azure OpenAI and Microsoft Foundry are the same product.
  • Claiming RAG eliminates hallucinations.
  • Treating Azure AI Search as only a vector database.
  • Confusing OCR with document understanding.
  • Using an LLM for every traditional ML problem.
  • Treating a system prompt as a security control.
  • Ignoring user-level document permissions.
  • Hard-coding API keys in Python code.
  • Ignoring quota, rate limits and regional availability.
  • Deploying an agent without tool-level authorisation.
  • Skipping evaluation and regression testing.
  • Recommending retired services (LUIS, QnA Maker, Content Moderator, Speaker Recognition) for new projects.

Frequently Asked Questions

What are the most important Azure AI services for interviews?
Microsoft Foundry, Azure OpenAI, Azure AI Search, Document Intelligence, Speech, Vision, Language, Content Safety and Azure Machine Learning, plus Foundry Agent Service for agentic roles.

What is the difference between Microsoft Foundry and Azure OpenAI?
Foundry is the platform for models, agents, tools, evaluation and governance. Azure OpenAI is one family of models available inside it.

Is Azure AI Search used for RAG?
Yes. It provides keyword, vector and hybrid retrieval with semantic ranking and security filters, and it underpins Foundry IQ knowledge bases.

Which Azure AI services are retired?
Microsoft lists Anomaly Detector, Content Moderator, LUIS, Metrics Advisor, Personalizer and QnA Maker as retired; Speaker Recognition has also been retired. Use CLU, custom question answering and Content Safety instead.

What is Foundry Agent Service used for?
Building and running agents: prompt agents, voice-based prompt agents and hosted agents that run your own code, with tools, identity, tracing and publishing.

What is the difference between Azure AI Search and Cosmos DB for RAG?
Azure AI Search is built for search and retrieval with hybrid search and semantic ranking; Cosmos DB is an operational database that also supports vector search for simpler workloads.

Which language is used for Azure AI development?
Python is the most common, with C#, JavaScript/TypeScript and Java SDKs also available.

What should I learn for an Azure AI Engineer interview?
Azure fundamentals, Entra ID and networking, Foundry and model deployments, Python, embeddings and RAG with Azure AI Search, Document Intelligence, security, evaluation and deployment.
