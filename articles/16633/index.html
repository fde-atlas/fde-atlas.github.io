FDE Weekly Report Template: A Three-Part Format for Progress, Risks, and Decisions Needed

Original title: FDE 周报模板：进度、风险、需要决策的三段式

FDE中国 · 2026-09-04 · 3 min read

Summary

FDEChina shares a copy-ready weekly report template for FDEs built on three sections: progress, risks, and decisions needed. Progress leads with a one-line judgment, each risk must include a mitigation and required support, and each decision item must present options with costs plus a recommendation. It also requires fixed metric definitions across the project and a separate section for unplanned fixes and rejected requests. The stated goal: a reader should judge project health in thirty seconds and know their action within a minute.

Key points

  • Three-section structure: conclusions first, risks with mitigations, decisions with options.
  • Risk entries listing problems without countermeasures only create anxiety.
  • A decision section that stays empty means decisions are being absorbed instead of escalated.
  • Metric definitions must be aligned with the client and never drift during the project.
  • Next-week plans are capped at three items, each with a completion criterion.

This article provides a ready-to-copy FDE weekly report template, solving the problem of "reinventing the structure every week when writing reports." The template's core is a three-part structure: progress conclusions first, risks must come with countermeasures, decisions needed must come with options and recommendations, plus no more than three items for next week's plan. The most common misuse is writing the risk section as a list of problems—entries without countermeasures and required support only make readers anxious and don't help. It differs from generic weekly report templates in two ways: explicitly separating out "problems ruled out" to reflect the project's real difficulty, and requiring that metric definitions stay fixed across the entire project, avoiding mismatches between reporting criteria and acceptance criteria. After reading, do one thing: rewrite last week's report using this template and check whether the decision section has been empty for a long time. — FDEChina Editorial Team · Practitioner's Edition

This template is used together with the FDE Weekly Report and Project Reporting Playbook: the Playbook explains why to write this way and how to set the cadence, while this article provides a structure and filling rules you can use directly. There is only one goal—let readers judge within thirty seconds whether the project is healthy, and know within a minute what they need to do.

The Template Itself

Fill in according to the following structure; bracketed content is a placeholder, replaced each time with the current week's actual situation:

  • Header: [FDE Weekly Report] Project Name · Week N · Reporter · Date Range
  • 一、进度（结论先行）
    • One-sentence conclusion for this week: e.g., "Core scenario eval pass rate met the target, moving into pilot scale-up preparation"; write a judgment, not a process;
    • Key progress (one to three items): each item organized as "what was done + metric change + comparison with last week's baseline," e.g., "Credential entry scenario pass rate improved from 82% to 89% (same regression set)";
    • Unplanned completions and problems ruled out (one to two items): what pitfalls were fixed, what infeasible requirements were blocked, what losses were avoided—state facts only.
  • 二、风险（只放需要对方知道或能帮忙的）
    • Write each item with five elements: description · impact (on schedule or acceptance) · probability (high/medium/low) · my countermeasure · support needed;
    • When there are no new risks, don't leave it blank; write "No new risks this week; existing risks see item X of the previous issue" and note changes in existing risks.
  • 三、需要决策（最多三条，没有就写「无」）
    • Write each item with five elements: the issue · Option A and its cost · Option B and its cost · my recommendation and rationale · expected decision time;
    • Decision items must include options; items that raise a question without options will be returned for rewriting.
  • 四、下周计划（不超过三条）
    • Write each item as "item + completion criteria"; if you can't write a completion criterion, it means you haven't thought it through—think it through before listing.
  • Attachments: links to eval reports, requirement pools, demo records, etc., provided with the report.

Usage Notes

First, the order of the three sections cannot be swapped; each serves a different function. The progress section leads with the conclusion—the first line is the judgment, so even readers who only read that line come away with the right impression. The risk section favors quality over quantity: include only items the other party needs to know or can help push forward; don't take up attention with things that can be resolved internally. The decisions-needed section is the most valuable part of the entire report—it turns the FDE from an information passer into someone who drives decisions; a long-running "none" usually means decisions that should be pushed upward aren't being pushed. For designing the reporting cadence (how weekly reports, biweekly demos, and milestone reviews work together), see Step 6 of the Reporting Playbook.

Second, metric definitions must be aligned with the client in advance and stay unchanged across the entire project. Which test case set is the denominator for the eval pass rate, what the statistical period is, and how it relates to acceptance criteria—write these in a definitions note attached to the weekly report. Once definitions drift, it damages trust more than ugly numbers do. For how to build a baseline, see the Eval Baseline Building Playbook; for which metrics to track across the whole project, see FDE Delivery Metrics. In the "unplanned completions and problems ruled out" section, write only facts and avoided losses for each item, without a self-congratulatory tone, otherwise the credibility of the entire section will be eroded along with it.

Third, put the weekly report into a fixed communication rhythm: send it at the same time so the client knows when to expect it; pair it with biweekly demos so the client sees a living system, and with milestone reviews to formally align on the baseline. The best test of a weekly report's quality: when the client's executives have no time to read the full text and only read the first section, they can still make the right judgment. If that fails, the problem is usually that the conclusion isn't sharp enough, not that the report is too short.

Common Filling Issues

Decision section empty for a long time: it's not that there are no decisions to push, but that you've absorbed decisions that should be escalated, and risks pile up accordingly. Risk section getting longer and longer: what's missing is countermeasures, not risks—go back to the risk register and do triage first. Metrics unchanged for two consecutive weeks: either there's genuinely no progress, in which case honestly write the reason and plan; or the wrong metrics were chosen, in which case go back to the definitions note and reconfirm their relationship to acceptance value. When the client's expectations diverge from the reality presented in the weekly report, refer to the stakeholder communication methods in Expectation Management, and if necessary arrange a separate meeting rather than continuing to wrangle in the weekly report.
